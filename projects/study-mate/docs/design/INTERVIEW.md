# 디자인 인터뷰 — 알림 패널

회차: 2 (2026-09-08) — **1회차에서 넷이 다 정해졌다. 아래 「결론」이 시안의 입력이다.**

승인된 시각 기준(`design-rules.md`)은 그대로 전제입니다. 이 상담은 **그 기준이 아직 다루지
않은 것 하나**만 좁힙니다 — **떠 있는 면(패널·오버레이)**. 승인된 세 언어(랜딩·목록·상세)는
전부 종이 위에 세로로 쌓이는 화면이라, 무언가가 화면 위에 뜨고 바깥을 덮는 모양은 지금
어디에도 없습니다.

## 0. 이미 정해져 있어서 안 묻는 것

- **알림은 별도 페이지가 없다** — 헤더 종 아이콘에 달린 패널이고 거기서 읽음 처리·전체
  읽음·삭제를 한다 (`docs/IA.md` 「화면이 아닌 것」).
- **안 읽음의 색은 코랄** — 형광펜 코딩 규칙이 「안 읽음」에 배정한 색이고, 종 옆 숫자 알약이
  이미 그 색입니다.
- **테두리 우선(2px) · 카드 둥글기 18px · 따뜻한 갈색 그림자** — 패널도 이 값을 씁니다.
- **약한 잉크는 종이 배경에서만** — 형광펜 위에 얹으면 대비가 미달입니다. 패널 안에서
  색면을 쓰면 그 위 글자는 전부 진한 잉크가 됩니다.

## 1. 패널이 어떻게 열리나 (가장 크게 갈리는 것)

> 🤖: 추천은 **B** 입니다. 이 서비스의 모바일 헤더가 햄버거를 안 쓰기로 한 근거
> (「감추려고 여는 동작을 하나 더 만들면 손이 늘어난다」)가 여기에도 그대로 적용됩니다 —
> 데스크톱과 모바일이 같은 동작이면 새로 배울 것이 없습니다.

- [ ] **A. 종 아래 드롭다운 / 모바일은 아래에서 올라오는 시트** — 익숙하지만 모바일에
      여는 방식이 하나 더 생깁니다
- [x] **B. 종 아래 드롭다운 / 모바일도 같은 드롭다운(폭만 화면 가득)** ← **사람이 골랐다**
- [ ] **C. 오른쪽에서 나오는 서랍 / 모바일은 전체 화면** — 알림이 많아질 때 편하지만
      화면을 통째로 덮습니다
- [ ] **D. 화면 가운데 모달** — 알림처럼 훑고 닫는 것에는 무겁습니다

## 2. 안 읽은 줄을 무엇으로 표시하나

> 🤖: 추천은 **B** 입니다. A(코랄 점)는 승인된 규칙에서 **점 붙은 알약 = 모집 상태**와
> 형태가 겹치고, C(줄 배경을 코랄 색면)는 그 위의 메타 글자(약한 잉크)가 대비 미달이라
> 줄 전체를 진한 잉크로 바꿔야 합니다.

- [ ] **A. 줄 왼쪽에 코랄 점**
- [x] **B. 줄 왼쪽에 4px 코랄 세로 띠 + 제목 굵게. 읽은 줄은 띠 없이 약한 잉크** ← **사람이 골랐다**
- [ ] **C. 안 읽은 줄의 배경을 옅은 코랄 색면으로**
- [ ] **D. 굵기만으로 (색 없이)**

## 3. 알림 삭제도 두 단계로 확인받나

승인된 규칙은 **파괴적 행동은 한 번에 실행되지 않는다**(모집글 삭제: 첫 버튼 → 확인 문구 →
두 번째 버튼)입니다. 알림 삭제도 되돌릴 수 없습니다(지운 것으로 표시하는 열이 없습니다).

> 🤖: 추천은 **B** 입니다. 그 규칙의 근거는 「잃는 것이 크고 되돌릴 수 없다」인데,
> 알림에서 잃는 것은 **이미 일어난 일의 복사본**입니다 — 알림을 지워도 참여 상태와 스터디는
> 그대로 남습니다. 모집글은 지우면 그 회차 자체가 없어집니다. 다만 이건 승인된 규칙에서
> 벗어나는 결정이라 사람이 정해야 하고, 정해지면 `design-rules.md` 에 「무게가 다른 삭제」로
> 적습니다.

- [ ] **A. 규칙대로 두 단계** — 줄마다 확인 단계가 생겨 목록이 시끄러워집니다
- [x] **B. 한 번에 지운다** ← **사람이 골랐다.** 규칙에 「무게가 다른 삭제」로 예외와 근거를 적는다
- [ ] **C. 줄 삭제는 아예 없애고 「전체 읽음」만 둔다** — IA 가 삭제를 적어 두었으므로
      이걸 고르면 IA 도 같이 고칩니다

## 4. 내가 정하고 로그에 남길 것 (되돌리기 싼 것 — 다르게 원하시면 말씀만)

**줄에 붙는 것**: 줄 전체가 링크이고(누르면 읽음 처리 + 이동), 오른쪽에 삭제(×) 하나만
붙습니다. 링크가 없는 줄(지워진 스터디)은 눌러도 읽음 처리만 됩니다. 근거는 「한 패널에 잉크
버튼은 하나다」와 같은 결입니다 — 좁은 줄에 버튼을 둘 놓으면 문장이 갈 자리가 없습니다.
아이콘을 마우스 올렸을 때만 보이게 하는 방식은 안 씁니다(터치 화면에는 그 상태가 없어서
손가락으로는 못 누릅니다).

- 패널 폭 360px, 최대 높이 화면의 70%까지 스크롤, 헤더 아래 8px 띄움
- 머리에 「알림」 + 오른쪽에 「전체 읽음」(테두리 톤, 안 읽은 것이 없으면 비활성)
- 빈 상태 문구: 「아직 알림이 없습니다」 + 한 줄 설명
- 한 번에 보여 주는 줄 수 20, 그 아래는 스크롤 (별도 페이지가 없으므로 더 보기는 두지 않음)
- 닫는 법: 바깥 누르기 · ESC · 종 다시 누르기. 열면 첫 줄로 포커스가 가고 닫으면 종으로
  돌아옵니다. 포커스는 패널 안에 갇힙니다
- 시각 표시: 「3분 전」 「어제」 같은 상대 시각, 7일이 넘으면 날짜

## 6. 결론 (2026-09-08, 시안의 입력)

1. **드롭다운 하나로 간다.** 종 아래에 카드가 뜨고, 640px 아래에서는 같은 카드가 폭만 화면
   가득이 된다. 여는 방식을 하나만 배우면 된다.
2. **안 읽음은 왼쪽 4px 코랄 세로 띠 + 제목 굵게.** 읽은 줄은 띠 없이 약한 잉크.
   점도 색면도 쓰지 않는다 — 점은 「모집 상태」의 형태이고, 색면 위에서는 약한 잉크가
   대비 미달이다.
3. **알림 삭제는 한 번에 실행된다.** 승인된 「파괴적 행동은 두 단계」에서 벗어나는 결정이고,
   근거는 잃는 것의 무게다 — 알림은 이미 일어난 일의 복사본이라 지워도 참여 상태와 스터디가
   그대로 남는다. 모집글은 지우면 그 회차 자체가 없어진다. 시안 승인 시 `design-rules.md` 에
   예외로 등재한다.
4. **줄에는 삭제(×) 하나만.** 줄 전체가 링크이고 누르면 읽음 처리 + 이동한다.
   링크가 없는 줄(지워진 스터디)은 눌러도 읽음 처리만 된다.

# 화면 목록과 흐름 — Study Mate

> 화면의 **경로와 역할**을 정한다. 무엇이 보이는지까지는 정하지만 어떻게 생겼는지는
> 정하지 않는다 — 그건 시각 기준(`design/design-rules.md`)과 시안이 맡는다.
>
> 출처 태그는 제품 정의와 같은 규칙이다. `[코드에서 확인]` 은 기존 프로젝트의
> 라우트 파일이 직접 말해준 것, `[결정]` 은 다시 지으면서 이 프로젝트가 새로 정한 것.

## 화면 (18장)

| 경로 | 무엇을 하는 곳 | 로그인 | 출처 |
|---|---|---|---|
| `/` | 홈 — 서비스가 무엇인지 보여주고 모집글 탐색과 스터디 개설로 보낸다 | 불필요 | `[코드에서 확인]` |
| `/about` | 소개 — 서비스 설명 | 불필요 | `[코드에서 확인]` |
| `/posts` | 모집글 목록 — 검색·카테고리·지역으로 좁혀 훑는다 | 불필요 | `[코드에서 확인]` |
| `/posts/[id]` | 모집글 상세 — 이 스터디가 나에게 맞는지 판단하고 참가를 신청한다 | 불필요(신청은 필요) | `[코드에서 확인]` |
| `/posts/create` | 모집글 작성 (AI 초안 도우미 포함) | **필요** | `[코드에서 확인]` |
| `/posts/[id]/edit` | 모집글 수정 | **필요 · 작성자만** | `[코드에서 확인]` |
| `/studies/create` | 스터디 개설 | **필요** | `[코드에서 확인]` |
| `/studies/[id]` | 스터디 상세 — 멤버 목록, 신청자 승인·거절, 채팅방 입구 | **필요** | `[코드에서 확인]` |
| `/studies/[id]/edit` | 스터디 수정 | **필요 · 호스트만** | `[코드에서 확인]` |
| `/profile` | 내 프로필 — 내 프로필 카드, 내가 만든 스터디, 내 신청 현황, **내가 쓴 모집글** | **필요** | `[코드에서 확인]` · 네 번째 구역은 `[결정 2026-09-06]` |
| `/profile/edit` | 프로필 수정 · 이미지 업로드 | **필요** | `[코드에서 확인]` |
| `/profile/password` | 비밀번호 변경 | **필요** | `[코드에서 확인]` |
| `/chats` | 채팅방 목록 — 안 읽은 메시지 표시 | **필요** | `[코드에서 확인]` |
| `/chats/[id]` | 그룹 채팅 — 실시간 대화 | **필요 · 멤버만** | `[코드에서 확인]` |
| `/login` | 로그인 | **비로그인만** | `[결정]` |
| `/signup` | 회원가입 | **비로그인만** | `[결정]` |

기존 프로젝트는 로그인·회원가입이 `/auth/login` · `/auth/signup` 이었다. 짧은 쪽으로
바꾼다 — 사용자가 입력하거나 공유하는 주소이고, `auth` 는 구현 사정이지 사용자의 말이
아니다. 이미 만들어 둔 세션 가드도 `/login` 을 쓰고 있다. `[결정]`

`/studies` (스터디 목록) 은 **없다.** 탐색은 모집글로 한다 — 스터디는 모집글을 통해서만
만난다는 것이 기존 구조이고, 목록이 둘이면 "어디서 찾아야 하나"가 생긴다. `[코드에서 확인]`

## 스터디 하나에 모집글은 여럿이다 — 목록은 하나만 보여준다

한 스터디가 기수를 나눠 여러 번 모집할 수 있다. 그래서 스터디 : 모집글 = **1 : N** 이다.
`[결정 2026-09-05]`

그대로 두면 `/posts` 에 같은 스터디가 여러 장 뜬다. 규칙은 이렇다:

- **목록(`/posts`)에는 스터디마다 가장 최근 모집글 한 장만 나온다.** 훑는 사람이 판단할
  대상은 스터디이지 모집 회차가 아니다.
- **지난 회차 모집글도 주소로는 계속 열린다**(`/posts/[id]`). 남이 공유한 링크가 죽지 않는다.
  화면 위쪽에 "이 스터디의 최신 모집글 보기"를 띄운다.
- **스터디 상세(`/studies/[id]`)가 그 스터디의 소개를 읽는 유일한 화면이다.** 모집글의 본문은
  회차마다 다를 수 있고, 스터디 자체의 소개는 회차를 넘어 같기 때문에 저장하는 자리가 다르다.

## 지역은 세 가지를 따로 담는다

승인된 시안이 지역을 세 가지 다른 뜻으로 쓰고 있다 — 필터 옵션은 고정 10개(`서울`·`경기·인천`
…)이고, 카드에 찍히는 값은 `서울 강남`, 상세는 `서울 강남 (역삼역 스터디카페, 온라인 병행)` 이다.
한 칸에 담으면 `서울` 필터가 `서울 강남` 스터디를 **조용히 빠뜨린다** — 오류가 아니라 "그런
스터디가 없다"로 보인다. `[결정 2026-09-05]`

| 무엇 | 값 | 쓰이는 곳 |
|---|---|---|
| **지역** | 고정 목록에서 하나 | 필터·카드의 앞부분 |
| **상세 위치** | 자유 텍스트, 비어도 된다 | 상세 화면. 카드에는 안 나온다 |
| **진행 방식** | 오프라인 · 온라인 · 병행 | 필터의 「온라인」 항목이 이것을 본다 |

「온라인」이 지역 목록에 섞여 있던 것이 이 분해로 풀린다 — 온라인은 지역이 아니라 진행
방식이고, 시안의 상세는 `온라인 병행` 이라는 제3의 상태까지 쓴다.

## 「마감 임박순」의 기준

목록 정렬 셋(최신순 · 마감 임박순 · 좋아요순) 중 마감 임박순은 **모집 마감일**을 기준으로 한다.
`[결정 2026-09-05]`

호스트가 스터디를 열 때 "언제까지 신청받는가"를 적고, 그 날짜가 가까운 순서다. 남은 자리
수로 해석하지 않은 이유는 그것이 매번 세어야 하는 파생값이라 정렬에 인덱스가 못 붙기
때문이고, 무엇보다 사용자가 읽는 말("마감 임박")이 가리키는 것이 날짜이기 때문이다.

**순서는 세 덩어리다** — ① 아직 안 지난 마감일이 **가까운 것부터** ② 기한 없음
③ 지난 마감일이 **최근에 지난 것부터**. `[결정 2026-09-05]`

지난 날짜는 오늘에서 가장 먼 쪽이라 앞에 오면 안 되고, 그렇다고 목록에서 빼지도 않는다 —
**마감일이 지나도 모집이 닫히는 것은 아니기 때문이다**(모집을 닫는 것은 호스트다).
③ 안에서 최근 것을 앞에 두는 이유는 같다: 지난주에 끝난 모집이 6년 전에 끝난 모집보다
지금 신청할 만하다.

## 화면이 아닌 것

- **알림** — 별도 페이지가 없다. 헤더의 종 아이콘에 달린 패널이고, 거기서 읽음 처리·
  전체 읽음·삭제를 한다. `[코드에서 확인]`
- **AI 추천** — 홈 안의 한 섹션이다. 독립 화면이 아니다. `[코드에서 확인]`
- **모집글 초안 도우미** — 모집글 작성 화면 안의 보조 장치다. `[코드에서 확인]`

## 핵심 흐름 — 화면으로 옮기면

제품 정의의 성공 조건은 **발견 → 신청 → 승인 → 대화**가 끊기지 않는 것이다. 화면으로는:

```
/  →  /posts  →  /posts/[id]  →  [참가 신청]  →  (호스트가) /studies/[id] 에서 승인
                                                            ↓
                                        /chats  →  /chats/[id] 에서 대화 시작
```

이 흐름에서 **로그인 벽이 처음 나타나는 자리는 참가 신청 버튼**이다. 그 앞의 발견 과정
(`/`, `/posts`, `/posts/[id]`) 은 전부 공개다. 판단에 필요한 정보를 로그인 뒤에 숨기면
"발견"이 시작되지 못한다. `[결정]`

신청한 사람의 시야에서 이 흐름은 **상태**로 보인다 — 대기 · 승인 · 거절. 제품 원칙 3
("신청·승인의 상태를 투명하게")이 요구하는 자리는 두 곳이다: 모집글 상세의 버튼
(신청하기 / 신청함(대기) / 참여 중), 그리고 프로필의 내 신청 현황. `[결정]`

## 화면 언어는 세 종류뿐이다

18장이지만 서로 다른 레이아웃은 셋이다. 시안을 셋만 그리면 나머지는 물려받는다.

| 언어 | 대표 화면 | 물려받는 화면 |
|---|---|---|
| **랜딩** — 히어로 + 섹션 쌓기 | `/` | `/about` |
| **목록** — 필터 줄 + 카드 그리드 | `/posts` | `/chats`, 프로필의 내 스터디 목록 |
| **상세·작업** — 본문 + 옆(또는 아래) 행동 패널 | `/posts/[id]` | `/studies/[id]`, `/profile`, 작성·수정 폼 5장, `/chats/[id]` |

폼 6장(모집글 작성·수정, 스터디 개설·수정, 프로필 수정, **비밀번호 변경**)과 인증 2장은 상세·작업 언어의
좁은 변형이다. 채팅은 상세 언어에 실시간 목록이 얹힌 것이다. `[결정]`

## 무엇을 먼저 만드나

핵심 흐름 위에 있는 것부터다. 흐름 밖의 것(AI 추천·소개·비밀번호 변경)은 흐름이 끝까지
이어진 뒤에 붙인다 — 제품 원칙 4가 "AI는 거들 뿐"이라고 정한 그대로다.

1. `/` · `/posts` · `/posts/[id]` — 발견
2. `/login` · `/signup` — 로그인 벽
3. `/studies/create` · `/posts/create` — 만드는 쪽
4. `/studies/[id]` — 신청 승인
5. `/chats` · `/chats/[id]` — 대화
6. `/profile` 계열 · `/about` · AI 추천 — 나머지

## 실제로 사고가 났고 그래서 바꾼 것

- **서버의 쿼리 클라이언트를 요청마다 새로 만든다.** 모듈 수준 싱글턴이 서버 프로세스에서
  요청과 사용자 사이에 캐시를 공유해, 초기 데이터가 이전 요청의 낡은 캐시에 밀리며 화면이
  어긋났다(모집 상태 배지 등). 브라우저는 처음 한 번만 만들어 재사용한다. `[문서에서 확인]`
- **조회수는 캐시를 단일 진실로 두고 낙관적으로 올린다.** 재진입 때 조회수가 어긋난 원인이
  라우터 캐시가 아니라 쿼리 캐시였다 — 초기 데이터가 있어도 캐시가 있으면 첫 값이 고착됐다.
  표시 쪽의 임시 보정과 하이드레이션 가드를 걷어내고 캐시 한 곳만 고치는 방식으로 바꿨다.
  `[문서에서 확인]`
- **모델에게 데이터를 다시 쓰게 하지 않는다.** 예전에는 모집글 전체를 모델이 JSON 으로
  되돌려 주게 하고 그 값을 그대로 그렸는데, 모델은 복사기가 아니라 생성기라 본문이 요약되고
  인원수가 옛 값으로 남고 이미지 주소를 지어냈다. 지금은 모델의 역할을 **"무엇을 어떤 순서로
  보여줄지 + 왜"**로 좁히고, 응답을 스키마로 두 겹 검증하고(모델 쪽 강제 + 실행 시 확인),
  돌려받은 id 를 후보 집합으로 걸러 내고, 살아남은 id 로 데이터베이스에서 다시 읽어 그린다.
  화면 데이터는 전부 데이터베이스에서 온다. `[문서에서 확인]`
  - 같은 한 줄이 두 가지를 막는다: 없는 것을 지어내는 것과, 남이 쓴 본문이 지시문처럼
    작동하는 것. 후보 목록을 구분자로 감싸고 태그 문자를 escape 하는 것도 같은 이유다.
- **스터디 화면 전체를 로그인 필수로 묶었다.** 상세·편집·작성을 각각 막는 대신 경로 접두사
  하나로 프록시 단계에서 막는다. `[문서에서 확인]`
- **제품에 없는 포인트 필드를 화면에서 뺐다.** 빈 배지와 정체불명의 숫자가 보이던 것을
  없앴다. "정직한 데모" 원칙의 적용이다. `[문서에서 확인]`

## 시각

- **옅은 단일 블루 틴트의 평평한 룩을 폐기하고 종이·잉크·형광펜 세계로 전면 전환했다.**

  카드 그리드로만 풀었던 것. `[문서에서 확인]`

  폐기했고, 균일한 회색 밴드는 스티커와 안 어울려 밋밋하다는 피드백이 있었다. 그 사이를

  그 위반에 파묻힌다. 다시 지으면 처음부터 규약 안에서 자란다. 원본은 읽기 전용 참고로 남는다.

  되어 되돌리기가 공짜다(초기에는 스키마를 여러 번 뒤집는다) / 행 수준 접근 정책을 첫

  쓰기 인가 스펙이 그 상태를 계약 위반으로 본다 / 원본 데모가 쓰는 데이터베이스를 안 건드린다.
  배포할 때는 같은 마이그레이션을 새 프로젝트에 올린다.

# 비밀번호 변경 스펙

로그인한 사람이 자기 비밀번호를 바꾸는 기능이다. **어기면 사고인 것은 하나다** —
비밀번호 변경은 계정의 열쇠를 바꾸는 일이라, 지금 이 창을 쓰는 사람이 정말 계정 주인인지
확인하지 않으면 **열려 있는 창을 지나가는 사람이 계정을 통째로 가져간다.** 원래 주인은
그 자리에서는 아무것도 못 느끼고, 다음에 들어오려 할 때 못 들어온다.

## 결정된 것 (2026-09-06, 사람 결정)

- **현재 비밀번호를 다시 받는다.** 남의 노트북에 로그인된 창이 열려 있을 때, 그 창만으로는
  비밀번호를 못 바꾸게 한다.
- **바꾸면 다른 기기의 로그인을 끊는다.** 비밀번호를 바꾸는 이유는 보통 「남이 들어온 것 같다」
  이고, 안 끊으면 그 사람의 창은 그대로 살아 있어 바꾼 의미가 없다. 지금 이 기기는 유지한다.

**인증 서버가 제공하는 「안전한 비밀번호 변경」은 쓰지 않는다.** 그 기능이 요구하는 것은
현재 비밀번호가 아니라 **이메일로 보낸 일회용 번호**라, 정하기로 한 것과 다른 물건이고
메일 발송에 매여 있다. 우리가 직접 현재 비밀번호를 확인한다.

## 불변식

- INV-C1: **현재 비밀번호를 같은 요청에서 맞혀야 새 비밀번호가 저장된다.**
  틀리면 비밀번호는 그대로다. 믿는 값은 검증된 세션의 사용자 식별자와 **인증 서버의 확인
  결과**뿐이고, 폼이 실어 보낸 어떤 값도 그 자체로는 안 믿는다.
  위반하면 로그인된 창 하나만으로 계정을 빼앗을 수 있다.
  (강제 위치: 서버 액션 — 현재 비밀번호로 인증 서버에 확인을 요청하고, 성공한 경우에만
  변경으로 넘어간다)

- INV-C2: **현재 비밀번호 확인은 지금 세션을 건드리지 않는다.**
  확인에 쓰는 인증 호출은 **쿠키를 읽지도 쓰지도 않는 별도 클라이언트**로 한다.
  위반하면 확인 과정이 세션 쿠키를 갈아치우고, 현재 비밀번호를 틀렸을 때조차 로그인 상태가
  흔들린다 — 실패해야 할 요청이 로그아웃을 일으킨다.
  (강제 위치: 서버 액션 — 확인용 클라이언트는 세션을 저장하지 않는 설정으로 만든다)

- INV-C3: **비밀번호가 바뀌면 다른 기기의 세션이 전부 끊기고, 지금 기기는 유지된다.**
  위반의 방향이 둘이라 둘 다 사고다 — 안 끊으면 침입자의 창이 살아남고, 지금 기기까지 끊으면
  바꾸자마자 로그아웃되어 사용자는 무엇이 성공했는지 모른다.
  (강제 위치: 서버 액션 — 변경 성공 직후 「나 말고 전부」 범위의 로그아웃을 부른다)

- INV-C4: **새 비밀번호의 강도 규칙은 우리가 다시 적지 않는다.**
  하한과 문자 구성은 인증 서버 설정이 정하고, 화면은 그 서버가 돌려준 사유를 그대로 보여 준다.
  위반하면 규칙이 두 벌이 되어, 한쪽만 바뀌는 날 가입에서는 되는 비밀번호가 변경에서는 안 된다.
  (강제 위치: 인증 서버. 가입 화면이 이미 같은 자리에 기대고 있다)

- INV-C5: **바뀌지 않았는데 바뀌었다고 말하지 않는다.**
  변경 요청이 실패로 돌아오면 성공 문구도, 다른 기기 로그아웃도 일어나지 않는다.
  위반하면 사용자는 비밀번호가 바뀐 줄 알고 옛 비밀번호를 지운다.
  (강제 위치: 서버 액션 — 변경 결과를 확인한 뒤에만 다음 단계로 간다)

- INV-C6: **세션 없이 들어온 변경 요청은 아무 일도 하지 않고 실패를 돌려준다.**
  INV-A4 의 비밀번호판이다. 새 계약이 아니라, 이 기능의 서버 액션도 그 하한선을 지킨다는 선언이다.
  (강제 위치: 서버 액션의 세션 가드)

## 시나리오

- S1 (INV-C1, 실패경로): Given 로그인한 사용자 / When 현재 비밀번호를 틀리게 적고 변경을
  요청한다 / Then 실패 문구가 나오고, **옛 비밀번호로 여전히 로그인된다**

- S2 (INV-C1, 반대 절반): Given 로그인한 사용자 / When 현재 비밀번호를 맞게 적고 새 비밀번호로
  바꾼다 / Then 새 비밀번호로 로그인되고 옛 비밀번호로는 안 된다

- S3 (INV-C2, 실패경로): Given 로그인한 사용자 / When 현재 비밀번호를 틀리게 적어 실패한다 /
  Then **그 요청 뒤에도 로그인 상태가 그대로다** (확인 호출이 세션 쿠키를 안 건드린다)

- S4 (INV-C3, 실패경로): Given 같은 계정으로 기기 둘이 로그인해 있다 / When 기기 A 에서
  비밀번호를 바꾼다 / Then 기기 B 의 세션은 더 이상 갱신되지 않는다

- S5 (INV-C3, 반대 절반): Given 위와 같은 상태 / When 기기 A 에서 바꾼 직후 / Then 기기 A 는
  로그인된 채로 남아 결과 화면을 본다

- S6 (INV-C4): Given 로그인한 사용자 / When 인증 서버의 하한에 못 미치는 새 비밀번호를 적는다 /
  Then 서버가 돌려준 사유가 그대로 화면에 나오고 비밀번호는 그대로다

- S7 (INV-C5, 실패경로): Given 현재 비밀번호는 맞았지만 변경 호출이 실패한다 / When 그 응답을
  받는다 / Then 성공 문구가 안 나오고 다른 기기도 안 끊긴다

- S8 (INV-C6, 실패경로): Given 세션이 없는 요청 / When 비밀번호 변경 액션을 부른다 /
  Then 인증 서버를 부르지도 않고 정해진 문구로 실패한다

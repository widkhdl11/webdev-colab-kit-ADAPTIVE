# 프로필 수정과 아바타 업로드 스펙

사용자가 자기 이름·소개·지역·관심분야를 고치고 얼굴 사진을 올리는 기능이다.
**어기면 사고인 것은 둘이다** — 남의 프로필 행이 고쳐지는 것과, **남의 아이디 폴더에 파일을
미리 올려 두는 것**. 뒤엣것은 지금 열려 있다: 저장소 정책이 버킷과 올린 사람만 보고
**경로를 안 보기 때문에**, 아직 사진을 안 올린 사람의 폴더에 아무나 자기 파일을 넣을 수 있다.
화면이 경로 규약으로 주소를 만드는 순간 그 파일이 그 사람의 얼굴로 나간다.

## 결정된 것 (2026-09-06, 사람 결정)

- **프로필 사진은 지금처럼 공개다.** 모집글 상세가 비로그인에게 열려 있고 거기에 작성자
  얼굴이 나오므로, 사진만 막으면 그 화면이 깨진다. 프로필 **본문**은 INV-Z13 이 좁힌 그대로다.
- **닉네임 중복을 허용한다.** 사람을 가르는 것은 내부 id 라 같은 이름이 둘 있어도 사고가 나지
  않는다. 유일성 제약을 걸면 이미 중복인 데이터를 먼저 정리해야 하고 가입 실패 사유가 하나 는다.

## 불변식

- INV-E1: **프로필 행을 고칠 수 있는 것은 본인뿐이다.**
  위반하면 남이 내 이름·소개·지역을 바꾼다. 믿는 값은 검증된 세션의 사용자 식별자뿐이고,
  폼이 실어 보낸 어떤 id 도 안 믿는다.
  (강제 위치: 데이터베이스 — `profiles_update_own` 의 `using` + `with check` 양쪽에
  `id = auth.uid()`. 0001 에 이미 있다)

- INV-E2: **프로필의 주인은 갱신으로 바뀌지 않는다.**
  `id` 를 남의 것으로 바꾸는 갱신은 거부된다. 위반하면 내 프로필 행이 남의 프로필이 되어
  그 사람 화면의 이름·소개가 통째로 바뀐다. INV-Z8(소유 열은 갱신으로 안 바뀐다)의 프로필판이다.
  (강제 위치: 데이터베이스 — `with check` 가 갱신 **후** 행을 보므로 `profiles_update_own` 이
  이미 막는다. 이 스펙은 그 사실을 계약으로 고정하는 것이고, 정책을 손댈 때 `with check` 를
  빼면 이 불변식이 깨진다)

- INV-E3: **아바타 파일은 자기 아이디 폴더 아래에만 올라간다.**
  저장 경로의 첫 칸이 올린 사람의 사용자 식별자와 같아야 하고, 그렇지 않은 쓰기·수정·삭제는
  거부된다. 위반하면 **아직 사진을 안 올린 사람의 폴더를 미리 차지할 수 있고**, 화면이
  경로 규약으로 주소를 만들면 그 파일이 그 사람의 얼굴로 나간다.
  믿는 값은 세션의 사용자 식별자, 안 믿는 값은 클라이언트가 정한 경로 문자열이다.
  (강제 위치: 데이터베이스 — `storage.objects` 의 아바타 정책 넷에 경로 첫 칸 판정을 더한다.
  **지금은 버킷과 올린 사람만 본다** — 이 스펙이 닫는 구멍이다)

- INV-E4: **아바타 버킷은 이미지라고 신고된 것만, 정해진 크기까지만 받는다.**
  허용 목록 밖의 형식으로 신고했거나 상한을 넘는 파일은 저장 자체가 거부된다. 위반하면
  공개 버킷이 아무 파일이나 담는 저장소가 되고, 그 주소는 누구나 읽을 수 있다.
  **크기는 실제 바이트를 세지만 형식은 신고값을 본다** — 저장소에 내용을 검사하는 자리가
  없어서, 요청을 손으로 만들면 아무 바이트나 이미지라고 신고해 넣을 수 있다. 남는 위험은
  「계정당 1MB 짜리 공개 파일 보관함」이고, 저장된 형식이 이미지라 브라우저가 실행하지도
  않는다. 앱에서 앞바이트를 확인하는 것은 앱을 우회한 업로드를 못 막으므로 **강제 위치가
  될 수 없어** 넣지 않는다.
  (강제 위치: 데이터베이스 — 버킷의 허용 형식·크기 상한. 화면 쪽 검사는 편의고 강제가 아니다)

- INV-E5: **프로필의 지역은 고정 목록의 값이거나 비어 있다.**
  목록에 없는 값을 넣는 갱신은 거부된다. 위반하면 그 사람은 지역 필터의 어느 값으로도
  안 걸리는데 화면에는 무언가 적혀 있는 상태가 된다 — 오류가 아니라 "그런 사람이 없다"로 보인다.
  0002 가 스터디의 지역을 고정 목록으로 뽑을 때 프로필 쪽만 안 따라갔다.
  (강제 위치: 데이터베이스 — `profiles.region` 이 `regions` 를 가리키는 외래 키가 된다)

- INV-E7: **아바타 목록은 자기 것만 보인다.**
  버킷을 통째로 나열하는 요청은 자기 폴더 밖의 것을 돌려주지 않는다. 위반하면 경로 규약이
  `<사용자 id>/...` 라서 **그 목록이 곧 회원 id 명부**이고, id 하나면 그 사람의 얼굴 사진이
  따라 나온다 — INV-Z13 이 프로필 본문을 좁혀 준 사람들의 얼굴이 통째로 샌다.
  **사진 주소 자체는 계속 열려 있다**(2026-09-06 사람 결정). 막는 것은 「주소를 몰라도
  찾을 수 있는 것」뿐이다.
  (강제 위치: 데이터베이스 — `avatars_read` 의 소유자 판정. 공개 버킷의 내려받기는 이 정책을
  안 지나므로 결정과 충돌하지 않는다)

- INV-E8: **`avatar_url` 도 자기 폴더만 가리킬 수 있다.**
  다른 사람의 폴더를 가리키는 값을 넣는 갱신은 거부된다. 위반하면 파일을 안 올려도 INV-E3 이
  막으려던 피해에 도달한다 — 모집글 상세에 작성자 사진이 붙는 순간 남의 얼굴을 자기 얼굴로
  걸 수 있다.
  (강제 위치: 데이터베이스 — `profiles_avatar_path_own`)

- INV-E9: **이름에 제어문자를 넣을 수 없다.**
  제어문자가 섞인 이름으로 바꾸는 갱신은 거부된다. 위반하면 참여자 목록·작성자 줄에서
  다른 회원의 이름처럼 보이게 만들거나 줄을 밀 수 있다. 가입 경로는 이미 같은 규칙을
  지키고 있었다 — 값이 들어오는 자리가 하나 늘었으므로 규칙도 따라온다.
  (강제 위치: 데이터베이스 — `profiles_username_no_control`. 화면은 읽을 수 있는 문구를
  주려고 먼저 막을 뿐이다)

- INV-E6: **세션 없이 들어온 수정 요청은 아무 일도 하지 않고 실패를 돌려준다.**
  INV-A4 의 프로필판이다. 새 계약이 아니라, 이 기능의 서버 액션도 그 하한선을 지킨다는 선언이다.
  (강제 위치: 서버 액션의 세션 가드 + 위 정책들)

## 시나리오

- S1 (INV-E1, 실패경로): Given 로그인한 사용자 A / When 데이터베이스를 직접 불러 B 의 프로필
  행에 이름을 쓴다 / Then 거부되고 B 의 이름은 그대로다

- S2 (INV-E1, 반대 절반): Given 로그인한 사용자 A / When 자기 프로필의 이름·소개·지역·
  관심분야를 고친다 / Then 네 값이 다 바뀐다

- S3 (INV-E2, 실패경로): Given 로그인한 사용자 A / When 자기 프로필 행의 `id` 를 B 의 것으로
  바꾸는 갱신을 보낸다 / Then 거부되고 A 의 행도 B 의 행도 그대로다

- S4 (INV-E3, 실패경로): Given 로그인한 사용자 A / When `<B 의 id>/avatar.png` 로 파일을
  올린다 / Then 거부된다. **아직 B 가 아무것도 안 올린 상태에서도 거부된다**

- S5 (INV-E3, 반대 절반): Given 로그인한 사용자 A / When `<A 의 id>/avatar.png` 로 올린다 /
  Then 저장되고, 다시 올리면 덮어써진다

- S6 (INV-E3, 수정·삭제 쪽): Given A 가 올린 파일과 B 가 올린 파일 / When A 가 B 의 파일을
  지우거나 덮어쓴다 / Then 거부된다

- S7 (INV-E4, 실패경로): Given 로그인한 사용자 / When 이미지가 아닌 파일을 자기 폴더에 올린다 /
  Then 거부된다. 상한을 넘는 파일도 같다

- S8 (INV-E5, 실패경로): Given 로그인한 사용자 / When 지역을 목록에 없는 값으로 바꾸는 갱신을
  보낸다 / Then 거부된다

- S9 (INV-E5, 반대 절반): Given 로그인한 사용자 / When 지역을 목록의 값으로 바꾸거나 비운다 /
  Then 저장된다

- S10 (INV-E6, 실패경로): Given 세션이 없는 요청 / When 프로필 수정 액션을 부른다 /
  Then 데이터베이스에 손도 대지 않고 정해진 문구로 실패한다

- S11 (INV-E7, 실패경로): Given 로그인하지 않은 사람 / When 아바타 버킷을 나열한다 /
  Then 0건이 온다

- S12 (INV-E7, 반대 절반): Given 같은 사람 / When 아바타 파일의 공개 주소를 받는다 /
  Then 200 으로 온다. **둘을 같이 봐야 한다** — 앞만 보면 사진이 아무에게도 안 보이는
  상태도 통과하고, 뒤만 보면 명부가 열린 상태도 통과한다

- S13 (INV-E8, 실패경로): Given 로그인한 사용자 A / When 자기 행의 `avatar_url` 을
  `<B 의 id>/avatar.png` 로 바꾼다 / Then 거부된다

- S14 (INV-E9, 실패경로): Given 로그인한 사용자 / When 이름을 제어문자가 섞인 값으로
  바꾼다 / Then 거부된다

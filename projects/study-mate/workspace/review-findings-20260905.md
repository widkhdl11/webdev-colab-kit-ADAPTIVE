### 중간

**S4. 정책 판정 함수가 그대로 RPC 로 열려 있다**
`0004:15-21` · `0001:453-461` · `0002:406-409`

PostgREST 는 `public` 스키마의 함수를 전부 끝점으로 만들고 실행 권한 기본이 `PUBLIC` 이다.
이 함수들은 `security definer` 라 정책을 통과한 채로 답한다:

```
GET /rest/v1/rpc/is_study_member?p_study_id=<스터디>&p_user_id=<사람>
```

**비로그인 상태에서도 참/거짓이 온다.** 프로필 id 가 전부 공개(`profiles_read using(true)`)이고
스터디 id 도 목록에서 얻어지니, **누구나 "누가 어느 스터디의 멤버인가"를 통째로 재구성할 수 있다**
— INV-Z11 이 좁혀 놓은 것이 이 경로로 우회된다. `increment_post_views` 는 쓰기라
**아무나 아무 글의 조회수를 무한히 올릴 수 있다.**
→ `revoke execute` 로는 못 고친다(정책이 그 권한으로 평가돼 `participants_read` 가 죽는다).
`private` 스키마를 만들어 `alter function … set schema private` 로 옮기고 정책도 같이 고친다.
확인: 익명 키로 위 curl 한 번. 200 에 참/거짓이 오면 열린 것이다.

**S5. 이미 열려 있는 채팅 구독은 강퇴로 안 끊긴다** (일부 추정)
`0006:57-58` 주석 · `ChatRoomView.tsx:80-82`

새로 구독하는 것은 막힌다(주제에서 uuid 를 뽑는 판정이 맞고, `realtime.messages` 에 insert
정책이 없어 가짜 방송도 못 쏜다). 다만 Realtime 은 이 정책을 **채널에 들어갈 때** 판정하고
결과를 연결 동안 들고 있는데, 클라이언트는 `setAuth` 를 마운트할 때 한 번만 부른다.
그래서 **이미 방을 열어 둔 탭은 강퇴된 뒤에도 토큰 만료(기본 1시간)까지 새 메시지를 받는다.**
쓰는 것은 막히고 새로고침하면 안 보인다.
→ 실측으로 갈라야 한다: 탭 둘로 같은 방을 열고 A 가 B 를 강퇴한 뒤 A 가 보낸 말이 B 에 뜨는지.
뜨면 `sync_study_chat` 의 else 가지에서 "나가라" 방송을 쏘고 클라이언트가 채널을 닫게 한다.

**S5b.** 주제 정규식 `'^chat:[0-9a-fA-F-]{36}$'` 가 uuid 모양을 안 본다 — `chat:` + 대시 36개가

## 닫은 것

### 1. 취소를 눌렀는데 눌린 상태가 돌아왔다 (높음 · 보안·코드 리뷰 공통)

`src/features/like-post/api/toggle-like.ts:47` 이 `const { data: mine }` 로 **`error` 를 버리고
있었다.** 조회가 실패하면 `mine` 이 없으니 「아직 안 눌렀다」로 읽혀 insert 갈래로 가고, 그
insert 는 23505 를 삼켜 `{ ok: true, liked: true }` 를 돌려준다. **취소가 안 됐는데 실패도 안
알린다.**

닫은 방법: `error: readError` 를 받아 실패로 돌려준다. 유닛 검사 하나를 같이 넣었고, 그 줄을
지우면 빨간불이 나는 것을 확인했다(아래 변이 근거).

### 2. 눌린 상태를 형광펜 코랄로 칠했다 (높음 · UI 리뷰)

design-rules 의 「형광펜 코딩 규칙」은 8색을 **카테고리 · 모집 상태 · 안 읽음 개수 ·
내 참여 상태** 넷에만 쓰기로 못 박아 뒀다. 「내가 좋아요를 눌렀다」는 그 넷이 아니다.
칠하면 같은 화면에서 코랄이 두 뜻을 진다 — 마감된 모집글을 좋아요 누른 사람의 화면에
코랄 「마감」 배지와 코랄 좋아요 단추가 나란히 뜬다.

**이건 결정이 아니라 규칙 적용이라 내가 정하고 진행했다.** 승인된 어휘 안에서 말하도록
바꿨다: 배경 없음 · 테두리와 글자를 잉크로 · 굵기 700. 색 말고 굵기·테두리로도 갈린다.

> 코랄 채움을 쓰려면 형광펜 허용 목록에 다섯째 뜻을 더해야 하고, 그건 design-rules 를
> 바꾸는 일이라 사람 결정이다. 원하면 그때 되돌리면 된다 — 지금 값은 되돌리기 싼 쪽이다.

### 3. 초점 테두리가 이 단추만 얇았다 (높음 · UI 리뷰)

`.button:focus-visible { outline: 2px … }` 가 전역 규칙(3px 잉크 + 3px offset)을 덮어쓰고
있었다. 앱 전체에서 2px 을 쓰는 곳은 여기뿐이었다. 블록을 통째로 지워 전역 규칙을 쓴다.

확인: 브라우저에서 이 단추에 적용되는 `:focus-visible` 규칙이 전역 하나뿐이고
`3px solid var(--ink) / offset 3px` 인 것을 실제로 읽었다.

### 4. 실패 문구가 낭독기에 안 읽힐 수 있었다 (중간~높음 · UI 리뷰)

둘이 겹쳐 있었다. ① `role="status"` — 사용자가 한 행동이 실패한 것이라 `alert` 다.
② 실패한 순간에 그 요소를 **만들어 넣고** 있었다 — 없던 라이브 영역을 새로 만들면 낭독기가
안 읽는 경우가 있다(같은 이유가 `NotificationBell` 에 주석으로 적혀 있었다).

닫은 방법: `role="alert"` 로 바꾸고 **자리를 항상 둔다**(빈 문자열일 때 `:empty` 로 여백만 죽인다).
브라우저에서 빈 `role="alert"` 가 상주하는 것을 확인했다.

### 5. 액션 결과가 서버 값을 영구히 이겼다 (중간 · 코드 리뷰)

`useActionState` 의 결과는 다음 제출 전까지 남는다. 그래서 탭 A 에서 누르고 탭 B 에서 취소한 뒤
탭 A 가 다시 그려지면 **하트는 켜져 있는데 개수는 0** 인 상태가 하드 새로고침 전까지 유지된다.

닫은 방법: 훅을 가진 부분을 `LikeForm` 으로 떼고, 서버 값으로 만든 `key` 를 붙였다. 서버 값이
바뀌면 컴포넌트째로 갈아 치워져 옛 결과가 남지 않는다.

### 6. 취소 갈래의 실패 처리가 넣는 갈래와 달랐다 (낮음 · 코드 리뷰)

insert 는 `42501` 을 사람 말로 갈랐는데 delete 는 안 갈랐다. `apply-to-study` 와 같은 모양으로
맞췄다. 검사 둘(거부 · 거부 아닌 실패)을 같이 넣었다 — 42501 검사만 있으면 그 아래 일반 갈래를
아무도 안 붙든다는 것을 변이로 확인했기 때문이다.

### 7. 위젯의 좋아요 대체 분기가 죽은 코드였고 주석이 이유를 잘못 적었다 (낮음 · 코드 리뷰)

`PostDetailView` 의 호출자는 하나뿐이고 거기서 `likeAction` 을 항상 넘긴다. 비로그인 갈래는
`LikeButton` 안에서 갈린다. 그런데 주석은 「자리를 넘겨받지 못한 화면(비로그인 등)」이라고 적어
**비로그인에서 그 분기가 도는 것처럼 읽혔다.** 분기를 지우고 `likeAction` 을 필수 prop 으로 올렸다.

### 8. 주석이 경합 결과를 과하게 단정했다 (낮음 · 코드 리뷰)

「그 경우도 한 번 누른 것으로 수렴한다」는 두 요청이 **모두 조회를 먼저 마친** 경우에만 맞다.
조건을 붙였다.

## 검사가 아무것도 안 붙들고 있던 자리 — test-auditor

**이것이 이번 사이클에서 제일 큰 지적이다.** 열한 개가 초록이었는데, 판정 도구가 `admin`
연결로 `likes` 행을 직접 세고 있었다. 원본에서 지우고 원본을 세는 항등식이라 **어떤 구현으로
바꿔도 초록**이었다.

| INV | 감사 전 | 지금 |
|---|---|---|
| L1 | 검증됨 (오류 코드 미고정) | 검증됨 + `23505` 고정 |
| **L2** | **검증 안 됨** | 검증됨 — 앱이 읽는 계산 열과 비로그인 눈을 Then 으로 올렸다 |
| L3 | 부분 (`likes_read` 를 아무도 안 봄) | 검증됨 + 거부 사유 `42501` 고정 |
| L4 | 검증됨 | 검증됨 |
| **L5** | 부분 (이름에 `like` 가 든 열만 봄) | 이름 짓기에 안 기대는 허용 목록으로 뒤집음 |

그 밖에 고친 것 둘:

- **정리를 단언 뒤에서 `afterEach` 로 옮겼다.** 끝줄에 `취소` 를 두면 잡고 싶은 변이가 났을 때
  그 단언이 먼저 던져서 정리가 안 돈다 — 행이 남아 엉뚱한 블록이 같이 빨개지고 원인 귀속이
  흐려진다. 원시 연결로 지워서 정리가 접근 정책에 기대지 않게 했다.
- **유닛 파일의 `describe` 에서 INV 번호를 뗐다.** 두 INV 의 강제 위치는 데이터베이스인데,
  커버리지 게이트는 테스트 이름의 번호를 센다 — 번호를 달아 두면 통합 파일을 통째로 지워도
  「덮였다」로 세어진다.

## 사용자 결정을 받아 닫은 것 — 조회수가 클릭마다 부풀었다 (중간)

**좋아요를 누를 때마다 조회수가 1 올랐다.** 실측 38 → 39 → 40 (누르기·취소 각 1회).

원인은 좋아요가 아니라 구조였다. 페이지 **본문**에 조회 집계 호출이 있어서, 좋아요 액션의
`revalidate` 가 화면을 다시 그릴 때마다 또 세어졌다. 좋아요 개수는 행에서 파생돼 멱등인데
(INV-L2) 같은 클릭이 진짜 카운터를 부풀린 것이다.

조회수의 정의가 걸린 결정이라 사용자에게 올렸고, **「사람이 열어 본 횟수」**로 정해졌다.
새 스펙 `docs/specs/post-view-count.md` (INV-V1, `surfaces: [concurrency]`) 로 고정했다.

고친 방법: 집계를 페이지 본문에서 빼고 클라이언트가 마운트될 때 한 번만 부른다
(`features/count-post-view/`). `postId` 별 가드가 개발 모드의 이중 실행을 흡수한다.

**가드를 세션 저장소로 만들었다가 실측에서 되돌렸다.** 세션 저장소는 새로고침을 넘어
살아남아서, 새로고침해도 조회수가 안 올랐다 — 스펙이 정한 「방문」의 경계보다 넓다.
기억을 페이지가 로드돼 있는 동안만 사는 자리로 옮겼고, 그 차이를 붙드는 검사(S3)를 넣었다.

## 반영하지 않고 사용자에게 올린 것 — 하나

**줄 구분자 U+2028·U+2029 가 제어문자 판정에 안 걸린다** (security-reviewer).
실측했다: `chr(8232) ~ '[[:cntrl:]]'` 거짓 · `chr(8233)` 거짓. 둘 다 줄바꿈 규칙에서는 강제
줄바꿈이라 `pre-wrap` 인 말풍선에서 U+000A 와 같은 일을 한다 — **INV-M4 가 이름 붙인 손해가
그대로 재현된다.**

고치지 않은 이유는 하나다: **INV-M4 의 문면이 「제어문자」이고 이 둘은 제어문자가 아니다.**
넓히려면 승인된 불변식의 문장을 고쳐야 하고, 그건 사람이 정할 일이다(CLAUDE.md 의 강제 승격).
`docs/BACKLOG.md` 에 실측값·고치는 SQL 한 줄과 함께 올려 뒀다.

## 안 붙들려 있는 것 — 밝혀 둔다

- **트리거의 열 범위(`update of last_read_at`)는 어떤 검사도 안 붙든다.** 오늘 동작을 안 바꾸는
  좁힘이라 행동으로 못 잰다. 권한·정책은 목록 단언(S1e·S5d·S5c)으로 고정했는데 트리거는 안 했다.
  백로그에 올렸다 — 고치려면 `pg_trigger.tgattr` 를 읽는다.
- **수정 정책과 삭제 정책 변이 둘이 같은 검사(S5c) 하나에 걸린다.** 둘 다 잡히지만, 어느 쪽이
  열렸는지는 판정이 못 가른다. 이름표가 검사 이름에 붙는 구조라 여기서는 더 못 가른다.


# 사이클 `study-mate-20260910-2` — 막았다가 되돌린 것

## 무엇을 했고 왜 되돌렸나

사용자가 「막는다」로 정해서 `0022` 로 제약을 걸고 스펙 INV-M4 의 문면을 「제어문자」에서
「줄을 강제로 바꾸는 글자」로 넓혔다. 그 뒤 **아무도 안 잰 것을 쟀고, 근거가 뒤집혔다.**

Chromium 에서 `<p>` 높이(대조군 포함, 2026-09-10):

| 넣은 글자 | white-space | 높이 |
|---|---|---|
| 없음(기준) | normal | 26px |
| **U+000A (대조군)** | **pre-wrap** | **51px** — 검사가 실제로 작동한다 |
| U+2028 | pre-wrap | 26px |
| U+2029 | pre-wrap | 26px |
| U+000B(수직탭) | pre-wrap | 26px |
| U+0085(NEL) | pre-wrap | 26px |

글자는 DOM 에 실제로 들어가 있다(코드 포인트 8232·8233 확인). **CSS 에서 줄을 바꾸는 것은
U+000A 하나뿐이다** — UAX #14 의 「강제 줄바꿈」과 CSS 의 「segment break」가 같은 집합이
아니다. 사용자에게 다시 올려 「되돌린다」를 받았다.

**되돌린 것**: `0022` 파일 · INV-M4 문면 · S4d · 앱 판정의 U+2028 갈래 · 변이 둘 ·
복구 목록/방벽의 0022 줄. 남긴 것은 **측정값과 기준 한 줄**이다 —
「눈에 안 보이는 글자를 막을지는 그 불변식이 이름 붙인 손해를 실제로 내는가로 가른다」.

**리뷰어가 잡은 것**: 앱 판정이 스키마보다 좁아져서, 붙여 넣은 U+2028 이 데이터베이스까지 가

그리고 **강제 줄바꿈은 유니코드에 일곱 개뿐이고 0021 이 다섯을 이미 덮는다**는 것,
**0015(이름)·0020(제목)도 같은 종류의 손해를 상한만큼 작게 받는다**는 것을 확인해 줬다 —
둘 다 백로그의 합쳐진 항목에 적었다.

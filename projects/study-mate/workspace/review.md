## 이 리뷰에서 가장 크게 드러난 것

### ① 자기에게만 보이는 버튼을 눌렀는데 404 (code-reviewer, 높음)

호스트가 지운 스터디의 모집글은 **그 사람에게는 계속 보인다** — `study_is_visible` 이
「안 지워졌거나 내가 호스트」이기 때문이다. 그런데 수정 화면은 그 글을 안 연다(「내가 쓴
모집글」 목록이 이미 빼 둔 것과 같은 판단). 두 판단이 갈려서, 상세 화면에 작성자에게만
보이는 「모집글 수정」이 뜨고 누르면 404 가 났다.

`canEditPost(detail, userId)` 를 엔티티에 두고 상세 화면이 그것을 쓴다. **브라우저에서
재현하고 고친 뒤 다시 확인했다** — 스터디를 지운 상태로 상세를 열면 링크가 사라진다.

### ② 실패하면 사용자가 적은 것이 사라진다 — 실측했고 고쳤다 (백로그 항목 + code-reviewer)

`<form action={…}>` 은 액션이 끝나면 제어되지 않는 입력칸을 초기화한다. 액션이 실패를
**반환**하면(던지지 않는다) React 는 정상 종료로 본다.

브라우저에서 재현했다: 본문에 새 문장을 적고 제목을 비워 제출하니 오류 문구는 떴는데
**본문이 저장돼 있던 옛 문장으로 되돌아가 있었다.** 작성 폼은 `defaultValue` 가 없으니
되돌아가는 것이 아니라 **빈칸**이 된다 — 4000자가 통째로 사라진다.

수정 폼과 작성 폼을 제어 컴포넌트로 바꾸고, 같은 방법으로 다시 실측해 남는 것을 봤다.
백로그에 「실측 안 함」으로 열려 있던 항목이 이 자리였다.

### ③ 수정 화면을 여는 판독기를 아무도 안 붙들고 있었다 (code-reviewer · test-auditor, 중간)

`readPostForEdit` 의 `.eq("author_id", userId)` 와 `.is("study.deleted_at", null)` 을
**둘 다 지워도 전 스위트가 초록불**이었다. 이 사이클의 결정 둘이 코드에만 있고 검사에는
없었다. 검사 일곱과 변이 둘을 붙였다.

### ④ 「거부는 오류가 아니라 0행」이 측정된 적 없는 전제였다 (test-auditor, 중간)

이 기능의 실패 설계 전체가 그 위에 서 있는데, 주장하는 것이 유닛의 가짜 데이터베이스
하나뿐이었다. 실제로 오류가 온다면 사용자는 "고칠 수 있는 모집글이 아닙니다"가 아니라
"잠시 뒤 다시 시도해 주세요"를 읽는데, **그 상태에서도 유닛은 전부 초록불이다.**

실제 로컬 Postgres 에 그 체인을 그대로 대고 `{data: null, error: null}` 을 단언하는 통합
검사 둘(실패경로 + 반대 절반)을 붙였다.

### ⑤ 검사가 주장하는 것을 검사가 못 가르고 있었다 (security-reviewer · test-auditor)

가짜 데이터베이스가 돌려주는 id 와 폼이 보내는 `postId` 가 **같은 값**이었다. 그래서
목적지·성공 값·캐시 경로를 폼 값으로 바꿔도 전부 통과했다 — 검사 파일 머리말이 「열린
리다이렉트가 아니다」를 붙든다고 적어 둔 그 자리다. 상수를 둘로 가르고 변이 둘을 등록했다.

INV-Z4 도 같은 모양이었다. 구현에 폼의 작성자 필드를 읽는 코드가 아예 없어서 단언 둘이
「그런 개념이 없다」로 자동 만족돼 있었다. 폼 값을 인가에 끼우는 변이를 등록했다.

### ⑥ 오류 문구와 로그로 새는 자리 셋 (security-reviewer)

- 모집글 상세만 `db-error.ts` 의 계약 밖에 있었다 — uuid 가 아닌 주소로 들어오면 Postgres
  원문(`invalid input syntax for type uuid: "<보낸 값>"`)이 그대로 실려 나가고, 없는 글은
  404 인데 형식 오류만 500 이라 응답이 갈렸다. `throwDbError` + `canonicalUuid` 로 닫았다.
- `throwShapeError` 가 행 원문을 로그에 찍고 있었다 — 거기 사람이 쓴 본문이 통째로 들어
  있다. 값 대신 키와 타입만 찍는다(판독기 넷이 같이 닫혔다).
- `.eq("author_id", …)` 를 남긴 근거 주석이 사실과 달랐다("정책에만 맡기면 오류로 온다").
  이 레포는 주석을 결정의 근거로 쓰므로 고쳤다.

### ⑦ 값이 두 벌인 자리 넷 (code-reviewer · ui-reviewer)

상한만 엔티티로 옮기고 **규칙은 두 벌로 남아 있었다**(작성·수정에 문구까지 같은 검사 여섯
줄). `validatePostText` 로 합쳤다. `PathDeps` 의 프로덕션 값도 바이트까지 같은 닫힘 함수가
둘이라 `shared/lib/action-deps.ts` 로 모았다. 폼 카드 껍데기(다섯 벌)는 `FormCard` 로,
작성 화면 둘의 페이지 껍데기는 `FormPage` 로 모았고 `--space-28` 토큰을 만들었다.

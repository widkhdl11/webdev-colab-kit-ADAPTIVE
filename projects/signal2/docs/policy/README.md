# 이 프로젝트에서 쌓인 결정 규칙

되돌리기 싼 결정을 사람에게 묻지 않고 내릴 때 근거가 되는 문장들이다. 여기 있는 것은
이 프로젝트에서만 통하는 성향이고, 어느 프로젝트에나 통하는 성향은 따로 있다.

규칙 하나가 파일 하나다. 형식은 이렇다.

```yaml
---
id: 파일명과 같은 식별자
scope: [이 규칙이 근거가 되는 영역]
status: confirmed | provisional
last_applied: 마지막으로 이 규칙을 근거로 쓴 작업 구간의 이름
---

규칙 본문. 산문으로 자유롭게 쓴다.
```

`---` 로 둘러싼 윗부분 네 줄만 기계가 값으로 읽고, 본문은 읽는 쪽에 통째로 넘어간다.
본문에서 값을 긁어내는 규약은 만들지 않는다.

## 여기 손으로 쓰지 않는다

같은 판단이 두 번 반복되면 `provisional` 로 자동 승격되고, 검토에서 뒤집히지 않으면
`confirmed` 가 된다. 한 번뿐인 판단은 승격하지 않는다 — 우연일 수 있어서다.

뒤집을 때는 파일 하나를 지우면 끝이다.

## 여기 들어올 수 없는 것

**시각 정체성은 여기 오지 않는다.** 색·글자 크기·간격의 리듬·움직임·레이아웃의 성격은
디자인 기준 문서가 정본이고, 그쪽에서만 바뀐다. 규칙은 본성상 수렴시키는데 시각은
프로젝트마다 달라야 하기 때문이다.

여기 올 수 있는 화면 관련 규칙은 시각이 아니라 **쓰임새의 패턴**까지다 — 폼 검증을 언제
보여줄지, 기다리는 동안 무엇을 띄울지, 오류 문구의 말투, 아무것도 없을 때의 화면 같은 것.

**되돌리기 비싼 결정도 여기 오지 않는다.** 데이터 모델, 인증 방식, 외부 서비스 선택,
비용이 드는 것. 이것들은 반복이 몇 번이든 규칙이 되지 않고 사람에게 올라간다.

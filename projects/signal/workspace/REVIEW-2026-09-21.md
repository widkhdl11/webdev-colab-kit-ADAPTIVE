## 1순위 — 데이터가 조용히 사라진다

- **저장 순서가 거꾸로다.** `api/ports.ts` 의 `saveHotIssue` 가 중요도·판정시각을 먼저 쓰고
  종류를 나중에 쓴다. 중간에 죽으면 앞 행은 판정시각이 차서 다음 주기에 안 잡히는데
  **종류가 영영 빈다.** 순서를 뒤집는다(종류 → 중요도 → 판정시각). 표시가 마지막이어야
  어디서 끊겨도 다음 주기가 다시 묻는다.
- **상한에 잘린 글이 영구 제외된다.** 스펙은 "상한에 부딪히면 **그때만** 자른다"인데,
  판정시각이 찼으므로 다음 바퀴 후보에서도 빠진다. 재진입 경로를 만든다 — 이미 중요도가
  있는 글은 모델을 다시 안 부르고 배정 후보로만 태우면 요금이 0이다.
- **나중에 잘릴 글 때문에 다른 글이 빠진다.** 「이미 뽑힌 목록」은 배정 후보가 된 시점에
  쌓이는데 실제 배정은 바퀴 끝에 정해진다. A가 앞 청크에서 후보가 되면 뒤 청크의 B가
  "같은 사건"으로 빠지고, 그 뒤 A가 잘린다 → **그 사건이 그날 하나도 안 남는다.**
- **행별 update 120번.** 중요도는 값이 0~3 넷뿐이라 묶어서 최대 네 번이면 된다.
  부분 적용 문제도 같이 사라진다.

## 2순위 — 판정을 조작당할 수 있다

- **기사 제목이 지시문 본문에 검사 없이 실린다.** `build-hot-issue-prompt.ts` 의
  「이미 뽑힌 목록」. 제목에 개행이 있으면 그 뒤 글자가 우리 규칙 줄과 똑같이 생긴 새 줄이
  되고, 감싼 따옴표는 값 안의 따옴표가 자기가 닫는다. 투고형 소스에 심으면 두 홉으로 닿는다.
  성공하면 그날 핫이슈가 통째로 0건이 되는데 **화면에는 "한가했다"로 보인다.**
  조립 지점에서 거른다(개행·따옴표 든 제목은 통째로 버린다, 길이 상한). 주입 테스트를 쓴다.
  옆자리 키워드 앵커는 쓰기·읽기 두 겹으로 막혀 있다 — 같은 수준으로 맞춘다.
- **`같은사건` 만 느슨하게 읽는다.** 질문 셋은 참/거짓이 아니면 응답 전체를 버리는데
  이 칸만 `=== true` 다. 모델이 `"예"` 로 답하는 날 중복 제거가 한 건도 안 걸리는데
  리포트는 정상으로 보인다.
- **`listPickedTitlesToday` 에 행 상한이 없다.** 지금은 하루 상한 10이라 안 닿는다.

## 3순위 — 검사가 겉만 본다 (전부 green인 채로 기능이 죽는다)

각 줄은 "이렇게 바꿔도 테스트가 전부 통과한다"는 뜻이다.

- `toGate` 를 `return null` 로 → **모든 뱃지가 사라지고 핫이슈가 항상 빈 목록.** 테스트 0건
- 조회 컬럼에서 `gate` 삭제 → 같은 증상
- `saveHotIssue` 의 종류 저장 블록 삭제 → 종류가 DB에 한 건도 안 남는다
- `assignGates` 를 `gate: null` 로 → 배정이 저장 안 된다
- `listPickedTitlesToday` 의 문 조건 삭제 → 오늘 모든 제목이 "이미 뽑힘"으로 실려 **매일 0건**
- 파이프라인에서 핫이슈 단계 통째로 삭제 → 아무도 모른다
- 중요도 0~3 제약 삭제 → 단어만 보는 검사라 통과
- 종류 표의 RLS 켜는 줄 삭제 → **publishable 키로 쓰기 가능**(정책 개수는 그대로 4)
- 상한에서 「이미 뽑힌 건수」를 빼기 → 스펙이 이름 대고 금지한 "어제 몫을 오늘이 이어받는다"
- 상한을 0으로 → 상한이 무력화되는데 잘린 건수는 0으로 보고된다
- 하루 상한 값(10)을 100으로 → 상수를 못박은 검사가 없다

**근원**: DB 어댑터(`api/ports.ts`)에 테스트가 하나도 없다. 단계 테스트가 포트를 전부 가짜로
갈아 끼우니 실제 코드가 한 줄도 안 돈다. `queries.test.ts` 의 체이닝 가짜를 재사용해
어댑터 테스트를 신설한다.

**같이**: 이 스키마 검사 파일에만 「위반을 심어 잡히는지 보는 항목」이 빠져 있다.
`schema-contract.test.ts` 의 방식대로 판정을 순수 함수로 빼고 넷을 심는다.

## 4순위 — 화면 [세 자리 이후 다시 판단]

- **판정 0건인 날 "아직 모인 소식이 없습니다"가 뜬다.** 소식은 수십 건 들어와 있다.
  승인된 규칙이 문구를 둘로 못박아 뒀으므로 세 번째 문구는 사용자 승인 대상이다.
- **목록이 줄어든 것을 스크린리더가 모른다.** 눌림(`aria-pressed`)만 전해지고 결과 수는 안
  전해진다. 「더 보기」가 쓰는 라이브 리전에 `총 N건 중 M건` 을 흘린다.
- **「더 보기」 버튼이 DOM에서 통째로 사라진다.** 승인된 규칙은 "다 불러온 뒤에도 사라지지
  않는다 — 문구를 바꾸고 `aria-disabled` 로 표시한다"이다. 바깥 조건이 언마운트한다.
- **세그먼트 그룹 이름이 아직 "정렬 방식"이다.** 이제 정렬만 하지 않는다.
- **`feed-controls.tsx` 주석 네 문장이 전부 거짓**이 됐다(거른다 / 저장된 판정을 본다 /
  두 쪽이 다른 글을 보여준다 / 이미 물려받았다).
- **뱃지 중복** — 핫이슈 자리에서는 모든 카드에 딱지가 붙어 정보가 0이 된다.
- **정렬과 자리가 얽혀 있다.** 지금은 정렬 모드가 보여줄 집합까지 정해서, 핫이슈를 최신순으로
  볼 방법이 없다. 자리(`segment`)와 순서(`sort`)를 따로 받는다 — 세 자리를 만들려면 필수다.

## 5순위 — 설계 정리

- **`placeArticle` 이 죽은 코드다.** 종류가 화면까지 안 온다(조회 컬럼에 종류 조인 없음,
  목록 타입에 칸 없음). 세 자리를 만들면 이 함수가 실제로 쓰이고 이 항목이 닫힌다.
- **같은 판정이 세 군데 있고 셋째만 답이 다르다.** 종류가 빈 글을 `placeArticle` 은
  "핫이슈 아님"이라 하는데 카드와 목록은 핫이슈로 친다. 판정을 한 자리로 모은다.
- **스펙 문장이 구현과 다르다.** `hot-issue.md` 의 참조 절이 "기존 핫뉴스 뱃지는 그대로
  둔다"인데 교체했다. 그 결과 `markTrending`·`TRENDING_TOP_N`·`isTrending` 이 매 조회마다
  계산되는데 읽는 화면이 없다. 문장을 고치면서 이 계산을 걷어낼지 정한다.
- **「어느 질문이 참인지」가 저장되지 않는다.** 스펙 시나리오가 요구하는데 저장 단계가 버리고
  DB에 칸도 없다. 이 값이 없으면 첫 2주 표본 검토를 할 수 없다. → 사용자 결정 대기
- **`computeIssueScore` 가 랭킹 점수 계산을 줄 단위로 베꼈다.** 반감기를 같이 써야 한다고
  주석에 적어 두고 붙드는 장치 없이 복사했다. 위임으로 바꾼다.
- **리포트가 저장되지 않는다.** 잘린 건수·뽑힌 건수가 수집 기록 표에 안 들어가 대시보드에서
  "매일 상한에 부딪히고 있나"를 되짚을 수 없다. 스펙이 그 기록을 요구한 이유가 그것이다.
- **실패 이유 상한 상수가 두 벌**이다(핫이슈는 공용 상수, 키워드는 파일 안 사본).
- **저장 시각이 바퀴의 기준 시각이 아니라 벽시계**다.

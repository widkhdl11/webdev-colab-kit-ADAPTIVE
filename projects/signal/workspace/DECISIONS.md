# DECISIONS — signal

트레이드오프가 있던 결정만 한 줄씩. 이유의 상세는 PRODUCT.md / 스펙.

- **수집 구조 = 런타임 + Supabase** (정적 빌드타임 아님): 랭킹·상태 저장 등 기능 우선. 정적보다 무겁고 유지비 있음.
- **신호 선별 = 랭킹까지 포함** (단순 최신순 아님): '뜨는 것' 정렬이 핵심 가치. 점수가 시변·파생 → /spec 예정.
- **상세 = 원문 전문 표시** (링크아웃 아님): 사이트 안에서 바로 읽기 우선. 본문 추출 난이도 + 저작권 표면 감수. _(2026-08-09 단서: "전문"은 **얻어졌을 때**다. 봇을 막는 사이트에서는 추출이 실패하고(OpenAI 403 실측), 그때 상세는 없다고 밝히고 출처로 보낸다 — 아래 INV-S5 항목)_
- **읽음·북마크 = MVP 제외, 후순위**: 범위를 좁혀 수집·랭킹·필터에 집중.
- **페이지 = 피드 + 상세 2개** (소스 관리 화면 없음): 소스 목록은 설정파일로.
- **프레임워크 = Next.js (App Router)** (Vite/SPA 아님): 웹 노출(SSR/SEO) + 기존 Next+FSD 경험. Vite→Next 전환은 signal 한정, 전역 게이트 불변. 프로파일 nextjs-fsd(pages 제거·app 통일, provider는 shared).
- **원문 표시 방식 = sanitize 후 렌더** (2026-08-02 spec): 화이트리스트 sanitize + html-react-parser. iframe 격리는 X-Frame-Options·높이제어 문제로 탈락. dangerouslySetInnerHTML 금지(게이트). → content-safety.md
- **요약 = AI 생성(Claude)** (2026-08-02 spec): RSS 요약 품질 편차 회피, 한국어 통일. 실패 시 null 적재 후 재시도, summary IS NULL만 재생성(비용). 요약은 신뢰경계 밖—원문이 진실. @anthropic-ai/sdk는 요약 구현 시 설치.
- **랭킹 = 시간감쇠 × 소스 weight(설정파일)** (2026-08-02 spec): 최신성만이면 랭킹=최신순이 돼 '뜨는 것' 가치 소멸 → 정적 소스 weight를 곱함. 앵커 패턴(점수 저장 안 함, 조회 시 계산 → 배치 사고·낡음 원천봉쇄). 외부 인기신호(HN points 등)는 시변 외부값이라 재수집 부담 → MVP 제외. → ingestion-ranking.md
- **중복제거 = 정규화 원문 URL** (2026-08-02 spec): utm_*·fbclid 등 추적파라미터·fragment 제거, 소문자화. 재수집은 upsert(중복 안 쌓임).
- **시각 방향 = 톤 a 인디고 + 밝은 회색 페이지 위 밝은 카드** (2026-08-02 checkpoint 1차): 레퍼런스 biko 는 흰 페이지+회색 카드였으나 "너무 하얘서 눈이 아프다" 피드백으로 명암을 뒤집음. 매일 훑는 리더라 눈부심이 비용. 부수효과로 카드 분리가 뚜렷해짐. 메타색은 그만큼 한 단계 낮춰 대비 재확보(#6A6F77→#656A72).
- **읽음 표시 = MVP로 승격** (2026-08-02, 위 "MVP 제외" 결정을 뒤집음): 사용자 요청. 로그인이 없어 브라우저 로컬에만 저장 → 서버·스키마 변경 없음, 기기 간 동기화 없음. 값이 싸서 승격이 가능했던 것. 흐릿하게 하되 대비 4.5:1 유지·호버 복원(읽은 글도 다시 찾을 수 있어야).
- **피드 = 날짜 그룹 1차, 정렬 2차** (2026-08-02): 수집이 매일 아침 1회 배치라 "오늘 뭐 왔지"가 기본 질문. 점수가 날짜를 가로지르면 하루 단위로 훑을 수 없음. 대안(정렬 1차·평면 목록)은 '뜨는순'에서 날짜가 뒤섞여 탈락. 갱신 주기가 바뀌면 이 결정도 다시 본다.
- **읽음 기록 시점 = 상세 화면 마운트** (2026-08-06, 목록 클릭 아님): 클릭 시점에 찍으면 이동이 실패했을 때(라우트 부재·네트워크) 읽지도 않은 글이 흐릿하게 굳고 localStorage라 새로고침해도 안 풀린다. PRODUCT의 "이미 **연** 소식" 정의와 어긋남. 대가는 상세를 열자마자 읽음이 된다는 것(스크롤 여부·체류 시간은 안 본다) — 개인용이라 그 정밀도가 필요 없다.
- **랭킹 점수·'뜨는 중'은 화면이 만들지 않는다** (2026-08-06): 계산식이 planned/ingestion-ranking.md 에 파킹된 상태라, 더미 데이터가 `score`·`isTrending` 을 들고 오고 화면은 표시만 한다. 대가는 지금 값이 가짜라는 것. 대신 스펙을 켤 때 화면을 안 고쳐도 된다. (열린 질문이었던 '그룹 안 상위'의 기준은 2026-08-09 에 정해짐 — 아래)
- **'뜨는 중' 판정 = 필터·정렬을 걸기 전 목록 기준, 날짜 그룹 안 상위 `TRENDING_TOP_N`개(기본 3)** (2026-08-09, INV-R5 신설): 대안은 필터 결과 안에서 다시 상위를 뽑는 것이었는데, 그러면 **같은 글이 필터에 따라 뱃지가 붙었다 떨어져** 뱃지가 무슨 뜻인지 알 수 없게 된다. 대가는 태그 필터를 걸면 결과 상단에 뱃지가 하나도 없을 수 있다는 것 — "지금 전체에서 뜨는 것"이라는 뜻을 지키는 쪽을 택했다. 개수는 어느 문서에도 없었다(design-rules 는 "그룹 안에서의 상위"까지만 정함). 참/거짓을 판정하려면 수가 필요해서 설정값으로 뒀다.
- **카드 밀도 = A(숨 쉴 곳) + B(출처 표식)** (2026-08-06 비교 시안 승인): "너무 글자글자글자~" 피드백. 요약 3→2줄로 정보량을 줄이고 여백을 키웠다 — 훑는 속도가 목적이라 요약 한 줄보다 밀도가 비싸다는 판단. 출처 이니셜 원은 요소를 하나 늘리는 대가로 훑을 기준점을 얻는다(색은 안 씀 — 포인트색은 "아직 안 본 것" 전용 규칙 유지). C안(제목 17px·요약 연하게)은 효과는 있으나 타이포 단계를 하나 더 늘려 보류.
- **아웃바운드 URL 스킴 = 허용 목록, 본문과 출처를 나눔** (2026-08-06 INV-D6 신설): sanitize 는 본문만 훑으므로 본문 밖 필드인 `sourceUrl` 은 방벽 밖이었다. 본문 링크는 `http·https·mailto`(원문에 이메일 링크가 온다), 출처 링크는 `http·https` 만 — 출처는 웹 주소라 mailto 를 받을 이유가 없고, 넓게 잡으면 나중에 왜 넓은지 아무도 설명 못 한다. 스킴 목록의 정본은 한 곳(`features/content-render/lib/url-safety.ts`). **URL 정리(제어문자·공백 제거)는 보안 장치가 아니다** — 문자를 지우기만 하므로 허용 범위를 넓히는 방향으로만 작동한다. 실제 역할은 멀쩡한 URL 을 잃지 않는 것과 "검사한 문자열 = 렌더할 문자열"을 맞추는 것.
- **AI 요약 박스 = 16px** (2026-08-06 checkpoint, 15px 에서 올림): `ui-layers` 의 "본문 16px 이상" 하한을 요약도 지킨다. 하한 예외의 근거가 "목록 미리보기는 본문이 아니다"인데 상세의 요약은 실제로 읽는 여러 문장이라 예외에 해당하지 않는다. 대가는 원문(17px)과 1px 차이밖에 안 남는다는 것 — 위계를 면·색·왼쪽 포인트선·줄높이 네 축으로 옮겨서 갚았다. 함께 "하한이 걸리는 자리(본문)와 안 걸리는 자리(문장에 딸린 부속: small·figcaption·첨자)"를 문서에 명시했다. 예외 목록이 짧았던 것이 이 혼란의 원인이었다.
- **원문 제목 h1~h6 = 크기 두 값(20/17) + 굵기·색·여백** (2026-08-06 checkpoint): 스펙이 허용하는 태그에 시각 기준이 없어 구현이 값을 발명할 수 없었다. "단계를 늘리지 말고 굵기로" 규칙을 지키려면 17px 아래로 못 내려간다(제목이 본문보다 작아지면 위계가 뒤집힌다). 그래서 h4~h6 은 굵기를 600 으로 고정하고 색 사다리(`--text→--text2→--meta`)로 나눴다. 원문 h1 은 페이지 제목(28px)과 경쟁하지 않게 20px 로 누르고 점선 밑선으로 구획만 표시. (h1 이 둘이 되는 문제는 2026-08-08 에 결론 — 아래)
- **`h1` 이 둘인 것을 그대로 두고, 색과 레이아웃으로 가른다** (2026-08-08, 2026-08-06 미결 해소): 파서에서 원문 제목을 한 단계 강등(h1→h2)하는 안을 검토했으나 채택 안 함 — HTML5 에서 h1 이 여럿인 건 위반이 아니고, 강등은 문서 개요를 위해 **원문 마크업을 우리가 고쳐 쓰는 일**이다. 대신 눈으로 갈리게 했다: 우리가 붙인 페이지 제목은 포인트색(`--accent`), 출처가 쓴 제목은 먹색 + 왼쪽 세로선. **대가는 스크린리더**다 — 색과 선은 시각 신호라 제목 목록에는 안 나타나고, 거기서는 두 h1 이 여전히 같은 층으로 보인다. 이 대가를 알고 고른 것이다. 부수적으로 design-rules 의 "포인트색은 면적을 최소로" 규칙이 페이지 제목까지 넓어졌다(전면 배경 금지는 유지).
- **원문 이미지의 `width`·`height` 를 허용한다 — 조건 넷을 다 만족할 때만** (2026-08-08, INV-D2 확장): 자리를 미리 비워 이미지가 뜰 때 아래 글이 밀리는 것을 막는다. 조건은 ① 둘 다 있음 ② 둘 다 양의 정수 ③ 비율 10:1 이내 ④ 각 값 20000 이하. 하나라도 어긋나면 **둘 다** 버린다(하나로는 비율을 못 구한다). ③·④ 가 필요한 이유는 정수 검사만으로는 `width="1" height="99999"` 같은 거짓 치수를 못 막기 때문 — 믿고 자리를 비우면 높이 0 에서 튀어오르는 것보다 나쁜 빈 공간이 생긴다. **대가는 화이트리스트에 "값도 보는" 규칙이 처음 생긴 것**이고, 그래서 경계(이 둘뿐)를 스펙·코드 양쪽에 못 박았다. 치수 없는 이미지는 CSS 가 16:9 로 대신 예약한다. 함께 **`src` 를 잃은 이미지는 태그째 버린다**(빈 상자가 "여기 그림이 있다"고 거짓말하지 않게).
- **INV-D6 스킴 목록의 정본은 `shared` 가 아니라 `features/content-render`** (2026-08-08, 스펙 문구를 코드에 맞춤): 스펙이 "shared 의 공용 URL 가드"라고 적었지만 구현은 features 에 있었고 **구현 쪽이 맞다.** 두 목록을 가르는 근거("출처는 웹 주소라 mailto 를 받을 이유가 없다")가 도메인 판단이라 shared 규칙(도메인 지식 금지)과 어긋난다. 도메인 없는 조각(문자열 정리·스킴 추출)만 `shared/lib/url.ts` 에 남았다 — 경계는 이미 옳았고 문서만 낡아 있었다.
- **포커스 아웃라인에 라운드를 주지 않는다** (2026-08-06, 기존 규칙 정정): `a:focus-visible` 의 명시도가 컴포넌트 클래스를 이겨서, 키보드 포커스가 닿는 순간 카드가 12px→6px, 알약 버튼이 999px→6px 로 각지게 변하고 있었다. "호버·포커스에서 완전 복구"와 정면으로 어긋난다. `--r-focus` 토큰도 없앴다 — 남겨두면 다음 화면이 되살린다.
- **소스 식별자를 표시 이름과 분리(`sourceId`)** (2026-08-09, INV-R4 구현 중): weight 조회 키를 표시 이름으로 두면 "Anthropic 블로그"를 "Anthropic"으로 다듬는 순간 그 소스의 모든 글이 기본 배수로 떨어져 순위가 조용히 바뀐다. 대가는 항목마다 필드가 하나 늘고 더미·테스트 픽스처를 전부 고쳐야 했던 것. 함께 **모르는 소스의 weight 를 0 이 아니라 1 로** 정했다 — 0 이면 점수가 0 이 되어 그 소스 글이 피드에서 사라지고, 소스 id 오타 하나의 증상이 "글이 안 보인다"가 되어 원인을 못 찾는다.
- **저장 모양과 조회 모양을 타입으로 가름(`StoredArticle`)** (2026-08-09, INV-R1): `score`·`isTrending` 을 뺀 타입에 `never` 자리를 둬서 조회 결과를 그대로 저장하는 코드가 컴파일되지 않게 했다. 규칙을 주석으로만 두면 언젠가 한 줄이 조용히 통과한다 — `ArticleListItem` 이 본문에 대해 쓰는 것과 같은 장치다. 더미 데이터도 이 모양으로 바꿔, 화면이 실제로 `rankFeed` 를 거치게 됐다.
- **DB 강제 불변식은 두 층으로 검증** (2026-08-09, INV-C1·R1·T1·T2): SQL 텍스트 검사(오프라인, 기본 `npm test`) + 실제 DB 검사(`test:integration`, 별도 config). 가짜 저장소만 쓰면 "우리 fake 가 unique 를 흉내낸다"를 검증하게 되고, DB 만 보면 왜 그렇게 생겼는지가 코드에 안 남는다. 통합 테스트는 환경변수가 없으면 **건너뛰지 않고 실패한다** — 조용히 건너뛰면 "통과했다"로 읽힌다.
- **타임존 없는 발행시각은 UTC 로 읽는다** (2026-08-09, 같은 날 뒤집은 결정): 처음엔 "존을 모르면 추측하지 말자"며 수집시각으로 대체하게 만들었다. 사용자가 필요한 정밀도를 밝히자("대략적인 날짜만 — 언제 나온 소식인지") 그 판단이 뒤집혔다 — **대체하면 일주일 전 글이 오늘 날짜 묶음에 들어간다.** UTC 로 읽으면 최악이 하루 어긋나는데, 목적이 "언제 나온 소식인지"라면 완전히 틀리는 쪽이 훨씬 나쁘다. 대가는 KST 자정 근처 글의 날짜 묶음이 하루 밀릴 수 있다는 것. **정밀도 요구를 모른 채 안전해 보이는 쪽을 고르면 틀릴 수 있다** — "모르면 버린다"가 늘 보수적인 선택은 아니다. 함께 `Date.parse` 에 맡기지 않는 것도 정했다: 존 없는 값을 로컬로 읽어 서버와 브라우저가 갈린다.
- **요약 표시 = AI 요약 → 출처 요약글 → 없음, 라벨은 값에 맞춘다** (2026-08-09, INV-S2 확장): "요약은 거의 무조건 나와야 한다"는 요구를 받았는데, 그대로 하면 본문 없는 항목에서 모델이 제목만 보고 지어낸다(INV-S1 위반). 그래서 요구를 **근거 확보 → 요약**으로 갈랐다. 출처가 준 요약글은 `summary` 가 아니라 `source_excerpt` 라는 **다른 칸**에 넣는다 — 같은 칸이면 "요약이 없다"는 신호가 사라져 AI 요약이 영영 안 생긴다(INV-S3 의 재시도 조건이 무력화). 화면은 어느 쪽인지 함께 알린다: 출처 글을 "AI 요약"이라 부르면 표시가 거짓이 된다.
- **근거 없으면 요약을 시도하지 않는다** (2026-08-09, INV-S3 조건 추가): 근거는 본문 또는 출처 요약글. 없으면 호출 자체를 건너뛰고 `skippedNoEvidence` 로 **실패와 따로 센다** — 재시도해도 소용없는 것과 다시 해볼 만한 것은 다른 이야기고, 섞으면 실패 건수가 계속 쌓여 진짜 문제를 가린다.
- **본문 추출을 수집 단계에 넣는다 (INV-S5 신설)** (2026-08-09): 왜 필요한지는 실측이 정했다 — HN 은 링크 모음이라 본문을 가진 적이 없고(요약글도 링크뿐), OpenAI 는 요약글은 주지만 원문이 403 이다. **소스마다 되는 길이 달라서** 요약글과 추출이 둘 다 필요하다. `@mozilla/readability` + `jsdom`, 브라우저 UA. 실패(403·타임아웃·본문 없음)는 항목 단위로 격리한다 — 봇 차단은 정상 경로지 예외가 아니다. 추출 결과는 신뢰 경계 밖이라 화면에서 sanitize 를 거친다. **추출을 요약보다 먼저** 돌려 이번 주기에 채운 본문이 곧 근거가 되게 했다.
- **태그 = 제목 키워드 규칙 + AI 분류의 합집합** (2026-08-09, INV-T3 신설): 규칙만 쓰면 표현이 다른 글을 놓치고, AI 만 쓰면 **요약이 실패한 항목에 태그가 하나도 안 붙는다**(요약과 분류를 한 번에 부르므로). 규칙은 적재 때, AI 는 요약 때 붙고 `item_tag` 기본키가 중복을 막는다. 목록 밖 태그는 버린다 — AI 가 새 태그를 만들면 필터가 늘어난다. 낱말 경계로 찾아 `toolbar`→'툴' 같은 오분류를 막되 영어 복수형은 잡는다. 태그 목록 자체는 아직 임시다.
- **RSS 가 본문을 안 주는 건 AI 차단이 아니다** (2026-08-09 실측): robots.txt 에 AI 크롤러 규칙이 없다(OpenAI·HN 둘 다 `User-agent: *` 뿐). HN 은 애초에 링크 모음이고, OpenAI 는 요약만 주는 피드다(AI 이전부터 흔한 트래픽 유도 방식). 원문 403 은 Cloudflare 의 봇 차단으로 브라우저 아닌 요청 전반에 걸린다. **추측하지 않고 확인한 덕에** 소스별로 다른 처방(요약글 vs 추출)이 나왔다.
- **제목을 한국어로 옮긴다. 본문 전문 번역은 지금 안 한다** (2026-08-10, INV-S6 신설): 사용자가 영어를 읽지 못한다는 것이 계기였다. 요구는 "본문 번역"이었는데 숫자가 답을 바꿨다 — **원문 본문이 있는 항목이 101건 중 42건뿐**이고(수집 당시엔 11%), 출력 토큰이 본문 길이만큼 나와 요약의 5~6배가 든다. 반면 제목은 훑을 때 제일 먼저 걸리는 자리인데 요약만 한국어라 시선이 언어를 두 번 건너뛰고 있었고, **이미 부르는 요약 호출의 응답에 필드 하나를 더하는 것**이라 추가 비용이 거의 0이다. 대가는 본문이 여전히 영어라는 것 — 본문을 읽는 일이 잦아지면 그때 다시 본다. 원문 제목은 덮지 않고 다른 칸(`title_ko`)에 넣는다: 원문이 진실이라는 규칙(INV-S1)을 지키려면 번역이 틀렸을 때 대조할 것이 있어야 한다.
- **번역의 근거는 제목 자신이라 요약과 조건이 갈린다** (2026-08-10, INV-S6): 요약은 근거(본문·출처 요약글)가 있을 때만 만들지만(INV-S3), 번역은 근거가 없어도 한다. 둘을 같은 조건으로 묶으면 본문도 요약글도 없는 항목이 **영어 제목으로 영영 남아 그 카드는 통째로 못 읽는 상태**가 된다. 실행이 이 결정을 확인해 줬다 — 첫 바퀴에서 번역 10건, 요약 7건으로 갈렸다.
- **핵심 항목(`summary_points`)은 AI 요약의 부속** (2026-08-10, INV-S7 신설): 컬럼·조회·화면이 다 있는데 **수집이 채우지 않아 비어 있던 필드**였다. 요약과 같은 호출·같은 근거에서 받아 채운다. 출처가 준 글을 보여줄 때는 항목을 딸려 보내지 않는다 — 우리가 뽑은 항목이 출처 글 옆에 붙으면 누가 쓴 것인지가 섞인다(INV-S2 의 라벨 규칙과 같은 계열). 화면이 `isAi && points.length` 를 각자 판단하던 것을 `displaySummary` 한 곳으로 내렸다.
- **마이그레이션 파일에는 재실행해도 같은 결과가 나오는 것만 담는다** (2026-08-10, 리뷰에서 발견): 요약 기준이 바뀌어 기존 요약을 비우는 `update public.item set summary = null` 을 `0003` 에 넣었는데, `apply-migrations.mjs` 는 **이름을 안 주면 폴더의 `.sql` 을 전부 다시 적용한다.** 다음에 `0004` 를 추가하고 습관대로 전부 돌리는 순간 그동안 만든 요약이 통째로 날아가고 전액 재과금된다. 파괴적 문장은 파일에서 빼고 "언제 무엇을 한 번 실행했는지"만 주석으로 남겼다. `add column if not exists` 류는 그대로 둔다. **"한 번만 도는 것"과 "여러 번 돌아도 되는 것"을 한 파일에 섞지 않는다**가 규칙이다.
- **주제 밖 판정을 요약 앞으로, 제목만으로** (2026-08-10, INV-F1 신설): 실측이 순서를 정했다 — 칵테일 레시피 항목 하나가 **13,099 입력 토큰**으로 나머지 7건 평균(2,496)의 5배였다. 요약을 만든 뒤 버리면 그 돈을 이미 쓴 뒤다. 제목만 보는 판정은 약 270 토큰. 대가는 제목만으로 판정하므로 오판 여지가 커진다는 것 — 그래서 **판정이 실패하면 거르지 않고 통과**시키고(INV-F3), 걸러진 건수와 제목을 리포트에 남긴다(INV-F2). 잘못 거르는 쪽이 잘못 통과시키는 쪽보다 비싸다: 걸러진 글은 화면에 없으니 사용자가 알아챌 방법이 없다.
- **출처 표시 = 수집 소스가 아니라 실제 발행처** (2026-08-10, INV-O1): 사용자가 "이런 건 보통 공식 발표니까"라며 출처를 신뢰 판단에 쓴다고 밝혔는데, 지금 화면은 HN 을 거친 글을 발행처와 무관하게 전부 "Hacker News" 로 보여주고 있었다. 판단 재료는 이미 DB 에 있다(`original_url`). 대가는 발행처를 못 뽑는 경우가 생긴다는 것 — 그때는 빈칸을 만들지 않고 수집 소스 이름으로 되돌아간다.
- **공식 여부는 근거를 구분해 남긴다** (2026-08-10, INV-O2·O3): `byUrl`(원문 주소가 그 주체의 도메인 — 도메인 비교뿐, 모델을 안 거친다) / `byContent`(모델 판단) / `none`. 하나로 합치면 모델 판단이 주소 근거와 같은 확실성으로 보이고, 모델이 틀리면 사용자가 잘못 믿는다. 대가는 화면에 표시가 두 종류가 되는 것 — design-rules 에 없는 요소라 시안이 한 바퀴 필요하다.
- **소스는 두 층으로 나누되 화면에는 안 드러낸다** (2026-08-10, INV-L1·L2): `daily`(화제성)/`deep`(전문적)은 weight 로만 반영한다. 사용자가 말한 두 가지 쓰임("매일 이슈 숙지" / "시간 날 때 전문적인 것")은 **읽는 방식**의 축이고, 처음 말한 갈래(뉴스/정보/스킬툴)는 **무엇에 관한 글**의 축이라 서로 다르다. 둘 다 화면의 1차 기준이 될 수는 없어서 화면은 갈래로 가르고 층은 순서로만 반영한다. HN 은 1번 쓰임에는 맞지만 2번에는 **구조적으로 못 쓴다** — 투표 상위에 뜬다는 건 이미 이슈가 됐다는 뜻이고, 검색 피드로 표 조건을 피하려면 **찾을 낱말을 미리 알아야 한다**(모르는 새 개념에는 못 쓴다).
- **태그(고정 분류)와 키워드(생성·누적)를 가른다** (2026-08-10, planned/keywords-and-kinds.md): 사용자가 태그를 키워드로 이해하고 있었고, 지금 구현은 고정 5개였다. 성질이 반대다 — 분류는 안 변해야 필터 버튼이 쓸모 있고, 키워드는 변해야 새 개념을 담는다. 한 칸에 두면 둘 다 나빠진다. **스키마는 이미 자유롭다**(`tag.normalized_name` unique + 다대다) — 고정한 것은 코드의 결정이었다. 키워드는 대상("루프 엔지니어링")과 사건("보안 이슈")을 **섞는다**: 나중에 가르는 건 가능하지만 합치는 건 이미 붙인 것을 다시 손봐야 한다.
- **키워드는 빈도가 아니라 "그 글이 다루는 것"** (2026-08-10, INV-K2): 사용자가 든 예가 반례였다 — 새 개념("벡터 엔지니어링") 발표 글에는 기존 용어가 훨씬 많이 나온다. 새 개념은 한 번 정의되고 그 뒤로는 지칭될 뿐이다. 빈도로 뽑으면 **정작 그 글이 다루는 것이 안 뽑힌다.** 같은 이유로 화면 신호도 둘로 갈랐다: **처음 보는 말**(공식 발표 첫날 1건)과 **요즘 자주 보이는 말**(급증). 급증만 보면 사용자가 원하는 순간을 못 잡는다.
- **키워드 통일은 목록을 프롬프트에 주는 것으로, 임베딩은 안 쓴다** (2026-08-10): `normalized_name` unique 는 **글자가 같을 때만** 합친다. 표기를 맞추는 건 "이미 쓰인 키워드 목록"을 함께 주는 것이 한다. 다만 목록은 **표기를 맞추라고 주는 것이지 범위를 제한하는 게 아니다** — 이걸 명시하지 않으면 지금 고정 5개 태그와 똑같은 상태가 된다. 의미 검색은 **지금 안 한다**: 키워드가 0개인 상태에서는 "얼마나 비슷하면 같은 것인가"를 정할 근거가 없고, 느슨하게 잡으면 새 개념이 기존 것에 흡수돼 목적과 정반대로 실패한다.
- **프롬프트 문장은 파일로 빼되 출력 형식 줄은 코드에 남긴다** (2026-08-10): 사용자가 말투·요약 방식을 자주 고치고 싶어 했다. 말투는 `model/prompt-text.ts` 로 옮겼고, **출력 JSON 의 키 이름·형식 지시는 옮기지 않았다** — 그 줄이 깨지면 파싱이 전부 실패하고 그 실패는 조용하다(빈 결과로 돌아가 매 주기 재시도만 반복). 진짜 `.md` 로 빼는 안은 로더 설정(next.config)이나 배포 시 파일 누락 위험을 새로 만들어 탈락. **프롬프트 변경의 진짜 비용은 파일 위치가 아니라 검증**이다 — 말투가 좋아졌는지는 테스트가 못 잡고 실제로 몇 건 돌려 읽어야 한다.
- **토큰 계측은 실패한 호출도 센다** (2026-08-10, `IngestReport.usage`): 성공 분기에서만 세면 "요약은 하나도 안 늘었는데 요금만 나간 주기"가 보고서에서 멀쩡해 보인다. 파싱 실패·응답 잘림으로 빈 결과를 돌려줄 때도 usage 를 담는 이유가 이것이다. 한 건의 최대 입력 토큰을 따로 남기는 것도 같은 계열 — 합계만 보면 "한 항목의 근거가 비정상적으로 컸다"와 "고르게 늘었다"가 구분되지 않는다. 호출이 아예 던진 경우는 세지 않는다(받은 적 없는 토큰을 지어내지 않는다).

- **점수순만으로는 부족해 소스당 상한을 같이 건다** (2026-08-13, 리뷰가 잡음, `PER_SOURCE_ENRICH_LIMIT = 3`): 최신순→점수순으로 바꾼 그날의 리뷰에서 **같은 결함이 축만 바꿔 살아 있다**는 지적이 나왔다 — 자주 올리고 weight 도 높은 소스(GeekNews, weight 1.5)는 그날 신규분만으로 10칸을 채운다. weight 0.8~0.9 인 매체는 당일에도 밀리고 다음 주기엔 감쇠로 더 떨어져 **영영 번역·요약을 못 받아 영어 제목 카드로 고정된다.** 상한에 걸려 칸이 남으면 남은 칸은 다시 점수순으로 채운다 — 소스가 하나뿐인 날 예산을 버리지 않기 위해서다. 실행이 확인해 줬다: 다음 주기 10칸이 geeknews 3 · aitimes 3 · aitimes-kr 3 · etnews-ai 1 로 갈렸다. 같은 리뷰에서 **자르는 기준과 고르는 기준이 달랐던 것**도 같이 고쳤다 — 풀을 발행시각 100건으로 자른 뒤 점수로 골랐는데, 후보가 약 395건이라 그 경계가 매 주기 실제로 자르고 있었다(풀 100 → 500). **본문 추출 후보도 같은 함수를 쓰게 통일했다**: 추출은 최신 10건을 채우고 요약은 점수 상위 10건을 보던 상태라, 본문을 채운 항목은 요약 후보에 못 들고 요약할 항목은 근거가 없어 건너뛰어졌다.

- **수집 한 바퀴에 시간 예산을 둔다** (2026-08-13, `INGEST_BUDGET_MS = 240_000`): 단계가 전부 순차라 최악치가 Vercel 상한(300초)을 넘는데 예산이 코드 어디에도 없었다. 2026-08-13 실행이 안 넘긴 건 요약 10건이 크레딧 소진으로 즉시 실패했기 때문이고, 크레딧을 채우니 158.9초가 됐다. **넘겼을 때의 증상이 이 파이프라인이 하려던 것과 정면으로 어긋난다** — Vercel 이 함수를 죽이면 응답 본문이 없어서 `failureReasons`·`notChecked`·토큰 계측이 제일 필요한 날 하나도 안 남고 요금만 나간다. 그래서 300 이 아니라 240 이다: 남은 60초는 리포트를 만들어 돌려주는 몫이다. 예산이 떨어지면 그 단계를 **멈추고 리포트를 정상 반환**하고, 건너뛴 것을 `budget` 칸에 남겨 터미널에 찍는다 — 안 남기면 "뒤쪽 소스가 매일 0건"이 *그 소스에 새 글이 없다*로 보인다(`notChecked`·`alreadyKnown` 을 따로 세는 이유와 같다). 시계는 주입받는다: 논리 시각 `now` 는 발행시각 계산용 고정값이라 흐르지 않고, 테스트가 실제로 4분을 기다릴 수도 없다.
- **예산 상수를 `server-only` 밖으로 내렸다** (2026-08-13, `lib/budgets.ts`): `BATCH`·`ENRICH_POOL` 이 `api/ports.ts` 안에 있었는데 그 파일은 `server-only` 라 **유닛 테스트가 한 번도 로드하지 않는다.** 그래서 `ENRICH_POOL` 을 100 → 10 으로 바꿔도 450개가 전부 green 이었다 — 그렇게 바꾸면 "점수로 고른다"가 항등 함수가 되어 방금 고친 버그로 그대로 돌아간다. 값을 못 박는 테스트에 **관계 단언도 같이 둔다**(`ENRICH_POOL >= ENRICH_BATCH * 20`) — 값만 못 박으면 다음 사람이 숫자만 고치고 지나간다. 7세션의 `MAX_RATIO` 10→100 과 같은 자리다.
- **자료 경계는 감싸는 것만으로 부족하다** (2026-08-13, 보안 리뷰, `data-fence.ts`): 외부 글을 `<자료>` 로 감쌌지만 안쪽을 무해화하지 않아 **자료가 자기 경계를 닫을 수 있었다.** 닫히면 그 뒤 문장이 지시가 된다. 도달 경로가 짧다 — 투고형 소스에 글을 올리면 본문 추출이 페이지 HTML 을 통째로 저장하고, weight 가 높으면 그 주기 요약 1순위로 배정된다. XSS 가 아니라 **내용 위조**다: 요약·핵심 항목·한국어 제목이 남의 문장이 되고 "공식 발표라고 함" 표시까지 붙어 피드 상단에 앉는다. 실행마다 다른 nonce 를 쓰는 방법도 있으나 **함수가 순수해야 조립 결과를 테스트가 직접 보고 "자료 밖에 남는 글이 없다"를 단언할 수 있어서** 결정론적 무해화(`<자료`·`</자료` → `‹자료`)를 골랐다.
- **외부 응답에 바이트 상한을 둔다** (2026-08-13, `MAX_FETCH_BYTES = 2_000_000`): 타임아웃 15초만으로는 부족하다 — 그 15초 동안 수백 MB 를 흘려보내면 함수가 메모리로 죽고, 그다음 JSDOM 파싱은 동기라 더 나쁘다. 공격이 필요한 것도 아니고 소스 14곳 중 하나가 큰 파일을 주기만 해도 같은 일이 난다. 게다가 실패한 항목은 `content_html` 이 빈 채 남아 다음 주기에도 같은 자리에서 다시 잡힌다(백오프 컬럼이 아직 없다). **넘치면 잘라 쓰지 않고 던진다** — 깨진 HTML 에서 나온 엉뚱한 결과가 조용히 본문으로 저장되는 것보다 "실패했다"가 낫다.

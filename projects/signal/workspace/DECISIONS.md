# DECISIONS — signal

트레이드오프가 있던 결정만 한 줄씩. 이유의 상세는 PRODUCT.md / 스펙.

- **수집 구조 = 런타임 + Supabase** (정적 빌드타임 아님): 랭킹·상태 저장 등 기능 우선. 정적보다 무겁고 유지비 있음.
- **신호 선별 = 랭킹까지 포함** (단순 최신순 아님): '뜨는 것' 정렬이 핵심 가치. 점수가 시변·파생 → /spec 예정.
- **상세 = 원문 전문 표시** (링크아웃 아님): 사이트 안에서 바로 읽기 우선. 본문 추출 난이도 + 저작권 표면 감수.
- **읽음·북마크 = MVP 제외, 후순위**: 범위를 좁혀 수집·랭킹·필터에 집중.
- **페이지 = 피드 + 상세 2개** (소스 관리 화면 없음): 소스 목록은 설정파일로.
- **프레임워크 = Next.js (App Router)** (Vite/SPA 아님): 웹 노출(SSR/SEO) + 기존 Next+FSD 경험. Vite→Next 전환은 signal 한정, 전역 게이트 불변. 프로파일 nextjs-fsd(pages 제거·app 통일, provider는 shared).
- **원문 표시 방식 = sanitize 후 렌더** (2026-08-02 spec): 화이트리스트 sanitize + html-react-parser. iframe 격리는 X-Frame-Options·높이제어 문제로 탈락. dangerouslySetInnerHTML 금지(게이트). → content-safety.md
- **요약 = AI 생성(Claude)** (2026-08-02 spec): RSS 요약 품질 편차 회피, 한국어 통일. 실패 시 null 적재 후 재시도, summary IS NULL만 재생성(비용). 요약은 신뢰경계 밖—원문이 진실. @anthropic-ai/sdk는 요약 구현 시 설치.
- **랭킹 = 시간감쇠 × 소스 weight(설정파일)** (2026-08-02 spec): 최신성만이면 랭킹=최신순이 돼 '뜨는 것' 가치 소멸 → 정적 소스 weight를 곱함. 앵커 패턴(점수 저장 안 함, 조회 시 계산 → 배치 사고·낡음 원천봉쇄). 외부 인기신호(HN points 등)는 시변 외부값이라 재수집 부담 → MVP 제외. → ingestion-ranking.md
- **중복제거 = 정규화 원문 URL** (2026-08-02 spec): utm_*·fbclid 등 추적파라미터·fragment 제거, 소문자화. 재수집은 upsert(중복 안 쌓임).
- **시각 방향 = 톤 a 인디고 + 밝은 회색 페이지 위 밝은 카드** (2026-08-02 checkpoint 1차): 레퍼런스 biko 는 흰 페이지+회색 카드였으나 "너무 하얘서 눈이 아프다" 피드백으로 명암을 뒤집음. 매일 훑는 리더라 눈부심이 비용. 부수효과로 카드 분리가 뚜렷해짐. 메타색은 그만큼 한 단계 낮춰 대비 재확보(#6A6F77→#656A72).
- **읽음 표시 = MVP로 승격** (2026-08-02, 위 "MVP 제외" 결정을 뒤집음): 사용자 요청. 로그인이 없어 브라우저 로컬에만 저장 → 서버·스키마 변경 없음, 기기 간 동기화 없음. 값이 싸서 승격이 가능했던 것. 흐릿하게 하되 대비 4.5:1 유지·호버 복원(읽은 글도 다시 찾을 수 있어야).
- **피드 = 날짜 그룹 1차, 정렬 2차** (2026-08-02): 수집이 매일 아침 1회 배치라 "오늘 뭐 왔지"가 기본 질문. 점수가 날짜를 가로지르면 하루 단위로 훑을 수 없음. 대안(정렬 1차·평면 목록)은 '뜨는순'에서 날짜가 뒤섞여 탈락. 갱신 주기가 바뀌면 이 결정도 다시 본다.
- **읽음 기록 시점 = 상세 화면 마운트** (2026-08-06, 목록 클릭 아님): 클릭 시점에 찍으면 이동이 실패했을 때(라우트 부재·네트워크) 읽지도 않은 글이 흐릿하게 굳고 localStorage라 새로고침해도 안 풀린다. PRODUCT의 "이미 **연** 소식" 정의와 어긋남. 대가는 상세를 열자마자 읽음이 된다는 것(스크롤 여부·체류 시간은 안 본다) — 개인용이라 그 정밀도가 필요 없다.
- **랭킹 점수·'뜨는 중'은 화면이 만들지 않는다** (2026-08-06): 계산식이 planned/ingestion-ranking.md 에 파킹된 상태라, 더미 데이터가 `score`·`isTrending` 을 들고 오고 화면은 표시만 한다. 대가는 지금 값이 가짜라는 것. 대신 스펙을 켤 때 화면을 안 고쳐도 된다. (열린 질문: '그룹 안 상위'가 태그 필터 전 기준인지 후 기준인지 — 스펙에 기록함)
- **카드 밀도 = A(숨 쉴 곳) + B(출처 표식)** (2026-08-06 비교 시안 승인): "너무 글자글자글자~" 피드백. 요약 3→2줄로 정보량을 줄이고 여백을 키웠다 — 훑는 속도가 목적이라 요약 한 줄보다 밀도가 비싸다는 판단. 출처 이니셜 원은 요소를 하나 늘리는 대가로 훑을 기준점을 얻는다(색은 안 씀 — 포인트색은 "아직 안 본 것" 전용 규칙 유지). C안(제목 17px·요약 연하게)은 효과는 있으나 타이포 단계를 하나 더 늘려 보류.
- **아웃바운드 URL 스킴 = 허용 목록, 본문과 출처를 나눔** (2026-08-06 INV-D6 신설): sanitize 는 본문만 훑으므로 본문 밖 필드인 `sourceUrl` 은 방벽 밖이었다. 본문 링크는 `http·https·mailto`(원문에 이메일 링크가 온다), 출처 링크는 `http·https` 만 — 출처는 웹 주소라 mailto 를 받을 이유가 없고, 넓게 잡으면 나중에 왜 넓은지 아무도 설명 못 한다. 스킴 목록의 정본은 한 곳(`features/content-render/lib/url-safety.ts`). **URL 정리(제어문자·공백 제거)는 보안 장치가 아니다** — 문자를 지우기만 하므로 허용 범위를 넓히는 방향으로만 작동한다. 실제 역할은 멀쩡한 URL 을 잃지 않는 것과 "검사한 문자열 = 렌더할 문자열"을 맞추는 것.
- **AI 요약 박스 = 16px** (2026-08-06 checkpoint, 15px 에서 올림): `ui-layers` 의 "본문 16px 이상" 하한을 요약도 지킨다. 하한 예외의 근거가 "목록 미리보기는 본문이 아니다"인데 상세의 요약은 실제로 읽는 여러 문장이라 예외에 해당하지 않는다. 대가는 원문(17px)과 1px 차이밖에 안 남는다는 것 — 위계를 면·색·왼쪽 포인트선·줄높이 네 축으로 옮겨서 갚았다. 함께 "하한이 걸리는 자리(본문)와 안 걸리는 자리(문장에 딸린 부속: small·figcaption·첨자)"를 문서에 명시했다. 예외 목록이 짧았던 것이 이 혼란의 원인이었다.
- **원문 제목 h1~h6 = 크기 두 값(20/17) + 굵기·색·여백** (2026-08-06 checkpoint): 스펙이 허용하는 태그에 시각 기준이 없어 구현이 값을 발명할 수 없었다. "단계를 늘리지 말고 굵기로" 규칙을 지키려면 17px 아래로 못 내려간다(제목이 본문보다 작아지면 위계가 뒤집힌다). 그래서 h4~h6 은 굵기를 600 으로 고정하고 색 사다리(`--text→--text2→--meta`)로 나눴다. 원문 h1 은 페이지 제목(28px)과 경쟁하지 않게 20px 로 누르고 점선 밑선으로 구획만 표시. (h1 이 둘이 되는 문제는 2026-08-08 에 결론 — 아래)
- **`h1` 이 둘인 것을 그대로 두고, 색과 레이아웃으로 가른다** (2026-08-08, 2026-08-06 미결 해소): 파서에서 원문 제목을 한 단계 강등(h1→h2)하는 안을 검토했으나 채택 안 함 — HTML5 에서 h1 이 여럿인 건 위반이 아니고, 강등은 문서 개요를 위해 **원문 마크업을 우리가 고쳐 쓰는 일**이다. 대신 눈으로 갈리게 했다: 우리가 붙인 페이지 제목은 포인트색(`--accent`), 출처가 쓴 제목은 먹색 + 왼쪽 세로선. **대가는 스크린리더**다 — 색과 선은 시각 신호라 제목 목록에는 안 나타나고, 거기서는 두 h1 이 여전히 같은 층으로 보인다. 이 대가를 알고 고른 것이다. 부수적으로 design-rules 의 "포인트색은 면적을 최소로" 규칙이 페이지 제목까지 넓어졌다(전면 배경 금지는 유지).
- **원문 이미지의 `width`·`height` 를 허용한다 — 조건 넷을 다 만족할 때만** (2026-08-08, INV-D2 확장): 자리를 미리 비워 이미지가 뜰 때 아래 글이 밀리는 것을 막는다. 조건은 ① 둘 다 있음 ② 둘 다 양의 정수 ③ 비율 10:1 이내 ④ 각 값 20000 이하. 하나라도 어긋나면 **둘 다** 버린다(하나로는 비율을 못 구한다). ③·④ 가 필요한 이유는 정수 검사만으로는 `width="1" height="99999"` 같은 거짓 치수를 못 막기 때문 — 믿고 자리를 비우면 높이 0 에서 튀어오르는 것보다 나쁜 빈 공간이 생긴다. **대가는 화이트리스트에 "값도 보는" 규칙이 처음 생긴 것**이고, 그래서 경계(이 둘뿐)를 스펙·코드 양쪽에 못 박았다. 치수 없는 이미지는 CSS 가 16:9 로 대신 예약한다. 함께 **`src` 를 잃은 이미지는 태그째 버린다**(빈 상자가 "여기 그림이 있다"고 거짓말하지 않게).
- **INV-D6 스킴 목록의 정본은 `shared` 가 아니라 `features/content-render`** (2026-08-08, 스펙 문구를 코드에 맞춤): 스펙이 "shared 의 공용 URL 가드"라고 적었지만 구현은 features 에 있었고 **구현 쪽이 맞다.** 두 목록을 가르는 근거("출처는 웹 주소라 mailto 를 받을 이유가 없다")가 도메인 판단이라 shared 규칙(도메인 지식 금지)과 어긋난다. 도메인 없는 조각(문자열 정리·스킴 추출)만 `shared/lib/url.ts` 에 남았다 — 경계는 이미 옳았고 문서만 낡아 있었다.
- **포커스 아웃라인에 라운드를 주지 않는다** (2026-08-06, 기존 규칙 정정): `a:focus-visible` 의 명시도가 컴포넌트 클래스를 이겨서, 키보드 포커스가 닿는 순간 카드가 12px→6px, 알약 버튼이 999px→6px 로 각지게 변하고 있었다. "호버·포커스에서 완전 복구"와 정면으로 어긋난다. `--r-focus` 토큰도 없앴다 — 남겨두면 다음 화면이 되살린다.

# PRODUCT.md — signal

> 상태: 초안 (kickoff 마무리 단계). 스코프 변경은 사용자 동의 후에만.
> 작업 등급: **정식 경로** (Supabase 데이터 모델 + 랭킹 = 시변·파생 상태).

## 한 줄 정의

요즘 넘쳐나는 AI·IT 정보(뜨는 스킬, 엔지니어링 기술, MCP, 새 모델 등)에서 신호만 골라
한곳에서 효율적으로 훑어보는 **개인용 소식 모음 사이트**.

## ① 목적 / 대상

- **푸는 문제**: 정보가 여러 곳에 흩어져 빠르게 쏟아진다 — 한곳에 모아 신호만 골라 빠르게 훑는다.
- **주 사용자**: 나 자신·소수 (개인용). 로그인·회원 개념 없음.
- **사용자가 얻는 것**: 흩어진 소스를 한곳에서, '뜨는 것'부터 확인하고, 원문까지 바로 읽음.

## 성공 기준 (이 사이트가 잘해야 하는 것 = 강점)

- **적합성**: 관심에 맞는 정보를 얼마나 잘 가져오는가 (수집·랭킹의 질)
- **요약 품질**: 이해하기 쉽고 **정확하고 간략한** 요약
  _(결정됨 2026-08-02: 요약 = AI 생성(Claude). 실패 시 요약 없이 적재 후 재시도. 요약은 신뢰경계 밖=원문이 진실. 상세는 ingestion-ranking.md INV-S)_
- **편의성**: 버벅임·잦은 클릭 없이 편하게 훑기 (성능 · 적은 인터랙션이 목적)

## ② 필수 기능 / 비범위

- **필수 (MVP)**:
  - 여러 소스에서 소식 **자동 수집** (RSS/API) → 제목·요약·**원문 본문**·출처·시각을 Supabase 적재
    _(정정됨 2026-08-09: **원문 본문은 늘 얻어지지 않는다.** RSS 가 본문을 안 주는 소스가 많아
    원문 페이지에서 추출을 시도하지만(INV-S5), 봇을 막는 사이트는 실패한다(OpenAI 403 실측).
    본문이 없으면 상세는 "원문 전문을 제공하지 않는다"고 밝히고 출처 링크로 보낸다.
    요약도 근거가 있을 때만 만든다 — 제목만으로 지어내지 않는다)_
  - **한국어로 읽기**: 제목을 한국어로 옮겨 보여주고(원문 제목은 상세에 함께 남김), 요약은
    핵심 항목까지 뽑아 준다
    _(결정됨 2026-08-10: 사용자가 영어를 읽지 못한다. 요약만 한국어인데 제목이 영어면 훑을 때
    제일 먼저 걸리는 곳이 막힌다. **원문 본문 전문 번역은 지금 안 한다** — 본문이 있는 항목이
    11%뿐이라 대상이 거의 없고 비용이 요약의 5~6배다. 본문을 읽는 일이 잦아지면 다시 본다.
    상세는 ingestion-ranking.md INV-S6·S7)_
  - **피드(목록)**: 제목 + 요약 + 태그로 정리, 랭킹/최신 정렬, 주제 필터, **날짜별 그룹**
    _(결정됨 2026-08-02: 수집이 매일 아침 1회 도는 배치라 "오늘 뭐 왔지"가 기본 질문이 된다.
    따라서 **날짜 그룹이 1차, 정렬(뜨는순/최신순)은 그룹 안에서 2차.** 점수가 날짜를 가로질러
    섞이면 하루 단위로 훑을 수 없다)_
  - **읽음 표시**: 이미 연 소식은 피드에서 흐릿하게 눌러 표시
    _(결정됨 2026-08-02: 원래 후순위였으나 시안 checkpoint에서 사용자가 요청해 MVP로 올림.
    로그인이 없으므로 읽음 상태는 브라우저 로컬에만 둔다 — 서버·DB 스키마 변경 없음.
    기기 간 동기화는 안 된다는 뜻이고, 그래서 값이 싼 기능. 흐릿하게 = 눌러두는 것이지
    읽을 수 없게 만드는 게 아니다: 읽은 항목도 대비 4.5:1 유지, 호버 시 복원)_
  - **소식 상세**: 원문 본문 전문 + 출처 링크 + 카테고리 태그(다중)
  - **신호 선별 + 랭킹**: 점수로 정렬해 '뜨는 것' 상위 · 중복 제거
    _(결정됨 2026-08-02: 점수 = 시간감쇠 × 소스별 weight(설정파일). 앵커 패턴(저장 안 함·조회 시 계산). 외부 인기신호(HN 등)는 MVP 제외. 상세는 ingestion-ranking.md INV-R)_
  - **카테고리 태그**: 항목마다 주제 태그 여러 개 → 피드 필터의 기준
  - **주제 밖 걸러내기 + 공식 발표 표시**: 수집할 때 제목만 보고 AI·IT 밖 글을 버리고,
    피드 카드에는 그 글이 공식 발표인지를 **근거를 나눠** 보여준다
    _(결정됨 2026-08-10~12: 사용자가 "가져온 글이 대부분 뉴스이고 중요하지 않다"고 지적했고,
    출처를 신뢰 판단에 실제로 쓰고 있었다. 표시는 두 종류다 — **"공식 발표"**(원문 주소가 그
    주체의 사이트. 기계가 대조하므로 확실) vs **"공식 발표라고 함"**(AI 가 글을 읽고 판단.
    틀릴 수 있다). 하나로 합치면 AI 가 틀린 날 사용자가 그대로 믿는다.
    상세는 content-selection.md INV-F·O·L)_
- **비범위 (안 만드는 것 / 후순위)**:
  - 이메일 구독·발송 · 회원가입·로그인 · 댓글·커뮤니티·공유 (안 함)
  - 콘텐츠 직접 작성/편집 (수집만)
  - ~~읽음 표시~~ → **2026-08-02 필수로 승격** (위 ② 필수 참조). 북마크는 여전히 후순위
  - 소스 관리 화면 → 후순위 (MVP는 소스 목록을 설정파일로)

## ③ 페이지 (MVP)

- **메인 피드**: 수집 항목 목록 — 제목·요약·태그, 날짜별 그룹 안에서 랭킹/최신 정렬, 주제 필터, 읽음 표시
- **소식 상세**: 원문 본문 전문 · 출처 링크 · 카테고리 태그(다중)

- **프레임워크/렌더링**: **Next.js (App Router, SSR)** — 상세는 tech-stack.md (approved)
- **데이터 계층**: **Supabase** (확정)
- **배포**: **Vercel** (+ Vercel Cron으로 수집 스케줄) — 확정
- **갱신 주기**: **매일 아침 1회 배치** (2026-08-02 확정). 실시간 스트림이 아니라 하루 한 묶음 —
  피드의 날짜 그룹, 랭킹의 시간감쇠 단위(planned/ingestion-ranking.md INV-R), "매일 아침 갱신" 카피가
  모두 이 전제를 공유한다. 주기가 바뀌면 셋 다 다시 본다

- **수집·중복·요약·랭킹** = docs/specs/planned/ingestion-ranking.md (INV-C/R/S/T) — 설계 합의됨, Supabase 프로비저닝 시 활성화(approved)
- **무엇을 모으고 무엇을 보여줄지** = docs/specs/content-selection.md (INV-F/P/O/L)
  _(2026-08-10 신설·사용자 승인. 계기는 실제 데이터를 며칠 돌려 본 뒤의 지적 — "가져온 글이

- **키워드와 갈래** = docs/specs/planned/keywords-and-kinds.md (INV-K/KD/G) — 설계 합의됨, 보류
  _(2026-08-10. 지금 태그는 고정 5개라 새로 생긴 개념을 담지 못한다. 분류(안 변함)와

## 데이터 모델 (얕은 스캔 — 깊게는 /spec에서)

- **엔티티 후보**:
  - `source` 출처(RSS 주소 등)
  - `item` 수집 항목(제목·요약·**본문**·출처URL·발행시각·점수)
  - `tag` 카테고리, `item_tag` 다대다(항목당 태그 여러 개)
- **플래그**:
  - **점수/랭킹 = 시변·파생 상태** → 불변식 스펙 필요 (/spec). 갱신 주기·계산식·정렬 안정성 확정.
  - **중복 제거 키**(원문 URL 등) → 스펙에서 확정.
  - **원문 전문 저장·표시** → 본문 추출 난이도 + 저작권 표면. 개인용이라 완화되나 기록해 둠.

# 수집·중복제거·요약·랭킹 스펙

여러 외부 소스(RSS/API)에서 소식을 자동 수집해 Supabase에 적재하고, 피드에서 '뜨는 것' 순으로
보여주는 파이프라인. 핵심 위험은 세 가지다: **(1) 랭킹 점수는 시간에 따라 변하는 파생값**이라
잘못 저장하면 낡거나 배치 사고가 난다, **(2) 같은 기사가 중복 적재**되면 피드가 오염된다,
**(3) 외부 응답·AI 요약은 신뢰 경계 밖**이라 검증 없이 믿으면 깨진 데이터·환각이 유입된다.

소스 목록·소스별 신뢰도(weight)는 설정파일로 관리한다(MVP는 소스 관리 화면 없음 — PRODUCT 비범위).

## 불변식 — 각각 참/거짓 판정 가능. 위반 시 무슨 일이 일어나는지 / 어디서 강제되는지 명시

### 수집·중복제거 (C)

- INV-C1: 항목의 유일성은 정규화된 원문 URL(canonical_url)로 판정한다. 같은 canonical_url의
  재수집은 새 행을 만들지 않고 기존 행을 갱신(upsert)한다. (강제 위치: 서버 — DB unique(canonical_url) + 수집 upsert)
  위반 시: 같은 기사가 여러 번 적재돼 피드 중복·랭킹 왜곡.

- INV-C2: canonical_url은 수집 시 정규화 규칙(스킴·호스트 소문자화, 추적 쿼리파라미터 제거[utm_*·fbclid·gclid 등],
  fragment(#) 제거, 트레일링 슬래시 정리)을 거친 값이다. 정규화 이전의 원본 URL도 함께 보존한다(원문 링크 표시용).
  (강제 위치: 서버 — 수집 시 정규화 함수)
  위반 시: 같은 기사가 utm 파라미터 차이만으로 서로 다른 항목이 돼 중복.

- INV-C3: 외부 소스 응답(RSS/HTTP)은 신뢰 경계 밖이다. 파싱 결과는 스키마(Zod) 검증을 통과한 항목만
  적재하고, 필수 필드(**제목·원문URL**) 누락 항목은 버린다(적재하지 않음). (강제 위치: 서버 — 수집 시 Zod 파싱)
  위반 시: 깨진/악의적 필드가 DB와 화면으로 유입.
  - 발행시각은 필수 목록에 없다 — 없거나 못 읽으면 버리지 않고 INV-C5 가 대체한다.
    (2026-08-09 정정: 원래 필수 목록에 발행시각이 들어 있었는데, 그러면 INV-C5 의 "대체하되
    대체 여부를 구분해 남긴다"가 영원히 닿지 않는 분기가 된다. 두 조항이 서로 다른 말을 하고 있었다.)
  - 원문URL은 "있다"가 아니라 **정규화에 성공한다**를 뜻한다(INV-C2). 정규화가 null 을 내면
    유일성 키가 없어 INV-C1 의 중복 판정 자체가 불가능하므로 버린다.

- INV-C4: 한 소스의 수집 실패(네트워크·파싱 오류)는 다른 소스의 수집을 막지 않는다. 실패는 기록하고
  다음 소스로 진행한다. (강제 위치: 서버 — 소스별 독립 실행·오류 격리)
  위반 시: 소스 하나가 죽으면 전체 수집이 중단돼 피드가 갱신 안 됨.

- INV-C5: 발행시각(published_at)은 UTC로 저장한다. 소스가 준 시각의 타임존을 UTC로 변환해 저장하고,
  발행시각이 없거나 파싱 불가면 수집시각(fetched_at)으로 대체하되 대체 여부를 구분해 남긴다.
  상대시간 표시("2시간 전")는 저장하지 않고 조회 시점에 계산한다. (강제 위치: 서버 — 저장 시 UTC 정규화 / 클라 — 조회 시 계산)
  위반 시: 타임존이 섞여 정렬·랭킹·상대시간이 어긋남.
  - **타임존이 없는 ISO 꼴 값(`2026-08-09T09:00:00`·`2026-08-09`)은 UTC로 읽는다** — 대체하지 않는다.
    (2026-08-09 사용자: 필요한 정밀도는 "언제 나온 소식인지"까지다.) 대체하면 일주일 전 글이
    오늘 날짜 묶음에 들어가는데, UTC로 읽으면 최악이 하루 어긋난다. 완전히 틀리는 것보다 낫다.
    대가: KST 자정 근처에 발행된 글의 날짜 묶음이 하루 밀릴 수 있다.
  - 실행 환경의 로컬 시간대로 읽지 않는다. 자바스크립트는 존 없는 값을 로컬로 해석하므로,
    서버와 브라우저가 다른 존이면 같은 값이 다른 날로 갈린다. UTC라고 명시해 넘긴다.

### 랭킹 (R) — 시변·파생값. 저장하지 않고 앵커에서 조회 시 계산

- INV-R1: 랭킹 점수는 저장하지 않는다. (published_at, 소스 weight, 조회시각 now)에서 조회 시점에
  계산되는 파생값이다. 점수 갱신 배치를 두지 않는다. (강제 위치: 서버 — 점수 컬럼 부재 + 조회 시 계산)
  위반 시: 저장 점수가 시간이 지나 낡고, 부분갱신 배치가 절반만 돌아 순위가 뒤섞이는 사고.

- INV-R2: 점수 = 시간감쇠(published_at, now) × 소스 weight. 시간감쇠는 (now − published_at)에 대해
  단조 감소하는 순수 함수이고, weight는 소스 설정파일의 값이다(항목이 아니라 소스에 귀속). 같은 입력에 항상 같은 점수.
  (강제 위치: 서버 — 순수 계산 함수)
  위반 시: 점수가 비결정적이 돼 정렬이 흔들림.

- INV-R3: 정렬은 안정적이다 — 점수 내림차순, 동률이면 published_at 내림차순, 그래도 같으면 id로
  타이브레이크한다. 같은 데이터·같은 조회시각이면 항상 같은 순서. (강제 위치: 서버 — 다단 ORDER BY)
  위반 시: 새로고침마다 순서가 흔들려 훑기를 방해.

- INV-R4: 소스 weight는 소스(설정파일)에 귀속하며 항목에 스냅샷 저장하지 않는다. weight를 바꾸면
  다음 조회부터 해당 소스의 모든 항목 순위에 즉시 반영된다. (강제 위치: 서버 — 조회 시 소스 weight 참조)
  위반 시: 옛 weight가 항목에 박혀 설정 변경이 반영되지 않음.

- INV-R5: '뜨는 중'은 **날짜 그룹 안에서 점수 상위 `TRENDING_TOP_N`개**(설정값, 기본 3)에 붙는다
  ([design-rules.md:113](../../design/design-rules.md#L113) "전역 상위가 아니라 그룹 안에서의 상위").
  판정은 **태그 필터와 정렬 토글을 적용하기 전 목록**을 기준으로 하며, 조회 파라미터가 바뀌어도
  같은 조회시각이면 뜨는 중인 항목 집합은 같다. 그룹 크기가 `TRENDING_TOP_N`보다 작으면
  그 그룹의 항목 전부가 뜨는 중이 된다. (강제 위치: 서버 — 필터·정렬 적용 전 단계에서 판정하고
  그 결과를 항목에 실어 보낸다)
  위반 시: 같은 글이 필터·정렬에 따라 뱃지가 붙었다 떨어져 "뜨는 중"이 무엇을 뜻하는지 알 수 없게 된다.
  대가(2026-08-09 사용자 결정): 태그 필터를 걸면 결과 상단에 뱃지가 하나도 없을 수 있다.
  뱃지가 "지금 전체에서 뜨는 것"이라는 뜻을 지키는 쪽을 택했다.

### AI 요약 (S)

- INV-S1: 요약은 표시용 파생 정보이며 신뢰 경계 밖이다(LLM 환각 가능). 요약은 원문의 대체가 아니고,
  정확성의 근거는 언제나 저장된 원문 본문·출처 링크다. 상세 화면은 요약 여부와 무관하게 원문·출처를 항상 제공한다.
  (강제 위치: 설계 — 상세 화면이 원문·출처를 필수로 렌더)
  위반 시: 환각 요약을 사실로 오인해 잘못된 정보 소비.

- INV-S2: 요약 생성 실패·타임아웃 시 항목은 요약 없이(summary=null) 적재되고, 수집 파이프라인은
  중단되지 않는다. summary=null 항목은 다음 수집 주기의 재시도 대상이다. (강제 위치: 서버 — 요약 호출을 적재와 분리, 실패 격리)
  위반 시: LLM 장애가 전체 수집을 막거나, 요약 실패 항목이 영원히 안 채워짐.
  - **AI 요약이 없으면 출처가 준 요약글(`source_excerpt`)을 대신 보여준다.** 화면에 아무것도
    없는 것보다 낫고, 그것도 없으면 제목만 보여준다. (2026-08-09 사용자: "요약은 거의 무조건 나와야 한다")
  - `source_excerpt` 는 `summary` 와 **다른 칸**이다. 같은 칸에 넣으면 "요약이 없다"는 신호가
    사라져 AI 요약이 영영 생기지 않는다(INV-S3 의 재시도 조건이 무력화된다).

- INV-S3: 요약은 원문 본문 기준으로 1회 생성해 저장하는 스냅샷이다. 원문이 바뀌지 않으면 재생성하지
  않는다. 재시도 대상은 **summary IS NULL 이면서 근거가 있는** 항목으로 한정한다.
  (강제 위치: 서버 — 재생성 조건 = summary IS NULL AND 근거 존재)
  위반 시: 매 수집 주기마다 전체 재호출로 LLM 비용 폭증.
  - **근거 = 원문 본문 또는 `source_excerpt`.** 근거가 없으면 요약을 시도하지 않는다 —
    제목만 주고 요약시키면 모델이 지어내고, 그건 INV-S1 위반이다. 근거 없는 항목을 후보에
    남겨 두면 매 주기마다 실패만 반복한다.

- INV-S5: 원문 본문이 없는 항목은 원문 URL 에서 본문을 추출해 채운다. 추출 실패(차단·타임아웃·
  본문 없음)는 그 항목만 건너뛰고 수집을 계속한다. (강제 위치: 서버 — 추출을 적재와 분리, 실패 격리)
  위반 시: 본문 없는 항목이 요약 근거를 못 얻어 영영 요약이 안 되거나, 추출 실패가 수집을 멈춤.
  - 2026-08-09 실측 근거: HN 은 링크 모음이라 본문을 가진 적이 없고(RSS 요약글도 링크뿐),
    OpenAI 는 요약글은 주지만 원문 페이지가 403 이다. **소스마다 되는 길이 달라서** 둘 다 필요하다.
  - 추출은 신뢰 경계 밖이다. 결과 HTML 은 화면에 그릴 때 content-safety 의 sanitize 를 거친다.

- INV-S6: 제목은 한국어로 옮겨 보여주되 **원문 제목을 덮어쓰지 않는다.** 번역문은 다른 칸(`title_ko`)에
  저장하고, 화면은 번역문이 있으면 그것을, 없으면 원문 제목을 보여준다. 상세 화면은 원문 제목을 함께 보여준다.
  (강제 위치: 서버 — 스키마에서 `title` 과 `title_ko` 를 다른 컬럼으로 분리)
  위반 시: 원문 제목을 덮으면 번역이 틀렸을 때 대조할 수단이 없어진다 — INV-S1 의 "원문이 진실"이 깨진다.
  - **번역의 근거는 제목 자신이다.** 따라서 INV-S3 의 "근거(본문·출처 요약글)가 있을 때만"은 요약에만
    적용되고, 근거가 없어 요약을 못 만드는 항목도 제목은 번역한다. 이게 없으면 본문도 요약글도 없는
    항목(HN 링크 글 다수)이 영어 제목만 덩그러니 남아 그 카드는 통째로 못 읽는 상태가 된다.
  - 재생성 조건은 `title_ko IS NULL` 이다(INV-S3 과 같은 형태 — 한 번 만들면 다시 부르지 않는다).
  - 이미 한국어인 제목은 그대로 둔다. 번역이 실패하면 `title_ko` 는 null 로 남고 화면은 원문 제목을 쓴다.

- INV-S7: 핵심 항목(`summary_points`)은 **AI 요약의 부속**이다. 요약과 같은 호출·같은 근거에서 나오고,
  AI 요약이 없으면 핵심 항목도 없다. 출처가 준 요약글을 대신 보여주는 화면에서는 핵심 항목을 보여주지 않는다.
  (강제 위치: 서버 — 요약과 같은 응답에서 받아 같이 저장 / 화면 — AI 요약일 때만 렌더)
  위반 시: 출처 글 옆에 우리가 뽑은 항목이 붙어 "누가 쓴 것인지"가 섞인다(INV-S2 의 라벨 규칙과 같은 계열).

- INV-S4: Claude API 키 등 서버 전용 시크릿은 클라이언트 번들·코드에 존재하지 않는다. 요약 생성은
  서버(수집 함수 / Vercel Cron)에서만 수행한다. 브라우저엔 Supabase anon 키만. (강제 위치: 게이트 NO_HARDCODED_SECRET + 배치 규칙 rules/supabase.md)
  위반 시: 키 유출로 과금 남용·무단 호출.

### 태그 (T)

- INV-T1: 항목↔태그는 다대다다(item_tag 조인 테이블). 항목은 태그를 0개 이상 가진다. 태그는 항목의
  단일 필드가 아니다. (강제 위치: 스키마 — item_tag 조인)
  위반 시: 항목당 태그를 하나밖에 못 담아 다중 태그 필터가 붕괴.

- INV-T2: 태그의 유일성은 대리키(id) + 정규화된 태그명(unique)으로 정한다. 같은 뜻의 태그가
  대소문자·공백 차이로 중복 생성되지 않는다. (강제 위치: DB unique(normalized_name))
  위반 시: 'MCP'와 'mcp'가 다른 태그가 돼 필터가 쪼개짐.

- INV-T3: 태그는 **제목 키워드 규칙과 AI 분류를 합쳐서** 붙인다. 둘 중 하나만 골라내도 붙고,
  같은 태그를 둘 다 골라도 한 번만 붙는다(INV-T2 의 유일성 + item_tag 기본키).
  AI 분류는 정해진 목록 밖의 태그를 만들지 못한다. (강제 위치: 서버 — 두 결과의 합집합을 목록으로 거른 뒤 저장)
  위반 시: 규칙만 쓰면 표현이 다른 글을 놓치고, AI 만 쓰면 요약이 실패한 항목에 태그가 하나도 안 붙는다.
  - 태그 목록은 아직 **임시**다(2026-08-09 사용자). 늘리거나 바꿀 때 이 불변식은 그대로다 —
    "정해진 목록 안에서만"이 규칙이고 목록의 내용물은 규칙이 아니다.

## 시나리오 — 각각 어느 불변식을 검증하는지 ID 참조 (불변식마다 실패 경로 1개 이상)

- S1 (INV-C1, 실패경로): Given 이미 적재된 canonical_url X의 항목 / When 같은 X를 재수집 /
  Then 새 행이 생기지 않고 기존 행이 갱신된다(행 수 불변).
- S2 (INV-C2): Given `https://ex.com/a?utm_source=rss#top`와 `HTTPS://EX.com/a/` /
  When 각각 정규화 / Then 둘 다 같은 canonical_url `https://ex.com/a`로 수렴한다.
- S3 (INV-C3, 실패경로): Given 발행시각·원문URL이 빠진 RSS 항목 / When 수집 / Then 그 항목은 적재되지 않는다.
- S4 (INV-C4, 실패경로): Given 소스 A가 500을 반환, 소스 B는 정상 / When 수집 실행 /
  Then B의 항목은 적재되고 A의 실패는 기록되며 파이프라인은 끝까지 진행된다.
- S5 (INV-C5): Given KST로 표기된 발행시각 / When 저장 / Then UTC로 변환돼 저장되고, 상대시간은 조회 시 계산된다.
- S6 (INV-R1, 실패경로): Given 적재된 항목 / When 스키마를 본다 / Then 점수 컬럼이 존재하지 않는다(점수는 조회 계산값).
- S7 (INV-R2): Given 발행시각 같고 weight가 다른 두 소스의 항목 / When 점수 계산 / Then weight 높은 쪽 점수가 크다.
- S8 (INV-R3, 실패경로): Given 점수·발행시각이 완전히 같은 두 항목 / When 두 번 정렬 / Then 두 번 다 같은 순서(id 타이브레이크).
- S9 (INV-R4): Given 소스 weight를 올림 / When 다시 조회 / Then 재수집·배치 없이 해당 소스 항목들의 순위가 오른다.
- S10 (INV-S2, 실패경로): Given Claude 호출이 타임아웃 / When 수집 / Then 항목은 summary=null로 적재되고 수집은 계속된다.
- S11 (INV-S3, 실패경로): Given summary가 이미 있는 항목 / When 다음 수집 주기 / Then 요약을 재생성하지 않는다(호출 없음).
- S12 (INV-S1): Given 요약이 원문과 다른 뉘앙스 / When 상세 조회 / Then 원문 본문과 출처 링크가 항상 함께 제공된다.
- S13 (INV-S4, 실패경로): Given 빌드된 클라이언트 번들 / When Claude 키 문자열 검색 / Then 발견 없음(게이트 통과).
- S14 (INV-T1): Given 태그 3개인 항목 / When 조회 / Then 태그 3개가 모두 붙어 온다.
- S15 (INV-T2, 실패경로): Given 태그 'MCP' 존재 / When 'mcp'를 추가 시도 / Then 새 태그가 생기지 않고 기존 태그에 연결된다.
- S16 (INV-R5): Given 같은 날짜 그룹에 항목 10개, 점수 상위 3개가 A·B·C (`TRENDING_TOP_N`=3) /
  When 필터 없이 조회 / Then A·B·C만 isTrending=true 이고, 정렬을 최신순으로 바꿔도 그대로다.
- S17 (INV-R5, 실패경로): Given S16과 같은 상태에서 A·B·C 중 어느 것도 갖지 않은 태그로 필터 /
  When 조회 / Then 결과에 isTrending=true 인 항목이 **0개**다(필터 결과 안에서 다시 상위를 뽑지 않는다).
- S18 (INV-S3, 실패경로): Given 본문도 source_excerpt 도 없는 항목 / When 요약 주기 /
  Then 요약을 시도하지 않는다(호출 없음). 제목만으로 지어내지 않는다.
- S19 (INV-S2): Given AI 요약이 없고 source_excerpt 가 있는 항목 / When 화면 조회 /
  Then 출처가 준 요약글이 대신 보이고, 그것이 AI 요약이 아님을 알 수 있다.
- S20 (INV-S5, 실패경로): Given 원문 페이지가 403 을 반환 / When 본문 추출 /
  Then 그 항목만 본문 없이 남고 다른 항목의 추출·적재는 계속된다.
- S21 (INV-T3): Given 제목에 'MCP'가 있고 AI 가 '툴'을 고른 항목 / When 태그 저장 /
  Then 두 태그가 모두 붙는다.
- S22 (INV-T3, 실패경로): Given AI 가 목록에 없는 태그('블록체인')를 고름 / When 태그 저장 /
  Then 그 태그는 만들어지지 않는다.
- S23 (INV-S6): Given 영어 제목의 항목 / When 번역 후 저장 / Then 원문 제목은 그대로 남고
  번역문은 다른 칸에 들어간다. 화면은 번역문을 보여주고 상세는 원문 제목을 함께 보여준다.
- S24 (INV-S6, 실패경로): Given 본문도 source_excerpt 도 없는 항목(요약 불가) / When 수집 주기 /
  Then 요약은 만들지 않지만 제목은 번역된다.
- S25 (INV-S6, 실패경로): Given `title_ko` 가 이미 있는 항목 / When 다음 수집 주기 /
  Then 번역을 다시 부르지 않는다.
- S26 (INV-S7, 실패경로): Given AI 요약이 없고 source_excerpt 만 있는 항목 / When 상세 조회 /
  Then 핵심 항목은 렌더되지 않는다.

## 신뢰 경계

- 믿는 값: 소스 설정파일(소스 목록·weight)은 우리가 통제하는 신뢰값. UTC로 정규화한 뒤의 published_at.
  DB에 저장돼 unique 제약을 통과한 canonical_url. 서버 계산 함수의 출력.
- 믿지 않는 값: 외부 RSS/HTTP 응답의 모든 필드(제목·본문·요약·URL·발행시각·태그 후보), Claude가 생성한 요약,
  클라이언트가 보내는 정렬·필터 파라미터(표시/UX용일 뿐 랭킹의 근거가 아니다).

## 비범위

- 원문 HTML의 XSS sanitize·렌더 방식 → 별도 스펙(content-safety.md).
- 소스 관리 화면(소스는 설정파일) · 읽음·북마크 · 개인화 랭킹(사용자별) → PRODUCT 비범위/후순위.
- 외부 인기 신호(HN points·stars 등) 기반 랭킹 → 시변 외부값이라 재수집 필요, MVP 제외(정적 weight로 대체).
- 원문 본문 추출 방식(RSS가 요약만 줄 때 readability류) → 수집 구현 시 결정(라이브러리 선택), 불변식 없음.

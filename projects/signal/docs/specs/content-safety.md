# 원문 렌더 보안 스펙

상세 화면은 외부에서 수집한 원문 본문(HTML)을 사이트 안에서 그대로 보여준다(DECISIONS: 링크아웃 아님).
수집한 HTML은 우리가 통제하지 않은 제3자 콘텐츠이므로 **신뢰 경계 밖**이고, 검증 없이 렌더하면
저장된 콘텐츠에서 스크립트가 실행되는 XSS(stored XSS)가 된다. 킷 게이트는 이미 dangerouslySetInnerHTML을
원천 차단하므로(DECISIONS 참조), 렌더는 sanitize + 파서 방식으로 설계한다.

## 불변식 — 각각 참/거짓 판정 가능. 위반 시 무슨 일이 일어나는지 / 어디서 강제되는지 명시

- INV-D1: 저장된 원문 HTML은 신뢰 경계 밖이다. 화면에 렌더하기 전 반드시 sanitize(허용 태그·속성
  화이트리스트)를 거친다. 원본 HTML을 그대로 렌더하는 경로는 존재하지 않는다. (강제 위치: 서버/렌더 경로 — sanitize-html)
  위반 시: 저장된 콘텐츠에서 스크립트 실행(stored XSS) → 세션·데이터 탈취.

- INV-D2: sanitize는 화이트리스트 방식이다 — 허용 태그(p·a·h1~h6·ul·ol·li·code·pre·blockquote·img·
  strong·em·br 등)와 허용 속성만 통과시키고, script·style 태그, on\* 이벤트 핸들러 속성, `javascript:`
  스킴 URL은 제거한다. 블랙리스트가 아니라 화이트리스트다. (강제 위치: sanitize 설정)
  위반 시: 블랙리스트 누락 벡터로 우회당함.

  **값 판정 로직을 우리가 직접 쓰는 속성은 `img` 의 `width`·`height` 둘뿐이다** (2026-08-08 추가).
  (`href`·`src` 의 스킴도 값을 보지만 그건 sanitize 라이브러리의 `allowedSchemes` 가 맡는다 —
  목록의 정본은 INV-D6 의 가드 모듈이다. "이름만 본다"가 아니라 "우리가 직접 안 쓴다"가 경계다.)

  두 값은 이미지가 도착하기 전 브라우저가 비워둘 상자를 정한다. **비율뿐 아니라 로드 전
  렌더 폭도 정한다**(`width` 속성은 `width` 프로퍼티의 표현 힌트다) — 다만 그 폭은 렌더 쪽
  `max-width:100%` 가 읽기 컬럼에서 자른다. 통과 조건은 넷을 모두 만족할 때이며,
  하나라도 어긋나면 **둘 다 제거**한다(하나만 남기면 브라우저가 비율을 구하지 못해 얻는 것이 없다):

  1. **둘 다 있다.** 한쪽만 오는 것은 통과가 아니다.
  2. **둘 다 양의 정수다.** `0`·음수·소수·단위 붙은 값(`704px`)·앞뒤 공백은 전부 거부.
  3. **비율이 10:1 안이다.** 정수 검사만으로는 부족해서 둔다 — `width="1" height="99999"` 도
     양의 정수인데, 믿고 자리를 비우면 로드 전에 거대한 빈 공간이 생겼다가 접힌다.
     **높이 0 에서 튀어오르는 것보다 나쁘다.** 값이 정직하면 이 범위 안에 들어오고,
     그 안에서는 크게 잡아도 실제로 그만큼 큰 것이므로 예약이 옳다.
  4. **각 값이 20000 이하다.** 비율만으로는 절대 크기가 안 묶인다 — 10:1 을 지키면서 자릿수만
     키운 값이 통과한다. 그런 값이 화면을 안 망가뜨리는 건 렌더 쪽 CSS(`height:auto`) 덕인데,
     **방어가 다른 레이어 한 줄에 얹혀 있으면 그 줄이 사라지는 날 조용히 깨진다.** 여기서 묶는다.
     20000px 은 브라우저가 실제로 다루는 이미지 크기의 실용 한계 언저리이고, 그보다 크면
     실측값이 아니라 잘못된 값이다. (정밀도를 잃는 자릿수도 이 조건에 함께 걸린다)

  거부되면 치수만 버리고 **이미지는 남긴다** — 치수가 틀렸다고 그림을 지우지 않는다.
  이때 자리 예약은 렌더 쪽 CSS 의 대체 비율이 대신 맡는다(그 값은 이 스펙이 아니라 design-rules 가 정한다).
  (강제 위치: sanitize 설정 — `transformTags.img`)

  **예외 하나 — `src` 를 잃은 이미지는 태그째 버린다.** 허용 스킴이 아닌 `src` 는 속성만
  제거되어 `<img alt="">` 껍데기가 남는데, 그 자리에 자리 예약이 걸리면 **영원히 안 채워지는
  빈 상자**가 화면에 보인다. 치수 없는 이미지의 예약은 언젠가 그림으로 채워지지만 이 자리는
  그렇지 않다 — 화면이 "여기 그림이 있다"고 거짓말하게 두지 않는다(INV-D6 의 죽은 링크 판단과 같은 이유).
  (강제 위치: sanitize 설정 — `exclusiveFilter`)
  위반 시: 즉시 XSS 는 아니다(sanitize-html 이 속성 값을 이스케이프한다). 실제 위험은 다른 쪽이다 —
  이 스펙에서 화이트리스트가 "속성 **이름**만 본다"에서 "값도 본다"로 넘어온 **첫 자리**이므로,
  조건을 여기 못 박아두지 않으면 다음에 속성을 넓힐 때 "값만 검사하면 된다"가 근거 없이 재사용된다.

- INV-D3: 렌더는 dangerouslySetInnerHTML을 사용하지 않는다. sanitize된 HTML을 파서(html-react-parser
  등)로 React 엘리먼트 트리로 변환해 렌더한다. (강제 위치: 게이트 — dangerouslySetInnerHTML 사용 차단)
  위반 시: 게이트 위반 + XSS 표면 재도입.

- INV-D4: 본문 내 외부 링크와 출처 링크(a[target=_blank])는 rel="noopener noreferrer"를 갖는다.
  (강제 위치: 렌더 시 속성 강제 + rules/ui-layers)
  위반 시: 탭내빙(opener를 통한 피싱 리다이렉트).

- INV-D5: 본문 내 이미지는 alt 속성을 보존한다. alt가 없으면 빈 alt=""로 채워 장식 이미지로 처리한다
  (스크린리더가 건너뜀). (강제 위치: sanitize)
  위반 시: 스크린리더 사용자에게 의미 없는 이미지 노이즈.
  (이미지 로드 실패·과대 이미지의 레이아웃 붕괴 방지는 이 보안 스펙 범위 밖 — rules/ui-layers 로 이관. 비범위 참조.)

- INV-D6: 화면에 렌더하는 **모든 아웃바운드 URL**은 허용 스킴 목록을 통과해야 한다. 대상은 본문 안의
  링크 href·이미지 src뿐 아니라, 원문 데이터가 **본문과 별개의 필드로 들고 오는 출처 링크(sourceUrl)**
  를 포함한다. 허용 목록은 두 가지다:
  - 본문 안의 링크: `http`·`https`·`mailto` (원문에 이메일 링크가 있을 수 있다 — 기존 sanitize 동작)
  - 출처 링크(`sourceUrl`): `http`·`https` 만. 출처는 웹 주소이므로 `mailto` 를 받을 이유가 없다.

  허용 스킴이 아니면 링크를 렌더하지 않는다(요소를 생략하거나 텍스트만 남긴다).
  **스킴 목록의 정본은 한 곳에 둔다** — 가드 모듈이 두 목록을 모두 소유하고,
  sanitize 설정과 출처 링크 컴포넌트가 각각 그것을 참조한다. 목록이 코드 두 곳에 복제되면 안 된다.
  (강제 위치: `features/content-render/lib/url-safety.ts` + 그것을 참조하는 sanitize 설정)

  > **정본을 왜 shared 가 아니라 features 에 두는가** (2026-08-08 정정). 이 스펙은 처음에
  > "shared 의 공용 URL 가드"라고 적었지만 구현은 `features/content-render` 에 놓였고,
  > **구현 쪽이 맞다.** 두 목록을 가르는 근거가 "출처는 웹 주소이므로 mailto 를 받을 이유가 없다"
  > 같은 **도메인 판단**이라, `shared` 규칙("도메인 지식 금지 — 어느 프로젝트에 옮겨도 동작해야 한다")과
  > 정면으로 어긋난다. 실제로 도메인 없는 부분(문자열 정리·스킴 추출)만 `shared/lib/url.ts` 로
  > 내려가 있고 목록은 여기 남았다 — 경계가 이미 옳게 그어져 있었고 문서만 낡아 있었다.
  위반 시: sanitize 를 거치지 않는 필드로 `javascript:` 링크가 렌더돼 클릭 시 스크립트 실행(XSS).

  > D2 는 강제 위치가 sanitize 라 **본문 안의 URL만** 덮는다. 출처 링크는 본문이 아니라 별도 필드라
  > 그 방벽 밖에 있었다. D4 가 출처 링크를 범위에 넣고도 `rel` 만 요구해 스킴이 빈칸으로 남았다.
  > (2026-08-06 review 에서 발견 — 당시 데이터는 하드코딩이라 도달 불가였으나 수집이 붙으면 실재한다)

## 시나리오 — 각각 어느 불변식을 검증하는지 ID 참조 (불변식마다 실패 경로 1개 이상)

- S1 (INV-D1/D2, 실패경로): Given 본문에 `<script>alert(1)</script>`가 포함된 원문 /
  When 상세 렌더 / Then script는 제거되고 실행되지 않는다.
- S2 (INV-D2, 실패경로): Given `<img src=x onerror=alert(1)>` / When sanitize /
  Then onerror 속성이 제거되고 img는 src만 남거나 걸러진다.
- S3 (INV-D2, 실패경로): Given `<a href="javascript:alert(1)">x</a>` / When sanitize /
  Then href의 javascript: 스킴이 제거된다(링크 무력화).
- S4 (INV-D3, 실패경로): Given 렌더 컴포넌트 / When 소스에서 dangerouslySetInnerHTML 검색 /
  Then 사용처가 없다(게이트 통과).
- S5 (INV-D2): Given 정상 본문(p·h2·code·ul) / When 렌더 / Then 서식이 유지된 채 안전하게 표시된다.
- S6 (INV-D4, 실패경로): Given 본문에 target=\_blank 외부 링크 / When 렌더 /
  Then rel="noopener noreferrer"가 부여돼 있다.
- S7 (INV-D5): Given alt 없는 본문 이미지 / When 렌더 / Then alt=""(장식)로 처리돼 스크린리더가 건너뛴다.
- S8 (INV-D6, 실패경로): Given `sourceUrl` 이 `javascript:alert(1)` 인 소식 / When 상세 렌더 /
  Then 출처 링크가 렌더되지 않는다.
- S9 (INV-D6, 실패경로): Given `sourceUrl` 이 `JaVaScRiPt:`·`\tjavascript:`·`data:text/html,...` 처럼
  대소문자·제어문자·다른 스킴으로 위장한 값 / When 가드 판정 / Then 전부 거부된다(허용 목록 방식).
- S10 (INV-D2): Given `<img src="https://ex.com/a.png" width="704" height="300">` / When sanitize /
  Then 두 속성이 보존된다 — 브라우저가 도착 전에 자리를 비울 수 있다.
- S11 (INV-D2, 실패경로): Given 치수가 조건을 못 맞추는 이미지 —
  `width="abc"`(숫자 아님) · `width="-1"`(양수 아님) · `width="0" height="0"`(0 쌍) ·
  `width` 만 있고 `height` 없음 · `width="704.5"`(정수 아님) · `width="704px"`(단위) ·
  `width=" 704 "`(공백) · `width="1" height="99999"`(비율 상한 초과) ·
  `width="400" height="4001"`(비율 상한 바로 밖) · `width="20001"`(절대 상한 초과) ·
  20자리 값(실측값일 수 없는 자릿수) / When sanitize / Then `width`·`height` 가 **둘 다** 제거된다.
  이미지 자체와 `src`·`alt` 는 남는다 — 치수가 틀렸다고 그림을 버리지는 않는다.

  > `0` 을 검증할 때는 **쌍으로** 넣어야 한다. `width="0" height="300"` 은 비율이 무한대라
  > 조건 3 이 대신 잡아서, 조건 2 를 없애도 거부된다 — 조건 2 를 검증하지 못하는 시나리오다.
  > `0/0` 은 비율 판정이 침묵하므로 그때 비로소 조건 2 가 유일한 방벽이 된다.

- S12 (INV-D2): Given 경계값 이미지 — `width="400" height="4000"`(정확히 10:1) ·
  `width="20000" height="20000"`(절대 상한 그 자리) / When sanitize / Then 보존된다.
  상한이 멀쩡한 세로 이미지까지 버리지 않는다(경계는 포함이다).
- S13 (INV-D2, 실패경로): Given `<img src="data:image/png;base64,...">` 처럼 허용 스킴이 아닌 이미지 /
  When sanitize / Then `<img>` 가 **태그째** 사라진다 — 껍데기가 빈 상자로 남지 않는다.
  주변 내용은 잃지 않는다.

## 신뢰 경계

- 믿는 값: sanitize 함수를 통과한 뒤의 HTML(화이트리스트 결과), 공용 URL 가드를 통과한 URL,
  우리 렌더 컴포넌트가 부여하는 속성(rel 등).
- 믿지 않는 값: 저장된 원문 HTML 원본 전체(태그·속성·URL·이미지 src), 소스가 준 본문의 모든 마크업,
  그리고 **본문 밖의 URL 필드(`sourceUrl`)** — sanitize 는 본문만 훑으므로 이 필드는 공용 가드를 따로 거친다.
  (제목·요약·출처명·태그는 속성이 아니라 텍스트 자리에만 들어가므로 React 이스케이프로 충분하다.
  URL·속성 자리로 옮기게 되면 그때 이 목록에 추가한다.)

## 비범위

- 수집·중복제거·요약·랭킹 → 별도 스펙(ingestion-ranking.md).

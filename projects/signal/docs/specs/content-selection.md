# 무엇을 모으고 무엇을 보여줄지

PRODUCT.md 의 성공 기준 첫 줄이 **"적합성 — 관심에 맞는 정보를 얼마나 잘 가져오는가"** 인데,
지금 파이프라인에는 그걸 정하는 규칙이 없다. 이 스펙은 그 빈칸 셋을 메운다:

1. **주제 밖 글을 거른다** — HN 프론트페이지는 AI·IT 전용이 아니다(2026-08-09 칵테일 레시피 유입 확인)
2. **출처를 실제 발행처로 보여준다** — 지금은 HN 을 거친 글이 전부 "Hacker News" 로 보인다
3. **소스를 두 층으로 나눈다** — 매일 훑을 것과 시간 날 때 읽을 것은 성격이 다르다

랭킹 계산식·중복제거·요약 생성 규칙은 여기서 바꾸지 않는다 → ingestion-ranking.md.

## 실측이 설계를 바꾼 자리 (2026-08-10, `npm run count:tokens`)

추정으로 정하지 않았다. 적재된 최신 8건으로 실제 프롬프트 토큰을 셌고, 두 가지가 뒤집혔다.

| 항목                            |  입력 토큰 |
| ------------------------------- | ---------: |
| 칵테일 레시피 (주제 밖)         | **13,099** |
| 나머지 7건 평균                 |      2,496 |
| 근거 없어 제목 번역만 하는 항목 |        269 |

- **제일 비싼 항목이 주제 밖 글이었다.** 한 건이 다른 항목 5건 값이다 → INV-F1 이
  "요약보다 먼저, 제목만으로" 인 이유가 여기 있다. 제목만 판정하면 약 270 토큰이다.
- **지시문을 다 실으면 번역만 하는 항목이 269 → 1,845 토큰(7배)** 이 된다 → INV-P1.

## 불변식 — 각각 참/거짓 판정 가능. 위반 시 무슨 일이 일어나는지 / 어디서 강제되는지 명시

### 주제 선별 (F)

- INV-F1: 주제 판정은 **요약·본문추출보다 먼저**, **제목만으로** 한다. 주제 밖으로 판정된 항목에는
  요약·본문추출을 시도하지 않는다. (강제 위치: 서버 — 파이프라인 순서 + 판정 호출의 입력에 본문이 없음)
  위반 시: 주제 밖 글에 요약 비용을 다 쓴다(실측 13,099 토큰짜리 항목이 실제로 있었다).

- INV-F2: 주제 밖으로 판정된 항목은 **적재하지 않는다.** 다만 그 **건수와 제목은 수집 리포트에 남긴다.**
  (강제 위치: 서버 — 적재 전 필터 + IngestReport)
  위반 시: 피드가 무관한 글로 오염된다. 리포트에 안 남기면 **오판을 알아챌 방법이 없다** —
  모델이 잘못 걸러도 그 글은 영영 안 보이고 아무 기록도 남지 않는다.

- INV-F3: 주제 판정은 신뢰 경계 밖이다. 판정이 실패하거나 응답이 깨지면 **거르지 않는다**(통과시킨다).
  (강제 위치: 서버 — 판정 실패 시 기본값 = 통과)
  위반 시: 판정 호출이 죽는 날 피드가 통째로 비고, 그 원인은 화면에 안 나타난다.
  실패는 "안 거름"으로 기울여야 한다 — 잘못 거르는 쪽이 잘못 통과시키는 쪽보다 비싸다.

### 프롬프트 조립 (P)

- INV-P1: 항목마다 **그 항목에 필요한 작업의 지시만** 싣는다. 번역만 필요한 항목의 프롬프트에는
  요약 규칙이 들어가지 않는다. (강제 위치: 서버 — 조립 함수 + 조립 결과를 직접 보는 테스트)
  위반 시: 요약도 안 할 항목에 요약 지시를 실어 보낸다(실측 7배).

### 출처와 공식 여부 (O)

- INV-O1: 화면에 보이는 출처는 **실제 발행처**다. 수집 소스 이름이 아니라 원문 주소에서 얻는다.
  (강제 위치: 서버 — 적재 시 원문 주소에서 발행처를 뽑아 저장 / 화면 — 그 값을 렌더)
  위반 시: HN 을 거쳐 온 글이 발행처와 무관하게 전부 "Hacker News" 로 보여
  **"이게 공식 발표인가"를 화면에서 판단할 수 없다**(사용자가 실제로 그 판단에 쓴다).

- INV-O2: 공식 여부는 **근거를 구분해서** 남긴다: `byUrl`(원문 주소가 그 주체의 도메인 — 기계적으로 확실)
  / `byContent`(내용이 "〜가 공식 발표했다" — 모델 판단) / `none`. 화면은 둘을 **다른 표시로** 보여준다.
  (강제 위치: 서버 — 두 판정을 따로 계산해 따로 저장 / 화면 — 서로 다른 표시)
  위반 시: 모델 판단이 주소 근거와 같은 확실성으로 보인다. 모델이 틀리면 사용자가 잘못 믿는다.

- INV-O3: `byUrl` 판정은 **모델을 거치지 않는다.** 원문 주소의 도메인과 설정에 적힌 주체 도메인을
  맞춰 보는 것뿐이다. (강제 위치: 서버 — 순수 함수)
  위반 시: 확실한 근거를 모델 판단으로 만들어 O2 의 구분이 무의미해진다.

### 소스 층 (L)

- INV-L1: 소스마다 층을 둔다: `daily`(화제성 — 매일 훑는 것) / `deep`(전문적 — 시간 날 때 읽는 것).
  층은 **소스에 귀속한다**(항목이 아니라). (강제 위치: 설정파일 — 소스 정의)
  위반 시: 같은 소스의 글이 항목마다 다른 층을 갖게 돼 "어느 소스가 어느 층인가"를 알 수 없다.
  - INV-R4 와 같은 이유다 — 소스에 귀속하는 값이 항목 쪽에 흩어지면 어느 것이 진짜인지 알 수 없다.

- INV-L2: 층은 **화면에 별도 컨트롤로 드러나지 않는다.** 랭킹 weight 로만 반영한다.
  (강제 위치: 화면 — 층을 가리키는 필터·토글이 없다)
  위반 시: 사용자가 고르지 않은 축이 화면에 늘어난다. 화면을 가르는 축은 갈래다
  (→ planned/keywords-and-kinds.md). 두 축을 동시에 1차 기준으로 두면 훑는 방법이 갈린다.

## 시나리오 — Given/When/Then + INV ID (불변식마다 실패 경로 1개 이상)

- CS1 (INV-F1): Given 제목이 "Tuxedo No. 2 – Cocktail recipes" 인 항목 / When 수집 /
  Then 주제 판정이 먼저 불리고, 그 판정의 입력에 본문이 들어 있지 않다.
- CS2 (INV-F1, 실패경로): Given 주제 밖으로 판정된 항목 / When 같은 주기 /
  Then 그 항목에 대해 요약·본문추출 호출이 **한 번도** 일어나지 않는다.
- CS3 (INV-F2): Given 주제 밖 2건과 주제 안 3건 / When 수집 /
  Then 적재는 3건이고, 리포트에 걸러진 2건의 건수와 제목이 남는다.
- CS4 (INV-F3, 실패경로): Given 주제 판정 호출이 타임아웃 / When 수집 /
  Then 그 항목은 **걸러지지 않고** 적재되며, 판정 실패가 리포트에 남는다.
- CS5 (INV-P1, 실패경로): Given 근거가 없어 제목 번역만 하는 항목 / When 프롬프트 조립 /
  Then 조립된 프롬프트에 요약 규칙 문장이 들어 있지 않다.
- CS6 (INV-O1): Given HN 을 거쳐 들어온 `techcrunch.com/...` 항목 / When 화면 조회 /
  Then 출처가 "TechCrunch" 로 보인다("Hacker News" 가 아니다).
- CS7 (INV-O1, 실패경로): Given 원문 주소에서 발행처를 못 뽑는 항목 / When 화면 조회 /
  Then 빈 출처를 그리지 않고 수집 소스 이름으로 되돌아간다(빈칸을 만들지 않는다).
- CS8 (INV-O2): Given `anthropic.com` 이 원문인 항목과, 내용으로만 공식이라 판정된 기사 /
  When 화면 조회 / Then 둘의 표시가 서로 다르다.
- CS9 (INV-O2, 실패경로): Given 모델이 공식 여부를 돌려주지 않음 / When 저장 /
  Then `none` 으로 남고 공식 표시가 붙지 않는다.
- CS10 (INV-O3): Given 원문 주소가 `https://www.anthropic.com/news/x` 이고 설정에 앤트로픽 도메인이 있음 /
  When 판정 / Then 모델 호출 없이 `byUrl` 이 된다.
- CS11 (INV-L1): Given `deep` 층 소스의 항목과 `daily` 층 소스의 항목이 같은 시각 /
  When 점수 계산 / Then 층이 weight 를 통해 순서에 반영된다.
- CS12 (INV-L2, 실패경로): Given 피드 화면 / When 컨트롤 줄을 본다 /
  Then 층을 고르는 토글·칩이 존재하지 않는다.

## 신뢰 경계

- 믿는 값: 소스 설정파일(소스 목록·weight·층·주체 도메인). 원문 주소의 도메인 문자열(우리가 파싱한 결과).
- 믿지 않는 값: 모델의 주제 판정, 모델의 공식 여부 판정(`byContent`), 외부 응답의 모든 필드.
  → 그래서 INV-F3(실패는 통과로)과 INV-O2(근거 구분)가 있다.

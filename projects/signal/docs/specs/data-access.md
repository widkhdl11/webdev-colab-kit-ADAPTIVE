# 데이터 접근 권한 스펙

이 사이트에는 로그인이 없다. 그래서 인가 모델은 **한 줄로 요약된다 — 브라우저는 읽기만,
쓰기는 서버만.** 브라우저에 나가는 키(publishable)는 공개된 값이라 그 키로 할 수 있는 일이
곧 아무나 할 수 있는 일이고, 그것을 제한하는 것은 애플리케이션 코드가 아니라 DB 의 행 수준
접근 정책이다. 여기가 뚫리면 남이 항목을 지우거나 가짜 소식을 밀어 넣을 수 있다.

쓰기 정책을 하나 추가하는 것만으로 이 모델이 무너지기 때문에, "정책이 있다"가 아니라
**"쓰기 정책이 없다"** 를 불변식으로 둔다.

## 불변식

- INV-DA1: 공개 테이블(`item` · `tag` · `item_tag`)은 행 수준 접근 제어가 켜져 있고, 있는
  정책은 **읽기(select)뿐**이다. 읽기는 전부 공개다 — 가릴 것이 없는 사이트다.
  (강제 위치: DB — 마이그레이션의 `enable row level security` + select 정책)
  위반 시: 제어가 꺼지면 공개 키로 테이블 전체를 쓸 수 있다.

- INV-DA2: 그 테이블들에 insert·update·delete 정책을 만들지 않는다. 행 수준 제어가 켜져 있고
  해당 정책이 없으면 공개 키로는 쓸 수 없다 — 이것이 쓰기를 막는 유일한 장치다. 쓰기는 서버가
  secret 키로만 하고, 그 키는 제어를 우회한다(INV-S4).
  (강제 위치: DB — 정책의 부재. 게이트: 마이그레이션 본문에 `for insert|update|delete|all` 이
  나타나지 않는지 검사한다)
  위반 시: 쓰기 정책이 하나라도 생기는 순간 "브라우저는 읽기만"이 거짓이 되고, 그 정책의
  조건식이 곧 인가 모델이 된다 — 그때는 이 스펙을 다시 써야 한다.

- INV-DA3: 운영 기록 테이블(`ingest_run`)은 공개 키로 **보이지 않는다.** 행 수준 제어가 켜져
  있고 정책이 하나도 없다. 수집이 언제 얼마나 돌았고 토큰을 얼마나 썼는지는 개발자용이다.
  (강제 위치: DB — 정책의 부재)
  위반 시: 운영 지표와 비용이 그대로 공개된다.

## 시나리오

- S1 (INV-DA1): Given 마이그레이션 / When 세 테이블을 확인한다 / Then 셋 다 행 수준 제어가 켜져 있다.
- S2 (INV-DA1): Given 공개 키 / When `item` 을 조회한다 / Then 읽힌다.
- S3 (INV-DA2, 실패경로): Given 마이그레이션 전체 / When 쓰기 정책을 찾는다 / Then 하나도 없다.
- S4 (INV-DA2, 실패경로): Given 공개 키 / When `item` 에 insert 한다 / Then 거부된다.
- S5 (INV-DA3, 실패경로): Given 공개 키 / When `ingest_run` 을 조회한다 / Then 보이지 않는다.

## 신뢰 경계

- 믿는 값: 서버에서만 쓰는 secret 키로 연 연결.
- 믿지 않는 값: 브라우저에 나간 publishable 키로 오는 모든 요청. 이 키는 공개된 값이라
  "우리 앱이 보냈다"는 근거가 되지 않는다.

## 비범위

- **사용자별 접근 제어.** 계정이 없으니 구분할 주체가 없다. 로그인이 생기면 이 스펙 전체를
  다시 써야 한다 — INV-DA2 의 "쓰기 정책 없음"이 제일 먼저 깨진다.
- **파일 저장소 정책.** 이 프로젝트는 파일을 저장하지 않는다.
- **호출자 확인** — `ingest-auth.md` 가 다룬다.

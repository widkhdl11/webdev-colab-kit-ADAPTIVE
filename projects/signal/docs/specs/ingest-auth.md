# 수집 엔드포인트 호출자 확인 스펙

수집은 `GET /api/ingest` 하나로 시작한다. 이 경로는 외부 소스를 긁고 LLM 을 호출하므로
**부를 때마다 돈이 든다.** 로그인이 없는 사이트라 확인할 수 있는 것은 호출자가 공유 시크릿을
알고 있는가 하나뿐이고, 그 검사가 느슨해지거나 설정 누락으로 사라지면 엔드포인트는 그대로
공개된 비용 수도꼭지가 된다. 어기면 사고가 조용히 난다 — 청구서가 오기 전까지는 아무 표시도
나지 않는다.

## 불변식

- INV-IA1: 수집 엔드포인트는 `Authorization` 헤더가 `Bearer <CRON_SECRET>` 과 **문자열 전체가
  같을 때만** 동작한다. 아니면 401 을 돌려주고 수집은 시작되지 않는다 — 외부 요청도, LLM 호출도
  일어나지 않는다. (강제 위치: 서버 — 라우트 핸들러 진입부, 다른 일이 시작되기 전)
  위반 시: 아무나 수집을 돌릴 수 있고 LLM 비용이 남의 손에 들어간다.

- INV-IA2: `CRON_SECRET` 이 없거나 빈 문자열이면 엔드포인트는 **열지 않고 503 으로 닫는다.**
  설정을 빼먹은 상태가 곧 공개가 되면 안 된다. (강제 위치: 서버 — 헤더를 비교하기 전)
  위반 시: 배포에서 환경변수 이름을 빼먹는 흔한 실수 하나가 그대로 무인증 공개가 된다.

- INV-IA3: 시크릿 비교는 **정확히 같은가**로만 한다. 접두사 일치·대소문자 무시·부분 일치로
  느슨해지지 않는다. (강제 위치: 서버 — 비교 연산 자체)
  위반 시: 시크릿의 앞부분만 아는 호출자가 통과한다.

- INV-IA4: 수집을 시작하는 입구는 이 라우트의 `GET` 하나다. 같은 파일에서 다른 HTTP 메서드를
  내보내지 않는다. (강제 위치: 서버 — 모듈이 내보내는 것)
  위반 시: 확인을 거치지 않는 두 번째 입구가 생기고, INV-IA1 은 그 입구를 모른다.

- INV-IA5: 수집 중에 서버가 밖으로 보내는 요청의 목적지는 **공개 인터넷의 http·https 주소**
  여야 한다. 스킴이 다른 것, 루프백·사설·링크로컬·고유로컬·멀티캐스트 대역, 이름이 내부를
  가리키는 것(`localhost`·`*.internal`·`*.local` 등)으로는 요청하지 않는다.
  (강제 위치: 서버 — 요청을 보내기 전, 목적지 판정 한 자리)
  위반 시: 소스 한 곳이 피드에 내부 주소를 실으면 서버가 그것을 받아 와 본문으로 저장하고,
  그 내용이 공개 화면에 렌더된다. **내부 응답이 밖으로 나간다.** 클라우드 메타데이터 주소
  하나면 인스턴스 자격 증명이 그대로 나온다.

- INV-IA6: 리다이렉트는 자동으로 따라가지 않는다. **한 칸씩 따라가며 칸마다 INV-IA5 를 다시
  판정하고**, 정해진 횟수를 넘으면 중단한다. (강제 위치: 서버 — 목적지 판정과 같은 자리)
  위반 시: 첫 주소만 검사하는 것은 검사하지 않는 것과 같다 — 공개 주소가 302 한 번으로
  내부 주소를 가리키면 그만이다.

## 시나리오

- S1 (INV-IA1): Given `CRON_SECRET` 이 설정돼 있다 / When 맞는 `Bearer` 값으로 부른다 /
  Then 200 이고 수집 보고서를 돌려준다.
- S2 (INV-IA1, 실패경로): Given 같은 상태 / When `Authorization` 헤더 없이 부른다 / Then 401.
- S3 (INV-IA1, 실패경로): Given 같은 상태 / When 값이 틀리다 / Then 401 이고 **비용이 드는 일이
  시작되지 않는다.**
- S4 (INV-IA1, 실패경로): Given 같은 상태 / When `Bearer ` 접두사 없이 값만 보낸다 / Then 401.
- S5 (INV-IA2, 실패경로): Given `CRON_SECRET` 이 빈 문자열이다 / When 부른다 / Then 503.
- S6 (INV-IA2, 실패경로): Given 환경변수 자체가 없다 / When 부른다 / Then 503.
- S7 (INV-IA3, 실패경로): Given 시크릿이 설정돼 있다 / When 맞는 값 **뒤에 무언가를 덧붙여**
  보낸다 / Then 401.
- S8 (INV-IA3, 실패경로): Given 같은 상태 / When 대소문자만 다른 값을 보낸다 / Then 401.
- S9 (INV-IA4): Given 라우트 모듈 / When 내보내는 것을 센다 / Then `GET` 이 있고 다른 메서드는 없다.
- S10 (INV-IA5): Given 공개 인터넷의 http·https 주소 / When 목적지를 판정한다 / Then 통과한다.
  **막는 쪽만 보면 전부 막는 구현이 통과하고, 그러면 수집이 통째로 죽는다.**
- S11 (INV-IA5, 실패경로): Given 루프백 주소를 어떤 표기로든 준다(점 넷·십진 한 덩어리·8진·
  16진·IPv6·IPv4 를 품은 IPv6·`localhost`) / When 판정한다 / Then 전부 거부된다.
- S12 (INV-IA5, 실패경로): Given 사설·링크로컬·통신사 내부 대역이나 내부를 가리키는 이름 /
  When 판정한다 / Then 거부된다. 클라우드 메타데이터 주소가 여기 포함된다.
- S13 (INV-IA5, 실패경로): Given 차단 대역의 **바로 바깥** 주소 / When 판정한다 / Then 통과한다.
  대역을 넓게 잡아 멀쩡한 발행처를 막지 않는다.
- S14 (INV-IA5, 실패경로): Given http·https 가 아닌 스킴이거나 스킴이 없는 문자열 /
  When 판정한다 / Then 거부된다.
- S15 (INV-IA5, 실패경로): Given 첫 주소가 내부 주소다 / When 가져오기를 부른다 /
  Then 요청이 **한 번도 나가지 않는다.**
- S16 (INV-IA6, 실패경로): Given 공개 주소가 내부 주소로 돌려보낸다 / When 가져오기를 부른다 /
  Then 두 번째 요청을 보내지 않는다.
- S17 (INV-IA6, 실패경로): Given 리다이렉트가 상대 주소로 온다 / When 따라간다 /
  Then 지금 주소를 기준으로 풀어서 다시 판정한다.
- S18 (INV-IA6): Given 공개 주소끼리의 리다이렉트 / When 따라간다 / Then 그대로 따라간다.
- S19 (INV-IA6, 실패경로): Given 서로를 가리키는 주소 한 쌍 / When 따라간다 /
  Then 정해진 횟수에서 끊고 던진다.

## 신뢰 경계

- 믿는 값: 서버 환경변수 `CRON_SECRET`.
- 믿지 않는 값: 요청 헤더 전부. `Authorization` 은 비교 대상이지 판단 근거가 아니다 —
  일치하지 않으면 그 요청에 대해 아무것도 하지 않는다.

## 비범위

- **사용자 인증.** 이 사이트에는 계정도 세션도 없다. 로그인이 생기면 이 스펙으로는 부족하고
  새 스펙이 필요하다.
- **역할·권한.** 호출자는 통과하거나 통과하지 못하거나 둘뿐이고 그 사이 등급이 없다.
- **비용 상한.** 통과한 호출이 얼마나 쓸 수 있는지는 이 스펙이 정하지 않는다.
- **데이터 접근 권한** — `data-access.md` 가 다룬다.
- **공개 이름이 내부 주소로 풀리는 경우(DNS 리바인딩).** INV-IA5 는 주소에 적힌 것을 본다.
  이름을 실제로 풀어서 그 결과를 봐야 잡히는데, 판정에 쓴 주소와 요청이 실제로 쓰는 주소가
  달라질 수 있는 문제가 그때 새로 생긴다(푸는 시점과 보내는 시점 사이에 답이 바뀔 수 있다).
  **지금 열어 두는 위험이라고 밝혀 둔다** — 목적지 목록을 우리가 정하는 쪽으로 좁히거나,
  요청을 나가는 대리 서버 한 곳으로 모으는 것이 이 위험을 닫는 길이다.
- **통과한 목적지가 무엇을 돌려주는지.** 받은 내용의 안전성은 `content-safety.md` 가 다룬다.
- **포트.** 목적지의 포트는 제한하지 않는다. 제한하면 멀쩡한 발행처가 막히고, 공인 주소의
  다른 포트를 두드려 얻을 수 있는 것은 실패까지 걸린 시간 정도인데 그 값은 호출자에게
  돌아가지 않는다(수집 리포트는 시크릿을 아는 호출자만 본다).
- **터널링 표기 일부.** IPv4 를 품은 IPv6 표기 중 널리 쓰이는 것들(`::ffff:`·옮겨 적은 표기·
  NAT64·6to4)은 풀어서 판정한다. Teredo(`2001:0::/32`)는 아직 아니다 — 그 주소로 실제
  트래픽이 흐르는 경로가 배포 환경에 있어야 위험해진다.

# 수집 엔드포인트 호출자 확인 스펙

수집은 `GET /api/ingest` 하나로 시작한다. 이 경로는 외부 소스를 긁고 LLM 을 호출하므로
**부를 때마다 돈이 든다.** 로그인이 없는 사이트라 확인할 수 있는 것은 호출자가 공유 시크릿을
알고 있는가 하나뿐이고, 그 검사가 느슨해지거나 설정 누락으로 사라지면 엔드포인트는 그대로
공개된 비용 수도꼭지가 된다. 어기면 사고가 조용히 난다 — 청구서가 오기 전까지는 아무 표시도
나지 않는다.

## 불변식

- INV-IA1: 수집 엔드포인트는 `Authorization` 헤더가 `Bearer <CRON_SECRET>` 과 **문자열 전체가
  같을 때만** 동작한다. 아니면 401 을 돌려주고 수집은 시작되지 않는다 — 외부 요청도, LLM 호출도
  일어나지 않는다. (강제 위치: 서버 — 라우트 핸들러 진입부, 다른 일이 시작되기 전)
  위반 시: 아무나 수집을 돌릴 수 있고 LLM 비용이 남의 손에 들어간다.

- INV-IA2: `CRON_SECRET` 이 없거나 빈 문자열이면 엔드포인트는 **열지 않고 503 으로 닫는다.**
  설정을 빼먹은 상태가 곧 공개가 되면 안 된다. (강제 위치: 서버 — 헤더를 비교하기 전)
  위반 시: 배포에서 환경변수 이름을 빼먹는 흔한 실수 하나가 그대로 무인증 공개가 된다.

- INV-IA3: 시크릿 비교는 **정확히 같은가**로만 한다. 접두사 일치·대소문자 무시·부분 일치로
  느슨해지지 않는다. (강제 위치: 서버 — 비교 연산 자체)
  위반 시: 시크릿의 앞부분만 아는 호출자가 통과한다.

- INV-IA4: 수집을 시작하는 입구는 이 라우트의 `GET` 하나다. 같은 파일에서 다른 HTTP 메서드를
  내보내지 않는다. (강제 위치: 서버 — 모듈이 내보내는 것)
  위반 시: 확인을 거치지 않는 두 번째 입구가 생기고, INV-IA1 은 그 입구를 모른다.

## 시나리오

- S1 (INV-IA1): Given `CRON_SECRET` 이 설정돼 있다 / When 맞는 `Bearer` 값으로 부른다 /
  Then 200 이고 수집 보고서를 돌려준다.
- S2 (INV-IA1, 실패경로): Given 같은 상태 / When `Authorization` 헤더 없이 부른다 / Then 401.
- S3 (INV-IA1, 실패경로): Given 같은 상태 / When 값이 틀리다 / Then 401 이고 **비용이 드는 일이
  시작되지 않는다.**
- S4 (INV-IA1, 실패경로): Given 같은 상태 / When `Bearer ` 접두사 없이 값만 보낸다 / Then 401.
- S5 (INV-IA2, 실패경로): Given `CRON_SECRET` 이 빈 문자열이다 / When 부른다 / Then 503.
- S6 (INV-IA2, 실패경로): Given 환경변수 자체가 없다 / When 부른다 / Then 503.
- S7 (INV-IA3, 실패경로): Given 시크릿이 설정돼 있다 / When 맞는 값 **뒤에 무언가를 덧붙여**
  보낸다 / Then 401.
- S8 (INV-IA3, 실패경로): Given 같은 상태 / When 대소문자만 다른 값을 보낸다 / Then 401.
- S9 (INV-IA4): Given 라우트 모듈 / When 내보내는 것을 센다 / Then `GET` 이 있고 다른 메서드는 없다.

## 신뢰 경계

- 믿는 값: 서버 환경변수 `CRON_SECRET`.
- 믿지 않는 값: 요청 헤더 전부. `Authorization` 은 비교 대상이지 판단 근거가 아니다 —
  일치하지 않으면 그 요청에 대해 아무것도 하지 않는다.

## 비범위

- **사용자 인증.** 이 사이트에는 계정도 세션도 없다. 로그인이 생기면 이 스펙으로는 부족하고
  새 스펙이 필요하다.
- **역할·권한.** 호출자는 통과하거나 통과하지 못하거나 둘뿐이고 그 사이 등급이 없다.
- **비용 상한.** 통과한 호출이 얼마나 쓸 수 있는지는 이 스펙이 정하지 않는다.
- **데이터 접근 권한** — `data-access.md` 가 다룬다.

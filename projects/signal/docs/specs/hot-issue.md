# 핫이슈 — 문턱 판정과 배치

## 왜 이 문서가 있나

지금 화면의 `핫뉴스` 뱃지는 **그날 점수 상위 3개**다(ingestion-ranking INV-R5). 그 점수는
`시간감쇠 × 소스 weight` 뿐이라 **글의 내용을 안 본다**. 그래서 두 가지가 어긋난다.

- 큰 일이 있는 날과 한가한 날에 **똑같이 3개**가 뜬다. 개수가 그날의 사정을 안 따라간다.
- 무엇이 뜨는지가 **어느 매체가 썼나**로 정해진다. OpenAI 블로그의 잡담글이 The Verge 의
  단독 보도를 이긴다.

2026-08-27·08-30 에 사용자가 "이슈성·중요도로 뽑는 것은 나중"이라고 결정했고, 그 기록에
**"붙는 날 이 상수를 조정하는 게 아니라 고르는 기준 자체가 바뀐다"** 고 적혀 있다.
2026-09-20 에 그 결정을 뒤집었다(결정 카드 `signal-20260920-3-d2`).

## 이번 범위

**한다**
- 글마다 종류(뉴스/툴)를 판정하고 저장한다 (INV-G1)
- 글마다 핫이슈 문턱을 판정하고 **중요도(0~3)를 저장한다** (INV-G2)
- 중요도 ≥ 1 인 글을 `1번` 문에 배정하고 그 값을 저장한다 (INV-H1)
- 이슈성을 모델 없이 계산해 **문 안에서의 순서**로 쓴다 (INV-N3)
- `1번` 문에 **개수 상한을 두지 않는다** — 문턱을 넘은 것은 전부 배정한다 (INV-N4)
- 화면 배치는 종류 × 문턱의 곱으로 한다 (INV-G3)

**안 한다**
- `2번`·`3번` 문, 관련성 3단계, 프로필 해시 → keywords-and-kinds.md INV-N1 에 그대로 있다
- 같은 사건 묶기(교차 발행처 수를 실제로 세는 것) → INV-N3 의 조건부 항으로만 적는다
- 이슈성으로 글을 들이는 것 → INV-N3 이 금지한다. 순서에만 쓴다

## 불변식

### 판정 (G)

- INV-G1: 글마다 **종류**를 판정한다: `뉴스` / `툴`. 한 글이 둘 다일 수 있다.
  (강제 위치: 스키마 — 다대다 / 서버 — 모델 판정)
  위반 시: 새 툴을 발표한 글은 뉴스이면서 툴이다. 하나만 고르게 하면 한쪽에서 사라진다.

- INV-G2: 종류와 별개로 **핫이슈 문턱**을 판정한다. 셋 중 하나라도 참이면 넘은 것이다 —
  ① 사용자가 쓰는 것에 변화가 있나 ② 지금까지의 방향을 뒤집나 ③ 놓치면 기회가 닫히나.
  **중요도는 참인 개수(0~3)이고 저장한다.**
  (강제 위치: 서버 — 모델 판정 + 저장)
  위반 시: "중요한가?" 처럼 흐릿하게 물으면 모델이 **큰 회사 발표를 전부 중요하다고 답한다** —
  고치려던 상태(빅테크 발표만 상단에 쌓임)로 그대로 돌아간다.
  - 셋을 **따로** 묻고 답도 따로 받는다. 하나로 뭉쳐 물으면 어느 질문이 참이어서 뽑혔는지
    사람이 확인할 수 없고, 첫 2주 표본 검토가 할 일이 없어진다.
  - 판정에 실패하면(응답을 못 읽음·타임아웃) **중요도를 채우지 않는다.** 0 으로 적으면
    "물어봤는데 아니었다"와 "못 물어봤다"가 같아지고, 다음 주기가 다시 안 묻는다.

- INV-G3: **두 자리는 문턱만으로 갈리고, 스킬·툴은 그 위에 겹친다.**
  핫이슈와 소식은 들어온 글 **전부**를 문턱으로 가른 것이라 종류를 보지 않는다.
  스킬·툴은 그중 `툴` 인 것을 따로 모아 보는 자리라, 같은 글이 두 자리에 동시에 선다.
  (강제 위치: 서버 — 순수 함수 + 그 함수를 실제로 부르는 화면)

  |                  | 문턱 넘음        | 못 넘음         |
  | ---------------- | ---------------- | --------------- |
  | **툴 아님**      | 핫이슈           | 소식            |
  | **툴**           | 핫이슈 + 스킬·툴 | 소식 + 스킬·툴  |

  위반 시(종류로 소식을 거르면): **갈 곳 없는 글이 조용히 사라진다.** 2026-09-21 실측 —
  판정 받은 117건 중 30건이 `뉴스` 도 `툴` 도 아니라고 판정돼 화면 어디에도 서지 않았다.
  그중 23건은 분석·관점 글이고 7건은 기업·정책 보도다. 소식은 "안 뽑힌 전부"가 서는 자리여야
  이 구멍이 생기지 않는다.
  - **종류 판정(INV-G1)은 `툴` 인지에만 쓰인다.** `뉴스` 는 배치에서 읽지 않는다 —
    계속 판정하지만 화면을 가르는 데는 안 쓴다(뱃지·필터가 나중에 쓸 수 있게 남긴다).
  - 스킬·툴에서는 문턱을 넘은 툴도 빠지지 않는다. 걸어 들어가는 자리라 거기서 빼면
    찾을 데가 없어진다.

- INV-G4: 핫이슈 판정 때 **그날 이미 핫이슈로 뽑힌 제목 목록을 함께 준다.** 같은 사건이면 뺀다.
  (강제 위치: 서버 — 프롬프트 조립 + 목록을 준 뒤 같은 사건이 빠지는지 보는 테스트)
  위반 시: 중복 제거가 정규화 원문 주소 기준이라 **같은 사건을 여러 매체가 쓰면 다 남는다.**
  큰 사건일수록 많이 겹치므로 **제일 중요한 날에 아침 시간을 제일 많이 버린다.**

### 배정과 양 (N·H)

- INV-H1: **문 배정을 저장한다.** 이번 범위에서 채우는 값은 `1번` 하나다 —
  중요도 ≥ 1 이면 `1번`, 아니면 비워 둔다. 값이 없는 항목은 핫이슈 화면에 안 나온다.
  (강제 위치: 스키마 — 항목의 칸 / 서버 — 순수 함수 + 저장)
  위반 시: 저장 안 하면 화면 구분이 불가능하고, 오배정의 원인을 못 짚는다.
  - keywords-and-kinds.md INV-N1 의 **1번 문 부분만** 떼어 쓴 것이다. `2번`·`3번`·`안 들임`과
    관련성 3단계는 아직 열지 않는다. 열 때 이 조항은 INV-N1 에 흡수된다.
  - 비어 있는 것이 곧 "판정 못 받음"이다 — INV-G2 의 실패 처리와 같은 자리다.
  - **배정은 판정과 같은 묶음 안에서 곧바로 한다** (2026-09-21). 모아 두었다가 끝에 한 번
    쓰면, 모으는 동안 수집이 죽었을 때 그 바퀴에 문턱을 넘은 글이 **전부 영영 핫이슈가 못
    된다** — 중요도가 이미 저장돼 「물어봤다」 표시가 찍혔으므로 다음 주기 후보에서 빠지고
    아무도 다시 채우지 않는다. 곧바로 쓰면 잃는 범위가 그 묶음 하나로 줄어든다.
    (강제 위치: 서버 — 배정이 저장과 같은 반복 안에 있다)

- INV-N3: 이슈성은 **모델을 거치지 않는다.** 교차 발행처 수 × 소스 weight × 시간감쇠로 계산한다.
  (강제 위치: 서버 — 순수 함수. 입력이 전부 DB 에 이미 있는 값이다)
  위반 시: 모델에게 점수를 매기게 하면 같은 글을 다시 물었을 때 다른 값이 나오고 날마다 기준이
  흔들린다. INV-O3(주소 근거는 모델을 안 거친다)과 같은 이유다.
  - **이슈성 단독으로는 글을 들이지 않는다.** 교차 발행처 수는 중요도가 아니라 보도량이고,
    보도량은 발표 주체의 크기를 따라간다 — 국내 4곳이 같은 발표를 받아쓰면 5가 되고
    Anthropic 엔지니어링 글은 1이 된다. 들이는 것은 INV-H1 이, 순서만 여기가 정한다.
  - **교차 발행처 수는 지금 항상 1 이다.** 중복 제거가 정규화 원문 주소 기준이라 같은 발표를
    두 매체가 쓰면 서로 다른 글이다. 그 항을 **식에서 빼지 않고 1 로 둔다** — 빼면 같은 사건
    묶기가 붙는 날 식이 조용히 달라지고, 그 전후를 대조할 수 없다.

- INV-N4: **개수 상한을 두지 않는다.** 문턱(INV-H1)을 넘은 글은 그 바퀴에 전부 배정된다.
  뽑히는 수는 그날 무슨 일이 있었는지를 따라간다 — 많은 날도 있고 한 건도 없는 날도 있다.
  (강제 위치: 서버 — 배정 함수에 개수 인자가 없다)
  위반 시: 상한을 두면 **개수가 기준을 대신한다.** 2026-09-21 실측이 그 모양이다 — 문턱을 넘은
  26건 중 10건만 배정되고 16건이 잘렸는데, **판정이 가장 높게 매긴 중요도 2 세 건이 전부 그
  잘린 쪽에 있었다**(알리바바 암 탐지 모델 공개 · 제브 · StepFun Step 5). 자르는 순서가
  이슈성(최근 × 소스 weight)이고 이슈성에는 중요도가 안 들어가기 때문이다(INV-N2 합산 금지).
  즉 상한은 "기준을 대체하지 않는다"고 적혀 있었지만 실제로는 기준을 **거꾸로** 적용하고 있었다.
  - **요금은 이 조항과 무관하다.** 요금을 정하는 값은 몇 건을 **물어볼지**(`HOT_ISSUE_BATCH`)이고,
    상한은 물어본 **뒤에** 자르는 값이라 없애도 호출 수가 늘지 않는다.
  - 판정이 헐거우면 뽑히는 수로 드러난다. 그것을 가리는 것이 상한이었다 — 수가 많아 보이면
    상한을 낮출 게 아니라 문턱 질문(INV-G2)을 고친다.

### 저장과 시각 (H)

- INV-H2: **이슈성은 저장하지 않고 중요도는 저장한다.** 가르는 기준은 다시 계산했을 때 같은 값이
  나오는가다. 이슈성은 입력이 전부 DB 에 있고 시간만 흐르므로 조회 시점에 계산한다
  (ingestion-ranking INV-R1 과 같은 이유). 중요도는 모델 판정이라 다시 물으면 다른 값이 나올 수
  있고 요금도 다시 나간다.
  (강제 위치: 스키마 — 이슈성 칸이 없다 / 서버 — 중요도는 판정한 그 주기에 저장한다)
  위반 시(이슈성을 저장하면): 시간이 지나 낡고, 갱신 배치가 절반만 돌면 순서가 뒤섞인다.
  위반 시(중요도를 저장 안 하면): 화면을 열 때마다 모델을 부르게 되고 값이 날마다 흔들린다.

> **INV-H3 은 2026-09-21 에 없앴다.** "하루 상한의 '하루'는 수집 한 바퀴다"를 정하던 조항인데,
> 상한 자체가 사라져서 정의할 대상이 없다. 이 자리는 비워 두고 번호를 다시 쓰지 않는다 —
> 다른 문서가 `INV-H3` 으로 이 조항을 가리키고 있을 수 있다.
>
> **같은 날의 다른 조항들은 "하루"를 안 쓴다.** INV-G4(그날 이미 뽑힌 제목)는 여전히 날짜로
> 세는데, 그건 개수를 자르는 값이 아니라 같은 사건인지 묻는 재료라 경계가 하루 어긋나도
> 판정이 뒤집히지 않는다.

## 참조 — 이 문서가 정의하지 않는 것

- **INV-N2(합산 금지)** — keywords-and-kinds.md 에 있다. 중요도·관련성·이슈성을 더해 하나의
  점수로 만들지 않는다. 이번 구현은 이슈성을 **문 안의 순서에만** 쓰므로 그 조항을 따른다.
- **INV-R1~R5(점수와 '뜨는 중')** — ingestion-ranking.md 에 있다. 기존 `핫뉴스` 뱃지는 그대로
  둔다. 이 문서의 핫이슈와 **다른 것**이고, 화면에서 이름으로 갈린다.
- **INV-B1~B5(뱃지 키워드)** — badge-keywords.md 에 있다. 이번 판정은 키워드를 안 쓴다.

## 시나리오

- S30 (INV-G1): Given 새 툴을 발표한 글 / When 종류 판정 / Then `뉴스` 와 `툴` 이 둘 다 붙는다.
- S31 (INV-G2): Given 질문 셋에 참·거짓·참으로 답한 응답 / When 판정을 읽는다 /
  Then 중요도가 2 로 저장되고 어느 질문이 참인지도 남는다.
- S31b (INV-G2, 실패경로): Given 응답을 못 읽는 판정 / When 판정 / Then 중요도가 비어 있고
  다음 주기의 후보로 다시 잡힌다.
- S32 (INV-G3): Given 종류가 `툴` 이고 문턱을 못 넘은 글 / When 화면 배치 /
  Then 소식과 스킬·툴 **양쪽**에 선다.
- S32b (INV-G3, 실패경로): Given 종류가 비어 있고 문턱을 못 넘은 글 / When 화면 배치 /

- S32c (INV-G3): Given 세 자리를 그리는 화면 / When 목록을 고른다 /
  Then 자리마다 나오는 글이 배치 함수의 판정과 같다 — 화면이 자기 기준으로 다시 거르지 않는다.
- S33 (INV-G4): Given 그날 이미 뽑힌 핫이슈 제목 목록 / When 같은 사건을 다룬 글을 판정 /
  Then 그 글은 핫이슈에서 빠진다.
- S34 (INV-H1): Given 중요도가 2 인 글과 0 인 글 / When 배정 /
  Then 앞엣것만 `1번` 이 되고 뒤엣것은 문 값이 비어 있다.

## 열린 값 — 닫혔다 (2026-09-21, 결정 카드 `signal-20260920-3-d3`)

사용자가 「값을 다시 정한다」를 골랐다. **넷째 값(하루 상한)은 값이 아니라 조항이 없어졌다** —
"핫이슈는 절대 기준이고 넘으면 다 보여준다, 많은 날도 있고 없는 날도 있다"가 사용자 판단이다.
나머지 셋은 기본안대로 간다.

1. 판정에 싣는 키워드 목록의 범위 — 최근 7일 · 상위 80개
2. 제외할 흔한 말과 최소 건수 조건 — 최소 2건, 제외어는 기존 키워드 규칙 그대로
3. "급증"의 판정식 — 이번 범위에서 안 쓴다
4. ~~`1번` 문 하루 상한~~ — 상한을 없앴다 (INV-N4)

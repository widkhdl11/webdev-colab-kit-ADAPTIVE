# 키워드와 갈래

지금 태그는 **고정 5개**(모델·에이전트·MCP·엔지니어링·툴)다. 세 군데에서 그렇게 묶여 있다:
수집 프롬프트의 "다음 목록에서만 고른다" · 규칙 기반 태깅의 키워드 표 · DB 에서 읽을 때 목록 밖 이름 버리기.

**그런데 스키마는 이미 자유롭다** — `tag(normalized_name unique)` + `item_tag` 다대다다.
고정한 것은 코드의 결정이지 스키마 제약이 아니다. 그래서 이 스펙은 스키마를 뒤집지 않는다.

두 가지를 나눈다. **성질이 반대라서** 한 칸에 두면 둘 다 나빠진다:

|                     | 변해야 하나    | 쓰임                                             |
| ------------------- | -------------- | ------------------------------------------------ |
| **분류**(지금 태그) | 안 변해야 한다 | 필터 칩. 매일 바뀌면 어제 쓰던 버튼이 오늘 없다  |
| **키워드**(새로)    | 변해야 한다    | 새 개념을 담는다. 안 변하면 지금 문제가 그대로다 |

## 불변식

### 키워드 (K)

- INV-K1: 키워드는 글마다 생성하고 **누적한다**. 같은 이름이 다시 나오면 새 행을 만들지 않고
  기존 행에 항목을 연결한다. (강제 위치: DB unique(normalized_name) — INV-T2 를 그대로 쓴다)
  위반 시: 같은 말이 여러 행으로 갈려 세는 것도 필터도 쪼개진다.

- INV-K2: 키워드는 **그 글이 다루는 것**만이다. 본문에 언급만 된 말은 키워드가 아니다.
  (강제 위치: 서버 — 프롬프트 지시 + 결과 검수)
  위반 시: 빈도로 뽑으면 정확히 틀린 답이 나온다. 예: "벡터 엔지니어링" 발표 글에는
  기존 용어(그래프 엔지니어링·루프 엔지니어링·하네스)가 훨씬 많이 나오지만
  **그 글이 다루는 것은 벡터 엔지니어링 하나**다. 새 개념은 한 번 정의되고 그 뒤로는 지칭될 뿐이다.

- INV-K3: 키워드는 **대상과 사건을 섞는다.** "루프 엔지니어링"(무엇에 대한 글)과
  "보안 이슈"(무슨 일이 일어났나)가 같은 칸에 나란히 붙는다. 층을 가르지 않는다.
  (강제 위치: 스키마 — 키워드에 종류 구분이 없다)
  위반 시: 가르면 모델이 매번 정확히 갈라야 하고 화면에 줄이 하나 는다. 나중에 가르는 건
  가능하지만 반대(합치기)는 이미 붙인 키워드를 다시 손봐야 한다.

- INV-K4: 표기는 **한국어가 기본이되 고유명사와 널리 원어로 쓰는 기술 용어는 원어**로 둔다
  (제품·회사 이름, MCP·RAG·LLM 등). (강제 위치: 서버 — 프롬프트 지시)
  위반 시: 같은 개념이 영어·한국어로 갈리면 누적이 쪼개진다. 반대로 전부 한국어로 옮기면
  "모델 컨텍스트 프로토콜" 같은 표기가 나와 오히려 못 알아본다.

- INV-K5: 이미 쓰인 키워드 목록을 프롬프트에 함께 준다. **다만 목록은 표기를 맞추라고 주는 것이지
  범위를 제한하는 게 아니다** — 목록에 없는 새 개념이면 반드시 새로 만든다.
  (강제 위치: 서버 — 프롬프트 지시 + 목록에 없는 개념이 들어왔을 때 새 키워드가 생기는지 보는 테스트)
  위반 시: **지금 고정 5개 태그와 똑같은 상태가 된다.** 새 개념이 비슷한 기존 키워드로 흡수되면
  이 제품이 하려는 일과 정반대로 실패한다.

- INV-K6: 프롬프트에 싣는 목록에는 상한이 있다. (강제 위치: 서버 — 조립 시 자른다)
  위반 시: 목록이 항목마다 통째로 실리므로 키워드가 늘수록 비용이 선형으로 는다.
  실측(2026-08-10): 100개가 898 입력 토큰.

### 화면 표시 (KD)

- INV-KD1: 피드의 분류 칩 줄은 그대로 두고, **키워드는 따로 보여준다.** 카드에는 키워드를 넣지 않는다.
  (강제 위치: 화면)
  위반 시: 카드 메타 줄이 이미 태그 2개로 차 있어 "너무 글자글자"로 되돌아간다
  (design-rules 2026-08-06 카드 밀도).

- INV-KD2: 화면에 내보내는 키워드는 두 신호로 고른다: **처음 보는 말**(우리 DB 에 오늘 처음 생긴 것)과
  **요즘 자주 보이는 말**(평소 대비 급증). 둘은 다른 신호다. (강제 위치: 조회 계층 — 두 목록을 따로 계산)
  위반 시: 급증만 보면 **공식 발표 첫날 1건을 못 잡는다.** 사용자가 원하는 순간이 바로 그때다 —
  여러 건 쌓여 급증으로 잡힐 무렵이면 이미 늦게 아는 것이다.
  - 세는 대상은 **부여된 키워드**이지 본문 낱말 빈도가 아니다(INV-K2 와 같은 이유).
  - 계산은 `item_tag` 와 `item.published_at` 조인으로 나온다 — 새 컬럼이 필요 없다.

- INV-KD3: 처음 보는 키워드에는 거르는 조건이 있다. (강제 위치: 조회 계층)
  위반 시: 회사 이름·제품 이름까지 매일 새로 생겨 그대로 띄우면 소음이 된다.
  조건의 구체적 값은 실제 데이터를 며칠 보고 정한다(열린 값).

### 갈래 (G)

- INV-G1: 갈래는 `뉴스` / `정보` / `스킬툴` 셋이고, **한 글이 여러 개를 가질 수 있다.**
  (강제 위치: 스키마 — 다대다 / 서버 — 모델 판정)
  위반 시: 새 툴을 발표한 글은 뉴스이면서 스킬·툴이다. 하나만 고르게 하면 한쪽 토글에서 사라진다.

- INV-G2: 갈래는 **글마다** 판정한다(소스마다가 아니다). (강제 위치: 서버)
  위반 시: HN 쿼리 피드처럼 여러 갈래가 섞인 소스를 가를 수 없다.

- INV-G3: 화면의 1차 축은 갈래다. 소스 층(content-selection INV-L2)은 축이 되지 않는다.
  (강제 위치: 화면 — 토글은 갈래 하나뿐)

## 시나리오

- K1 (INV-K1): Given 키워드 "MCP" 가 이미 있음 / When 다른 글에서 "mcp" 가 나옴 /
  Then 새 행이 생기지 않고 기존 행에 연결된다.
- K2 (INV-K2, 실패경로): Given 기존 용어가 다수 언급되고 새 개념 하나를 다루는 글 /
  When 키워드 추출 / Then 그 글이 다루는 개념이 키워드에 들어가고, 언급만 된 말은 안 들어간다.
- K3 (INV-K3): Given "루프 엔지니어링의 보안 이슈" 글 / When 키워드 추출 /
  Then 대상과 사건이 같은 목록에 함께 들어간다.
- K4 (INV-K4, 실패경로): Given 제품명 "DeepSearcher" 가 나오는 글 / When 키워드 추출 /
  Then 그 이름은 번역되지 않는다.
- K5 (INV-K5, 실패경로): Given 목록에 없는 새 개념이 담긴 글 / When 키워드 추출 /
  Then 기존 키워드로 흡수되지 않고 새 키워드가 생긴다.
- K6 (INV-K6): Given 키워드가 상한보다 많이 쌓인 상태 / When 프롬프트 조립 /
  Then 실리는 목록이 상한을 넘지 않는다.
- K7 (INV-KD1, 실패경로): Given 키워드가 붙은 항목 / When 피드 카드 렌더 /
  Then 카드에 키워드 칩이 없다.
- K8 (INV-KD2): Given 오늘 처음 생긴 키워드 1건과, 지난 2주 0건에서 이번 주 12건이 된 키워드 /
  When 피드 조회 / Then 둘이 서로 다른 목록으로 나온다.
- K9 (INV-G1): Given 새 툴 발표 글 / When 갈래 판정 / Then 뉴스와 스킬툴 양쪽에 들어간다.
- K10 (INV-G3, 실패경로): Given 피드 화면 / When 토글을 본다 / Then 갈래 토글만 있고 층 토글은 없다.

## 열린 값 (구현 전에 정한다)

- 프롬프트에 싣는 키워드 목록의 범위 — 최근 N일 / 상위 N개 (INV-K6 의 상한)
- 제외할 흔한 말과 최소 건수 조건 (INV-KD3)
- "급증" 의 판정식 — 평소 대비 몇 배, 며칠 창 (INV-KD2)
- 화면에 몇 개까지 내보낼지

## 구현에 필요한 것 (여기 때문에 파킹했다)

1. 마이그레이션 — `tag` 에 분류/키워드를 가르는 칸 하나. 테이블을 새로 만들 필요는 없다
2. 갈래 저장 — 다대다
3. 화면 — 키워드 줄 추가 → **design-rules 에 없는 요소라 시안 한 바퀴**
4. 프롬프트 확장 — content-selection INV-P1(필요한 지시만 싣는다)을 지키면서

## 비범위

- 의미 검색(임베딩)으로 같은 뜻의 키워드 합치기. **지금은 안 한다** — 키워드가 0개인 상태에서는
  "얼마나 비슷하면 같은 것인가"의 기준을 정할 근거가 없고, 느슨하게 잡으면 새 개념이 기존 것에
  흡수돼 INV-K5 와 정면으로 부딪힌다. 다시 볼 조건: 목록이 프롬프트에 다 못 들어갈 만큼 커졌을 때,
  또는 같은 개념이 다른 이름으로 갈린 것이 **실제로 관찰됐을 때**.
- 키워드로 검색·질의하는 화면 → PRODUCT 비범위(읽기형 피드).

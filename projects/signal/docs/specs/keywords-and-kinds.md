# 키워드와 갈래

지금 태그는 **고정 5개**(모델·에이전트·MCP·엔지니어링·툴)다. 세 군데에서 그렇게 묶여 있다:
수집 프롬프트의 "다음 목록에서만 고른다" · 규칙 기반 태깅의 키워드 표 · DB 에서 읽을 때 목록 밖 이름 버리기.

**그런데 스키마는 이미 자유롭다** — `tag(normalized_name unique)` + `item_tag` 다대다다.
고정한 것은 코드의 결정이지 스키마 제약이 아니다. 그래서 이 스펙은 스키마를 뒤집지 않는다.

두 가지를 나눈다. **성질이 반대라서** 한 칸에 두면 둘 다 나빠진다:

|                     | 변해야 하나    | 쓰임                                             |
| ------------------- | -------------- | ------------------------------------------------ |
| **분류**(지금 태그) | 안 변해야 한다 | 필터 칩. 매일 바뀌면 어제 쓰던 버튼이 오늘 없다  |
| **키워드**(새로)    | 변해야 한다    | 새 개념을 담는다. 안 변하면 지금 문제가 그대로다 |

## 불변식

### 키워드 (K)

> **INV-K1 · INV-K4 · INV-K6 은 `badge-keywords.md` 로 옮겼다** (2026-08-27, approved).
> 여기서 지운 것은 **같은 조항이 두 곳에 있으면 갈라지기 때문**이다. 고칠 일이 있으면 그쪽을 고친다.
> 남은 K2·K3·K5 는 **새 개념 키워드**에 관한 것이고 아직 안 만든다 — badge-keywords 의
> INV-B3(같은 뜻이면 합친다)과 K5(새 개념이면 반드시 새로 만든다)가 정면으로 부딪혀서,
> 켤 때는 두 종류를 가르든지 프롬프트에서 두 질문으로 나눠야 한다.

- INV-K2: 키워드는 **그 글이 다루는 것**만이다. 본문에 언급만 된 말은 키워드가 아니다.
  (강제 위치: 서버 — 프롬프트 지시 + 결과 검수)
  위반 시: 빈도로 뽑으면 정확히 틀린 답이 나온다. 예: "벡터 엔지니어링" 발표 글에는
  기존 용어(그래프 엔지니어링·루프 엔지니어링·하네스)가 훨씬 많이 나오지만
  **그 글이 다루는 것은 벡터 엔지니어링 하나**다. 새 개념은 한 번 정의되고 그 뒤로는 지칭될 뿐이다.

- INV-K3: 키워드는 **대상과 사건을 섞는다.** "루프 엔지니어링"(무엇에 대한 글)과
  "보안 이슈"(무슨 일이 일어났나)가 같은 칸에 나란히 붙는다. 층을 가르지 않는다.
  (강제 위치: 스키마 — 키워드에 종류 구분이 없다)
  위반 시: 가르면 모델이 매번 정확히 갈라야 하고 화면에 줄이 하나 는다. 나중에 가르는 건
  가능하지만 반대(합치기)는 이미 붙인 키워드를 다시 손봐야 한다.
  - **2026-08-15: 가를 이유가 생겼다 — 이 조항은 다시 봐야 한다.** 위 "나중에 가르는 건
    가능하지만"이 지금 자리다. 소식 탭 뱃지 줄에 실을 것은 안 변하는 말(분야·사건종류)인데,
    새 개념 키워드가 같은 줄에 섞이면 창 기간에 수십 개가 쌓여 줄이 무너진다(INV-B1·B3).
    다만 **가르는 자리는 키워드 쪽이 아니라 분류 쪽일 수 있다** — 분류를 두 축으로 넓히면
    (INV-B1) 뱃지 줄은 분류만으로 채워지고 키워드는 K3 대로 섞인 채 다른 자리에 남는다
    (INV-KD1·KD2 가 이미 그 자리를 잡아뒀다). 구현 전에 둘 중 어느 쪽인지 확정한다.

- INV-K5: 이미 쓰인 키워드 목록을 프롬프트에 함께 준다. **다만 목록은 표기를 맞추라고 주는 것이지
  범위를 제한하는 게 아니다** — 목록에 없는 새 개념이면 반드시 새로 만든다.
  (강제 위치: 서버 — 프롬프트 지시 + 목록에 없는 개념이 들어왔을 때 새 키워드가 생기는지 보는 테스트)
  위반 시: **지금 고정 5개 태그와 똑같은 상태가 된다.** 새 개념이 비슷한 기존 키워드로 흡수되면
  이 제품이 하려는 일과 정반대로 실패한다.

### 소식 배치 (N) — 2026-08-15 신설

소식 탭에 **무엇을 들이고 어떤 순서로 놓을지**의 규칙이다. 갈래(G)가 어느 탭인지를 정한다면
여기는 그 탭 안에 들어올 자격과 양을 정한다.

- INV-N1: 들어오는 문은 셋이고 **배정은 이산 판정으로만** 한다.
  중요도 ≥ 1 → `1번`(관련성 안 봄) / 중요도 0 + 관련성 `높음` → `2번` /
  중요도 0 + 관련성 `낮음` → `3번`(맛보기) / 관련성 `없음` + 중요도 0 → **안 들임**.
  어느 문으로 들어왔는지를 **저장한다.**
  (강제 위치: 서버 — 순수 함수 + 저장 / 문 값이 없는 항목은 화면에 안 나온다)
  위반 시: 저장 안 하면 문별 상한(INV-N4)도 화면 구분도 불가능하고, 오배정의 원인을 못 짚는다.
  - `중요도` = 핫이슈 문턱 질문 셋(INV-G2) 중 참인 개수(0~3). `1번` 문이 곧 핫이슈 후보다.
  - `관련성` = 프로필 대비 3단계. **100점 척도가 아니다** — 3단계로 충분하다는 것이
    사용자 요구 문장에서 그대로 나온다("관련성이 낮아도 아예 없는 게 아니면").

- INV-N2: 세 값을 **더해서 하나의 점수로 만들지 않는다.** 연속값(이슈성)은 문을 고르는 데 쓰지 않고
  **문 안에서의 순서에만** 쓴다. (강제 위치: 서버 — 배정 함수의 입력에 이슈성이 없다)
  위반 시: 합치면 `중요도 3 + 관련성 없음`과 `중요도 1 + 관련성 높음`이 같은 점수가 되는데,
  앞엣것은 반드시 봐야 하고 뒤엣것은 안 봐도 된다. INV-G2 를 만든 이유와 같은 계열의 실패다.

> **INV-N3 · INV-N4 도 `hot-issue.md` 로 옮겼다** (2026-09-20, approved). 위와 같은 이유다.
>
> **INV-N1 은 안 옮겼다.** `1번` 문만 여는 이번 범위에 맞춰 저쪽에서 INV-H1 로 다시 썼고,
> 여기 남은 이 조항이 여전히 네 문 전체의 정본이다. 나머지 세 문을 열 때 INV-H1 이 여기로
> 흡수된다. INV-N2(합산 금지)도 여기 그대로다 — 이번 구현이 그 조항을 지킨다.

> **INV-N5 는 `badge-keywords.md` 로 옮겼다** (2026-08-31, 화면이 생겼으므로).
> **핫이슈는 반대다** — 꼭 알아야 하는 것이라 다 봤다는 표시가 값을 한다. 그 갈래는 아직
> 화면이 없어서 이 조항의 핫이슈 쪽 절반은 여기 남는다.

  > **2026-08-27 에 좁혔다.** 원래 문장은 "총 개수와 안 읽은 개수를 보여주지 않는다"였는데,
  > 사용자가 뱃지 옆에 안 읽은 글 수를 붙이기로 했다(0이 되면 취소선까지). 그 조항이 막으려던
  > 것과 같은 모양이라 그대로 두면 구현이 스펙 위반이 된다.
  >
  > **가르는 근거**: "오늘 소식 8건"은 화면 전체를 덮는 하나의 숫자라 그게 곧 오늘 치 할당량이
  > 되는데, 뱃지 숫자는 **수십 개 중 무엇을 누를지 고르는 정보**라 하나로 합쳐지지 않는다.
  > 그래서 `전체` 칩에는 숫자를 안 붙인다 — 붙이는 순간 다시 하나로 합쳐진다.
  >
  > **약하게 갈랐다는 것을 적어 둔다.** `0` + 취소선은 명백히 "다 봤다" 표시라 원래 조항의
  > 취지에서 벗어난다. 사용자 판단은 그 숫자가 부담이 아니라 흥미를 돋운다는 것이었다.
  > **다시 볼 조건**: 실제로 써 보고 뱃지 숫자가 할당량처럼 느껴질 때.
  > 시각 기준은 design-rules.md 2026-08-27 블록에 있다.

- K2 (INV-K2, 실패경로): Given 기존 용어가 다수 언급되고 새 개념 하나를 다루는 글 /
  When 키워드 추출 / Then 그 글이 다루는 개념이 키워드에 들어가고, 언급만 된 말은 안 들어간다.
- K3 (INV-K3): Given "루프 엔지니어링의 보안 이슈" 글 / When 키워드 추출 /

- K5 (INV-K5, 실패경로): Given 목록에 없는 새 개념이 담긴 글 / When 키워드 추출 /
  Then 기존 키워드로 흡수되지 않고 새 키워드가 생긴다.
- K7 (INV-KD1): Given 뱃지가 5개 붙은 항목 / When 피드 카드 렌더 /
  Then 별도 줄에 4개가 보이고 나머지는 `+1` 로 접힌다. 메타 줄에는 뱃지가 없다.
- K7b (INV-KD1, 실패경로): Given 같은 항목 / When 상세 화면 렌더 /
  Then 5개가 전부 보이고 접히지 않는다.
- K8 (INV-KD2): Given 오늘 처음 생긴 키워드 1건과, 지난 2주 0건에서 이번 주 12건이 된 키워드 /
  When 피드 조회 / Then 둘이 서로 다른 목록으로 나온다.
- K9 (INV-G1): Given 새 툴 발표 글 / When 갈래 판정 / Then 뉴스와 스킬툴 양쪽에 들어간다.
- K10 (INV-G3, 실패경로): Given 피드 화면 / When 토글을 본다 / Then 갈래 토글만 있고 층 토글은 없다.
- K13b (INV-B5): Given 분야 뱃지와 사건종류 뱃지가 한 줄에 섞여 있음 / When 뱃지 줄 렌더 /
  Then 둘이 서로 다른 면 색 토큰을 쓴다.
- K14 (INV-B4): Given 창이 3일이고 4일 전에만 있는 분류 / When 오늘 뱃지 줄 조회 /
  Then 그 뱃지는 없지만, 날짜 그룹을 내려가면 그 글은 그대로 있다.
- K15 (INV-N1): Given 중요도 0 · 관련성 없음인 항목 / When 배정 / Then 소식에 안 들어온다.
- K16 (INV-N1, 실패경로): Given 중요도 2 · 관련성 없음인 항목 / When 배정 /
  Then `1번` 문으로 들어온다 — 관련성이 배정을 막지 않는다.
- K17 (INV-N2, 실패경로): Given 이슈성이 아주 높고 중요도 0 · 관련성 없음인 항목 /
  When 배정 / Then 안 들어온다 — 이슈성이 문을 열지 못한다.
- K18 (INV-N3): Given 같은 항목 / When 배정을 두 번 / Then 이슈성 값이 같다(모델 호출이 없다).
- K19 (INV-N4): Given `3번` 문 상한이 2인데 자격을 갖춘 항목이 5건 /
  When 배정 / Then 2건만 남고 리포트에 잘린 3건이 남는다.
- K20 (INV-N5, 실패경로): Given 소식 탭 / When 화면을 본다 /
  Then 글 목록에도 `전체` 칩에도 총 건수·안 읽은 건수를 나타내는 숫자가 없다.
- K20b (INV-N5): Given 안 읽은 글이 3건인 뱃지 / When 뱃지 줄 렌더 /

- 화면에 몇 개까지 내보낼지
- **표기 기준의 문장 자체** (INV-B2). 불변식이 아니라 설정이라 `prompt-text.ts` 에 둔다
  (`TOPIC_SCOPE` 와 같은 자리·같은 성격). 유닛 테스트가 옳고 그름을 못 잡으므로 **실제로 돌려
  나온 키워드 목록을 보고 고친다.**

  돌려 본 뒤** — 표기 갈림이 실제로 얼마나 나오는지, 뱃지로 쓸 만한 굵기의 말이 나오는지를 보고
  정한다. **지금 손으로 정하면 그건 추측이고, 고정 5개가 실패한 이유가 그 추측이다.**
  - 고정 목록의 값 하나는 여기서 사라진다: 목록이 있으면 **빈 칸이 곧 소스 쇼핑 목록**이 되는데

  - 2026-08-13 에 "태양광류는 나중에 'IT 그외' 갈래를 열어 담는다"고 미뤄둔 것이 이 자리다.

- **문별 하루 상한** (INV-N4). 며칠 돌려 보고 정한다 — 지금 정하면 추측이다.

  안 붙이면 눌러보기 전엔 뭐가 있는지 모른다. **시안에서 나란히 놓고 정한다.**

## 구현에 필요한 것 (여기 때문에 파킹했다)

1. 마이그레이션 — **필요하다.** `tag` 에 **축을 가르는 칸**(분야/사건종류)이 있어야 한다(INV-B1).
   2026-08-15 에 한때 "필요 없다"고 적었는데 그건 축을 하나로 줄였던 동안의 이야기다.
   테이블을 새로 만들 필요는 없다 — 칸 하나면 된다.
   - **기존 태그 5개와 그에 붙은 `item_tag` 475건**: 지우지 않고 둔다(2026-08-15 결정).
     지금 지우면 피드의 필터 칩 5개가 빈 결과를 내는데 대체할 뱃지 줄이 아직 없다.
     **뱃지 줄이 화면에 붙을 때 칩과 함께 정리한다.** 되살아나는 것은 확인됐다 —
     690건에서 `에이전트`(95건)·`MCP`(3건)가 고정 목록 없이 스스로 다시 나왔고,
     `툴` 은 한 번도 안 나왔다.

## 비범위

- 의미 검색(임베딩)으로 같은 뜻의 키워드 합치기. **지금은 안 한다** — 키워드가 0개인 상태에서는
  "얼마나 비슷하면 같은 것인가"의 기준을 정할 근거가 없고, 느슨하게 잡으면 새 개념이 기존 것에
  흡수돼 INV-K5 와 정면으로 부딪힌다. 다시 볼 조건: 목록이 프롬프트에 다 못 들어갈 만큼 커졌을 때,
  또는 같은 개념이 다른 이름으로 갈린 것이 **실제로 관찰됐을 때**.
- 키워드로 검색·질의하는 화면 → PRODUCT 비범위(읽기형 피드).
- **관심도 자동 학습** — 안 본 글의 점수를 내리고 언급이 쌓이면 되살리는 것. **지금은 안 한다.**
  ① 뱃지로 골라 보는 구조에서는 **안 누른 뱃지의 글이 전부 "안 봄"** 이 되는데 그날 안 끌렸을
  뿐이다 — 이 신호로 점수를 내리면 관심사가 쪼그라든다(넓히려는 것과 정반대). ② "언급이 쌓이면
  되살린다"의 언급 횟수는 **우리 소스가 그 주제를 얼마나 다루느냐**일 뿐이라 큰 회사 소식만
  되살아난다. ③ 사용자 1명 · 며칠에 한 번 · 클릭 몇 건이라 표본이 없다.
  넓히는 일은 학습이 아니라 **`3번` 문(INV-N1)** 이 한다 — 프로필이 그대로여도 매일 몇 건씩
  프로필 밖이 들어오고, 학습과 달리 클릭한 것 근처가 아니라 아예 안 보던 쪽도 들어온다.
  다시 볼 조건: **뱃지 클릭 기록만 남겨** 두고 몇 주 뒤 한 번도 안 눌린 뱃지가 실제로 관찰될 때.

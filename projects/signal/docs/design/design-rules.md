## 2026-08-02 · 피드 + 소식 상세 · checkpoint 승인

첫 시각 방향이다. 이후 화면은 특별한 사정이 없는 한 이 언어를 물려받는다.

### 한 줄

**깔끔한 뼈대에 귀엽고 가벼운 디테일.** 가벼운 SNS 피드처럼 훑되 피로감은 낮게.
발랄함은 캐릭터나 일러스트가 아니라 **포인트색·라운드·작은 움직임**에서 나온다.

### 색

라이트 전용. 다크 모드는 지금 범위가 아니다.

| 토큰            | 값        | 쓰임                                |
| --------------- | --------- | ----------------------------------- |
| `--bg`          | `#EFEFF5` | 페이지. 라벤더 기가 도는 옅은 회색  |
| `--surface`     | `#F8F8FC` | 카드·요약 박스. 페이지보다 **밝다** |
| `--surface-h`   | `#FDFDFF` | 호버. 순백 직전까지만               |
| `--sunken`      | `#E5E5EE` | 코드 블록. 글 흐름에서 눌러 앉는 면 |
| `--hairline`    | `#E2E2EC` | 헤더 밑선                           |
| `--dot`         | `#C9C9D6` | 점선 구분선                         |
| `--text`        | `#1F2024` | 본문. 순검정은 쓰지 않는다          |
| `--text2`       | `#4A4E55` | 요약문                              |
| `--meta`        | `#656A72` | 출처·시각 등 메타                   |
| `--accent`      | `#4F46E5` | 포인트색(인디고)                    |
| `--accent-soft` | `#E9E8FB` | 뱃지 배경                           |

**순백 배경은 쓰지 않는다.** 매일 훑는 리더라 눈부심이 그대로 비용이 된다.
레퍼런스(biko)는 흰 페이지에 회색 카드였지만 우리는 명암을 뒤집었다 — 회색 페이지에 밝은 카드.
부수효과로 카드 분리가 더 뚜렷해졌다.

**포인트색은 면적을 최소로.** 활성 상태, '뜨는 중' 뱃지, 로고 점, 링크 정도에만 닿는다.
전면 배경으로 까는 것은 금지. 2차 강조색(초록 등)도 두지 않는다.

### 형태와 입체감

- 카드 라운드 **12px**, 칩·버튼·세그먼트 토글은 **완전 알약(999px)**, 이미지 8px
- **입체감은 "아직 안 봄"의 신호다.** 안 읽은 카드에만 아주 옅은 그림자를 두 겹으로 준다:
  `0 1px 2px rgba(31,32,36,.05)`(경계를 또렷하게) + `0 4px 10px rgba(31,32,36,.05)`(면을 살짝 띄우기).
  읽은 카드는 그림자가 없다. 호버는 `0 2px 4px rgba(31,32,36,.06)` + `0 10px 22px rgba(31,32,36,.08)`
  에 `translateY(-1px)`
  > 처음에는 레퍼런스를 따라 "그림자 없이 면으로만 분리"로 갔다가, 읽음/안읽음 구분이 약해
  > 이 규칙으로 대체했다. 입체감이 상태를 나르는 쪽이 흐릿함과 같은 방향으로 겹쳐 작동한다.
- 테두리 선은 거의 쓰지 않는다. 면과 그림자로 나눈다

### 타이포

- **Pretendard** 하나. 코드 블록만 모노
- **크기 단계를 늘리지 말고 굵기로 위계를 만든다.** 굵기 800·700·600·500을 먼저 쓴다
- 실제 단계(2026-08-06 구현하며 실측해 정정): 28 상세 제목 / 22 피드 제목 / 20 본문 소제목 /
  19 로고 / 17 상세 본문 / 16 카드 제목·모바일 본문 / 15 기본 글자·요약 박스 / 14 버튼 /
  13.5 카드 요약·코드 블록·날짜 제목 / 13 태그라인·컨트롤 칩 / 12.5 건수·주석 / 12 메타 /
  11.5 뱃지·태그 칩
  > 승인 시점에 문서는 다섯 단계라고 적었지만 승인된 시안이 이미 이만큼 쓰고 있었다.
  > 다음에 단계를 **늘리지 않기 위해** 실제 값을 적어둔다. 13과 12.5는 육안 구분이 어려워
  > 합칠 후보지만, 승인된 시안을 바꾸는 일이라 지금은 그대로 둔다.
- **본문 16px 하한의 예외: 카드 요약 13.5px.** 목록 미리보기는 본문이 아니다 —
  진짜 본문(상세 17px)은 하한을 넘는다. 반대로 화면에 문장 하나만 남는 자리
  (빈 상태 등)는 미리보기가 아니므로 15px 이상을 쓴다
- 초대형 헤드라인 금지. 피드 페이지 제목도 22px/700까지
- 상세 본문은 **17px, 줄높이 1.78, 읽기 컬럼 704px** — 이 사이트의 핵심 가치가 "편하게 읽기"다

### 레이아웃

- 최대 폭 **1168px** 중앙 정렬. 카드 그리드 3열, gap 16px, 카드 안쪽 padding 16px
- 데스크톱 우선. 980px에서 2열, 640px에서 1열
- 상단 헤더는 아주 얇게. 네비 메뉴는 두지 않는다(2페이지짜리 개인용)

### 시그니처 (이 사이트를 알아보게 하는 것)

1. **카드 안 점선 구분선** — 제목·요약 블록과 아래 메타 줄을 나눈다. 상세에서도 이어 쓴다
2. **알약 필터 칩 줄** — 정렬 세그먼트 토글 + 주제 태그 칩이 목록 위에 나란히
3. **뱃지로 압축한 정보** — '뜨는 중', 태그 칩

### 상태 규칙

- **읽음**: 카드 채움을 페이지 쪽으로 눕히고(`#F3F3F8`), 제목 `#666B73`/굵기 600, 요약·메타 `#6A6F77`,
  태그 칩 글자 `#63676F`, 그림자 제거.
  **흐릿하게 = 눌러두는 것이지 못 읽게 만드는 게 아니다** — 읽은 항목도 대비 4.5:1을 지킨다
- **호버·포커스에서 완전 복구**: 읽은 카드도 색·굵기·입체감이 안 읽은 카드와 같아진다.
  다시 읽으려는 순간에는 또렷해야 한다. 키보드 이동(`:focus-visible`)도 같다
- **뱃지 중립화**: 읽은 카드의 '뜨는 중' 뱃지는 포인트색을 잃는다.
  색은 "아직 안 본 것"에만 쓴다
- 상태를 색으로만 알리지 않는다. 읽음에는 스크린리더용 텍스트를 함께 둔다

### 날짜 그룹

수집이 매일 아침 한 번 도는 배치라, **날짜가 1차 묶음이고 정렬(뜨는순/최신순)은 그 안에서 2차**다.
점수가 날짜를 가로지르면 "오늘 뭐 왔지"를 볼 수 없다.

- 섹션 헤더는 절제한다: 13.5px, 메타색 + 굵기. 옆에 그날 건수를 작게(`오늘 · 5건`),
  남는 폭은 시그니처인 점선으로 채운다
- 제목 계층은 h1(페이지) → h2(날짜) → h3(카드)
- '뜨는 중' 뱃지는 전역 상위가 아니라 **그룹 안에서의 상위**에 붙는다

### 접근성

- 텍스트 대비 **4.5:1 이상**. 포커스 스타일을 제거하지 않는다
- 이건 장식 규칙이 아니라 실제로 설계를 몇 번 바꿨다:
  레퍼런스의 메타색 `#8A8F95`는 우리 카드 위에서 2.95:1이라 탈락했고,
  읽음 상태를 더 흐리게 하려다 색으로는 바닥에 막혀 **굵기까지 낮추는 쪽**으로 풀었다.
  태그 칩은 배경이 카드보다 어두워서 글자색을 따로 뒀다
- 현재 최저값 4.57:1(읽은 카드의 요약·메타). **더 흐리게 하려면 색이 아닌 수단을 써야 한다** —
  카드를 접어 부피로 줄이는 방식이 다음 후보다
- 움직임은 `prefers-reduced-motion`을 존중한다

### 하지 않는 것

- 포인트색 전면 배경(히어로·네비 풀블리드)
- 초대형 헤드라인(60px 굵은 제목류)
- 마스코트 캐릭터·3D 이모지 일러스트 — 귀엽되 유치하지 않게. 작은 이모지 포인트까지만 허용
- 복잡하고 산만한 포털 룩: 사이드바·배너·위젯 나열. 한 줄기 피드 + 최소 컨트롤만
- 카드 제목을 한 줄에서 `…`로 자르는 것 — 2줄까지 허용한다
- 순백 배경, 2차 강조색

### 아직 안 정한 것

- 다크 모드 (범위 밖)
- 오류·로딩 화면 — 필요해질 때 시안으로 확인받고 여기 덧붙인다
  (빈 상태는 2026-08-06 블록에서 확정)
- 모바일 전용 조정 — 지금은 1열로 접히는 수준까지만 봤다

## 2026-08-06 · 피드 구현 중 확정 · 사용자 승인

시안에는 없었지만 실제로 만들다 보니 정해야 했던 것들. ui-reviewer 지적을 사용자가
승인해 덧붙인다. 새 시각 방향이 아니라 위 언어 안에서의 마감이다.

### 빈 상태

주제 필터 결과가 0건일 때. **문장 한 줄, 15px, 메타색, 중앙 정렬, 위아래 여백 56px.**
일러스트·아이콘·재시도 버튼을 두지 않는다 — 필터를 바꾸면 끝나는 상황이라
화면이 사건처럼 보이면 과하다. (오류·로딩은 여전히 미정)

> 2026-08-06 (2) 덧붙임 — **문구는 두 가지다. 형태는 위와 같다.**
> 필터가 켜져 있으면 "이 주제로 모인 소식이 아직 없습니다",
> 전체가 0건이면 "아직 모인 소식이 없습니다".
> 켜지도 않은 필터를 탓하면 화면이 엉뚱한 것을 가리킨다.
> 404 화면도 같은 언어를 쓴다(문장 한 줄 + 피드로 돌아가는 링크).

### 메타 줄 태그 칩

카드 아래 메타 줄의 칩은 **2개까지.** 초과분은 `+N` 칩 하나로 접고,
접힌 태그 이름은 스크린리더용 텍스트로 함께 둔다.

> 칩을 그냥 자르면 화면이 거짓말을 한다 — 그 태그로 필터하면 카드는 나오는데
> 칩은 안 보인다. 상세 화면은 폭이 넉넉하므로 태그를 전부 보여준다.

### 입체감이 나르는 상태를 가리지 않기

상단 헤더가 sticky 라, 키보드로 이동해 온 카드·날짜 섹션은 `scroll-margin-top: 72px`
를 둬서 헤더 밑에 깔리지 않게 한다. "읽은 카드도 포커스에서 완전 복구된다"는 규칙은
포커스 링이 화면에 보여야 성립한다.

### 목록을 늘리는 버튼

"더 보기"는 **다 불러온 뒤에도 사라지지 않는다.** 문구를 "모두 불러왔습니다"로 바꾸고
`aria-disabled` 로 표시하되 포커스는 그대로 둔다 — 버튼이 사라지면 키보드 사용자는
방금 불러온 카드가 아니라 페이지 맨 위로 되던져진다. 늘어난 건수는 화면 밖으로도 알린다.

### 카드 밀도 — A+B 채택 (비교 시안 승인)

사용자 피드백: "너무 글자글자글자~ 한 느낌". 비교 시안
[mockups/feed-card-density.html](mockups/feed-card-density.html) 에서 A(숨 쉴 곳)+B(출처 표식)를 골랐다.
C(위계 벌리기)는 타이포 단계를 하나 더 늘리는 대가가 있어 보류 — A+B로 부족하면 그때 얹는다.

- **어절 단위 줄바꿈**: 카드 제목·요약에 `word-break: keep-all`. 상세 본문에는 원래 있던 규칙인데
  카드에만 빠져 있었다. 한국어가 어절 중간에서 끊기는 것이 밀도 체감을 키우던 주범이다
- **요약은 2줄까지** (3줄에서 줄임). 3줄이면 카드 절반이 회색 덩어리가 된다
- **카드 안쪽 여백 20px** (16px에서 키움), 제목 아래 10px, 요약 아래 16px, 발 위 14px
- **출처 표식**: 메타 줄 맨 앞에 지름 20px 원. 한글 출처는 첫 한 글자, 로마자는 두 글자
  (한 글자면 GitHub 과 Google 이 구별되지 않는다). 10.5px/700, 배경은 태그 칩과 같은 계열
  - **색은 쓰지 않는다.** 포인트색은 "아직 안 본 것" 전용이라는 규칙을 그대로 지킨다
  - 읽은 카드에서는 태그 칩과 같이 중립색으로 내려가고, 호버·포커스에서 함께 복구된다
  - 출처 이름을 줄인 것뿐이라 스크린리더에는 `aria-hidden` — 옆에 전체 이름이 이미 있다
- 이때 `--fs-mark: 10.5px` 가 추가됐다. 위 타이포 단계 목록에서 **가장 작은 단계**이고
  출처 표식 원 안에서만 쓴다

### 실측 대비 (2026-08-06 재계산)

피드 18개 조합 최저 **4.57:1**(읽은 카드 요약·메타), 상세 13개 조합 최저 **4.75:1**.
새 토큰 `--on-accent`(포인트색 면 위 흰 글자) 6.29:1, `--code-ink`(코드 면 위 글자) 9.78:1.

## 2026-08-06 (2) · 원문 본문 타이포 확장 + 요약 크기 · checkpoint 승인

승인된 시안: [mockups/article-prose.html](mockups/article-prose.html)

review 사인오프가 실패해 되돌아온 자리다. 새 시각 방향이 아니라 **이미 승인된 언어의 빈칸 메우기**다.
빈칸은 두 종류였다 — 문서가 스스로 모순인 곳, 그리고 스펙이 허용하는데 시각 기준이 없는 곳.

### AI 요약 박스는 16px (15px 에서 올림)

`ui-layers` 의 "본문 16px 이상" 하한을 요약 박스도 지킨다. 이 문서 65행이 "15 기본 글자·요약 박스"라고
적고 71~73행은 하한 예외를 "카드 요약 13.5px" 하나만 인정해 **서로 다른 말을 하고 있었다.** 카드 요약이
예외인 근거는 "목록 미리보기는 본문이 아니다"인데, 상세의 요약 박스는 미리보기가 아니라 실제로 읽는
여러 문장이다. 그러니 예외에 해당하지 않는다 — 올리는 쪽이 맞다.

대가: 원문 본문이 17px 이라 이제 **1px 차이밖에 안 난다.** 크기로는 더 이상 구분되지 않으므로
위계를 네 축으로 옮긴다. 넷이 같이 작동해야 갈라진다.

| 축   | 요약 박스                                   | 원문                                      |
| ---- | ------------------------------------------- | ----------------------------------------- |
| 면   | `--surface` (페이지보다 밝은 카드면)        | 페이지 배경 위 맨몸                       |
| 색   | `--text2`                                   | `--text` (원문이 더 진하다 = 원문이 본체) |
| 형태 | 라운드 12px + 왼쪽 4px 포인트선 + 라벨 알약 | 테두리 없음                               |
| 질감 | 줄높이 1.70 (조여서 "블록")                 | 1.78 (벌려서 "흐름")                      |

### 하한이 걸리는 자리와 안 걸리는 자리

혼란의 원인이 예외 목록이 짧았던 것이므로 여기서 경계를 분명히 한다.

- **16px 하한 대상(본문)**: 상세 원문 17px, AI 요약 박스 16px, 모바일 본문 16px
- **하한 대상이 아닌 것(부속)**: 문장에 딸린 덧말 `small` 15px, 그림 설명 `figcaption` 12px,
  위·아래 첨자 12px, 메타 줄·뱃지·칩. **문장 단위로 읽는 글이 아니라 문장에 붙는 부속**이다
- **기존 예외 유지**: 카드 요약 13.5px (목록 미리보기)

### 원문 본문의 제목 h1~h6

sanitize 는 `h1`~`h6` 를 전부 통과시키는데(content-safety INV-D2) `.prose` 에는 `h2` 값만 있었다.
그래서 원문에 `h3` 가 오면 Preflight 리셋 그대로 **본문보다 작고 굵기도 없는 글**로 나왔다.

크기 단계를 늘리지 않는다(63행). 크기는 **20 / 17 두 값만** 쓰고 굵기·색·여백으로 6단계를 만든다.

| 태그 | 크기 | 굵기 | 색                   | 위 여백 |
| ---- | ---- | ---- | -------------------- | ------- |
| `h1` | 20px | 800  | `--text` + 점선 밑선 | 2.4em   |
| `h2` | 20px | 700  | `--text`             | 2.1em   |
| `h3` | 17px | 700  | `--text`             | 2em     |
| `h4` | 17px | 600  | `--text`             | 1.8em   |
| `h5` | 17px | 600  | `--text2`            | 1.6em   |
| `h6` | 17px | 600  | `--meta`             | 1.5em   |

- **원문 `h1` 을 20px 로 누른 이유**: 페이지 제목(28px)은 우리가 붙인 것이고 원문 안의 `h1` 은
  출처가 쓴 것이다. 28px 로 나오면 "이 글의 제목이 둘"로 보인다. 크기는 `h2` 와 같이 두고
  굵기 800 + 시그니처 점선 밑선으로 "구획의 시작"만 알린다
- **`h3`~`h6` 이 본문과 같은 17px 인 이유**: 17 아래는 16→15 인데 제목이 본문보다 작아지면 위계가
  뒤집힌다. 17 위로 열면 63행 위반. 남는 길은 같은 크기에서 굵기·색으로 나누는 것뿐이다
- **`h4`·`h5`·`h6` 이 굵기 600 으로 같고 색만 다른 이유**: 500 은 본문 400 과 붙어 제목으로 안 읽힌다.
  세 번째 축을 색으로 열었고 `--text → --text2 → --meta` 는 이미 쓰는 사다리(제목→요약→메타)다
- 17px/600 제목은 굵은 문장과 헷갈릴 수 있다. **위 여백을 문단 간격보다 확실히 넓게** 잡아
  "새로 시작한다"를 여백이 나르게 한다

### 목록 불릿을 되살린다

Tailwind Preflight 가 `ol, ul { list-style: none }` 으로 마커를 지우는데 `.prose` 가 복구하지 않아
**점도 번호도 안 보이는 상태였다.** 마커 색만 `--meta` 로 정해두고 정작 칠할 마커가 없었다.

- `ul` = `disc`, `ol` = `decimal`. 중첩 2단계까지 모양을 달리한다(`circle` / `lower-alpha`)
- 마커 색은 `--meta` 로 절제. 마커가 글자보다 튀면 목록이 장식처럼 보인다
- AI 요약 박스 안의 목록도 같다

### 표

- 셀 **16px**. 본문 17px 그대로면 열이 넓어져 가로 스크롤이 상시로 생긴다
- 헤더 면은 `--surface`, 글자는 `--text`/700. `--sunken`(코드 면)을 쓰면 `--meta` 가 **4.35:1 로 미달**이고
  면이 어두워 표가 코드 블록처럼 보인다
- 선은 거의 쓰지 않는 규칙대로 **세로줄 없음**, 가로 구분만 점선(`--dot`)
- 머리글은 `white-space: nowrap`, 표 자체는 `min-width: 480px` — 더 좁아지면 한글이 글자 단위로 부서진다

### 가로로 넘치는 것은 키보드로도 닿아야 한다

표와 코드 블록은 읽기 컬럼 704px 을 넘긴다. **페이지가 통째로 밀리면 안 되고**, 스크롤 영역이
마우스로만 닿아도 안 된다(키보드 사용자는 오른쪽을 영영 못 본다).

- 표는 `overflow-x: auto` 껍데기로 감싸고 `tabindex="0"` + `role="region"` + `aria-label`
- 코드 블록 `pre` 도 `tabindex="0"`
- **이 껍데기는 sanitize 결과에 없다** — 원문에는 class 를 붙일 수 없으므로(속성이 전부 제거된다)
  렌더 계층(html-react-parser)이 끼워 넣어야 한다

### 문장 안의 표식들

- **`mark`**: `--accent-soft` 면 + `--text` 글자. 2차 강조색 금지라 노랑을 못 쓴다.
  글자를 `--accent` 로 하면 링크로 오인되므로 면만 빌린다
- **`u`**: 이 화면에서 밑줄+포인트색은 링크의 표식이다. `u` 는 글자색을 두고 밑줄만 `--dot` 으로 눕혀 분리
- **`s`**: 지워진 내용이므로 `--meta` 로 한 칸 내린다
- **`small`**: 15px + `--text2`
- **`span`**: **아무 스타일도 주지 않는다.** sanitize 가 class·style 을 버려 빈 껍데기로 남으므로,
  여기 효과를 주면 원문이 의도하지 않은 강조가 생긴다
- **`hr`**: 점선(`--dot`). 이 사이트의 구획선은 전부 점선이라 실선만 이물감이 생긴다

### 포커스에서 형태가 변하지 않게 (기존 규칙 정정)

전역 포커스 스타일에 있던 `border-radius: var(--r-focus)` 를 **뺀다.** `a:focus-visible` 의 명시도가
`.card` 를 이겨서, 키보드 포커스가 닿는 순간 **카드가 12px→6px, 알약 버튼이 999px→6px 로 각지게
변하고 있었다.** 94~95행("호버·포커스에서 완전 복구… 키보드 이동도 같다")과 정면으로 어긋난다.

빼면 아웃라인이 각 요소 자신의 라운드를 따라간다. 라운드가 없는 인라인 링크는 사각 아웃라인이
나오고 그게 정상이다. 승인된 시안 두 장(feed-a·article)도 같은 결함을 갖고 있었으므로
[mockups/article-prose.html](mockups/article-prose.html) 에서 고쳤다 — 안 고치면 다음 화면이 물려받는다.

### 새 토큰

`--r-inline: 6px` — 글 흐름에 박히는 인라인 칩(`code`·`mark`)의 라운드. 지금 `code` 라운드가 6px 로
하드코딩돼 있는데 `mark` 가 들어오며 같은 값이 두 곳이 된다. 값은 기존과 같아 보이는 것은 안 바뀐다.

### 앞선 블록의 문서 누락 정정 (값 변경 아님)

구현이 승인된 시안을 따랐는데 이 문서 목록이 그걸 못 따라간 것들. **새 결정이 아니라 기록 보정이다.**

- 타이포 단계 목록(64~67행)에 **모바일 ≤640px: 상세 제목 23px, 본문 16px** 추가 (시안 `article.html` 승인분)
- 66~67행의 "11.5 뱃지·태그 칩" 은 두 자리를 뭉쳤다 →
  **11.5 뱃지·카드 태그 칩 / 12 메타·상세 태그 칩** 으로 나눈다. 12 는 이미 있는 단계라 단계가 늘지 않는다

## 2026-08-08 · 우리 제목과 원문 제목 가르기 + 이미지 자리 예약 · checkpoint 승인

승인된 시안: [mockups/article-prose.html](mockups/article-prose.html) (같은 파일에 덧그렸다)

review 사인오프 직전에 남아 있던 결정들을 처리한 자리다. 새 시각 방향이 아니라
**이미 승인된 언어 안의 마감**이라 시안 루프를 새로 돌지 않고 기존 시안에 반영해 확인받았다.

### 상세 화면에는 `h1` 이 둘이고, 그대로 둔다

페이지 제목은 우리가 붙인 것이고 원문 안의 `h1` 은 출처가 쓴 것이다. 파서에서 강등(h1→h2)하는
안을 검토했지만 **채택하지 않았다** — HTML5 에서 `h1` 이 여럿인 것은 위반이 아니고, 강등은
문서 개요를 위해 원문 마크업을 우리가 고쳐 쓰는 일이다. 대신 **눈으로 갈라지게** 만든다.

대가는 정직하게 적어둔다: 스크린리더의 제목 목록에서 원문 제목이 페이지 제목과 같은 층으로
보인다. 색과 세로선은 시각 신호라 그 목록에는 안 나타난다.

### 포인트색 면적 규칙을 넓힌다 (2026-08-02 "색" 절 정정)

그 절은 포인트색이 "활성 상태, '뜨는 중' 뱃지, 로고 점, 링크 정도에만 닿는다"고 적었다.
여기에 **상세 화면의 페이지 제목**을 더한다.

> 이 문서의 기존 참조들이 줄 번호를 쓰는데(63행·71~73행 등) 문서가 자라면서 이미 몇 줄씩
> 어긋나 있다. 이 블록부터는 **절 이름으로 가리킨다** — 줄은 움직여도 절 이름은 안 움직인다.

- **`--accent` 는 "우리가 붙인 것"의 표식이다.** 상세 화면에서 제목이 포인트색이면 우리 것,
  먹색이면 출처가 쓴 것. 원문 안의 `h1`~`h6` 에는 포인트색을 쓰지 않는다
- 피드의 "색은 '아직 안 본 것'에만 쓴다"("상태 규칙" 절)와 부딪히지 않는다 — 상세는
  **여는 순간 읽음이 되는** 화면이라 안 읽음/읽음 구분 자체가 없다. 두 규칙이 서로 다른 화면에서 산다
- 대비 `--accent` on `--bg` = **5.49:1**. 링크가 이미 쓰던 조합이라 새 하한이 생기지 않았다
- 넓히는 것은 여기까지다. "하지 않는 것" 절의 **포인트색 전면 배경 금지**는 그대로다

### 원문 시작을 구획선으로 선언한다

"아래는 출처에서 가져온 원문입니다" 줄 **위에** 점선 한 줄. 안내문은 굵기 600 으로 한 칸 올리고
아래 여백을 24px 로 키운다. 크기·색은 그대로(12px, `--meta`) — 읽는 문장이 아니라 안내다.

- **아래쪽에는 선을 두지 않는다.** 위아래를 다 막으면 안내문이 상자에 갇히고, 이 화면은 이미
  점선을 여러 곳(메타 줄·요약 주의문구·원문 h1·hr)에서 쓰고 있어 한 줄만 더해도 충분하다
- **요약이 없으면 이 선을 뺀다.** AI 요약 박스는 조건부라(생성 실패 시 안 그린다) 그때 원문은
  메타 줄 바로 뒤에 오는데, 메타 줄이 이미 아래에 점선을 갖고 있다. 선이 둘 나란히 서면
  실수처럼 보인다 (`.metaRow + .prose { border-top: 0 }`)

### 원문 안 `h1`·`h2` 에 왼쪽 세로선

`--dot` 2px, 안쪽 여백 14px, **본문 칼럼 바깥으로 16px 내민다**(`margin-left: -16px`).

- **내미는 이유**: 안쪽으로 들여쓰면 제목이 본문보다 오른쪽에서 시작해 위계가 뒤집혀 보인다.
  내밀면 선만 밖에 서고 글자는 본문과 정확히 같은 자리에서 시작한다(2px + 14px = 16px).
  `.read` 의 좌우 여백이 20px 이라 모바일에서도 화면 밖으로 나가지 않는다
- **`h3`~`h6` 에는 두지 않는다.** 깊어질수록 장식이 줄어드는 쪽이 자연스럽고,
  17px 제목에까지 선이 붙으면 원문이 온통 세로줄이 된다
- **선은 본문 칼럼 최상위 제목에만.** 인용문·목록·표 **안**의 제목에서는 선을 접는다.
  내밀기의 근거("`.read` 의 여백 20px 안에 들어간다")가 최상위에서만 성립하고, 그 안에서는
  인용문의 4px 선에 딱 붙어 6px 실선처럼 보이거나 표의 가로 스크롤에 잘린다.
  거기서는 이미 부모가 구획을 나르고 있다

**이 화면의 왼쪽 세로선은 셋이다.** 넷째를 발명하지 않도록 적어둔다:

| 자리 | 색 | 두께 | 위치 |
| --- | --- | --- | --- |
| AI 요약 박스 | `--accent` | 4px | 상자를 감싼다(우리가 만든 것) |
| 원문 인용문 | `--dot` | 4px | 안으로 들여쓴다 |
| 원문 `h1`·`h2` | `--dot` | 2px | 칼럼 **바깥**으로 내민다(출처가 쓴 것) |

인용문이 제목보다 두꺼운 같은 색 선을 쓰는 건 구조상 거꾸로지만, 내밀기/들여쓰기로 갈리고
승인된 시안에 둘이 같이 그려져 있어 그대로 둔다.

### 원문 이미지는 도착 전에 자리를 잡는다

지금까지는 `height: auto` 뿐이라 **로드 전 높이가 0** 이었고 이미지가 뜨는 순간 아래 글이 통째로 밀렸다.
예약을 두 갈래로 나눠 맡긴다:

- **원문이 치수를 들고 온 이미지 → 브라우저 기본 동작에 맡긴다.** `.prose img` 에 `aspect-ratio` 를
  두지 않는다. 그 속성이 로드 전 상자(비율 + 폭)를 정한다
- **안 들고 온 이미지 → `.prose img:not([width]):not([height])` 에 `aspect-ratio: 16 / 9`**
- 원문 치수는 sanitize 가 조건을 통과시킨 값만 남긴다(content-safety INV-D2 · S10~S13).
  치수가 거부되면 이 화면에서는 위 대체 비율이 그대로 받는다 — 선택자가 `[width]` 유무만 보므로
  자동으로 맞물린다
- 남는 대가: 치수 없는 이미지가 16:9 에서 멀면 로드 후 한 번 조정된다. 높이 0 에서 튀어오르는 것보다 작다
- `display: block` 은 장식이 아니라 **예약의 전제**다. 인라인이 되면 폭이 칼럼을 안 채워 예약 높이가 같이 줄어든다

> **한 줄(`aspect-ratio: auto 16/9`)로 두 경우를 덮으려다 되돌렸다.** 그러면 작성자 선언이
> 치수에서 온 값을 덮는지에 결과가 걸리는데(캐스케이드에서 표현 힌트와 작성자 스타일의 우열),
> 이번 세션에 브라우저가 없어 실측하지 못했다. 선택자를 가르면 **어느 해석이 맞든 결과가 같다** —
> 답을 몰라도 되게 만드는 쪽을 골랐다. code-reviewer 가 이 자리를 HIGH 로 지적했다.

### 실측 대비

**새로 생긴 텍스트 색 조합이 없다.** 페이지 제목이 쓰는 `--accent` on `--bg`(5.49:1)는 링크가
이미 쓰던 조합이고, 나머지 변경은 선·여백·굵기·비율이라 색을 건드리지 않는다. 하한은 **4.75:1** 유지.

> 이 세션도 Playwright 가 붙지 않아(MCP·로컬 모두 부재) **브라우저 실측을 못 했다.**
> 위 수치는 CSS 값 계산이다. 2026-08-06 (2) 에 이어 두 세션 연속이라, 실측이 필요한
> 변경을 하기 전에 Playwright 연결을 먼저 해결하는 편이 낫다.

상태(요약이 없는 소식)와, 제목 번역(INV-S6)을 붙이며 생긴 줄인데 시각 기준이 없었다.

### 요약이 없는 카드는 그대로 둔다 (빈칸을 메우지 않는다)

`displaySummary` 가 AI 요약도 출처 요약글도 못 찾으면 카드에서 요약 문단이 통째로 빠진다
(2026-08-10 실측: 101건 중 9건). `.cardBody` 가 `flex: 1 1 auto` 라 점선 발은 카드 바닥에
붙고 제목 아래가 빈칸으로 남는다. **그 빈칸을 그대로 둔다.**

- 카드 높이는 그리드가 같은 행끼리 맞춘다 — 어느 안을 골라도 **점선 발 위치는 안 흔들린다.**
  시그니처(카드 안 점선)가 걸린 문제가 아니었다
- 검토한 두 대안과 시안에서 잰 결과:
  - **요약 없을 때만 제목 3줄 허용**: 잘렸던 제목이 펴져 빈칸이 81px→58px 로 줄지만,
    제목이 짧은 카드에서는 104px 그대로다. 되는 카드와 안 되는 카드가 갈린다
  - **"요약을 준비하지 못했습니다" 한 줄**: 빈칸이 49px 까지 줄지만 같은 문장이 9개 카드에
    반복되고, 지금 요약이 없는 항목은 **근거가 없어 호출 자체를 건너뛴 것**이라
    (`skippedNoEvidence`) 재시도해도 안 생긴다 — 곧 채워질 것처럼 읽히는 문구가 사실과 다르다
- 빈칸은 "요약이 없다"를 그대로 보여준다. **빈 상태 규칙**("일러스트·재시도 버튼을 두지 않는다")과
  같은 방향이다 — 없는 것을 말로 채우지 않는다
- 다시 볼 조건: 요약 없는 항목이 지금처럼 열에 하나 수준이 아니라 절반을 넘어가면,
  그때는 빈칸이 화면의 기본 상태가 되므로 이 결정을 다시 확인받는다

### 원문 제목 병기 줄은 메타 줄 안으로

번역 제목을 보여주므로(INV-S6) 대조할 원문이 필요하다. 그 줄을 **제목 바로 밑이 아니라
출처·시각과 같은 묶음(메타 줄)에 둔다.** 메타 줄 안에서 한 줄을 통째로 차지한다.

- **왜 제목 밑이 아닌가**: 제목 바로 밑 6px 에 붙으면 우리가 붙인 제목과 한 덩어리로 보인다.
  이 화면은 "우리가 붙인 것 = 포인트색 / 출처가 쓴 것 = 먹색"으로 가르는 중인데
  (2026-08-08 "포인트색 면적 규칙"), 원문 제목은 출처가 쓴 것이라 제목 묶음에 들어가면 안 된다
- **라벨 "원문 제목:" 을 유지한다.** 제목에서 떨어져 나온 만큼 이 줄이 무엇인지는 라벨만 나른다
  (라벨을 빼는 안도 같이 봤고, 원문인지 부제인지가 문맥에만 기대게 되어 채택하지 않았다)
- 크기·색은 그대로 12px `--meta`. 읽는 문장이 아니라 대조용 참고다
- 여백은 메타 줄의 `gap`(10px)이 준다 — 여기에 `margin` 을 또 주면 둘이 더해진다.
  이전의 `margin-top: -6px` 은 제목과의 간격을 맞추려던 값이라 함께 없앴다
- 메타 줄 높이가 46px → 74px 로 한 줄 두꺼워진다. 대신 제목 아래가 비어 h1 이 홀로 선다
- **번역이 없으면 이 줄은 아예 안 나온다** — 원문이 이미 제목 자리에 있다

> 이 줄은 이제 메타 줄의 **자식**이라, "요약이 없으면 원문이 메타 줄의 바로 다음 형제"
> (2026-08-08 `.metaRow + .prose`)가 번역 유무와 무관하게 성립한다. 제목 밑에 두면
> 번역이 있는 소식에서만 그 전제가 깨질 수 있었다. 테스트로 붙들어 뒀다.

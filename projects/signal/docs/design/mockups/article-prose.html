도구를 늘리기 전에 호출 로그부터 본다

Anthropic 블로그 · 3시간 전 에이전트 툴 운영
✨ AI 요약

도구를 더 붙일수록 에이전트가 똑똑해질 것 같지만, 선택지가 늘어난 만큼 잘못 고르는 일도 함께 늘어난다. 늘리기 전에 지금 도구가 실제로 어떻게 쓰이는지부터 세어보자는 이야기.

  • 비슷한 일을 하는 도구가 여러 개면 모델이 고민을 시작한다 — 묶을 수 있으면 묶는다
  • 도구 설명은 길게 쓰는 것보다 무엇을 안 하는지 적는 쪽이 효과가 컸다
  • 호출 로그를 며칠만 모아도 안 쓰이는 도구가 금방 드러난다

요약은 자동으로 생성됩니다. 사실 확인이 필요하면 아래 원문을 읽어주세요.

아래는 출처에서 가져온 원문입니다.

에이전트를 만들다 보면 자연스럽게 도구를 하나씩 더 붙이게 된다. 검색이 필요하니 검색 도구, 파일을 읽어야 하니 읽기 도구, 그리고 어느새 목록이 화면을 넘어간다. 그런데 도구를 붙일 때마다 기대만큼 결과가 좋아지지는 않는다.

1부 — 도구가 많아지면 생기는 일

모델 입장에서 도구 목록은 결국 프롬프트의 일부다. 도구가 스무 개라면 스무 개의 설명이 매 요청마다 함께 들어간다. 문제는 길이만이 아니다. 설명이 서로 비슷하면 경계가 흐려지고, 모델은 그 흐린 경계에서 판단을 내려야 한다.

선택지가 늘면 무슨 일이 생기나

사람에게는 사소해 보이는 겹침이 모델에게는 매번 다시 풀어야 하는 문제로 남는다. 자주 보이는 경우는 대략 세 가지다.

  • search_docs 와 find_file 처럼 이름만 다르고 하는 일이 겹치는 경우
    • 둘 중 하나만 문서화가 잘 되어 있으면 그쪽으로 쏠린다
    • 쏠린 쪽이 정답이 아니어도 로그를 보기 전까지는 드러나지 않는다
  • 같은 대상을 다루는데 인자 모양만 다른 도구가 나란히 있는 경우
  • 거의 안 쓰이지만 "혹시 몰라서" 남겨둔 도구

정리 순서를 정해두면 손이 덜 간다.

  1. 호출 로그를 모아 현황을 본다
    1. 도구별 호출 수
    2. 실패한 호출의 비율
  2. 겹치는 도구를 합친다
  3. 남은 도구의 설명에 경계를 적는다

겹침은 이름이 아니라 결과로 판단한다

이름이 달라도 같은 것을 돌려주는 도구는 겹친 것이다. 반대로 이름이 비슷해도 돌려주는 모양이 다르면 합치면 안 된다. 판단 기준을 호출 결과에 두면 논쟁이 짧아진다.

합칠 때의 신호

두 도구의 설명을 다듬은 뒤에도 모델이 계속 헷갈린다면, 그건 두 도구가 실제로 하나여야 한다는 신호일 수 있다.

합치지 말아야 할 때

권한 범위가 다르면 합치지 않는다. 읽기 전용 도구와 쓰기 도구를 한 이름으로 묶으면, 모델이 실수했을 때 되돌릴 수 없는 쪽으로 실수한다.

부록 — 이름 짓기 메모

동사로 시작하고, 대상은 하나만 담는다. get_user_and_orders 같은 이름이 나오면 대개 도구가 두 개여야 한다는 뜻이다.

호출 로그를 세어본 결과

2주치 호출을 모아 도구별로 세었다. 상위 세 개가 전체 호출의 대부분을 차지했고, 하위 도구들은 거의 불리지 않았다.

도구 호출 수 실패율
search_docs 1,284 3.1%
read_file 903 1.2%
find_file 47 28.9%

열이 많은 표는 읽기 컬럼을 넘어간다. 이럴 때 페이지가 통째로 밀리지 않고 표만 좌우로 움직이는지 확인해보자. 표 안을 한 번 클릭하거나 Tab 으로 들어간 뒤 좌우 화살표로도 움직인다.

도구를 하나 더 만들기 전에, 지금 있는 도구 중 무엇을 지울 수 있는지 먼저 본다. 지울 게 없다면 대개 설명이 부족한 것이지 도구가 부족한 게 아니다.

— 내부 회고 메모에서

설명은 짧게, 대신 경계를 적는다

도구 설명을 길게 쓰면 잘 고를 것 같지만, 실제로 도움이 된 건 "이 도구가 무엇을 하지 않는지"를 한 줄 넣는 쪽이었다.

{
  name: "search_docs",
  description:
    "사내 문서에서 키워드로 검색한다. " +
    "코드 파일은 다루지 않는다 — 그건 search_code 를 쓴다.",
  input: {
    query: { type: "string" },
    limit: { type: "number", default: 10 }
  }
}

원문이 문장 안에서 쓰는 표식들

원문에는 문장 안쪽을 꾸미는 태그도 섞여 들어온다. 여기 한 줄에 모아 보면 이렇다. 이 문단에서 가장 중요한 건 굵은 글자이고, 기울인 글자는 강조가 한 단계 약하다. 출처가 직접 형광펜을 친 이 부분은 소프트 포인트면으로 받고, 밑줄만 그은 부분은 링크와 헷갈리지 않도록 밑줄 색을 눕혔다. 취소선이 그어진 문장은 한 단계 흐려진다. span 은 sanitize 를 지나면 속성이 모두 사라지므로 아무 효과도 주지 않는다.

수식이나 단위가 섞이면 위첨자·아래첨자도 온다. 물 분자는 H2O 이고, 이번 달 호출은 약 105 회였다. 이 문장처럼 덧붙임은 한 단계 작게 나온다 — 다만 본문 하한을 지켜 15px 까지만 내려간다.

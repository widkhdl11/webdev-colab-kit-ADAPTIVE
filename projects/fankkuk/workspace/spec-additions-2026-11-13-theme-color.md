## 무엇이 바뀌나

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 고를 수 있는 색 | 파스텔 8색 중 하나, 또는 비어 있음 | `#RRGGBB` 꼴인 아무 색, 또는 비어 있음 |
| 화면 | 8색 견본 + 「선택 안 함」 | 8색 견본 + 「직접 고르기」(색 고르기 판 · 색 코드 칸 · 「옅게 맞추기」 체크박스, 기본 꺼짐) + 「선택 안 함」 |
| 「옅게 맞추기」 | 없음 | 켜면 화면이 흰색을 섞어 밝기(상대 휘도) 0.70 에 닿는 가장 진한 색으로 바꾸고, 그 색을 「적용 색」으로 보인 뒤 보낸다. 체크 상태는 저장하지 않는다 — 저장되는 것은 색 하나 |
| 팬덤 배지 글자 | #111827 고정 | 테마 색에 따라 **#000000 · #FFFFFF 중 대비가 큰 쪽**. 어떤 색에서도 4.58:1 이상(모든 색을 훑어 계산, 가장 나쁜 색 `#5D60FF` 근처). #111827 · 흰색 조합은 가장 나쁜 색에서 4.21:1 이라 쓰지 않는다 |
| 배지 테두리 | 테마 색과 #1F2937 22% 섞음 | 그대로 |
| 검사하는 곳 | 앱 서버 · DB 함수 · DB 제약이 8색 목록과 비교 | 같은 세 곳이 꼴만 검사(10-15 때와 같은 강도). 화면은 그리기 직전 꼴을 한 번 더 확인(틀리면 기본 모양) |

진한 색이 그대로 쓰이는 곳: 카드의 사진 없는 배너, 크리에이터 페이지 맨 위 띠, 프로필 사진 테두리 — 셋 다 위에 글자가 없다(INV-E14 그대로).

## INV-E13 새 문장 (바뀌는 줄만)

- 값은 비어 있음(사이트 기본 모양) 또는 `#RRGGBB`(대문자로 저장)인 아무 색이다. 꼴이 틀린 값은 앱 서버와 DB 가 모두 거부한다.
- 화면은 견본 8색과 「직접 고르기」를 보인다. 「옅게 맞추기」를 켜면 보내기 전에 화면이 색을 바꾼다(서버 규칙이 아니다).
- 나머지(쓰는 자리 네 곳, 버튼·글자·선택·초점에 안 씀, 본인만 바꿈, 팬컬러)는 그대로.

## INV-E14 새 문장

- 팬덤 배지 글자색은 저장하지 않고, 테마 색에서 공용 계산 함수 하나로 정한다: #000000 과 #FFFFFF 가운데 대비가 큰 쪽. 테마 색이 없으면 지금 기본 모양 그대로.
- 요청 본문에 글자색을 넣어도 쓰이지 않는다(그대로).

## 시험 바뀌는 것

- S12: `#dcebff` → `#DCEBFF` 그대로 + 진한 색 `#2b4c9b` 저장 → `#2B4C9B`.
- S12b: `red`·`#12345`·`#123456; background:url(x)` 거부는 그대로. `#1E3A8A` 는 이제 통과 — 거부 목록에서 뺀다.
- S13: 8색 → 검정 글자. 진한 색 `#2B4C9B` → 흰 글자. 경계 색(가장 나쁜 색 근처)에서도 4.5:1 이상.
- 새 시험: 「옅게 맞추기」 계산 — 진한 색은 결과 밝기 0.70 이상, 이미 밝은 색은 그대로.

## 구현 범위 (승인 뒤)

- 라이브러리: react-colorful 5.8.1(MIT, 설치 의존성 없음, React 16.8 이상) — `HexColorPicker` 하나. 색 코드 칸·체크박스는 사이트 부품.
- 공용 계산: `src/entities/creator/model/creator-color.ts` — 꼴 검사(8색 목록 검사를 대신), 배지 글자색, 옅게 맞추기.
- DB 마이그레이션 하나: 제약 `creators_personal_color_palette` → 꼴 검사로, 저장 함수 `update_my_creator_profile` 의 8색 비교 → 꼴 검사로. 지운 값 없음.
- 화면 명세(docs/ux/pages/creator-profile.md): 채널 탭 상태 추가 — 「직접 고르기 열림」, 「옅게 맞추기 켬」.
- 리뷰: 저장 경로 입력 검사가 바뀌므로 security-reviewer, 화면은 ux → ui.

## 가입 전화번호 암호화 — 키를 어디에 둘지

지금: 가입 번호는 개인정보 구역 표에 평문으로 있다. 화면 쪽 키로는 읽을 수 없고(팬·크리에이터·익명 모두 거부), 서버만 읽는다.
본인 화면에는 가운데 넷을 가린 번호만 간다. 운영자 화면에는 가입 번호가 아예 나오지 않는다.

평문을 쓰는 곳 다섯: 가입 때 같은 번호 중복 확인 · 번호 바꾸기 때 「지금 번호와 같은지」 · 인증번호 요청 횟수 제한(번호별 하루 5회) · 카카오 알림톡 발송 · 본인 화면 가린 번호.

### 안 A (추천, 업계 표준): 앱 서버가 암호화 + 중복 확인용 해시
- 저장: 번호 암호문(AES-256-GCM) + 같은 번호 찾기용 해시(HMAC-SHA256, 다른 키) + 뒤 4자리(가린 표시용).
- 키 두 개는 서버 비밀값에 둔다. 주소처럼 클라우드 KMS 는 외부 연결 단계에서 옮긴다.
- DB 가 통째로 새도 키가 없으면 번호가 안 열린다. 키를 잃으면 번호를 못 연다 — 알림톡이 안 나가고 사용자가 번호를 다시 인증해야 한다.
- 인증 기록 표(3분짜리)는 해시만 저장한다.
- 시험 사이트 DB 의 기존 번호는 사람이 돌리는 변환 스크립트로 한 번 바꾼다(개인정보 수동 SQL 은 사람이 적용).

### 안 B: DB 안에서 암호화(pgcrypto + DB 비밀 금고)
- 코드 변경이 적다. 키가 같은 DB 에 있어 DB 접근 권한이 털리면 같이 열린다.

### 같이 정하는 것(사용자 지시 그대로)
- 운영자 화면에 가입 번호를 보일 일이 생기면 뒷자리를 가린다(010-1234-****). 원번호를 보는 운영자 화면은 만들지 않는다.
- 사람이 원번호를 보게 되는 화면을 만들게 되면 열 때마다 누가·언제·누구 번호를 기록한다.
- 기계가 여는 것(알림톡 발송)은 열람 기록 대상이 아니다.

### 지시와 부딪히는 한 곳
운영자 「보류 상자」 목록과 「뒤 4자리 검색」은 상자에 붙어 온 원 송장의 전화번호 뒤 4자리를 운영자에게 보여 준다(가입 번호가 아님). 6자리 코드 없이 온 상자를 문의한 팬과 잇는 데 쓴다. 「뒷자리 가림」을 여기에도 적용하면 이 잇기가 안 된다 — 추천은 그대로 둠.

## 사용자 결정 (2026-11-06) — d2 가 닫히면 이 내용으로 카드를 올리고 진행

1. A안. 서버가 번호를 암호화해 저장. 키는 Vercel 환경 변수(Sensitive), 백업은 사용자의 비밀번호 관리 프로그램 한 곳. KMS 는 쓰지 않는다. 중복 가입 확인용 해시 키도 별도 값으로 같은 방식.
2. 뒤 4자리는 가린 번호 표시용으로 따로 둔다.
3. 기존 번호 변환 스크립트는 개인정보 SQL 이라 사용자가 적용한다 — 실행 순서와 확인 쿼리를 적어 넘긴다.
4. 운영자 화면: 목록은 가입 번호 가운데 가림(010-****-1234). 대표 권한 「전화번호 보기」는 사유 입력 없이 바로 표시, 서버가 접속 기록(누가·언제·어느 계정)만 자동으로 남긴다(안전성 확보조치 기준의 접속 기록, 1년 보관). 직원 권한은 가린 번호만.
5. 「보류 상자」 목록·뒤 4자리 검색은 원 송장 번호라 그대로. 가림 규칙은 가입 번호 화면에만.
6. 알림톡 발송은 서버가 풀어서 솔라피에 넘기고 화면에는 나오지 않는다(지금과 같음).

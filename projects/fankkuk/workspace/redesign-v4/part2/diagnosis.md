# 2파트 크리에이터 화면 다섯 진단 — 시안 4 기준 (2026-11-01)

비교 페이지: `docs/design/mockups/part2-v4-20261101/index.html` (지금 캡처: `docs/design/mockups/part2-v4-20261101/now/`). 원칙 번호는 `docs/design/design-prompt.md`.
문구·칸 순서·노출 조건은 지금 코드 그대로 두고 배치·위계·간격·색·경계·정렬만 다뤘다. 코드(`src/`)는 건드리지 않았다.
탭 다섯: 지금 할 일(비어 있음 · 승인 요청 하나 · 할 일 여럿) / 받은 선물(비어 있음 · 상자 목록 · 답장 칸 열림) / 승인 내역(5건 · 네 결과 섞임 · 없음) / 선물 현황(받는 선물 · 승인 대기 판 · 보내는 선물) / 열람 기록(비어 있음 · 기록 여러 줄). 열네 상태 × PC 1440 · 휴대폰 390.

캡처가 있는 상태 다섯(지금 할 일 빈 상태 · 받은 선물 빈 상태 · 승인 내역 5건 · 선물 현황 받는 선물 진행 중 · 열람 기록 빈 상태)은 캡처 그대로다. **나머지 아홉은 캡처가 없어 코드의 CSS 값으로 같은 틀에 다시 그린 「지금(재현)」이다**(로컬 시드에 데이터가 없다). 그린 상태: 지금 할 일 둘(승인 요청 하나 · 할 일 여럿 — 추적 장치 · 블루투스 「받기 선택」 · 승인 판 · 남은 승인 요청 카드 셋 · 반송 주소 · 미도착 상자 · 결제 대기 · 추가 결제 · 상자 찾기 줄), 받은 선물 둘(목록 · 답장 칸 열림), 승인 내역 둘(네 결과 섞임 + 접는 줄 둘 · 없음), 선물 현황 둘(승인 대기 판 · 보내는 선물 + 하늘 카드), 열람 기록 하나(여러 줄 + 재출력 · 출력 실패).
**승인 내역의 「승인 대기 요청이 있는 상태」는 그리지 않았다** — 이 화면에는 없다. 대기 중인 요청은 지금 할 일에서 처리하고(action-center INV-J5·J6, 2026-10-16) 이 화면은 처리를 마친 요청만 보인다. 요청이 대기 중일 때의 모양은 지금 할 일 「승인 요청」 상태가 맡는다.
왼쪽 메뉴는 이 파트 범위 밖이라 펼친 240(크리에이터 메뉴 · 「하루님」)으로 그렸다. 승인 내역 캡처는 메뉴가 접힌 채(64)다. 캡처는 전체 페이지라 폭이 1425/375다.

## 이 다섯 화면의 공통 원인
1파트(팬 쪽 같은 종류 화면)에서 정한 부품이 크리에이터 쪽에는 아직 안 닿아 있다. 같은 역할이 팬 쪽과 크리에이터 쪽에서 다른 모양이다.
- 촘촘한 줄 안쪽 12 (팬 쪽은 32) · 선 버튼 gray-400 (팬 쪽 짙은 선) · 빈 상태 (팬 쪽 흰 카드) · 상태 뱃지 글자만 (팬 쪽 점 + 글자)
- 회색 보조 칸에 경계 없음 (36·37·39절 안내 상자 = 면 + 1px 선)

## 1. 지금 할 일 `/creator/actions`
지금과 어긋나는 곳
- **빈 상태가 카드 없이 그림 + 문구 + 버튼이 바탕에 떠 있다.** 팬 지금 할 일 빈 상태는 흰 카드다(1파트 9-2). 크리에이터 다섯 화면의 빈 상태가 다섯 모양이다(그림만 / 한 줄 카드 / 그냥 글자 / 카드 + 접힌 상자 / 카드) (4-6, 2-4)
- 촘촘한 줄 안쪽 12 인데 하늘 승인 판 안쪽은 40, 카드는 24 — 얼굴 · 글자 · 버튼 정렬선이 어긋난다(1파트 강조 칸 32 · 줄 12 와 같은 원인) (2-9)
- 선 버튼 테두리 gray-400(흰 바탕 2.5:1) (8-12, 37·38절)
- **줄 안의 「확인하기」(반송 주소)만 채움 버튼(48)**: 같은 줄 오른쪽 처리 버튼이 「신고할지 정하기」 · 「내 상자 찾기」 · 「결제하기」는 선 버튼(44)인데 이것만 채움이고, 반송 주소 줄이 여럿이면 채움 버튼이 여러 개가 된다 (1-2, 4-1)

바꾼 것: 빈 상태 흰 카드(그림 72), 줄 안쪽 32(휴대폰 24), 승인 판 안쪽 40 → 32, 선 버튼 짙은 선 `#6B7280`(4.8:1), 「확인하기」를 선 버튼 44 로.
바뀌지 않는 것: 받은 선물 → 승인 요청 하늘 판 하나(받지 않기 · 승인하기 채움 하나) → 남은 승인 요청 카드 2열 → 보낸 선물 줄 순서와 건수, 남은 날 48, 「받기 선택」 + 「선택 취소」, 제목 32(38절로 이미 적용).

## 2. 받은 선물 `/creator/boxes`
- **오른쪽 288 회색 칸 윗선이 왼쪽 첫 카드와 어긋난다(빈 상태)**: 칸은 위 48 로 고정인데 빈 상태 왼쪽 카드는 달 머리가 없어 위로 붙는다(캡처 y 113 대 162). 목록 상태는 달 머리 32 + 16 = 48 이라 맞는다 (2-9)
- **지난 달 줄에서 글자가 잘린다**: 줄 목록은 왼쪽 단(560)에 들어가는데 오른쪽 끝에 「10월 29일 출고 · 「너무 마음에 들어요」 답장」 + 「답장 삭제」가 자리를 차지해 이름 「솜사탕님의 선…」과 설명이 말줄임(…)된다. 값이 칸보다 길 때 잘라서 정보가 사라진다 (칸 길이는 값 길이에 맞춘다) (2-9)
- **한 행 카드의 아래 줄이 칸 폭에 따라 달라진다**: 카드 2열이 560 안에서 272 라 「11월 1일 출고 · 수령 확인」 + 「답장 남기기」는 한 줄에 안 들어가 버튼이 아래로 떨어지고, 옆 카드의 「받았어요」는 같은 줄 오른쪽에 있다 — 같은 카드인데 버튼 자리가 다르다 (2-4, 2-6)
- 회색 칸 · 답장 인용 상자 경계 없음(흰 카드 위 밝기 차 1.07:1) (4-7)
- 답장 고르기 칩 테두리 gray-200(1.2:1) · 높이 48 (8-12, 4-3, 37절 칩 = 짙은 선 44)
- 지난 달 줄 안쪽 12, 선 버튼 gray-400, 빈 상태 한 줄 카드

바꾼 것: 빈 상태 카드를 같은 줄(48)에서 시작 · 공통 빈 카드 모양, 지난 달 줄 글자 줄바꿈(잘리지 않게), 카드 아래 줄을 「글자 → 버튼」 두 줄로 모든 카드 같게, 회색 칸 · 인용 상자 1px `--gray-200`, 칩 짙은 선 44 + 고른 칩 굵게, 줄 안쪽 32, 선 버튼 짙은 선.
바뀌지 않는 것: 최근 달 같은 모양 카드 2열 · 지난 달 촘촘한 줄 · 「받았어요」를 누른 카드만 한 줄 전체로 열림 · 오른쪽 288 칸에 답장 안 한 수 48(23-3절), 답장 칸 안 문구 · 순서.

## 3. 승인 내역 `/creator/requests`
- 줄 상태가 **글자만 든 알약**(점 없음). 1파트 받은 선물 · 5파트 팬 홈은 점 + 글자다 — 같은 역할 두 모양 (4-1, 4-2, 35·38절)
- 줄 안쪽 12 인데 위쪽 판(안쪽 32) · 달 머리(0)는 이미 정렬돼 줄만 12 로 들어가 있다. 휴대폰에서 달 머리 · 판 · 줄의 왼쪽 선이 셋이다 (2-9)
- 결과별 숫자 4칸 경계 없음 (4-7)
- (캡처 PC 승인 내역은 메뉴가 접힌 채 찍혔다 — 본문은 영향 없음)

바꾼 것: 점 + 글자 굵게(승인 초록 · 기한 만료 노랑 · 거절 · 차단 빨강 — 색은 그대로), 줄 안쪽 32(휴대폰 24), 4칸 1px `--gray-200`, 날짜 칸 폭 96 오른쪽 정렬 유지, 빈 상태 공통 카드.
바뀌지 않는 것: 처리 수 판 48 + 오른쪽 288 결과별 4칸, 달마다 촘촘한 줄, 맨 아래 접는 줄(승인 기한 만료 · 팬 차단), 접는 줄 문구.

## 4. 선물 현황 `/creator/progress`
- 「진행 중인 선물이 없습니다.」가 카드 없이 글자만 있고 왼쪽이 12 안으로 들어가 구간 머리(0)와 어긋난다 (4-7, 2-9)
- **같은 「5칸 진행 막대 + 단계 이름」이 두 모양**: 받는 카드는 칸 높이 8 · 단계 이름 짙은 글자 600, 보내는 줄은 칸 12 × 4 · 단계 이름 회색 500(늦은 줄만 갈색 600) (4-1, 2-4)
- **보내는 줄의 막대 · 단계 이름이 줄마다 다른 x 에서 시작한다**: 막대 묶음이 버튼 앞에서 오른쪽 맞춤이라 버튼 0 ~ 3 개에 따라 막대 시작점이 달라지고(별빛 1092 · 하늘 940 · 달토끼 765), 표처럼 읽히지 않는다 (2-7, 2-9)
- 보낸 날 머리의 「· 팬 3명」이 줄 맨 오른쪽에 떨어져 앞 점이 혼자 남는다(`justify-content: space-between` + 앞 구분점) (2-9)
- 하늘 승인 대기 판 안쪽 32 · 40, 줄 안쪽 12 — 정렬선 셋

바꾼 것: 빈 문구를 공통 빈 카드 안에, 줄 막대도 칸 16 × 8 · 단계 이름 짙은 글자 600(늦은 줄 갈색 600은 그대로), 보내는 줄을 「이름 200 | 막대 + 단계 200 | 버튼」 세 열로(왼쪽 맞춤, 순서는 그대로), 보낸 날 머리를 한 줄로(「11월 1일 14:20 결제 완료 · 팬 3명」), 승인 대기 판 안쪽 32, 줄 안쪽 32(휴대폰 24), 선 버튼 짙은 선.
바뀌지 않는 것: 승인 대기 하늘 판(건수 48 · 얼굴 · 채움 「지금 할 일」 하나), 받는 선물 같은 모양 카드 2열(할 일 있는 카드만 하늘 면), 보낸 날별 촘촘한 줄, 「받은 선물 전체 ›」 · 「보낸 내역 전체 ›」 44, 버튼은 필요한 줄에만.
진행 막대는 시안에서 `role="progressbar"` 로 그렸다(코드는 막대 숨김 + 낭독용 글자). 낭독 방식은 건드리지 않는 쪽이 지금 코드라 구현 때 판단.

## 5. 열람 기록 `/creator/log`
- 회색 규칙 칸(「주소 열람은 …최대 3회…」) 경계 없음 (4-7)
- 표 안쪽 12 인데 위쪽 판은 32 — 날짜 머리 · 시각 · 비고의 왼쪽 선이 판과 20 어긋난다 (2-9)
- **「비고」 한 열에 모양이 셋**: 「첫 출력」 글자, 「재출력 N번째」 회색 알약, 「출력 실패」 글자. 「출력 실패」는 돌려받은 줄이라는 **상태**인데 상태 뱃지가 아니다 (4-1)
- 빈 상태 카드는 다섯 화면 공통 모양으로

바꾼 것: 규칙 칸 1px `--gray-200`, 표 안쪽 32(휴대폰 24, 날짜 머리 포함), 「출력 실패」를 상태 뱃지(점 + 글자, 빨강), 빈 카드 공통. 「재출력 N번째」 알약은 분류라 그대로.
바뀌지 않는 것: 설명 문장 · 「이번 달」 판(열림 48 · 승인 · 재출력) + 「최대 3번」 칸 2:1, 880 폭 표 날짜별 묶음, 시각 · 주문번호 · 비고 세 칸.

## 승인 기준과 부딪혀 판단한 곳
1. **13절 「줄 오른쪽 5칸 진행 막대(100폭, 칸 높이 6)」 대 v35 카드 막대(칸 높이 8)**: 같은 역할이라 줄도 8(폭 96)로 올렸다. 13절 문장을 바꾸는 제안이다.
2. **13절 「버튼 PC 높이 36」 대 base.css `.btn--sm` 44**: 이미 44 로 구현돼 있어 시안도 44(8-1 · 37절 44).
3. **23-3절 「받은 선물: 「받았어요」를 누른 카드만 한 줄 전체」 대 카드 아래 줄 정리**: 열림 규칙은 그대로고, 카드 아래 줄(출고 날 · 상태 글자 → 버튼)만 모든 카드에서 같게 두 줄로 쌓았다.
4. **23-1절 회색 보조 카드 「그림자 없음, 위 반사선만」 대 4-7 경계**: 36·37·39절이 안내 상자에 1px `--gray-200` 을 정했으므로 같은 회색 면인 이 화면의 보조 칸에도 같은 선을 더했다(그림자는 그대로 없음). 39절의 「회색 안내 상자 = 면 + 1px 선」을 회색 보조 카드까지 넓히는 제안이다.
5. **21절 「한 화면에 강조 하나」 대 지금 할 일의 하늘 판 + 채움 버튼**: 하늘 승인 판 하나 + 채움 「승인하기」 하나로 이미 맞다. 선물 현황 승인 대기 판도 하늘 판 하나 + 채움 하나.
6. **시안의 한계**: 크리에이터 얼굴은 고양이로 대신했다. 사이드바는 단순화(접힘 64 없음, 높이 36 — 범위 밖). 「받을지 정하기」 · 「신고할지 정하기」 창 · 승인 창(카카오톡 서명) · 배송 조회 · 내 상자 찾기 창은 이 파트 범위 밖이라 그리지 않았다.

## 정할 것
- **묻는 것: 없음.** 배치가 크게 바뀌는 곳이 없다.
- **정함 1 — 보내는 선물 줄 세 열(이름 | 막대 + 단계 | 버튼, 왼쪽 맞춤)**: 지금은 막대 · 버튼이 오른쪽 맞춤이라 줄마다 막대 시작점이 다르다. 세 열로 맞췄다. 칸 순서는 그대로, 줄 오른쪽에 빈 곳이 생긴다(버튼이 없는 줄). 대안(오른쪽 맞춤 유지 + 버튼 칸 폭 고정)은 버튼 셋 폭 340 이 모든 줄에 비어 이름 칸이 좁아져 버렸다.
- **정함 2 — 받은 선물 카드 아래 줄 두 줄 쌓기**: 카드가 272 라 한 줄에 안 들어가는 카드가 생기므로 모든 카드를 같은 모양으로.
- **정함 3 — 빈 상태 공통 카드**: 다섯 화면 모두 흰 카드 + 가운데 글. 그림은 코드에 있던 지금 할 일에만 둔다(그림을 새로 넣지 않음). 받은 선물의 빈 카드 위쪽에 48 여백이 생긴다(오른쪽 칸과 윗선 맞춤).

- **같은 역할 두 모양(팬 쪽 대 크리에이터 쪽)**: 빈 상태(흰 카드), 촘촘한 줄 안쪽 32, 선 버튼 짙은 선, 상태 뱃지 점 + 글자(승인 내역 · 열람 기록 출력 실패), 5칸 막대(줄 대 카드), 줄 오른쪽 처리 버튼(채움 → 선 버튼).
- **같은 상태 두 색**: 이번에는 해당 없음(승인 내역 뱃지 색은 지금도 뱃지 공통 색과 같다).
- **정렬선 어긋남**: 줄 안쪽 12 대 판 · 카드 · 표 안쪽(다섯 화면 전부), 하늘 판 안쪽 40 · 32 → 32, 받은 선물 빈 상태 오른쪽 칸 윗선, 선물 현황 막대 시작점, 보낸 날 머리의 떨어진 구분점, 빈 문구 12 안으로 들어감.
- **칸 길이가 값을 안 따라감**: 받은 선물 지난 달 줄 말줄임(이름 · 설명이 잘림).
- **색면 안 상자 경계 없음**: 회색 보조 칸 셋(받은 선물 288 칸 · 승인 내역 4칸 · 열람 기록 규칙 칸) · 답장 인용 상자.
- **경계 대비 3:1 미달**: 선 버튼 · 답장 고르기 칩.
- **44 미만 누를 칸**: 지금 코드에서 다섯 화면 모두 44 이상(`.btn--sm` 44, 「선택 취소」 44) — 해당 없음.

## 추가 — 반 폭 숫자 카드의 그림 자리 (11-01 사용자 「열람기록 페이지에서 이미지 위치가 이상한거같아」)

- 바꾼 것: 두 카드 모두 PC 에서 그림을 카드 안 오른쪽(안쪽 32) 세로 가운데로 — 숫자 오른쪽 빈자리. 카드 안 글자와 겹침 0(글자 폭으로 잼). 휴대폰은 카드가 화면 폭을 다 쓰고 옆 칸이 없어 모서리 걸침(64) 그대로.
- 넓은 판·오른쪽 끝 카드의 걸침은 그대로다.

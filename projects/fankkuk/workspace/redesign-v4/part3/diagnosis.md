비교 페이지: `docs/design/mockups/part3-v4-20261101/index.html` (지금 캡처: `docs/design/mockups/part3-v4-20261101/now/`). 원칙 번호는 `docs/design/design-prompt.md`.
문구·칸 순서·노출 조건·단계 수는 지금 코드 그대로 두고 배치·위계·간격·색·경계·정렬만 다뤘다. 코드(`src/`)는 건드리지 않았다.
탭 셋: 선물 보내기(일곱 상태) / 팬에게 보내기(두 상태) / 보낸 역조공(빈 상태 · 묶음 목록). 열한 상태 × PC 1440 · 휴대폰 390.
캡처가 있는 상태(10장)는 캡처 그대로, **보낸 역조공 묶음 목록(수락 · 수락 대기 · 받지 않음 섞은 3묶음 7개)은 캡처가 없어** 코드의 CSS 값(`revgift-sent.module.css` · `base.css` 태그 628~632줄)으로 같은 틀에 다시 그린 「지금(재현)」이다. 로컬 시드에 데이터가 없다.
캡처 일부는 왼쪽 메뉴가 접힌 채(64) 찍혀 있다 — 왼쪽 메뉴는 이 파트 범위 밖이라 바꾼 뒤 시안에는 펼친 240 으로 단순화해 그렸다(크리에이터 메뉴 이름도 단순화).

## 캡처를 읽을 때 — 착시와 실제를 가른 것
캡처는 전체 페이지라 화면에 붙어 따라오는(sticky) 요소가 스크롤한 자리에 찍힌다.
- **선물 보내기 1단계 · 3단계에서 「보낼 선물」 칸이 가운데 떠 있는 것, 휴대폰 3단계 합계 줄이 본문 한가운데 있는 것**: 착시. 칸은 `position: sticky; top: 32` 이고 맨 위에서는 단계 판 위와 맞는다(2단계 · 4단계 캡처가 그 모양). 시안은 스크롤 맨 위 기준.
- **팬에게 보내기 PC 결제 띠가 「진행 절차」 상자 위에 겹치고 그 아래 큰 빈 공간**(revnew-picked-1440 · revnew-1440): 둘을 나눠서 본다.
  - 겹침은 **실제**다. 띠는 `.tray { position: sticky; bottom: 24px }` 이고 흐름 안 제자리는 「진행 절차」 상자 아래 32 다. 창 높이(900)보다 내용이 길면 제자리가 창 아래로 나가고, 띠가 창 바닥 24 위로 끌려 올라와 상자의 아래쪽 줄(상자 크기 안내 불릿)을 덮는다. 스크롤을 내리면 제자리로 돌아와 풀린다 — sticky 의 본래 동작이고 25절 A안(붙어 따라오는 띠)이 정한 것이라 시안은 유지했다.
  - 띠 아래 큰 빈 공간은 **착시**다. 캡처 도구는 창은 900 인 채 페이지만 1500 으로 늘려 찍어, 창 바닥에 붙은 띠가 제자리로 못 내려간 것이다. 실제로는 스크롤 끝에서 띠가 제자리(상자 아래 32)에 앉는다.
  - 다만 **실제 여백 하나는 이유가 틀렸다**: `.page { padding-bottom: var(--section-gap) }`(96)의 주석은 「띠가 마지막 내용을 가리지 않게」인데, 띠는 `.col` 안의 sticky 라 바깥 여백이 막아 주지 않는다. 띠 아래 96 이 그대로 빈 공간이 된다. 시안은 0 으로 줄였다(쪽 기본 여백 40 + 바닥글만 남음).
- 선물 보내기 4단계 입력 판 위, 첫 줄 앞에 **약 48 빈 칸**이 캡처에 있다(y 345 → 425). 판 안쪽은 32 인데 48 이 더 있다. 코드에서 원인을 확인하지 못했다(`register-form.module.css` 53줄 주석이 말하는 「숨은 단계 뒤 단계 위 여백」이 아직 남은 것으로 의심). 시안은 안쪽 32 만. 구현 때 화면에서 확인.

지금과 어긋나는 곳

바뀌지 않는 것: 하늘 단계 판 하나 + 흰 입력 판 한 기둥 720 + 오른쪽 「보낼 선물」 칸 288 · 합계 1040(25 · 33절), 본문 칸 880 미만 한 기둥 + 3단계 합계 줄, 「보낼 선물」 칸(이미 흰 카드 + 카드 그림자), 채움 버튼 하나, 4단계 하늘 결제 칸 하나, 결제 실패 오류 줄(빨강 면 + 「!」 원 — 37절과 이미 같다).

## 3. 보낸 역조공 `/creator/revgifts`
지금과 어긋나는 곳
- 제목 24 (3-2)
- 「팬에게 보낸 선물 · 크리에이터에게 보낸 선물」 탭: 고른 탭이 굵기 + 하늘 밑줄(1.8:1)뿐 (4-3, 8-12, 38절 탭)
- **빈 상태 선물 상자 그림이 왼쪽으로 쏠려 있다**(PC · 휴대폰 둘 다): 그림이 블록 요소라 `text-align: center` 가 먹지 않는다. 글만 가운데라 정렬선이 둘이다 (2-7, 2-9)
- 주소·실명 안내 상자(회색 면) 경계 없음 (4-7)
- **묶음 목록 상태 뱃지**: `.tag` 가 수락 = 하늘 면 + 체크, 수락 대기 · 받지 않음 = **같은 회색 칩**이다. 둘이 글자로만 구분된다 (4-1, 4-2, 35절)
- **같은 상태가 한 화면에 두 색**: 맨 위 상태 띠 · 범례의 「수락」은 하늘인데 줄 뱃지는 초록이다. 같은 상태는 한 모양이어야 한다 (4-1, 2-4). 뱃지가 사이트 공통(35절)이고 띠는 이 화면 하나뿐이라 띠를 뱃지에 맞춘다

바꾼 것: 제목 32(휴대폰 24), 탭 높이 44 · 안쪽 16 · 고른 탭 `--primary-50` + 밑줄 2px, 그림 가운데, 안내 상자 1px 선, 상태 뱃지 점 + 글자(수락 초록 · 수락 대기 노랑 · 받지 않음 빨강 — 1파트 받은 선물의 수락 대기 · 수락 완료와 같은 색), **상태 띠 칸 · 범례 점을 같은 색으로**(수락 = 초록 채움 · 수락 대기 = 노랑 옅은 면 + 노랑 윤곽 2px · 받지 않음 = 빨강 채움). 채움 / 윤곽 모양 구분은 남겼다(색을 못 보는 사람도 구분).
바뀌지 않는 것: 880 한 단, 보낸 선물 수 48 + 상태 띠의 모양(팬 한 명이 한 칸 · 높이 16 · 사이 4, 25절), 같은 모양 묶음 카드(최근 묶음만 펼침 · 얼굴 5명까지 · 휴대폰은 얼굴 없음), 묶음마다 받는 주소 안내 한 번, 줄 64, 「송장번호 등록」 접는 줄, 「반송·환불 안내」 접는 줄. 받는 주소 부품(6칸 · 복사)은 이 시안에서 단순화해 그렸고 33절 그대로다.

## 승인 기준과 부딪혀 판단한 곳
1. **25절 상태 띠 색(수락 = 하늘 채움 · 수락 대기 = 하늘 윤곽 · 받지 않음 = 회색) 대 35절 뱃지(색 + 점)**: 같은 상태가 띠와 뱃지에서 다른 색이었다. 뱃지는 사이트 공통이고 띠는 이 화면 하나뿐이라 **25절 띠 색을 바꾼다**(초록 · 노랑 · 빨강). 25절의 띠 모양(한 명 한 칸, 높이 16, 사이 4, 채움 / 윤곽)은 그대로다. design-rules 에 25절 문장을 고치는 제안이다.
2. **23-1 「고르기 카드는 면 효과를 넣지 않는다」 대 4-6 흰 카드 경계**: 면 효과(그라데이션)는 그대로 빼고 1px 선 + 옅은 그림자만 안 고른 팬 카드에 더했다. 면 효과 금지와 그림자는 별개라고 읽었다. 선물 보내기 1단계 크리에이터 카드는 이미 흰 입력 판 안이라(카드 안 카드) 선만 두고 그림자는 더하지 않았다.
3. **21절 「한 화면에 강조 하나」 대 4단계의 하늘 판 둘(단계 판 + 결제 칸)**: 23-1 이 결제 칸을 강조 면으로 정했고 25절이 단계 판을 하늘로 정했다. 지금 그대로 둔다(1파트 상세와 같은 판단).
4. **37절 선 버튼 「이 범위 안에서만」**: 선물 보내기의 `.btn--line` 은 공용이라 이 시안의 짙은 선은 이 세 화면 범위(`.gift-send` · `.revgift-send` · `.revgift-sent`)에서만 바꾼다. 공용 `.btn--line` 정리는 BACKLOG 그대로.
5. **탭 모양**: 38절 규칙(`.tabs--line`)이 사이드바 화면 전체에 이미 적용돼 보낸 역조공 탭도 그대로 따라간다. 따로 정할 것 없음.
6. **시안의 한계**: 크리에이터 얼굴 사진은 고양이로 대신했다. 플랫폼 칩 아이콘은 색 점으로 단순화했다. 받는 주소 부품은 단순화했다. 사이드바는 단순화(접힘 64 상태는 그리지 않음).

## 정할 것
- **묻는 것: 없음.** 배치가 크게 바뀌는 곳이 없다(카드 높이 맞춤 · 그림 가운데 · 띠 윗선 맞춤은 모두 같은 요소의 정렬 보정).
- **정함 1 — 상태 띠 칸 색**(사용자 쪽 판단으로 뒤집음 11-01): 띠 칸 · 범례 점을 뱃지 점과 같은 색으로 바꾼다(25절 띠 색이 바뀜). 시안에 반영했다. 흰 카드 위 칸 경계 대비: 수락 6.73:1 · 수락 대기 윤곽 6.13:1 · 받지 않음 6.57:1(모두 3:1 이상, Playwright computed style).
- **정함 2 — 한 행 카드 높이 같게의 비용**: 안 고른 팬 카드 아래쪽이 비어 보인다. 대안(높이 맞춤 없이 고른 카드만 길게)은 1파트가 이미 같은 이유로 버렸다.
- **정함 3 — 결제 띠 sticky**: 유지. 스크롤 전 겹침은 sticky 의 본래 동작이다. 쪽 아래 여백만 96 → 0.

## 기본 원칙으로 같이 고친 것 (묻지 않고 반영)
같은 원인의 요소를 함께 고쳤다.
- **같은 역할 두 모양**: 같은 상태의 띠 · 뱃지 색(보낸 역조공 → 뱃지에 맞춤), 고른 칸 면(칩 · 크리에이터 카드 · 팬 카드 → `--primary-50`), 상태 뱃지(보낸 역조공 → 점 + 색), 구역 라벨(결제 띠 두 라벨 → 14/600), 안내 상자(회색 면 + 1px 선 — 선물 보내기 셋 + 팬에게 보내기 하나 + 보낸 역조공 둘).
- **정렬선 어긋남**: 결제 띠 세 묶음 윗선, 빈 상태 그림(PC · 휴대폰).
- **칸 길이 · 줄 나눔이 값을 안 따라감**: 3단계 상자 설명의 끊는 자리, 팬 카드 높이.

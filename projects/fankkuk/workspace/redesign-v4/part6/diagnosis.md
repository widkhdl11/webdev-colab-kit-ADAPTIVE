# 6파트 로그인·가입·비밀번호 화면 진단 — 시안 4 기준 (2026-11-01)

비교 페이지: `docs/design/mockups/part6-v4-20261101/index.html` (지금 캡처: `docs/design/mockups/part6-v4-20261101/now/`). 원칙 번호는 `docs/design/design-prompt.md`.
문구·칸 순서·단계 수·노출 조건은 지금 코드 그대로 두고 배치·위계·간격·색·경계만 다뤘다. 코드(`src/`)는 건드리지 않았다.
탭 넷: 로그인(기본·오류) / 비밀번호 찾기·새 비밀번호(여섯 상태) / 가입 1~3단계(다섯 상태) / 가입 4·5단계(크리에이터, 여덟 상태). 모두 PC 1440 · 휴대폰 390.
캡처가 있는 상태(로그인·오류·찾기·링크 죽음·가입 1·2)는 캡처 그대로, 캡처가 없는 상태(3·4·5단계, 비밀번호 입력·결과)는 코드의 CSS 값(`login.module.css`·`signup.module.css`·`verification-panel.module.css`·`signature-link-panel.module.css`·`base.css`·`tokens.css`)으로 같은 틀에 다시 그려 「지금(재현)」으로 놓았다.

6파트는 1차(10-25, 29절)에서 이미 머리 32/24 · 입력칸 48 + 짙은 선 4.8:1 · 젤리 체크 · 단계 알약 · 구분선 묶음을 정해 시안 4와 겹치는 곳이 많다. 그래서 바뀌는 곳이 적다.

## 1. 로그인 `/login`
지금과 어긋나는 곳
- 카드 경계가 안쪽 1px `#E5E7EB`(흰 바탕 1.24:1) + `0 1px 3px` 그림자다. 5·7파트 흰 카드(1px 테두리 + `--card-shadow`)와 모양이 다르다 (4-6, 4-8, 35절)
- 오류 상자가 하늘 면 + 글자뿐이다. 하늘은 「고른 칸」의 색이기도 해서 오류를 색으로만 알리는 모양이 된다 (4-1, 4-2, 4-3)

바꾼 것: 카드 바깥 1px `#DCE3EA` + `--card-shadow`, 오류 상자 앞에 「!」 원(상자 색·글자·자리는 그대로).
바뀌지 않는 것: 머리(제목 32 · 휴대폰 24, 설명 16), 입력칸 48 · 짙은 선, 「로그인 상태 유지」 젤리 체크, 하늘 채움 「로그인」 하나(1-2 이미 맞음), 카드 아래 링크 줄(높이 44), 바탕 흰색.

## 2. 비밀번호 찾기 · 새 비밀번호 `/password/forgot` · `/password/reset`
- 카드 경계: 로그인과 같다 (4-6)
- 링크 죽음 상자: 로그인 오류 상자와 같은 모양에 「!」 원 (4-2)
- 새 비밀번호 칸 아래 틀림 줄이 본문색(`#1F2937`) + 「!」 원이다. 가입 2단계의 틀림 줄은 빨강 `#B42318`(흰 바탕 6.57:1) + 「!」 원이라 같은 「칸 아래 틀림」이 두 색이다 (4-1, 2-4). 가입 쪽은 2026-10-26 사용자 지시(「상태를 색으로도 가른다」)로 빨강이 됐다 — 같은 모양으로 맞춘다
바뀌지 않는 것: 머리·카드 480·칸 순서·버튼 이름, 「로그인으로 돌아가기」 줄, 보낸 뒤 안내 줄(링크 유효 시간 · 1:1 문의), 변경 완료 상자(결과라서 「!」 없이 회색 면 + 1px 선 그대로).

## 3. 가입 1~3단계 `/signup`
- 카드 경계: 로그인과 같다 (4-6)
- **1단계 유형 선택 칸**: 누르는 칸인데 선이 `#E5E7EB`(1.24:1)라 경계가 흐리다. 35절이 칩·탭에 쓴 「짙은 선 3:1」을 안 따랐다 (8-12, 12-2, 4-3). 고르기 전 1px `#6B7280`(4.83:1), 고른 칸은 하늘 면 + 짙은 선 1px → 2px
- **2단계 태그 칩(크리에이터)**: 높이 36 · 경계 없는 옅은 면 → 높이 44 + 짙은 선 1px, 고르면 하늘 면 + 하늘 선 + 굵게. 5파트 찾기 칩과 같다 (8-12, 4-3, 35절). 아이콘은 시안에 그리지 않았다
- **선(보조) 버튼**(인증번호 받기·다시 받기·이전·나중에 하기·로그인): 테두리 `#E5E7EB` → `#6B7280` (35절 짙은 선)
바뀌지 않는 것: 단계 알약 줄(높이 48, 지금·지난 단계 하늘, 번호 칸은 지금만 검정 — 4-3 이미 맞음, 휴대폰은 지금 단계만 이름), 2단계 구분선 + 소제목 16/600(29절), 이메일 한 줄, 약관 줄·「보기」 44, 「이전|다음」 1:2(29절 줄바꿈 5), 칸 아래 틀림 줄(빨강 + 「!」), 칸 안내 14, 3단계 칸 + 버튼 한 줄 · 인증번호 칸 안 시간, 「다음」 하나만 채움(1-2 이미 맞음).

## 4. 가입 4·5단계(크리에이터) `/signup/creator?step=4,5`
- 카드·선 버튼: 위와 같다
- **4단계 채널 주소 칸 높이 52**(공용 `.input`)라 1~3단계·5단계 칸(`.field` 48)과 어긋난다 (2-4, 2-6). 48로 맞춘다
- **4단계 「확인 전」 뱃지**가 회색 면 + 회색 글자다. 상태 표시가 안 눈에 띈다 (4-1). 하늘 면 + `#075985`(6.59:1) + 옅은 하늘 선. 「확인 완료」 초록은 그대로
- **4단계 회색 상자**(채널·인증 코드): 흰 카드 위 `#F9FAFB`(1.05:1)라 경계가 안 보인다 (4-7, 4-8). 1px `#DCE3EA` 테두리를 더한다
- **5단계 실패 상자**: 로그인 오류 상자와 같게 「!」 원 (4-2)
바뀌지 않는 것: 카카오 노랑 「카카오톡 인증 요청」·「확인 기다리는 중」 · 번호 동그라미 두 줄 · 연결 완료 초록 상자, 휴대폰 폭에서 요청 버튼이 위로 올라가는 쌓기(29절 5), 4단계 「나중에 하기 + 다음」 줄, 인증 코드 글자 크기, 단계 알약 줄(1~3단계 완료 체크).

## 승인 기준과 부딪혀 판단한 곳
1. **29절 「색은 하늘 한 색 + 회색」 대 오류 표시**: 10-26 사용자 지시로 가입 칸 안내는 이미 빨강이다. 오류 상자(`.err`)는 사이트 전체 규칙(하늘 면)이라 색은 건드리지 않고 「!」 원만 붙였다 — 아래 정할 것 1.
2. **카드 테두리 `#DCE3EA`는 흰 바탕 1.29:1**: 3:1 에는 못 미친다. design-prompt 4-6 · 35절이 정한 「바탕보다 조금 진한 테두리 + 그림자」 기준을 따랐다(칸 자체가 아니라 묶음 경계). 누르는 칸(유형 선택 칸·칩·선 버튼)에만 짙은 선 3:1 을 썼다.
3. **바탕 흰색**: 36절 신고 화면처럼 흰 바탕을 유지했다. `#F9FAFB` 로 바꾸면 카드가 더 또렷하지만 푸터 띠와 만나는 모양이 바뀐다 — 정할 것 4.
4. **선 버튼은 전역 `.btn--line`** 이라 이 화면 틀 안에서만 바꾸려면 구현 때 범위를 한정해야 한다(5파트처럼 사이트 전체로 퍼질지 정할 것 3).
5. **시안의 한계**: 칩 아이콘·플랫폼 로고는 그리지 않았다. 5단계 「확인 기다리는 중」 노랑은 연한 노랑으로 그렸고(재현), 실제 비활성 색은 구현에서 다시 본다.

## 사용자가 정할 것 (추천 하나씩)
1. **오류 상자에 「!」 원을 붙일까**(로그인 오류·링크 죽음·5단계 실패, 면 색은 지금 하늘 그대로). 추천: 붙인다. 색만으로 알리지 않는 기준이고, 가입 칸 안내와 같은 표시다.
2. **새 비밀번호 칸 아래 틀림 줄을 가입과 같은 빨강으로 맞출까.** 추천: 맞춘다(두 화면이 같은 「칸 아래 틀림」이다).
3. **선(보조) 버튼 테두리를 짙은 선으로 바꾸는 범위**: 이 화면 틀 안만 / 사이트 전체 `.btn--line`. 추천: 이 틀 안만(다른 파트 승인 모양을 건드리지 않음). 확인 11-01: 공용 `.btn--line`(`src/shared/ui/base.css:81`)은 아직 옅은 선이고, 짙은 선은 메인 일부 묶음(`base.css:847`)에만 있다 — 사이트 전체 정리는 BACKLOG 감.
4. **바탕을 흰색 유지 / `#F9FAFB`.** 추천: 흰색 유지(36절 신고와 같음).
5. **4단계 채널 주소 칸 52 → 48.** 추천: 48(같은 가입 흐름 안 모든 칸이 48이 된다). 공용 `.input` 을 바꾸면 채널 설정 등 다른 화면 칸도 바뀌므로 4단계 안에서만 한정한다.
6. **유형 선택 칸·태그 칩의 짙은 선**: 지금 가입의 가벼운 느낌이 조금 무거워진다. 추천: 바꾼다(5파트 칩과 같은 기준). 무거우면 비선택 선만 `#9CA3AF`(2.5:1)로 낮출 수 있으나 3:1 기준 미달이라 권하지 않는다.
7. **가입 카드 폭 720 → 480**(사용자 지적 11-01 「휴대폰 칸이 쓸데없이 길다」 → 「가입 완료 버튼이랑 다른 요소들도」): 원인은 칸 하나가 아니라 카드 폭이다. 가입은 1~5단계 모두 칸이 한 줄에 하나라 720 이 칸·버튼·선택 칸을 늘이기만 했다(아이디 칸 672, 휴대폰 번호 543, 「가입 완료」 506). 로그인·비밀번호(480)와도 달랐다. 시안에 반영: 가입 전 단계 480, 3단계 버튼 셋(인증번호 받기·다시 받기·확인) 폭 120 으로 같게 — 두 줄 칸 끝이 맞고 상태가 바뀌어도 칸 길이가 그대로. 크리에이터 다섯 단계 표시는 480 에 이름 다섯이 안 들어가 휴대폰 모양(지금 단계만 이름)을 PC 에도 쓴다. 근거: 칸 길이는 들어갈 값 길이에 맞춘다(업계 표준 가이드), 한 흐름 안 카드 폭은 하나. **이 항목이 29절 「가입 720」을 바꾼다.** 처음엔 3단계 줄만 440 으로 줄였다가 카드와 아래 버튼이 어긋나 되돌렸다. 480 으로 줄인 뒤 5단계 버튼 셋(이전·나중에 하기·카카오톡 인증 요청)이 한 줄에 안 들어가 카카오 버튼이 카드 밖으로 19 나갔다(사용자 발견 — 페이지 넘침 검사만 돌려 못 잡음) → 카카오 버튼 위 꽉 차게, 아래 「이전 | 나중에 하기」 반씩(PC·휴대폰 같음). 이후 검사에 「카드 밖으로 나간 요소」를 더해 21상태 × 2폭 0.

## 기본 원칙으로 같이 고친 것 (묻지 않고 반영, 11-01 사용자 지시 「분간해서 작업」)
- **비밀번호 찾기 · 보낸 뒤**: 회색 상자 + 상자 밖 두 줄(유효 시간 · 1:1 문의)로 같은 안내가 세 조각이었다 → 한 상자로 묶음(가까운 것이 한 묶음). 문장 그대로. 「일치하면 발송」은 확인된 성공이 아니라 체크 표시는 붙이지 않았다.
- **새 비밀번호 · 변경 완료**: 오류 상자만 「!」 원이 있고 완료 상자는 표시가 없었다 → 체크 원(성공·실패를 같은 규칙으로 구분, 색만으로 알리지 않음).

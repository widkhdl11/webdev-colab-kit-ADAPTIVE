## 한 줄 정의

팬이 크리에이터에게 보내는 선물을 사무실에서 받아 검수한 뒤, 크리에이터 주소를 누구에게도
보여주지 않고 다시 보내 주는 **선물 배송 대행 서비스**.

- 서비스 이름: **팬꾹** (개발 중 가칭, 출시 전 확정. 대안 후보: 팬덕). 코드·폴더 이름은 `fankkuk`.
- 사업자: 기존 개인사업자 네오코드(일반과세자)를 그대로 쓴다.

## ① 목적 / 대상

- **푸는 문제**: 기존 서비스(팬심)는 서버가 주소를 평문으로 볼 수 있었고, 2026-09-18 실명·닉네임
  유출 사고가 났다. 크리에이터가 승인한 선물만, 승인한 건에 한해서만 주소가 열리는 대안을 만든다.
- **사용자 셋**
  - 팬: 선물을 등록하고 요금을 내고 사무실로 보낸 뒤 상태를 확인한다.
  - 크리에이터: 주소를 등록하고 선물을 건별로 승인·거절하며 열람 기록을 본다. 무료.
  - 운영자: 대표 계정 1개 + 직원 계정. 입고·검수·출고를 처리한다. 송장 출력은 대표만.
- **우선순위**: 1. 보안 2. 속도(하루라도 빠른 배송) 3. 상태 확인
- **광고 문구의 한계**: "승인 없이는 저희 시스템이 주소를 열지 않습니다"는 참이고,
  "절대 유출되지 않습니다"는 거짓이다. 문구는 앞의 것만 쓴다.

## 성공 기준

- 크리에이터 승인이 없는 건은 운영자도 주소를 볼 수 없다. DB가 통째로 털려도 암호문만 나간다.
- 주소가 열린 횟수와 승인 횟수가 일치하고, 크리에이터가 그 기록을 전부 볼 수 있다.
- 팬과 크리에이터가 문의하지 않아도 상태 화면만 보고 지금 어디까지 왔는지 안다.
- 승인이 등록 시점에 끝나 있으면 도착 당일 출고된다.

## ② 필수 기능 / 비범위

### 필수 (첫 출시)

- [ ] 회원가입 / 로그인 — 팬·크리에이터 **(스펙 필요: auth)**
  - 가입: 아이디·이메일·비밀번호·휴대폰 번호 + 카카오톡 인증으로 본인 확인
  - 로그인: 아이디 + 비밀번호. 이메일은 비밀번호 재설정용
  - **주소 등록·변경, 차단 해제처럼 주소나 승인에 닿는 동작은 매번 카카오 인증서 서명을 다시 받는다** —
    비밀번호만으로 열리는 범위는 목록·상태 보기로 제한 _(2026-10-01 사용자 결정, 원본의 "비밀번호 로그인 금지"를 대체)_
  - 휴대폰 번호는 알림톡 발송용이며 실명·주소와 같은 격리 보관 대상
- [ ] 크리에이터 본인 확인 — 방송 채널에 인증 코드를 올려 채널 주인임을 확인한다 (가정: 원본 비용표의 "방송 채널 인증 코드로 대체")
- [ ] 크리에이터 주소 등록 — 브라우저에서 암호화해 서버는 암호문만 받는다 **(스펙 필요: auth·secrets — 주소 암호화·복호화 키 격리)**
- [ ] 팬 선물 등록 → 주문번호 발급(예: FC-7K3M9)
  - 상자 수 입력(FC-001-1, FC-001-2로 나뉘고 승인은 하나로 묶음)
  - "전자기기 또는 금속 제품이 들어 있나요?" 신고
  - 그 크리에이터의 평균 승인 시간 표시
- [ ] 결제 — 상자마다 배송비 포함 구간 요금: 소형(세 변 합 100cm·5kg 이하) 6,900원 / 중형(세 변 합 100cm·10kg 이하) 8,900원. 크기·무게 중 큰 쪽 구간. 중형 초과 상자는 받지 않는다. 도착 실측이 신고보다 크면 차액을 따로 결제 요청(7일 미납이면 반송). PG를 처음부터 붙인다 **(스펙 필요: payment)** _(2026-10-01 사용자 결정, 이전 「배송비 실비 + 서비스료 5,000원」을 대체)_
  - 결제 화면: 상자 수 × 구간 요금 줄을 합계 앞에, 금액 옆에 「추적 장치 검수 포함」
  - 상품 대금과 대행 수수료를 결제·영수증·DB에서 분리할 수 있게 둔다(부가세 기준은 세무사 확인 대기)
- [ ] 크리에이터 승인 — 카카오톡 인증서 전자서명, 건별 승인. "전체 승인" 버튼 없음 **(스펙 필요: auth·authz·concurrency — 서명 1건=주문 1건, 같은 서명 재처리 금지)**
  - 승인 모듈은 "요청 생성 → 본인 확인 결과 수신 → 승인 처리" 세 단계, 가운데만 교체 가능
- [ ] 거절 · 팬 차단 — 거절 이유는 팬에게 알리지 않는다. 차단한 팬은 이후 등록 자체가 막힌다
- [ ] 결제 직후 팬에게 사무실 주소 공개 — 승인을 기다리지 않고 바로 보낸다. 승인은 출고 전에만 있으면 된다. 크리에이터가 거절하면(7일 자동 반려 포함) 반송하고 반송 택배비를 뺀 금액을 환불하며, 이 사실을 보내기 전에 공지한다. 팬이 택배 송장번호 입력 _(2026-10-02 사용자 결정, 이전 「승인 후에만 주소 공개」를 대체)_
- [ ] 알림 — 카카오 알림톡(승인 요청·입고·검수·출고·배송중·수령 6종). 본문에 선물 내용·보낸 사람·주소 없음
  - 템플릿 승인 전에는 같은 본문을 이메일로 보내는 대체 경로
- [ ] 상태 화면 — 등록 → 입고 → 검수 → 출고 → 배송중 → 수령 여섯 단계. 크리에이터 승인은 단계가 아니라 검수와 출고 사이에 갈라져 붙는 칸(출고의 조건, 언제 끝나도 된다) _(2026-10-02 사용자)_ 팬·크리에이터가 보는 정보가 다르다
  - 팬에게 운송장 번호는 보여주지 않는다(택배사 조회로 수령지 일부가 보이므로)
- [ ] 운영자 작업 화면 — 스캔 입력 하나로 입고·검수·출고 처리, 서버가 상태 전환표로 허용 여부 판단 **(스펙 필요: concurrency·authz — 상태 전환표)**
  - 내부 QR 라벨 출력(QR 안에는 주문번호만), 미확인 입고 목록
  - 검수 기록(장비·시간·반응·담당자) 건마다 저장
- [ ] 송장 출력(= 주소 복호화) — 대표 계정만, 승인 토큰 + 검수 완료일 때만, 택배사 API 호출 뒤 평문 즉시 폐기 **(스펙 필요: authz·secrets)**
- [ ] 크리에이터 열람 기록 화면 — 언제·어느 주문·누가 출력했는지 전부 공개
- [ ] 자동 처리 — 장기 미승인 재알림(도착 시·3일 후) → 7일 후 자동 반려·반송, 미확인 입고 7일 후 반송 **(스펙 필요: 시변 상태 — 7일 규칙)**
- [ ] 공개 페이지 — 메인 소개, 이용약관, 개인정보처리방침, 하단 사업자 정보(카카오 이용기관 심사 조건)
- [ ] 크리에이터 찾기 — 입력하는 대로 아래에 결과 목록이 바뀌는 실시간 검색. 본인 확인(방송 채널 인증)을 마친 크리에이터만 나온다. 결과에서 크리에이터 페이지(이름·채널·평균 승인 시간·팔로우·선물 보내기)로 _(2026-10-01 사용자 「넣어」)_
- [ ] 팔로우 — 팬이 크리에이터를 팔로우하고, 내 정보에서 팔로우한 크리에이터 목록을 본다 _(2026-10-01 사용자 「넣어」)_
- [ ] 공지사항 · 고객센터(자주 묻는 질문·1:1 문의·운영 시간) _(2026-10-01 사용자 「넣어」)_
- [ ] 헤더 선물 상태 아이콘 — 진행 중인 선물마다 아이콘(승인 대기·이동 중·배송 완료), 마우스 올림·포커스 시 「선물 4개 중 1번째 · 하루님께 · 배송중」, 휴대폰은 배지 하나 → 목록 _(2026-10-01 사용자 「넣어」)_
- [ ] 내 정보 — 개인정보 확인·수정(아이디 변경 불가, 휴대폰 번호 변경은 카카오 인증 재확인), 팔로우 목록, 선물 보낸 내역·진행 중인 선물 상황 _(2026-10-01 사용자 「넣어」)_
- [ ] 크리에이터 메인 — 로그인하면 승인 요청 대신 먼저 나오는 첫 화면. 오늘 승인할 선물·진행 중인 선물·최근 열람 기록·공지·내가 보낸 선물 _(2026-10-03 사용자 「셋 다」, 카드 d15 — 새 화면이라 시안 먼저)_
- [ ] 크리에이터도 선물 보내기(다른 크리에이터에게) — 팬과 같은 흐름. 자기 자신에게는 못 보내고, 둘 사이에 팔로우가 한쪽이라도 있어야 보낸다(그래서 크리에이터도 다른 크리에이터를 팔로우할 수 있다) **(스펙 변경: session-login INV-L3·L8·L9, 카드 d16 승인)** _(2026-10-03 사용자 「셋 다」 카드 d15 · 팔로우 조건은 같은 날 사용자 지시)_
- [ ] 관리자 화면 — 요금 수정(소형·중형·대형·검수비·택배 원가, 대표만, 새 주문부터, 바꾼 기록) · 들어온 상자 목록과 입고·검수·출고 · 보낼 수 없는 물품 목록 · 역조공 처리 · 크리에이터 본인 확인 승인 · 공지사항 작성 · 환불·결제 내역 · 미확인 입고 · 자동 처리 현황 · 1:1 문의 답변 **(스펙 필요: authz·payment·concurrency)** _(2026-10-03 사용자 · 카드 d20)_
- [ ] 대형 상자 — 세 변 합 160cm·20kg 이하, 10,900원(역조공 8,400). 대형 초과는 받지 않는다 _(2026-10-03 사용자, d8 의 「중형 초과는 받지 않는다」를 대체)_
- [ ] 역조공 — 크리에이터가 자기 팬에게 보내는 선물. 선물 보내기와 **따로 나눈 기능**이다(이름·입구·목록이 따로). 요금은 팬 선물에서 검수비를 뺀 소형 5,400 · 중형 6,900원(추적 장치 검사 없이 겉면·금지 물품만 확인) _(2026-10-03 사용자)_. 방향이 거꾸로라 팬 주소 등록·암호화·팬 승인·열람 기록을 팬 쪽에 새로 두고 개인정보처리방침 문구가 바뀐다 **(스펙 필요: auth·authz — 팬 주소 보호)** _(2026-10-03 사용자 「셋 다」 카드 d15 · 「역조공으로 나누고 싶어」)_

## ④ 기술 결정 (프리셋: TypeScript + FSD — 하네스 전제)

- 프레임워크: **Next.js(App Router) + FSD** — 확정 2026-10-01. SEO는 중요하지 않고, 화면 이동은 첫 화면 뒤 브라우저 안에서 바뀌게 한다(signal과 같은 구성)
- 데이터: **Supabase** — 실명·주소·연락처는 API로 노출되지 않는 별도 스키마에 둔다. 새 테이블 RLS 강제, 공개 스토리지 금지
- 비밀 저장: 복호화 키는 앱 서버·DB와 분리된 곳(클라우드 KMS 또는 Supabase Vault 같은 별도 비밀 저장소)
- 배포: **Vercel** + 카카오 인증 API 호출만 고정 IP 경로(소형 VM 또는 고정 IP 프록시)로 보낸다
- 배포 전 검사: 익명·일반 사용자 권한으로 공개 엔드포인트를 호출해 실명·주소·전화번호가 나오면 배포 실패
- 주소 스키마를 건드리는 마이그레이션은 사람이 직접 적용한다

## 모델링 플래그 (얕게 훑기 2026-10-01)

- 🔴 **주문 상태 = 시변 상태 + 전환 규칙**. 상태 전환표가 원본에 있다 → 스펙에서 불변식으로 고정 (concurrency)
- 🔴 **승인 토큰 ↔ 복호화 횟수 대조**. 승인 1건당 복호화 1회. 파생 지표(평균 승인 시간)는 저장하지 않고 계산 → 스펙
- 🔴 **7일 규칙**(자동 반려·미확인 입고 반송)은 기준 시각과 시간대(Asia/Seoul)를 정해야 한다 → 스펙
- 🔴 **반송용 팬 주소**: 원 송장 주소로만 반송하고 반송 후 폐기 — 팬 주소도 개인정보로 같은 격리를 받는지 → 스펙
- 🟡 **주문 ↔ 상자 1:N**: 승인은 주문 단위, 입고·검수·송장은 상자 단위
- 🟡 **크리에이터 ↔ 팬 차단 목록**: 차단 해제 시 과거 거절 건의 처리
- 🟡 **삭제·탈퇴 시 기록 보존**: 열람 기록·검수 기록은 크리에이터 탈퇴 뒤에도 남기는지

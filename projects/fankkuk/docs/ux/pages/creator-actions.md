# 크리에이터 처리할 일 — 승인 요청 창 (서명 기다림)

승인 요청 창은 처리할 일(`/creator/actions`)의 승인 요청 줄이 연다. 알림톡의 [승인 화면 열기]는 `/creator/actions?order=<주문번호>` 로 와서
그 주문의 창을 바로 연다(로그인 전이면 로그인 뒤 같은 주소로 돌아온다. 그 주문이 이 크리에이터의 기다리는 요청이 아니면 창을 열지 않고 목록만 보인다 — notifications INV-N9).
시각은 지금 창(시안 v21-addendum3 `dlg-d`)과 design-rules 그대로다. 바뀌는 것은 「승인」 뒤의 상태뿐이다.

## 페이지 브리프

- 목적: 이 문서는 처리할 일 화면 중 **승인 요청 창**의 서명 단계만 다룬다(나머지 줄은 지금 그대로).
- 주 사용자: 크리에이터(휴대폰, 알림톡을 받고 들어옴) / 부 사용자: 없음
- 하려는 일: 선물을 받을지 정하고, 받으면 카카오톡 서명으로 승인을 마친다
- 방문 빈도: 선물마다 한 번
- 유형: 작업형
- 같은 유형: 가입 5단계 「승인 서명 연결하기」(시험 서명 기다림이 같은 모양)
- 특이점: 승인은 다른 앱(카카오톡)에서 끝나고, 이 화면은 그 결과를 기다린다
- 바꾸면 안 되는 것: 받는 주소 단계(INV-S13), 받지 않기 확인·차단 고르기(decline-block)

## 스펙 참조

approval-signature INV-S1·S13·S17, notifications INV-N1·N9

## 상태표

| 상태 | 언제 | 보이는 것 | 할 수 있는 것 | 다음 |
|---|---|---|---|---|
| `ask` / 고르기 | 창을 엶 | 보낸 사람 닉네임 · 선물 종류·개수 · 주문번호 · 자동 반려 기한 · 「거절」 · 「승인」 | 거절 · 승인 | 승인 → 주소 단계(INV-S13) 또는 `waiting` / 거절 → 받지 않기 확인 |
| `address` / 배송지 | 「승인」을 눌렀고 받는 주소 확인이 필요함 | 지금 주소 단계 그대로(등록·확인) · 「승인 요청 보내기」 | 주소 입력·확인 · 요청 보내기 | `waiting` |
| `waiting` / 서명 기다림 | 서버가 서명 요청을 만들었다(approval-signature INV-S17) | 「카카오톡에서 인증을 마쳐 주세요」 · 남은 시간(5:00부터) · 진행 표시 | 창 닫기(요청은 그대로 기다림 — 다시 열면 `waiting` 으로 이어짐) | 서명 확인 → `approved` / 기한 지남·실패 → `ended` |
| `approved` / 승인됨 | 서버가 승인을 저장함 | 체크 + 「승인됨」 · 「승인 내역 보기」 | 내역 보기 · 닫기 | — |
| `ended` / 다시 요청 | 5분 안에 서명이 없거나, 거부·실패함 | 「인증 시간이 지났습니다.」(실패면 「인증을 완료하지 못했습니다.」) · 「다시 요청」 | 다시 요청 | `waiting` / 하루 5번 넘으면 오류 줄 |
| `error` | 요청 만들기 실패(창구 없음·한도·기한 지난 주문) | 창 아래 빨간 줄(서버가 준 문구) | 닫기 · (한도가 아니면) 다시 요청 | — |

- 화면은 3초마다 서버에 결과를 묻는다. 서버가 「승인됨」을 답한 뒤에만 `approved` 로 바뀐다 — 화면이 스스로 바꾸지 않는다.
- `waiting` 중에 창을 닫았다 열거나 새로고침하면 서버가 기다리는 요청을 돌려주고 남은 시간부터 이어 센다.
- 로컬·시험 사이트(가짜 창구)는 첫 확인에서 바로 서명돼 `waiting` 이 잠깐 보였다가 `approved` 가 된다.

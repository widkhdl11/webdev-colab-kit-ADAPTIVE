# 이용약관 UX 명세 — `/terms`

> 2026-10-23 문서형 페이지 1단계. **지금 구현된 그대로**를 적었다(코드 수정 없음). 바꿀 것은 `_diff-policy.md` 에 따로 있다.
> 그리는 코드: `src/app/(site)/terms/page.tsx` → `src/widgets/legal/ui/policy-page.tsx`(+ `policy-toc.tsx`, `policy-page.module.css`), 글은 `src/widgets/legal/model/terms-doc.ts`, 버전은 `legal-versions.ts`.
> 실측: 2026-10-23 next dev, 1440(로그인 전)·1280(크리에이터 로그인, 사이드바)·390.

## 페이지 브리프

1. 목적: 팬꾹을 쓰는 약속(요금·환불·검수·금지 행위·책임)을 로그인 없이 한 주소에서 확인한다. 가입 때 동의하는 글의 원문이다.
2. 주 사용자 / 부 사용자: 팬·크리에이터 / 가입 전 방문자, 결제대행사 심사 담당자
3. 사용자가 와서 하려는 일: 거절·환불·금지 물품·요금 중 내 상황에 맞는 조 하나를 찾아 읽는다. 크리에이터는 본인 확인(제6조)·주소 보호(제15조)·역조공(제12조)을 찾는다.
4. 방문 빈도: 가입할 때 한 번, 문제가 생겼을 때(거절·반송·환불) 한 번
5. 페이지 유형: 문서형 — 읽기만 하고 입력이 없다
6. 같은 유형의 다른 페이지: 개인정보처리방침·취소·환불 규정(같은 틀), 이용 안내 두 글·검수 기준·보안 안내·분쟁 처리 안내·요금 안내(안내 글 틀), 자주 묻는 질문
7. 이 페이지만의 특이점: 조가 19개(제1조~제18조 + 부칙)로 세 글 중 가장 길다(1440 높이 13,565). 목차 묶음 다섯 개가 데이터에 있다(`terms-doc.ts:30-36`). 요금 숫자는 결제와 같은 DB 요금표에서 읽는다(`page.tsx:22`).
8. 바꾸면 안 되는 것: 글 내용(`terms-doc.ts` 문장)·버전 기록·요약 세 줄·고객센터 안내, 세 글 탭 순서, 조 번호와 `id`(가입 화면·다른 글이 가리킨다)

# 신고·문의 UX 명세 — `/report`

> 2026-10-23 문서형 페이지 정돈 1단계. 코드를 읽고 **지금 구현된 그대로** 적었다. 바꿀 것은 `docs/ux/pages/_diff-faq-report.md` 에 따로 있다.
> design-rules 28절(2026-10-22 승인 — 요약 판 없앰, 「이메일 앱이 열려요」 줄을 버튼 위로, 양식 680 한 기둥)은 아직 코드에 들어가지 않았다.

## 페이지 브리프

1. 목적: 팬꾹을 사칭하는 페이지나 허락 없이 쓰인 사진을 로그인 없이 신고하고, 그 밖의 문의도 보낸다.
2. 주 사용자 / 부 사용자: 가입하지 않은 사람(사칭 페이지를 본 사람·사진 권리자) / 팬·크리에이터 회원(회원은 고객센터 1:1 문의도 쓸 수 있다 — `report-form.tsx:134`)
3. 사용자가 와서 하려는 일: 분류를 고르고 답장받을 이메일·주소·내용을 적어 고객센터 이메일로 보낸다
4. 방문 빈도: 드묾 — 사칭 페이지나 사진 도용을 봤을 때 한 번
5. 페이지 유형: **작업형(주)·문서형(부)** — 화면의 주인은 칸 넷짜리 입력 양식이고(`report-form.tsx:52-136`), 글은 요약 세 줄뿐이다. 조·목차가 없고(실측 h2=1, anchors=0) 찾아 읽을 섹션이 없다
6. 같은 유형의 다른 페이지: 고객센터 1:1 문의 양식(`/support` — 같은 칸 모양, `report-form.tsx:8`). 문서형으로는 머리·요약 판을 안내 글과 같이 쓴다
7. 이 페이지만의 특이점: 서버에 저장하지 않는다. 「이메일로 보내기」는 적은 내용을 담은 `mailto:` 주소로 이동할 뿐이라(`report-mail.ts:52`, `report-form.tsx:48`) 이메일 앱이 실제로 열렸는지 화면은 알 수 없다. 파일은 첨부할 수 없다
8. 바꾸면 안 되는 것: 분류 세 가지와 이름(`report-mail.ts:6-14`), 내용 1,000자 한도(`report-mail.ts:17`), 「주소를 묻지 않아요」 문장(`NO_ADDRESS_ASK`, `site-copy.ts:29`), 받는 이메일 줄을 늘 보여 주는 것(`report-form.tsx:9`·`:133-135`)

## 상태표

`docs/ux/states.md` 는 시범 세 화면만 다뤄 이 화면의 상태 이름이 없다. 화면 안 상태는 `ReportForm` 의 `error`·`opened` 두 값(`report-form.tsx:27-28`)이 정한다. 이름은 모두 「(제안)」이다.

| 상태(코드 식별자 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `signed_out`(제안) / 로그인 전 | 쿠키 없음 | 상단 바 · 머리 · 요약 판 · 양식 카드 · 바닥글. 머리·판은 x272, 양식 카드는 640 가운데(1440 에서 x392) | 아래 양식 동작 전부 | — |
| `signed_in`(제안) / 로그인 후 | 팬·크리에이터 로그인 | 사이드바 + 같은 화면. 양식·문구는 로그인 전과 같다(1:1 문의 안내도 그대로) | 같음 | — |
| `idle`(제안) / 입력 전 | 처음 열었을 때, 또는 칸을 고친 뒤(`edit` 가 `error`·`opened` 를 모두 지움 — `report-form.tsx:30-34`) | 분류(「분류를 골라 주세요」) · 답장받을 이메일 · 페이지 주소(선택, 안내 한 줄) · 내용(안내 한 줄) · 「이메일로 보내기」(폭 꽉) · 받는 이메일 줄 | 칸 채우기, 보내기 | 보내기 → `field_error` / `config_error` / `opened` |
| `field_error`(제안) / 칸 오류 | 보내기를 눌렀는데 칸 검사에서 걸림. **첫 번째로 걸린 칸 하나만** 알린다(`report-mail.ts:40`) — 분류 안 고름 · 이메일 형식 틀림 · 주소가 http(s) 아님 · 내용 비었거나 1,000자 넘음(`report-mail.ts:23-32`) | 그 칸에 `aria-invalid`, 초점이 그 칸으로 감(`report-form.tsx:43`). 오류 문장은 칸 아래가 아니라 **버튼 바로 위 한 곳**(`report-form.tsx:122-128`, 「!」 동그라미) | 칸 고치기 | 칸을 고치면 오류가 사라짐 → `idle` |
| `config_error`(제안) / 받는 이메일 없음 | 칸은 모두 맞는데 고객센터 이메일 설정값이 비었거나 형식이 아님(`report-mail.ts:46`). 지금 설정값은 `support@fankkuk.com`(`site-info.ts:35`)이라 실제로는 나오지 않는다 | 버튼 위 오류 문장 「고객센터 이메일이 아직 없어요. 로그인했다면 고객센터의 1:1 문의를 써 주세요.」, 받는 이메일 줄은 「(출시 전 기재)」 | 없음(1:1 문의 링크) | — |
| `opened`(제안) / 이메일 앱 열림 | 검사를 모두 통과 | 버튼 위 브랜드색 문장 「이메일 앱을 열었어요. 열리지 않으면 {받는 이메일}로 보내 주세요.」(`report-form.tsx:129`), 브라우저가 `mailto:` 로 이동 | 다시 보내기, 칸 고치기 | 칸을 고치면 문장이 사라짐 → `idle` |

# 개인정보처리방침 UX 명세 — `/privacy`

> 2026-10-23 문서형 페이지 1단계. **지금 구현된 그대로**를 적었다(코드 수정 없음). 바꿀 것은 `_diff-policy.md` 에 따로 있다.
> 그리는 코드: `src/app/(site)/privacy/page.tsx` → `src/widgets/legal/ui/policy-page.tsx`(+ `policy-toc.tsx`, `policy-page.module.css`), 글은 `src/widgets/legal/model/privacy-doc.ts`, 버전은 `legal-versions.ts`.
> 화면 틀은 이용약관과 같다 — 같은 내용은 `terms.md` 와 같은 문장으로 적고 다른 점만 따로 적었다.

## 페이지 브리프

1. 목적: 팬꾹이 받는 개인정보와 쓰는 목적·보관 기간·맡기는 곳·내 권리를 로그인 없이 확인한다. 가입 때 동의하는 글의 원문이다.
2. 주 사용자 / 부 사용자: 팬·크리에이터 / 가입 전 방문자, 결제대행사 심사 담당자
3. 사용자가 와서 하려는 일: 내 정보 중 무엇을 받는지(1절) 찾는다, 얼마나 보관하는지(2절) 본다, 지우거나 열람을 요청하는 방법(9절)을 찾는다. 크리에이터는 주소가 언제 열리는지(7·8절)를 찾는다.
4. 방문 빈도: 가입할 때 한 번, 탈퇴·삭제를 생각할 때 한 번
5. 페이지 유형: 문서형 — 읽기만 하고 입력이 없다
6. 같은 유형의 다른 페이지: 이용약관·취소·환불 규정(같은 틀), 보안 안내(주소 보호를 쉬운 말로), 안내 글 다섯·요금 안내·자주 묻는 질문
7. 이 페이지만의 특이점: 절 번호가 「제N조」가 아니라 「N.」이라 조 꼬리표가 없다(`policy-page.tsx:20-23`). 목차 묶음이 없다(`privacy-doc.ts` 에 `tocGroups` 없음). 1절 「받는 개인정보」 상자가 13줄로 세 글 중 가장 큰 덩어리다(1440 에서 2070). 요금표를 읽지 않는다.
8. 바꾸면 안 되는 것: 글 내용(`privacy-doc.ts` 문장)·버전 기록·요약 세 줄·고객센터 안내, 세 글 탭 순서, 절 `id`

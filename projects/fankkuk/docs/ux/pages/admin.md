# 관리자 대시보드 UX 명세 — `/admin`

> 2026-10-28 처음 만든다. 메뉴의 「대시보드」와 로고가 `/admin` 을 가리키는데 화면이 없어 404 였다(BACKLOG 「승인 시안에 있는데 기록 없이 빠진 것」 ①,
> 만들기로 한 결정은 DECISIONS 2026-10-18 「이번에 만드는 것」). 시각 기준은 승인된 시안 `docs/design/mockups/site/v4/admin/index.html` 이다(design-rules 8절).
> 시안의 세부(무엇을 몇 개 보여 줄지)는 「나중에 실제 화면으로 다시 묻는다」로 남아 있었다(BACKLOG 「관리자 대시보드 세부 조정」) — 이 명세가 첫 판을 정한다.
> UX 기준 문서 중 `principles.md`·`admin-pages.md` 가 아직 없다. 상태 이름은 「제안」이다.

## 페이지 브리프

- 목적: 지금 처리할 일이 몇 건인지 한 화면에서 보고, 그 화면으로 간다
- 주 사용자: 대표 / 부 사용자: 직원
- 와서 하려는 일: 출근해서 또는 작업 사이에 밀린 일을 확인하고 해당 작업 화면으로 이동한다
- 방문 빈도: 하루 여러 번(관리자 화면의 첫 화면)
- 페이지 유형: 관리형(주)
- 같은 유형의 다른 페이지: 자동 처리 현황, 들어온 상자
- 이 페이지만의 특이점: 스스로 바꾸는 것이 없다 — 숫자와 링크만 있다
- 바꾸면 안 되는 것: 운영자가 아니면 404(admin-console INV-K1 S1c) · 상자 상태를 바꾸는 버튼이 없다(design-rules 8절, office-workflow INV-W1) · 사람 정보(주소·전화·사진) 칸이 없다

## 첫 판에 넣는 숫자 칸 — 지금 있는 DB 함수의 목록을 센다

| 칸 | 세는 것 | 출처(이미 있는 운영자 전용 함수) | 누르면 |
|---|---|---|---|
| 입고 대기 | 「들어온 상자」의 입고 대기 탭과 같은 상자(`no_waybill`·`awaiting`) | admin_office_parcels | 입고 `/admin/work/inbound` |
| 검수 대기 | 검수 대기 탭과 같은 상자(`received`·`labeled`·`held` — 크리에이터 확인 대기 포함) | admin_office_parcels | 검수 `/admin/work/inspect` |
| 출고 대기 | 출고 대기 탭과 같은 상자(`inspected`·`label_printed`) | admin_office_parcels | 출고 `/admin/work/outbound` |
| 보류 상자 | 주문을 못 찾은 상자(출고를 멈춘 상자는 뺀다) | admin_unmatched_parcels | 보류 상자 `/admin/unmatched` |
| 답 안 한 문의 | 답하지 않은 문의 + 가장 오래된 것의 날짜 | admin_inquiries | 1:1 문의 `/admin/inquiries` |
| 환불 대기 | 환불 상태 `due`·`failed` | admin_payment_rows | 결제·환불 `/admin/payments` |
| 역조공 기한 임박 | 받기 대기이고 기한이 48시간 안 | admin_revgift_shares | 역조공 처리 `/admin/revgifts` |
| 자동 처리 대기 | 기한이 지나 자동 처리를 기다리는 건(종류별 합) | admin_expiry_due | 자동 처리 현황 `/admin/automation` |

- 목록 함수 여섯은 모두 한 번에 500건까지 준다(최신순). 500건이 오면 목록이 잘렸을 수 있어, 그 목록으로 세는 칸은 센 숫자 뒤에 「+」를 붙인다(「3+건」 = 적어도 3건) — 잘린 숫자를 정확한 숫자처럼 쓰지 않는다. (2026-10-28 리뷰: 처음 문장 「500+로 적는다」는 칸마다 숫자가 다른데 전부 500+ 로 읽혀 고쳤고, 상자 목록만이 아니라 여섯 목록 모두 한도가 있어 넓혔다)
- 상자 목록은 출고·반송까지 끝난 상자도 포함해 최신 500건이라, 쌓인 상자가 500개를 넘으면 세 칸이 늘 「+」가 되고 오래된 입고 대기가 빠질 수 있다 — 그때 상태별로 세는 함수를 만든다(BACKLOG 「관리자 대시보드 둘째 판」)
- 숫자는 화면을 연 때의 값이다. 저절로 바뀌지 않는다(새로 열면 바뀐다).

## 첫 판에서 빼는 것 — 새 DB 함수가 있어야 해서 (BACKLOG 로)

- 오늘 입고 처리 · 어제 대비: 하루 단위로 세는 함수가 없다(지금 함수는 30일 묶음)
- 자동 처리의 「다음 자동 실행」·「마지막 결과」: 실행 이력을 돌려주는 함수가 없다
- 「방금 있었던 일」 최근 활동: 운영자 활동을 한데 모은 기록이 없다(기록 표가 기능마다 흩어져 있다)

## 상태표

| 상태 (코드 · 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `not_operator` · 404 | 운영자가 아님(손님 포함) | 404 화면 | — | — |
| `loaded` · (표기 없음) | 숫자를 다 읽음 | 제목·날짜·숫자 칸 8개 | 칸을 눌러 해당 화면으로 | — |
| `partial` · 「불러오지 못했습니다」 (제안) | 숫자 칸 일부의 함수가 실패 | 실패한 칸만 숫자 대신 「—」와 「불러오지 못했습니다」(설명 줄은 숨김), 나머지는 그대로 | 칸을 눌러 해당 화면으로(그 화면이 다시 읽는다) | — |

- 0건인 칸도 숫자 0 으로 보여 준다(숨기지 않는다 — 칸 자리가 매번 같아야 찾기 쉽다).
- 대표·직원 화면은 같다. 대표만 하는 동작이 이 화면에는 없다.

## 적용한 규칙

- 시안의 칸 중 지금 DB 로 셀 수 없는 셋(오늘 입고·자동 처리 이력·최근 활동)은 첫 판에서 뺐다 — 근거 없는 숫자를 보이지 않는다.
- 시안의 「미확인 입고」는 메뉴 이름에 맞춰 「보류 상자」로 쓴다(지금 메뉴 표기).
- 예외 경로 요소(「불러오지 못했습니다」)는 기본 상태에 없다.

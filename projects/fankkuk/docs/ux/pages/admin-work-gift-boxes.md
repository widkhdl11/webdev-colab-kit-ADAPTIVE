# 선물함 입고·실측 UX 명세 — `/admin/work/gift-boxes`

근거: 선물함 흐름 명세 `creator-revgifts-new.md`(사무실 — 큰 상자 입고·나눠 실측·닉네임 보류), 스펙 `revgift-box.md` INV-GB10·GB12·GB13·GB16.
2026-11-09 선물함 3부 구현 때 새로 적었다. 사용자 승인 전이다 — 승인되면 approved.

## 페이지 브리프

1. 목적: 선물함 6자리로 온 큰 상자를 받고, 안의 선물마다 팬을 찾아 실측한다
2. 주 사용자 / 부 사용자: 사무실 운영자(대표·직원) / 없음
3. 사용자가 와서 하려는 일: 큰 상자를 받으면 입고하고, 상자를 열어 선물마다 바코드를 스캔(또는 손글씨 닉네임 입력)하고 세 변 합·무게를 적는다
4. 방문 빈도: 큰 상자가 올 때마다
5. 페이지 유형: 작업형
6. 같은 유형의 다른 페이지: 입고(`/admin/work/inbound`) · 검수(`/admin/work/inspect`)
7. 이 페이지만의 특이점: 구간을 고르는 칸이 없다 — 세 변 합·무게를 적으면 서버가 구간을 정한다. 맞지 않는 선물은 기록하되 「확인 필요」로 남고 크리에이터가 팬을 고른다
8. 바꾸면 안 되는 것: 상태를 고르는 칸이 없다(INV-GB1) · 금액은 착불 택배비와 개인접수 실비만 넣는다(범위는 서버가 다시 본다)

## 상태표

| 상태(코드 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `idle`(제안) / 처음 | 화면을 엶 | 「큰 상자 입고」 칸(6자리 · 원 송장번호 · 착불 택배비 · 선반 · 입고) · 「선물 실측」 칸(6자리 · 불러오기) | 입고 · 불러오기 | `received`·`held`·`unknown` · `loaded` |
| `received`(제안) / 입고함 | 유효한 6자리 | 결과 한 줄 「{선물함} · 입고했어요.」 | 다음 상자 입고 | — |
| `held`(제안) / 보류 | 무효가 된 6자리(취소·명세서·반송) | 「이미 끝났거나 취소한 선물함이라 보류로 넣었어요. 보류 상자 화면에서 확인해 주세요.」 | — | — |
| `unknown`(제안) / 선물함 아님 | 선물함 6자리가 아님 | 「선물함 6자리가 아니에요. 일반 입고 화면에서 받아 주세요.」 | — | — |
| `loaded`(제안) / 불러옴 | 유효한 6자리 | 선물함 이름 · 상태 · 도착한 상자/보낸 상자 · 확인 필요 수 · 담길 팬 표(닉네임 · 신청 번호 · 실측 구간) · 찾기(바코드/손글씨 닉네임) · 세 변 합 · 무게 · 우체국 실비 · 실측 기록 | 실측 기록 | `measured` · `hold` |
| `measured`(제안) / 기록함 | 바코드·닉네임이 담길 팬과 맞음 | 「{닉네임} · {구간}로 기록했어요.」, 표가 새로 읽힌다 | 다음 선물 | `loaded` |
| `hold`(제안) / 확인 필요 | 맞는 팬이 없음 | 「맞는 신청이 없어 확인 필요로 두었어요({구간}). 크리에이터가 팬을 고르면 이어져요.」 | 다음 선물 | `loaded` |

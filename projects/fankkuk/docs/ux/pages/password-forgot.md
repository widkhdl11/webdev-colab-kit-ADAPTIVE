# 비밀번호 찾기 UX 명세 — `/password/forgot`

## 페이지 브리프

1. 목적: 비밀번호를 잊은 사람이 아이디와 가입 이메일을 넣어 재설정 메일을 받게 한다.
2. 주 사용자 / 부 사용자: 로그인하지 못한 팬·크리에이터 / 새 비밀번호 화면에서 링크가 죽어 다시 온 사람
3. 사용자가 와서 하려는 일: 아이디·가입 이메일을 넣고 「재설정 링크 보내기」 → 메일함에서 링크를 연다
4. 방문 빈도: 드물게 — 비밀번호를 잊었을 때
5. 페이지 유형: 작업형
6. 같은 유형의 다른 페이지: `/login`(같은 틀 — 머리 카드 밖, 카드 480) · `/password/reset`(다음 화면)
7. 이 페이지만의 특이점: 응답은 계정이 있든 없든, 이메일이 다르든, 한도를 넘었든 늘 같은 문장이다(INV-L10). 그래서 「계정이 없어요」 같은 상태가 없다
8. 바꾸면 안 되는 것: 늘 같은 응답 문장, 1시간·한 번만 안내, 메일이 안 올 때 「1:1 문의」 링크(`/support`), 아래 「로그인으로 돌아가기」

## 상태표

| 상태(코드 식별자 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `request_idle`(제안) / 처음 | 화면을 엶 | 카드 밖 머리(제목 「비밀번호 찾기」·설명 「아이디와 가입할 때 적은 이메일을 넣으면…」) · 카드(아이디 칸 · 가입 이메일 칸 · 「재설정 링크 보내기」 — 이 화면의 채운 버튼 하나) · 카드 밖 아래 「로그인으로 돌아가기」 | 칸 입력 · 보내기 · 로그인으로 | `request_sending` |
| `request_sending`(제안) / 보내는 중 | 보내기 누름 | 위와 같고 버튼 글자 「보내는 중」(`aria-busy`·`aria-disabled`) | — | `request_answered` 또는 `request_error` |
| `request_error`(제안) / 빨간 상자 | 빈 칸 400 「아이디와 이메일을 입력해 주세요.」 · 연결 실패 「잠시 문제가 생겼어요. 조금 뒤 다시 해 주세요.」 | 처음 요소 + 버튼 위 상자(`role=status`, 문장마다 줄) | 다시 입력 · 다시 보내기 | `request_sending` |
| `request_answered`(제안) / 메일 보냄 안내 | 그 밖의 모든 경우(계정 없음·이메일 다름·한도 넘음·실제 보냄 — INV-L10) | 처음 요소 + 버튼 위 초록 상자 「입력한 정보가 맞으면 메일을 보냈어요.」 + 그 아래 「링크는 1시간 동안 한 번만 쓸 수 있어요.」 / 「메일이 오지 않으면 1:1 문의로 알려 주세요.」(두 문장 줄 나눔, 「1:1 문의」는 링크·안 쪼갬) | 1:1 문의로 · 다시 보내기 · 로그인으로 | 메일 링크 → `/password/reset` · 다시 보내기 → `request_sending` |

## 적용한 규칙

- 29절 비밀번호 찾기 줄 그대로(로그인과 같은 틀). 줄바꿈은 29절 줄바꿈 1~4(「비밀번호 재설정 링크」·「1:1 문의」 안 쪼갬, 짧은 여러 문장 안내는 문장마다 줄).
- 로그인 화면의 접는 재설정 칸(`login.md` `reset_open`)은 없어지고 「비밀번호를 잊으셨나요?」 링크가 이리로 온다.

# 비밀번호 찾기 UX 명세 — `/password/forgot`

## 페이지 브리프

1. 목적: 비밀번호를 잊은 팬·크리에이터가 가입한 휴대폰 번호로 받은 인증번호를 맞히고 새 비밀번호를 정하게 한다.
2. 주 사용자 / 부 사용자: 로그인하지 못한 팬·크리에이터 / 인증번호를 못 받아 번호를 다시 확인하는 사람
3. 사용자가 와서 하려는 일: 번호 입력 → 「인증번호 받기」 → 인증번호 입력 → 새 비밀번호 두 번 → 「비밀번호 바꾸기」 → 로그인
4. 방문 빈도: 드물게 — 비밀번호를 잊었을 때
5. 페이지 유형: 작업형
6. 같은 유형의 다른 페이지: `/login`(같은 틀 — 머리 카드 밖, 카드 480) · `/signup` 3단계(같은 인증번호 칸)
7. 이 페이지만의 특이점: 번호로 가입한 계정이 있든 없든 받기 응답은 같은 문장이다(INV-L10) — 「가입되지 않은 번호」 상태가 없다. 인증번호가 틀린 것과 그 번호로 보낸 인증번호가 없는 것도 같은 문장이다
8. 바꾸면 안 되는 것: 늘 같은 받기 문장, 아래 「로그인으로 돌아가기」, 바꾼 뒤 모든 기기 로그아웃(INV-L11), 메일이 오지 않을 때가 아니라 **인증번호를 못 받을 때** 고객센터 이메일(`mailto:`) 안내 — 1:1 문의는 로그인이 필요해 쓰지 않는다(2026-11-05)

## 적용한 규칙

- design-rules 29절 비밀번호 찾기 틀(로그인과 같은 틀) 그대로. 인증번호 칸은 가입 3단계와 같은 컴포넌트·같은 문구 — 같은 동작에 다른 문장을 쓰지 않는다.
- 단계마다 채운 버튼 하나. 지난 단계의 칸은 다음 단계에서 지운다(번호·인증번호가 새 비밀번호 화면에 남지 않게).

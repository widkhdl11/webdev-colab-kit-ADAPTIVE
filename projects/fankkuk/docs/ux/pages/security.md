# 보안 안내 UX 명세 — `/security`

> 2026-10-23 문서형 페이지 1단계. 코드를 읽고 **지금 구현된 그대로** 적었다. 고칠 점은 `_diff-guide.md` 에 따로 있다.
> 그리는 코드: `src/app/(site)/security/page.tsx` → `src/widgets/legal/ui/legal-page.tsx` · 글 `src/widgets/legal/model/security-doc.ts`(`SECURITY_DOC`·`SECURITY_FLOW`).

## 페이지 브리프

1. 목적: 크리에이터 주소가 언제·누구에게 열리는지와 그 기록을 어디서 보는지 한 주소에서 확인한다.
2. 주 사용자 / 부 사용자: 크리에이터(가입 전 포함) / 팬(역조공을 받을 때의 내 주소)
3. 사용자가 와서 하려는 일: 내 주소가 어디까지 노출되는지 본다, 열린 기록을 어디서 보는지 찾는다.
4. 방문 빈도: 가입을 고민할 때 한 번
5. 페이지 유형: 문서형 — 읽기만 하고 입력이 없다
6. 같은 유형의 다른 페이지: 이용 안내 두 글·검수 기준·분쟁 처리 안내·요금 안내(같은 틀), 약관 세 글, 자주 묻는 질문
7. 이 페이지만의 특이점: 안내 글 중 유일하게 흐름 그림 네 칸(「크리에이터 주소가 열리는 때」)이 요약 아래에 있다(`page.tsx:19`, `legal-page.tsx:113~130`). DB 를 읽지 않아 오류 상태가 없다.
8. 바꾸면 안 되는 것: 글 내용, 요약 세 줄, 흐름 그림 네 칸의 문장, 약속 문장(`PROMISE.address`)

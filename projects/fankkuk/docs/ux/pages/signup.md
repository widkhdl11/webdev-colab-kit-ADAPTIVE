## 페이지 브리프

1. 목적: 팬 또는 크리에이터 계정을 만든다 — 카카오톡 본인 확인을 거친 휴대폰 번호 하나에 계정 하나(INV-U1·U3)
2. 주 사용자 / 부 사용자: 처음 온 팬 / 처음 온 크리에이터
3. 사용자가 와서 하려는 일: 유형을 고르고 → 정보를 채우고 → 카카오톡으로 본인 확인해 가입을 끝낸다
4. 방문 빈도: 한 번
5. 페이지 유형: 작업형(단계 입력) — 한 번에 한 단계씩, 지금 단계 카드 한 장만 보인다(`:35`)
6. 같은 유형의 다른 페이지: `/gifts/new`(선물 보내기 단계 — 단계 표시 기준이 같다고 `:365` 주석) · `/login`(같은 가운데 카드 틀)
7. 이 페이지만의 특이점: 크리에이터를 고르면 2단계에 칸이 늘어난다(INV-V1 기본 공개 정보 · 태그 INV-T3 · 팬덤 이름). 마지막 버튼은 카카오 노랑(00절 예외)이고, 같은 버튼이 「요청 보내기」 → 「인증했어요, 가입하기」로 바뀐다
8. 바꾸면 안 되는 것: 세 단계(signup 스펙 23줄 「가입은 세 단계다」) · 칸 목록과 입력 규칙(INV-U6·U13) · 아이디·닉네임 미리 확인의 답 셋(INV-U14) · 칸에 `name` 을 두지 않는 것(`:38`) · 2단계에서 3단계로 갈 때 미리 확인 답을 기다리는 것(`:207-229`)

## 바꿀 것 (진단 문서 5절 추천안 기준 — 승인 전)

1. **「크리에이터로 가입하면 …」 안내는 `role=creator` 일 때만 보인다.** `step 1 · role=fan` 에서 사라지고, 크리에이터 카드를 고르면 유형 카드 아래에 나타난다(문장 그대로). 5절 선택과 상관없는 제안이다.
2. **갈 곳이 없는 「보기」는 그리지 않는다**(지금 [선택] 이벤트·소식 알림). 전문 화면이 생겨 주소가 채워지면 다른 「보기」와 같이 보인다. 5절 선택과 상관없다.
3. **단계 표시를 하나로**(5절 4번 ①): 카드 머리의 번호 동그라미와 390 의 「n / 3 단계」 줄을 뺀다. 알약 줄은 모든 폭에서 한 줄이고 지난 단계 누르기는 그대로다. 3단계의 카카오 안내 번호 목록 「1·2·3」은 그대로 둔다(카드 머리 「3」이 빠지면 번호가 겹치지 않는다).
   - 4번 ②를 고르면: 390 에서만 알약 줄을 숨기고 「n / 3 단계」 줄에 단계 이름을 붙인다 — 휴대폰에서는 「이전」으로만 돌아간다.
4. **2단계를 묶음 넷으로**(5절 3번 ①): 계정(아이디 · 닉네임 · 이메일 · 비밀번호 · 비밀번호 확인) → 연락처(휴대폰) → 채널 정보(`role=creator` 만 — 지금 하늘 판의 칸 그대로) → 선택 입력 사항(어디서 알게 되셨나요) → 약관 동의 _(2026-10-26 사용자: 「마무리」 이름 대신, 약관은 필수가 있어 따로)_. 묶음마다 구분선과 소제목. 칸·순서·검사는 바뀌지 않는다 — 크리에이터 칸이 휴대폰 뒤에 오는 지금 순서 그대로다. 소제목 문구는 새로 정해야 한다(진단 문서 6절).
   - 3번 ②를 고르면: 크리에이터는 4단계(유형 · 정보 · 채널 정보 · 본인 확인)가 되고 팬은 3단계로 남는다 — signup 스펙 23줄 「가입은 세 단계다」를 먼저 고쳐야 한다.
5. 결함(선택과 상관없음): 단계를 옮길 때 단계 줄이 상단 바 밑에 가리지 않게 한다(`:120-124` 의 올리기 위치에 상단 바 높이를 뺀다). 보이는 요소는 바뀌지 않는다.

> 규칙은 `docs/specs/creator-verification.md` INV-V17~V22. 이 절은 채널 확인 화면(verification-panel — 가입 `step 4` 와 크리에이터 계정 화면이 같이 쓴다)의 상태다.
> **위 `step 4` 줄의 「지금 채널 확인 화면(verification-panel) 그대로」는 이 절로 대체됐다.** 인증 코드 칸·「코드 복사」·「코드 다시 받기」·소개란 자동 확인 「확인」은 없어진다.
> 화면 구현은 시안 승인 뒤(2026-11-02 사용자 「화면 시안을 먼저」). 서버는 이 상태표의 데이터(지금 아이디·다음 재확인 날·유예 끝·다시 확인 요청)를 이미 준다.
> 시안: `docs/design/mockups/channel-link-verify-20261102/`. 2026-11-02 사용자 문구 지시: 화면에서 부르는 이름은 「팬꾹 링크」(용어집), 확인 전 상태의 맨 앞 문장, 팬꾹 링크는 채널 확인 단계의 ①에서 만든다, 가입 4단계 버튼 배치.

| 상태(코드 식별자 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `idle` / 확인 전(시안 `#s4-make`·`#s4-ready`) | 살아 있는 요청이 없음(링크용 아이디가 없어도 이 상태 — 옛 `link_needed` 는 ①에 흡수됐다) | 제목 「채널 소유자 확인」 + 상태 뱃지 → 안내 「다른 사람이 내 채널로 가입하지 못하도록, 채널 소유자를 확인해 주세요.」 → 「채널 이름」(2단계에서 적은 값, 읽기 전용) → ① 팬꾹 링크 — 링크가 없으면 「팬꾹 링크를 만들어 주세요」(설명 「외부에서 크리에이터님의 팬꾹으로 안내할 때 사용할 주소입니다.」 · `fankkuk.com/` + 칸 + 「만들기」 · 칸 아래 「로그인 아이디와 다르게 정해 주세요. 만든 뒤 30일 동안은 변경할 수 없습니다.」 · 미리 확인 INV-U14 · 누르면 30일 확인 창 · 저장은 설정 화면의 링크 저장 함수 그대로), 링크가 있으면 「활동 중인 채널에 팬꾹 링크를 올려 주세요」 + `fankkuk.com/<아이디>` + 「복사」 + 예시 상자(「게임 방송하는 하루입니다. 선물은 여기로 보내 주세요 / fankkuk.com/haru」) → ② 「팬꾹 링크를 올린 채널 주소를 입력해 주세요」 + 채널 주소 칸 + 주소 예시 → 「채널 확인 요청」(주소를 넣기 전에는 꺼짐). **팬꾹 링크가 아직 없으면 ①(링크 만들기)만 보이고 ②·「채널 확인 요청」은 보이지 않는다(꺼진 채로 두지 않음, 시안 `#s4-make`). 링크를 만들면 ①이 올리기 안내로 바뀌고 ②·요청이 나타난다.** 「치지직으로 바로 확인」은 실제 치지직 연결이 생길 때까지 화면에 두지 않는다(서버의 로그인 확인 길은 그대로) | 만들기 · 복사 · 채널 확인 요청 | 링크 만들면 ① 이 「올려 주세요」로 · 요청 → `waiting` |
| `waiting` / 요청 완료(시안 `#s4-sent`) | 확인 대기 요청이 있음 | 체크 아이콘 「채널 확인 요청을 보냈습니다」 · 「운영자가 채널을 확인하면 채널 확인이 완료됩니다.」 · 채널 이름 · 채널 주소 · 팬꾹 링크 · 「요청 취소」(선 버튼 — 보조 동작, 글자 버튼은 상자 안에서 글자처럼 보여 2026-11-02 바꿈). 가입 4단계는 이 상태로 끝난다 — 버튼 줄 「다음」 하나(켜짐), 「나중에 하기」 없음 | 요청 취소 · (가입) 다음 | 승인 → `verified` / 반려 → `rejected` / 요청 취소 → `idle` |
| `rejected` / 반려(시안 `#s4-rejected`) | 마지막 요청이 반려됨 | 사유 상자(사유 값 한 줄, 예 「팬꾹 링크를 찾지 못함」 — 남은 요청 횟수는 보이지 않는다) → 그 뒤는 `idle` 과 같은 순서 → 「채널 확인 재요청」 | 채널 확인 재요청 | `waiting` |
| `verified` / 확인 완료 | 확인됨 | 「채널 인증이 완료되었습니다」 + 확인 날 · 채널 주소 · 다음 재확인 날. 계정 설정에서 「채널 변경」을 펼치면 안내 「새 채널의 소유자 확인이 필요합니다. 확인 중에는 기존 채널로 표시되며 새 선물을 받을 수 없습니다.」 + ①② (가입 4단계에는 「채널 변경」이 없다 — 가입 중에는 채널을 바꿀 일이 없다, 2026-11-02 리뷰) | 채널 변경(계정 설정만) · (가입) 다음 | 재확인 → `recheck_missing` |
| `recheck_missing`(제안) / 팬꾹 링크를 찾지 못했어요 | 재확인에서 링크 없음(유예 중) | 「활동 중인 채널에서 팬꾹 링크를 찾지 못했어요. ○월 ○일까지 다시 올려 주세요」 · 찾을 링크 + 「복사」 · 「채널 확인 재요청」. 재요청을 보냈으면 버튼 대신 「채널 확인을 다시 요청했습니다 · ○월 ○일」, 유예 끝 날이 지났는데 아직 취소 전이면 날짜 문장 대신 「운영자 확인을 기다리고 있습니다」(2026-11-02 리뷰 — 눌렀는지 알 수 없었다) | 채널 확인 재요청 | 운영자 「링크 있음」 → `verified` / 유예 끝 → 승인 취소 |
| `locked` / 더 요청할 수 없음(시안 `#s4-locked`) | 마지막 요청 채널로 끝난 요청 10번(INV-V15) | 「이 채널로는 더 요청할 수 없습니다. 1:1 문의를 이용해 주세요.」 + 「1:1 문의」, 그 아래 ①② 그대로 — 한도는 채널마다 따로라 다른 채널 주소로는 요청할 수 있다(S15d, 2026-11-02 리뷰: 스펙이 이 명세보다 앞선다). 같은 채널 주소면 DB 가 같은 문구로 거부. 버튼 줄 「나중에 하기 | 다음(꺼짐)」 | 1:1 문의 · 다른 채널로 채널 확인 요청 · 나중에 하기 | 요청 → `waiting` |

- 가입 `step 4` 의 「다음」은 `verified` 와 `waiting`(요청 완료)에서 켜진다 — 요청을 보내면 4단계가 끝난다(2026-11-02 사용자 지시). 선물 받기는 여전히 승인 뒤다(INV-U5). `waiting` 의 버튼 줄은 「다음」 하나이고 「나중에 하기」는 없다. 4단계에는 「이전」이 없다 — 3단계에서 계정이 이미 만들어져 돌아갈 단계가 없다(2026-11-02 구현 때 확인, 시안에 잘못 그려져 있었다). 확인 전·반려에서는 「나중에 하기」로 넘어갈 수 있다.
- 확인 전(`idle`)인데 지난 요청이 승인 취소·닫힘으로 끝났으면, 맨 앞에 그 결과 한 줄 상자(예 「승인이 취소되었습니다」 — 사유 목록 값)를 둔다(2026-11-02 리뷰, 코드에 있던 요소를 명세에 올림). ①의 「만들기」는 미리 확인 답이 「쓸 수 있어요」일 때만 켜진다.
- 맨 앞 안내 문장은 확인 전 상태(`idle`·`rejected`)에만 둔다(2026-11-02 사용자 지정 문장 그대로). 요청 완료·확인 완료·유예에는 없다.
- 팬꾹 링크는 이 채널 확인 단계(가입 `step 4` · 계정 설정의 채널 확인)에서만 만든다 — 가입 2단계에는 링크 칸이 없다(2026-11-02 사용자 「둘중 하나만 있어야지」). ①의 만들기는 설정 화면의 링크 칸과 같은 저장 함수를 쓴다(새 저장 길 없음 — creator-link INV-E1~E4: 꼴·예약어·로그인 아이디와 같은 값 거부, 만들면 30일 잠금). 칸 아래 오류 문구도 설정 화면과 같다. 계정 설정의 채널 확인도 같은 ①②다.
- 가입 `step 4` 버튼 줄(확인 전·반려, PC·휴대폰 모두 — 요청 완료는 위 「다음」 하나): 「나중에 하기 | 다음」 한 줄. 채움 버튼은 화면에 하나다 — 요청 전에는 「채널 확인 요청」이 채움이고 「다음」은 꺼져 있다(design-rules 42절).
- 문구 「채널 확인이 끝나면 선물을 보낼 수 있어요」 등 새 문장은 화면 문구 규칙대로 구현 때 다듬는다(정할 것 아님).

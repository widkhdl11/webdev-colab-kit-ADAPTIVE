# 보낸 선물 상세 UX 명세 — `/gifts/[orderNo]`

> 2026-10-26 사용자 지시 네 가지로 만든 초안. 대상 상태는 **결제는 끝났고 크리에이터 승인 전**이다.
> ① 「아직 승인 상태가 아니라는 표시가 잘 보이지 않으며, 승인이 어느 시점에 필요한지도 잘 보이지 않는다. 카드 안에 표에 알맞게, 'OO님의 승인 상태'처럼」
> ② 「코드 6자리가 잘 보이지도 않는다. 모든 사람들이 글을 하나하나 읽지 않는다」
> ③ 「'FC-DERLY'는 무엇을 뜻하는 건가? MCPC3P 같은 코드랑은 다른 건가? 헷갈린다」
> ④ 「내가 보낸 선물에 대한 내용과 정보를 한번에 보여주는 부분이 없다」
> 이 화면의 슬러그 파일이 없어 규칙 6절대로 **지금 모습을 먼저** 적었다. 로컬 DB 에 이 상태의 주문이 없어 코드(`src/widgets/gift-status/ui/gift-status-page.tsx`·`gift-status.module.css`·`payment-summary.tsx`, `src/features/box-waybill/ui/receiving-address.tsx`·`early-send-gate.tsx`, `src/entities/order/ui/fan-stage-copy.ts`)를 읽어 적었다.
> 시안: `docs/design/mockups/site/v41-user-fixes/gift-detail-compare.html` (지금 / 바꾼 뒤, PC 1440 · 휴대폰 390). 다른 상태(검수 뒤·출고·거절 등)는 이번에 바꾸지 않는다 — 아래 「다른 상태에 미치는 것」.

## 페이지 브리프

1. 목적: 보낸 선물이 지금 어디까지 왔고 내가 할 일이 무엇인지 본다 — 이 화면이 없으면 상자를 어디로 보낼지 모르고, 문의해야 진행을 안다.
2. 주 사용자 / 부 사용자: 선물을 보낸 팬 / 선물을 보낸 크리에이터 계정.
3. 사용자가 와서 하려는 일: 팬꾹 주소를 복사해 상자를 보낸다, 승인됐는지 본다, 얼마를 냈고 무엇을 보냈는지 확인한다.
4. 방문 빈도: 결제 직후 한 번 + 상자를 보낼 때 + 도착할 때까지 하루 한두 번.
5. 페이지 유형: 상세형(주) · 작업형(부 — 승인 전에는 「먼저 보내기」, 주소 복사).
6. 같은 유형의 다른 페이지: 받은 선물(역조공) 상세, 함께한 시간.
7. 이 페이지만의 특이점: 「승인」이 줄 세운 6단계에 들어 있지 않고 출고의 조건이다 — 그래서 단계 막대만 봐서는 승인이 언제 필요한지 안 보인다. 코드 둘(주문번호 FC-…, 상자별 팬꾹 주소 6자리)이 한 화면에 함께 나온다.
8. 바꾸면 안 되는 것: 맨 위 하늘 상태 판(배지 · n/6 · 6단계 막대), 상자 칸 8 + 오른쪽 한 열 배치(999 이하 한 단), 「먼저 보내기」 안내와 버튼 글자, 6자리를 가려 두고 눌러야 보이는 동작(스펙), 「주소 한 번에 복사」가 6자리까지 복사하는 동작, 맨 아래 「1:1 문의하기」.

## 지금 모습 (역진단, 승인 전 두 상태)

| 자리 | 「먼저 보내기」 전 | 「먼저 보내기」 누름(주소 보임) |
|---|---|---|
| 상태 판 위 줄 | 「주문번호 FC-R2D8Q · 등록 10월 24일 (토)」 | 같음 |
| 상태 판 배지 · 큰 줄 | 「승인 대기」 · 「크리에이터가 아직 승인하지 않았어요」 | **「보내 주세요」 · 「사무실로 보내 주세요」 — 승인 전이라는 표시가 판에서 사라진다** |
| 6단계 막대 | 등록 ✓ · 입고(다음 단계) · 검수 · 출고 · 배송중 · 수령. 승인 자리 없음 | 같음 |
| 상자 카드 | 「먼저 보내기」 안내 + 상자 줄 | 회색 14 문장 「상자마다 팬꾹 주소가 달라요. … 승인은 출고 전까지만 나면 돼요.」(승인 시점은 이 문장 끝에만) → 상자마다 「FC-R2D8Q-1 · 소형 상자」 + 「아직 도착 전」 → 하늘 칸 「이 선물의 팬꾹 주소」: 받는 곳 = 긴 주소 끝에 6자리(20 글자, 기본 ●●●●●● 가림) · 받는 사람 · 「6자리 보기」「주소 한 번에 복사」(둘 다 줄 버튼) · 긴 안내 문장 → 접힌 송장번호 |
| 결제 카드 | 금액 32 · 상자별 줄 · 검수 포함 · 「… 구간이 더 크면 …」 · 취소하기 | 같음 |
| 주문 정보 카드(회색, 낮춤) | 등록 · 「크리에이터 승인」 = 회색 태그 「출고 전에 받아요」(검수 전이라 `approval.state = todo`) | 같음 |

문제 넷의 원인:

- ① 승인 전 표시: 주소가 보인 뒤에는 상태 판에서 승인 이야기가 사라지고, 남는 곳은 회색 카드의 회색 태그 하나다. 태그 글자 「출고 전에 받아요」는 「아직 승인 안 됨」으로 읽히지 않는다. 승인이 출고 앞에 필요하다는 건 상자 카드 위 회색 문장 끝에만 있다.
- ② 6자리: 긴 주소 끝에 붙은 20 글자, 그것도 기본으로 가려져 있다. 「6자리 보기」 버튼은 「주소 한 번에 복사」와 같은 모양이라 눈에 띄지 않는다.
- ③ 두 코드: 주문번호가 상태 판 위 줄과 **상자 이름**(「FC-R2D8Q-1 · 소형 상자」)에 나온다. 상자 이름 바로 아래 하늘 칸에 6자리가 나오니, 같은 상자에 코드가 둘 붙은 것처럼 보인다. 어느 쪽에도 「주문번호」·「팬꾹 주소 6자리」라는 이름표가 같은 자리에 붙어 있지 않다(상태 판 위 줄의 「주문번호」는 작은 회색 14).
- ④ 선물 요약: 받는 크리에이터·선물·상자 수는 상태 판, 금액은 결제 카드, 등록 시각은 주문 정보 카드, 상자 크기는 상자 줄로 흩어져 있다. 상자 크기별 개수(「소형 1개 · 중형 1개」)는 어디에도 한 줄로 없다.

## 적용한 규칙

- **UX 기준 문서 없음**: `docs/ux/principles.md` · `docs/ux/detail-pages.md` · `docs/ux/task-pages.md`. 작성할지는 따로 묻는다. 이번 판정은 승인된 design-rules 와 `states.md` 로 대신했다.
- design-rules 22절(상세 = 하늘 상태 판 → 상자·결제·주문 정보 카드, 주문 정보는 회색으로 낮춤, 크리에이터 승인 날짜는 주문 정보 안): **벗어남** — 결제·주문 정보 두 카드를 흰 「선물 정보」 카드 하나로 합치고 승인 상태를 그 안 노란 칸으로 올린다(사용자 지시 ①④). 승인되면 22절 그 줄을 고친다.
- design-rules 21절 「한 화면에 강조 하나」: 하늘 면은 상태 판·팬꾹 주소 칸(지금도 둘). 승인 칸은 사이트의 기다림 색(「승인 대기」 배지의 노랑 #fff5db/#805b16 · 칸 #fffbeb/#fde68a — tokens.css 값)이라 새 강조색이 아니다.
- 용어집: 「주문번호」(1절) · 「팬꾹 주소 6자리」(5절 — 「코드」 단독·「주소 코드」 금지) · 「승인 대기」(3절) · 「상자 크기」(6절 — 「구간」은 운영자 말이라 결제 안내 문장에서 바꾼다).

## 바뀌는 것

1. 상태 판: 배지 자리에 「OO님 승인 대기」를 함께(주소가 보인 뒤에도 남는다). 6단계 막대 「출고」 아래 작은 노란 태그 「승인 필요」. 「먼저 보내기」 전 큰 줄은 「OO님이 아직 승인하지 않았어요」(용어집 3절 문장 꼴).
2. 「OO님의 승인 상태」 칸: 선물 정보 카드 안에 표로 — 지금(승인 대기) · 필요한 때(출고 전) · 기한(○월 ○일 (요일)까지). 상자 카드 위 문장의 「승인은 출고 전까지만 나면 돼요.」는 뺀다(표와 겹침). 지금의 회색 태그 「출고 전에 받아요」는 없앤다.
3. 팬꾹 주소 6자리: 주소 칸 맨 위에 이름표 「팬꾹 주소 6자리」 + 한 글자씩 흰 칸(32, 휴대폰 24) + 「6자리 보기/가리기」. 받는 곳 줄 끝의 6자리에는 테두리. 「주소 한 번에 복사」는 주 버튼. 주소 칸 제목 「이 선물의 팬꾹 주소」는 상자 이름과 6자리 이름표가 대신해 뺀다. 기본은 지금처럼 가림(INV-C2).
4. 주문번호: 상자 이름에서 빼고(「FC-R2D8Q-1 · 소형 상자」 → 「상자 1 · 소형」) 상태 판 위 줄에서도 뺀다. 선물 정보 카드 「주문번호」 줄에만 보통 굵기로. → 두 코드가 이름표(주문번호 / 팬꾹 주소 6자리) · 자리(오른쪽 표 / 상자 안 하늘 칸) · 모양(보통 글자 / 큰 글자 칸)이 모두 다르다.
5. 결제 카드 + 주문 정보 카드 → 흰 「선물 정보」 카드 하나: 받는 크리에이터 · 선물 · 상자(「소형 1개 · 중형 1개」) · 주문번호 · 등록 → 승인 상태 칸 → 결제(상자별 금액 · 결제 금액 24 · 검수 포함 · 결제한 날 · 취소하기). 휴대폰은 상자 카드 아래.
6. 문구: 결제 안내 「재어 보니 구간이 더 크면」 → 「재어 보니 상자 크기가 더 크면」.

## 다른 상태에 미치는 것 (이번 시안 밖, 구현 때 함께 정할 것)

- 상자 이름 「상자 N · 크기」와 선물 정보 카드는 모든 상태에 쓰인다. 끝난 선물(거절·반송·취소)도 같은 카드 — 승인 칸은 진행 중에만.
- 승인된 뒤: 상태 판 승인 배지·「승인 필요」 태그가 사라지고, 승인 칸은 「승인됨 · ○월 ○일」 한 줄.
- 검수 뒤 승인 대기(`shipped` 단계, 승인 전): 지금도 배지 「승인 대기」 — 「OO님 승인 대기」로 맞춘다.
- 상자 이름의 「상자 N」은 상자 순번(`boxSeq`)이 필요하다. 지금 팬 읽기의 상자 이름(`label`)은 주문번호 꼴이라, 구현 때 순번을 화면에 넘기는지 확인한다(추가 결제 줄은 이미 「상자 N」을 쓴다).
- 「승인 필요」는 용어집에 없는 라벨이다. 승인되면 용어집 3절에 행을 더한 뒤 쓴다.

## 정해 주실 것

- 6자리를 처음부터 보여 줄까 — ① 지금처럼 가려 두고 「6자리 보기」(추천: 스펙 INV-C2 그대로, 큰 칸이 생겨 가려져 있어도 자리는 보임, 복사는 가려져도 됨) ② 처음부터 보이기(스펙 변경, 방송 화면 공유 중 노출 위험).
- 승인 칸 색 — ① 노란 칸(추천: 이미 쓰는 기다림 색, 「잘 안 보인다」 지적에 맞음) ② 다른 줄과 같은 흰 표.

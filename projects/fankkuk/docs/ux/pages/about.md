# 팬꾹 소개 UX 명세 — `/about` (시안 비교용 새 안)

> 2026-11-11 초안. 입력: `external-material-box/exam_info_prompt.md`(본문 문장·조건 고정).
> 용도: 디자인 스킬끼리 시안을 비교하는 공통 입력. 이번에는 **독립된 소개 페이지 한 장 시안**까지이고 코드는 바꾸지 않는다.
> 올릴 자리는 소개 페이지 또는 메인 페이지 중 미정 — 소개 페이지라면 지금 `/about`(헤더·바닥글의 「팬꾹 소개」 링크가 가리키는 곳)을 바꾸게 된다.

## 지금 모습 (`/about`, 명세 없이 구현된 화면)

그리는 코드: `src/app/(site)/about/page.tsx` → `src/widgets/about/ui/about-page.tsx`.
구역 순서: 첫 화면(제목 「팬꾹 소개」) → 왜 필요한가(송장에 주소가 남는 문제) → 주소가 열리는 때(잠긴 주소 그림 + 흐름 단계)
→ 역조공(팬 A·B·C가 받기·받지 않기를 고르는 그림) → 검수 · 선물 관리(현황 화면 예시) · 함께한 시간 · 내 팬꾹 꾸미기 카드
→ 하지 않는 것(주소 열람 기록 예시 표) → 마지막 행동 구역.
새 안과 다른 점은 맨 아래 「바뀌는 것」에 적었다.

## 페이지 브리프

1. 목적: 크리에이터가 팬꾹이 무엇을 해 주는지(선물 승인, 주소 보호, 선물함으로 팬에게 보내기, 채널, 선물 기록)를 한 페이지에서 알고 가입 여부를 정한다.
2. 주 사용자 / 부 사용자: 크리에이터(가입 전 포함) / 팬
3. 사용자가 와서 하려는 일: 팬꾹을 쓰면 무엇이 달라지는지 훑어본다, 내 주소가 어떻게 보호되는지 확인한다, 팬에게 선물을 보내는 방법이 있는지 본다, 마지막에 행동 버튼을 누른다.
4. 방문 빈도: 처음 알게 됐을 때 한두 번(배너·헤더 「팬꾹 소개」·바깥 링크로 들어온다)
5. 페이지 유형: 문서형(추천) — 읽기만 하고 입력이 없다. 다만 「내 상황의 한 부분을 찾으러 오는」 안내 글과 달리 위에서 아래로 한 번 읽는 글이라, 찾기 수단 규칙 몇 개에서 벗어난다(아래 「적용한 규칙」).
6. 같은 유형의 다른 페이지: 크리에이터 이용 안내·팬 이용 안내·보안 안내·요금 안내·자주 묻는 질문
7. 이 페이지만의 특이점: 본문 문장이 정해져 있다(고치지 않고, 고칠 곳은 제안으로만). 행동 버튼의 문구와 이동 위치가 미정이다. 그림은 구역 3-1에만 꼭 넣는다.
8. 바꾸면 안 되는 것: 본문 문장과 구역 순서(1 → 6), 헤드라인 「팬꾹의 소개」, 「확인 필요」 표시가 붙은 문장(그대로 쓰고 표시를 남긴다)

## 「확인 필요」 문장 — 문서 대조 결과

본문은 그대로 쓰고 표시도 남긴다. 아래는 사람이 확인할 때 쓸 근거다.

| 문장 | 문서에 있는 사실 | 판정 |
|---|---|---|
| 구역 2 제목 「암호화하여 저장」 | 크리에이터 주소는 브라우저에서 암호화된 뒤에만 서버로 가고, 서버·DB에는 암호문만 있다(address-protection INV-P1) | 근거 있음 |
| 구역 2 제목 「팬의 주소는 사용 후엔 폐기」 — 폐기 시점 | 선물함 신청의 팬 주소 사본은 그 선물이 끝나면 지운다. 끝나는 때 = 택배사가 상자를 가져간 때, 택배사 연결 전에는 출고 확정 + 72시간(revgift-box INV-GB20, reverse-gift INV-R9). 받지 않음·반송·취소는 그 순간 지운다 | 근거 있음 — 「사용 후」를 이 시점으로 적을지 정할 것 |
| 구역 2 「인증 시스템을 통해 잠시동안만 주소가 보이게 돼요」 (표시 없음) | 주소는 사람이 인증해서 보는 것이 아니라, 송장을 출력하는 순간 한 건씩만 열린다(address-protection). 카카오톡 인증은 크리에이터가 선물을 승인할 때 쓴다 | 문서와 다르다 — 제안 참고 |
| 구역 2 「만일 정보유출이 되더라도 피해가 최소화」 — 안전 보장 표현 | 저장된 값이 암호문뿐이라는 사실은 있다. 「피해 최소화」를 보장하는 문서는 없다 | 확인 필요 유지 |
| 구역 3-2 다른 서비스의 이용료·거주지역 노출 | 레포 문서에 근거 없음 | 확인 필요 유지 |
| 구역 3-2 「저렴한 비용」 | 비교 대상·수치 문서 없음 | 확인 필요 유지 |

## 제안 (문장을 고치지는 않음 — 결정은 사람)

- 구역 2 「인증 시스템을 통해 잠시동안만」 → 실제 동작은 「송장을 출력할 때 한 건씩만 열린다」. 사실과 다르게 읽힐 수 있다.
- 구역 4 「대표색」 → 채널 설정 화면 이름은 「테마 색」(creator-link). 화면 이름과 맞추면 가입 뒤 찾기 쉽다.
- 구역 3 제목 「크리에이터 -> 팬에게」 → 화살표 기호 대신 말로(「크리에이터가 팬에게」).
- 맞춤법·띄어쓰기: 「보낼 때 마다」→「보낼 때마다」, 「보낼때는」→「보낼 때는」, 「그럴경우」→「그럴 경우」, 「잠시동안만」→「잠시 동안만」, 구역 3-1 「(그림 포함)」은 지시문이라 화면에 넣지 않는다.
- 자주 묻는 질문의 「역조공」과 본문의 「팬에게 보내기」 — 같은 기능을 두 이름으로 부른다.

## 바뀌는 것 (지금 `/about` → 새 안)

- 헤드라인: 「팬꾹 소개」 → 「팬꾹의 소개」
- 첫 설명: 송장에 주소가 남는 문제(왜 필요한가) → 선물 승인부터 시작
- 주소 보호: 잠긴 주소 그림 + 열리는 흐름 → 본문 3문장(그림은 필수 아님)
- 역조공(팬 A·B·C 받기·받지 않기) → 선물함 만들기·신청·마감 흐름(그림 필수) + 모아서 보내기
- 검수 카드·하지 않는 것(열람 기록 표) → 없음. 일부 사실 문장은 구역 6 신뢰 요소 후보로
- 자주 묻는 질문 → 새로 생김
- 행동 버튼 → 첫 화면과 끝 두 자리, 문구·이동 위치 미정

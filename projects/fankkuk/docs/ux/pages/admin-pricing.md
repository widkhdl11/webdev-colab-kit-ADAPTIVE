# 관리자 요금표 UX 명세 — `/admin/pricing`

> 2026-11-07 처음 만든다. 지금 화면(요금표·요금 바꾼 기록)을 먼저 적고(역진단), 이번에 더한 경로표·기본 경로·팬에게 보내기 택배비·수정안을 적는다.
> 시각 기준은 승인된 시안 `docs/design/mockups/site/v4/admin/pricing.html` 의 표·검사 목록 모양 그대로다(새 시각 방향 없음). 상태 이름은 「제안」이다.

## 페이지 브리프

- 목적: 팬 선물 요금표와 택배 원가 경로표를 보고, 대표가 고친다
- 주 사용자: 대표 / 부 사용자: 직원(읽기만)
- 와서 하려는 일: 요금을 바꾸거나, 택배 계약이 바뀌어 기본 경로·경로 값을 바꾼다
- 방문 빈도: 드물다(요금·계약이 바뀔 때)
- 페이지 유형: 관리형
- 같은 유형의 다른 페이지: 보낼 수 없는 물품, 광고 배너
- 이 페이지만의 특이점: 저장이 돈 계산을 바꾼다 — 검사(INV-K4·K16)를 어기면 통째로 거부하고, 경로표 쪽은 수정안을 보여 준다
- 바꾸면 안 되는 것: 대표만 고친다(직원에게는 입력칸·버튼이 없다) · 요금 바꾼 기록은 고치거나 지울 수 없다 · 새 주문부터 적용

## 상태표

| 상태 (코드 · 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `not_operator` · 404 | 운영자가 아님 | 404 | — | — |
| `staff` · 「직원 계정이에요」 | 직원 운영자 | 요금표·경로표·택배비를 값으로만, 기본 경로에 「기본」 꼬리표 | — | — |
| `owner_idle` · 「바뀐 곳이 없어요」 | 대표, 입력이 서버 값과 같음 | 두 양식의 입력칸, 저장 버튼은 눌리지 않음 | 칸 고치기 | `owner_dirty` |
| `owner_dirty` · 「요금표 저장」/「경로표 저장」 | 바뀐 칸이 있음 | 저장 버튼 | 저장 · 되돌리기 | `saved` · `rejected_check` · `owner_idle` |
| `route_incomplete` · 「값을 다 채워야 고를 수 있어요」 (제안, 2026-11-07) | 경로의 네 칸 중 빈칸이 있음 | 그 경로의 기본 경로 선택이 꺼짐 | 칸 채우기 | `owner_dirty` |
| `rejected_check` · 「수정안」 (제안, 2026-11-07) | 경로표 저장이 검사(INV-K16 (a)(b))에 걸림 | 거부 문구 + 수정안 목록(어긴 구간·지금 값·수정안·근거) + [이 값으로 채우기] | [이 값으로 채우기] · 직접 고치기 | `filled` |
| `filled` · 「함께 저장할 팬 선물 받는 값」 (제안, 2026-11-07) | 수정안을 채움 | 팬에게 보내기 택배비 칸에 수정안, 팬 선물 받는 값 수정안이 있으면 그 구간의 입력칸(지금 값 함께) | 금액 고치기 · 경로표 저장 | `saved` · `rejected_check` |
| `saved` · 「저장했어요.」 | 저장 성공 | 저장 문구, 요금표·기록을 다시 읽어 그림 | — | `owner_idle` |

- 수정안은 서버가 DB 검사로 계산한다 — (a) 받는 값 수정안 = 경로 원가 + 검수비 + 지금 기본 서비스료, (b) 택배비 수정안 = 경로 원가를 100원 단위로 반올림.
- 「이 값으로 채우기」는 입력칸만 채운다. 저장은 대표가 다시 누른다(금액을 더 고칠 수 있게).

## 적용한 규칙

- 예외 경로 요소(수정안·함께 저장할 받는 값)는 기본 상태에 없다.
- UX 기준 문서 중 `principles.md`·`admin-pages.md` 가 아직 없다.

# 검수 기준 UX 명세 — `/inspection`

> 2026-10-23 문서형 페이지 1단계. 코드를 읽고 **지금 구현된 그대로** 적었다. 고칠 점은 `_diff-guide.md` 에 따로 있다.
> 그리는 코드: `src/app/(site)/inspection/page.tsx` → `src/widgets/legal/ui/legal-page.tsx` · 글 `src/widgets/legal/model/inspection-doc.ts`(상수 `INSPECTION_DOC`).

## 페이지 브리프

1. 목적: 팬꾹 사무실이 상자를 어떻게 검수하고, 무엇이 나오면 어떻게 처리하는지 한 주소에서 확인한다.
2. 주 사용자 / 부 사용자: 팬 / 크리에이터(역조공 상자 조·검수의 한계)
3. 사용자가 와서 하려는 일: 내 선물이 검수를 통과할지 본다, 탐지기가 반응하거나 돌려보내는 경우를 찾는다.
4. 방문 빈도: 처음 보내기 전 한 번, 검수에서 걸렸을 때 한 번
5. 페이지 유형: 문서형 — 읽기만 하고 입력이 없다
6. 같은 유형의 다른 페이지: 이용 안내 두 글·보안 안내·분쟁 처리 안내·요금 안내(같은 틀), 약관 세 글, 자주 묻는 질문
7. 이 페이지만의 특이점: 머리 설명이 고정 약속 문장 둘(`PROMISE.inspection`·`inspectionOpen`, `inspection-doc.ts:13`)이다. DB 를 읽지 않아 오류 상태가 없다.
8. 바꾸면 안 되는 것: 글 내용, 요약 세 줄, 약속 문장(상수 참조)

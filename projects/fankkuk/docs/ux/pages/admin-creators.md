# 운영자 크리에이터 본인 확인 UX 명세 — `/admin/creators`

> 2026-11-02 초안. 규칙은 `docs/specs/creator-verification-link.md`(초안, 결정 카드 대기). 위 「지금 모습」은 코드 그대로(`src/widgets/admin-creators/ui/creators-panel.tsx`),
> 「바꿀 것」이 개정안이다. 태그 관리 등 이 화면의 다른 묶음은 바뀌지 않아 적지 않았다.

## 페이지 브리프

1. 목적: 크리에이터의 채널 확인 요청을 처리하고, 확인된 크리에이터의 채널을 다시 확인한다
2. 주 사용자: 운영자 · 부 사용자: 대표
3. 사용자가 와서 하려는 일: 대기 요청을 오래된 순으로 열어 채널 이름이 같고 선물 링크가 있는지 보고 승인·반려한다, 재확인 목록을 처리한다
4. 방문 빈도: 하루 몇 번(요청이 들어올 때)
5. 페이지 유형: 관리형
6. 같은 유형의 다른 페이지: `/admin/inquiries`, `/admin/payments`
7. 이 페이지만의 특이점: 판정 근거가 팬꾹 밖(채널 공개 페이지)에 있다 — 운영자가 새 탭으로 열어 눈으로 대조한다
8. 바꾸면 안 되는 것: 한 요청은 한 번만 결정, 결정 기록은 지울 수 없음, 휴대폰·이메일·실명은 이 목록에 없음(INV-V11)

## 지금 모습 (역진단)

| 묶음 | 칸 |
|---|---|
| 확인 요청(올림) | 닉네임 · 채널 · 인증 코드 · 채널 확인 · 요청 시각 · 쓴 횟수 · 승인/반려 |
| 코드 받음 | 닉네임 · 채널 · 인증 코드 · 받은 시각 · 쓴 횟수 · 반려 |
| 승인된 크리에이터 | 닉네임 · 채널(「채널 이사 중」 꼬리표) · 승인한 사람 · 승인 시각 · 승인 취소 |
| 끝난 신청 | 승인 / 승인 취소 / 반려 / 닫힘 기록 · 횟수 풀기 |

## 바꿀 것 (상태표)

| 상태(코드 식별자 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `queue` / 확인 대기 | 확인 대기 요청 | 닉네임 · 채널(누르면 새 탭) · **채널 이름**(가입 때 적은 값) · **찾을 링크** `fankkuk.com/<요청 때 아이디>` · 요청 시각 · 쓴 횟수 · 「승인」 · 「반려」(사유: 선물 링크를 찾지 못함 · 링크 주소가 다름 · 채널 이름이 다름 · 채널 주소가 열리지 않음 · 그 밖) | 승인 · 반려 | 목록에서 빠짐 |
| `recheck` / 재확인 | 승인·지난 재확인에서 90일 지남, 또는 링크용 아이디를 바꿈 | 닉네임 · 채널 · 찾을 링크(**지금** 아이디) · 오른 이유(90일 / 아이디 바꿈) · 「링크 있음」 · 「링크 없음」 | 링크 있음 · 링크 없음 | 있음 → 목록에서 빠짐 / 없음 → `grace` |
| `grace` / 유예 중 | 「링크 없음」 뒤 유예 기간 안 | 닉네임 · 채널 · 유예 끝 날 · (크리에이터가 다시 요청했으면) 「다시 확인 요청됨」 꼬리표 · 「링크 있음」 | 링크 있음 | 있음 → 끝 / 유예 끝 → 승인 취소(사유 「선물 링크가 채널에서 내려감」) |

- 「코드 받음」 묶음과 「인증 코드」 칸은 없어진다(코드 받음 단계가 없다).
- 승인된 크리에이터·끝난 신청 묶음은 그대로다. 승인 취소 사유 목록에 「선물 링크가 채널에서 내려감」이 더해진다.
- 대기·재확인 목록은 오래된 순.

## 적용한 규칙

- UX 기준 문서 `docs/ux/principles.md`·`docs/ux/admin-pages.md` 가 아직 없다 — 이 명세는 `states.md` 와 다른 관리자 화면(`/admin/inquiries`)의 목록·처리 꼴을 따랐다.

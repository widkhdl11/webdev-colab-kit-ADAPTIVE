# 출고 작업 UX 명세 — `/admin/work/outbound` (팬 선물·역조공 출고 칸만)

> 2026-11-08 송장 출력 방식 「수동 입력」(address-protection INV-P21 ③)을 넣으며 처음 만들었다. 이 화면 전체가 아니라
> **출고 쪽 세 상태(출고 조건 충족 → 운송장 번호 입력 전 → 출고 확정 대기)**만 적는다. 반송·처분·경찰 인계·확정 뒤 다시 출력은
> 승인된 시안 `admin/work-outbound.html` 과 지금 코드가 기준이다(바뀌지 않음).
> 지금 모습(역진단): QR 스캔 → 「송장 출력」(대표) → 개발용 송장번호와 함께 송장 출력 단계 → 송장 바코드 스캔으로 출고 확정. 주소는 인쇄 칸에만 찍히고 화면에는 없다.
> 바뀌는 것: 설정이 「수동 입력」(택배사 계약 전 기본값)이면 주소를 화면에 보여 주고, 대표가 택배 접수 뒤 받은 운송장 번호를 넣는 상태가 하나 생긴다.
> UX 기준 문서 중 `principles.md`·`admin-pages.md`(관리형)가 아직 없다 — 상태 이름은 DB 다음 단계 값(`office_next_step`)을 그대로 쓴다.

## 페이지 브리프

- 목적: 검수가 끝난 상자를 택배로 내보낸다
- 주 사용자: 대표 / 부 사용자: 직원(스캔·확정만)
- 와서 하려는 일: 상자 QR 을 스캔해 주소를 열고, 택배 접수 뒤 운송장 번호를 넣고, 송장 바코드로 출고를 확정한다
- 방문 빈도: 출고하는 날마다 여러 번
- 페이지 유형: 작업형(주)
- 같은 유형의 다른 페이지: 입고 작업, 검수 작업
- 이 페이지만의 특이점: 주소가 화면에 보이는 유일한 화면(수동 입력일 때) — 상자 하나씩, 열 때마다 열람 기록에 남는다
- 바꾸면 안 되는 것: 주소를 여는 것은 대표만(INV-P8) · 상자마다 최대 3번(INV-P5) · 주소는 저장하지 않고 다른 상자를 스캔하면 사라진다

## 상태표 (출고 쪽)

| 상태 (코드 · 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `print_label` · 출고 조건 충족 | 검수 완료, 승인·차액 조건 충족 | 상자 정보, 확인 목록, 「주소 열기」(수동 입력) / 「송장 출력」(그 밖) — 대표만 | 주소 열기 | enter_waybill (수동 입력) / confirm_shipment |
| `enter_waybill` · 운송장 번호 입력 전 (새로) | 주소를 열었고 운송장 번호가 비어 있음 | 상자 정보, 방금 연 주소(그 화면에서만) 또는 「주소 다시 열기」, 운송장 번호 칸·「운송장 번호 저장」 — 대표만 | 번호 저장 · 주소 다시 열기 | confirm_shipment |
| `confirm_shipment` · 송장 출력함 | 운송장 번호가 있음 | 운송장 번호, 「택배 송장의 바코드를 스캔하면 출고가 확정돼요」 | 송장 바코드 스캔 · 송장 다시 출력(대표) | done(출고함) |

직원(`staff`)에게는 `print_label`·`enter_waybill` 에서 버튼·입력 칸 대신 「대표만」 안내만 보인다.

## 적용한 규칙

- 예외 경로 요소(주소 다시 열기·오류 줄)는 기본 상태(방금 주소를 연 화면)에 보이지 않는다.
- 상태 이름은 DB 의 다음 단계 값 그대로다 — states.md 에 출고 단계가 없어 「제안」에 해당한다.

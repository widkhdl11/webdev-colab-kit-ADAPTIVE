# 새 비밀번호 정하기 UX 명세 — `/password/reset`

코드: `src/app/(site)/password/reset/page.tsx`(라우트 — 주소의 `token` 값을 넘김, 다른 사이트로 주소를 넘기지 않고 검색에 싣지 않음 `:9`) · `reset-password-panel.tsx` · `reset-password.module.css`. 서버: `src/app/api/auth/password/reset/route.ts` → `src/features/password-reset/model/reset-password.ts`.

## 페이지 브리프

1. 목적: 재설정 메일의 링크로 들어와 새 비밀번호를 정한다
2. 주 사용자 / 부 사용자: 비밀번호를 잊은 회원(로그인하지 않은 채) / 링크가 죽은 채 들어온 회원
3. 사용자가 와서 하려는 일: 새 비밀번호를 두 번 적고 바꾼 뒤 로그인하러 간다
4. 방문 빈도: 드묾 — 메일 한 통에 한 번
5. 페이지 유형: 작업형 — 칸 둘, 버튼 하나
6. 같은 유형의 다른 페이지: `/login`(같은 480 카드) · `/signup` 2단계의 비밀번호 칸(같은 규칙 `PASSWORD_HINT`)
7. 이 페이지만의 특이점: 링크를 여는 것만으로는 아무것도 바뀌지 않고 저장해야 바뀐다(`page.tsx:11`). 바뀌면 모든 기기에서 로그아웃된다(INV-L11) — 그래서 끝 상태는 「로그인하러 가기」 하나다. 로그인과 상관없이 연다
8. 바꾸면 안 되는 것: 링크 확인·만료·한 번 쓰기는 서버가 한다는 것(`:10`), 실패 때 그 칸으로 초점(`:37-39`), 끝 상태에서 로그인 링크로 초점(`:33-35`)

## 바꿀 것 (진단 문서 5절 추천안 기준 — 승인 전)

1. **칸 오류는 칸 바로 아래**: `failed` + 칸 `password`·`passwordConfirm` 일 때 버튼 위 상자 대신 그 칸 아래에 가입 2단계와 같은 「!」 줄(초점·`aria-describedby` 는 지금처럼). 칸을 모르는 실패(연결 실패)와 링크 오류는 지금처럼 상자. 5절 선택과 상관없다.
2. **요청 화면을 새로 둔다**(5절 1번 ①). 가칭 `/password/forgot`(명세 슬러그 `password-forgot` — 승인되면 따로 연다). `/login` 의 「비밀번호를 잊으셨나요?」 링크가 이리로 온다. 상태는 지금 로그인 접는 칸의 것을 그대로 옮긴다:
   - `request_idle` — 제목 · 안내 「아이디와 가입할 때 적은 이메일을 넣으면…」 · 아이디 칸 · 가입 이메일 칸 · 「재설정 링크 보내기」(이 화면의 채운 버튼 하나) · 아래 줄(로그인으로 돌아가는 링크)
   - `request_sending` — 「보내는 중」
   - `request_error` — 빈 칸·연결 실패 상자
   - `request_answered` — 늘 같은 초록 상자 「입력한 정보가 맞으면 메일을 보냈어요.」 + 「링크는 1시간 동안…1:1 문의로 알려 주세요.」(INV-L10 — 계정이 없어도 같은 화면)
   - 그러면 이 화면의 「로그인 화면에서 재설정 메일을 다시 받아 주세요」 두 문장이 가리키는 곳이 바뀐다 — 문구 결정이 따로 필요하다(진단 문서 6절). 버튼 「로그인 화면으로」/「로그인하러 가기」도 하나로 맞출 후보다.
   - 5절 1번에서 ②나 ③을 고르면 이 항목은 없다(요청은 로그인 화면에 남는다).
3. 머리를 카드 밖으로 옮기는 것(5절 5번)은 보이는 요소가 그대로라 진단 문서에만 적었다.

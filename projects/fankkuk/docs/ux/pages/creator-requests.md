# 크리에이터 승인 내역·선물 현황 — 「승인 취소」

## 페이지 브리프

1. 목적: 승인한 선물을 되돌릴 길을 준다. 지금은 한 번 승인하면 되돌릴 수 없다.
2. 주 사용자 / 부 사용자: 크리에이터 / 팬(취소 결과를 선물 상세에서 본다)
3. 사용자가 와서 하려는 일: 실수로 또는 마음이 바뀌어 승인한 선물의 승인을 취소한다
4. 방문 빈도: 드물다(선물 몇십 건에 한 번)
5. 페이지 유형: 목록형(승인 내역·선물 현황) 안의 작업 하나 — 확인 창
6. 같은 유형의 다른 페이지: 처리할 일의 받지 않기 확인 창(decline-block)
7. 이 페이지만의 특이점: 같은 「승인 취소」가 상자가 팬꾹에 도착했는지에 따라 결과가 다르다(대기로 되돌림 / 거절로 끝남). 확인 창이 그 결과를 먼저 보여 준다
8. 바꾸면 안 되는 것: 승인 내역의 숫자 칸·달별 줄 모양, 선물 현황 카드 모양, 승인은 카카오톡 서명으로만 한다는 것

## 지금 모습

- 승인 내역(`/creator/requests#done`): 처리한 요청이 달마다 줄로 나온다. 줄 오른쪽에 결과 태그(승인·거절·기한 만료·차단)와 날짜. 버튼 없음.
- 선물 현황(`/creator/progress`): 받는 선물 카드(5칸 막대 + 단계 이름). 버튼은 「지금 할 일」(처리할 일에 그 주문이 있을 때)뿐. 읽기 전용.

## 상태표 — 바뀌는 것

| 상태(코드 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `cancelable` / (줄·카드에 버튼) (제안) | 승인됨 · 송장이 한 번도 출력되지 않음 | 승인 내역의 「승인」 줄(날짜 오른쪽), 선물 현황의 받는 선물 카드(「지금 할 일」 왼쪽)에 테두리 없는 글자 버튼 「승인 취소」(`btn--text btn--sm`, 보조 글자색, 눌리는 칸 44 — 줄 높이 56 은 그대로) | 승인 취소 | 확인 창 |
| `confirm-before` / 확인 창(입고 전) (제안) | 도착한 상자 0개 · 승인 기한 안 | 「승인을 취소할까요?」 · 「승인 대기로 돌아갑니다. M월 D일까지 다시 승인할 수 있습니다.」 · 「닫기」 · 「승인 취소」 | 닫기 · 승인 취소 | `done-before` |
| `confirm-expired` / 확인 창(입고 전, 기한 지남) (제안) | 도착한 상자 0개 · 승인 기한 지남 | 「승인을 취소할까요?」 · 「승인 기한이 지나 다시 승인할 수 없습니다. 취소하면 기한 만료로 반려됩니다.」 · 「닫기」 · 「승인 취소」 | 닫기 · 승인 취소 | `done-before`(곧 기한 만료로 바뀜) |
| `confirm-after` / 확인 창(입고 뒤) (제안) | 도착한 상자 1개 이상 | 「승인을 취소할까요?」 · 「팬꾹에 도착한 상자가 있어 취소하면 거절로 끝나고 상자는 팬에게 반송됩니다. 다시 승인할 수 없습니다.」 · 「닫기」 · 「승인 취소」 | 닫기 · 승인 취소 | `done-after` |
| `done-before` (제안) | 입고 전 취소가 저장됨 | 창이 닫히고 그 줄은 승인 내역에서 빠진다. 처리할 일의 승인 요청에 다시 나온다(처리할 일 화면 그대로) | — | (처리할 일에서) 다시 승인 |
| `done-after` (제안) | 입고 뒤 취소가 저장됨 | 창이 닫히고 그 줄의 태그가 「거절」로. 선물 현황에서는 카드가 빠진다 | — | 끝 |
| `cancel-error` (제안) | 서버가 거부(그사이 송장 출력·이미 처리됨 등) | 창 아래 빨간 줄. 송장이 출력됐으면 「송장이 이미 출력돼 승인을 취소할 수 없습니다. 1:1 문의로 알려 주세요.」, 그 밖은 서버가 준 문구 | 닫기 | 목록 새로 읽음 |

- 버튼이 보이는지·창이 어느 문구인지는 서버가 준 값(취소 가능·도착한 상자 수·기한)으로만 정한다. 저장할 때는 서버가 다시 판정한다(approval-cancel INV-AC1·AC4) — 창을 연 사이 상자가 도착하면 서버 판정(거절)이 이긴다. 그때는 `cancel-error` 대신 결과를 그대로 보여 준다.
- 취소한 뒤 화면을 옮기지 않는다 — 보던 화면에 그대로 두고 목록만 새로 읽는다(사이드바 「지금 할 일」 숫자가 늘어 돌아간 것이 보인다). 사용자 결정 2026-11-02.
- 확인 창에는 받지 않기 확인 창처럼 팬 이름·선물 종류·상자·주문번호를 함께 보인다. 오류 줄은 사이트의 기존 오류 줄 모양(느낌표 원 + 글자)이고, 오류 때는 「닫기」만 남는다.
- 「승인 취소」 버튼은 송장이 출력된 뒤에는 보이지 않는다. 이미 출고된 주문의 줄도 마찬가지다.

## 팬 화면 — 바뀌는 것 (`/gifts/[orderNo]`, 팬 선물 목록)

| 상태 | 조건 | 보이는 것 |
|---|---|---|
| 입고 전 취소 뒤 (제안) | 승인이 한 번 있었고 지금 대기 | 배지 「승인 대기」. 받는 주소는 그대로 보인다(INV-AC6) — 「먼저 보내기」 안내는 다시 나오지 않는다. 팬의 나머지 동작(송장번호·취소하기)은 「보내 주세요」와 같다 |
| 입고 뒤 취소 뒤 | 거절로 끝남 | 지금 「거절」 상태 그대로(같은 환불 안내·같은 알림톡) |

- 입고 전 취소는 팬에게 알림톡을 보내지 않는다(제안 — 상태가 대기로 돌아갈 뿐이고, 크리에이터가 다시 고르면 그 결과 알림이 간다).

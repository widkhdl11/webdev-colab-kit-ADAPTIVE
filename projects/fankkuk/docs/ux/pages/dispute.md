# 분쟁 처리 안내 UX 명세 — `/dispute`

> 2026-10-23 문서형 페이지 1단계. 코드를 읽고 **지금 구현된 그대로** 적었다. 고칠 점은 `_diff-guide.md` 에 따로 있다.
> 그리는 코드: `src/app/(site)/dispute/page.tsx` → `src/widgets/legal/ui/legal-page.tsx` · 글 `src/widgets/legal/model/dispute-doc.ts`(`disputeDoc()`).

## 페이지 브리프

1. 목적: 선물이나 환불 때문에 생긴 불만을 어디에 알리고, 팬꾹이 어떤 순서로 처리하는지 한 주소에서 확인한다.
2. 주 사용자 / 부 사용자: 팬 / 크리에이터 (둘 다 같은 조를 읽는다)
3. 사용자가 와서 하려는 일: 문제가 생겼을 때 어디에 알리는지 찾는다, 상자가 없어지거나 부서지면 어떻게 되는지 본다.
4. 방문 빈도: 문제가 생겼을 때 한 번
5. 페이지 유형: 문서형 — 읽기만 하고 입력이 없다
6. 같은 유형의 다른 페이지: 이용 안내 두 글·검수 기준·보안 안내·요금 안내(같은 틀), 약관 세 글, 자주 묻는 질문
7. 이 페이지만의 특이점: 연락처는 사이트 정보 상수(`SITE_INFO`)에서 읽는다(`dispute-doc.ts:10`). 아직 정해지지 않은 값 넷이 화면에 「[확인 필요: …]」로 보인다(`dispute-doc.ts:45·90·91·107`).
8. 바꾸면 안 되는 것: 글 내용, 요약 세 줄, 한국소비자원 안내

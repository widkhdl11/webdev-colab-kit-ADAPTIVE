# 팬 이용 안내 UX 명세 — `/guide/fan`

> 2026-10-23 문서형 페이지 1단계. 코드를 읽고 **지금 구현된 그대로** 적었다. 고칠 점은 `_diff-guide.md` 에 따로 있다.
> 그리는 코드: `src/app/(site)/guide/fan/page.tsx` → `src/widgets/legal/ui/legal-page.tsx`(안내 글 틀) · 글 `src/widgets/legal/model/guide-fan-doc.ts`.

## 페이지 브리프

1. 목적: 팬이 선물을 등록하고 상자를 보내는 순서, 요금, 상자가 돌아오는 경우를 가입 전에도 한 주소에서 확인한다.
2. 주 사용자 / 부 사용자: 팬(가입 전 포함) / 고객센터 답변에서 이 글을 가리키는 운영자
3. 사용자가 와서 하려는 일: 보내는 순서를 확인한다, 받는 주소 끝 6자리가 무엇인지 안다, 거절되거나 돌려보내면 어떻게 되는지 본다. (지시 표의 「팬꾹코드」는 글과 용어집에 없는 말이다 — 글은 「받는 주소 6자리」라고 쓴다, `guide-fan-doc.ts:47~62`)
4. 방문 빈도: 처음 보내기 전 한 번, 문제가 생겼을 때 한 번
5. 페이지 유형: 문서형 — 읽기만 하고 입력이 없다
6. 같은 유형의 다른 페이지: 크리에이터 이용 안내·검수 기준·보안 안내·분쟁 처리 안내·요금 안내(같은 안내 글 틀), 약관 세 글(policy-page), 자주 묻는 질문(faq-page)
7. 이 페이지만의 특이점: 요금 조의 금액은 결제와 같은 DB 공개 요금표를 읽는다(`page.tsx:16`). 조가 10개로 안내 글 중 두 번째로 길다.
8. 바꾸면 안 되는 것: 글 내용(문장), 요약 세 줄, 요금 숫자를 코드에 쓰지 않는 것

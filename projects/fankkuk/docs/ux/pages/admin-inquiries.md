# 1:1 문의(운영자) UX 명세 — `/admin/inquiries`

이번에 바꾸는 것은 **대표에게만 보이는 「회원 탈퇴」 칸 하나를 더하는 것**이다. 문의 목록·상세·답 달기(지금 모습)는 건드리지 않는다.

## 페이지 브리프

1. 목적: 운영자가 1:1 문의를 읽고 답하며, 탈퇴 신청을 받은 대표가 그 자리에서 탈퇴를 처리한다
2. 주 사용자 / 부 사용자: 대표 / 직원
3. 사용자가 와서 하려는 일: 새 문의에 답하고, 탈퇴 문의면 그 회원을 탈퇴 처리한다
4. 방문 빈도: 하루 여러 번
5. 페이지 유형: 관리형 — 목록과 처리 동작
6. 같은 유형의 다른 페이지: 결제·환불(`/admin/payments` — 「크리에이터 사정 취소」 칸이 같은 꼴)
7. 이 페이지만의 특이점: 탈퇴 신청이 1:1 문의로 들어오므로 처리 칸을 여기 둔다
8. 바꾸면 안 되는 것: 문의 목록·상세·답 달기의 위치와 순서

## 상태표 (「회원 탈퇴」 칸)

| 상태(코드 식별자 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `closed` (제안) | 대표 로그인, 처음 | 칸 제목 「회원 탈퇴」 · 「회원 탈퇴 처리하기」 버튼 | 열기 | `open` |
| `open` (제안) | 버튼을 누름 | 아이디 칸 · 「탈퇴 처리」 · 「닫기」 | 아이디 입력 · 탈퇴 처리 · 닫기 | `confirm` / `closed` |
| `confirm` (제안) | 아이디를 적고 「탈퇴 처리」 | 「(아이디) 계정을 탈퇴 처리할까요? 되돌릴 수 없어요.」 · 「탈퇴 처리」 · 「취소」 | 확정 · 취소 | `done` 또는 `error` / `open` |
| `done` (제안) | 처리됨 | 칸 제목 · 「(아이디) 계정을 탈퇴 처리했어요.」 · 「회원 탈퇴 처리하기」 버튼 · (사진 파일을 못 지웠을 때만) 안내 한 줄 | 다시 열기 | `open` |
| `error` (제안) | 아이디 형식 오류(화면에서 바로) · DB 거절(없는 회원 · 진행 중인 선물 · 권한) | `open` 의 요소 + 거절 문장 한 줄 | 고쳐서 다시 · 닫기 | `confirm` / `closed` |
| (없음) | 직원 로그인 | 칸 자체가 없다 | — | — |

## 요소 목록

| 요소 | 보이는 상태 | 정상 경로 / 예외 경로 | 근거 |
|---|---|---|---|
| 「회원 탈퇴」 칸 | 대표일 때 모든 상태 | 정상(대표) | admin-console 의 대표 전용 칸(문의 제한 버튼)과 같은 조건 |
| 아이디 칸 | open · error | 정상 | 탈퇴 신청한 사람을 아이디로 고른다(INV-A15) |
| 확인 문장 | confirm | 예외 | 되돌릴 수 없는 처리라 한 번 더 묻는다 |
| 사진 안내 한 줄 「탈퇴는 처리됐지만 사진을 지우지 못했어요. 개발 담당에게 알려 주세요.」 | done(사진을 못 지웠을 때만) | 예외 | 탈퇴는 됐지만 공개 저장소의 사진이 남아 누구나 열 수 있다 — 대표가 알아야 손으로 지운다(2026-10-23 ux 리뷰 반영) |
| 거절 문장 | error | 예외 | 「아이디를 영문 소문자·숫자·밑줄 4~30자로 적어 주세요.」(형식) · 「진행 중인 선물이나 역조공이 있어 탈퇴할 수 없어요. 먼저 끝내 주세요.」 등 |

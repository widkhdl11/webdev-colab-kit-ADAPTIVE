# 문서형 정돈 2단계 차이 목록 — `/faq` · `/report`

> 2026-10-23. 명세: `docs/ux/pages/faq.md` · `docs/ux/pages/report.md`. 기준: `docs/ux/document-pages.md`(원칙 ①~⑥, 기준 1~11). principles.md 없음 — 받은 뒤 대조.
> 「크기」는 셋 중 하나: 추가(없던 요소를 넣음) · 숨김(있던 요소를 조건부로 숨기거나 뺌) · 구조(데이터 모양이나 배치 틀을 바꿈).
> 여러 문서형 페이지에 같이 있는 문제(검색·분류·anchor 등)는 공통 컴포넌트 묶음에서 한 번 더 모인다. 여기서는 이 두 화면 몫만 적는다.

해당 없음: 원칙 ①②③④⑤⑥, 기준 1·2·3·4·5·6·7·11 — 찾아갈 섹션이 없는 양식 한 장이다. 지킨 것: 기준 8·10.

### document-pages 밖이지만 이미 승인된 차이 (design-rules 28절, 아직 구현 안 됨)

같은 작업에서 같이 고칠 것이라 적어 둔다. 기준은 document-pages 가 아니라 design-rules 28절과 part7 진단 10절이다.

| 요소 | 지금 | 승인된 모습 | 크기 |
|---|---|---|---|
| 요약 판 | 하늘 판 세 줄(`report-page.tsx:29-36`) | 판을 없앤다 | 숨김 |
| 요약 첫 줄 | 머리 설명과 같은 말(`report-page.tsx:8` vs `:25-27`) | 뺀다 | 숨김 |
| 「이메일 앱이 열려요」 줄 | 버튼에서 약 690px 위 판 안(`report-page.tsx:9`) | 버튼 바로 위(문장 그대로) | 구조(위치) |
| 주소를 묻지 않는다는 줄 | 판 셋째 줄(`report-page.tsx:10`) | 머리 아래 한 줄 | 구조(위치) |

`/faq` 쪽 28절 차이(「먼저 알아 두세요」 판 모양 · 첫 줄 펼침)는 위 1절의 요약 줄 연결·답 폭과 같은 자리를 고친다 — 둘을 함께 정해야 판을 두 번 바꾸지 않는다.

## 4. 질문 분류 초안 (4단계 데이터 표의 출발점 — 확정 아님)

분류 넷: 팬 · 크리에이터 · 결제·환불 · 배송. 한 질문이 둘에 걸치면 주 분류를 앞에 둔다.

| 줄 | 질문 | 분류(주 / 부) | 이유 |
|---|---|---|---|
| `faq-doc.ts:27` | 요금은 얼마인가요? | 결제·환불 / 팬 | 상자 요금 |
| `faq-doc.ts:31` | 크리에이터에게 도착하기까지 얼마나 걸리나요? | 배송 / 팬 | 입고부터 출고까지 기간 |
| `faq-doc.ts:35` | 크리에이터가 거절하면 어떻게 되나요? | 결제·환불 / 팬 | 답의 대부분이 돌려드리는 금액 |
| `faq-doc.ts:39` | 크리에이터에게 가는 송장번호를 볼 수 있나요? | 배송 / 팬 | 출고 송장 |
| `faq-doc.ts:43` | 받는 주소가 왜 상자마다 다른가요? | 배송 / 팬 | 받는 주소 6자리 |
| `faq-doc.ts:47` | 받는 주소 없이 보냈어요. | 배송 / 팬 | 상자 찾기 |
| `faq-doc.ts:51` | 크리에이터는 선물을 어떻게 승인하나요? | 크리에이터 | 승인 절차 |
| `faq-doc.ts:55` | 도착해서 잰 크기가 등록한 것보다 크면요? | 결제·환불 / 팬 | 차액 결제 |
| `faq-doc.ts:59` | 역조공을 보내는 데 얼마가 드나요? | 크리에이터 / 결제·환불 | 크리에이터가 결제하는 요금 |

치우침: 「팬」이 주 분류인 질문은 0개이고 부 분류로만 일곱 번 나온다. 넷 중 「팬」 칩은 걸러 주는 것이 거의 없다 — 팬·크리에이터(누구) 축과 결제·환불·배송(주제) 축을 따로 두는 편이 맞는지 4단계에서 정한다.

# 팬에게 보내기 — 선물함 흐름 (`/creator/revgifts/new` 와 그 뒤)

근거: 사용자 확정문(2026-11-07 대화에 붙여 넣음 — 「「팬에게 보내기」 화면 흐름 확정」 17항). 이 확정문은 앞선 대화에서 받았지만
레포 어디에도 기록되지 않았다(11-07 확인: 문서·커밋·stash·브랜치·Claude·Codex 대화 기록 모두 없음). 이 명세가 그 첫 기록이다.
확정문에 있는 것은 「확정」, 지금 규칙과 부딪히거나 확정문에 없던 것은 맨 아래 「정한 것」(11-07 비교 시안에서 받은 답)과 「아직 정할 것」에 모았다 — 「아직 정할 것」이 비기 전에는 승인하지 않는다.

## 페이지 브리프

1. 목적: 크리에이터가 팬 여러 명에게 보낼 선물을 큰 상자 하나로 팬꾹에 보내고, 팬꾹이 열어 팬마다 발송한다
2. 주 사용자: 크리에이터 · 부 사용자: 신청하는 팬(신청 화면), 사무실(실측·나눠 보내기)
3. 사용자가 와서 하려는 일: 선물함을 만들어 신청을 받고 → 마감하고 → 팬마다 상자 크기를 고르고 → 큰 상자를 보내고 → 실측 명세서를 보고 한 번 결제한다
4. 방문 빈도: 선물함 하나에 여러 번(만들 때·마감할 때·결제할 때), 크리에이터당 한 달 몇 번
5. 페이지 유형: 작업형(주) · 문서형(부 — 1페이지 설명)
6. 같은 유형의 다른 페이지: 선물 보내기(`/send`), 처리할 일(`/creator/actions`)
7. 이 페이지만의 특이점: 결제가 맨 끝이다(실측 뒤 1회). 그 전까지 금액은 모두 「예상」이다
8. 바꾸면 안 되는 것: 크리에이터는 팬 주소·실명·번호를 어떤 경로로도 받지 못한다(reverse-gift INV-R8) · 팬꾹이 크리에이터 대신 방문수거를 신청하지 않는다(주소를 여는 범위를 넓히지 않는다) · 미리 결제 버튼을 두지 않는다

## 지금 모습 (역진단, 2026-11-07 코드·스펙 기준)

| 단계 | 지금 |

## 상태 전이표 — 선물함 하나

선물함 = 보내기 하나. 이름은 모두 「제안」(states.md 에 없음).

| 상태(코드 / 화면 표기) | 들어오는 조건 | 크리에이터에게 보이는 것 | 크리에이터가 할 수 있는 것 | 다음 상태 |
|---|---|---|---|---|
| `explain`(제안) / 설명 | 「팬에게 보내기」를 처음 누름 | 1페이지 전체 | 이해했어요, 진행하기 | `open` |
| `open`(제안) / 신청 받는 중 | 선물함을 만듦(이름 · 받을 인원 1~100 · 공개/비공개) | 신청 관리 창 — 신청한 팬 목록·수 / 받을 인원 | 검색 · 체크로 제외·다시 넣기 · 초대 링크 복사 · 마감 · 선물함 취소 | `closed` · 취소(끝) |
| `closed`(제안) / 마감 · 상자 고르기 | 마감 누름(제외 안 된 신청 1명 이상) | 2페이지: 팬마다 구간 칸, 일괄 버튼, 예상 금액 | 구간 고르기 · 다음 | `awaiting_box` |
| `awaiting_box`(제안) / 상자 보내 주세요 | 2페이지 「다음」 | 3페이지: 담는 법 그림, 번호 라벨 PDF, 팬꾹 수령 주소(6자리 포함)·복사, 방문수거 안내, 「실측 후 결제 요청」 문장 | 라벨 받기 · 주소 복사 | `arrived` |
| `arrived`(제안) / 도착 · 실측 중 | 사무실이 큰 상자 입고 스캔 | 「팬꾹에 도착했어요. 실측 중이에요」 | — | `invoiced` · `held` |
| `held`(제안) / 확인 필요 | 닉네임이 신청 목록과 맞지 않는 선물이 있음 | 처리할 일에 카드 한 장 — 선물함 이름 · 선물 사진 · 「작성한 닉네임」 · 「팬 선택하기」(확정 13, 정한 것 ⑧) | 팬 선택하기 · 확인 | `invoiced` |
| `invoiced`(제안) / 결제 요청 | 모든 선물 실측 끝 | 4페이지: 명세서(팬별 구간·택배비·서비스료·합계), 결제 기한(3일) | 결제 | `paid` · `overdue` |
| `overdue`(제안) / 결제 기한 지남 | 결제 요청 뒤 3일 | 명세서 + 「7일째 착불로 돌려보냅니다」 한 줄 | 결제 | `paid` · `returning` |
| `returning`(제안) / 착불 반송 | 결제 요청 뒤 7일째 미결제 | 「결제가 없어 착불로 돌려보냈어요」 | — | 끝 |
| `paid`(제안) / 발송 중 | 결제 완료 | 팬마다 송장·배송 상태 | — | `done` |
| `done`(제안) / 끝 | 모든 팬 상자 배송 완료 | 팬마다 결과 | — | 끝 |

선물(팬 한 명 몫)마다: `applied` 신청 → (`excluded` 제외) → `in_box` 큰 상자에 담김 → `measured` 실측(구간 확정) → `shipped` 발송 → `delivered` 배송 완료.
실측 구간이 크리에이터가 고른 구간과 다르면 명세서에는 실측 구간으로 적는다(「입고 실측 후 확정됩니다」 — 확정 10).

## 화면별 상태표

### 1페이지 — 설명 (확정 4~7)

| 상태 | 조건 | 보이는 요소 | 가능한 동작 | 다음 |
|---|---|---|---|---|
| `explain` | 첫 진입 | 그림 하나(크리에이터 → 팬꾹 → 팬) · 왼쪽 「직접 보낼 때」(팬마다 주소 받기·포장·접수를 팬 수만큼) · 오른쪽 「팬꾹」(닉네임 적은 선물을 큰 상자 하나에 담아 보내면 팬꾹이 열어 팬마다 발송) · 「큰 상자를 팬꾹으로 보내는 택배비는 팬꾹 결제와 별도(크리에이터 부담, 착불 가능)」 · 준비물(닉네임을 적거나 라벨을 붙인 선물, 큰 상자, 팬꾹 수령 주소) · 「이해했어요, 진행하기」 | 진행하기 | 선물함 만들기 |

### 2페이지 — 상자 선택 (확정 8~12)

| 상태 | 조건 | 보이는 요소 | 가능한 동작 | 다음 |
|---|---|---|---|---|
| `tier_empty` | 마감 직후, 아무 구간도 안 고름 | 신청한 팬 목록(닉네임) · 팬마다 구간 칸(3kg·5kg·7kg·10kg·15kg·20kg) · 구간별 상자 그림(그림마다 세 변 합·무게) · 실측 예시 그림(세 변 합 재는 법) · 「전부 3kg」「전부 5kg」 · 요금표(3kg 80cm 4,300 / 5kg 100cm 4,800 / 7kg 100cm 5,300 / 10kg 120cm 6,300 / 15kg 120cm 7,300 / 20kg 120cm 8,300원, 무게와 크기 중 큰 쪽 — 정한 것 ⑤) · 예상 금액 0 · 「다음」 비활성 | 구간 고르기 · 일괄 | `tier_partial` · `tier_full` |

| `tier_full` | 모두 고름 | 예상 금액 = 택배비 합 + 서비스료(정가 700원, 초기 크리에이터 300원·월 30건) · 옆에 작게 「입고 실측 후 확정됩니다」 · 「다음」 | 바꾸기 · 다음 | 3페이지 |

요금표 값은 설정표에서 읽는다(확정 11). 택배사 계약 단가(원가)는 크리에이터에게 보이지 않는다(확정 17).

| ③ | 팬 주소를 언제 받나 | 신청 = 받기. 신청할 때 정보 입력 폼(받을 주소 포함)을 작성한다. 출고·반송 뒤 지우는 규칙은 그대로. 폼 항목은 아래 ⓐ |
| ④ | 요금 | 팬에게 보내기용 요금표가 따로 있고, 그 요금표는 택배비 구간 + 서비스료, 실측 뒤 결제다. 옛 소 5,400 · 중 6,900 · 대 7,400원 선결제는 없앤다 |
| ⑤ | 상자 구간 | 두 서비스의 구간을 따로 둔다(11-07 두 번째 지시가 첫 답 「공통 이름」을 대체). 팬에게 보내기 = 우체국 창구 등기소포 구간 그대로 + 300원, 이름은 무게로 — 3kg(80cm) 4,300 / 5kg(100cm) 4,800 / 7kg(100cm) 5,300 / 10kg(120cm) 6,300 / 15kg(120cm) 7,300 / 20kg(120cm) 8,300원, 무게와 크기 중 큰 쪽, 서비스료 별도, 160cm 초과는 받지 않는다. 요금 설정표에 우체국 요금 열을 두고 배포 전에 「팬꾹 요금 ≥ 우체국 요금」을 검사한다. 팬 선물 쪽은 ⓑ. 화면·요금표·약관·환불 규정·검수 화면의 구간 이름을 각 서비스 기준으로 바꾸고, 상자 그림에 세 변 합·무게를 적는다 |
| ⑥ | 결제 시점 | 실측 뒤 한 번 결제 · 기한 3일 · 7일째 착불 반송(확정 14·16). 등록 때 결제·24시간 닫기(INV-R15)는 없앤다 |
| ⑦ | 6자리 번호 | 아래 ⓒ(사용자 질문에 답하고 확인받는다) |
| ⑧ | 닉네임이 안 맞는 선물 | 처리할 일에 카드 한 장 — 선물함 이름 · 선물 사진 · 「작성한 닉네임」 · 「팬 선택하기」 · 확인. 「빼기」는 두지 않는다(이미 팬꾹에 와 있는 선물이다) |
| ⑨ | 받을 인원 | 크리에이터가 선물함을 만들 때 1~100명에서 정한다. 팬꾹으로 보내는 상자는 크리에이터가 구해서 보낸다. 상자가 여러 개일 때는 아래 ⓓ. 마감은 제외 안 된 신청 1명 이상일 때, 마감 전에는 선물함 취소 가능(결제 전이라 환불 없음) |
| ⑩ | 요금 변경 공지 | 요금 설정의 적용 날짜는 자유로 고르고, 오늘부터 30일 안이면 저장 전에 경고만 띄운다. 30일 전 공지(확정 17)는 운영자가 지키는 규칙으로 남는다 |

## 아직 정할 것

| # | 무엇 | 추천 |
|---|---|---|
| ⓐ | 신청 폼 항목 | 받을 주소(내 주소록에서 고르기·새로 입력) · 받는 분 이름 · 연락처는 가입 번호를 그대로 쓴다. 크리에이터에게는 닉네임만 보인다. 판단 |
| ⓑ | 팬에게 보내기 121~160cm 상자 | 지시는 「160cm 초과는 받지 않는다」인데 구간표는 120cm 에서 끝나, 121~160cm 상자가 들어갈 구간이 없다. 우체국 표의 다음 구간(160cm)을 같은 방식(+300원)으로 더할지, 120cm 초과를 받지 않을지 정한다. 금액은 사용자가 준다(추측해 적지 않는다) |
| ⓒ | 6자리 번호 | 수령 주소 6자리는 선물함마다 하나. 번호 라벨 PDF 에 팬마다 바코드(사이트가 만든 번호)를 찍어, 사무실이 선물마다 스캔해 팬을 찾는다 — 지금 몫마다 6자리가 하던 일을 라벨이 대신한다. 손글씨 닉네임은 사무실이 신청 목록에서 닉네임으로 찾고, 안 맞으면 ⑧ 카드. 판단 |
| ⓓ | 상자가 여러 개일 때 | 같은 주소(6자리)로 몇 상자든 보낸다. 3페이지에서 「보낸 상자 수」를 적게 하고, 그 수만큼 들어오고 제외 안 된 팬 몫이 모두 실측되면 결제 요청. 첫 상자 도착 뒤 7일 안에 안 온 몫은 「도착 안 함」으로 빼고 나머지만 결제 요청. 판단 |

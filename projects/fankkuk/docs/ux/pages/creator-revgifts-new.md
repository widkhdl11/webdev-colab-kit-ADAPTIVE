# 팬에게 보내기 — 선물함 흐름 (`/creator/revgifts/new` 와 그 뒤)

근거: 사용자 확정문(2026-11-07 대화에 붙여 넣음 — 「「팬에게 보내기」 화면 흐름 확정」 17항). 이 확정문은 앞선 대화에서 받았지만
레포 어디에도 기록되지 않았다(11-07 확인: 문서·커밋·stash·브랜치·Claude·Codex 대화 기록 모두 없음). 이 명세가 그 첫 기록이다.
확정문에 있는 것은 「확정」, 지금 규칙과 부딪히거나 확정문에 없는 것은 맨 아래 「정할 것」에 모았다 — 그 표의 답이 나오기 전에는 승인하지 않는다.

## 페이지 브리프

1. 목적: 크리에이터가 팬 여러 명에게 보낼 선물을 큰 상자 하나로 팬꾹에 보내고, 팬꾹이 열어 팬마다 발송한다
2. 주 사용자: 크리에이터 · 부 사용자: 신청하는 팬(신청 화면), 사무실(실측·나눠 보내기)
3. 사용자가 와서 하려는 일: 선물함을 만들어 신청을 받고 → 마감하고 → 팬마다 상자 크기를 고르고 → 큰 상자를 보내고 → 실측 명세서를 보고 한 번 결제한다
4. 방문 빈도: 선물함 하나에 여러 번(만들 때·마감할 때·결제할 때), 크리에이터당 한 달 몇 번
5. 페이지 유형: 작업형(주) · 문서형(부 — 1페이지 설명)
6. 같은 유형의 다른 페이지: 선물 보내기(`/send`), 처리할 일(`/creator/actions`)
7. 이 페이지만의 특이점: 결제가 맨 끝이다(실측 뒤 1회). 그 전까지 금액은 모두 「예상」이다
8. 바꾸면 안 되는 것: 크리에이터는 팬 주소·실명·번호를 어떤 경로로도 받지 못한다(reverse-gift INV-R8) · 팬꾹이 크리에이터 대신 방문수거를 신청하지 않는다(주소를 여는 범위를 넓히지 않는다) · 미리 결제 버튼을 두지 않는다

## 상태 전이표 — 선물함 하나

선물함 = 보내기 하나. 이름은 모두 「제안」(states.md 에 없음).

| 상태(코드 / 화면 표기) | 들어오는 조건 | 크리에이터에게 보이는 것 | 크리에이터가 할 수 있는 것 | 다음 상태 |
|---|---|---|---|---|
| `explain`(제안) / 설명 | 「팬에게 보내기」를 처음 누름 | 1페이지 전체 | 이해했어요, 진행하기 | `open` |
| `open`(제안) / 신청 받는 중 | 선물함을 만듦 | 신청 관리 창 — 신청한 팬 목록·수 | 검색 · 제외 · 초대 · 마감 | `closed` · (취소 — 정할 것 ⑨) |
| `closed`(제안) / 마감 · 상자 고르기 | 마감 누름(신청 1명 이상 — 정할 것 ⑨) | 2페이지: 팬마다 구간 칸, 일괄 버튼, 예상 금액 | 구간 고르기 · 다음 | `awaiting_box` |
| `awaiting_box`(제안) / 상자 보내 주세요 | 2페이지 「다음」 | 3페이지: 담는 법 그림, 번호 라벨 PDF, 팬꾹 수령 주소(6자리 포함)·복사, 방문수거 안내, 「실측 후 결제 요청」 문장 | 라벨 받기 · 주소 복사 | `arrived` |
| `arrived`(제안) / 도착 · 실측 중 | 사무실이 큰 상자 입고 스캔 | 「팬꾹에 도착했어요. 실측 중이에요」 | — | `invoiced` · `held` |
| `held`(제안) / 확인 필요 | 닉네임이 신청 목록과 맞지 않는 선물이 있음 | 맞지 않는 선물 줄과 고르는 칸(확정 13 — 화면은 정할 것 ⑧) | 팬 고르기 · 제외 | `invoiced` |
| `invoiced`(제안) / 결제 요청 | 모든 선물 실측 끝 | 4페이지: 명세서(팬별 구간·택배비·서비스료·합계), 결제 기한(3일) | 결제 | `paid` · `overdue` |
| `overdue`(제안) / 결제 기한 지남 | 결제 요청 뒤 3일 | 명세서 + 「7일째 착불로 돌려보냅니다」 한 줄 | 결제 | `paid` · `returning` |
| `returning`(제안) / 착불 반송 | 결제 요청 뒤 7일째 미결제 | 「결제가 없어 착불로 돌려보냈어요」 | — | 끝 |
| `paid`(제안) / 발송 중 | 결제 완료 | 팬마다 송장·배송 상태 | — | `done` |
| `done`(제안) / 끝 | 모든 팬 상자 배송 완료 | 팬마다 결과 | — | 끝 |

선물(팬 한 명 몫)마다: `applied` 신청 → (`excluded` 제외) → `in_box` 큰 상자에 담김 → `measured` 실측(구간 확정) → `shipped` 발송 → `delivered` 배송 완료.
실측 구간이 크리에이터가 고른 구간과 다르면 명세서에는 실측 구간으로 적는다(「입고 실측 후 확정됩니다」 — 확정 10).

## 정할 것 — 확정문에 없거나 지금 규칙과 부딪히는 것

추천은 각 줄 끝. 「표준」은 업계에서 흔한 방식, 「판단」은 이 사이트 사정에 맞춘 내 판단이다.

| # | 무엇 | 지금 규칙 | 추천 |
|---|---|---|---|
| ① | 신청 관리 창의 내용 — 확정문은 「앞서 정한 대로」인데 그 내용이 기록에 없다 | 없음 | 팬 목록(닉네임·신청 시각) · 닉네임 검색 · 마감 전 제외 · 초대 링크 복사 · 마감(확인 창 한 번). 판단 — 받은 내용이 있으면 그것으로 바꾼다 |
| ② | 누가 신청할 수 있나, 팬 신청 화면은 어떻게 생겼나 | 크리에이터가 팔로워 목록에서 체크로 고름(INV-R2) | 나를 팔로우한 팬만 초대 링크로 신청. 판단 — 모르는 사람에게 보내는 길을 열지 않는다 |
| ③ | 팬 주소를 언제 받나 | 팬이 「받기」를 누를 때, 등록 주소를 복사(INV-R4) | 신청할 때 받기를 겸한다(신청 = 받기). 출고·반송 뒤 지우는 규칙은 그대로. 판단 |
| ④ | 요금 | 소 5,400 · 중 6,900 · 대 7,400, 등록 때 선결제(PRODUCT·INV-R3) | 이 흐름은 확정문 요금(택배비 + 서비스료)으로 바꾸고 옛 요금은 없앤다. 판단 — 흐름이 하나라 요금도 하나여야 한다 |
| ⑤ | 상자 구간 정의 | 대형 = 세 변 합 160cm·20kg(팬 선물과 같음) | 팬에게 보내기는 확정문 구간(소 80·중 100·대 120cm 10kg·특대 120cm 20kg)을 따로 쓴다. 팬 선물 구간은 그대로. 판단 |
| ⑥ | 결제 시점과 지금 닫기 규칙 | 등록 때 결제, 24시간 결제 대기면 닫음(INV-R15) | 실측 뒤 1회 결제, 기한 3일, 7일째 착불 반송(확정 14). INV-R15 는 없앤다 |
| ⑦ | 팬꾹 수령 주소의 6자리 | 몫(상자)마다 6자리 | 큰 상자 하나에 6자리 하나, 안의 선물은 닉네임·번호 라벨로 가른다. 판단 |
| ⑧ | 닉네임 불일치 보류 화면 | 없음 | 처리할 일에 카드 한 장 — 맞지 않는 선물 사진·적힌 글자와 신청 팬 고르기. 판단 |

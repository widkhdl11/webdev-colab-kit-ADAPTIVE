# 선물함 신청 UX 명세 — `/gift-boxes/[boxId]` (비공개는 `?invite=<토큰>`)

근거: 선물함 흐름 명세 `creator-revgifts-new.md` 의 「정한 것 ②·③·ⓐ」, 스펙 `revgift-box.md` 정할 것 Q5·Q6.
2026-11-08 선물함 2부 구현 때 팬 쪽 화면이 명세에 없어 새로 적었다. 받을 주소 칸은 역조공 받기 판(`/gifts/RG-…` 의 받기 칸)과 같은 흐름이다.
2026-11-08 팬 주소 등록을 없앴다(DECISIONS 같은 날) — 「받을 주소 확인」 상태를 빼고, 신청할 때마다 받는 분 이름·휴대폰 번호·주소를 입력한다.
2026-11-09 대기 신청 — 받을 인원이 다 차면 신청은 대기로 들어간다(revgift-box INV-GB5 개정 초안, DECISIONS 2026-11-09 「선물함 대기자」). 같은 폼·같은 주소 입력이고, 버튼과 결과만 바뀐다.
사용자 승인 전이다 — 승인되면 approved.

## 페이지 브리프

1. 목적: 팔로우한 크리에이터의 선물함에 받을 주소를 내고 신청한다
2. 주 사용자 / 부 사용자: 팬 / 없음(크리에이터·로그인 안 한 사람은 안내만)
3. 사용자가 와서 하려는 일: 크리에이터 상세의 입구나 초대 링크로 들어와 신청하고, 나중에 다시 와서 신청 상태를 본다
4. 방문 빈도: 선물함 하나에 한두 번
5. 페이지 유형: 작업형 — 할 일 하나(신청)
6. 같은 유형의 다른 페이지: 받은 역조공 상세의 받기 칸(`/gifts/RG-…`)
7. 이 페이지만의 특이점: 다른 신청자 수·닉네임·받을 인원·제외 여부가 보이지 않는다(정할 것 Q6). 대기 신청한 팬에게만 자기 대기 순번이 보인다(2026-11-09). 비공개 선물함은 토큰이 틀리면 없는 주소와 같다
8. 바꾸면 안 되는 것: 주소는 이 브라우저에서 봉인한 값만 보낸다(address-protection INV-P1·P17) · 크리에이터에게 주소를 보이지 않는다

## 적용한 규칙

- UX 기준 문서 `docs/ux/principles.md`·`docs/ux/task-pages.md` 가 아직 없다 — 같은 작업형인 받기 칸의 흐름을 따랐다.
- 주소는 신청할 때마다 입력하고, 신청한 순간의 봉인이 그 신청의 사본이 된다(INV-GB6). 설정에 저장해 둔 주소에서 고르는 길은 없다.

## 2026-11-09 바꿀 것 — 신청 폼을 모달 단계로 (사용자 「팬 신청폼도 모달로 자연스러운 흐름이 느껴지게」)

지금: 선물함 주소를 열면 주소·이름·번호 칸이 있는 폼이 페이지에 바로 펼쳐진다.

바뀐 뒤: 페이지는 선물함 소개(크리에이터 · 선물함 이름 — 신청 수·받을 인원·대기 수는 보이지 않는다, revgift-box 정할 것 Q6)와 「선물함 신청」(다 찼으면 「대기 신청」) 버튼 하나. 누르면 모달(휴대폰은 전체 시트)이 열리고 페이지 주소는 바뀌지 않는다.

|---|---|---|---|
| `apply_address` / 1/3 받을 주소 | 진행 표시 「1/3 · 다음: 받는 분」 · 우편번호+주소 검색 · 기본 주소 · 상세 주소 · 「주소는 입력한 기기에서 암호화해 전송합니다. {크리에이터}님에게는 공개하지 않습니다.」(지금 문구) | 다음 · 닫기 | `apply_person` |

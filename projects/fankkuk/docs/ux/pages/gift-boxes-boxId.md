사용자 승인 전이다 — 승인되면 approved.

## 페이지 브리프

1. 목적: 팔로우한 크리에이터의 선물함에 받을 주소를 내고 신청한다
2. 주 사용자 / 부 사용자: 팬 / 없음(크리에이터·로그인 안 한 사람은 안내만)
3. 사용자가 와서 하려는 일: 크리에이터 상세의 입구나 초대 링크로 들어와 신청하고, 나중에 다시 와서 신청 상태를 본다
4. 방문 빈도: 선물함 하나에 한두 번
5. 페이지 유형: 작업형 — 할 일 하나(신청)
6. 같은 유형의 다른 페이지: 받은 역조공 상세의 받기 칸(`/gifts/RG-…`)
7. 이 페이지만의 특이점: 다른 신청자 수·닉네임·받을 인원·제외 여부가 보이지 않는다(정할 것 Q6). 비공개 선물함은 토큰이 틀리면 없는 주소와 같다
8. 바꾸면 안 되는 것: 주소는 이 브라우저에서 봉인한 값만 보낸다(address-protection INV-P1·P17) · 크리에이터에게 주소를 보이지 않는다

## 상태표

| 상태(코드 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `guest`(제안) / 로그인 필요 | 로그인 안 함 | 머리 · 「로그인한 뒤 신청할 수 있습니다.」 · 로그인 버튼 | 로그인 | 로그인 뒤 이 화면 |
| `not_fan`(제안) / 팬 계정만 | 크리에이터·운영자 계정(주인 제외) | 머리 · 「팬 계정만 신청할 수 있습니다.」 | — | — |
| `owner`(제안) / 내 선물함 | 선물함 주인 | 머리 · 「내가 만든 선물함입니다.」 · 신청 관리 링크 | 신청 관리 | 신청 관리 창 |
| `not_follower`(제안) / 팔로우 필요 | 팔로우 안 함, 신청 없음, 신청 받는 중 | 머리 · 「팔로우한 팬만 신청할 수 있습니다.」 · 팔로우 버튼 | 팔로우 | `enter_address` |
| `enter_address`(제안) / 받을 주소 입력 | 팔로우함 · 신청 없음 · 신청 받는 중 | 머리 · 암호화 안내 한 줄 · 주소 입력 칸(받는 사람 이름·휴대폰 번호·주소) · 「신청」 | 신청 | `applied` |
| `applied`(제안) / 신청함 | 신청함(제외돼도 같음) · 신청 받는 중 | 머리 · 「신청했습니다.」 · 「신청 취소」 | 신청 취소(확인 창) | `enter_address` |
| `preparing`(제안) / 준비 중 | 마감 때 담긴 팬 | 머리 · 「선물이 준비되고 있어요.」 | — | — |
| `closed`(제안) / 마감 | 마감됐고 담기지 않음(제외 포함) 또는 신청 없이 마감 | 머리 · 「이번 선물함은 마감됐어요.」 | — | — |
| `cancelled`(제안) / 취소 | 신청했던 선물함이 취소됨 | 머리 · 「선물함이 취소됐어요.」 | — | — |

머리 = 크리에이터 이름 + 선물함 이름. 없는 선물함·토큰이 틀린 비공개 선물함은 404 화면.

## 적용한 규칙

- UX 기준 문서 `docs/ux/principles.md`·`docs/ux/task-pages.md` 가 아직 없다 — 같은 작업형인 받기 칸의 흐름을 따랐다.
- 주소는 신청할 때마다 입력하고, 신청한 순간의 봉인이 그 신청의 사본이 된다(INV-GB6). 설정에 저장해 둔 주소에서 고르는 길은 없다.

# 선물함 출고·반송 UX 명세 — `/admin/work/gift-box-outbound`

근거: 선물함 흐름 명세 `creator-revgifts-new.md`(4페이지 결제 뒤 「송장 출력·발송」, 미결제 착불 반송), 스펙 `revgift-box.md` INV-GB19·GB20·Q16.
2026-11-09 선물함 4부 구현 때 새로 적었다. 사용자 승인 전이다 — 승인되면 approved.

## 페이지 브리프

1. 목적: 결제가 끝난 선물함의 선물마다 송장을 출력해 팬에게 보내고, 결제가 없어 돌려보내는 선물함을 반송한다
2. 주 사용자 / 부 사용자: 사무실 운영자(송장 출력은 대표만) / 없음
3. 사용자가 와서 하려는 일: 선물의 바코드를 스캔해 송장을 출력하고(수동 입력이면 운송장 번호를 넣고), 송장 바코드를 스캔해 출고한다. 반송 목록의 큰 상자 원 송장으로 착불 반송을 접수하고 반송 송장번호를 넣는다
4. 방문 빈도: 선물함 결제가 끝날 때마다 · 반송이 생길 때
5. 페이지 유형: 작업형
6. 같은 유형의 다른 페이지: 출고(`/admin/work/outbound`) · 선물함 입고·실측(`/admin/work/gift-boxes`)
7. 이 페이지만의 특이점: 사무실 상자 QR 이 아니라 선물의 바코드(신청 번호 GB…)로 불러온다. 주소는 송장을 출력한 그 응답에만 보이고, 다시 불러와도 나오지 않는다
8. 바꾸면 안 되는 것: 주소 열기는 대표만, 결제가 끝난 신청만, 한 신청에 3회(INV-GB20) · 상태를 고르는 칸이 없다(INV-GB1)

## 상태표

| 상태(코드 / 화면 표기) | 조건 | 보이는 요소 | 가능한 동작 | 다음 상태 |
|---|---|---|---|---|
| `idle`(제안) / 처음 | 화면을 엶 | 「출고」 칸(선물 바코드 · 불러오기) · 「착불 반송」 칸(목록 또는 「반송할 선물함이 없어요.」) | 불러오기 · 반송 확정 | `loaded` |
| `loaded`(제안) / 불러옴 | 바코드가 신청과 맞음 | 선물함 이름 · 선물함 상태 · 닉네임 · 신청 상태 · 실측 구간 · (불일치면) 「할증 지역 불일치」 · 결제 완료면 「송장 출력」(이미 출력했으면 「다시 출력」) | 송장 출력 | `printed` |
| `printed`(제안) / 출력함 | 대표가 출력 | 받는 사람 · 휴대폰 번호 · 주소(그 응답에만) · 수동 입력이면 운송장 번호 칸, 번호가 있으면 송장 바코드 칸 · 「출고 확정」 | 운송장 번호 저장 · 출고 확정 | `shipped` |
| `shipped`(제안) / 출고 | 송장 바코드가 맞음 | 「출고했어요.」, 신청 상태 「출고」 | 다음 선물 | `idle` |
| `returning`(제안) / 착불 반송 목록 | 결제 없이 168시간 지난 선물함, 또는 모든 신청이 도착 안 함인 선물함(명세서 없음, Q12)이 있음 | 줄마다 선물함 · 크리에이터 · 까닭(결제 없음 / 모두 도착 안 함) · 큰 상자 원 송장번호 · 반송 시작 · 반송 송장번호 칸 · 「반송 확정」 | 반송 확정 | 목록에서 빠짐 |

거부 문구(서버가 정한다): 결제 전 「결제가 끝난 신청만 송장을 출력할 수 있어요.」 · 횟수 「이 신청의 송장 출력 횟수(다시 출력 포함 3번)를 다 썼어요.」 · 직원 「송장 출력은 대표만 할 수 있어요.」 · 다른 송장 「이 신청의 송장이 아니에요.」

# 선물 보내기 UX 명세 — `/gifts/new`

> 2026-10-26 사용자 지시 「상자 선택시 합산 가격이 바로 나오는 사이드 섹션이 있으면 좋겠는데?」로 만든 초안.
> 이 화면의 슬러그 파일이 없어 규칙 6절대로 **지금 모습을 먼저** 적고(코드 `src/widgets/gift-register/ui/gift-register-page.tsx`·`src/features/gift-register/ui/register-form.tsx`, 개발 서버 화면 2026-10-26), 바꿀 것을 번호로 적었다.
> 시안: `docs/design/mockups/site/v41-user-fixes/gift-new-compare.html` (지금 / 바꾼 뒤, PC 1440 · 휴대폰 390).
> 이번에 바뀌는 것은 「금액이 언제 어디에 보이는가」 하나다. 단계 수·입력 항목·흐름은 그대로다.

## 페이지 브리프

1. 목적: 팔로우한 크리에이터에게 보낼 선물을 등록하고 결제한다 — 이 화면이 없으면 선물을 보낼 수 없다.
2. 주 사용자 / 부 사용자: 팬 / 크리에이터(크리에이터 계정도 같은 화면으로 선물을 보낸다).
3. 사용자가 와서 하려는 일: 받을 사람을 고르고, 선물을 적고, 상자 수를 정하고, 얼마인지 보고 결제한다.
4. 방문 빈도: 선물을 보낼 때마다 한 번. 대부분 크리에이터 페이지의 「선물 보내기」로 들어온다.
5. 페이지 유형: 작업형 — 4단계 입력을 끝내야 결과(결제)가 나온다.
6. 같은 유형의 다른 페이지: 팬에게 보내기(크리에이터 화면, 아래 결제 띠가 따라온다 — design-rules 25절 A).
7. 이 페이지만의 특이점: 결제 금액이 3단계(상자 수)에서 정해지는데, 지금은 4단계에서야 합계가 보인다.
8. 바꾸면 안 되는 것: 맨 위 하늘 단계 판(단계 숫자 48 · 네 칸 막대), 단계 순서와 각 단계의 입력 칸, 4단계 「이럴 때는 돌려보내 드려요」 회색 칸, 결제 버튼 글자 「N원 결제하기」.

## 지금 모습 (역진단)

- 폭 720 한 기둥. 위에 하늘 단계 판, 아래 흰 입력 판.
- 3단계: 소형·중형·대형 상자 칸(이름 · 크기 기준 · 한 상자 요금 · −/+ 수량). **합계는 어디에도 없다.** 몇 개를 고르든 얼마인지 알려면 4단계로 넘어가야 한다.
- 4단계: 확인 줄(받는 크리에이터·선물 종류·전자기기·상자) → 회색 안내 → 하늘 결제 칸(상자별 「소형 상자 1개 6,900원 × 1」 줄 · 합계 32 · 검수 포함 · 「배송비가 포함된 금액이에요…」 · 동의) → 「N원 결제하기」.
- 1·2단계: 금액 표시 없음.
- 문구: 3단계 설명 「상자마다 배송비가 포함돼 있어요」, 결제 칸 아래 「배송비가 포함된 금액이에요」 — 용어집 6절은 팬 화면에서 「배송비」를 쓰지 않고 「택배비」로 쓴다.
- design-rules 25절(v39 B안 승인)은 「1~3단계에 오른쪽 요약 칸을 새로 두지 않는다」고 정해 두었다. 이번 지시는 이 줄을 바꾼다.

## 적용한 규칙

- **UX 기준 문서 없음**: `docs/ux/principles.md` · `docs/ux/task-pages.md`. 작성할지는 따로 묻는다. 이번 판정은 승인된 design-rules 와 `states.md` 로 대신했다.
- design-rules 0000절 「카드를 왼쪽·오른쪽으로 늘어놓는 구성은 피한다 — 업계 표준이거나 꼭 필요한 경우만」: 주문서 오른쪽 요약은 업계 표준이라 예외에 든다.
- design-rules 21절 「한 화면에 강조 하나」: 「보낼 선물」 칸은 하늘 면이 아니라 흰 카드다(하늘 면은 단계 판).
- 벗어남: design-rules 25절 「1~3단계에 오른쪽 요약 칸을 새로 두지 않는다」 — 사용자 지시로 바꾼다. 승인되면 25절 그 줄을 고친다.
- 금액은 화면이 계산해 보이는 안내일 뿐이고 결제 금액은 서버가 등록 때 다시 계산한다(`features/gift-register/model/box-summary.ts` 주석 — payment INV-M1). 「보낼 선물」 칸도 같은 `summarizeBoxes` 결과를 그린다. 새 계산을 만들지 않는다.

## 스펙 참조

- `docs/specs/payment.md` INV-M1(결제 금액은 서버 계산) — 화면 합계는 안내.
- `docs/specs/creator-receiving.md` INV-B2·B6 — 미리 고른 크리에이터가 쉬는 중·한도일 때는 폼 대신 상태 카드(이때 「보낼 선물」 칸 없음).
- 요약 칸 자체는 「스펙 없음」(표시만, 규칙 없음).

## 바뀌는 것

1. PC(폭 1000 이상): 입력 기둥 오른쪽에 「보낼 선물」 칸(폭 288, 화면을 내려도 위에 붙어 따라옴). 입력 기둥 + 칸 = 1040(선물 상세와 같은 넓은 폭). 1~4단계 내내 같은 자리.
2. 휴대폰(폭 999 이하): 3단계에서만 화면 아래 합계 줄. 「다음」 버튼은 지금 자리 그대로.
3. PC 4단계: 금액 줄·합계는 「보낼 선물」 칸에만. 가운데 결제 칸은 검수 포함 · 안내 · 동의만. 결제 버튼 「N원 결제하기」는 그대로.
4. 문구: 「배송비」 → 「택배비」 두 곳(3단계 설명, 결제 칸 아래 줄).

## 정해 주실 것

- 오른쪽 칸을 언제 보일까 — ① 1~4단계 모두(추천: 단계를 넘겨도 입력 칸 폭이 그대로, 주문서 표준) ② 3·4단계만.
- 휴대폰 아래 줄에 「다음」 버튼도 — ① 합계만(추천: 바뀌는 것이 적고 버튼이 두 군데 생기지 않음) ② 합계 + 「다음」.

## 2. 새 기능 상세: 팬·크리에이터 화면 기능 (노출·재발송·크리에이터 부담 조절)

이 절의 기능은 세 가지 목적을 함께 만족시키기 위한 것이다. 1. 크리에이터가 링크를 붙이거나 팬이 자랑하는 순간마다 팬꾹이 자연스럽게 노출된다. 2. 팬이 다시 보내고 싶어진다. 3. 크리에이터가 받는 양과 품목을 부담 없이 조절한다. 어느 기능도 다른 팬과의 경쟁(순위·명단·금액 비교)을 만들지 않는다.

### 원칙 (기능을 추가할 때마다 이 표로 확인)

| 원칙 | 허용 | 금지 |
| --- | --- | --- |
| 노출은 사용자가 자기 이유로 공유할 때만 | 크리에이터가 링크를 붙임, 팬이 답장 카드를 공유함 | 방송 화면 오버레이, 팬꾹이 크리에이터에게 직접 보내는 홍보 알림 |
| 경쟁 대신 개인 기록 | 팬 본인만 보는 선물 수·답장 수·며칠째 | 공개 명단, 순위, 금액, 개인별 횟수 공개 |
| 공개는 양쪽 동의 | 팬 "공개 허용" + 크리에이터 "모음 보이기" 둘 다 켜졌을 때만 | 한쪽 설정만으로 공개 |
| 크리에이터 문구는 부드러운 고정 문구 | 품목·이유·기간을 골라 시스템이 문장 생성 | 자유 문장 입력, "○○ 사양합니다" 같은 거절형 문구, "받고 싶은 것" 목록 |
| 끊기면 잃는 구조 없음 | 쌓이기만 하는 기록 | 연속 기록(스트릭), 기한 내 안 보내면 사라지는 혜택 |
| 시점 노출 최소화 | 날짜 단위 표시, 공개는 수령 확인 며칠 뒤 | 실시간 도착 표시, 시각 단위 표시 |
| 어떤 공개 화면·이미지에도 | 크리에이터 닉네임, 프로필 사진, 크리에이터가 공개를 고른 항목 | 주소, 주문번호, 운송장, 팬 실명, 상자·송장이 찍힌 사진 |

### F-1. 선물 링크 페이지 (공개 화면)

- 주소: `fankkuk.kr/{닉네임}`. 닉네임은 영문·숫자·밑줄, 3~20자, 크리에이터가 설정에서 정하고 한 번 바꾸면 30일간 다시 못 바꾼다(링크 깨짐 방지). 이전 닉네임 주소는 90일간 새 주소로 넘겨준다.
- 화면 순서(위에서 아래):
  1. 프로필 사진(크게), 닉네임, 한 줄 소개(크리에이터 입력, 40자)
  2. 감사 문장: "보내주시는 마음 늘 감사해요" (고정)
  3. 받는 상태: "지금 선물을 받고 있어요" 또는 "잠시 선물 받기를 쉬고 있어요. {날짜}부터 다시 받을게요"
  4. 받기 어려운 품목 안내(F-3), 설정된 것이 있을 때만
  5. 다가오는 기념일 D-day(F-6), 30일 안에 있을 때만
  6. "이번 달 N명의 팬이 마음을 보냈어요" (숫자만, N이 0이면 줄 자체를 숨김)
  7. 주소 열람 기록 요약: "이번 달 주소 열람 {n}건, 모두 승인된 선물이에요" (decrypt_log와 승인 기록에서 계산. 승인 없는 열람이 1건이라도 있으면 이 문구를 내리고 운영자에게 경보)
  8. 감사 답장 모음(F-5), 양쪽 동의한 것만
  9. "선물 보내기" 버튼 (받는 상태가 쉬는 중이면 비활성 대신 "다시 받는 날 알림 받기"로 바뀜 — 알림은 백로그, 1차에서는 버튼 숨김)
- 표시하지 않는 것: 사무실 주소(승인 후 팬의 배송 현황에서만), 보낸 팬 명단, 금액, 선물 목록 전체.

### F-2. 링크 미리보기 이미지 (OG 이미지)

- 크리에이터마다 자동 생성. Next.js의 OG 이미지 생성 기능(`next/og`, 서버에서 이미지를 그려 주는 라우트)을 쓴다.
- 구성: 프로필 사진(가장 크게, 원형) + 닉네임 + "승인한 선물만 받습니다" 한 줄 + 팬꾹 로고. 배경은 대표색 계열 단색.
- 프로필 사진은 크리에이터가 팬꾹에 직접 올린 것만 쓴다. 방송 플랫폼에서 자동으로 가져오지 않는다.
- 업로드 이미지는 저장 전에 EXIF(촬영 위치 등)를 지우고, 정사각형으로 자른 뒤 저장한다.
- X·카카오톡은 미리보기를 캐시하므로 이미지 주소에 프로필 버전 값(`?v={profile_updated_at}`)을 붙인다.
- 완료 조건: 1. X와 카카오톡에 링크를 붙였을 때 프로필 사진이 들어간 미리보기가 뜬다. 2. 프로필 사진을 바꾸면 새 링크 붙여넣기에서 바뀐 사진이 뜬다. 3. 미리보기 이미지에 닉네임·사진·고정 문구·로고 외의 정보가 없다.

### F-3. 받기 어려운 품목 안내

- 목적: 크리에이터가 방송에서 "○○ 너무 많이 와서 곤란해요"라고 말하지 않아도 되게 하고, 팬이 거절당하기 전에 알게 한다.
- 크리에이터 입력(설정 화면):
  1. 품목: 등록 화면의 물품 종류와 같은 목록에서 여러 개 선택 (예: 인형·쿠션, 꽃, 의류, 향수·화장품, 대형 물품, 문구, 전자기기, 기타)
  2. 이유: 이미 많이 받았어요 / 보관할 곳이 부족해요 / 잠시 집을 비워요 / 이유 표시 안 함
  3. 기간: 1주 / 2주 / 한 달 / 직접 해제
  4. 동작: 안내만(기본값) / 등록 막기
- 생성 문구(고정 템플릿): "지금은 {품목들}을 받기 어려워요 ㅠㅠ {이유}" — 이유를 "표시 안 함"으로 고르면 앞 문장만. 크리에이터가 문장을 직접 쓰는 칸은 없다.
- 기간이 끝나면 자동으로 사라진다. 남은 기간은 크리에이터 설정 화면에만 보인다.
- 팬 등록 화면: 팬이 고른 물품 종류가 겹치면 결제 전에 "{닉네임}님이 지금 {품목}은 받기 어렵대요. 다른 선물을 고르시겠어요?"를 띄운다. "안내만"이면 팬이 그대로 진행할 수 있고, "등록 막기"면 그 품목으로는 등록이 안 된다. 어느 경우든 최종 판단은 크리에이터 승인이다.
- 참고: 냉장·냉동·음식·액체는 서비스 차원 금지 품목이라 이 목록에 없다. 등록 화면에서 처음부터 고를 수 없다.
- 완료 조건: 1. 크리에이터가 품목·이유·기간을 고르면 링크 페이지에 고정 문구가 뜬다. 2. 기간이 지나면 문구가 사라진다. 3. 겹치는 품목으로 등록하는 팬에게 결제 전 안내가 뜬다. 4. 자유 문장 입력 칸이 어디에도 없다.

### F-4. 받는 상태와 팬당 한도 (크리에이터 부담 조절)

- 받는 상태: 받는 중 / 쉬는 중(다시 받는 날짜 필수). 쉬는 중이면 새 등록이 안 되고, 이미 승인된 건은 그대로 처리된다.
- 팬당 한도(선택, 기본값 꺼짐): "팬 한 명당 한 달 N개". 한도에 닿은 팬은 등록 화면에서 "이번 달은 이미 마음을 충분히 보내셨어요. {다음 달 1일}부터 다시 보낼 수 있어요"를 본다. 다른 팬에게는 보이지 않는다.
- 주간 전체 한도는 두지 않는다("이번 주 3개 남음" 같은 문구는 경쟁처럼 읽히므로). 물량이 많으면 쉬는 중으로 바꾼다.

### F-5. 수령 확인과 감사 답장

- 크리에이터 화면 "받은 선물" 목록에서 상자별로 "받았어요" 버튼을 누르면 같은 자리에 답장 칸이 열린다.
- 답장 방식:
  1. 짧은 답장 고르기(고정 문구 5개 내외: "잘 받았어요, 고마워요", "너무 마음에 들어요", "잘 쓸게요" 등)
  2. 원하면 한 줄 더 쓰기(80자). 이 칸만 자유 입력이며, 팬 한 명에게만 가는 개인 답장이라 F-3의 고정 문구 원칙의 예외다.
  3. 답장 없이 수령 확인만도 가능
- 크리에이터 화면에 "아직 답장 안 한 선물 N개"를 보여준다(크리에이터에게만).
- 팬에게: 알림톡 "{닉네임}님이 선물을 받았어요" / 답장이 있으면 "{닉네임}님이 답장을 남겼어요". 알림 본문에 답장 내용은 넣지 않는다(불변식 14).
- 답장 카드 공유: 팬의 "함께한 시간" 화면에서 답장 카드 단위로 "카드로 공유"를 누르면 카드 이미지(크리에이터 프로필 사진·닉네임·답장 문구·날짜·팬꾹 로고, 팬 닉네임은 팬이 선택)가 만들어지고 X 글쓰기 창에 "#팬꾹" 문구가 채워진다. 크리에이터가 설정에서 X 계정을 등록하고 "태그 허용"을 켠 경우에만 "@크리에이터계정"이 붙는다.
- 감사 답장 모음(링크 페이지 8번): 팬이 그 답장에 "공개해도 괜찮아요"를 켜고, 크리에이터가 설정에서 "답장 모음 보이기"를 켠 경우에만 보인다. 수령 확인 후 3일 지나서 보이기 시작한다. 최신순만, 다른 정렬 없음. 팬 닉네임은 팬이 공개를 고른 경우만, 아니면 "익명의 팬".
- 완료 조건: 1. 수령 확인과 답장이 한 화면에서 끝난다. 2. 공개 동의가 한쪽만 켜졌을 때 링크 페이지에 답장이 보이지 않는다. 3. 수령 확인 3일 전에는 모음에 보이지 않는다. 4. 공유 카드 이미지에 주소·주문번호·운송장·날짜 외 시각 정보가 없다.

### F-6. 기념일 D-day

- 크리에이터가 설정에서 생일(월·일만, 연도 받지 않음)과 기념일 최대 3개(이름 + 월·일, 예: 데뷔일)를 등록한다.
- 링크 페이지와 팬의 "함께한 시간" 화면에 가장 가까운 기념일 D-day를 30일 전부터 보여준다.
- 팬이 선물을 등록할 때 기념일 7일 안이면 "{기념일 이름} 선물" 표시를 고를 수 있고, 이 표시는 팬의 기록 화면에 남는다.
- 팬이 D-day 알림을 신청하는 기능은 백로그(알림 비용·빈도 정책 확정 후).

### F-7. ○○님과 함께한 시간 (팬 본인 전용 화면)

- 위치: 팬의 "내 선물" 메뉴에서 크리에이터별로 들어간다. 크리에이터가 한 명이면 바로 이 화면.
- 공개 범위: 팬 본인만. 화면 상단에 "나만 볼 수 있어요" 표시. 이 화면 전체를 공유하는 기능은 없고, 답장 카드 단위 공유만 있다.
- 구성(위에서 아래):
  1. 크리에이터 프로필 사진·닉네임, "{닉네임}님과 함께한 시간"
  2. "처음 선물한 날 {날짜} · {며칠}째"
  3. 개인 기록 두 칸: 함께한 선물 {n}개, 받은 답장 {m}통
  4. 다음 기념일 칸(F-6, 30일 안일 때): "{기념일} D-{n} · 다음 추억을 남겨 볼까요" + "선물 보내기" 버튼. 크리에이터가 쉬는 중이면 버튼 대신 "{날짜}부터 다시 받아요"
  5. 시간순 카드(최신이 위): 선물 카드(팬이 입력한 물품 종류, 기념일 표시, 팬이 남긴 한마디, 팬이 올린 사진 선택) → 그 아래 답장 카드(있으면 강조 색, "카드로 공유"). 답장이 아직 없고 도착 완료면 "답장을 기다리고 있어요". 배송 중이면 현재 단계.
  6. 맨 아래 첫 선물 카드에 "{닉네임}님께 처음 보낸 선물이에요"
- 특별한 순간: 10번째, 30번째 선물과 처음 선물한 지 1년째에는 그 카드의 테두리·문구를 다르게 보여준다. 본인 화면에서만 바뀐다. 숫자는 남과 비교되지 않는다.
- 팬 사진: 등록할 때 선택으로 선물 사진 1장. 저장 전 EXIF 제거, 화면에 "상자·송장이 아니라 선물만 찍어 주세요" 안내. 이 사진은 크리에이터에게도 보이지 않는다(팬 기록 전용).
- 하지 않는 것: 연속 기록, 다른 팬과의 비교, 금액 표시.
- 탈퇴·차단 처리:
  1. 크리에이터가 탈퇴해도 팬의 선물 기록은 남는다. 프로필 사진은 기본 이미지로 바뀌고 "선물 보내기"는 사라진다.
  2. 크리에이터가 쓴 답장은 크리에이터가 개별로 지운 경우만 사라진다. 탈퇴 시 답장을 모두 지울지는 크리에이터가 탈퇴 화면에서 고른다(기본값: 남김).
  3. 크리에이터가 그 팬을 차단하면 팬 화면에서 "선물 보내기"와 D-day 칸만 숨긴다. 기록은 남긴다. 팬에게 차단 사실을 알리지 않는다.
- 완료 조건: 1. 다른 계정으로 이 화면 주소를 열면 볼 수 없다. 2. 개인 기록 숫자가 실제 선물·답장 수와 같다. 3. 답장 카드 공유가 카드 단위로만 된다. 4. 업로드 사진에서 EXIF가 제거된 것이 확인된다.

## 7. 결정 기록 추가 (decisions.md에 이어 붙임)

### D-07. 노출은 사용자가 자기 이유로 공유할 때만 일어나게 한다

- 결정: 선물 링크 미리보기(프로필 사진 + "승인한 선물만 받습니다"), 팬의 답장 카드 공유, 상자 속 검수 완료 카드, 크리에이터 공지 이미지(선택)로 노출한다. 크리에이터에게 쪽지·메일을 일괄로 보내지 않는다.
- 이유: 크리에이터 한 명이 바꾸면 그 팬들이 따라온다. 링크를 붙이는 행동과 답장을 자랑하는 행동은 원래 하던 일이라 광고로 보이지 않는다. 사전 동의 없는 영리 목적 광고 메시지는 정보통신망법상 위험이 있다.
- 버린 대안: 방송 화면 선물 알림 오버레이(방송 방해, 광고처럼 보임), 크리에이터 개별 쪽지 일괄 발송, 커뮤니티 직접 홍보 글, 자작 후기.

### D-08. "받고 싶은 것" 대신 "지금 받기 어려운 품목"을 부드러운 고정 문구로

- 결정: 크리에이터는 품목·이유·기간을 고르기만 하고, 문장은 시스템이 "지금은 {품목}을 받기 어려워요 ㅠㅠ {이유}"로 만든다. 기간이 끝나면 자동으로 사라진다. 팬 등록 시 겹치면 결제 전에 안내하되 기본은 막지 않는다.
- 이유: "이걸 갖고 싶어요", "이건 싫어요"는 팬에게 요구처럼 읽힌다("마음으로 주는 건데 바라는 게 많네"). 한꺼번에 몰리는 품목 때문에 크리에이터가 방송에서 곤란함을 직접 말하는 상황을 미리 막는다. 거절은 팬에게 상처라 보내기 전에 알리는 편이 낫다.
- 버린 대안: 받고 싶은 것 목록(위시리스트), 크리에이터 자유 문장 공지, "이번 주 3개 남음" 같은 수량 표시.

### D-09. 보낸 팬 명단·순위는 공개하지 않고, 개인 기록은 본인에게만

- 결정: 링크 페이지에는 "이번 달 N명의 팬이 마음을 보냈어요" 숫자만. 감사 답장 모음은 팬과 크리에이터 둘 다 동의하고 수령 3일 뒤부터, 최신순만. 팬별 선물 수·답장 수는 그 팬의 "함께한 시간" 화면에서만 보인다.
- 이유: 명단·순위는 선물 경쟁을 만들어 물량이 몰리고(크리에이터 부담), 자주 보이는 팬이 공격 대상이 되며, 팬의 활동 패턴이 드러난다. 팬이 다시 보내게 만드는 동기는 공개 경쟁이 아니라 크리에이터의 답장, 기념일, 본인 기록으로 만든다.
- 버린 대안: 보낸 팬 명단 자동 슬라이드, 많이 보낸 순 정렬, 연속 기록.

### D-10. 팬 화면에 "○○님과 함께한 시간"을 둔다

- 결정: 팬 본인만 보는 크리에이터별 기록 화면. 처음 선물한 날·며칠째, 함께한 선물 수·받은 답장 수, 다음 기념일 칸, 시간순 선물 카드와 답장 카드, 답장 카드 단위 공유, 10·30번째·1년째 특별 카드.
- 이유: 선물을 보내는 순간보다 답장을 받고 다시 보는 순간이 더 자주 생긴다. 기록이 쌓이는 것을 보면 다음 선물로 이어진다. 숫자가 남에게 보이지 않으니 경쟁이 되지 않는다.
- 제약: 연속 기록 없음, 금액 없음, 화면 전체 공유 없음, 팬이 올린 사진은 크리에이터도 못 봄, 업로드 이미지 EXIF 제거. 크리에이터 탈퇴 시 팬 기록은 남고 답장 삭제 여부는 크리에이터가 고름. 차단 시 팬에게 알리지 않고 "선물 보내기"만 숨김.

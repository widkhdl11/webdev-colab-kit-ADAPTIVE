## 0. 원문이 던진 질문 두 개 — 지금 코드의 답

1. **모르는 사람을 습관적으로 승인하면 주소가 요청자에게 보이나?** 아니다. 팬 화면에는 사무실 주소와 단계 이름뿐이고, 크리에이터에게 가는 송장번호도 보여 주지 않는다. 주소는 송장 출력 함수 안에서만 풀린다.
2. **악성 코드를 담은 요청을 승인받으면 풀린 주소를 받아 볼 수 있나?** 아니다.
   - 사용자 입력을 HTML로 그리는 곳이 없다. 게이트가 `dangerouslySetInnerHTML`을 막는다.
   - 마크다운 렌더러도, 자동 링크도 없다.
   - 송장 출력은 주문번호와 그 주문의 승인 기록을 대조한다. 다른 주문 번호를 넣으면 거부된다.
   - 풀린 라벨(이름·전화·주소)이 가는 곳은 대표 브라우저 하나다. 택배사 API가 없어서 대표가 직접 인쇄하기 때문이고, 출력 기록이 크리에이터 열람 기록에 남는다.

원문의 전제는 지금 코드에서도 그대로 성립한다. 아래는 원문이 더 얹은 조건 중 지금 없거나 다른 것이다.

**이미 있는 것:** 팬에게 운송장 비공개, 송장 출력 함수만 주소를 엶, 열람 기록, 반송은 사무실 경유, 이미지는 jpg·png·webp만 받아 파일 내용으로 판별한 뒤 다시 인코딩해 EXIF를 지움(SVG 거부), 알림 본문은 고정 문구, 주소 재등록 링크를 보내는 경로 없음, 사용자가 정하는 웹훅 없음.

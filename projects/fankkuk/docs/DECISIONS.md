## 2026-10-01 — 요금: 단일 요금 → 상자마다 구간 요금

- 결정: 배송비를 포함한 한 금액을 상자마다 받는다. 소형(세 변 합 100cm·5kg 이하) 6,900원, 중형(세 변 합 100cm·10kg 이하) 8,900원. 크기와 무게 중 큰 쪽 구간. 중형을 넘으면 받지 않는다.
- 도착 실측이 신고 구간보다 크면 차액을 따로 결제 요청한다. 7일 안에 안 내면 반송하고, 실측이 작아도 환불하지 않는다.
- 기록은 배송비(구간 택배 원가)·서비스료(나머지)로 나눠 저장한다 — 부가세 분리(D-03)와 환불(반송 때 배송비 칸만)이 이 칸을 쓴다. 택배 원가는 계약 전 가정값(소형 4,000·중형 5,000).
- 이유: 검수와 송장이 상자 단위로 일어나므로 값도 상자 단위로 받는다. 「검수가 빠진 요금은 없다」는 그대로다.
- 출처: 결정 카드 d7(상자마다)·d8(빈칸 네 개 추천대로).

## 2026-10-01 — 화면 폭 거부 · 사이트 구성과 기능 다섯 개 추가

- 사용자가 메인 화면을 거부했다: 「저렇게 좁은 화면이 아니라 일반 사이트같은 사이즈로 생각했는데」, 「애초에 모든 페이지 시안을 보여주고 시작해야지」. 상담의 「모바일 우선」을 PC에서도 최대 480px로 옮긴 것이 원인이다. 색·모양은 그대로 두고 폭만 다시 잡는다(PC 본문 최대 1200px).
- 사용자가 사이트 구성을 직접 줬다(헤더 로그인·회원가입과 선물 상태 아이콘, 랜딩 → 메인, 네비 다섯, 내 정보 셋). 그중 제품 정의에 없던 크리에이터 찾기·팔로우·공지사항·고객센터·헤더 선물 아이콘을 첫 출시 필수에 넣었다 — 사용자 「넣어」.

## 2026-10-02 — 승인을 기다리지 않고 보낸다 · 거절되면 반송비를 빼고 환불

- 결정: 팬은 결제 직후 사무실 주소를 받아 바로 보낸다. 크리에이터 승인은 출고 전에만 있으면 된다(송장 출력 = 주소 열기는 여전히 승인 뒤에만). 거절·7일 자동 반려된 선물은 팬에게 반송하고, 결제 금액에서 반송 택배비(배송비 칸)를 뺀 금액(서비스료·상품 대금 칸)을 환불한다. 이 사실은 보내기 전(선물 보내기 화면)에 알린다.
- 이유: 사용자 「승인 기다리고 보내는게 아니라 걍 보낼 수 있게. 승인은 우리쪽에서 보내기 전에만」 — 팬이 승인을 기다리는 시간을 없앤다. 대신 거절될 선물이 사무실로 들어오는 비용은 환불에서 뺀다. 환불 계산은 질문 답 「반송 택배비만 빼고 환불」(추천안).
- 대체: 승인 서명 스펙 INV-S9(승인 전 사무실 주소 비공개) → 「결제 끝난 주문에만, 거절·반려·취소 주문엔 비공개」. 결제 스펙 INV-M8 의 「입고 뒤 거절·반려 → 배송비 칸만」(가정이었음).
- 그대로인 것: 크리에이터 주소는 승인 + 검수 완료 뒤 송장 출력 때만 열린다(INV-P4). 입고 전 거절은 전액 환불. 검수 불합격·차액 미납 반송은 배송비 칸만.

## 2026-10-02 — 검수에 걸려 반송하면 검수비·반송비 모두 차감

- 결정: 검수에서 추적 장치 등 보낼 수 없는 물품이 나오거나 실측이 중형을 넘어 반송하면, 서비스료(검수비)와 배송비 칸(반송 택배비)을 모두 빼고 상품 대금 칸만 환불한다(지금은 상품 대금이 0 이라 환불 없음). 결제 전에 알린다.
- 이유: 사용자 「검수에 걸렸다는 건 gps 같은게 있었다는 것, 검수비를 차감해야」 — 팬의 위반이라 비용을 팬이 부담. 질문 답 「검수비+반송비 모두 차감」(추천안). 중형 초과 실측은 같은 「검수 불합격」으로 묶여 있어 함께 바뀐다.
- 대체: 결제 스펙 INV-M8 「입고 뒤 검수 불합격 반송 → 배송비 칸만」.

## 2026-10-02 — DB 표 구성과 임시 로그인: 시험 계정 + 간단 로그인

- 결정: 로컬 DB에 시험 계정 셋(팬·크리에이터·운영자)을 심고 아이디·비밀번호 로그인 화면 하나만 붙인다. 로그인은 실제 방식(로그인한 사람 ID로 DB가 거른다)이고, 가입 화면·카카오 본인 확인은 계정 스펙 때 더한다.
- 표 열 개(계정·크리에이터·주문·상자·결제·승인 요청·주소 열람 기록·팔로우·공지·문의). 화면은 표를 직접 읽지 못하고 DB 함수가 보여도 되는 칸만 돌려준다. 돈·상태를 바꾸는 쓰기는 앱 서버 키로만. 실명·주소·전화번호 표는 이번에 만들지 않는다.
- 이유: 카카오 본인 확인은 딜러사 계약 전이라 계정 전체를 먼저 만들면 반쪽이 되고 DB 연결이 늦어진다. 로그인 방식은 실제와 같아 나중에 버리는 코드가 없다.
- 출처: 결정 카드 d9 「추천대로 진행」(A).

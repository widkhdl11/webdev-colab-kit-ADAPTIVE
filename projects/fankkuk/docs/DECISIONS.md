## 2026-10-01 — 요금: 단일 요금 → 상자마다 구간 요금

- 결정: 배송비를 포함한 한 금액을 상자마다 받는다. 소형(세 변 합 100cm·5kg 이하) 6,900원, 중형(세 변 합 100cm·10kg 이하) 8,900원. 크기와 무게 중 큰 쪽 구간. 중형을 넘으면 받지 않는다.
- 도착 실측이 신고 구간보다 크면 차액을 따로 결제 요청한다. 7일 안에 안 내면 반송하고, 실측이 작아도 환불하지 않는다.
- 기록은 배송비(구간 택배 원가)·서비스료(나머지)로 나눠 저장한다 — 부가세 분리(D-03)와 환불(반송 때 배송비 칸만)이 이 칸을 쓴다. 택배 원가는 계약 전 가정값(소형 4,000·중형 5,000).
- 이유: 검수와 송장이 상자 단위로 일어나므로 값도 상자 단위로 받는다. 「검수가 빠진 요금은 없다」는 그대로다.
- 출처: 결정 카드 d7(상자마다)·d8(빈칸 네 개 추천대로).

## 2026-10-01 — 화면 폭 거부 · 사이트 구성과 기능 다섯 개 추가

- 사용자가 메인 화면을 거부했다: 「저렇게 좁은 화면이 아니라 일반 사이트같은 사이즈로 생각했는데」, 「애초에 모든 페이지 시안을 보여주고 시작해야지」. 상담의 「모바일 우선」을 PC에서도 최대 480px로 옮긴 것이 원인이다. 색·모양은 그대로 두고 폭만 다시 잡는다(PC 본문 최대 1200px).
- 사용자가 사이트 구성을 직접 줬다(헤더 로그인·회원가입과 선물 상태 아이콘, 랜딩 → 메인, 네비 다섯, 내 정보 셋). 그중 제품 정의에 없던 크리에이터 찾기·팔로우·공지사항·고객센터·헤더 선물 아이콘을 첫 출시 필수에 넣었다 — 사용자 「넣어」.

## 2026-10-02 — 승인을 기다리지 않고 보낸다 · 거절되면 반송비를 빼고 환불

- 결정: 팬은 결제 직후 사무실 주소를 받아 바로 보낸다. 크리에이터 승인은 출고 전에만 있으면 된다(송장 출력 = 주소 열기는 여전히 승인 뒤에만). 거절·7일 자동 반려된 선물은 팬에게 반송하고, 결제 금액에서 반송 택배비(배송비 칸)를 뺀 금액(서비스료·상품 대금 칸)을 환불한다. 이 사실은 보내기 전(선물 보내기 화면)에 알린다.
- 이유: 사용자 「승인 기다리고 보내는게 아니라 걍 보낼 수 있게. 승인은 우리쪽에서 보내기 전에만」 — 팬이 승인을 기다리는 시간을 없앤다. 대신 거절될 선물이 사무실로 들어오는 비용은 환불에서 뺀다. 환불 계산은 질문 답 「반송 택배비만 빼고 환불」(추천안).
- 대체: 승인 서명 스펙 INV-S9(승인 전 사무실 주소 비공개) → 「결제 끝난 주문에만, 거절·반려·취소 주문엔 비공개」. 결제 스펙 INV-M8 의 「입고 뒤 거절·반려 → 배송비 칸만」(가정이었음).
- 그대로인 것: 크리에이터 주소는 승인 + 검수 완료 뒤 송장 출력 때만 열린다(INV-P4). 입고 전 거절은 전액 환불. 검수 불합격·차액 미납 반송은 배송비 칸만.

## 2026-10-02 — 검수에 걸려 반송하면 검수비·반송비 모두 차감

- 결정: 검수에서 추적 장치 등 보낼 수 없는 물품이 나오거나 실측이 중형을 넘어 반송하면, 서비스료(검수비)와 배송비 칸(반송 택배비)을 모두 빼고 상품 대금 칸만 환불한다(지금은 상품 대금이 0 이라 환불 없음). 결제 전에 알린다.
- 이유: 사용자 「검수에 걸렸다는 건 gps 같은게 있었다는 것, 검수비를 차감해야」 — 팬의 위반이라 비용을 팬이 부담. 질문 답 「검수비+반송비 모두 차감」(추천안). 중형 초과 실측은 같은 「검수 불합격」으로 묶여 있어 함께 바뀐다.
- 대체: 결제 스펙 INV-M8 「입고 뒤 검수 불합격 반송 → 배송비 칸만」.

## 2026-10-02 — DB 표 구성과 임시 로그인: 시험 계정 + 간단 로그인

- 결정: 로컬 DB에 시험 계정 셋(팬·크리에이터·운영자)을 심고 아이디·비밀번호 로그인 화면 하나만 붙인다. 로그인은 실제 방식(로그인한 사람 ID로 DB가 거른다)이고, 가입 화면·카카오 본인 확인은 계정 스펙 때 더한다.
- 표 열 개(계정·크리에이터·주문·상자·결제·승인 요청·주소 열람 기록·팔로우·공지·문의). 화면은 표를 직접 읽지 못하고 DB 함수가 보여도 되는 칸만 돌려준다. 돈·상태를 바꾸는 쓰기는 앱 서버 키로만. 실명·주소·전화번호 표는 이번에 만들지 않는다.
- 이유: 카카오 본인 확인은 딜러사 계약 전이라 계정 전체를 먼저 만들면 반쪽이 되고 DB 연결이 늦어진다. 로그인 방식은 실제와 같아 나중에 버리는 코드가 없다.
- 출처: 결정 카드 d9 「추천대로 진행」(A).

## 2026-10-02 — 로그인 유지: Supabase 공식 라이브러리 + 로그인 규칙 일곱 줄

- 결정: 로그인 쿠키 저장·만료 갱신은 `@supabase/ssr`에 맡긴다. 로그인 규칙(`docs/specs/session-login.md` INV-L1~L7)을 승인한다 — 토큰은 스크립트가 못 읽는 쿠키에만, 서버는 요청마다 사람을 다시 확인, 쓰기에는 확인한 ID만, 관리자 키는 서버 전용, 실패 안내는 하나, 시험 계정은 운영에서 막음, 로그아웃은 서버 세션까지 끝냄.
- 이유: 토큰 갱신과 동시 요청 처리를 직접 짜면 틀렸을 때 조용히 로그아웃되거나 만료 토큰이 통과한다. 공식 라이브러리는 study-mate 에서 이미 쓴다.
- 출처: 결정 카드 d10 「추천대로 진행」.

## 2026-10-02 — 내 정보: 연락처는 개인정보 구역에, 이메일은 확인한 주소에만

- 결정: 내 정보의 이메일·휴대폰·알림은 칸을 만들어 실제로 저장한다(카드 d11). 이메일·휴대폰은 개인정보 구역에 두고, 휴대폰은 암호화하지 않되 화면에는 가운데를 가려서만 보인다. 이메일은 바꾸면 확인 메일의 링크를 눌러야 새 주소가 된다(카드 d12).
- 이유: 배송 소식을 이메일로 보내므로 오타나 남의 주소로 가면 안 된다. 휴대폰은 알림톡 발송에 서버가 수시로 읽어야 해서 주소처럼 잠그지 않는다 — 법상 저장 암호화 의무 대상(고유식별정보·비밀번호·생체정보)도 아니다(운영 전 처리방침 작성 때 재확인).
- 주소는 지금 방식 유지: 「번호처럼 두면 안 되나」를 검토했고, 주소는 승인 건 출력 때만 필요하며 「승인 없이는 우리도 못 연다」가 제품 약속이라 브라우저 암호화·복호화 함수 구조를 그대로 둔다.
- 남은 것: 개정 스펙(my-account INV-A1~A8)과 메일 라이브러리 nodemailer 추가는 카드 d13 승인 대기.

## 2026-10-02 — 회원가입: 확인된 번호 하나에 계정 하나, 카카오 연결 전엔 로컬만 가짜 확인

- 결정: 번호 하나에 계정 하나, 가입 이메일도 확인 메일, 카카오 연결 전에는 로컬만 가짜 본인 확인이고 운영 가입은 막는다(카드 d14 「됐다」→ 추천대로). 스펙 signup(INV-U1~U11).
- 이유: 휴대폰 번호는 알림톡이 가는 곳이라 확인하지 않은 번호로 계정이 생기면 남에게 선물 소식이 간다. 운영에서 가짜가 켜질 길은 두지 않는다 — 설정 하나 잘못 넣어 아무 번호로 가입되는 일이 없게.
- 리뷰 뒤 더한 것: 본인 확인 번호표는 그것을 받은 브라우저의 쿠키에만 둔다(남이 번호표를 가져가도 못 쓴다).

## 2026-10-03 — 크리에이터 메인, 크리에이터도 선물 보내기(크리에이터에게·자기 팬에게)

- 결정: 셋 다 연다 — 크리에이터 메인 화면, 크리에이터 → 다른 크리에이터, 크리에이터 → 자기 팬(카드 d15 「셋 다」, 추천은 앞의 둘이었다).
- 이유: 크리에이터 로그인 뒤 승인 요청만 바로 나와 「본론부터 들어가는」 느낌이었다. 크리에이터도 팬에게, 가끔은 다른 크리에이터에게 선물을 보낸다.
- 비용으로 알고 고른 것: 팬에게 보내는 쪽은 방향이 거꾸로라 팬 주소를 새로 맡는다 — 팬 주소 등록·암호화·승인·열람 기록을 팬 쪽에 새로 만들고 개인정보처리방침 문구가 바뀐다. 로그인 스펙의 「크리에이터 선물 등록 거부」(S3c)를 고쳐야 한다.

- 고침(같은 날): 크리에이터 → 다른 크리에이터는 둘 사이에 팔로우가 한쪽이라도 있어야 보낸다(사용자 「서로 팔로우가 돼 있거나 한쪽에서 하고 있어야 보낼 수 있는걸로」). 그래서 크리에이터도 다른 크리에이터를 팔로우할 수 있게 된다. 로그인 스펙 고침은 카드 d16 「추천대로 승인」.
- 고침(같은 날): 크리에이터 → 자기 팬은 「역조공」으로 따로 나눈다(사용자 「역조공으로 나누고 싶어」). 선물 보내기와 입구·목록·이름이 따로다. 착수는 팬 주소 보호 스펙부터, 순서는 그대로 세 번째.
- 고침(같은 날): 역조공에서 팬 주소는 마지막에 받는다 — 팬이 「받기」를 누를 때 그 자리에서 주소를 입력하고, 팬 브라우저에서 암호화된 뒤 서버로 간다. 배송이 끝나면 지운다. 팬 주소를 미리 저장해 두지 않는다(사용자 「마지막에 주소 받아서 보내는걸로 했지?」 → 확인 「맞아」).
- 고침(같은 날, 카드 d18): 역조공은 나를 팔로우한 팬에게만, 팬 아이디를 정확히 입력해 찾는다(팔로워 명단은 펼쳐 보이지 않는다). 한 번에 한 명도 여러 명도 보낼 수 있다(사용자 「한명도 되고 여러명에게 보낼 수 있게」) — 일부 팬만 받지 않았을 때의 환불 규칙을 스펙에서 정한다.
- 고침(같은 날): 역조공은 팬 선물보다 싸다 — 팬 선물 요금에서 검수비를 뺀 금액(소형 5,400 · 중형 6,900). 크리에이터가 팬에게 추적 장치를 달 이유가 적어 검수를 겉면·크기·무게·금지 물품 확인으로 줄이기 때문이다(사용자 「크리에이터 친화적으로 조금 더 싸게… 검수 비용이 줄기 때문」·「격면·금지 물품만」). 그래서 결제 기록의 서비스료를 기본 서비스료와 검수비로 나눈다 — 검수비 소형 1,500 · 중형 2,000(사용자 「내부적으로 서비스료 안에 기본 서비스료랑 검수비용을 나눠」·「소형 1,500 · 중형 2,000원」). 팬 선물 요금(6,900 · 8,900)은 그대로.

## 2026-10-03 — 관리자 페이지와 대형 상자

- 결정(카드 d20 「추천대로」 + 이어진 질문): 관리자 화면을 만든다. 넣는 것 — 요금 수정(소형·중형·대형, 검수비·택배 원가 포함) · 들어온 상자 목록과 입고·검수·출고 처리 · 보낼 수 없는 물품 목록 수정 · 역조공 처리(받기 기한·몫별 환불·반송) · 크리에이터 본인 확인 승인 · 공지사항 작성 · 환불·결제 내역 · 미확인 입고 목록 · 자동 처리 현황 · 1:1 문의 답변(문의 받는 기능도 새로).
- 요금 수정은 대표 계정만, 고친 요금은 새 주문부터 적용하고 이미 결제한 주문은 결제 때 요금 그대로. 바꾼 기록(언제·누가·얼마에서 얼마로)을 남긴다.
- 대형 상자를 연다(d8 「중형 초과는 받지 않는다」를 대체): 세 변 합 160cm·20kg 이하, 10,900원(택배 원가 가정 6,500 + 검수비 2,500 + 기본 서비스료 1,900), 역조공 8,400원. 대형을 넘으면 받지 않는다. 처음 값이고 관리자 화면에서 고친다.
- 직원 계정 관리는 이번에 넣지 않는다(사용자가 고르지 않음). 대표·직원 구분은 PRODUCT 의 운영자 정의 그대로 둔다.
- 이유: 사용자 「중형, 대형, 소형별 가격 수정하고, 택배 물품 목록 관리하는 관리자 페이지 만들어줘. 이것들 외에도 필요한거 있으면 추가해서」 · 「그 외 필요한게 있는지 확인」.
- 비용으로 알고 고른 것: 요금이 코드 상수에서 DB 로 옮겨 가 결제 스펙(INV-M1)이 바뀐다. 권한(대표·직원·크리에이터·팬)과 상태 전환(입고·검수·출고)에 스펙이 먼저 필요하다. 관리자 화면은 빽빽한 작업 화면이라 새 시각 방향 — 시안 승인이 먼저다.

## 2026-10-04 — 마이페이지 이름 「내 팬꾹」, 크리에이터의 일하는 화면을 그 안 왼쪽 메뉴로

- 결정: 크리에이터의 승인 요청 · 보낸 역조공 · 열람 기록 · 주소와 설정을 헤더 가로 메뉴에서 빼고 「내 팬꾹」 화면의 왼쪽 메뉴로 옮긴다. 마이페이지 이름을 「내 정보」에서 「내 팬꾹」으로 바꾼다(팬·크리에이터 둘 다). 크리에이터 헤더 메뉴는 팬과 같다(크리에이터 찾기 · 선물 보내기 · 공지사항 · 팬꾹 소개 · 고객센터) — 같은 날 사용자 「크리에이터도 일반 팬처럼 크리에이터 찾기 같은거 보여야하지 않나? 다른 방송인에게 선물 보내주고 싶을때 어떻게해」로 고침.
- 이유: 사용자 「승인요청, 역조공, 열람기록은 크리에이터 로그인상태에서만 보이게하고, 왼쪽 사이드바로 보는거면 좋겠어. 내 정보 페이지로 들어가서 보게. 그리고 마이페이지의 이름은 내 팬꾹으로 해주고. 페이지 구성 자체가 일반적이지 못한거 같아」. 앞서 「역조공 리스트가 너무 커서 싸구려 사이트 같다」는 지적이 있었고, 목록이 1200px 폭을 다 쓰던 것이 왼쪽 메뉴 옆 본문 칸으로 좁아진다.
- 같이 고친 것: 열람 기록·주소와 설정 화면은 로그인 확인 없이 예시 데이터를 그리고 있었다 — 이제 크리에이터가 아니면 로그인 화면으로 보낸다(승인 요청·보낸 역조공과 같게).
- 주소는 그대로다(/creator/requests 등) — 옮기면 결제 뒤 돌아오는 주소·알림 링크를 같이 바꿔야 해서 이득이 없다.

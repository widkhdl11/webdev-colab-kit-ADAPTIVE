# 카카오 알림톡 템플릿 — 솔라피에 올릴 본문 (2026-10-29 초안 · 2026-11-04 검수 반려 반영)

솔라피 콘솔 → 카카오 알림톡 → 템플릿 등록에 이 본문을 **그대로** 붙여 넣는다. 알림톡은 등록한 본문과 글자 하나·줄바꿈 하나까지 같아야 나가므로,
코드는 아래 `#{변수}` 자리만 채워 보낸다(notifications INV-N1·N7). 본문을 고치면 이 문서와 코드(`src/features/notification-dispatch/lib/alimtalk-body.ts`)를 같이 고치고 다시 검수받는다.

- 템플릿 유형: 정보성 · 아이콘형(알림마다 상태 아이콘 이미지). 인증번호만 「인증」 분류 + 보안 템플릿(이미지 없음).
- **2026-11-04 검수 반려 반영**: ① 누가 어떤 행동을 해서 받는 알림인지 본문에 적는다 ② 제3자(팬·크리에이터)가 한 행동으로 가는 알림에는 받는 사람과 보낸 사람의 이름을 넣는다(카카오 회신 「#{수신자명}님, #{보내는사람}이 보내신 선물이 도착했습니다」). 그래서 승인 요청·재알림·로그인 링크(2·3·10절)에 보낸 팬 닉네임, 답장 도착(8절)에 답장한 크리에이터 이름이 들어간다 — 10-29 「승인 요청 알림에 보낸 팬 닉네임을 넣지 않는다」를 사용자가 되돌렸다(DECISIONS 2026-11-04). 아이콘형 이미지는 반려(일러스트로 판정)라 아이콘을 다시 만들어 아이콘형으로 다시 올린다(2026-11-04 사용자 「아이콘형으로 올릴거야」 — 작업은 사용자가 진행 중). 이미지 기준은 `kakao-alimtalk-guide.md`.
- 변수 예시(솔라피 등록 칸): `#{수신자명}` 하루 · `#{보내는사람}` 별빛님(여럿이면 「별빛님 외 2명」) · `#{건수}` 3 · `#{일수}` 2 · `#{닉네임}` 별빛 · `#{주문번호}` FC-7K3M9 · `#{크리에이터}` 하루 · `#{경로}` /gifts/FC-7K3M9
- 버튼은 모두 「웹 링크」. 모바일·PC 주소 둘 다 같은 값.
- 검수 승인 뒤 받은 템플릿 ID: 인증번호는 Vercel 환경 변수 `SOLAPI_PHONE_CODE_TEMPLATE_ID`, 나머지는 DB 표 `notification_kakao_templates` 에 종류(`kind`)별로 넣는다.
  넣지 않은 종류는 지금처럼 이메일로만 간다.

## 1. 인증번호 (`SOLAPI_PHONE_CODE_TEMPLATE_ID`)

- 분류: 인증 · 보안 템플릿 체크
- 변수: `#{인증번호}` — 6자리 숫자
- 버튼: 없음

```
[팬꾹] 인증번호 안내

인증번호: #{인증번호}

3분 안에 입력해 주세요.
```

알림톡이 실패하면 같은 번호가 문자로 간다: `[팬꾹] 인증번호 123456 (3분 안에 입력해 주세요)` (signup INV-U15).

## 2. 승인 요청 (`approval_request`) — 크리에이터

- 변수: `#{수신자명}` — 받는 크리에이터의 닉네임 · `#{보내는사람}` — 이 통에 새로 묶인 승인 요청을 보낸 팬 닉네임. 한 명이면 「별빛님」, 여럿이면 가장 먼저 온 요청의 팬으로 「별빛님 외 2명」(사람 수는 서로 다른 팬 수) · `#{건수}` — 보내는 시점의 그 크리에이터 승인 대기 건수 전체
- 버튼: [승인 화면 열기] → `https://fankkuk.com/creator/actions` — 로그인 전이면 로그인 화면을 거쳐 이 화면으로 돌아온다(2026-11-04 고침: 전에는 로그인 뒤 홈으로 갔다)
- 로그인 링크 템플릿(10절)이 검수를 마치고 등록되면 그쪽으로 보낸다. 이 템플릿은 그 전까지만 쓰인다.
- 같은 크리에이터에게는 10분 창 단위로 보낸다 — 창의 첫 요청은 바로 보내고, 창 안에 더 온 요청은 쌓았다가 창이 끝날 때 한 통 더 보낸다. 같은 본문을 쓰고 건수는 그때의 대기 전체다(notification-batching INV-NB1).
- 버튼은 특정 주문이 아니라 처리할 일의 승인 대기 목록으로 간다. 목록에서 한 건씩 열어 승인·거절한다(INV-N9).
- 선물 종류·개수·주문번호는 넣지 않는다 — 승인 화면에서만 보인다. 보낸 팬 닉네임은 2026-11-04부터 넣는다(위 반려 반영).
- 꼭 가는 알림이라 마지막 줄이 상태 알림과 다르다(INV-N6).

```
[팬꾹] 선물 승인 요청

#{수신자명}님, #{보내는사람}이 선물을 보내려고 승인을 요청했습니다.

승인 대기: 총 #{건수}건

승인 화면에서 선물 내용을 확인하고 승인 또는 거절해 주세요. 7일 안에 승인하지 않은 요청은 자동으로 반려됩니다.

이 알림은 팬이 크리에이터에게 선물 승인을 요청했을 때 발송되는 필수 알림으로, 알림 수신 설정과 관계없이 발송됩니다.
```

## 3. 승인 재알림 (`approval_reminder`) — 크리에이터

- 변수: `#{수신자명}` · `#{보내는사람}` — 지금 대기 중인 요청을 보낸 팬(2절과 같은 꼴, 가장 빨리 자동 반려될 요청의 팬이 앞) · `#{건수}` — 보내는 시점의 승인 대기 건수 전체 · `#{일수}` — 대기 건 중 가장 빨리 자동 반려될 건까지 남은 날(하루 단위로 올림, 최소 1)
- 버튼: [승인 화면 열기] → `https://fankkuk.com/creator/actions` (2절과 같다)
- 승인 대기 건이 결제 완료 3일째(72시간)·6일째(144시간)가 될 때 생기고, 보내는 순간 그 건이 아직 대기일 때만 간다. 2절의 10분 창이 열려 있으면(10분 안에 승인 요청 알림이 이미 갔다) 보내지 않는다(INV-NB2).

```
[팬꾹] 선물 승인 대기 안내

#{수신자명}님, #{보내는사람}이 요청한 선물 승인이 아직 대기 중입니다.

승인 대기: 총 #{건수}건
#{일수}일 뒤에는 승인하지 않은 요청이 자동으로 반려됩니다.

이 알림은 팬이 요청한 선물 승인이 대기 중일 때 발송되는 필수 알림으로, 알림 수신 설정과 관계없이 발송됩니다.
```

## 상태 알림 (4~8절) — 기본은 하루 한 번 묶음

4~8절은 받는 사람이 알림 설정에서 「바로 받기」를 켰을 때만 사건마다 간다. 켜지 않은 사람(기본)에게는 이 소식들이 9절 하루 묶음 한 통으로 간다(notification-batching INV-NB5).
「바로 받기」는 팬·크리에이터 각자의 알림 설정에 있다.

## 9. 하루 묶음 (`status_digest`) — 「바로 받기」를 켜지 않은 팬·크리에이터

- 변수: `#{닉네임}` · `#{건수}` — 직전 묶음 뒤 생긴 4~8절 소식의 수 · `#{경로}` (팬 `/gifts`, 크리에이터 `/creator/actions`)
- 버튼: [선물 보기] → `https://fankkuk.com#{경로}`
- 매일 오후 7시(서울 시간)에 보낸다. 소식이 0건이면 보내지 않는다(notification-batching INV-NB5).
- 어느 선물의 무슨 소식인지는 넣지 않는다 — 건수만 넣고, 내용은 로그인한 화면에서 본다.

## 10. 승인 요청 — 로그인 링크 (`approval_request_login_link`) — 크리에이터

솔라피에 등록할 값(2026-10-31 솔라피 확인: 버튼 URL 에 변수를 넣을 수 있다):

| 칸 | 값 |
|---|---|
| 본문 | 아래 코드 블록 그대로 (2절과 같다) |
| 본문 변수 | `#{수신자명}` · `#{보내는사람}` · `#{건수}` |
| 버튼 종류 | 웹링크 |
| 버튼 이름 | 승인 화면 열기 |
| 버튼 URL (모바일·PC 같음) | `https://fankkuk.com/login/link#t=#{token}` |
| 버튼 URL 변수 | `#{token}` |

- 버튼: [승인 화면 열기] → `https://fankkuk.com/login/link#t=#{token}`
- 2절과 본문이 같고 버튼 주소만 다르다. 누르면 토큰으로 로그인한 뒤 승인 대기 목록(`/creator/actions`)으로 바로 간다(link-login INV-K4). 토큰이 만료·사용됐으면 로그인 화면을 거쳐 같은 목록으로 돌아온다. 등록된 템플릿은 고칠 수 없어 새로 등록하고 검수받는다(link-login 「바깥에서 해야 하는 일」).
- 변수: `#{수신자명}` · `#{보내는사람}` · `#{건수}` — 2절과 같다 · `#{token}` — 발송 코드가 보내는 순간 그 크리에이터 계정에 묶어 만든 1회용 로그인 토큰으로 채운다(43자, 30분, 한 번만 쓰인다 — link-login INV-K1·K2). 이름은 등록한 템플릿과 글자 하나까지 같아야 한다.
- 변수를 채운 주소는 76자다(솔라피 한도 300자 이하). 토큰을 `#` 뒤에 둔다 — 브라우저가 `#` 뒤는 서버로 보내지 않아 호스팅 요청 기록에 원문이 남지 않는다(link-login INV-K1·S3)
- 검수 승인 뒤 받은 템플릿 ID 는 `notification_kakao_templates` 의 `approval_request` 줄 `login_link_template_code` 칸에 넣는다. 비어 있으면 2절 템플릿(토큰 없음)으로 간다.
- 토큰은 알림톡 버튼 주소에만 있다 — 발송 기록·오류 코드·로그·DB 에는 남지 않는다(DB 에는 해시만).

```
[팬꾹] 선물 승인 요청

#{수신자명}님, #{보내는사람}이 선물을 보내려고 승인을 요청했습니다.

승인 대기: 총 #{건수}건

승인 화면에서 선물 내용을 확인하고 승인 또는 거절해 주세요. 7일 안에 승인하지 않은 요청은 자동으로 반려됩니다.

이 알림은 팬이 크리에이터에게 선물 승인을 요청했을 때 발송되는 필수 알림으로, 알림 수신 설정과 관계없이 발송됩니다.
```

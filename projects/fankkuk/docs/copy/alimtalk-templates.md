# 카카오 알림톡 템플릿 — 솔라피에 올릴 본문 (2026-10-29 초안, 같은 날 문구 수정안 반영)

솔라피 콘솔 → 카카오 알림톡 → 템플릿 등록에 이 본문을 **그대로** 붙여 넣는다. 알림톡은 등록한 본문과 글자 하나·줄바꿈 하나까지 같아야 나가므로,
코드는 아래 `#{변수}` 자리만 채워 보낸다(notifications INV-N1·N7). 본문을 고치면 이 문서와 코드(`src/features/notification-dispatch/lib/alimtalk-body.ts`)를 같이 고치고 다시 검수받는다.

- 템플릿 유형: 기본형(정보성). 인증번호만 「인증」 분류 + 보안 템플릿.
- 버튼은 모두 「웹 링크」. 모바일·PC 주소 둘 다 같은 값.
- 검수 승인 뒤 받은 템플릿 ID: 인증번호는 Vercel 환경 변수 `SOLAPI_PHONE_CODE_TEMPLATE_ID`, 나머지는 DB 표 `notification_kakao_templates` 에 종류(`kind`)별로 넣는다.
  넣지 않은 종류는 지금처럼 이메일로만 간다.

---

## 1. 인증번호 (`SOLAPI_PHONE_CODE_TEMPLATE_ID`)

- 분류: 인증 · 보안 템플릿 체크
- 변수: `#{인증번호}` — 6자리 숫자
- 버튼: 없음

```
[팬꾹] 인증번호 안내

인증번호: #{인증번호}

3분 안에 입력해 주세요.
```

알림톡이 실패하면 같은 번호가 문자로 간다: `[팬꾹] 인증번호 123456 (3분 안에 입력해 주세요)` (signup INV-U15).

## 2. 승인 요청 (`approval_request`) — 크리에이터

- 상태: 코드 반영 전 — 솔라피에 올려 검수는 받아도 되지만, 발송 코드가 이 본문으로 바뀌기 전에는 템플릿 ID 를 넣어도 보내지 않는다(그동안 승인 요청은 이메일로 간다).
- 변수: `#{건수}` — 보내는 시점의 그 크리에이터 승인 대기 건수 전체
- 버튼: [승인 화면 열기] → `https://fankkuk.com/creator/actions`
- 새 승인 요청이 생기면 10분을 기다렸다가, 그 사이 같은 크리에이터에게 생긴 요청까지 한 통으로 보낸다(notifications INV-N8).
- 버튼은 특정 주문이 아니라 처리할 일의 승인 대기 목록으로 간다. 목록에서 한 건씩 열어 승인·거절한다(INV-N9).
- 보낸 팬 닉네임·선물 종류·개수·주문번호는 넣지 않는다 — 승인 화면에서만 보인다.
- 꼭 가는 알림이라 마지막 줄이 상태 알림과 다르다(INV-N6).

```
새 선물 승인 요청이 왔어요.
승인 대기 #{건수}건

이 알림은 서비스 이용에 필요한 필수 알림으로, 알림 수신 설정과 관계없이 발송됩니다.
```

## 3. 승인 재알림 (`approval_reminder`) — 크리에이터

- 상태: 코드 반영 전 — 2절과 같다.
- 변수: `#{건수}` — 보내는 시점의 승인 대기 건수 전체 · `#{일수}` — 대기 건 중 가장 빨리 자동 반려될 건까지 남은 날(하루 단위로 올림, 최소 1)
- 버튼: [승인 화면 열기] → `https://fankkuk.com/creator/actions`
- 승인 대기 건이 결제 완료 3일째(72시간)·6일째(144시간)가 될 때 생기고, 보내는 순간 그 건이 아직 대기일 때만 간다. 10분 묶음은 2절과 같다 — 같은 10분 안에 새 요청이 있으면 2절 한 통만 간다.

```
승인 대기 #{건수}건, #{일수}일 뒤 자동 반려

이 알림은 서비스 이용에 필요한 필수 알림으로, 알림 수신 설정과 관계없이 발송됩니다.
```

## 상태 알림 (4~8절) — 기본은 하루 한 번 묶음

4~8절은 받는 사람이 알림 설정에서 「바로 받기」를 켰을 때만 사건마다 간다. 켜지 않은 사람(기본)에게는 이 소식들이 9절 하루 묶음 한 통으로 간다(notifications INV-N23).
「바로 받기」는 팬·크리에이터 각자의 알림 설정에 있다.

## 4. 상자 도착 (`box_arrived`) — 보낸 팬 (역조공이면 보낸 크리에이터)

- 변수: `#{닉네임}` · `#{주문번호}` · `#{경로}` (팬 `/gifts/FC-…`, 역조공 `/creator/revgifts`)
- 버튼: [상자 확인] → `https://fankkuk.com#{경로}`
- 상자 하나의 도착을 알린다(INV-N14). 여러 상자를 보냈어도 모두 도착했다는 뜻은 아니다.

```
#{닉네임}님,
보내신 상자 1개가 팬꾹에 도착했습니다.

주문번호: #{주문번호}

상자 도착 현황은 로그인 후 확인해 주세요.

알림 수신 여부는 ‘계정 설정 > 알림’에서 변경할 수 있습니다.
```

## 5. 출고 (`shipped`) — 보낸 팬

- 변수: `#{닉네임}` · `#{주문번호}`
- 버튼: [선물 보기] → `https://fankkuk.com/gifts/#{주문번호}`
- 팬꾹의 출고 처리와 택배사의 배송 시작을 구분한다.

```
#{닉네임}님,
보내신 선물이 팬꾹에서 출고 처리되었습니다.
택배사에 인계되면 배송이 시작됩니다.

주문번호: #{주문번호}

선물 진행 상황은 로그인 후 확인해 주세요.

알림 수신 여부는 ‘계정 설정 > 알림’에서 변경할 수 있습니다.
```

## 6. 배송 중 (`in_transit`) — 보낸 팬

- 변수: `#{닉네임}` · `#{주문번호}`
- 버튼: [선물 보기] → `https://fankkuk.com/gifts/#{주문번호}`
- 택배사 연결 전이라 아직 이 알림이 생기는 사건이 없다(INV-N12). 미리 검수만 받아 둔다.

```
#{닉네임}님,
보내신 선물이 배송 중입니다.

주문번호: #{주문번호}

선물 진행 상황은 로그인 후 확인해 주세요.

알림 수신 여부는 ‘계정 설정 > 알림’에서 변경할 수 있습니다.
```

## 7. 배송 완료 (`delivered`) — 보낸 팬

- 변수: `#{닉네임}` · `#{주문번호}`
- 버튼: [선물 보기] → `https://fankkuk.com/gifts/#{주문번호}`
- 택배사의 배송 완료 정보로 생긴다(택배사 연결 뒤). 크리에이터가 「받았어요」를 누를 때 가는 알림(`gift_received`)과는 다르다 —
  그 종류는 지금 알림톡으로 보내는 목록에 없어서, 템플릿을 올려도 코드를 고치기 전에는 나가지 않는다.

```
#{닉네임}님,
보내신 선물의 배송이 완료되었습니다.

주문번호: #{주문번호}

선물 상세 정보는 로그인 후 확인해 주세요.

알림 수신 여부는 ‘계정 설정 > 알림’에서 변경할 수 있습니다.
```

## 9. 하루 묶음 (`status_digest`) — 「바로 받기」를 켜지 않은 팬·크리에이터

- 상태: 코드 반영 전 — 2절과 같다. 그동안 4~8절은 지금처럼 사건마다 간다.
- 변수: `#{닉네임}` · `#{건수}` — 직전 묶음 뒤 생긴 4~8절 소식의 수 · `#{경로}` (팬 `/gifts`, 크리에이터 `/creator/actions`)
- 버튼: [선물 보기] → `https://fankkuk.com#{경로}`
- 매일 오후 7시(서울 시간)에 보낸다. 소식이 0건이면 보내지 않는다(notifications INV-N23).
- 어느 선물의 무슨 소식인지는 넣지 않는다 — 건수만 넣고, 내용은 로그인한 화면에서 본다.

```
#{닉네임}님,
새 선물 소식 #{건수}건이 있습니다.

선물 진행 상황은 로그인 후 확인해 주세요.

알림 수신 여부는 ‘계정 설정 > 알림’에서 변경할 수 있습니다.
```

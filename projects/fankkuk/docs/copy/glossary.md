# 팬꾹 용어집

서비스 개념과 대표 표기를 확인하는 문서다. 문구의 역할·문체·정확성·검토 절차는 프로젝트 `CLAUDE.md`의 ‘화면 문구 규칙’을 따른다. `AGENTS.md`도 같은 규칙을 참조한다.

## 읽는 법

- 먼저 해당 개념의 뜻과 읽는 사람을 확인한다. 코드 식별자를 한국어로 직역하지 않는다.
- 대표 표기는 같은 개념을 일관되게 부르기 위한 기준이다. 문장 예시는 그대로 복사해야 할 고정 문장이 아니다. 상태·행동·설명은 역할에 맞게 표현할 수 있다.
- ‘문맥별 주의’는 해당 개념에 관한 주의사항이다. 단어 자체의 전역 금지가 아니다. 일반 서비스 용어와 필요한 기술 용어를 무조건 풀어 쓰지 않는다.
- 역할별 문체가 모든 화면에 적용된다. 아직 교체하지 않은 화면의 해요체나 이전 시안 문구를 새 문구의 기준으로 삼지 않는다.
- 최근 사용자의 수정 지시로 표기가 바뀌면 관련 행도 고친다. 의미가 같은 이름 개선은 진행하고, 정책·권한·비용·상태 의미가 새로 결정되는 경우만 확인한다.
- 검토용 다듬은본은 비교 자료다. 개별 제안이 승인·반영됐는지는 작업 기록에서 확인하며 문서 전체를 자동으로 확정하지 않는다.

비고(역조공 수락): 라벨은 「수락」, 팬 버튼과 문장은 「받기」로 단어가 둘이지만 역할이 다르다 — 라벨은 상태 이름, 버튼·문장은 행동이다. 「승인」은 크리에이터의 카카오톡 서명에만 쓴다.

## 8. 내부 진단과 사용자 오류

사용자에게 노출되는 오류는 CLAUDE.md의 문구 규칙을 따른다. 서버·DB·운영자 진단에는 원인을 정확히 나타내는 기술 용어와 식별자를 사용할 수 있다. ‘DB가 요청을 거부했다’를 무조건 ‘받지 않았다’로 바꾸지 않는다. 기술 오류를 사용자 화면에 그대로 출력하지 말고, 확인된 문제와 가능한 다음 행동으로 안내한다. 개인정보·인증정보·시크릿을 오류나 로그에 남기지 않는 원칙은 별도로 지킨다.

## 9. 전역 금지어 (금지어 검사용)

아래 목록은 문맥을 읽지 않는 보조 검사가 찾는 제한된 표현이다. 개념별 오용이나 과장 여부는 문장 전체로 검토한다. ‘안전한·공식·팔로워·배송지·복호화’처럼 올바른 용도가 있는 단어는 여기서 일괄 차단하지 않는다. 허용되었다고 실제보다 넓은 보장을 해도 된다는 뜻은 아니다.

```
팬꾹도 주소를 열지 않아요
절대 유출되지 않습니다
저희도 열 수 없습니다
100% 안전
받을지 정하고 있어요
```

목록을 추가할 때는 정확한 문제와 적용 범위를 설명한다. 특정 문맥에서만 잘못된 단어는 개념 표의 주의사항에 적는다. 검사 통과는 사실·의미·말투의 검토 완료가 아니다.

## 10. 문구만으로 결정하지 않는 것

새로운 정책·비용·권한·상태 의미는 용어집에서 만들지 않는다. 확정된 서비스 기준과 실제 동작이 다르면 차이를 기록하고 관련 결정을 요청한다. 기존 용어의 표현 개선이나 이미 합의한 문구의 반영을 같은 승인 대기로 취급하지 않는다.

## 11. 공통 문구 상수

같은 의미·같은 조건의 반복 문구는 아래 상수를 재사용한다. 현재 문자열은 각 소스 파일에 있으며 여기 복제하지 않는다. 공통 상수도 개선 대상이다. 고칠 때 실제 문구·사용 조건·연결된 안내를 함께 확인하며, 사용자용·약관용·짧은 라벨용 표현을 무리하게 하나로 합치지 않는다.

| 상수 | 파일 | 의미와 검토 기준 |
| --- | --- | --- |
| `PROMISE` | `src/shared/config/site-copy.ts` | 승인·주소 보호·검수 안내. 주소는 누구에게 비공개인지, 검수는 어떤 선물에 어떤 범위로 적용되는지 명확히 한다. 승인 후 팬에게 주소가 공개되는 것으로 읽히지 않게 한다. |
| `PROMISE_SHORT` | `src/shared/config/site-copy.ts` | 위 안내의 짧은 표기. 짧게 줄이더라도 적용 조건을 잘못 전달하지 않는다. |
| `NO_ADDRESS_ASK` | `src/shared/config/site-copy.ts` | 사칭 연락 안내. 요청하지 않는 연락 경로와 사이트에서의 주소 입력을 구분한다. |
| `DECLINED_PHRASE` | `src/entities/order/ui/fan-stage-copy.ts` | 거절 결과. 거절 사실과 선물 처리 결과를 안내하며 상대의 속마음·거절 이유를 추측하지 않는다. |
| `EXPIRED_TEXT` | `src/entities/order/ui/fan-stage-copy.ts` | 승인 기한 만료 결과. 직접 거절과 기한 만료를 구분한다. |
| `APPROVAL_EXPIRED_MESSAGE` | `src/entities/order/config/approval-deadline.ts` | 승인 기한이 지나 처리된 선물 안내. 짧은 상태 표기와 같은 뜻을 유지한다. |

상수 정의의 검사 제외는 기존 검사 동작일 뿐 정확성 보증이나 수정 금지가 아니다. 현재 코드에 남아 있는 옛 문구도 다음 문구 반영 시 검토한다.

## 12. 화면별 문구와 이력

홈 제목·배너·오류 화면 등 자리별 문구는 각 화면과 문구 검토 자료에서 관리한다. 과거 시안의 문장을 용어집에 중복 고정하지 않는다. 이번 문서 정리는 작성 기준의 변경이며, 검토용 문구 1~5 전체의 승인이나 사이트 반영을 뜻하지 않는다. 과거 문구와 결정의 이력은 Git 기록·DECISIONS·작업 기록에서 확인한다.

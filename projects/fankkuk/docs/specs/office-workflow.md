# 사무실 작업 흐름 스펙

사무실에 들어온 상자는 「스캔 → 서버가 허용해야 다음 단계」로만 움직인다. 사람이 상태를 고르거나 주문번호를 손으로
넣는 자리가 없다. 어기면 생기는 사고는 넷이다 — 다른 주문의 상자에 송장이 붙거나, 승인 안 된 상자가 나가거나,
같은 상자가 두 번 처리되거나, 7일 규칙이 하루 늦거나 빨리 돌아 팬과 다투게 된다.
팬 선물(크리에이터에게 가는 상자)과 역조공(팬에게 가는 상자)이 같은 흐름을 탄다. 다른 점은 출고 조건(크리에이터 승인 /
팬의 받기)과 검수 범위(역조공은 추적 장치 검사 없음)뿐이다.

## 정한 것 (2026-10-04)

1. **7일 자동 반려의 기준 시각은 결제 완료(등록) 시각부터 168시간이다.** 크리에이터는 상자가 오기 전에도 승인할 수 있으니
   기한은 「크리에이터가 답하는 기한」이고, 팬이 늦게 보내도 늘지 않는다. (배송대행지는 도착부터 세지만 그건 보관 기한이다)
2. **반송은 팬의 원 송장 주소로 보낸다. 주문에 이어진 상자는 팬꾹이 선불로 보내고 환불에서 택배 원가(배송비 칸)를 뺀다**(payment INV-M8,
   2026-10-08 정책 ③ — 착불이면 팬이 반송비를 두 번 내고, 착불을 거부하면 상자가 돌아온다). 어느 주문에도 이어지지 않은 상자(미확인·보류)는
   뺄 결제가 없어 착불이다. 입고 때 뗀 원 송장을 보관 봉투에 따로 두었다가 반송 때 그 주소를 쓰고, 끝나면 파쇄한다
   (INV-W8). 원 송장에는 팬이 직접 적은 팬 주소만 있고 크리에이터 정보는 없다 — 크리에이터에게 가는 상자에서 떼어 내기만 하면
   지키려던 것(크리에이터 쪽에 팬 신상이 가지 않는다)은 그대로다. 팬에게 반송 주소를 다시 받는 안은 팬이 끝내 입력하지 않을 때
   폐기 다툼이 생겨 고르지 않았다. 개인정보처리방침에 원 송장 보관·파쇄를 적는다.

## 불변식

- INV-W1: 상자의 상태는 아래 전환표의 한 칸씩만 움직인다. 표에 없는 전환은 거부한다. 상태를 고르는 화면·API 는 없다.
  | 지금 | 스캔한 것 | 작업 화면 | 다음 | 거부 조건 |
  |---|---|---|---|---|
  | 결제 완료(입고 전) | 원 송장 바코드 + 6자리 | 입고 | 입고 완료 + 내부 라벨 출력 | inbound-address-code INV-C5 의 보류 조건 → 보류(W5) |
  | 보류 | (운영자 확인 · 주인의 찾기) | — | 입고 완료 또는 반송 대기 | inbound-address-code INV-C4 ②·C9 를 거치지 않음 |
  | 입고 완료 | 내부 QR | 입고 | 라벨 부착 확인 | 직전에 출력한 라벨과 다른 주문번호 |
  | 라벨 부착 확인 | 내부 QR | 검수 | 검수 완료 또는 반송 대기 | 검수 기록(W4)이 없음 |
  | 검수 완료 | 내부 QR | 출고 | 송장 출력(주소 열기 1회) | 출고 조건(W3) 불충족 |
  | 송장 출력 | 송장 바코드 | 출고 | 출고 확정 | 송장번호가 이 상자의 것이 아님 |
  (강제 위치: DB 전환 함수 — 지금 상태 확인과 바꾸기가 한 처리 / 서버 — 스캔 값 꼴 검사)
  위반 시: 검수를 건너뛴 상자, 입고도 안 된 상자가 출고된다.

- INV-W2: 같은 상자에 스캔이 동시에 두 번 와도 전환은 한 번만 일어난다. 두 번째는 「이미 처리됨」으로 거부된다.
  한 작업자가 라벨 부착 확인 스캔을 하기 전에는 같은 작업자의 다음 상자 입고 스캔을 거부한다(1상자 1스캔 1라벨).
  (강제 위치: DB 전환 함수 — 행 잠금 / 작업자별 「부착 대기 중인 라벨」 한 칸)
  위반 시: 라벨이 두 장 나가 상자가 섞이거나, 출고 확정이 두 번 기록된다.

- INV-W3: 출고 조건 — 팬 선물은 크리에이터 승인(approval-signature)이 있고 거절·반려·차액 미납(payment INV-M12)이 아니어야
  한다. 차단은 승인 전 주문을 거절로 바꿀 뿐이고, 이미 승인된 주문은 차단해도 출고한다(decline-block INV-D8, 카드 d27). 역조공은 팬이 받기를 했어야 한다(reverse-gift INV-R7). 송장 출력(주소 열기)은 대표만(address-protection INV-P8).
  승인 전에 상자가 먼저 와도 입고·검수까지는 정상 처리하고, 출고 목록에만 나오지 않는다.
  (강제 위치: DB 전환 함수 / 복호화 함수)
  위반 시: 승인 안 된 상자가 크리에이터 주소로 나간다 — 팬꾹이 파는 약속이 깨진다.

- INV-W4: 검수 완료·반송 대기로 넘기려면 그 상자의 검수 기록이 먼저 있어야 한다 — 단계별 결과(블루투스·RF·금속 / 역조공은
  겉면·금지 물품만), 시각, 담당 운영자. 검수 기록은 고치거나 지울 수 없다. 추적 장치가 나온 팬 선물은 바로 반송하지 않고
  보관하며 크리에이터와 보낸 팬에게 알린다(notifications INV-N13). 보관된 때(검수 완료 스캔 시각)부터 168시간이 지나면 자동 처리가
  반송 대기로 넘긴다(INV-W6) — 크리에이터가 위험을 알 기회를 주면서 상자가 선반에 무기한 남지 않게(2026-10-08 정책 ②).
  환불은 검수 불합격 줄(payment INV-M8 — 상품 대금 칸만)을 따른다.
  팬 선물 상자가 검수 완료(통과)로 넘어가려면 실측 구간 기록도 먼저 있어야 한다 — 요금이 상자 크기로 갈리므로 실측이 빠지면
  차액(payment INV-M11)을 확인할 길이 없다(2026-10-08 결정, 정책 질문 ⑤). 보관·반송으로 가는 상자와 역조공 상자(겉면·금지 물품만)는 실측 없이 넘어간다.
  (강제 위치: DB — 전환 함수가 검수 기록과 팬 선물의 실측 기록을 확인 / 검수 기록 표는 추가만)
  위반 시: 「검수했다」는 근거가 없어 분쟁 때 배상 기준이 무너진다.

- INV-W5: 6자리로 이어지지 않은 상자는 「보류」(미확인 입고)로 기록된다 — 도착 시각, 원 송장 바코드, 택배사, 발신인 이름 앞 한 글자,
  보류 사유, 보관 선반 번호만. 팬이 「받는 주소 없이 보냈어요」에 송장번호·택배사·이름 앞 1글자를 넣어 셋 다 맞으면 그 팬의 결제 완료 주문과
  이어진다(inbound-address-code INV-C4 ②·C10). 이 목록은 운영자에게만 보이고, 운영자가 손으로 주문번호를 붙이는 길은 없다.
  (강제 위치: DB — 매칭 함수는 팬 본인 토큰 + 세 값 일치로만)
  위반 시: 다른 팬의 상자가 엉뚱한 주문으로 처리된다.

- INV-W6: 7일 규칙은 서버 시각으로 168시간을 센다(시간대와 상관없는 경과 시간). 대상: 크리에이터가 승인하지 않은 팬 선물
  (결제 완료 시각 기준), 매칭 안 된 미확인 입고(도착 시각 기준), 차액 미납(payment INV-M13), 역조공 받기 기한(INV-R10),
  추적 장치로 보관된 상자(보관된 시각 기준 → 반송 대기, INV-W4), 승인 뒤 도착하지 않은 상자(결제 완료 기준 14일 알림 · 30일 닫기, INV-W10).
  자동 처리와 사람의 처리(승인·받기·매칭·차액 결제)가 겹치면 둘 중 하나만 반영된다. 자동 처리는 관리자 화면에서 지금 돌릴
  수도 있고, 같은 대상을 두 번 처리하지 않는다.
  (강제 위치: DB 자동 처리 함수 — 조건부 갱신 한 문장 / 사람 처리 함수 — 행 잠금 뒤 기한 확인)
  위반 시: 승인한 직후에 자동 반려돼 상자가 반송되거나, 같은 반송이 두 번 기록된다.

- INV-W8: 입고 때 뗀 원 송장은 그 상자의 내부 QR 번호가 적힌 보관 봉투에 넣고, 상자와 따로 보관 선반에 둔다(크리에이터에게
  가는 상자에 섞이지 않게). 반송 송장은 상자의 내부 QR 을 스캔해야만 출력 화면이 열리고, 화면에는 그 상자의 봉투 번호만 뜬다 —
  사람이 봉투나 주문을 고르는 칸은 없다. 봉투는 반송 확정 또는 출고 확정 때 파쇄하고 「파쇄함」(누가·언제)을 기록한다.
  원 송장의 내용(이름·주소·전화)은 시스템에 입력하지 않는다(INV-W7).
  (강제 위치: DB 전환 함수 — 반송 송장 출력은 반송 대기 상자의 QR 스캔으로만 / 파쇄 기록은 추가만)
  위반 시: 다른 팬의 원 송장이 붙어 상자가 엉뚱한 팬에게 가거나, 원 송장이 크리에이터에게 가는 상자에 섞인다.

- INV-W7: 이 흐름의 어느 화면·기록에도 실명·주소·전화번호가 들어가지 않는다(admin-console INV-K8). 미확인 입고의 발신인은
  앞 한 글자만, 원 송장은 시스템에 입력하지 않는다.
  (강제 위치: DB 표에 그 칸이 없다 / 읽기 함수 반환 칸)
  위반 시: 작업 화면이 개인정보 목록이 된다.

- INV-W9: 크리에이터가 받은 선물의 진행 단계 읽기 함수는 계정·크리에이터 ID 를 인자로 받지 않는다. 로그인 토큰이 확인한 계정이
  받는 크리에이터인 주문만 돌려주고, 결제가 끝나지 않은 주문은 돌려주지 않는다(payment INV-M6 — 돈을 내지 않은 등록은 크리에이터에게 오지 않은 것이다).
  한 줄의 칸은 주문번호 · 보낸 사람 닉네임 · 상자 수 · 지금 단계 · 단계마다 처리된 시각(결제 완료·입고·검수·출고) · 검수 결과(통과·보관·반송 중 하나) ·
  배송 칸(배송중·수령)뿐이다. 실명·주소·전화번호, 보낸 사람의 계정 ID·아이디, 팬이 쓴 원 송장번호, 검수 장비별 세부, 처리한 운영자는 없다
  (INV-W7, admin-console INV-K8 — 열람 기록 읽기도 처리한 사람을 「대표인지 아닌지」로만 돌려준다). 크리에이터행 출고 송장번호도 넣지 않는다 —

  「도착하지 않음」으로 닫는다 — 그 상자의 받는 주소 6자리는 무효가 되고(inbound-address-code INV-C3 과 같은 끝), 그 상자 금액은 환불 대상이 된다

  그 주문의 상자로 입고되고, 출고할 수 없는 상자라 검수 뒤 반송 대기로 간다(INV-W6 의 「나갈 수 없게 된 상자」, 선불 반송).

  위반 시: 결제·승인까지 된 주문이 상자 없이 기한 없이 남고, 받는 주소 6자리가 계속 유효하다(2026-10-08 카드 d50).

- INV-W11: 자동 처리(INV-W6·W10 등 시간 규칙 전부)와 승인 요청 3일 재알림 줄 넣기(notifications INV-N8)는 DB 예약 작업이 5분마다 주문번호 없이 전부 돌린다.

  팬·크리에이터·익명이 앱 경로로 자동 처리를 부를 길은 늘지 않는다. 예약과 사람의 처리가 겹쳐도 하나만 반영된다(INV-W6 그대로).
  (강제 위치: DB — 예약 작업 등록, 자동 처리 함수의 실행자 판정)
  위반 시: 운영자가 누르지 않으면 7일 반려·30일 닫기·재알림이 돌지 않는다. 판정을 넓게 풀면 아무나 자동 처리를 돌린다.

- INV-W12: 한 주문(역조공은 한 몫)을 건드리는 쓰기 처리는 모두 같은 순서로 잠근다 — 상자 줄(순번 차례) → 승인 요청 → 주문 줄(역조공은 몫 줄) → 받는 주소 6자리 → 사무소 상자 줄.
  내부 QR 을 스캔해 시작하는 처리(라벨 확인·검수·실측·송장 출력·출고·반송)도 그 QR 의 상자와 주문을 먼저 잠근 뒤 사무소 상자 줄을 잠근다. 앞 단계를 이미 쥔 채
  뒤 단계를 기다리는 일만 있고 거꾸로 기다리는 일이 없어서, 같은 주문의 처리 둘이 겹치면 뒤에 온 쪽이 기다렸다가 앞쪽이 끝난 상태를 보고 판단한다.
  (강제 위치: DB — QR 잠금 함수 하나가 순서를 쥐고, 상자·주문에서 시작하는 처리 함수는 같은 순서를 따른다)
  위반 시: 실측과 대표 취소처럼 같은 주문을 동시에 만지는 두 처리가 서로를 기다리다 한쪽이 오류(교착)로 되돌려진다. 자료는 어긋나지 않지만 작업자는 이유 모를 실패를 보고 다시 스캔해야 한다.
## 시나리오

- S1 (INV-W1): Given 결제 완료 상자 / When 입고 화면에서 원 송장 스캔 / Then 입고 완료, 내부 라벨 1장.
- S1b (INV-W1, 실패경로): Given 입고 완료 상자 / When 출고 화면에서 스캔 / Then 거부, 상태 그대로.
- S1c (INV-W1, 실패경로): Given 아무 상태 / When 상태 값을 직접 바꾸는 요청 / Then 그런 함수가 없다(권한 거부).
- S2 (INV-W2, 동시): Given 검수 완료 상자 / When 출고 확정 스캔 두 개가 동시에 / Then 하나만 반영.
- S2b (INV-W2, 실패경로): Given 라벨을 출력했지만 부착 확인 전 / When 같은 작업자가 다음 상자 입고 스캔 / Then 거부.
- S3 (INV-W3, 실패경로): Given 승인 없는 검수 완료 팬 선물 / When 송장 출력 / Then 거부, 출고 목록에 없음.
- S3b (INV-W3, 실패경로): Given 받기 전 역조공 상자 / When 송장 출력 / Then 거부.
- S3c (INV-W3): Given 승인 전 도착 / When 입고·검수 / Then 정상 처리, 출고 목록에는 없음.
- S4 (INV-W4, 실패경로): Given 검수 기록 없는 상자 / When 검수 완료 스캔 / Then 거부. S4b: 검수 기록 수정·삭제 → DB 거부.
- S4c (INV-W4): Given 추적 장치가 나온 팬 선물 / When 검수 결과 기록 / Then 반송 대기가 아니라 보관, 크리에이터 알림 1건.
- S4d (INV-W4, 실패경로): Given 통과 기록만 있고 실측이 없는 팬 선물 / When 검수 완료 스캔 / Then 거부, 단계 그대로. 실측 기록 뒤 → 검수 완료.
- S4e (INV-W4): Given 보관(추적 장치) 결과 / When 검수 완료 스캔 / Then 실측 없이도 보관.
- S4f (INV-W4·W6): Given 보관된 상자 / When 보관 + 167시간에 자동 처리 / Then 보관 그대로. 168시간 / Then 반송 대기, 주문의 검수 결과 「반송」, 환불은 상품 대금 칸만.
- S5 (INV-W5): Given 안 맞는 송장 / When 입고 스캔 / Then 미확인 입고 1줄(발신인 앞 한 글자만).
- S5b (INV-W5): Given 별빛의 결제 완료 주문 + 같은 송장번호의 미확인 입고 / When 별빛이 내 물건 찾기 / Then 이어지고 입고 완료.
- S5c (INV-W5, 실패경로): Given 달토끼 / When 별빛 상자의 송장번호로 찾기 / Then 달토끼에게 결제 완료 주문이 없으면 이어지지 않음.

- S6c (INV-W6, 동시): Given 기한 직전 / When 크리에이터 승인과 자동 반려가 동시에 / Then 하나만 반영.

- S11 (INV-W11): Given DB / Then 자동 처리 예약 작업이 5분 간격으로 하나 등록돼 있고, 그 작업 명령을 DB 직접 연결로 돌리면 7일 지난 미승인 주문이 반려된다.
- S11b (INV-W11, 실패경로): Given 팬·크리에이터·익명 로그인 / When 앱 경로로 자동 처리 함수 / Then 거부(42501), 아무것도 바뀌지 않는다.

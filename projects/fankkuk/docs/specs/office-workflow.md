# 사무실 작업 흐름 스펙

사무실에 들어온 상자는 「스캔 → 서버가 허용해야 다음 단계」로만 움직인다. 사람이 상태를 고르거나 주문번호를 손으로
넣는 자리가 없다. 어기면 생기는 사고는 넷이다 — 다른 주문의 상자에 송장이 붙거나, 승인 안 된 상자가 나가거나,
같은 상자가 두 번 처리되거나, 7일 규칙이 하루 늦거나 빨리 돌아 팬과 다투게 된다.
팬 선물(크리에이터에게 가는 상자)과 역조공(팬에게 가는 상자)이 같은 흐름을 탄다. 다른 점은 출고 조건(크리에이터 승인 /
팬의 받기)과 검수 범위(역조공은 추적 장치 검사 없음)뿐이다.

## 정할 것 (승인 때 함께 정한다)

1. **7일 자동 반려의 기준 시각** — 추천: 결제 완료(등록) 시각부터 168시간. 다른 안: 사무실 도착(입고) 시각부터 168시간.
   결제 완료 기준이면 팬이 늦게 보내도 기한이 늘지 않아 사무실 보관이 길어지지 않는다.
2. **반송할 팬 주소** — 원본은 「원 송장 주소로만 반송하고 반송 후 폐기」다. 원 송장은 입고 즉시 떼어 파쇄하므로, 추천은
   **입고 때 원 송장을 사진 없이 보류 봉투에 따로 보관하고 반송 때 그 송장의 주소로 착불 반송, 반송 확정과 함께 파쇄**한다.
   주소를 시스템에 입력하지 않는다. 다른 안: 반송이 필요해지면 팬에게 반송 주소를 받기(역조공처럼 봉인 입력).

## 불변식

- INV-W1: 상자의 상태는 아래 전환표의 한 칸씩만 움직인다. 표에 없는 전환은 거부한다. 상태를 고르는 화면·API 는 없다.
  | 지금 | 스캔한 것 | 작업 화면 | 다음 | 거부 조건 |
  |---|---|---|---|---|
  | 결제 완료(입고 전) | 원 송장 바코드 | 입고 | 입고 완료 + 내부 라벨 출력 | 송장번호가 어느 상자와도 안 맞음 → 미확인 입고(W5) |
  | 입고 완료 | 내부 QR | 입고 | 라벨 부착 확인 | 직전에 출력한 라벨과 다른 주문번호 |
  | 라벨 부착 확인 | 내부 QR | 검수 | 검수 완료 또는 반송 대기 | 검수 기록(W4)이 없음 |
  | 검수 완료 | 내부 QR | 출고 | 송장 출력(주소 열기 1회) | 출고 조건(W3) 불충족 |
  | 송장 출력 | 송장 바코드 | 출고 | 출고 확정 | 송장번호가 이 상자의 것이 아님 |
  (강제 위치: DB 전환 함수 — 지금 상태 확인과 바꾸기가 한 처리 / 서버 — 스캔 값 꼴 검사)
  위반 시: 검수를 건너뛴 상자, 입고도 안 된 상자가 출고된다.

- INV-W2: 같은 상자에 스캔이 동시에 두 번 와도 전환은 한 번만 일어난다. 두 번째는 「이미 처리됨」으로 거부된다.
  한 작업자가 라벨 부착 확인 스캔을 하기 전에는 같은 작업자의 다음 상자 입고 스캔을 거부한다(1상자 1스캔 1라벨).
  (강제 위치: DB 전환 함수 — 행 잠금 / 작업자별 「부착 대기 중인 라벨」 한 칸)
  위반 시: 라벨이 두 장 나가 상자가 섞이거나, 출고 확정이 두 번 기록된다.

- INV-W3: 출고 조건 — 팬 선물은 크리에이터 승인(approval-signature)이 있고 거절·반려·차단·차액 미납(payment INV-M12)이 아니어야
  한다. 역조공은 팬이 받기를 했어야 한다(reverse-gift INV-R7). 송장 출력(주소 열기)은 대표만(address-protection INV-P8).
  승인 전에 상자가 먼저 와도 입고·검수까지는 정상 처리하고, 출고 목록에만 나오지 않는다.
  (강제 위치: DB 전환 함수 / 복호화 함수)
  위반 시: 승인 안 된 상자가 크리에이터 주소로 나간다 — 팬꾹이 파는 약속이 깨진다.

- INV-W4: 검수 완료·반송 대기로 넘기려면 그 상자의 검수 기록이 먼저 있어야 한다 — 단계별 결과(블루투스·RF·금속 / 역조공은
  겉면·금지 물품만), 시각, 담당 운영자. 검수 기록은 고치거나 지울 수 없다. 추적 장치가 나온 팬 선물은 반송하지 않고
  보관하며 크리에이터에게 알린다.
  (강제 위치: DB — 전환 함수가 검수 기록을 확인 / 검수 기록 표는 추가만)
  위반 시: 「검수했다」는 근거가 없어 분쟁 때 배상 기준이 무너진다.

- INV-W5: 송장번호가 어느 상자와도 맞지 않는 상자는 「미확인 입고」로 기록된다 — 도착 시각, 발신인 이름 일부(앞 한 글자 + *),
  보관 선반 번호만. 팬이 「내 물건 찾기」에 원 송장번호를 넣어 맞으면 그 팬의 결제 완료 주문과 이어진다. 운영자가 손으로
  주문번호를 붙이는 길은 없다.
  (강제 위치: DB — 매칭 함수는 팬 본인 토큰 + 송장번호 일치로만)
  위반 시: 다른 팬의 상자가 엉뚱한 주문으로 처리된다.

- INV-W6: 7일 규칙은 서버 시각으로 168시간을 센다(시간대와 상관없는 경과 시간). 대상: 크리에이터가 승인하지 않은 팬 선물
  (기준 시각은 「정할 것」 1), 매칭 안 된 미확인 입고(도착 시각 기준), 차액 미납(payment INV-M13), 역조공 받기 기한(INV-R10).
  자동 처리와 사람의 처리(승인·받기·매칭·차액 결제)가 겹치면 둘 중 하나만 반영된다. 자동 처리는 관리자 화면에서 지금 돌릴
  수도 있고, 같은 대상을 두 번 처리하지 않는다.
  (강제 위치: DB 자동 처리 함수 — 조건부 갱신 한 문장 / 사람 처리 함수 — 행 잠금 뒤 기한 확인)
  위반 시: 승인한 직후에 자동 반려돼 상자가 반송되거나, 같은 반송이 두 번 기록된다.

- INV-W7: 이 흐름의 어느 화면·기록에도 실명·주소·전화번호가 들어가지 않는다(admin-console INV-K8). 미확인 입고의 발신인은
  앞 한 글자만, 원 송장은 시스템에 입력하지 않는다.
  (강제 위치: DB 표에 그 칸이 없다 / 읽기 함수 반환 칸)
  위반 시: 작업 화면이 개인정보 목록이 된다.

## 시나리오

- S1 (INV-W1): Given 결제 완료 상자 / When 입고 화면에서 원 송장 스캔 / Then 입고 완료, 내부 라벨 1장.
- S1b (INV-W1, 실패경로): Given 입고 완료 상자 / When 출고 화면에서 스캔 / Then 거부, 상태 그대로.
- S1c (INV-W1, 실패경로): Given 아무 상태 / When 상태 값을 직접 바꾸는 요청 / Then 그런 함수가 없다(권한 거부).
- S2 (INV-W2, 동시): Given 검수 완료 상자 / When 출고 확정 스캔 두 개가 동시에 / Then 하나만 반영.
- S2b (INV-W2, 실패경로): Given 라벨을 출력했지만 부착 확인 전 / When 같은 작업자가 다음 상자 입고 스캔 / Then 거부.
- S3 (INV-W3, 실패경로): Given 승인 없는 검수 완료 팬 선물 / When 송장 출력 / Then 거부, 출고 목록에 없음.
- S3b (INV-W3, 실패경로): Given 받기 전 역조공 상자 / When 송장 출력 / Then 거부.
- S3c (INV-W3): Given 승인 전 도착 / When 입고·검수 / Then 정상 처리, 출고 목록에는 없음.
- S4 (INV-W4, 실패경로): Given 검수 기록 없는 상자 / When 검수 완료 스캔 / Then 거부. S4b: 검수 기록 수정·삭제 → DB 거부.
- S4c (INV-W4): Given 추적 장치가 나온 팬 선물 / When 검수 결과 기록 / Then 반송 대기가 아니라 보관, 크리에이터 알림 1건.
- S5 (INV-W5): Given 안 맞는 송장 / When 입고 스캔 / Then 미확인 입고 1줄(발신인 앞 한 글자만).
- S5b (INV-W5): Given 별빛의 결제 완료 주문 + 같은 송장번호의 미확인 입고 / When 별빛이 내 물건 찾기 / Then 이어지고 입고 완료.
- S5c (INV-W5, 실패경로): Given 달토끼 / When 별빛 상자의 송장번호로 찾기 / Then 달토끼에게 결제 완료 주문이 없으면 이어지지 않음.
- S6 (INV-W6): Given 기준 시각 + 167시간 59분 / When 자동 처리 / Then 변화 없음. S6b: + 168시간 → 반려, 같은 처리 두 번 돌려도 반려 기록 1건.
- S6c (INV-W6, 동시): Given 기한 직전 / When 크리에이터 승인과 자동 반려가 동시에 / Then 하나만 반영.
- S7 (INV-W7): Given 작업 화면·미확인 입고 목록 / When 응답을 검사 / Then 실명·주소·전화 꼴의 값이 없다.

## 신뢰 경계

- 믿는 값: 스캐너가 읽은 바코드·QR 값(꼴 검사 뒤), 로그인 토큰으로 확인한 운영자, DB 의 상자 상태, 서버 시각
- 믿지 않는 값: 화면이 보내는 상태·주문번호 직접 입력(그 칸이 없다), 작업자의 기억

## 비범위

- 택배사 송장 API 연동·실제 라벨 프린터 — 계약 뒤. 그 전에는 송장 출력이 개발용 복호화(INV-P12)와 화면 인쇄로 대신한다
- 알림톡 발송 — 알림 스펙
- 검수 장비 자체(블루투스 스캔 앱 등)

# 사무실 작업 흐름 스펙

사무실에 들어온 상자는 「스캔 → 서버가 허용해야 다음 단계」로만 움직인다. 사람이 상태를 고르거나 주문번호를 손으로
넣는 자리가 없다. 어기면 생기는 사고는 넷이다 — 다른 주문의 상자에 송장이 붙거나, 승인 안 된 상자가 나가거나,
같은 상자가 두 번 처리되거나, 7일 규칙이 하루 늦거나 빨리 돌아 팬과 다투게 된다.
팬 선물(크리에이터에게 가는 상자)과 역조공(팬에게 가는 상자)이 같은 흐름을 탄다. 다른 점은 출고 조건(크리에이터 승인 /
팬의 받기)과 검수 범위(역조공은 추적 장치 검사 없음)뿐이다.

## 정한 것 (2026-10-04)

1. **7일 자동 반려의 기준 시각은 결제 완료(등록) 시각부터 168시간이다.** 크리에이터는 상자가 오기 전에도 승인할 수 있으니
   기한은 「크리에이터가 답하는 기한」이고, 팬이 늦게 보내도 늘지 않는다. (배송대행지는 도착부터 세지만 그건 보관 기한이다)
2. **반송은 보낸 사람이 확인한 등록 주소로 보낸다**(2026-10-17 카드 d100 — 그 전에는 원 송장 주소로만 보냈다). 반송할 상자가 생기면 보낸 사람에게 설정에 등록한
   주소(address-protection INV-P17)가 「주소를 확인해 주세요」 창으로 뜨고, 바꾸거나 그대로 「확인」을 눌러야 반송 송장이 나간다(등록 전이면 그 자리에서 입력).
   확인하지 않으면 14일에 한 번 더 알리고, 30일이 지나면 처분 대상이 된다(INV-W15). 원 송장 주소로 보내는 길은 주문에 이어진 상자에는 없다(사용자 2026-10-17 「반송 직전에 입력한 주소가 있으면 뜨게하고, 원하면 바꿀 수도 있게해. 안바꿀거면 '선택' '확인' 하게 해서 진행」). **주문에 이어진 상자는 팬꾹이 선불로 보내고 환불에서 택배 원가(배송비 칸)를 뺀다**(payment INV-M8,
   2026-10-08 정책 ③ — 착불이면 팬이 반송비를 두 번 내고, 착불을 거부하면 상자가 돌아온다). 어느 주문에도 이어지지 않은 상자(미확인·보류)는
   확인할 사람도 뺄 결제도 없어 지금처럼 원 송장 주소로 착불이다. 원 송장에는 팬이 직접 적은 팬 주소만 있고 크리에이터 정보는 없다 — 크리에이터에게
   가는 상자에서 떼어 내기만 하면 지키려던 것(크리에이터 쪽에 팬 신상이 가지 않는다)은 그대로다. 봉투는 반송 확정·출고 확정·처분·경찰 인계 때 파쇄한다(INV-W8).
   2026-10-04 에는 팬이 끝내 입력하지 않으면 폐기 다툼이 생긴다는 이유로 반송 주소를 다시 받지 않았다. 지금은 14일 재알림과 30일 처분을 약관·환불 규정에
   미리 적어 그 다툼을 막는다. 개인정보처리방침에 원 송장 보관·파쇄와 등록 주소 보관을 적는다.

- INV-W2: 같은 상자에 스캔이 동시에 두 번 와도 전환은 한 번만 일어난다. 두 번째는 「이미 처리됨」으로 거부된다.
  한 작업자가 라벨 부착 확인 스캔을 하기 전에는 같은 작업자의 다음 상자 입고 스캔을 거부한다(1상자 1스캔 1라벨).
  (강제 위치: DB 전환 함수 — 행 잠금 / 작업자별 「부착 대기 중인 라벨」 한 칸)
  위반 시: 라벨이 두 장 나가 상자가 섞이거나, 출고 확정이 두 번 기록된다.

- INV-W3: 출고 조건 — 팬 선물은 크리에이터 승인(approval-signature)이 있고 거절·반려·차액 미납(payment INV-M12)이 아니어야
  한다. 차단은 승인 전 주문을 거절로 바꿀 뿐이고, 이미 승인된 주문은 차단해도 출고한다(decline-block INV-D8, 카드 d27). 역조공은 팬이 받기를 했어야 한다(reverse-gift INV-R7). 송장 출력(주소 열기)은 대표만(address-protection INV-P8).

- INV-W4: 검수 완료·반송 대기로 넘기려면 그 상자의 검수 기록이 먼저 있어야 한다 — 단계별 결과(블루투스·RF·금속 / 역조공은

    그대로 「확인」을 누른다. 등록 전이면 「주소를 입력해 주세요」로 그 자리에서 등록한 뒤 확인한다(INV-P17). 확인 없이 진행되는 길은 없다.
    확인하는 순간 그 주소의 암호문을 상자에 복사해 둔다 — 확인한 뒤 설정의 주소를 바꾸거나 지워도 이 상자는 확인한 때의 주소로 간다(INV-P18).
    확인은 보낸 사람 본인만(로그인 토큰, 남의 상자·없는 상자는 같은 「없음」)이고, 반송 송장을 출력하기 전까지 다시 확인(다른 주소로 바꾸기)할 수 있다.
  · 시간은 상자가 반송 대기가 된 시각부터 센다(그 처리에서 보낸 사람에게 반송 주소를 확인해 달라는 알림이 간다, notifications INV-N22).
    14일(336시간)이 지나도 확인하지 않았으면 한 번 더 알린다(상자마다 한 번). 30일(720시간)이 지나도 확인하지 않았으면 자동 처리가 「처분 대상」으로 바꾸고, 그 뒤에는 확인을 받지 않는다.
  · 처분: 운영자가 처분 대상 상자의 내부 QR 을 스캔해 처분을 기록한다(운영자·시각, 추가만). 원 송장 봉투도 그때 파쇄한다.
    환불은 다시 계산하지 않는다 — 주문이 끝날 때 이미 반송 택배비(배송비 칸)를 뺀 금액이 정해졌고, 그 칸은 보관·처분 비용이 된다(payment INV-M8).
  · 어느 주문에도 이어지지 않은 상자(보류·미확인)는 확인할 사람이 없어 이 규칙 밖이다 — 지금처럼 원 송장 주소로 착불 반송(정한 것 2).
  · 확인과 자동 처리(처분 대상)가 겹치면 상자 줄을 잠근 뒤(INV-W12) 하나만 반영된다. 같은 상자를 두 번 처분 대상으로 바꾸거나 재알림을 두 번 넣지 않는다.
  · 보낸 사람에게는 처리할 일의 「반송 주소 확인」 카드로 보인다(action-center INV-J1).
  (강제 위치: DB — 반송 주소 확인 함수(로그인 토큰으로 보낸 사람 판정, 상자 줄 잠금 뒤 상태·기한 확인, 등록 주소 암호문 복사) / 반송 송장 출력 함수가 복사본을 확인 /
  자동 처리 함수 — 재알림·처분 대상 / 처분 기록 함수는 운영자만, 기록 표는 추가만)
  위반 시: 확인하지도 않은 상자가 옛 주소로 나가 이사한 팬에게 닿지 않거나, 확인한 뒤에 바꾼 주소 때문에 엉뚱한 곳으로 간다. 기한이 없으면 찾아가지 않는 상자가 선반에 끝없이 쌓인다.

- INV-W16: 보낸 팬이 위치 추적기로 판정된 상자를 보낸 적이 있으면(어느 크리에이터에게 보낸 주문이든 추적기 판정 기록이 하나라도 있으면), 그 팬의 팬 선물 상자는
  탐지기 반응과 상관없이 연다 — 「개봉 대상」(2026-10-17 카드 d100). 처음 보내는 팬이나 전자기기 신고는 개봉 이유가 아니다(카드 d99, DECISIONS 2026-10-17).
  · 판정은 검수 기록을 남기는 순간 서버가 한다 — 등록 때가 아니라서, 등록 뒤에 다른 주문에서 추적기가 나온 팬의 상자도 열린다. 검수 화면은 상자를 불러올 때 같은 판정으로
    「개봉 대상 — 추적기 판정 이력」을 띄운다.
  · 개봉 대상 상자의 검수 기록에는 개봉 결과(「장치 없음」·「장치 나옴」)가 꼭 있다. 「장치 나옴」이면 블루투스·RF 반응과 같이 직원 판정(추적기·추적기 아님)과 그 짝의 결론(INV-W4)을 따른다.
    「장치 없음」이면 반응이 없는 상자와 같다(통과는 실측 기록 뒤). 개봉 대상이 아닌 상자의 기록에는 개봉 결과 칸이 비어 있다. 역조공 상자는 대상이 아니다.
  · 이 판정과 개봉 사실은 크리에이터·보낸 팬의 어느 화면·알림에도 없고, 등록 화면에서도 미리 알리지 않는다(알리면 표시된 팬이 다른 계정으로 옮겨 간다). 요금은 그대로다.
  (강제 위치: DB — 검수 기록 함수가 보낸 팬의 추적기 판정 기록을 읽어 개봉 결과 칸을 요구·거부, 검수 기록 표 제약 / 검수 화면 읽기 / 크리에이터·팬 읽기 함수의 반환 칸에 없음)
  위반 시: 추적기를 넣었던 팬이 이번에는 꺼 둔 채 보내면 탐지기에 걸리지 않고 크리에이터에게 간다. 개봉 대상이 팬에게 보이면 그 팬이 다른 계정으로 피해 간다.
## 시나리오

- S1 (INV-W1): Given 결제 완료 상자 / When 입고 화면에서 원 송장 스캔 / Then 입고 완료, 내부 라벨 1장.
- S1b (INV-W1, 실패경로): Given 입고 완료 상자 / When 출고 화면에서 스캔 / Then 거부, 상태 그대로.
- S1c (INV-W1, 실패경로): Given 아무 상태 / When 상태 값을 직접 바꾸는 요청 / Then 그런 함수가 없다(권한 거부).
- S2 (INV-W2, 동시): Given 검수 완료 상자 / When 출고 확정 스캔 두 개가 동시에 / Then 하나만 반영.
- S2b (INV-W2, 실패경로): Given 라벨을 출력했지만 부착 확인 전 / When 같은 작업자가 다음 상자 입고 스캔 / Then 거부.
- S3 (INV-W3, 실패경로): Given 승인 없는 검수 완료 팬 선물 / When 송장 출력 / Then 거부, 출고 목록에 없음.
- S3b (INV-W3, 실패경로): Given 받기 전 역조공 상자 / When 송장 출력 / Then 거부.
- S3c (INV-W3): Given 승인 전 도착 / When 입고·검수 / Then 정상 처리, 출고 목록에는 없음.
- S4 (INV-W4, 실패경로): Given 검수 기록 없는 상자 / When 검수 완료 스캔 / Then 거부. S4b: 검수 기록 수정·삭제 → DB 거부.
- S4c (INV-W4·W14): Given 블루투스 반응 · 판정 「추적기」인 팬 선물 / When 검수 결과 기록 뒤 검수 완료 스캔 / Then 반송 대기가 아니라 추적기 보관, 크리에이터 알림 1건, 팬 알림 없음, 팬 화면에는 「확인 중」.
- S4d (INV-W4, 실패경로): Given 통과 기록만 있고 실측이 없는 팬 선물 / When 검수 완료 스캔 / Then 거부, 단계 그대로. 실측 기록 뒤 → 검수 완료.
- S4e (INV-W4): Given 추적기 보관 결과 / When 검수 완료 스캔 / Then 실측 없이도 추적기 보관.
- S4f (INV-W4·W14): Given 추적기 보관된 상자 / Then 환불은 상품 대금 칸만(지금 0원). 신고 보관·경찰 인계·반송 어느 쪽으로 끝나도 환불 금액이 같다.
- S4g (INV-W4): Given 블루투스 반응 · 판정 「추적기 아님」 · 실측 기록 / When 크리에이터 확인으로 기록 뒤 검수 완료 스캔 / Then 크리에이터 확인 대기, 검수 기록에 판정 「추적기 아님」,
  크리에이터 「확인할 선물」 알림 1건, 추적기 기록은 없다. 「추적기 아님」 · 반송으로 기록하면 일반 반송 대기.
  실패경로: 반응이 있는데 판정이 없음 · 반응이 없는데 판정이 있음 · 「추적기」인데 통과·반송·크리에이터 확인 · 「추적기 아님」인데 통과·추적기 반송 ·
  판정 없이 크리에이터 확인 · 역조공 기록에 판정 칸 → 기록 거부. 표에 직접 「추적기 아님」 + 통과를 넣어도 거부.
- S4i (INV-W4·W13): Given 크리에이터 확인 대기 상자 / When 그 주문의 크리에이터가 받기를 고르고 운영자가 처리 / Then 검수 완료, 승인돼 있으면 출고할 수 있다. 거절을 고르고 운영자가 처리 / Then 반송 대기,
  팬 「돌려보낼 상자」 알림 1건, 주문 검수 결과 「반송」. 처리 전까지 주문은 검수 단계(「라벨」)에 머물고 검수 결과는 비어 있다.
  실패경로: 다른 크리에이터·보낸 팬의 고르기 → 「없음」 · 고른 상태에서 또 고르기 → 「이미 고름」 · 끝난 주문·나갈 수 없게 된 상자 → 「끝남」(목록에도 없다).
- S4j (INV-W4·W6·W13): Given 고른 것이 없는 크리에이터 확인 대기 상자 / When 검수 완료 + 167시간 59분 자동 처리 / Then 그대로, 고르기를 받는다. 정확히 168시간 / Then 고르기는 「기한 지남」,
  자동 처리가 반송 대기로 넘기고 확인 줄에 「기한 지남」, 팬 알림 1건(두 번 돌려도 한 번). 그 뒤 골라도 「기한 지남」.
- S4k (INV-W4): Given 확인 대기 상자가 있는 주문 / When 거절·7일 반려·대표의 입고 뒤 취소 / Then 상자는 바로 반송 대기, 답은 빈 채, 팬 「돌려보낼 상자」 알림 없음,
  환불은 그 주문의 줄(검수 불합격 아님). 이미 끝난 주문의 상자를 크리에이터 확인으로 검수 완료 스캔하면 묻지 않고 반송 대기.
- S4h (INV-W4): Given 소형으로 신고한 팬 선물 / When 검수 화면에서 상자를 불러옴 / Then 실측 구간에 소형이 골라져 있고, 바꾸지 않고 「실측 기록」을 누르면 소형으로 기록된다.
- S13 (INV-W13): Given 하루의 확인 대기 상자 / When 하루가 받기 고름 / Then 확인 줄에 받기 선택, 상자는 확인 대기 그대로, 출고 목록에 없다. When 하루가 취소 / Then 선택 없음, 다시 거절을 고를 수 있다. 기록에는 고름·취소·고름 세 줄.
- S13b (INV-W13, 실패경로): Given 운영자가 받기 선택을 처리한 상자 / When 하루가 취소 · 다시 고르기 / Then 「이미 처리됨」, 상자는 검수 완료 그대로. 고른 것이 없는 상자에 운영자 처리 / Then 「고른 것이 없음」.
  팬·다른 크리에이터의 취소 / Then 「없음」. 크리에이터가 운영자 처리 함수를 부름 / Then 거부.
- S13c (INV-W13, 실패경로): Given 운영자가 화면에서 받기 선택을 봄, 그사이 하루가 취소하고 거절을 고름 / When 운영자가 본 선택(받기)으로 처리 / Then 「바뀜」, 아무것도 바뀌지 않는다.
- S13d (INV-W13, 동시): Given 받기 선택인 상자 / When 하루의 취소와 운영자 처리가 동시에 / Then 하나만 반영 — 취소가 먼저면 처리 거부(상자 확인 대기, 선택 없음), 처리가 먼저면 취소 거부(검수 완료, 받기 처리 완료). 둘 다 반영된 상태는 없다.
- S13e (INV-W13·W6): Given 거절 선택인 채 운영자가 처리하지 않은 상자 / When 검수 완료 + 168시간 자동 처리 / Then 반송 대기, 팬 알림 1건, 확인 줄은 거절 처리 완료(처리한 사람 = 자동 처리). 받기 선택이었으면 / Then 검수 완료.
  기한 뒤 하루의 취소 / Then 「기한 지남」. 자동 처리를 두 번 돌려도 한 번.
- S14 (INV-W14): Given 추적기 보관 상자 / When 하루가 「신고하지 않기」를 고르고 운영자가 처리 / Then 반송 대기, 별빛에게 「돌려보낼 상자」 1건, 반송 주소 고르기가 열린다.

- S14b (INV-W14·W6): Given 고른 것이 없는 추적기 보관 상자 / When 검수 완료 + 168시간 자동 처리 / Then 반송 대기와 팬 알림 1건(두 번 돌려도 한 번). 「신고하기」를 고른 채였으면 / Then 신고 보관.
- S14c (INV-W14, 실패경로): Given 추적기 보관 상자가 있는 주문 / When 크리에이터가 주문을 거절 / Then 그 상자는 추적기 보관 그대로, 신고 선택을 받는다. 다른 상자는 반송 대기.
- S14d (INV-W14, 실패경로): Given 신고 보관 상자 / When 보낸 팬으로 선물 상세 읽기 / Then 「확인 중」만, 「신고」「추적기」 꼴의 값이 없다. 직원이 아닌 계정의 경찰 인계 기록 / Then 거부.
- S15 (INV-W15): Given 별빛의 반송 대기 상자, 등록 주소 「집」 / When 확인 창에서 「확인」 / Then 상자에 주소 암호문 복사, 대표가 반송 송장 출력 가능. 그 뒤 별빛이 설정 주소를 바꿔도 / Then 상자의 주소는 그대로.

- S15b (INV-W15, 실패경로): Given 확인하지 않은 반송 대기 상자 / When 반송 송장 출력 / Then 거부. 다른 팬이 그 상자의 주소 확인 / Then 「없음」.
- S15c (INV-W15): Given 확인하지 않은 반송 대기 상자 / When 반송 대기 + 335시간 자동 처리 / Then 알림 없음. 336시간 / Then 재알림 1건(두 번 돌려도 1건). 720시간 / Then 처분 대상, 그 뒤 확인 「기한 지남」.
- S15d (INV-W15): Given 처분 대상 상자 / When 운영자가 QR 스캔 후 처분 기록 / Then 처분 기록 1건·봉투 파쇄 1건, 환불 금액은 바뀌지 않는다.
- S15e (INV-W15, 동시): Given 반송 대기 + 720시간 직전 / When 별빛의 확인과 자동 처리가 동시에 / Then 하나만 반영.
- S15f (INV-W15): Given 어느 주문에도 이어지지 않은 보류 상자의 반송 / Then 확인 없이 봉투 번호로 반송 송장이 나온다.
- S16 (INV-W16): Given 다른 크리에이터에게 보낸 상자가 추적기로 판정된 적이 있는 별빛의 새 팬 선물 / When 탐지기 반응 없이 검수 기록 / Then 개봉 결과가 없으면 거부, 「장치 없음」이면 기록, 검수 화면에 「개봉 대상」.
  「장치 나옴」이면 판정 칸이 있어야 한다.
- S16b (INV-W16, 실패경로): Given 추적기 판정 이력이 없는 팬의 전자기기 선물 / When 개봉 결과를 넣은 검수 기록 / Then 거부(개봉 대상이 아니다). 역조공 기록에 개봉 결과 / Then 거부.
- S16c (INV-W16): Given 개봉 대상 상자 / When 크리에이터의 선물 현황·승인 요청, 보낸 팬의 등록 화면·선물 상세 읽기 / Then 개봉 대상·개봉 결과 꼴의 값이 없다.
- S5 (INV-W5): Given 안 맞는 송장 / When 입고 스캔 / Then 미확인 입고 1줄(닉네임 일치 여부만).
- S5b (INV-W5): Given 별빛의 결제 완료 주문 + 같은 송장번호의 미확인 입고 / When 별빛이 내 물건 찾기 / Then 이어지고 입고 완료.
- S5c (INV-W5, 실패경로): Given 달토끼 / When 별빛 상자의 송장번호로 찾기 / Then 달토끼에게 결제 완료 주문이 없으면 이어지지 않음.
- S6 (INV-W6): Given 기준 시각 + 167시간 59분 / When 자동 처리 / Then 변화 없음. S6b: + 168시간 → 반려, 같은 처리 두 번 돌려도 반려 기록 1건.
- S6c (INV-W6, 동시): Given 기한 직전 / When 크리에이터 승인과 자동 반려가 동시에 / Then 하나만 반영.
- S8 (INV-W8): Given 반송 대기 상자 / When 내부 QR 스캔 / Then 그 상자의 봉투 번호(= 내부 QR 번호)가 뜨고 반송 송장 출력, 반송 확정 때 파쇄 기록 1건.
- S8b (INV-W8, 실패경로): Given 검수 완료(반송 대기 아님) 상자 / When 반송 송장 출력 요청 / Then 거부.
- S8c (INV-W8): Given 출고 확정 / Then 그 상자의 봉투 파쇄 기록 1건. 파쇄 기록 수정·삭제 → DB 거부.
- S7 (INV-W7): Given 작업 화면·미확인 입고 목록 / When 응답을 검사 / Then 실명·주소·전화 꼴의 값이 없다.
- S9 (INV-W9): Given 하루에게 온 주문 셋(입고·검수 완료·출고), 모모에게 온 주문 하나 / When 하루로 읽기 / Then 하루 주문 셋만, 각 줄에 단계 시각이 맞게.
- S9b (INV-W9, 실패경로): Given 하루에게 온 결제 대기 주문 / When 하루로 읽기 / Then 그 주문은 없다. 팬·운영자·익명으로 읽기 / Then 0줄.

- S10 (INV-W10): Given 승인된 상자 2개 주문, 하나만 입고 / When 결제 + 335시간 자동 처리 / Then 알림 없음. 336시간 / Then 팬에게 알림 1건(두 번 돌려도 1건).
  When 720시간 / Then 안 온 상자 닫힘·6자리 무효, 입고된 상자는 그대로 진행. 두 번 돌려도 같은 상자를 다시 닫지 않는다.
- S10b (INV-W10): Given 상자가 하나도 입고되지 않은 승인된 주문 / When 결제 + 720시간 / Then 주문 취소, 6자리 전부 무효.
- S10d (INV-W10): Given A 만 도착한 채 거절된 주문의 B / When 결제 + 720시간 / Then 닫지 않는다. B 가 도착 / Then 그 주문 상자로 입고 → 검수 → 반송 대기.
- S10c (INV-W10, 실패경로): Given 결제 + 720시간이 지났지만 그 상자가 입고됨 / Then 닫지 않는다. 출고·취소된 주문은 건드리지 않는다.
- S11 (INV-W11): Given DB / Then 자동 처리 예약 작업이 5분 간격으로 하나 등록돼 있고, 그 작업 명령을 DB 직접 연결로 돌리면 7일 지난 미승인 주문이 반려된다.
- S11b (INV-W11, 실패경로): Given 팬·크리에이터·익명 로그인 / When 앱 경로로 자동 처리 함수 / Then 거부(42501), 아무것도 바뀌지 않는다.
- S12 (INV-W12, 동시): Given 다른 처리가 그 상자 줄(또는 주문 줄)을 쥐고 있다 / When 내부 QR 로 시작하는 처리·대표의 입고 뒤 취소 / Then 기다리는 동안 그 사무소 상자 줄은 아직 잠그지 않았다.
- S12b (INV-W12, 동시): Given 입고된 상자의 주문 / When 실측 기록과 대표의 입고 뒤 취소가 동시에 / Then 둘 다 교착 없이 끝난다(하나는 성공, 다른 하나는 바뀐 상태를 보고 거부될 수 있다).
## 신뢰 경계

- 믿는 값: 스캐너가 읽은 바코드·QR 값(꼴 검사 뒤), 로그인 토큰으로 확인한 운영자, DB 의 상자 상태, 서버 시각
- 믿지 않는 값: 화면이 보내는 상태·주문번호 직접 입력(그 칸이 없다), 작업자의 기억

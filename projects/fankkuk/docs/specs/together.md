# 함께한 시간 스펙

팬이 「내 선물」에서 크리에이터별로 들어가는 본인 전용 기록 화면이다. 처음 선물한 날과 며칠째, 함께한 선물 수·받은 답장 수,
다음 기념일 칸, 시간순 선물 카드와 답장 카드를 보여 준다. 10번째·30번째 선물과 처음 선물한 지 1년째 카드는 테두리와 문구가 다르다.
팬은 등록할 때 선물 사진 한 장을 올릴 수 있고, 그 사진은 이 화면에서만 본다.

어기면 생기는 사고: 다른 사람이 주소를 알아내 남의 선물 기록·사진을 보거나, 크리에이터가 팬의 사진을 보거나, 사진에 촬영 위치가 남거나,
숫자가 다른 팬과 비교되는 꼴로 나간다.

## 불변식

- INV-F1: 함께한 시간 화면의 내용(선물 카드·답장 카드·개인 기록 숫자)은 그 팬 본인의 주문에서만 만든다. 다른 계정으로 같은 주소를 열면
  없는 페이지와 같다. 크리에이터·운영자 화면에도 이 화면을 여는 길이 없다.
  (강제 위치: DB 본인 읽기 함수 — 로그인 토큰의 계정 주문만 / 시험 — 다른 팬·크리에이터 계정으로 조회 거부 계약 시험)
  위반 시: 팬의 선물 기록이 남에게 보인다(추가분 불변식 19).
- INV-F2: 팬이 올린 선물 사진은 비공개 저장소에 두고 그 팬 본인만 연다(짧게 유효한 서명 주소). 크리에이터·운영자·다른 팬은 열 수 없다.
  서버가 받아 실제 이미지인지 열어 보고(그림 크기 상한), 사진 정보(EXIF 등)를 모두 지운 뒤 줄여 저장한다. 원본은 저장하지 않는다. 주문당 한 장.
  (강제 위치: 저장소 — 비공개, 쓰기는 서버만 / 서버 — 사진 저장 경로 하나 / 시험 — 위치 정보가 든 사진을 올리고 저장된 파일에 없는지)
  위반 시: 팬의 집 위치가 담긴 사진이 남거나 크리에이터가 팬 사진을 본다(추가분 불변식 19·23).
- INV-F3: 개인 기록 두 칸은 실제 수와 같다 — 함께한 선물 = 그 크리에이터에게 보낸 주문 가운데 결제가 끝나고 취소·결제 실패가 아닌 것의 수,
  받은 답장 = 그 주문들의 상자에 남은(지우지 않은) 답장 수. 처음 선물한 날은 그 가운데 가장 이른 주문 날짜(한국 시간), 며칠째는 그날을 1일째로 센다.
  (강제 위치: DB 본인 읽기 함수 하나)
  위반 시: 숫자가 실제와 달라 기록을 믿지 못한다.
- INV-F4: 특별 카드는 10번째·30번째 선물 카드와, 처음 선물한 날로부터 1년이 지난 뒤 처음 보낸 선물 카드다. 본인 화면에서만 다르게 보이고
  어떤 공개 화면·공유 카드에도 순번·횟수가 나가지 않는다. 연속 기록(끊기면 사라지는 것)은 없다.
  (강제 위치: 화면 쪽 계산 함수 하나 / 공유 카드 생성은 순번을 받지 않는다)
  위반 시: 팬끼리 횟수를 비교하게 된다(추가분 불변식 18).
- INV-F5: 「선물 보내기」는 크리에이터가 받을 수 있을 때만 보인다. 쉬는 중이면 다음 기념일 칸은 그대로 두고 버튼 자리에 「{날짜}부터 다시 받아요」(시안 그대로).
  크리에이터가 그 팬을 차단했으면 지금 규칙대로 버튼을 숨기지 않고, 누르면 「선물을 받을 수 없는 크리에이터예요」(decline-block INV-D7) — 기록은 그대로 남는다(사용자 답 ⑬).
  (강제 위치: 서버 — 크리에이터 페이지와 같은 판정)
  위반 시: 차단 사실을 팬이 짐작하거나 쉬는 중인 크리에이터에게 보내라고 권한다.
- INV-F6: 화면에 금액은 없다. 날짜는 날짜 단위만, 시각은 없다. 이 화면 전체를 공유하는 기능은 없고 답장 카드 단위 공유만 있다(gift-reply INV-G9).
  (강제 위치: 서버 — 화면용 읽기에 금액·시각 칸이 없음)
  위반 시: 금액 비교가 생기거나 도착 시각이 드러난다.
- INV-F7: 나만 보는 메모는 선물 이름(앞뒤 공백을 뺀 0~20자, 한 줄)과 내용(앞뒤 공백을 뺀 0~200자, 줄바꿈 허용) 두 칸이고 둘 다 선택이다. 둘 다 비면 저장하지 않는다.
  메모는 주문 표가 아니라 **메모만 담는 따로 된 표**에 주문당 한 줄로 두고, 그 표는 행 보안을 켜고 정책을 두지 않으며 화면 쪽 키(익명·로그인 사용자)에 권한이 없다.
  메모는 등록과 같은 처리에서 저장되고, 메모 주인은 서버가 세션에서 확인한 보낸 사람이다(등록 함수의 보낸 사람과 같다). 메모는 물품 이름(`item_kind`)을 채우지 않고, 물품 이름은 메모를 채우지 않는다.
  등록 화면은 메모를 「나만 보는 메모」 덩어리로 물품 이름과 떨어뜨려 둘을 구분한다(시안 v21). 물품 이름 칸에 공개 범위 안내 문구는 붙이지 않는다(2026-10-15 사용자 「쓸대없이 문구를 남발하면 사이트가 어색해보여」).
  (강제 위치: DB — 따로 된 표, 권한 회수, 길이 제약 / 서버 입력 경계 / 등록 처리)
  위반 시: 메모가 주문 칸이면 크리에이터·운영자용 함수를 고치다 한 칸만 더 적어도 샌다. 팬이 「기타」 글을 나만 보는 줄 알고 개인적인 내용을 적어 크리에이터에게 간다.
- INV-F8: 메모 표를 읽거나 쓰는 DB 함수는 정해진 셋뿐이다 — 등록 때 저장, 보낸 팬 본인의 선물 상세 읽기, 보낸 팬 본인의 보낸 선물 목록 읽기. 읽기 둘은 계정 ID 를 인자로 받지 않고 로그인 토큰의 계정이 그 주문의 보낸 사람일 때만 메모를 준다.
  크리에이터·직원·대표 권한으로 부를 수 있는 어떤 함수의 응답에도, 승인 요청의 서명 원문, 알림 본문, 결제사로 가는 주문 이름, 공유 카드·미리보기·공지 이미지, 함께한 시간의 답장 카드 공유(gift-reply INV-G9)에도 메모는 없다.
  (강제 위치: DB — 메모 표를 참조하는 함수 허용 목록 / 시험 — ① 구조: DB 함수 본문 전체에서 메모 표 이름을 참조하는 함수가 허용 목록 셋뿐인지 ② 응답: 알아볼 수 있는 표시 값을 메모로 심고, 크리에이터·직원·대표로 로그인해 열린 표·함수를 모두 불러 그 값이 한 번도 나오지 않는지, 보낸 팬으로는 선물 상세에 나오는지)
  위반 시: 팬이 「나만 본다」고 믿고 쓴 글(예: 「고백 편지 들어 있음」)이 크리에이터나 운영자 화면에 나간다. 카드 d87 ②가 깨진다.

### 나만 보는 메모가 새는 길 (2026-10-15 코드에서 확인)

- 주문 표·상자 표는 행 보안이 켜져 있고 정책이 없어 밖으로 나가는 길은 DB 함수뿐이다. 그 함수들은 안에서 주문 줄 전체를 잡기도 하지만 돌려주는 칸은 하나씩 적혀 있다 — 그래서 메모를 주문 칸으로 두면 함수를 고치며 칸 하나를 더 적는 순간 샌다(INV-F7 이 따로 된 표인 이유).
- 크리에이터·사무실·운영자에게 주문이 나가는 길: 승인 요청 목록·승인 내역·서명할 원문(서명된 원문은 고칠 수 없다)·받은 선물·확인할 선물·추적기 반송·사무실 QR 조회·송장 출력 원문·관리자 결제 목록·알림 본문.
- 팬이 쓴 글이 이미 크리에이터에게 가는 칸이 있다: 물품 종류가 「기타」일 때 팬이 쓴 1~30자 물품 이름. 메모의 「선물 이름」과 섞이기 쉽다.
- 배포 전 개인정보 노출 검사(address-protection INV-P9)는 이름·전화번호·주소 꼴만 찾아서 자유 글인 메모가 새도 0건이다. 그래서 INV-F8 의 시험 ①②가 따로 필요하다 — 그 검사의 「모두 부르기」와 허용 목록 구조 검사에 메모 표와 심은 값을 더한다. 시험 계정 메모에는 전화번호 꼴을 넣지 않는다(넣으면 그 검사가 본인 응답을 잡는다).

## 스스로 정한 것 (추가분·사용자 답에 없던 세부)

- 주소: `/gifts/with/{크리에이터의 링크 주소 또는 ID}` — 판단. 내용은 로그인한 팬의 주문에서만 만들어지므로 주소를 알아도 남의 기록이 나오지 않는다.
- 「보낸 선물」 목록을 크리에이터별로 묶고, 묶음 머리에서 이 화면으로 온다(action-center INV-J14). 크리에이터가 한 명이어도 바로 넘기지 않는다(2026-10-21 카드 d104 — 묶음 하나가 보인다). 「‹ 보낸 선물로」는 보낸 선물 목록으로 간다.
- 함께한 선물 수에 거절·반려된 주문도 넣는다 — 판단. 팬이 보낸 마음의 기록이다. 카드에는 「받지 않은 선물이에요」로 보인다.
- 1년째 카드: 처음 선물한 날 + 1년 이후 첫 선물 — 판단.
- 사진: jpg·png·webp, 10MB·4천만 화소 이하, 긴 변 1280 webp — 판단. 「상자·송장이 아니라 선물만 찍어 주세요」 안내.
- 사진은 등록 화면에서 올린다(선택). 등록 뒤 이 화면에서 바꾸거나 지울 수 있다 — 판단.
- 탈퇴한 크리에이터는 「탈퇴한 크리에이터」·기본 이미지, 「선물 보내기」 없음(사용자 답 ⑭) — 탈퇴 흐름이 생길 때 적용.

## 시나리오

- S1 (INV-F1, 실패경로): Given 팬 A 의 하루님 기록 / When 팬 B·크리에이터 하루·로그인 안 함이 같은 주소를 엶 / Then 없는 페이지(로그인 안 함은 로그인으로).
- S2 (INV-F2, 실패경로): Given 팬 A 가 올린 사진 / When 크리에이터·팬 B 가 저장소 주소로 바로 엶 / Then 거부된다.
- S2b (INV-F2): Given 위치 정보가 든 사진 / When 팬이 올림 / Then 저장된 파일에 사진 정보가 없다. 원본은 어디에도 없다.
- S3 (INV-F3): Given 결제 3·결제 대기 1·취소 1·거절 1, 답장 2(하나는 지움 1 더) / When 화면 / Then 선물 4·답장 2.
- S4 (INV-F4): Given 선물 10개 / When 화면 / Then 10번째 카드만 특별하고, 공유 카드 생성 입력에 순번이 없다.
- S5 (INV-F5): Given 크리에이터가 쉬는 중 / When 기념일 칸 / Then 「{날짜}부터 다시 받아요」, 버튼 없음.
- S6 (INV-F6): Given 화면 응답 / When 칸을 봄 / Then 금액·시각이 없다.
- S7 (INV-F7): Given 별빛이 등록하며 선물 이름 「생일 편지와 인형」, 내용 3줄 / When 별빛이 선물 상세·보낸 선물 목록을 봄 / Then 메모가 나온다. 주문의 물품 이름은 고른 종류 이름 그대로다.
- S7b (INV-F7, 실패경로): Given 선물 이름 21자 또는 내용 201자 / When 등록 / Then 400, 주문·메모 모두 생기지 않는다. 별빛 세션으로 메모 표를 직접 읽기·쓰기 / Then 거부.
- S8 (INV-F8, 실패경로): Given 별빛의 주문에 표시 값 메모 / When 하루(받는 크리에이터)·직원·대표로 승인 요청 목록·승인 내역·서명 원문·받은 선물·확인할 선물·QR 조회·송장 출력 원문·관리자 결제 목록을 포함해 열린 함수를 모두 부름 / Then 그 값이 0번. 그 주문의 알림 줄 본문에도 없다.
- S8b (INV-F8, 실패경로): Given 메모 표 이름을 본문에 쓴 함수를 하나 심음 / When 구조 검사 / Then 허용 목록 밖이라 실패로 잡힌다(심은 위반이 잡히는지 보는 시험).

## 신뢰 경계 (INV-F7·F8)

- 믿는 값: 세션에서 확인한 보낸 사람 ID, DB 함수가 돌려주는 칸 목록
- 믿지 않는 값: 화면이 보낸 메모 글(길이 검사 전), 요청 본문의 계정 ID

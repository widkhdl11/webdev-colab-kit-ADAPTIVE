# 크리에이터의 승인 취소

지금은 승인을 되돌리는 길이 없다(approval-signature INV-S7). 이 스펙은 크리에이터가 승인한 선물의 승인을 취소하는 길을 더한다.
기준은 **팬꾹 사무실에 상자가 도착했는지(입고)** 하나다.

- 입고 전: 취소하면 주문은 **승인 대기로 돌아간다.** 크리에이터는 다시 승인할 수 있다(새 서명). 몇 번이든 자유롭다.
- 입고 뒤: 취소하면 주문은 **거절로 끝난다.** 환불·반송은 지금의 「입고 뒤 거절」 규칙 그대로다(payment INV-M8).

## 불변식

- INV-AC1: 「입고」는 그 주문의 상자가 **하나라도** 사무실에 도착한 것이다(입고 스캔). 상자가 하나도 오지 않았으면 입고 전이다.
  판정은 서버가 취소를 처리하는 순간의 상자 기록으로 한다 — 화면이 보낸 값을 쓰지 않는다.
  (강제 위치: DB 승인 취소 함수 — 입고 판정과 상태 변경을 한 처리에서)
  위반 시: 상자가 이미 들어온 주문이 「대기로 되돌림」으로 처리돼 검수·보관 중인 상자의 갈 곳이 사라진다.

- INV-AC2: 입고 전 취소는 승인을 **무효로 표시**하고 주문을 승인 대기로 되돌린다. 승인 기록과 서명 기록은 지우지 않는다(approval-signature INV-S12·S14 — 5년 보관 그대로).
  다시 승인하려면 **새 서명**을 받는다 — 지금의 승인과 같은 길(INV-S2·S4·S5·S17, 주문당 하루 서명 요청 5번 포함). 취소 전 서명으로는 다시 승인되지 않는다.
  승인 기한(결제 완료부터 168시간, INV-S6)은 취소로 늘어나지 않는다 — 기한이 지난 뒤 취소하면 그 주문은 다시 승인할 수 없고 지금 규칙대로 자동 반려된다.
  (강제 위치: DB 승인 취소 함수 · 승인 함수 — 무효가 된 승인의 서명은 받지 않는다)
  위반 시: 취소한 승인의 서명이 다시 쓰여 크리에이터 모르게 승인이 살아나거나, 취소·재승인으로 승인 기한을 끝없이 늘린다.

- INV-AC3: 주소를 푸는 복호화 함수는 **무효가 아닌 가장 최근 승인**의 서명만 다시 검증한다(address-protection INV-P4 (a) 에 더한다). 승인이 무효면 주소를 열지 않고 거부 로그를 남긴다.
  (강제 위치: 복호화 함수 진입부)
  위반 시: 취소한 승인의 서명으로 송장이 출력돼 크리에이터가 거둔 허락으로 주소가 나간다.

- INV-AC4: 입고 뒤 취소는 그 주문을 **거절**로 끝낸다 — 지금의 거절과 같은 상태·같은 환불(payment INV-M8 「입고 뒤 거절」 줄: 도착한 상자마다 상자 금액 − 배송비 칸, 아직 안 온 상자는 INV-M18)·같은 반송 흐름·같은 팬 알림.
  취소할 수 있는 때는 **첫 송장 출력 전까지**다. 송장이 한 번이라도 출력된 상자가 있으면 취소를 거부한다(그 뒤는 지금처럼 1:1 문의).
  (강제 위치: DB 승인 취소 함수 — 거절 처리는 지금의 거절 함수를 부른다, 송장 출력 기록 확인)
  위반 시: 주소가 이미 라벨로 나간 상자를 거절로 돌려 반송과 출고가 엇갈리거나, 거절과 다른 금액으로 환불된다.

- INV-AC5: 승인 취소는 그 주문의 크리에이터 본인만 한다. 카카오 서명은 받지 않고 화면의 확인 질문(「승인을 취소할까요?」)만 거친다 — 취소는 주소를 닫는 쪽이다.
  취소마다 누가·언제·입고 전/뒤를 기록한다. 같은 주문에 취소와 승인(서명 결과)이 동시에 와도 하나만 반영되고, 상태는 둘 중 나중 처리의 결과 하나다.
  (강제 위치: 승인 취소 라우트 — 로그인한 사람과 주문의 크리에이터 대조 / DB — 주문 줄 잠금)
  위반 시: 남이 크리에이터의 승인을 취소하거나, 취소와 재승인이 엇갈려 「승인됨」과 「대기」가 함께 남는다.

- INV-AC6: 승인이 한 번이라도 있었던 주문은 팬에게 **받는 주소를 계속 보인다** — 입고 전 취소로 대기로 돌아가도 가리지 않는다. 팬은 이미 상자를 보냈을 수 있다.
  환불 계산의 「받는 주소를 본 적이 있다」(payment INV-M8)는 승인이 있었던 주문에서 참이다.
  (강제 위치: 서버 — 주소 안내 조회는 「먼저 보내기」 기록 또는 승인 이력이 있으면 준다, approval-signature INV-S9)
  위반 시: 승인을 믿고 보낸 상자가 6자리 없는 「누구 것인지 모르는 상자」가 되거나, 환불에서 반송비를 빼야 할지 판정이 엇갈린다.

## 시나리오

- AC1 (INV-AC1·AC2): Given 승인된 주문, 상자 0개 도착 / When 크리에이터 「승인 취소」 → 확인 / Then 주문은 승인 대기, 승인·서명 기록은 그대로(무효 표시). 다시 「승인」 → 새 서명 요청.
- AC1b (INV-AC1·AC4): Given 상자 2개 중 1개 도착 / When 취소 / Then 거절로 끝남, 도착한 상자는 반송·상자 금액 − 배송비 칸 환불, 안 온 상자는 INV-M18.
- AC2 (INV-AC2): 취소 전 서명 결과가 취소 뒤에 도착 → 승인되지 않는다. 결제 + 170시간에 취소 → 다시 승인 거부(기한 지남).
- AC3 (INV-AC3): 입고 전 취소된 주문의 송장 출력 요청 → 거부·거부 로그.
- AC4 (INV-AC4): 송장이 출력된 상자가 있는 주문의 취소 → 거부, 상태 그대로.
- AC5 (INV-AC5): 다른 크리에이터가 취소 → 거부. 취소와 승인 서명 결과가 동시에 → 상태 하나.
- AC6 (INV-AC6): 승인 → 취소(대기) 뒤 팬 화면에 받는 주소가 그대로 보인다.

## 판단 근거 (표준인지 판단인지)

- 입고 = 상자 하나라도 도착: 판단(카드 d3 추천, 사용자 「다른건 다 추천대로」).
- 취소에 재인증 없음: 주문 거절·결제 취소에 재인증을 요구하지 않는 것이 보통 — 업계 표준에 가깝다. 주소를 여는 쪽(승인)만 서명을 받는다.
- 첫 송장 출력 전까지: 판단 — 송장 출력이 주소가 밖으로 나가는 순간이고, 환불 표의 「출고 뒤 없음」보다 앞에서 끊는다.
- 한 번 보인 주소는 계속 보임: 판단 — 승인을 보고 이미 보낸 상자가 길을 잃지 않게.

# 팬 결제와 환불 스펙

팬은 선물을 등록할 때 상자마다 구간 요금(배송비 포함, 소형 6,900원·중형 8,900원)을 낸다.
구간은 세 변 합과 무게 중 큰 쪽으로 정한다 — 소형 = 세 변 합 100cm 이하·5kg 이하, 중형 = 세 변 합 100cm 이하·10kg 이하.
중형을 넘는 상자는 받지 않는다. 도착 뒤 실측 구간이 신고보다 크면 차액을 따로 결제 요청한다. 결제가 끝나야
크리에이터에게 승인 요청이 간다. 결제는 브라우저가 PG 화면에서 인증하고, **서버가 PG 승인 API 를
호출해야 끝난다.** 브라우저가 보내는 금액과 "결제 성공" 이동은 위조할 수 있으므로 판단 근거가 아니다.
어기면 생기는 사고는 셋이다 — 덜 낸 금액으로 주문이 완료되거나, 한 결제가 두 번 반영되거나, 환불이
결제보다 많이 나간다.

## 불변식

- INV-M1: 결제 금액은 서버가 계산한다 — `상자별 신고 구간 요금의 합 (+ 상품 대금, 지금은 0)`.
  구간 요금은 서버 설정표에서만 읽는다. 결제 대기 기록을 만들 때 서버가 계산한 금액을 저장하고,
  브라우저가 보낸 금액은 쓰지 않는다. 상자가 0개이거나 중형을 넘는 구간이 있으면 결제 대기를 만들지 않는다.
  (강제 위치: 서버 — 결제 대기 기록 생성)
  위반 시: 팬이 금액을 고쳐 100원만 내고 주문을 완료한다.

- INV-M2: 결제 승인 API 를 부르기 전에, 성공 주소로 돌아온 `orderId`·`amount` 를 서버의 결제 대기 기록과
  대조한다. 기록이 없거나 금액이 다르면 승인 API 를 부르지 않고 그 결제 대기를 실패로 닫는다.
  (강제 위치: 서버 — 승인 처리 진입부)
  위반 시: 브라우저에서 금액을 바꾼 결제가 바뀐 금액으로 승인된다.

- INV-M3: 결제 완료는 서버가 부른 승인 API 응답의 상태가 `DONE` 이고, 응답의 `orderId`·`totalAmount` 가
  결제 대기 기록과 같을 때만 기록된다. 성공 주소에 도착한 것만으로는 완료가 아니다.
  (강제 위치: 서버 — 승인 응답 처리)
  위반 시: 승인되지 않은 결제(실패·만료·중단)가 완료로 기록된다.

- INV-M4: PG 비밀 키는 서버에서만 읽는다. 브라우저 번들과 공개 환경 변수(`NEXT_PUBLIC_` 접두어)에 없다.
  (강제 위치: 서버 설정 / 검사: 비밀 키 이름이 공개 접두어로 쓰이지 않음)
  위반 시: 누구나 우리 가맹점 이름으로 결제를 승인·취소한다.

- INV-M5: 한 주문의 결제 완료 기록은 하나다. 같은 결제의 승인 처리가 두 번·동시에 와도 결제 완료는
  한 번만 기록되고, 두 번째는 처음 결과를 돌려준다. 승인 API 호출에는 멱등 키를 붙인다.
  (강제 위치: DB 제약 — 주문당 결제 완료 1건 / 서버 — 멱등 키)
  위반 시: 새로고침 한 번에 결제 기록이 둘이 되고 정산·환불 계산이 틀어진다.

- INV-M6: 결제 완료 전에는 크리에이터에게 승인 요청을 만들지 않는다. (강제 위치: 서버 — 승인 요청 생성)
  위반 시: 돈을 안 낸 선물이 승인되고 사무실 주소가 공개된다.

- INV-M7: 결제 기록은 상품 대금·기본 서비스료·검수비·배송비를 서로 다른 칸에 저장하고, 네 칸의 합은 결제 금액과 같다.
  화면에는 구간 요금 한 금액만 보이지만, 기록의 배송비 칸 = 그 구간의 택배 원가(설정값), 검수비 칸 = 그 구간의 검수비
  (소형 1,500 · 중형 2,000), 기본 서비스료 칸 = 나머지다. 아래 INV-M8 의 「서비스료 칸」은 기본 서비스료 + 검수비를 뜻한다.
  차액 결제도 같은 방식으로 나눈다.
  (강제 위치: 서버 — 결제 기록 생성 / DB 제약 — 합계 일치)
  위반 시: 대행 수수료와 상품 대금이 섞여 매출·부가세 신고가 틀어진다(결정 D-03).

- INV-M8: 환불 금액은 서버가 주문 상태로 정한다. 브라우저나 관리자가 금액을 입력하지 않는다.

- INV-M9: 한 결제의 환불 합계는 결제 금액을 넘지 않는다. 같은 환불이 두 번·동시에 와도 한 번만 나간다.

- INV-M11: 차액은 서버가 상자마다 `실측 구간 요금 − 신고 구간 요금` 으로 계산한다(배송비·서비스료 칸도 각각의 차).

- INV-M16: 팬의 입고 전 취소(청약철회) — 결제를 마친 주문의 보낸 사람은 아직 상자가 하나도 입고되지 않았으면 선물 상세에서 직접 「취소하기」를 누를 수 있다.

  (강제 위치: DB — 「승인 중」이 된 시각 칸, 확인 대상 목록·반영 함수는 앱 서버 키만 / 서버 — 조회 응답 판정)
  위반 시: 돈은 나갔는데 선물·승인 요청이 영영 생기지 않는다. 확인을 너무 일찍 하면 아직 승인 중인 결제를 실패로 닫아 돈만 나간 주문이 생긴다. 금액이 다른 결제를 완료하면 덜 낸 금액으로 주문이 생긴다(INV-M3).

- INV-M20: 「확인 필요」 결제의 전액 취소 — INV-M19 가 「확인 필요」로 표시한 결제는 대표가 관리자 결제 화면에서 「전액 취소」로만 정리한다.
  팬 선물 결제·차액 결제·역조공 결제 모두 같다. 차액 청구는 하지 않는다.
  ① 표시할 때 결제사 조회 응답의 결제 키와 취소 가능 금액(부분 취소 뒤 남은 금액)을 같이 기록한다. 금액은 보여 주기용이다 — 결제사에는 금액을 비워
     남은 금액 전부 취소를 보낸다(표시 뒤 결제사 화면에서 일부를 더 취소했어도 남은 것만 취소된다). 화면은 금액을 보내지 않는다. 금액을 모르면 버튼이 열리지 않는다.
  ② 누를 수 있는 사람은 대표뿐이고, 표시가 있고 아직 「승인 중」인 결제에만 된다. 한 결제에 취소 기록은 하나다. 「처리 중」인 동안 다시 누르면
     결제사까지 가지 않고 거부한다. 실패했거나 「처리 중」이 2분 넘게 남은 기록은 같은 기록·같은 멱등 키로 다시 잡는다(결제사는 첫 요청의 결과를 돌려준다).
     결제사가 오류로 분명히 거절했을 때만 실패로 남긴다. 응답을 받지 못했거나(시간 초과·연결 끊김) 알아볼 수 없거나 전부 취소가 아니면 결과를 모르는 것 —
     기록을 「처리 중」으로 둔다(결제사에서는 취소가 됐을 수 있다, ④가 그동안 결제를 지킨다).
  ③ 결제사 취소가 이 금액으로 끝나면 같은 처리에서 취소 기록을 완료로, 결제를 실패로 닫는다(「승인 중인 줄만 바꾸기」, INV-M5).
     팬 선물·차액 결제면 보낸 팬에게 알림이 한 번 간다(notifications INV-N19). 그 뒤의 흐름은 지금 결제 실패와 같다 —
     첫 결제면 주문은 결제 전으로 남아 팬이 다시 등록해 결제하고, 차액이면 팬이 차액 결제를 다시 한다.
  ④ 취소 기록이 「처리 중」이거나 완료면, 늦게 돌아온 원래 승인 응답이 와도 그 결제를 완료로 바꾸지 않는다 — 돈은 돌려줬는데 주문이 진행되는 일을 막는다.
  ⑤ 차액 결제를 다시 준비하면 지난 결제의 확인 필요 표시·기록값은 비운다(새 결제번호로 처음부터).
  (강제 위치: DB — 취소 기록 표·잡기 함수(대표 로그인 토큰)·결과 반영 함수(앱 서버 키)·결제 줄 완료 막기 / 서버 — 결제사 취소 응답 판정)
  위반 시: 금액이 맞지 않는 결제가 그대로 남아 돈만 나간 주문이 생기거나, 같은 결제가 두 번 취소되거나, 돈을 돌려준 주문이 진행된다.

- INV-M18: 늦게 오는 상자 — 주문이 끝날 때(거절·7일 자동 반려·차단 거절·취소) 아직 안 온 상자는, 팬이 받는 주소를 본 적이 있으면
  (승인됐거나 「먼저 보내기」를 눌렀거나 상자가 하나라도 도착함) 이미 오고 있을 수 있어 닫지 않고 6자리를 살려 둔다(살려 둔 상자). 그 상자 몫은:
  ① 끝나는 때 주문 환불에 그 상자 금액 − 배송비 칸을 넣는다 — 배송비 칸(반송 택배비)만 남겨 둔다.
  ② 나중에 도착하면 살아 있는 6자리로 그 주문 상자로 입고돼 반송 대기로 간다(팬꾹 선불 반송 — 남겨 둔 배송비 칸으로). 더 돌려줄 것은 없다.
     늦게 온 상자가 검수에 걸려도 이미 돌려준 몫을 되찾지 않는다(어차피 반송되는 상자다).
  ③ 끝난 때(살려 둔 시각)부터 168시간 안에 오지 않으면 자동 처리가 「도착하지 않음」으로 닫는다 — 대표도 그 전에 닫을 수 있다.
     닫히면 남겨 둔 배송비 칸을 상자 환불로 돌려주고 그 상자의 6자리는 같은 처리에서 무효. 직원·팬·크리에이터는 닫을 수 없다.
  받는 주소를 본 적이 없는 주문의 상자는 올 수 없으므로 끝나는 때 6자리를 무효로 하고 그 상자 금액 전액을 주문 환불에 넣는다.
  닫기와 그 상자의 입고가 겹치면 둘 중 하나만 반영된다. 같은 상자를 두 번 닫지 않는다.
  (2026-10-10 B8·C10·D10 — 그 전에는 상자가 하나라도 도착한 거절·반려에만, 상자 몫 전체를 들고 있다가 대표가 닫았다)
  (강제 위치: DB — 주문 상태 트리거(안 온 상자의 6자리를 살려 둠), 입고 함수(끝난 주문의 상자는 반송 대기 길로), 닫기 함수(대표 판정·상자 줄 잠금 뒤 미도착 확인)·
  자동 처리, 환불 계산 함수)
  위반 시: 이미 보낸 상자가 착불로 돌아가 팬이 택배비를 두 번 내거나, 오지 않을 상자의 택배비를 영영 돌려주지 않거나, 그 상자 몫이 두 번 나간다.

- INV-M17: 대표의 입고 뒤 취소 — 입고 뒤 취소는 1:1 문의로 받아 대표가 관리자 화면에서 처리한다(사유 1~200자 필수, 기록 한 줄). 출고된 주문은 취소하지 않는다.
  취소하면 주문은 「취소」, 남은 6자리는 무효, 들어온 상자는 반려된 주문과 같은 길로 반송 대기로 간다(office-workflow INV-W6 의 「나갈 수 없게 된 상자」).
  검수에서 걸린 상자(반송·추적기 반송 판정, 중형 초과 실측)가 있어도 취소한다 — 걸린 상자는 0(검수 불합격 줄)이라 위반한 팬이 취소 요청으로 차감을 피하지 못한다
  (2026-10-10 B9 — 카드 d53 의 「취소하지 않는다」를 바꿈). 나머지 도착한 상자는 기본 서비스료 칸, 아직 안 온 상자는 INV-M18.
  환불은 INV-M8 의 「입고 뒤 취소」 줄. 직원·팬·크리에이터는 부를 수 없다.
  (강제 위치: DB 함수 — 대표 판정, 출고 전 확인, 취소 기록)
  위반 시: 직원이 돈이 걸린 취소를 하거나, 이유 없는 취소가 남아 환불 다툼의 근거가 없다.

- INV-M21: 무통장 입금은 주문마다 새로 발급된 입금 전용 계좌(가상계좌)로만 받는다. 회사 통장 직접 입금·입금자 이름 대조는 없다.
  결제 승인 응답이 「입금 기다리는 중」이면 주문은 **입금 대기**이고, 입금이 확인되기 전에는 결제가 끝난 주문으로 보지 않는다 —
  승인 요청이 크리에이터에게 가지 않고, 받는 주소·라벨·상자별 6자리도 나오지 않는다. 발급 금액은 서버가 계산한 금액(INV-M1 계열)과 같아야 한다.
  (강제 위치: 서버 — 결제 승인 처리, DB — 주문 상태 전이 함수)
  위반 시: 돈이 들어오지 않은 주문이 크리에이터에게 가고 상자가 발송된다.

- INV-M22: 입금 확인은 서버가 토스에 그 결제를 **직접 조회해 「완료」로 나온 것만** 믿는다. 입금 알림(웹훅)은 「지금 다시 조회하라」는 신호로만 쓰고,
  알림 본문의 상태 값으로 주문을 바꾸지 않는다. 알림의 비밀 값이 결제 승인 때 저장한 그 결제의 비밀 값과 다르면 조회도 하지 않고 버린다.
  같은 결제의 알림이 여러 번(다시 보내기·두 종류 알림) 와도 주문은 한 번만 바뀐다. 처리에 실패해도 알림에는 200 을 돌려주지 않아 토스가 다시 보내게 하고,
  자동 처리 예약 작업도 입금 대기 주문을 조회해 놓친 알림을 메운다.
  (강제 위치: 서버 — 입금 알림 입구·결제 조회, DB — 주문 줄 잠금과 「이미 반영됨」 확인을 한 처리에서)
  위반 시: 가짜 알림 하나로 입금하지 않은 주문이 결제 완료가 되거나, 같은 입금이 두 번 반영된다.

- INV-M23: 입금 기한은 계좌 발급 뒤 24시간이다. 기한이 지나도록 입금이 없으면 서버가 결제사에 그 결제의 취소를 먼저 요청하고, 주문은 결제 실패로 닫은 뒤 팬에게 「입금 기한이 지났어요」를 알린다
  (결제가 끝나지 않은 주문은 「취소」 상태가 될 수 없는 기존 규칙에 맞춰, 결제 대기 만료와 같은 길로 닫는다 — 2026-10-15 구현).
  기한 직전·직후에 입금 알림과 취소가 겹쳐도 둘 중 하나만 반영된다(조회 결과가 「완료」면 취소하지 않는다).
  (강제 위치: DB — 자동 처리 예약 작업이 주문 줄을 잠그고 조회 결과로만 바꿈)
  위반 시: 입금한 주문이 취소되거나, 기한 지난 계좌로 들어온 돈이 어디에도 반영되지 않는다.

- INV-M24: 입금 완료로 바뀐 뒤 토스 조회가 다시 「입금 기다리는 중」으로 나오면(드문 되돌림) 주문을 조용히 되돌리지 않는다 —

  위반 시: 승인·발송이 진행된 주문이 아무도 모르게 미입금 상태로 남는다.

- INV-M25: 무통장으로 낸 주문을 환불할 때는 팬이 환불 받을 계좌(은행·계좌번호·예금주)를 한 번 입력한다. 환불 계좌는 개인정보 구역에 암호화해

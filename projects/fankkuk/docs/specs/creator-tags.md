# 크리에이터 태그 스펙

크리에이터는 자기가 활동하는 곳과 방송 종류를 태그로 여러 개 고른다(예: 「치지직 · 버추얼」). 팬은 찾기 화면과 메인의 칩으로
태그별 크리에이터를 본다. 지금까지는 가입 때 「분야」를 빈칸에 자유롭게 적었고, 칩은 적힌 값을 모아 만들었다 — 그래서
「게임」「겜방」이 따로 칩이 되고 노래·먹방처럼 주 사용자(SOOP·치지직 방송인)에게 맞지 않는 칩이 나왔다.

이제 칩은 **운영자가 관리하는 선택지 목록**에서만 나온다. 목록에 없는 곳은 크리에이터가 직접 적을 수 있지만, 직접 적은 말은
공개 화면에 나오지 않고 운영자 화면에만 모인다. 운영자가 보고 선택지에 올리면 그때부터 칩이 되고, 같은 말을 적은 크리에이터의
태그도 함께 공개된다. 어기면 생기는 사고: 아무나 적은 말(욕설·광고 포함)이 찾기 화면 칩이나 카드에 그대로 뜬다.

처음 선택지(순서대로): SOOP · 치지직 · 유튜브 · 알플레이 · 인스타그램 · X · 스레드 · 틱톡 · 버추얼

용어
- **선택지**: 운영자가 관리하는 태그 이름 목록. 이름은 겹치지 않는다(앞뒤 공백을 빼고 영문 대소문자를 무시해 비교).
- **숨긴 선택지**: 운영자가 숨긴 선택지. 새로 고를 수 없고 공개 화면에 나오지 않는다. 지우지는 않는다.
- **직접 입력**: 크리에이터가 선택지 밖에서 적은 태그 한 개.

## 불변식

- INV-T1: 선택지 추가·이름 고치기·숨기기·다시 보이기·순서 바꾸기는 운영자만 한다. 운영자가 아니면 아무것도 바뀌지 않고 거부된다.
  (강제 위치: DB 함수 — 운영자 확인 / 선택지 표는 화면 쪽 API 로 쓰기 불가)
  위반 시: 아무나 찾기 화면의 칩을 만들거나 없앤다.
- INV-T2: 크리에이터 태그 고치기 함수는 계정·크리에이터 ID 를 인자로 받지 않고, 로그인 토큰이 확인한 계정에 연결된 크리에이터 한 줄만
  고친다(my-account INV-A9 와 같은 방식). 크리에이터가 아니면 거부된다.
  (강제 위치: DB 함수 / 태그 표는 화면 쪽 API 로 쓰기 불가)
  위반 시: 남의 태그를 바꾼다.
- INV-T3: 한 크리에이터의 태그는 합쳐 1~5개다 — 숨기지 않은 선택지 0~5개 + 직접 입력 0~1개. 같은 선택지는 한 번만. 직접 입력은
  앞뒤 공백을 뺀 1~20자이고, 숨기지 않은 선택지 이름과 같으면(용어 「선택지」의 비교 방법) 그 선택지를 고른 것으로 저장한다.
  하나라도 어기면 아무 태그도 바뀌지 않는다. 가입 때도 같은 규칙으로 1개 이상 받는다.
  (강제 위치: DB 함수 — 가입 함수·태그 고치기 함수 / DB 제약 — 같은 선택지 중복 금지)
  위반 시: 태그가 없는 크리에이터, 같은 칩이 두 번 붙은 카드, 숨긴 선택지가 다시 붙는 일.
- INV-T4: 공개 화면(찾기·메인·크리에이터 페이지·팔로우 목록)이 받는 태그는 숨기지 않은 선택지뿐이다. 직접 입력은 그 크리에이터 본인의
  설정 화면과 운영자 화면에서만 읽힌다. 칩 목록은 숨기지 않은 선택지 가운데 그 태그를 가진 공개 크리에이터가 1명 이상인 것만, 선택지 순서대로.
  (강제 위치: DB 읽기 함수 — 공개 목록 함수가 직접 입력 칸을 돌려주지 않음)
  위반 시: 확인 안 한 말이 공개 화면에 뜬다.
- INV-T5: 운영자가 직접 입력 하나를 선택지로 올리면 한 처리 안에서 — 새 선택지가 생기고(이미 있으면 그것을 쓰고, 숨겨져 있으면 다시 보이게),
  같은 말(용어 「선택지」의 비교 방법)을 적은 모든 크리에이터의 직접 입력이 그 선택지로 바뀐다. 이미 그 선택지를 가진 크리에이터는 직접 입력만 지운다.
  바뀐 뒤에도 각자 태그 수는 늘지 않는다(INV-T3 유지). 중간에 실패하면 아무것도 바뀌지 않는다.
  (강제 위치: DB 함수 — 운영자 확인, 한 트랜잭션, 선택지 이름 유일 제약)
  위반 시: 일부 크리에이터만 칩에 나오거나, 같은 이름 선택지가 둘 생긴다.
- INV-T6: 선택지를 숨겨도 크리에이터가 고른 기록은 지우지 않는다. 다시 보이게 하면 그대로 돌아온다. 숨긴 동안 그 크리에이터가 태그를 고치면
  숨긴 선택지는 고를 수 없으므로 빠진다(INV-T3).
  (강제 위치: DB 함수·읽기 함수)
  위반 시: 숨겼다 되돌리면 크리에이터들의 태그가 사라져 있다.

## 시나리오

- S1 (INV-T1): Given 운영자 / When 선택지 「팬더TV」 추가 / Then 목록 끝에 생긴다.
- S1b (INV-T1, 실패경로): Given 크리에이터·팬·로그인 안 한 사람 / When 선택지 추가·숨기기 / Then 거부, 목록 그대로.
- S2 (INV-T2): Given 크리에이터 하루 로그인 / When 태그를 「치지직·버추얼」로 / Then 하루의 태그만 바뀐다.
- S2b (INV-T2, 실패경로): Given 팬 로그인 / When 태그 고치기 / Then 거부. 다른 크리에이터의 ID 를 실어 보내도 받을 칸이 없다.
- S3 (INV-T3): Given 선택지 4개 + 직접 입력 「팝콘TV」 / When 저장 / Then 5개 저장.
- S3b (INV-T3, 실패경로): Given 선택지 5개 + 직접 입력 1개 / 0개 / 같은 선택지 두 번 / 숨긴 선택지 / 직접 입력 21자 / When 저장 / Then 거부, 태그 그대로.
- S3c (INV-T3): Given 직접 입력 「 유튜브 」(앞뒤 공백) / When 저장 / Then 선택지 유튜브를 고른 것으로 저장, 직접 입력 없음.
- S4 (INV-T4): Given 하루 = 치지직 + 직접 입력 「팝콘TV」 / When 찾기·메인·크리에이터 페이지 / Then 「치지직」만 보이고 「팝콘TV」는 어디에도 없다. 칩 목록에도 없다.
- S4b (INV-T4): Given 아무 공개 크리에이터도 고르지 않은 선택지 「틱톡」 / When 찾기 / Then 칩 목록에 틱톡이 없다.
- S5 (INV-T5): Given 하루·모모가 직접 입력 「팝콘TV」, 별이가 「팝콘tv」 / When 운영자가 「팝콘TV」를 선택지로 / Then 셋 다 선택지 팝콘TV 를 갖고 직접 입력이 없다. 칩에 팝콘TV.
- S5b (INV-T5, 실패경로): Given 크리에이터 / When 올리기 함수 호출 / Then 거부, 아무도 안 바뀜.
- S6 (INV-T6): Given 하루 = 치지직·버추얼 / When 운영자가 버추얼 숨김 → 다시 보이게 / Then 숨긴 동안 하루 카드에 치지직만, 되돌리면 치지직·버추얼.

## 신뢰 경계

- 믿는 값: 로그인 토큰이 확인한 계정과 역할, DB 의 선택지 표.
- 믿지 않는 값: 화면이 보낸 선택지 ID 목록과 직접 입력 글자(서버가 다시 검사), 화면이 보낸 크리에이터 ID(받지 않는다).

## 비범위

- 플랫폼 본인 확인(creator-verification)은 그대로다. 태그 「치지직」을 골라도 치지직 채널이 확인된 것은 아니다 — 태그는 자기소개다.
- 직접 입력의 욕설 걸러내기 — 공개되지 않으므로 운영자가 보고 올리지 않으면 된다.
- 팬이 칩을 여러 개 한꺼번에 고르는 검색(칩은 한 번에 하나).
- 기존 「분야」 값 옮기기 — 아직 실제 가입자가 없어 시험 데이터만 새 태그로 다시 넣는다. 「분야」 칸은 이 기능과 함께 쓰지 않게 된다.

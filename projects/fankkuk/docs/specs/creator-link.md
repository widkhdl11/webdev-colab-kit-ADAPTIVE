# 선물 링크 페이지 스펙

크리에이터가 방송·SNS 에 붙이는 링크 하나 `fankkuk.kr/{링크용 아이디}` 가 크리에이터 페이지를 연다. 공개 페이지는 이것 하나다 —
지금 크리에이터 페이지를 추가분 F-1 순서로 다시 짠다. 링크를 붙이면 프로필 사진이 들어간 미리보기 이미지가 뜨고, 크리에이터는
「내 팬꾹 꾸미기」에서 자기 프로필을 담은 홍보 카드(공지 이미지, 정사각·스토리 세로·가로)를 내려받아 쓸 수 있다.

어기면 생기는 사고: 남의 링크를 가로채거나, 옛 링크가 남의 페이지로 열리거나, 로그인 아이디가 링크로 드러나거나,
사진에 남은 촬영 위치·주소·주문번호·팬 이름이 공개 화면이나 이미지로 나간다.

용어
- **링크용 아이디**: 링크 주소에만 쓰는 영문 아이디. 공개 이름(한글 1~20자, 화면에 크게 보이는 이름)과 따로다. 로그인 아이디와도 따로다.
- **공개 화면**: 로그인 없이 누구나 열 수 있는 링크 페이지, 그 미리보기 이미지, 공지 이미지. (답장 공유 카드는 gift-reply 스펙이 같은 규칙을 따른다.)
- **이번 달**: 한국 시간 달력의 달.

## 불변식

- INV-E1: 링크용 아이디·한 줄 소개·프로필 사진·프로필 배경사진·팬덤 이름·팬덤 심볼·미리보기 이미지 사진 고르기는 그 크리에이터 본인만 바꾼다. 바꾸는 함수는 크리에이터 ID 를 인자로 받지 않고
  로그인 토큰이 확인한 계정에 연결된 크리에이터 한 줄만 바꾼다. 사진 저장소에는 서버만 쓴다 — 화면에서 저장소로 바로 올리는 길이 없다.
  (강제 위치: DB 함수 — 본인 계정 / 저장소 쓰기 정책 없음, 서버의 비밀 키로만 씀)
  위반 시: 남이 링크 아이디를 바꿔 팬을 엉뚱한 곳으로 보내거나, 위치 정보가 남은 사진이 처리 없이 올라간다.
- INV-E2: 링크용 아이디는 영문 소문자·숫자·밑줄 3~20자다. 대문자로 들어오면 소문자로 바꿔 저장하고, 대문자 주소로 열면 소문자 주소로 넘긴다.
  사이트가 쓰는 첫 단계 주소(로그인·가입·관리·고객센터 등 지금 있는 것 전부)와 예약어 목록은 받지 않는다.
  그 크리에이터의 로그인 아이디와 같은 값은 받지 않는다.
  (강제 위치: DB 함수 — 저장 전 검사. 예약어 목록은 DB 에 두고 지금 있는 첫 단계 주소가 모두 들어 있는지 시험이 확인한다)
  위반 시: 링크가 로그인 화면 같은 사이트 주소를 덮거나, 링크로 로그인 아이디가 드러나 비밀번호 대입의 절반이 풀린다.
- INV-E3: 한 아이디는 한 크리에이터만 쓴다. 아이디를 바꾸면 옛 아이디는 90일 동안 그 크리에이터에게 묶여 있어 다른 사람이 가져갈 수 없고,
  옛 주소로 들어오면 새 주소로 넘긴다. 90일이 지나면 옛 아이디는 풀린다. 두 크리에이터가 같은 아이디를 동시에 골라도 한 명만 성공한다.
  (강제 위치: DB — 지금 아이디와 묶인 옛 아이디가 같은 고유 목록에 있다)
  위반 시: 옛 링크가 다른 크리에이터 페이지로 열려 팬이 엉뚱한 사람에게 선물을 보낸다.
- INV-E4: 아이디를 정하거나 바꾸면 30일 동안 다시 바꿀 수 없다(처음 정할 때도 같다). 남은 날은 설정 화면에 보인다.
  (강제 위치: DB 함수 — 마지막으로 바꾼 시각과 비교)
  위반 시: 링크를 자주 바꿔 이미 붙인 링크가 깨진다.
- INV-E5: 링크 주소와 지금 크리에이터 페이지 주소는 같은 페이지를 연다. 아이디가 있는 크리에이터의 옛 페이지 주소는 링크 주소로 넘긴다.
  아이디가 아직 없으면 옛 페이지 주소가 그대로 그 페이지다. 본인 확인 전이거나 없는 아이디는 없는 페이지다.
  (강제 위치: 서버 — 페이지 읽기)
  위반 시: 같은 크리에이터의 공개 페이지가 둘이 되어 내용이 어긋나거나, 본인 확인 전 크리에이터가 링크로 선물을 받는다.
- INV-E6: 한 줄 소개는 앞뒤 공백을 뺀 0~40자이고 줄바꿈이 없다. 직접 입력 태그와 같은 업계 기본 필터를 거친다
  (금칙어·전화번호·이메일·인터넷 주소 꼴 거부 — creator-tags INV-T7).
  (강제 위치: DB 함수 — 저장 전 검사)
  위반 시: 링크 페이지·미리보기에 긴 글이 넘치거나 연락처·욕설이 소개로 뜬다.
- INV-E7: 공개 화면에 나가는 것은 크리에이터 공개 이름·링크용 아이디·프로필 사진·프로필 배경사진·한 줄 소개·팬덤 이름·팬덤 심볼·
  확인된 채널(플랫폼·채널 주소·확인 날짜)·크리에이터가 켠 항목(받는 상태·받기 어려운 품목·기념일 D-day·답장 모음)·
  정해진 문구·집계 숫자·요금표뿐이다. 주소·주문번호·운송장·팬 실명·팬 닉네임 목록·팬이 올린 사진·로그인 아이디·금액 합계·
  주소 열람 건수는 페이지 응답(HTML·데이터)에도, 생성 이미지에도 없다.
  (강제 위치: 서버 — 공개 화면용 읽기 함수가 위 칸만 돌려준다 / 시험 — 공개 응답과 이미지 생성 입력에 금지 칸이 없는지 계약 시험)
  위반 시: 공개 링크 하나로 주소·팬 정보가 퍼진다(추가분 불변식 17).
- INV-E8: 「이번 달 N명의 팬이 마음을 보냈어요」의 N 은 이번 달에 결제가 끝난 그 크리에이터 팬 선물 주문의 서로 다른 팬 수다(취소·결제 실패 제외).
  N 이 0 이면 줄을 숨긴다. 숫자만 보이고 누가 보냈는지·몇 개인지·금액은 없다.
  (강제 위치: DB 공개 읽기 함수 — 숫자 하나만 돌려줌)
  위반 시: 보낸 팬 명단이나 팬별 횟수가 드러나 경쟁이 생긴다(추가분 불변식 18).
- INV-E9: 프로필 사진·프로필 배경사진·팬덤 심볼은 서버가 받아 실제 이미지인지 열어 보고(그림 크기 상한), 위치 정보를 포함한 사진 정보(EXIF 등)를 모두 지우고,
  정해진 크기로 줄인 결과만 저장한다(프로필 사진·심볼은 가운데를 정사각으로 자르고, 배경사진은 비율을 두고 긴 변만 줄인다). 원본은 저장하지 않는다. 사진을 바꾸거나 지우면 옛 파일도 지운다.
  사진 판(버전)이 바뀌면 미리보기 이미지 주소의 판 값도 바뀐다.
  (강제 위치: 서버 — 사진 저장 경로 하나 / 시험 — 위치 정보가 든 사진을 올리고 저장된 파일에 사진 정보가 없는지 확인)
  위반 시: 촬영 위치(집 주소)가 공개 사진에 남는다(추가분 불변식 23). 사진을 바꿔도 SNS 미리보기가 옛 사진을 보여 준다.
- INV-E10: 미리보기 이미지에는 크리에이터가 고른 사진(프로필 사진 또는 팬덤 심볼, 없으면 기본 이미지)·공개 이름·「승인한 선물만 받습니다」·팬꾹 로고만 있다.
  공지 이미지(정사각 1080×1080·스토리 세로 1080×1920·가로 1200×675)에는 프로필 배경사진(없으면 단색)·프로필 사진·공개 이름·한 줄 소개·
  하단의 작은 「팬꾹으로 선물 보내기」와 링크 주소만 있다. 「선물은 팬꾹으로 받아요」 같은 부탁 문구는 넣지 않는다. 공지 이미지는 링크용 아이디가 있을 때만 내려받는다.
  (강제 위치: 서버 — 이미지 생성 라우트가 공개 읽기 함수 결과만 받는다)
  위반 시: 이미지에 공개하면 안 되는 정보가 들어간다(INV-E7).
- INV-E12: 팬덤 심볼은 크리에이터가 「내가 만들었거나 쓸 권리가 있는 이미지예요」에 체크한 요청에서만 저장되고, 체크한 시각을 심볼과 함께 남긴다.
  체크가 없으면 서버가 거부한다. 신고 버튼은 두지 않고 권리 문제는 1:1 문의로 받는다(사용자 2026-10-14, 카드 d81).
  (강제 위치: 서버 — 심볼 저장 경로 / 시험 — 체크 없이 올리면 거부)
  위반 시: 권리 확인 없이 남의 캐릭터가 공개 화면에 걸린다.
- INV-E11: 주소 열람 기록 가운데 승인 서명 없이 열린 줄이 하나라도 있으면 운영자 자동 처리 현황에 경보가 뜬다. 공개 화면에는 열람 건수를 쓰지 않는다.
  (강제 위치: DB 운영자 읽기 함수)
  위반 시: 승인 없이 주소가 열린 사고를 아무도 모른다.

## 스스로 정한 것 (추가분·사용자 답에 없던 세부)

- 아이디는 소문자로만 저장하고 대문자 주소는 소문자로 넘긴다 — 업계 일반 방식(대소문자만 다른 두 아이디가 서로를 흉내 내지 못하게).
- 예약어: 지금 있는 첫 단계 주소 전부 + `fankkuk`·`admin`·`api`·`www`·`help`·`official`·`staff`·`root`·`system`·`null`·`undefined`·`settings`·`og` 등. 판단.
- 로그인 아이디와 같은 값 거부는 **그 크리에이터 본인 것만** 본다 — 판단. 남의 로그인 아이디까지 거부하면 「이 아이디는 누군가의 로그인 아이디」라는 사실이 드러난다.
- 처음 정할 때도 30일 잠금 — 판단(추가분 「한 번 바꾸면」을 정하는 순간부터로 읽음). 저장 전에 「정하면 30일 동안 바꿀 수 없어요」를 보여 준다.
- 아이디는 꼭 정해야 하는 것이 아니다 — 판단. 없으면 지금 페이지 주소가 그대로 링크다. 설정 화면에서 정하라고 안내한다.
- 옛 주소 넘기기는 영구 넘기기(308) — 업계 일반 방식. 90일 뒤에는 없는 페이지.
- 소개 40자 줄이기: 출시 전이라 기존 소개는 마이그레이션에서 40자로 자른다.
- N 명 집계에 거절·반려된 주문도 넣는다 — 판단. 마음을 보낸 것은 맞고, 거절 여부를 공개 숫자로 짐작하지 못하게.
- 프로필 사진: jpg·png·webp, 10MB·4천만 화소 이하, 512×512 webp 로 저장 — 판단. 저장소 경로에 크리에이터 ID 와 판 번호를 넣는다.
- 모바일 링크 페이지는 맨 위에도 「선물 보내기」를 하나 더 둔다(DECISIONS 2026-10-11 — 시안 확인 1번).
- 「이번 달 주소 열람 n건」 줄은 넣지 않는다(사용자 답 ⑪). 경보는 INV-E11.
- 답장 모음 자리(F-5)는 gift-reply 스펙에서 채운다. 이 스펙에서는 자리만 둔다.

## 시나리오

- S1 (INV-E1): Given 크리에이터 A·B / When A 로그인으로 아이디 저장 / Then A 만 바뀌고 B 의 ID 를 넣을 칸이 없다.
- S1b (INV-E1, 실패경로): Given 팬 로그인·로그인 안 함 / When 아이디·소개 저장 함수를 부름 / Then 거부되고 아무것도 바뀌지 않는다.
- S1c (INV-E1, 실패경로): Given 로그인한 크리에이터 / When 화면 쪽 키로 사진 저장소에 바로 파일을 올림 / Then 거부된다.
- S2 (INV-E2, 실패경로): Given 아이디 저장 / When `ab`·21자·`ha-ru`·`하루`·`login`·`admin`·본인 로그인 아이디 / Then 각각 거부된다. `ha_ru`·`HaRu7`(→ `haru7`)는 저장된다.

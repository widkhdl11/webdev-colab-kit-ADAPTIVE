# 알림톡 링크로 바로 로그인

카카오톡 인앱 브라우저는 크롬·사파리와 쿠키 저장소가 따로라, 평소 브라우저에서 로그인해 둔 크리에이터도 알림톡 링크를 누르면
로그인 화면부터 본다. 승인 요청 알림톡의 링크에 그 계정 전용 1회용 토큰을 붙여, 처음 한 번은 링크만으로 로그인되게 한다.
그 뒤로는 인앱 브라우저에 남은 로그인 쿠키(크리에이터의 로그인 유지 기간 — session-login INV-L16)로 들어온다.

## 용어

- **로그인 링크**: 1회용 토큰이 붙은 알림톡 버튼 주소. `https://fankkuk.com/login/link#t=<토큰>` — 토큰은 `#` 뒤에 둔다(브라우저가 서버로 보내지 않아 요청 기록에 남지 않는다)
- **토큰**: 추측할 수 없는 무작위 값(32바이트). 링크에만 있고 DB 에는 해시만 있다.

## 불변식

- INV-K1: 로그인 링크의 토큰은 승인 요청 알림톡을 **보내는 순간** 받는 크리에이터 계정 하나에 묶여 만들어지고, 만든 뒤 30분에 만료된다.
  DB 에는 토큰의 SHA-256 해시·계정·만든 시각·만료 시각만 저장한다. 토큰 원문은 알림톡 본문(버튼 주소) 말고는 어디에도 남지 않는다 —
  발송 기록·오류 로그·DB 에 없다.
  - 위반 시: DB 나 로그가 새면 그 안의 값으로 크리에이터 계정에 들어갈 수 있다.
  - 강제 위치: 토큰을 만드는 DB 함수(서비스 키 전용) · 발송 코드.
- INV-K2: 토큰은 한 번만 쓰인다. 쓰기는 한 처리 안에서 「아직 안 썼고 만료 전이면 쓴 것으로 표시」를 한 번에 한다 — 같은 링크를 동시에 두 번 열어도
  로그인되는 것은 하나다. 쓴 시각을 남기고, 실패(없는 토큰·이미 씀·만료)는 사유와 시각을 남긴다.
  - 위반 시: 전달된 링크·앞서 연 링크로 다시 들어갈 수 있다.
  - 강제 위치: 토큰을 쓰는 DB 함수(서비스 키 전용, 행 잠금).
- INV-K3: 링크를 **여는 것(GET)만으로는 토큰을 쓰지 않는다.** 열린 페이지가 스스로 토큰을 서버에 보내고(POST, 같은 사이트 출처 확인) 그때 쓴다.
  - 위반 시: 카카오톡·메신저의 링크 미리보기나 보안 검사 로봇이 링크를 먼저 열어 토큰을 써 버리고, 크리에이터는 로그인 화면을 본다.
  - 강제 위치: `/login/link` 페이지(쓰기 없음) · 토큰 쓰기 라우트.
- INV-K4: 토큰을 쓰면 그 계정으로 로그인한 쿠키(session-login INV-L1, 유지 켬)를 주고 `/creator/actions`(승인 대기 목록)로 보낸다.
  토큰이 없거나 이미 썼거나 만료됐으면 로그인 화면으로 보내고, 로그인 뒤 돌아갈 곳은 `/creator/actions` 다(INV-L13). 실패 사유는 화면에 나누어
  보이지 않는다 — 「로그인 링크가 만료됐습니다.」 한 가지.
  이미 로그인해 있으면 링크로 계정을 바꾸지 않는다(카드 fankkuk-20261031-1-d1): 토큰의 계정과 같으면 그 로그인 그대로 `/creator/actions` 로,
  다르면 지금 로그인을 끝내고(로그아웃) 안내 문구 없이 로그인 화면으로(돌아갈 곳 `/creator/actions`), 토큰이 쓸 수 없으면 그 로그인 그대로 `/creator/actions` 로.
  - 위반 시: 다른 계정의 승인 화면이 열리거나, 토큰 상태(있음·씀·만료)가 화면으로 드러나거나, 남이 보낸 링크로 남의 계정에 로그인된 채 쓰게 된다.
- INV-K5: 토큰이 주소창·다른 사이트로 새지 않는다. 로그인 링크 페이지는 `Referrer-Policy: no-referrer` 를 보내고 외부 리소스를 부르지 않으며,
  토큰을 쓴 뒤 주소창에서 토큰을 지운다. 토큰 쓰기 실패를 서버 로그에 남길 때 토큰 원문이 아니라 해시 앞 8자만 쓴다.
  - 위반 시: 브라우저 기록·외부 사이트 접속 기록에 남은 링크로 다시 시도할 수 있다(INV-K2 로 한 번은 막히지만 30분 안의 미사용 링크는 열린다).
- INV-K6: 링크로 로그인한 쿠키의 유효기간은 그 계정 역할의 절대 기간이다(session-login INV-L16 — 크리에이터 30일). 요청마다 서버(proxy)가 세션을 갱신해 다시 쓰고, 그때도 같다.
  링크 로그인은 새 세션이라 절대 기간을 새로 센다. 「로그인 상태 유지」 끔(INV-L15)은 그대로 만료 없는 쿠키다.
  - 위반 시: 라이브러리 기본값(400일)이 남거나, 갱신 때 유효기간이 다시 400일로 돌아간다.
  - 강제 위치: session-cookies 의 쓰기 옵션(라이브러리가 쓸 때마다 400일로 강제하므로 쓰는 자리에서 바꾼다).
## 시나리오

- S1 (INV-K1·K4): 로그인 쿠키가 없는 브라우저에서 승인 요청 알림톡의 링크를 열면 승인 대기 목록이 바로 뜬다. DB 의 토큰 줄에 쓴 시각이 남는다.
- S1b (INV-K2, 실패경로): 같은 링크를 두 번째 열면 로그인 화면으로 가고 「로그인 링크가 만료됐습니다.」가 보인다. 실패 기록에 「이미 씀」이 남는다.
- S1c (INV-K2, 실패경로·동시): 같은 토큰으로 쓰기 요청 둘이 동시에 와도 로그인 쿠키를 받는 것은 하나다.
- S1d (INV-K1, 실패경로): 만든 지 30분이 지난 토큰은 쓰이지 않는다(29분 59초면 쓰인다).
- S1e (INV-K1, 실패경로): 다른 크리에이터의 승인 요청 알림에서 나온 토큰은 그 크리에이터 계정으로만 로그인한다 — 토큰으로 계정을 고를 수 없다.
- S2 (INV-K3, 실패경로): 링크를 GET 으로만 열고 페이지 스크립트를 돌리지 않으면(미리보기 로봇) 토큰은 쓰이지 않은 채 남는다.
- S2b (INV-K3, 실패경로): 다른 사이트 출처의 POST 로 토큰을 보내면 거부한다.
- S3 (INV-K1·K5, 실패경로): 발송 기록·DB·서버 로그 어디에도 토큰 원문이 없다(해시와 해시 앞 8자만).
- S4 (INV-K6): 크리에이터가 링크로 로그인한 쿠키의 Max-Age 는 30일(INV-L16)이고, 갱신된 응답의 쿠키도 30일이다.

## 비범위

- 상태 알림톡(상자 도착·출고 등) 링크의 로그인 토큰 — 카드 d4 ①: 승인 요청만. 써 본 뒤 넓힐지 정한다.
- 「크롬으로 열기」·인앱 브라우저 감지 — 카드 d4 ④: 넣지 않는다. iOS·안드로이드 모두 1회용 토큰 + 서버 쿠키로만 푼다.
- 팬에게 가는 알림톡의 로그인 링크.
- 이메일 알림의 로그인 링크(메일은 보통 평소 브라우저로 열린다).

## 바깥에서 해야 하는 일

- 알림톡 버튼 주소를 `https://fankkuk.com/login/link#t=#{token}` 꼴로 바꾼 **새 템플릿을 솔라피에 등록하고 카카오 검수를 받는다.**
  등록된 템플릿은 고칠 수 없어 새로 등록해야 한다(솔라피 안내 — 주소 일부 수정도 불가). 변수를 넣은 버튼 주소는 300자 이하.
  검수가 끝나기 전까지는 지금 템플릿(`/creator/actions?order=…`)으로 보내고, 토큰 링크는 검수가 끝난 템플릿 코드가 들어온 뒤에만 쓴다.

# 크리에이터 상세 「나에게 온 감사 카드」 스펙

크리에이터 상세 페이지(`/{링크용 아이디}`·`/creators/{id}`)를 로그인한 팬이 볼 때, 그 크리에이터가 **이 팬이 보낸 선물에** 남긴 감사 답장을
카드 슬라이드로 보여 준다. 공개 「감사 답장 모음」(gift-reply INV-G7)과 다르다 — 이것은 공개가 아니라 본인에게만 보이는 영역이다.

어기면 생기는 사고: 상세 페이지는 누구나 여는 공개 페이지라, 이 영역이 다른 팬의 답장을 섞어 보여 주면 누가 이 크리에이터에게 선물했는지와
답장 내용이 남에게 드러난다. 페이지가 사람 사이에 캐시되면 한 팬의 카드가 다음 사람에게 그대로 보인다.

용어
- **감사 카드**: 답장 하나(gift-reply 의 정해진 문구 + 선택 한 줄)를 카드 한 장으로 그린 것. 문구가 없는 「확인만」은 카드가 아니다.
- **보는 팬**: 로그인한 회원 중 역할이 팬인 사람.

## 불변식

- INV-RC1: 감사 카드는 보는 팬 **본인이 보낸** 선물에 이 크리에이터가 남긴 답장만이다. 다른 팬이 보낸 선물의 답장은 한 장도 섞이지 않는다.
  누구의 답장인지는 로그인 토큰으로만 정한다 — 화면이 넘기는 크리에이터 ID 는 「어느 크리에이터 것만」 고르는 거르개일 뿐 권한이 아니다.
  읽기는 팬 본인 답장 읽기 함수(지금 마이꾹·함께한 시간이 쓰는 것, 주문의 보낸 사람 = 로그인한 사람)를 크리에이터로 걸러 부른다. 새 공개 읽기를 만들지 않는다.
  (강제 위치: DB 함수 — 보낸 사람 = 로그인한 사람 조건. 신뢰하지 않는 값: 화면이 넘기는 크리에이터 ID)
  위반 시: 공개 페이지에서 다른 팬의 선물 사실과 답장 글이 보인다.
- INV-RC2: 감사 카드 영역은 **로그인한 팬이 이 크리에이터를 팔로우하고 있을 때만** 읽고 그린다. 로그인 전 · 팔로우 전 · 크리에이터 계정(본인 포함) · 운영자는
  읽기 함수를 부르지도 않고 영역도 없다. 팔로우했어도 카드가 0장이면 영역(제목 포함)을 그리지 않는다.
  (강제 위치: 페이지 읽기(서버) — 역할·팔로우 여부를 먼저 보고 부른다. 로그인 전 차단은 DB 함수 권한도 한 번 더 막는다)
  위반 시: 팔로우하지 않은 팬에게 빈 제목만 보이거나, 크리에이터·운영자 화면에서 읽기 오류가 페이지를 깨뜨린다.
- INV-RC3: 카드는 답장 날짜 최신순으로 **최대 20장**이다. 크리에이터가 지운 답장(gift-reply INV-G4)과 문구 없는 「확인만」은 카드가 되지 않는다.
  20 은 상수 하나로 두고 시험은 그 상수를 부른다.
  (강제 위치: 페이지 읽기(서버))
  위반 시: 지운 답장이 다시 보이거나, 답장이 많은 팬의 페이지가 끝없이 길어진다.
- INV-RC4: 카드에 보이는 것은 크리에이터 공개 이름·프로필 사진 · 답장 문구와 한 줄 · 답장 날짜뿐이다. 시각·주문번호·상자 번호·다른 팬의 닉네임은 없다.
  공개 동의(「공개해도 괜찮아요」)와 상관없이 본인에게는 보인다 — 공개 동의는 공개 모음(INV-G7)과 공유에만 쓰인다.
  (강제 위치: 페이지 읽기가 화면으로 넘기는 칸 — 위 칸만 넘긴다)
  위반 시: 답장 시각으로 크리에이터의 생활 시간이 드러나거나(gift-reply INV-G6 과 같은 이유), 주문 정보가 화면 HTML 에 실린다.
- INV-RC5: 이 영역이 있는 상세 페이지는 사람마다 따로 만들어진다 — 한 사람이 받은 페이지를 다른 사람에게 다시 쓰지 않는다(공유 캐시·정적 생성 금지).
  감사 카드 읽기는 그 요청의 로그인 세션으로만 한다.
  (강제 위치: 라우트 설정(요청마다 새로 만듦) · 페이지 읽기가 세션 클라이언트를 씀)
  위반 시: 한 팬의 감사 카드가 다음에 페이지를 연 사람에게 그대로 보인다.

## 시나리오

- S1 (INV-RC1): Given 별빛·달토끼 둘 다 하루에게 선물, 하루가 둘 다에 답장 / When 별빛이 하루 페이지 / Then 별빛 선물의 답장만 보이고 달토끼 답장 글은 HTML 어디에도 없다.
- S1b (INV-RC1, 실패경로): Given 별빛 로그인 / When 화면이 다른 크리에이터 ID(모모)로 바꿔 읽기를 부름 / Then 모모에게 보낸 별빛 본인 답장만(없으면 0장) — 다른 팬 답장은 나오지 않는다.
- S2 (INV-RC2): Given 별빛이 하루 팔로우, 답장 2개 / When 하루 페이지 / Then 「나에게 온 감사 카드」 2장.
- S2b (INV-RC2, 실패경로): Given 로그인 전 / When 하루 페이지 / Then 영역 없음, 읽기 함수 호출 0번.
- S2c (INV-RC2, 실패경로): Given 별빛이 하루를 팔로우하지 않음(답장은 있음) / When 하루 페이지 / Then 영역 없음, 읽기 함수 호출 0번.
- S2d (INV-RC2, 실패경로): Given 하루(크리에이터) 본인 · 운영자 / When 하루 페이지 / Then 영역 없음, 읽기 함수 호출 0번.
- S2e (INV-RC2): Given 별빛 팔로우, 답장 0개(확인만 1개) / When 하루 페이지 / Then 영역(제목 포함) 없음.
- S3 (INV-RC3): Given 별빛이 하루에게서 받은 답장 25개 / When 하루 페이지 / Then 최근 20장, 답장 날짜 최신순.
- S3b (INV-RC3, 실패경로): Given 하루가 별빛 답장 하나를 지움 / When 하루 페이지 / Then 그 답장은 카드에 없다.
- S4 (INV-RC4): Given 별빛 답장(공개 동의 끔) / When 하루 페이지 / Then 카드가 보인다. 카드 HTML 에 시각·주문번호·상자 번호가 없다.
- S5 (INV-RC5, 실패경로): Given 별빛이 하루 페이지를 연 직후 / When 달토끼가 같은 주소를 연다 / Then 달토끼 화면에 별빛 카드가 없다(라우트가 요청마다 새로 만들어짐).

## 스스로 정한 것(사용자 추천안 밖의 세부)

- 영역 제목은 시안대로 「나에게 온 감사 카드」. 대안 「받은 감사 카드」(마이꾹과 같은 이름) — 화면 문구라 구현 때 용어집과 맞춘다.
- 자리는 시안 e판대로 상세 정보(여닫는 영역) 안 2열 아래 독립 줄. 상세 정보가 닫혀 있으면 함께 닫혀 있다.
- 카드를 눌러도 이동하지 않는다(시안 — 누르는 카드가 아니다). 공유는 지금처럼 함께한 시간·선물 상세에서만.
- 「팔로우 취소 저장 실패」(fail_unfollow)처럼 팔로우가 아직 저장돼 있는 상태는 팔로우한 것으로 본다(저장된 값 기준).

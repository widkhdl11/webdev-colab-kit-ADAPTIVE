# 물품 종류 고정 목록 · 받기 어려운 품목 스펙

팬은 선물의 **물품 종류**를 정해진 목록에서 고른다 — 인형·쿠션 / 꽃 / 의류 / 향수·화장품 / 대형 물품 / 문구 / 전자기기 / 기타.
기타만 30자까지 직접 적는다. 냉장·냉동·음식·액체는 목록에 없다(서비스 차원 금지품이라 처음부터 고를 수 없다).
운영자가 관리하는 「보낼 수 없는 것」 목록은 그대로 크리에이터 페이지에 보인다.

크리에이터는 설정에서 **받기 어려운 품목**을 고른다 — 품목(목록에서 여러 개)·이유·기간·동작(안내만/등록 막기).
문장을 직접 쓰는 칸은 없고, 공개 문구는 정해진 틀 「지금은 {품목들}을 받기 어려워요 ㅠㅠ {이유}」로만 만든다(추가분 불변식 21).
겹치는 품목을 고른 팬에게는 결제 전에 안내가 뜨고, 「등록 막기」면 서버가 그 품목 등록을 거부한다. 최종 판단은 여전히 크리에이터 승인이다.

어기면 생기는 사고: 남의 크리에이터에 등록 막기가 걸리거나, 막아 둔 품목이 들어오거나, 기간이 끝났는데 계속 막히거나,
크리에이터가 쓴 문장이 공개 화면에 그대로 나가 욕설·연락처가 실리거나, 기존 주문의 물품 이름이 사라진다.

용어
- **물품 종류**: 아래 여덟 가지 중 하나. 저장 값은 영문 코드, 화면 이름은 한국어.
  `doll` 인형·쿠션 · `flower` 꽃 · `clothing` 의류 · `beauty` 향수·화장품 · `large` 대형 물품 · `stationery` 문구 · `electronics` 전자기기 · `other` 기타
- **물품 이름**: 주문에 적히는 보여 주기용 이름(승인 화면·선물 내역·운영자 화면이 보여 준다). 기타면 팬이 적은 글, 나머지는 종류의 화면 이름.
- **설정이 살아 있다**: 받기 어려운 품목 설정이 있고, 끝나는 날이 없거나(직접 해제) 끝나는 날이 한국 시간 오늘보다 뒤다.

## 불변식

- INV-H1: 새 주문의 물품 종류는 여덟 가지 중 하나다. 기타면 1~30자 글이 꼭 있고, 나머지 종류면 글이 없다. 물품 이름은 서버가 정한다 —
  기타면 그 글, 나머지는 종류의 화면 이름. 목록에 없는 종류(냉장·음식 등)나 꼴이 틀린 입력은 주문을 만들지 않는다.
  이 기능 전에 만든 주문은 종류 칸이 비어 있고 물품 이름이 그대로 남아 기존 화면이 그대로 보여 준다.
  (강제 위치: DB 등록 함수 — 주문을 만들기 전 / DB 표 제약 — 종류 값 목록 / 앱 서버 입력 경계가 먼저 같은 규칙으로 거른다)
  위반 시: 목록 밖 물품이 들어오거나 겹침 판정이 안 되는 주문이 생기고, 기존 주문의 물품 이름이 사라진다.
- INV-H2: 전자기기를 고른 주문은 전자기기·금속 신고가 켜진 채 저장된다 — 팬이 「없어요」를 보내도.
  (강제 위치: DB 등록 함수 / 화면은 전자기기를 고르면 「있어요」로 고정해 보인다)
  위반 시: 전자기기 상자가 신고 없이 검수에 들어가 추적 장치 구분이 늦어진다.
- INV-H3: 받기 어려운 품목은 그 크리에이터 본인만 바꾼다. 저장 함수는 크리에이터 ID 를 인자로 받지 않고 로그인 토큰이 확인한 계정에
  연결된 크리에이터 한 줄만 바꾼다. 설정 표는 화면 쪽 API 로 읽기·쓰기가 안 된다. 운영자 화면에서도 바꾸지 않는다.
  (강제 위치: DB 함수 — 본인 계정 / 설정 표 권한 없음)
  위반 시: 남이 크리에이터에 「등록 막기」를 걸어 선물 받기를 막거나 공개 문구를 바꾼다.
- INV-H4: 설정은 고르는 값으로만 이루어진다 — 품목 1~8개(목록 안, 같은 품목 두 번 없음), 이유 넷 중 하나(이미 많이 받았어요 /
  보관할 곳이 부족해요 / 잠시 집을 비워요 / 이유 표시 안 함), 기간 넷 중 하나(1주 / 2주 / 한 달 / 직접 해제), 동작 둘 중 하나(안내만 / 등록 막기).
  문장을 받는 칸은 저장 함수에도 화면에도 없다. 품목을 하나도 고르지 않고 저장하면 설정이 지워진다(해제).
  (강제 위치: DB 저장 함수 — 저장 전 검사 / 표 제약)
  위반 시: 크리에이터가 쓴 문장이나 목록 밖 값이 공개 화면에 나간다.
- INV-H5: 기간은 저장한 날(한국 시간)부터 센다 — 1주는 7일 뒤, 2주는 14일 뒤, 한 달은 다음 달 같은 날(그날이 없으면 그달 마지막 날)이
  끝나는 날이고, 끝나는 날 한국 시간 0시부터 설정은 없는 것이다. 직접 해제는 끝나는 날이 없다. 다시 저장하면 그날부터 다시 센다.
  끝난 설정은 따로 지우지 않아도 공개 읽기·본인 읽기·등록 판정 어디에서도 쓰이지 않는다.
  (강제 위치: DB — 끝나는 날을 저장하고 읽을 때·등록할 때 한국 시간 오늘과 비교한다. 예약 작업 없음)
  위반 시: 기간이 끝났는데 문구가 남거나 등록이 막힌다.
- INV-H6: 공개 문구는 「지금은 {품목들}을 받기 어려워요 ㅠㅠ {이유}」 하나다. 품목들은 목록 순서로 「, 」로 잇고, 마지막 품목 이름의
  받침에 따라 「을/를」을 고른다. 이유 「표시 안 함」이면 앞 문장(「ㅠㅠ」까지)만. 남은 기간·끝나는 날은 공개 응답에 넣지 않는다 —
  본인 설정 읽기와 설정 화면에만 있다. 설정이 살아 있을 때만 크리에이터 페이지에 한 줄 보인다.
  (강제 위치: 화면 쪽 문구 함수 하나 — 크리에이터 페이지·설정 화면 미리보기가 같은 함수를 쓴다 / DB 공개 읽기 — 끝나는 날 칸 없음)
  위반 시: 틀이 아닌 문장이 나가거나 크리에이터의 집 비우는 기간이 공개된다.
- INV-H7: 설정이 살아 있고 동작이 「등록 막기」이며 팬이 고른 종류가 받기 어려운 품목에 있으면 등록 함수가 주문을 만들지 않는다(FKR03).
  「안내만」이거나 겹치지 않거나 설정이 끝났으면 등록된다. 등록 판정은 그 크리에이터 줄을 잠근 뒤 하고, 설정 저장도 같은 줄을 잠그므로
  저장과 등록이 겹치면 등록은 저장이 끝난 뒤의 설정으로 판정한다.
  (강제 위치: DB 등록 함수 — 크리에이터 줄 공유 잠금 뒤, 주문을 만들기 전 / DB 저장 함수 — 같은 줄을 먼저 잠근다)
  위반 시: 막아 둔 품목이 들어오거나, 저장 직전에 시작한 등록이 옛 설정으로 지나간다.
- INV-H8: 팬 등록 화면에서 고른 종류가 살아 있는 받기 어려운 품목과 겹치면 결제 전에
  「{크리에이터 공개 이름}님이 지금 {품목}은 받기 어렵대요. 다른 선물을 고르시겠어요?」를 보인다(품목 이름 받침에 따라 「은/는」).
  「안내만」이면 그대로 다음 단계로 갈 수 있고, 「등록 막기」면 그 종류로는 다음 단계로 가지 않는다(서버도 INV-H7 로 막는다).
  (강제 위치: 화면 쪽 판정 함수 하나 — 등록 화면이 쓴다)
  위반 시: 팬이 거절당할 선물을 모르고 결제하거나, 안내만인데 진행이 막힌다.

## 스스로 정한 것 (추가분에 없던 세부)

- 저장 방식: 크리에이터당 설정 하나(새 표, 크리에이터와 1:1). 끝나는 날을 저장하고 읽을 때 오늘과 비교한다 — 업계 일반 방식.
  추가분은 「스케줄 작업」이라 했지만 읽을 때 계산하면 같은 결과이고 예약 작업이 늦거나 빠질 일이 없다. 받는 양 조절의 「다시 받는 날」과 같은 방식.
- 기간 계산: 1주 = 7일, 2주 = 14일, 한 달 = 달력의 한 달(10월 11일 → 11월 11일, 1월 31일 → 2월 28일) — 업계 일반 방식. 기준은 한국 시간 날짜.
  고른 기간도 저장해 둔다 — 설정 화면이 다시 열 때 같은 칸을 골라 보이게. 다시 저장하면 그날부터 다시 센다(설정 화면에 그렇게 적는다).
- 주문의 칸: 새 칸 「물품 종류」(코드, 기존 주문은 비어 있음)를 더하고, 기존 「물품 이름」 칸은 보여 주기용으로 계속 채운다(기타면 팬의 글,
  아니면 종류 이름). 기존 화면·운영자 화면·승인 화면이 물품 이름을 그대로 읽어 바꿀 곳이 없다 — 판단.
  기존 주문은 옛 글을 종류로 추측해 채우지 않는다(틀리게 채우면 겹침 판정이 엉뚱하게 걸린다).
- 기타 30자 — 지금 입력 칸과 같은 길이. 기타 글에는 금칙어 필터를 걸지 않는다 — 크리에이터·운영자에게만 보이는 글이고 지금도 걸지 않는다.
- 전자기기를 고르면 신고를 자동으로 켠다 — 판단. 신고는 검수에 시간을 더 쓰라는 표시라, 켜는 쪽으로 틀리는 것이 안전하다.
  다른 종류에 전자기기·금속이 들어 있을 수 있어 그때는 지금처럼 팬이 고른다.
- 받기 어려운 품목에 「기타」도 고를 수 있다(추가분 목록 그대로). 겹침은 종류 코드로만 본다 — 기타 글의 내용은 보지 않는다.
- 공개 응답에 동작(안내만/등록 막기)은 넣는다 — 등록 화면이 「그대로 진행」을 허락할지 정해야 하고, 팬에게 알려져도 사고가 아니다.
- 화면을 건너뛴 등록이 서버에서 「등록 막기」로 거부되면 「지금 {품목}은 받기 어려운 크리에이터예요. 다른 선물을 골라 주세요.」(응답 409).
  서버 등록 처리는 크리에이터 이름을 읽지 않아 화면 안내와 문장이 조금 다르다 — 정상 흐름에서는 화면이 먼저 막는다.
- 주문의 종류 인자는 등록 함수의 맨 뒤에 기본값 「기타」로 더했다 — 종류 없이 부르는 옛 호출(통합 시험 도우미)은 물품 이름을 기타 글로 친다.
  앱은 늘 종류를 넘긴다.
- 설정 해제는 품목을 모두 빼고 저장하는 것과 같은 동작이다(따로 「해제」 버튼이 같은 저장을 부른다).

## 시나리오

- S1 (INV-H1): Given 팔로우한 팬 / When 종류 「인형·쿠션」(doll)으로 등록 / Then 주문의 종류는 doll, 물품 이름은 「인형·쿠션」.
- S1b (INV-H1): Given 같은 팬 / When 기타 + 「손편지와 사진」 / Then 종류 other, 물품 이름 「손편지와 사진」.
- S1c (INV-H1, 실패경로): When 종류 「food」·「냉장」·빈 값 / 기타인데 글 없음·31자 / doll 인데 글을 같이 보냄 / Then 각각 거부되고 주문이 생기지 않는다.
- S1d (INV-H1): Given 이 기능 전에 만든 주문 / When 이 기능을 적용한 뒤 / Then 종류 칸은 비어 있고 물품 이름은 그대로다.
- S2 (INV-H2): When 전자기기를 고르고 신고 「없어요」로 등록 / Then 신고가 켜진 채 저장된다. 다른 종류는 보낸 대로 저장된다.
- S3 (INV-H3): Given 크리에이터 A·B / When A 로그인으로 설정 저장 / Then A 에만 설정이 있고, 저장 함수에 크리에이터 ID 칸이 없다.
- S3b (INV-H3, 실패경로): When 팬·운영자·로그인 안 한 사람이 저장 함수를 부름, 크리에이터가 설정 표에 직접 씀 / Then 거부되고 아무것도 바뀌지 않는다.
- S4 (INV-H4, 실패경로): When 품목 「food」·같은 품목 두 번·9개 / 이유·기간·동작에 목록 밖 값·문장 / Then 각각 거부되고 설정 그대로.
- S4b (INV-H4): When 품목 없이 저장 / Then 설정이 지워진다.
- S5 (INV-H5): When 1주·2주·한 달·직접 해제로 저장 / Then 끝나는 날이 오늘+7·오늘+14·다음 달 같은 날·없음. 1월 31일의 한 달은 2월 28일(평년).
- S5b (INV-H5): Given 끝나는 날이 오늘(한국 시간) / When 공개 읽기·본인 읽기·「등록 막기」 품목으로 등록 / Then 설정이 없는 것으로 보이고 등록된다. 끝나는 날이 내일이면 보이고 막힌다.
- S6 (INV-H6): Given 인형·쿠션, 꽃 / 이유 「이미 많이 받았어요」 / Then 「지금은 인형·쿠션, 꽃을 받기 어려워요 ㅠㅠ 이미 많이 받았어요」.

## 신뢰 경계

- 믿는 값: 로그인 토큰이 확인한 계정(저장 함수의 크리에이터), DB 의 한국 시간 오늘, DB 에 저장된 설정, 등록 함수가 정한 물품 이름.

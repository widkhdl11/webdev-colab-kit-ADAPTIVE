# 배송 현황 표시 스펙 (웹훅 연결 전)

팬꾹이 상자를 내보낸 뒤 받는 쪽이 받을 때까지를 단계 네 개로 보여 준다. 배송 조회 서비스(웹훅)를 붙이기 전이라
택배사의 실제 위치는 모른다 — 송장 출력·출고 날짜·받는 쪽 확인과 지금 시각만으로 단계를 정한다.
팬 선물(팬 → 크리에이터)과 선물함(크리에이터 → 팬)이 같은 단계를 쓴다.

어기면 생기는 사고: 송장번호로 택배사 조회를 하면 「○○대리점」 줄에서 받는 사람의 지역이 드러난다. 받지 않은 선물을 「도착했어요」로
확정해 보여 주거나, 날짜로 짐작한 도착을 확인된 도착처럼 보여 준다. 웹훅을 붙일 때 화면을 다시 짜야 한다.

용어
- **송장 출력**: 사무실이 그 상자의 출고 송장을 출력한 것(주문 상태 송장 출력, 선물함 신청의 송장 출력 시각).
- **출고**: 사무실이 택배사에 넘긴 것(출고 확정 시각). 날짜는 서울 날짜로 센다.
- **받는 쪽 확인**: 팬 선물은 크리에이터의 「받았어요」(답장과 함께 남긴 것 포함 — gift-reply INV-G2), 선물함은 받는 팬의 「받았어요」.

## 불변식

- INV-DS1: 단계는 넷이고 문구는 결정문 그대로다 — 「팬꾹에서 보냈어요」(송장 출력부터) → 「보통 1~2일 안에 도착해요」(출고한 서울 날짜의 다음 날 0시부터)
  → 「도착했어요」(받는 쪽 확인) / 확인이 없으면 출고 + 3일(서울 날짜) 0시부터 「도착했어요(예상)」을 흐리게. 송장 출력도 출고도 없으면 배송 단계가 없다.
  단계는 저장하지 않는다 — 원천(송장 출력 여부·출고 날·받는 쪽 확인)과 화면을 그리는 서버의 지금 시각으로 한 곳(순수 함수)에서 계산한다.
  날짜 경계(다음 날 = 1, 예상 도착 = 3)는 설정값 하나씩이다.
  (강제 위치: 단계 계산 함수 · 화면은 그 결과만 그린다)
  위반 시: 같은 상자가 화면마다 다른 단계로 보이거나, 시각 경계가 시간대(UTC)로 어긋난다.
- INV-DS2: 「도착했어요」(확정)는 받는 쪽 확인으로만 된다. 날짜가 아무리 지나도 확인이 없으면 「도착했어요(예상)」이고, 확정과 구별되게 흐리게 보인다
  (팬 선물 상세의 단계 막대에서도 수령 칸을 끝난 칸으로 칠하지 않는다). 받는 쪽 확인은 출고 뒤에만 남길 수 있고, 두 번·동시에 눌러도 기록은 하나다.
  (강제 위치: 단계 계산 함수 · DB — 팬 선물은 gift-reply INV-G1·G2, 선물함은 받았어요 저장 함수의 줄 잠금 + 비어 있을 때만 씀)
  위반 시: 받지 않은 선물을 받은 것처럼 알린다.
- INV-DS3: 송장번호와 배송 이력의 노출 범위.
  ① 팬 화면·팬이 받는 응답에는 팬꾹이 발송한 송장번호가 어느 단계에서도 없다(팬 선물의 크리에이터행, 선물함의 팬행 모두). 팬이 사무실로 보낼 때 직접 넣은 자기 송장번호는 여기 해당하지 않는다(inbound-address-code INV-C7).
  ② 크리에이터 화면에는 자기 선물(자기 주소로 가는 상자)의 송장번호만 낼 수 있다. 선물함에서 팬에게 가는 송장번호는 크리에이터에게도 내지 않는다
     — 「자기 선물」이 아니고, 그 번호로 택배사 조회를 하면 팬의 지역·수령인이 드러난다.
  ③ 배송 이력의 대리점·터미널명, 기사 이름·전화, 배달 지역, 수령인은 팬·크리에이터 화면과 그 화면이 받는 응답 어디에도 내지 않는다. 단계 계산의 입력에는 이 칸이 없다.
  ④ 외부 조회 페이지(택배사·조회 서비스) 링크를 팬·크리에이터 화면에 두지 않는다 — 팬꾹 화면에서 단계만 보인다.
  (강제 위치: DB 읽기 함수가 돌려주는 칸 · 읽기 응답 꼴 검사(정해진 칸만) · 단계 계산 입력의 형)
  위반 시: 받는 사람의 지역·이름이 상대에게 드러난다(address-protection 의 목적이 무너진다).
- INV-DS4: 단계를 어디서 정할지는 설정값 하나(estimate | webhook)로 바뀐다. webhook 이면 날짜가 아니라 택배사 상태(집하·배송 중·배달 완료)로 정하고 화면 구조는 그대로다.
  웹훅 수신·택배사 상태 저장은 아직 없다 — 이 스펙은 설정값과 상태의 형(세 값)만 정한다. estimate 에서는 택배사 상태 칸이 와도 쓰지 않는다.
  (강제 위치: 설정 파일 · 단계 계산 함수)
  위반 시: 웹훅을 붙일 때 화면마다 고쳐야 하고, 한쪽만 바뀐 채 남는다.
- INV-DS5: 웹훅 연결 전에는 「배송 완료」를 쓰는 기준 넷 — 헤더 선물 아이콘의 체크, 선물함 신청의 delivered, 팬 주소 사본 삭제 시점, 탈퇴 가능 기준 — 이
  지금대로 출고 기준이다. 「도착했어요」(확정·예상)는 화면 단계일 뿐 이 넷을 바꾸지 않는다. 헤더 아이콘·상태 문구는 「배송 완료」 대신 「발송 완료」라고 쓴다(배달 완료를 모르기 때문).
  (강제 위치: 헤더 아이콘 판정 · DB — 받았어요 저장 함수는 신청 상태를 바꾸지 않는다)
  위반 시: 확인되지 않은 배달 완료를 근거로 주소를 지우거나 탈퇴를 허용한다.
- INV-DS6: 선물함(크리에이터 → 팬)도 INV-DS1~DS3 의 같은 단계를 쓴다. 받는 쪽은 팬이다 — 팬은 내 선물함 화면에서 단계와 [받았어요]를 보고, [받았어요]는 그 선물함에
  신청한 팬 본인만(로그인 토큰으로 DB 가 신청을 찾는다, 선물함 ID 외 인자 없음), 출고 뒤에만 남긴다. 크리에이터는 명세서 줄의 진행 칸에서 같은 단계를 본다.
  (강제 위치: DB 함수 revgift_box_fan_received · 팬이 보는 선물함 읽기)
  위반 시: 남의 신청에 받았어요가 남거나, 사무실에 있는 선물을 받았다고 표시한다.

## 시나리오

- S1 (INV-DS1): Given 서울 11월 9일 23시 59분 출고 / When 그날 23시 59분 · 10일 0시 · 12일 0시 직전 · 12일 0시에 본다 / Then 팬꾹에서 보냈어요 · 보통 1~2일 · 보통 1~2일 · 도착했어요(예상).
- S1b (INV-DS1, 실패경로): Given 검수 완료·출고 대기(송장 전) / Then 배송 단계 없음.
- S2 (INV-DS2): Given 출고한 날 / When 받는 쪽이 받았어요 / Then 도착했어요(확정), 흐리지 않음, 막대 끝까지.
- S2b (INV-DS2, 실패경로): Given 확인 없음 / When 30일 뒤 / Then 여전히 도착했어요(예상), 수령 칸은 끝나지 않음.
- S2c (INV-DS2, 실패경로): Given 출고 전 선물함 신청 / When 팬이 받았어요 / Then 거부, 기록 없음. 동시에 두 번 / Then 기록 하나.
- S3 (INV-DS3, 실패경로): Given 출고 송장번호가 있는 팬 선물 / When 팬 목록·팬 상자별 받았어요·크리에이터 받은 선물·선물 현황 읽기 / Then 어느 응답에도 그 번호가 없다(출고 날짜는 있다).
- S3b (INV-DS3, 실패경로): Given 팬행 송장번호가 있는 선물함 신청 / When 팬이 보는 선물함·크리에이터의 선물함 / Then 번호 없음. 팬 읽기 응답에 송장번호 칸이 섞여 오면 받지 않는다.
- S3c (INV-DS3, 실패경로): Given 크리에이터 선물 현황 · 팬 선물 상세 / Then 배송 조회 버튼·외부 조회 링크 없음.
- S4 (INV-DS4): Given webhook / Then 택배사 상태 없음 = 팬꾹에서 보냈어요, 집하·배송 중 = 보통 1~2일, 배달 완료 = 도착했어요. estimate 에서는 택배사 상태를 쓰지 않는다.
- S5 (INV-DS5): Given 출고된 팬 선물 / Then 헤더 아이콘 체크(발송 완료), 문구에 「배송 완료」 없음. 선물함 받았어요 뒤에도 신청 상태 shipped 그대로.
- S6 (INV-DS6): Given 선물함 신청 — 송장 전 · 송장만 · 출고 2일 / Then 팬 화면 준비 중 · 팬꾹에서 보냈어요(버튼 없음) · 단계 + [받았어요]. 신청하지 않은 팬·크리에이터·로그인 안 함은 남길 수 없다.

## 신뢰 경계

- 믿지 않는 값: 브라우저 시각(단계 경계는 서버가 그린 시각), 요청 본문의 신청·팬 ID(받았어요는 선물함 ID 하나만 받고 신청은 로그인 토큰으로 찾는다).
- 읽기 응답은 정해진 칸만 받는다 — 송장번호·이력 칸이 섞여 오면 화면 코드가 거부한다.

## 스스로 정한 것

- 「다음 날」·「출고 + 3일」은 서울 날짜로 센다(72시간이 아니라 날짜) — 「다음 날」과 같은 기준으로 맞췄다.
- 한 주문의 상자는 한 송장으로 함께 나가므로, 팬 선물 상세는 상자 중 하나라도 받았어요가 있으면 「도착했어요」로 본다.
- 크리에이터 받은 선물 목록은 받았어요를 남긴 상자의 글을 지금처럼 답장 상태(수령 확인·답장)로 두고, 아직 남기지 않은 상자에만 단계 문구를 붙인다.
- 팬 선물 상세의 단계 막대 여섯 칸은 그대로 두고, 「배송 중」·「수령」 칸만 단계에 맞춘다(보통 1~2일 → 배송 중 끝, 도착했어요 → 수령 끝, 예상 → 수령 칸 흐리게).

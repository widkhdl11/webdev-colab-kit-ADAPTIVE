# 크리에이터 이름 = 닉네임 스펙

크리에이터에게는 이름이 하나뿐이다 — 가입 때 정한 **닉네임**이다. 예전에는 닉네임과 따로 「공개 이름」(팬에게 보이는 이름)과
「채널 이름」(방송 채널에 보이는 이름)을 받았지만, 2026-11-05 사용자 지시로 둘 다 없앴다.
「채널 이름이 없는 크리에이터도 많아서 혼란」이었고, 이름이 셋이면 어느 것이 어디에 보이는지 크리에이터가 알 수 없었다.

데이터베이스에는 크리에이터 정보 표의 이름 칸(`creators.name`)이 그대로 있다. 팬에게 크리에이터를 보여 주는 읽기가 모두 이 칸을 읽기 때문에
칸을 없애지 않고, 대신 **그 계정의 닉네임과 언제나 같은 값**이 되게 한다. 그래서 읽는 쪽은 바뀌지 않는다.

## 불변식

- INV-CN1: 계정이 연결된 크리에이터 행의 이름은 언제나 그 계정의 닉네임과 같다. 행을 새로 만들거나 고칠 때 어떤 값을 넣어도 이름은 닉네임이 되고,
  닉네임이 바뀌면 같은 처리 안에서 크리에이터 이름도 바뀐다. 닉네임 바꾸기와 크리에이터 정보 저장이 동시에 와도 둘 다 끝난 뒤의 이름은 지금 닉네임이다.
  탈퇴해 계정이 끊긴 행(이름 「탈퇴한 크리에이터」, my-account INV-A15)은 이 규칙에서 빠진다.
  채널을 아직 만들지 않은 크리에이터(signup INV-U21)는 닉네임이 비어 있고 이름도 비어 있다 — 채널을 만들어 닉네임이 생기면 같은 처리 안에서 이름이 닉네임이 된다(2026-11-11).
  (강제 위치: DB — 크리에이터 행을 넣거나 고치기 전에 이름을 닉네임으로 바꾸는 트리거, 닉네임이 바뀐 뒤 크리에이터 이름을 바꾸는 트리거)
  위반 시: 프로필·카드·알림의 크리에이터 이름이 닉네임과 달라져, 팬이 찾는 이름과 크리에이터가 아는 자기 이름이 갈라진다.

- INV-CN2: 크리에이터가 이름을 닉네임과 따로 정하는 길은 없다. 가입은 공개 이름을 받지 않고, 크리에이터 정보 저장 함수에는 이름 칸이 없다 —
  프로필 수정의 「닉네임」 칸은 닉네임을 바꾸며(signup INV-U13 의 규칙·겹침 금지 그대로), 그 결과 이름이 따라 바뀐다.
  (강제 위치: DB 함수 — 가입·크리에이터 정보 저장 함수의 인자 목록 / 서버 입력 경계 — 이름 칸을 읽지 않는다)
  위반 시: 남과 겹치거나 금칙어가 든 이름이 닉네임 검사를 거치지 않고 팬에게 보인다.

- INV-CN3: 크리에이터의 닉네임이 바뀔 때마다(프로필 수정·내 정보 어느 경로로든) 언제·전·후가 이름 바꾼 기록에 한 줄 남는다.
  그 기록은 추가만 되고 운영자 크리에이터 목록의 「닉네임 바꾼 기록」에 보인다(my-account INV-A9 의 사칭 판단 근거).
  이 규칙을 들일 때(2026-11-10) 이름이 닉네임과 달랐던 행은 옛 이름 → 닉네임을 같은 기록에 남기고 덮었다.
  (강제 위치: DB — 닉네임이 바뀐 뒤 도는 트리거가 기록과 이름 바꾸기를 한 처리에서 / 기록 표는 고치기·지우기 금지)
  위반 시: 이름을 바꿔 다른 크리에이터를 흉내 낸 뒤 되돌려도 흔적이 없어 사칭 신고를 판단할 수 없다.

- INV-CN4: 채널 이름은 받지 않는다 — 가입 화면에 칸이 없고 가입 함수도 받지 않는다. 칸(`channel_title`)은 남지만 빈 값이 기본이고 필수가 아니며,
  화면 어디에도 보이지 않는다. 채널 확인은 이름을 대조하지 않는다(creator-verification INV-V18).
  (강제 위치: 서버 입력 경계 / DB 가입 함수의 인자 목록)
  위반 시: 채널 이름이 없는 크리에이터가 가입을 못 하거나, 가입 때 적은 값이 채널 확인 반려 사유가 된다.

## 시나리오

- S1 (INV-CN1): Given 닉네임 「하루」인 크리에이터 / When 내 정보에서 닉네임을 「하루달」로 바꿈 / Then 크리에이터 이름도 「하루달」.
- S1b (INV-CN1): Given 같은 크리에이터 / When 크리에이터 행의 이름을 직접 「가짜이름」으로 고침 / Then 이름은 닉네임 그대로.
- S1c (INV-CN1, 동시): Given 크리에이터 행이 잠긴 동안 / When 닉네임 바꾸기와 소개 저장이 겹쳐 옴 / Then 둘 다 끝난 뒤 이름 = 지금 닉네임.
- S2 (INV-CN2): Given 크리에이터로 로그인 / When 프로필 저장에 닉네임 「별빛」(다른 계정이 쓰는 닉네임) / Then 「이미 쓰는 닉네임」, 아무 칸도 안 바뀜.
- S2b (INV-CN2): Given 크리에이터 가입 / When 닉네임 「꿀단지」로 가입 / Then 크리에이터 이름 「꿀단지」, 채널 이름은 빈 값.
- S3 (INV-CN3): Given 크리에이터 / When 닉네임을 바꿈 / Then 이름 바꾼 기록에 전·후 한 줄. 같은 닉네임으로 다시 저장하면 기록이 늘지 않는다.

## 비범위

- 크리에이터 이름 칸을 DB 에서 없애거나 이름을 바꾸는 일 — 읽는 SQL 이 많아 남긴다. 값만 닉네임과 같게 맞춘다.
- 팬의 닉네임 규칙 — signup INV-U13·my-account INV-A5 그대로다.

# 광고 배너 스펙

팬꾹 소식과 크리에이터 광고를 넓은 배너로 보여 준다. 운영자가 관리자 화면에서 그림·제목·설명·누르면 가는 곳·기간을 적어 올리고,
기간 안의 배너만 로그인 전 첫 화면·팬 홈(칸 ②)·크리에이터 홈과 크리에이터 찾기에 순서대로 넘어가며 보인다. 사이트 안에서 신청하거나 결제하지 않는다.
어기면 사고가 나는 자리는 넷이다 — ① 운영자가 아닌 사람이 배너를 바꿔 모든 방문자에게 보이는 자리에 아무 글·링크나 건다
② 공개 전 배너(발표 전 행사)나 끝난 배너가 보인다 ③ 누르면 가는 곳에 `javascript:` 같은 주소가 들어가 누른 사람의 화면에서 코드가 돈다
④ 공개 저장소가 늘어나며 비공개여야 할 그림(선물 사진 등)까지 공개 쪽에 들어간다.

## 불변식

- INV-Y1: 배너를 만들고·고치고·내리고·순서를 바꾸는 것은 운영자만 한다(직원 포함 — 요금표처럼 대표만은 아니다). 판정은 DB 함수가
  로그인 토큰의 사람 ID 로 계정 역할을 읽어서 한다(admin-console INV-K1 과 같은 방법). 운영자가 아니면 거부하고 아무것도 바뀌지 않는다.
  배너 표에는 화면 쪽 키(익명·로그인 사용자)의 쓰기 정책을 두지 않는다 — 쓰는 길은 운영자 확인을 하는 DB 함수(또는 그것을 부르는 서버)뿐이다.
  (강제 위치: DB 함수 진입부 · 표 쓰기 정책 없음 / 화면 — 운영자가 아니면 관리자 주소 404)
  위반 시: 팬·크리에이터 한 명이 모든 방문자가 보는 첫 화면에 아무 글과 링크를 건다.

- INV-Y2: 공개 읽기(누구나, 로그인 없이)는 **지금 보이는 배너만** 돌려준다. 보이는 배너 = 시작 날짜 ≤ 오늘 그리고 (끝 날짜가 비었거나 오늘 ≤ 끝 날짜).
  날짜는 한국 날짜(Asia/Seoul)로 세고, 시작·끝 날짜는 그날 하루 전체를 포함한다. 예정·끝난 배너와 만든 사람·고친 사람 칸은 공개 읽기에 나오지 않는다.
  상태(보이는 중·예정·끝남)는 저장하지 않고 읽을 때 같은 규칙 하나로 계산한다 — 공개 목록과 관리자 화면의 상태 이름이 서로 다른 규칙을 쓰지 않는다.
  끝 날짜는 시작 날짜보다 앞설 수 없다(같은 날은 된다).
  (강제 위치: DB 공개 읽기 함수의 조건 · 표 읽기 정책은 운영자만 / DB 제약 — 끝 ≥ 시작)
  위반 시: 발표 전 행사 배너가 미리 보이거나, 끝난 이벤트 광고가 계속 걸린다. 화면마다 「보이는 중」의 기준이 달라 운영자가 본 것과 방문자가 본 것이 다르다.

- INV-Y3: 누르면 가는 곳은 둘 중 하나만 저장된다 — ⓐ 팬꾹 안 주소: `/` 로 시작하고 두 번째 글자가 `/`·`\` 가 아니며 공백·제어 문자가 없다
  ⓑ 바깥 주소: `https://` 로 시작하고 호스트가 있는 주소. 그 밖(`http:`·`javascript:`·`data:`·`//다른곳`·빈 값)은 저장을 거부한다.
  바깥 주소는 새 탭으로 열고 `rel="noopener noreferrer"` 를 붙인다. 팬꾹 안 주소는 같은 탭.
  (강제 위치: DB 제약(저장 경계) / 서버 저장 경로의 같은 검사 / 화면 — 그리는 부품이 ⓐⓑ 를 다시 갈라 ⓑ 에만 새 탭)
  위반 시: 배너를 누른 방문자 화면에서 스크립트가 돈다, 또는 팬꾹 주소처럼 보이는 링크가 다른 사이트로 보낸다.

- INV-Y4: 배너 그림은 공개 저장소(`banner-images`)에 두되, 쓰기는 서버만 한다 — 저장소에 화면 쪽 키의 쓰기·고치기·지우기 정책이 없다.
  서버는 운영자 확인(INV-Y1)을 먼저 하고, 받은 파일이 실제 이미지인지 열어 보고(PNG·JPG, 5MB 이하 — 시안 값), 위치를 포함한 사진 정보(EXIF 등)를
  모두 지우고, 정해진 크기로 다시 그려 WebP 로만 저장한다. 원본은 저장하지 않는다. 파일 이름은 서버가 정하고 짐작할 수 없는 부분을 포함한다
  (공개 저장소는 주소만 알면 열리므로 — 공개 전 배너 그림이 주소 짐작으로 미리 열리지 않게). 그림을 바꾸면 옛 파일을, 배너를 내리면 그 파일을 지운다.
  (강제 위치: 저장소 — 화면 쪽 쓰기 정책 없음, 서버의 비밀 키로만 씀 / 서버 — 그림 저장 경로 하나 / 시험 — 위치 정보가 든 사진을 올려 저장 파일에 사진 정보가 없는지)
  위반 시: 남이 저장소에 바로 올려 배너 그림을 바꾼다. 운영자 휴대폰 사진의 위치 정보가 공개된다. 발표 전 배너 그림이 미리 열린다.

- INV-Y5: 공개 저장소는 셋뿐이다 — 크리에이터 사진(`creator-photos`) · 팬 프로필 사진(`fan-photos`) · 배너 그림(`banner-images`). 그 밖의 저장소는 비공개다.
  (2026-10-11 ⑫ 「공개 저장소 금지」의 세 번째 예외 — DECISIONS 2026-10-18.) 새 공개 저장소는 이 목록을 바꾸는 결정 없이 생기지 않는다.
  (강제 위치: 시험 — 로컬 DB 의 저장소 목록에서 공개인 것이 정확히 이 셋인지)
  위반 시: 선물 사진처럼 서명 주소로만 열어야 할 그림이 누구나 여는 주소로 새어 나간다.

- INV-Y6: 제목은 앞뒤 공백을 뺀 1~30자, 설명은 0~40자(글자 수는 화면에 보이는 글자 단위). 저장 시 넘거나 제목이 비면 거부한다.
  화면은 글자 그대로(HTML 로 해석하지 않고) 그린다.
  (강제 위치: DB 제약 / 서버 저장 경로 / 화면 — 글자로만 그림)
  위반 시: 긴 글이 배너를 넘쳐 깨지거나, 글 속 태그가 화면에서 실행된다.

- INV-Y7: 「크리에이터 광고」로 표시한 배너는 어느 화면에 나오든 제목 앞에 「광고」 꼬리표가 보인다. 이 표시는 관리자 화면에서 켜고 끄며,
  공개 읽기가 그 값을 함께 돌려준다. 꼬리표를 그리지 않는 화면 자리는 없다(첫 화면·팬 홈·크리에이터 홈·크리에이터 찾기·관리자 미리보기 모두 같은 부품).
  (강제 위치: DB — 공개 읽기에 표시 값 포함 / 화면 — 배너 한 장을 그리는 부품 하나)
  위반 시: 돈을 받거나 부탁받은 광고가 팬꾹 소식처럼 보인다(표시·광고의 공정화에 관한 법률의 추천·보증 심사지침 — 광고임을 알 수 있게 표시).

- INV-Y8: 보이는 순서는 순서 값이 작은 것부터, 같으면 먼저 만든 것부터다(순서 값은 겹쳐도 된다 — 두 운영자가 동시에 바꿔도 순서가 정해진다).
  보이는 배너가 하나도 없으면 칸 ② 자체를 그리지 않는다(빈 틀·자리표시가 남지 않는다).
  (강제 위치: DB 공개 읽기 함수의 정렬 / 화면 — 0장이면 칸 없음)
  위반 시: 새로 고칠 때마다 순서가 바뀌거나, 배너가 없는 날 첫 화면에 빈 상자가 남는다.

- INV-Y9: 배너가 저절로 넘어가면 멈춤 버튼이 늘 보이고 눌러 멈출 수 있다. 움직임 줄이기 설정(prefers-reduced-motion)이면 저절로 넘어가지 않는다.
  키보드로 배너 안에 초점이 있거나 마우스가 올라가 있는 동안에는 넘어가지 않는다.
  (강제 위치: 화면 — 배너 넘김 부품 / 시험 — 설정을 켠 상태에서 시간이 지나도 장이 바뀌지 않는지)
  위반 시: 읽는 중에 장이 바뀌어 누르려던 링크가 다른 배너로 바뀐다. 움직임에 민감한 사람에게 어지러움을 준다(WCAG 2.2.2).

- INV-Y10: 배너를 만들고 고치고 내린 기록이 남는다 — 언제, 어느 운영자가, 무엇을(만듦·고침·순서·내림). 이 기록은 화면에서 고치거나 지울 수 없다.
  (강제 위치: DB 쓰기 함수가 같은 처리 안에서 기록 / 기록 표에 쓰기 정책 없음)
  위반 시: 잘못된 배너가 걸렸을 때 누가 걸었는지 알 수 없다.

## 시나리오

- S1 (INV-Y1): Given 운영자 / When 배너를 만들고, 제목을 고치고, 순서를 바꾸고, 내림 / Then 넷 다 반영된다.
- S1b (INV-Y1, 실패경로): Given 팬·크리에이터·로그인 안 한 사람 / When 같은 네 가지를 DB 함수로 직접 부름 / Then 모두 거부, 표는 그대로.
- S1c (INV-Y1, 실패경로): Given 로그인한 팬 / When 화면 쪽 키로 배너 표에 바로 넣기·고치기·지우기 / Then 모두 거부(정책 없음).
- S2 (INV-Y2): Given 오늘(한국 날짜) 2026-10-20, 배너 넷 — 10-14~10-20 · 10-21~ · 10-01~10-19 · 10-20~(끝 없음) / When 공개 읽기 / Then 첫째·넷째만, 관리자 상태 이름은 보이는 중·예정·끝남·보이는 중.
- S2b (INV-Y2, 실패경로): Given 한국 시간 10-21 00:30(UTC 로는 10-20) / When 끝 날짜 10-20 인 배너를 공개 읽기 / Then 나오지 않는다(UTC 날짜로 세지 않는다).
- S2c (INV-Y2, 실패경로): Given 로그인 안 한 사람 / When 배너 표를 직접 읽음 / Then 빈 결과(예정·끝난 배너·만든 사람이 보이지 않음).
- S2d (INV-Y2, 실패경로): When 끝 날짜가 시작보다 앞서는 배너를 저장 / Then 거부.
- S3 (INV-Y3): When `/about`·`/#price`·`https://youtube.com/@haru` 를 저장 / Then 저장되고, 화면에서 앞의 둘은 같은 탭, 셋째는 새 탭 + noopener noreferrer.
- S3b (INV-Y3, 실패경로): When `javascript:alert(1)`·`http://a.com`·`//evil.com`·`/\evil.com`·`data:text/html,x`·빈 값·`/ a` 를 저장 / Then 모두 거부.
- S4 (INV-Y4): Given 운영자 / When 위치 정보가 든 JPG 를 배너 그림으로 올림 / Then 저장된 파일은 WebP 이고 사진 정보가 없으며 이름에 짐작할 수 없는 부분이 있다. 그림을 바꾸면 옛 파일이 사라진다.
- S4b (INV-Y4, 실패경로): Given 로그인한 팬 / When 화면 쪽 키로 `banner-images` 에 파일을 올림 / Then 거부. When 그림이 아닌 파일(이름만 .png)·5MB 넘는 파일을 운영자가 올림 / Then 거부, 배너는 그대로.
- S5 (INV-Y5): When 로컬 DB 의 저장소 목록을 읽음 / Then 공개인 것은 정확히 셋. 
- S5b (INV-Y5, 실패경로): Given 시험용으로 공개 저장소 하나를 더 만든 상태 / Then 이 시험이 실패한다(목록과 다르다).
- S6 (INV-Y6): When 제목 30자·설명 40자 / Then 저장. When 제목 「<b>x</b>」 / Then 화면에 글자 그대로 보인다.
- S6b (INV-Y6, 실패경로): When 제목 공백만·31자, 설명 41자 / Then 거부.
- S7 (INV-Y7): Given 「크리에이터 광고」 켠 배너 / When 첫 화면·팬 홈·크리에이터 홈·크리에이터 찾기·관리자 미리보기 / Then 다섯 다 제목 앞 「광고」.
- S7b (INV-Y7, 실패경로): Given 끈 배너 / Then 「광고」 꼬리표 없음(켠 값만 따른다 — 꼬리표를 늘 그리거나 늘 빼는 구현은 S7 이나 S7b 에서 실패).
- S8 (INV-Y8): Given 순서 값 2·1·1(먼저 만든 것이 셋째) / When 공개 읽기 / Then 셋째 → 둘째 → 첫째.
- S8b (INV-Y8, 실패경로): Given 보이는 배너 0 / When 첫 화면을 그림 / Then 칸 ② 가 없다(배너 영역 요소 0).
- S9 (INV-Y9): Given 배너 둘 / When 멈춤 버튼을 누르고 시간이 지남 / Then 장이 바뀌지 않는다.
- S9b (INV-Y9, 실패경로): Given 움직임 줄이기 켬 / When 넘김 간격보다 오래 기다림 / Then 첫 장 그대로.
- S10 (INV-Y10): Given 운영자 A 가 배너를 만들고 B 가 내림 / Then 기록 두 줄(A 만듦 · B 내림)과 시각.
- S10b (INV-Y10, 실패경로): Given 운영자 / When 기록 표를 직접 고치거나 지움 / Then 거부.

## 신뢰 경계

- 믿는 값: 로그인 토큰의 사람 ID 와 DB 의 계정 역할(운영자 여부) · DB 가 계산한 한국 날짜 · 서버가 다시 그려 저장한 그림 파일 · 서버가 정한 파일 이름.
- 믿지 않는 값: 화면이 보낸 링크·제목·설명(DB 제약과 서버가 다시 검사) · 올린 파일의 확장자·MIME 표시(열어서 확인) · 화면이 보낸 「오늘」 날짜나 상태 이름 · 브라우저의 시간대.

## 비범위

- 크리에이터가 사이트 안에서 광고를 신청하거나 결제하는 것(design-rules 00절 — 운영자가 올린다).
- 누른 횟수·노출 횟수 세기, 사람마다 다른 배너.
- 로그인 전·후·화면별로 다른 배너 묶음 — 보이는 배너 목록은 한 가지다.
- 배너 모양(바탕 색·크기·넘김 간격)은 design-rules 가 정한다.

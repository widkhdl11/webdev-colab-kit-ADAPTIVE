# 채널 확인 개정안 — 선물 링크 게시 확인

크리에이터가 **자기 선물 링크(`fankkuk.com/<링크용 아이디>`)를 자기 채널의 소개·프로필 링크 칸에 올리면**, 운영자가 그 채널의 공개 페이지를 열어
**채널 이름이 가입 때 적은 채널 이름과 같고 선물 링크가 걸려 있으면** 승인한다. 채널 주인만 그 칸을 고칠 수 있으니, 그 칸에 이 계정의 선물 링크가 있다는 것이 채널 주인이라는 증거다.
링크용 아이디는 팬꾹에서 따로 정하는 값이라 플랫폼 아이디와 같을 필요가 없다 — 보는 것은 「그 채널에 이 계정의 링크가 있는가」다.

지금 방식(인증 코드를 소개란에 잠깐 붙임)과 다른 점은 **올리는 것이 팬에게 쓸모 있는 링크**라는 것이다. 확인이 끝난 뒤에도 내릴 이유가 없고,
그래서 90일마다 「아직 있는지」로 다시 확인할 수 있다. 확인 코드를 공개 페이지에 넣는 방식은 쓰지 않는다.

화면 안내 문구(사용자 지정): 「팬이 선물을 보낼 수 있게 선물 링크를 채널 소개에 올려 주세요. 올라와 있으면 채널 확인도 같이 끝나요.」

## 확인 방법 (기본 하나 + 보조 둘)

| 방법 | 누가 판정 | 어디 | 상태 |
|---|---|---|---|
| **선물 링크 게시 확인(기본)** | 운영자가 공개 페이지를 열어 본다 | 모든 「받음」 플랫폼 | 이 개정으로 새로 |
| 치지직 로그인 확인(보조 ①) | 서버가 치지직 공식 API 에 묻는다 | 치지직 | 규칙(INV-V14)과 DB 처리는 있다. **실제 치지직 연결은 아직 없고 가짜 창구만 있다** — 치지직 개발자센터 앱 등록과 연결 구현이 남았다 |
| 운영자 1:1(보조 ②) | 운영자 | 어디든 | 지금처럼 1:1 문의 |

공개 페이지에서 링크를 서버가 자동으로 찾는 기능은 **2차**다 — 플랫폼 약관과 공개 API 로 읽을 수 있는 곳부터. 그때도 판정 규칙은 INV-V18 하나를 쓴다.

## 불변식

- INV-V17: 선물 링크 게시 확인 요청은 크리에이터 역할 계정이 자기 자신에 대해서만 낸다. 요청에 담기는 것은 채널 주소 하나다(주소 꼴은 INV-V2 그대로).
  요청하려면 그 계정에 **링크용 아이디가 있어야 한다** — 없으면 요청을 거부하고 「선물 링크 주소를 먼저 정해 주세요」로 답한다.
  요청은 만들어질 때 바로 「확인 대기」다(코드 받음 단계가 없다). 요청 줄에는 **그때의 링크용 아이디**를 같이 적어 둔다 — 운영자가 무엇을 찾아야 하는지가 요청 뒤에 바뀌지 않게.
  한 계정에 살아 있는 요청은 하나(INV-V4), 한 채널은 한 계정(INV-V8), 같은 채널로 끝난 요청은 3번까지(INV-V15)는 그대로다.
  (강제 위치: DB 요청 함수 — 로그인 토큰의 계정, 링크용 아이디 확인, 계정 단위 잠금)
  위반 시: 링크용 아이디가 바뀐 뒤 운영자가 옛 아이디 링크를 보고 승인해, 그 아이디를 나중에 가져간 다른 크리에이터의 링크가 확인 증거가 된다.

- INV-V18: 승인하려면 두 가지가 모두 맞아야 한다. (1) 그 채널 공개 페이지에 보이는 **채널 이름**이 그 계정이 가입 때 적은 채널 이름과 같다 — 앞뒤 공백과 영문 대소문자 차이만 같은 것으로 본다.
  팬꾹 닉네임은 비교하지 않는다(팬꾹 안에서 쓰는 이름이라 방송 이름과 다를 수 있다). (2) **공개 페이지의 소개·프로필 링크 칸**에 걸린 주소가 요청 줄의 선물 링크와 같다. 링크가 같다고 보는 것과 아닌 것:
  - 같다: `fankkuk.com/<아이디>` 에 `https://`·`http://`·`www.` 가 붙거나 빠진 것, 끝의 `/` 하나, 아이디의 대소문자만 다른 것(주소가 소문자로 넘어가므로 같은 페이지다).
  - 반려: 도메인만(`fankkuk.com`), 다른 경로(`/creators/…`·`/gifts/new` 등), 다른 아이디, 이 크리에이터의 **묶인 옛 아이디**(90일 뒤 풀려 다른 사람이 가져갈 수 있다),
    `?`·`#` 가 붙은 주소, 단축 주소·링크 모음 페이지를 거친 주소, 게시물·댓글·영상 설명에만 있는 링크.
  운영자 화면은 이 판정에 쓸 「찾을 링크」(요청 줄의 아이디로 만든 것)와 「채널 이름」(가입 때 적은 값)을 보여 준다. 2차의 자동 찾기도 같은 판정 함수를 쓴다.
  (강제 위치: 운영자 판정 — 화면이 보여 주는 「찾을 링크」와 반려 사유 목록 / 2차 자동 찾기 — 서버 판정 함수 하나)
  위반 시: 이름이 다른 채널을 자기 것이라 신청한 계정, 도메인만 걸어 둔 남의 채널, 다른 크리에이터의 링크, 링크 모음처럼 채널 주인이 아니어도 만들 수 있는 주소로 확인을 받는다.

- INV-V19: 확인 대기 요청의 승인·반려는 운영자만 한다. 한 요청은 한 번만 결정되고 결정마다 지울 수 없는 기록이 남는다(INV-V6 그대로).
  반려 사유 목록은 「선물 링크를 찾지 못함」·「링크 주소가 다름」·「채널 이름이 다름」·「채널 주소가 열리지 않음」·「그 밖」이다.
  크리에이터에게는 사유 값만 보이고 운영자 메모는 보이지 않는다(INV-V9 그대로). 운영자 확인에는 기한이 없다.
  (강제 위치: DB 승인·반려 함수)
  위반 시: 크리에이터가 스스로 승인하거나, 같은 요청에 승인과 반려가 함께 남는다.

- INV-V20: 승인된 크리에이터는 마지막 확인 시각(승인 또는 지난 재확인)에서 90일이 지나면 운영자 재확인 목록에 오른다. 링크용 아이디를 바꾸면 그때 바로 오른다.
  재확인은 같은 판정(INV-V18 — 지금 링크용 아이디 기준)이다. 운영자가 「링크 있음」을 누르면 마지막 확인 시각이 그때로 바뀐다.
  「링크 없음」이면 유예가 시작된다 — 유예 기간과 그동안 선물을 받는지는 「정할 것」 2다. 유예가 끝날 때까지 다시 확인되지 않으면 승인 취소(INV-K10)되고,
  사유는 새 값 「선물 링크가 채널에서 내려감」이다. 이미 등록된 주문은 그대로 간다(INV-V10 그대로).
  (강제 위치: DB 재확인 목록 계산 — 서버 시각 / DB 재확인 처리 함수 — 운영자 판정, 행 잠금 / 예약 작업 — 유예 끝 처리)
  위반 시: 확인 뒤 채널을 다른 사람에게 넘기거나 링크를 내린 채널이 계속 확인된 채널로 남는다. 아이디를 바꾼 뒤 옛 아이디가 풀려 남의 링크가 증거로 남는다.

- INV-V22: 확인 대기 요청이 있는 크리에이터의 선물 링크는 「없는 페이지」가 아니라 **「채널 확인 중」 페이지**로 열린다 — 「정할 것」 1 의 답에 따른다.
  그 페이지에는 선물 보내기가 없고, 선물 등록 함수도 거부한다. 크리에이터 찾기에는 나오지 않는다.
  (강제 위치: 서버 — 링크 페이지 읽기 / DB 선물 등록 함수 — 확인됨 판정은 그대로)
  위반 시: 크리에이터가 안내대로 링크를 올렸는데 팬이 누르면 없는 페이지가 열린다(지금 creator-link INV-E5). 또는 확인 전 계정이 선물을 받는다.

## 정할 것 (결정 카드)

1. **확인 대기 중의 선물 링크 페이지** — 추천: 「채널 확인 중」 페이지(공개 이름·프로필 사진·한 줄 소개, 선물 버튼 자리에 「채널 확인이 끝나면 선물을 보낼 수 있어요」).
   요청 전·반려 뒤에는 지금처럼 없는 페이지. 이유: 안내대로 링크를 올린 크리에이터의 팬이 없는 페이지를 보지 않게 하되, 확인 전 계정이 쓸 수 있는 공개 페이지를 요청 중으로만 좁힌다.
2. **재확인에서 링크가 없을 때** — 추천: 14일 유예, 유예 동안 선물 받기는 그대로, 크리에이터 화면에 「채널 소개에서 선물 링크를 찾지 못했어요」와 「다시 확인 요청」. 14일 뒤 승인 취소.
3. **링크용 아이디를 바꿨을 때** — 추천: 바로 재확인 목록에 오르고 2와 같은 14일 유예. 옛 주소는 90일 동안 새 주소로 넘어가므로 그 사이 팬이 길을 잃지 않는다.

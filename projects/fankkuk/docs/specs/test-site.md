# 시험 사이트 스펙

## 왜

배포한 사이트는 코드가 언제나 운영으로 판정한다. 카카오·플랫폼 연결 전이라 운영에는 본인 확인·승인 서명·채널 확인 창구가 없어서,
배포한 시험 사이트에서는 아무도 가입할 수 없고 크리에이터도 생기지 않는다. 시험·스테이징 환경에서 외부 인증을 모의 창구로
바꾸는 것은 업계에서 흔한 방식이다. 다만 그 스위치가 실제 운영에 남으면 본인 확인 없이 가입이 열리므로, 켜지는 조건을 좁게 묶는다.

## 불변식

- INV-TS1: 시험 사이트인지는 한 곳에서만 정한다. 두 조건을 모두 만족할 때만 시험 사이트다 — 설정 `FANKKUK_TEST_SITE` 의 값이
  정확히 `1` 이고, 설정 `APP_ORIGIN` 의 사이트 주소가 코드에 적힌 시험 주소 목록에 있다. 하나라도 아니면 운영 그대로다.
  요청 헤더(Host 등)는 보지 않는다 — 요청 보내는 사람이 바꿀 수 있는 값이다.
  (강제 위치: 서버 — 시험 사이트 판정 함수 하나)
  위반 시: 실제 운영 사이트에서 본인 확인 없이 가입되고, 크리에이터 서명 없이 선물이 승인된다.

- INV-TS2: 시험 사이트에서 가짜로 열리는 창구는 넷뿐이다 — 휴대폰 본인 확인(signup INV-U9, 가입과 번호 바꾸기),
  승인 서명(approval-signature INV-S11 — 크리에이터 주소 등록 address-protection INV-P13 도 같은 창구),
  플랫폼 로그인 확인(creator-verification INV-V14), 채널 소개란 읽기(INV-V16).
  주소 복호화(address-protection INV-P12)·알림 발송 창구(notifications INV-N11)·시험 계정 로그인 주소(session-login INV-L6)는
  시험 사이트에서도 운영과 똑같이 닫혀 있다. (강제 위치: 서버 — 각 창구를 고르는 곳 하나씩, 판정은 INV-TS1 의 함수)
  위반 시: 개발용 주소 열쇠가 배포 서버에서 쓰이면 앱 서버 하나로 전원의 주소가 열린다(INV-P2·P3).

INV-TS3(시험 사이트의 모든 화면 맨 위 「시험 사이트」 띠)은 2026-10-24 지웠다(카드 d127). 이제 화면에는 시험 사이트라는 표시가 없다.
받아들인 위험: 방문자가 가짜 본인 확인·가짜 승인 서명으로 만든 계정과 승인을 진짜로 믿을 수 있다. 결제는 토스 테스트 키라 실제 돈은 나가지 않는다.

DB 쪽 잠금은 바뀌지 않는다 — 가짜 서명은 「가짜 서명 허용」 줄이 있는 DB 에서만 받는다(approval-signature INV-S11).
시험 사이트의 DB 에는 사람이 그 줄을 직접 넣고, 실제 운영 DB 에는 넣지 않는다(배포 절차 문서).

**시험 사이트의 DB 는 실제 운영 DB 로 돌려쓰지 않는다 — 실제 운영은 새 DB 로 연다.** 가짜 본인 확인으로 등록한 번호와 가짜 플랫폼 로그인으로
확인한 채널은 DB 에 진짜와 같은 모양으로 남아 구별할 수 없다(서명과 달리 DB 쪽 잠금이 없다). 시험 사이트 안에서는 크리에이터 누구나 아무 채널이든
확인됨으로 가져갈 수 있고 남의 번호로 먼저 가입할 수 있다 — 시험 데이터라 받아들인다(2026-10-12 보안 리뷰 medium·low. 그때는 띠가 알렸으나 2026-10-24 띠를 지웠다).

## 시나리오

- S1 (INV-TS1): Given 운영 빌드, `FANKKUK_TEST_SITE=1`, `APP_ORIGIN` 이 시험 주소 / When 판정 / Then 시험 사이트.
- S1b (INV-TS1, 실패경로): Given `FANKKUK_TEST_SITE=1` 이지만 `APP_ORIGIN` 이 다른 주소·비어 있음·주소 꼴이 아님 / When 판정 / Then 시험 사이트 아님.
- S1c (INV-TS1, 실패경로): Given `APP_ORIGIN` 은 시험 주소지만 `FANKKUK_TEST_SITE` 가 없음·`true`·`0` / When 판정 / Then 시험 사이트 아님.
- S2 (INV-TS2): Given 시험 사이트 / When 본인 확인·승인 서명·플랫폼 로그인·소개란 창구를 고름 / Then 넷 다 가짜 창구.
- S2b (INV-TS2, 실패경로): Given 운영 빌드, 시험 사이트 아님 / When 같은 넷을 고름 / Then 넷 다 창구 없음.
- S2c (INV-TS2, 실패경로): Given 시험 사이트 / When 주소 복호화 설정을 읽음 · 알림 창구를 고름 · 시험 계정 로그인 주소를 만듦 / Then 복호화 거부, 알림톡 창구 없음, 시험 계정 주소 없음.

## 비범위

- 시험 사이트용 메일 서비스 — 메일 서비스를 정할 때 같이 정한다. 그 전까지 시험 사이트에서도 메일은 오류가 난다.
- 시험 데이터(크리에이터·주문)를 운영 DB 에 미리 넣기 — 시험 사이트에서 직접 가입해 만든다.

# 알림 묶어 보내기

알림이 사건마다 한 통씩 가던 것을 받는 사람마다 묶는다. 승인 요청은 크리에이터마다 10분 창(첫 건은 바로, 창 안에 더 온 건은 창 끝에 한 통)으로,
상태 알림 다섯은 기본이 하루 한 번 묶음이다. 본문 템플릿은 `docs/copy/alimtalk-templates.md` 2·3·9절(「상태: 코드 반영 전」).
이메일도 같은 규칙을 따른다 — 이메일 본문은 카카오 템플릿과 같은 틀이다(notifications INV-N7).

## 용어

- **10분 창**: 한 크리에이터의 승인 요청 알림을 세는 10분. 창을 연 요청은 바로 알리고, 창 안에 더 온 요청은 쌓았다가 창이 끝날 때 한 번 더 알린다.
- **승인 대기 건수**: 보내는 순간 그 크리에이터의 승인 요청 중 아직 「대기」인 것의 수.
- **하루 묶음**: 상태 알림 다섯을 받는 사람마다 하루 한 통으로 모은 알림.
- **바로 받기**: 받는 사람의 알림 설정 칸. 켜면 상태 알림이 사건마다 간다. 기본은 꺼짐.

## 불변식

- INV-NB1: 승인 요청 알림(approval_request)은 받는 크리에이터마다 10분 창 단위로 보낸다(「알림톡 규칙 확정」 1, 2는 2026-10-30 사용자 지시로 고침).
  ① 첫 결제가 끝나 승인 요청이 생겼는데 그 크리에이터에게 열린 창이 없으면, 지금부터 10분짜리 창을 열고 **바로** 한 통을 보낸다.
  ② 창이 열려 있는 동안 생긴 요청은 알림 없이 쌓는다.
  ③ 창이 끝날 때 ②로 쌓인 요청이 하나라도 있으면 한 통을 더 보낸다. 쌓인 것이 없으면 보내지 않는다. 끝 통은 창이 끝난 뒤 다음 자동 처리(5분마다)에서 만들어져,
  늦으면 창이 끝나고 5분 안에 간다. 끝 통이 만들어지기 전에 새 요청이 와서 새 창이 열리면, 새 창의 첫 통(건수는 그때의 대기 전체)이 끝 통을 대신한다.
  ④ 창이 끝난 뒤 생긴 요청은 ①로 새 창을 연다.
  어느 통이든 본문의 건수는 **보내는 순간** 그 크리에이터의 아직 처리되지 않은(대기) 승인 요청 전체다. 보내는 순간 대기가 0건이면(그 사이 모두 승인·거절·반려됨)
  보내지 않고 건너뜀으로 끝낸다. 한 창에서 가는 승인 요청 알림은 많아야 두 통이다.
  (강제 위치: DB — 승인 요청을 만드는 처리가 그 크리에이터의 열린 창을 찾거나 연다. 크리에이터마다 열린 창은 하나(유일 제약) — 결제 둘이
  동시에 끝나도 창은 하나이고, 창을 연 쪽만 ①의 줄을, 진 쪽은 쌓인 표시만 남긴다 / 자동 처리 — 끝난 창에 쌓인 것이 있으면 ③의 줄 하나 /
  서버 보내는 일꾼 — 보내기 직전 대기 건수를 다시 읽음)
  위반 시: 한꺼번에 여러 건이 오면 알림이 건마다 쏟아진다. 창이 둘 열려 첫 통이 두 번 간다. 창 안에 온 요청을 크리에이터가 끝 통 없이 모른 채 지나친다.
  건수를 창이 열릴 때 세면 그 뒤 들어온 요청이 빠진 수가 간다.

- INV-NB2: 승인 재알림(approval_reminder) — 대기 중인 요청이 결제 완료 시각부터 72시간(3일째)·144시간(6일째)이 되면 바로 간다(「알림톡 규칙 확정」 3).
  재알림은 창을 열지 않는다. 그 크리에이터에게 열린 창이 있으면(10분 안에 승인 요청 알림이 이미 갔다) 재알림은 보내지 않고 건너뜀으로 끝낸다. 본문의 일수는 보내는 순간 대기 건 가운데 **가장 빨리 자동 반려될 건**의 반려까지
  남은 시간을 하루 단위로 올린 값이다(최소 1 — 2026-10-30 질문 답). 「상자가 처음 입고될 때」 재알림은 없어진다(notifications INV-N8 의 둘째 차례).
  7일 자동 반려 기준(결제 완료 시각부터 168시간)은 알림 때문에 늘지 않고, 주말·공휴일도 그대로 센다.
  (강제 위치: DB 자동 처리 — 72·144시간이 된 대기 요청마다 줄 하나(요청·차례마다 한 번), 그 크리에이터의 창이 재알림 시각을 덮고 있으면 만들지 않음 /
  보내기 직전 — 요청이 대기인지·창이 열려 있는지 다시 보고, 가장 이른 반려 시각을 다시 읽음)
  위반 시: 이미 처리한 요청 때문에 재알림이 간다. 일수가 가장 급한 건이 아닌 건 기준이라 내일 반려될 선물을 「4일 뒤」로 알린다. 같은 차례 재알림이 자동 처리 때마다 새로 생긴다.

- INV-NB3: 승인 요청·승인 재알림 본문에는 주문번호가 없고 **승인 대기 건수**, 재알림에 한해 **남은 일수**만 더 들어간다. 하루 묶음에는 받는 사람의 닉네임과
  **소식 건수**, 선물 목록 경로만 들어간다 — 어느 선물의 무슨 소식인지는 넣지 않는다. 보낸 팬 닉네임·선물 종류·개수·주소·상대방 이름은 어느 쪽에도 없다
  (notifications INV-N1 의 금지 목록 그대로).
  (강제 위치: 서버 — 종류별 본문 틀의 인자 목록)
  위반 시: 묶음 알림 한 통에 여러 선물의 정보가 모여 잠금 화면에 「누가 무엇을」이 더 많이 남는다.

- INV-NB4: 승인 요청·승인 재알림의 링크는 특정 주문이 아니라 승인 대기 목록(`/creator/actions`)이다(「알림톡 규칙 확정」 4 — 지금은 `?order=주문번호`).
  목록은 맨 위에 새 요청, 그 아래 밀린 건을 오래된 순으로 놓고, 반려가 가까운 건에는 남은 날짜를 보이며, 한 건씩 열어 승인·거절한다.
  목록의 순서·표시는 action-center INV-J5 와 UX 명세 creator-actions 를 그때 고쳐 정한다(이 문서는 링크가 목록으로 간다는 것만 정한다).
  (강제 위치: 서버 — 본문 틀의 링크 / 화면 — 처리할 일의 승인 요청 줄 순서)
  위반 시: 여러 건을 묶은 알림이 그중 한 주문만 열어, 나머지 건을 크리에이터가 못 보고 지나친다.

- INV-NB5: 상태 알림 다섯 — 상자 도착(box_arrived)·출고(shipped)·배송중(in_transit)·수령(delivered)·답장(gift_reply) — 은 기본이 하루 한 번 묶음이다(「알림톡 규칙 확정」 5).
  받는 사람 각자(팬·크리에이터)의 알림 설정에 「바로 받기」 칸이 있고 기본값은 꺼짐이다(2026-10-30 질문 답).
  ① 「바로 받기」가 켜진 사람에게는 지금처럼 사건마다 그 종류의 알림이 간다.
  ② 꺼진 사람에게는 사건마다 가지 않고, 매일 오후 7시(서울 시간 — 2026-10-30 질문 답)에 직전 묶음 뒤 생긴 다섯 종류 소식을 한 통(status_digest)으로 보낸다.
  링크는 팬 `/gifts`, 크리에이터 `/creator/actions`. 소식이 0건이면 보내지 않는다. 계정마다 하루 묶음 줄은 하나다(계정 + 날짜).
  ③ 「바로 받기」는 **사건이 생기는 순간** 읽어, 그 소식을 사건 알림 줄로 넣을지 묶음 대기로 넣을지 그때 정한다. 묶음 대기로 들어간 소식은 그 뒤
  「바로 받기」를 켜도 묶음으로 가고, 사건 알림 줄로 들어간 소식은 그 뒤 꺼도 그대로 간다 — 같은 소식이 두 번 가지 않는다.
  ④ 카카오·이메일 칸(notifications INV-N6)은 그대로 따른다 — 칸을 끈 통로로는 묶음도 가지 않는다. 다섯 종류 밖의 알림(꼭 가는 알림, 입고·검수 끝, 받았다고 확인됐어요)은 묶지 않는다.
  (강제 위치: DB — 상태 알림 다섯이 생기는 처리가 「바로 받기」를 그 순간 읽어 사건 알림 줄 또는 묶음 대기 하나로 / 하루 한 번 자동 처리가 계정 + 날짜마다 묶음 줄 하나를 만듦 /
  화면 — 내 정보·크리에이터 계정 설정의 알림 칸, my-account INV-A11 이 두 칸에서 세 칸으로)
  위반 시: 바로 받기를 끈 사람에게 하루 종일 알림이 간다. 같은 소식이 사건 알림과 묶음으로 두 번 간다. 오후 7시 묶음이 여러 통 간다.

## 시나리오

- S1 (INV-NB1): Given 대기 0건인 하루에게 0분·3분·6분에 결제 셋 / When 일꾼 / Then 0분에 「승인 대기 1건」이 바로 가고, 3분·6분에는 가지 않으며, 10분에 「승인 대기 3건」이 한 통 더 간다.
- S1b (INV-NB1): Given 하루에게 0분에 결제 하나뿐 / When 10분에 창이 끝남 / Then 쌓인 것이 없어 더 보내지 않는다. 12분에 온 결제는 새 창을 열고 바로 「승인 대기 2건」(앞 건이 아직 대기면).
- S1c (INV-NB1, 실패경로): Given 하루에게 결제 둘이 동시에 끝남 / When 둘 다 창을 찾거나 엶 / Then 열린 창은 하나, 바로 가는 통도 하나다. 다른 하나는 쌓여 창 끝에 간다.
- S1d (INV-NB1, 실패경로): Given 0분·3분에 결제, 9분에 하루가 둘 다 처리 / When 10분에 창이 끝남 / Then 대기 0건이라 끝 통은 건너뜀.
- S2 (INV-NB2): Given 결제 완료 + 72시간, 승인 요청 대기 / When 자동 처리 / Then 그 크리에이터에게 재알림 창 1개. 자동 처리를 두 번 돌려도 1개. 144시간에도 같다.
- S2b (INV-NB2): Given 결제 완료 + 71시간 59분 / When 자동 처리 / Then 재알림 창 없음. 첫 상자가 입고돼도 재알림 창 없음.
- S2c (INV-NB2): Given 대기 셋 중 하나가 남은 20시간 / When 재알림이 나감 / Then 「승인 대기 3건, 1일 뒤 자동 반려」.
- S2d (INV-NB2): Given 5분 전에 새 요청으로 창이 열림 / When 다른 대기 건이 72시간이 됨 / Then 재알림은 건너뜀. 창이 없을 때는 바로 가고, 창을 열지 않는다.
- S3 (INV-NB3): Given 별빛이 하루에게 상자 2개를 결제 / When 승인 요청 본문 / Then 건수와 [승인 화면 열기]만 있고 주문번호·「별빛」·선물 종류·개수가 없다.
- S4 (INV-NB4): Given 승인 요청 알림 링크 / When 하루가 엶 / Then 처리할 일의 승인 대기 목록이 열리고, 어느 창도 저절로 열리지 않는다.
- S5 (INV-NB5): Given 별빛의 「바로 받기」 꺼짐, 오늘 출고 1·답장 1 / When 오후 7시 자동 처리와 일꾼 / Then 하루 묶음 한 통, 건수 2. 출고·답장 사건 알림은 가지 않는다.
- S5b (INV-NB5): Given 별빛의 「바로 받기」 켜짐 / When 출고 사건 / Then 출고 알림이 바로 가고, 오후 7시 묶음에 들어가지 않는다.
- S5c (INV-NB5, 실패경로): Given 오늘 소식 0건 / When 오후 7시 / Then 묶음 줄 없음. 자동 처리를 두 번 돌려도 계정마다 묶음 줄은 하나.
- S5d (INV-NB5, 실패경로): Given 오후 3시 출고(바로 받기 꺼짐), 오후 5시에 바로 받기를 켬 / When 오후 7시 / Then 그 출고는 묶음으로 한 번만 간다. 반대로 바로 받기를 켠 채 생긴 출고는 그 뒤 꺼도 사건 알림으로 한 번만 간다.
- S5e (INV-NB5): Given 별빛의 이메일 칸 꺼짐, 카카오 칸 켜짐 / When 오후 7시 / Then 묶음은 카카오로만.

# 크리에이터 본인 확인 스펙

크리에이터로 가입한 계정이 자기 채널의 주인인지 확인하는 기능이다. 방송인만이 아니라 크리에이터라면 누구나 받는다.

**기본 방법은 팬꾹 링크 게시 확인이다(2026-11-02).** 크리에이터가 자기 팬꾹 링크(`fankkuk.com/<링크용 아이디>`)를 자기 채널의 소개·프로필 링크 칸에 올리고
채널 주소로 「확인 요청」을 낸다. 운영자가 그 채널의 공개 페이지를 열어 **채널 이름이 가입 때 적은 채널 이름과 같고 팬꾹 링크가 걸려 있으면** 승인한다(INV-V17·V18).
채널 주인만 그 칸을 고칠 수 있으니, 그 칸에 이 계정의 팬꾹 링크가 있다는 것이 채널 주인이라는 증거다. 링크용 아이디는 플랫폼 아이디와 같을 필요가 없다.
올리는 것이 팬에게 쓸모 있는 링크라 확인 뒤에도 내릴 이유가 없고, 그래서 90일마다 「아직 있는지」로 다시 확인한다(INV-V20).
화면 안내 문구(사용자 지정): 「팬이 선물을 보낼 수 있게 팬꾹 링크를 채널 소개에 올려 주세요. 올라와 있으면 채널 확인도 같이 끝나요.」

| 방법 | 누가 판정 | 어디 |
|---|---|---|
| **팬꾹 링크 게시 확인(기본)** | 운영자가 공개 페이지를 열어 본다 | 모든 「받음」 플랫폼 |
| 치지직 로그인 확인(보조 ①) | 서버가 치지직 공식 API 에 묻는다(INV-V14) | 치지직. DB 처리는 있고 **실제 치지직 연결은 아직 없다** — 로컬·시험 사이트의 가짜 창구만 있다 |
| 운영자 1:1(보조 ②) | 운영자 | 어디든 |

인증 코드를 채널에 붙이는 방식(옛 INV-V3)과 소개란 코드 자동 확인(옛 INV-V16)은 없앴다. 공개 페이지에서 링크를 서버가 자동으로 찾는 기능은 2차다 —
그때도 판정 규칙은 INV-V18 하나를 쓴다.

한 계정이 같은 채널로 낼 수 있는 확인 요청은 10번까지다(INV-V15). 플랫폼 로그인 연결은 외부 연결 때 붙인다 —
그때까지 로컬에서는 가짜 창구(운영에서는 없음, 시험 사이트는 예외 — test-site INV-TS2)로 흐름을 끝까지 돌린다.

승인되면 그 크리에이터는 크리에이터 찾기에 나오고 선물·팔로우를 받는다. 승인 **취소**는 이미 있는 기능이다(INV-K10).

어기면 생기는 사고는 다섯이다.
- 남의 채널 주소로 확인을 받으면, 유명 크리에이터를 사칭한 계정이 팬의 선물을 받는다. 팬은 그 계정으로 선물을 보내고
  승인 서명이 끝나면 물건이 사칭한 사람에게 간다.
- 같은 채널로 두 계정이 승인되면, 팬이 찾기에서 같은 채널 둘을 보고 어느 쪽이 진짜인지 모른다.
- 운영자가 엉뚱한 링크(도메인만·남의 아이디·묶인 옛 아이디)를 보고 승인하면, 채널 주인이 아니어도 만들 수 있는 증거로 확인이 난다(INV-V17·V18).
- 확인 뒤 채널이 넘어가거나 링크를 내렸는데 확인된 채널로 남으면, 팬이 지금 주인이 아닌 계정에 선물을 보낸다(INV-V20).
- 사칭하려는 계정이 같은 채널로 신청을 끝없이 되풀이하면, 한 채널 한 명 규칙(INV-V8) 때문에 진짜 주인이 계속 막힌다.

용어
- **확인 요청(신청)**: 크리에이터 계정 하나가 채널 주소 하나로 확인을 요청한 기록. 그때의 링크용 아이디를 같이 적는다(INV-V17). 상태는 다음과 같다.
  - **확인 대기(올림)**: 요청이 만들어진 상태 — 만들어질 때 바로 이 상태다. 운영자 확인을 기다리고, 기한이 없다(INV-V5).
  - **승인됨** · **반려됨** · **거둠**(크리에이터가 요청을 거둔 것) ·
    **닫힘**(다른 계정이 플랫폼 로그인으로 같은 채널을 확인해 끝난 것, INV-V14 — 또는 2026-11-02 확인 방식을 바꾸며 닫은 옛 코드 신청).
  - 옛 코드 신청에만 있던 상태: **코드 받음**·**기간 지남**. 새 요청에는 없다.
  - **살아 있는 요청** = 확인 대기.
- **팬꾹 링크**: `<사이트 주소>/<링크용 아이디>` — 그 크리에이터의 공개 페이지 주소(creator-link). 확인에 쓰는 것은 요청 줄에 적힌 아이디로 만든 링크다.
- **재확인**: 승인된 크리에이터의 채널에 팬꾹 링크가 아직 있는지 운영자가 다시 보는 일(INV-V20). **마지막 확인 시각**은 승인 또는 지난 재확인 「링크 있음」의 시각.
- **유예**: 재확인에서 「링크 없음」이 나온 뒤 14일. 그동안 확인됨과 선물 받기는 그대로다.
- **채널 키**: 서버가 채널 주소에서 뽑은 (플랫폼, 채널 식별자) 한 쌍. 주소 표기가 달라도 같은 채널이면 같은 키다(INV-V2).
- **채널 점유**: 한 채널 키를 지금 누가 쥐고 있는지. 살아 있는 신청이나 확인된 크리에이터가 쥔다(INV-V8).
- **확인됨**: 크리에이터 공개 정보의 본인 확인 칸이 참인 상태. 찾기·팔로우·선물 등록은 이미 이 칸으로 거른다.
- **운영자**: 관리자 화면에 들어오는 계정(대표·직원). admin-console 의 운영자 판정을 그대로 쓴다.

## 불변식

- INV-V1: 확인 요청은 크리에이터 역할 계정이 자기 자신에 대해서만 한다. 요청에 담기는 것은 채널 주소 하나뿐이다 — 이름·채널 이름·분야 같은
  기본 공개 정보는 가입 때 받아 둔 것을 쓴다. 누구의 신청인지는 로그인 토큰이 확인한 사람(INV-L2)으로 서버가 정한다.
  브라우저가 계정·크리에이터 식별값을 보내도 쓰지 않는다. 팬·운영자·로그인하지 않은 사람의 신청은 거부한다.
  (강제 위치: DB 신청 함수 — 인자는 채널 주소 하나, 진입부에서 auth.uid() 의 역할이 크리에이터인지 확인)
  위반 시: 팬 계정이나 다른 크리에이터 계정 이름으로 신청이 생겨, 승인되면 엉뚱한 계정이 확인된 크리에이터가 된다.

- INV-V2: 채널 주소는 서버가 형식을 검사한다. 신청을 받는 플랫폼은 아래 표에서 「받음」인 것뿐이고, 플랫폼마다 받는 주소 꼴과 채널 키 규칙이 정해져 있다.
  공통 규칙: `https` 만 받는다. 쿼리(`?…`)·조각(`#…`)·끝의 `/` 는 버린다. `www.`·`m.` 이 붙거나 빠져도 같은 호스트로 본다.
  저장하는 주소는 **브라우저가 보낸 문자열이 아니라 서버가 채널 키로 다시 만든 주소**다. 목록 밖의 호스트, 아래 꼴이 아닌 경로는 거부한다.
  「받지 않음」 플랫폼과 목록 밖 플랫폼의 주소는 「1:1 문의로 알려 주세요」로 거부한다 — 운영자가 그 플랫폼의 규칙을 이 표에 더하기 전까지 신청할 수 없다.

- 믿는 값: 로그인 토큰이 확인한 사람(INV-L2)과 그 계정의 역할 칸, DB 의 운영자 판정, 서버가 만든 채널 키, 요청 때 DB 가 적은 링크용 아이디,

# 회원가입 스펙

가입은 세 단계다 — 팬·크리에이터 고르기, 아이디·이메일·비밀번호·휴대폰 번호 입력, 카카오톡 본인 확인.
본인 확인이 끝나면 계정이 만들어지고 바로 로그인된 상태로 메인으로 간다.

이 스펙이 막는 사고는 **확인하지 않은 번호로 계정이 생기는 것**이다. 휴대폰 번호는 선물 소식 알림톡이 가는 곳이라,
남의 번호로 가입되면 그 사람에게 내 선물 소식이 가고, 진짜 주인은 그 번호로 가입하지 못한다.
본인 확인 결과는 브라우저가 아니라 서버가 카카오에게 직접 물어서 얻은 것만 믿는다.

카카오 인증 연결은 아직 없다. 연결 전까지 로컬에서는 **가짜 본인 확인**(버튼을 누르면 바로 확인됨)으로 대신하고,
운영에서는 가입을 받지 않는다(INV-U9).

## 불변식

- INV-U1: 계정은 서버가 카카오에게 직접 확인한 휴대폰 번호로만 만들어진다. 가입 요청에는 본인 확인 번호표(서버가 발급한 ID)만
  실어 보내고, 서버는 그 번호표로 DB 에 저장된 확인 결과를 찾아 쓴다. 확인 결과의 번호와 가입 입력의 번호가 다르면 거부한다.
  브라우저가 보낸 「인증 완료」 표시·번호·이름은 판단에 쓰지 않는다. (강제 위치: 서버 — 가입 처리, DB — 계정 만들기 함수)
  위반 시: 브라우저에서 「인증 완료」만 꾸며 보내 남의 번호로 가입한다.

- INV-U2: 본인 확인 한 건은 가입 한 번에만 쓰이고, 확인된 때부터 10분이 지나면 쓸 수 없다. 같은 번호표로 동시에 두 가입이
  와도 계정은 하나만 생긴다. (강제 위치: DB — 계정 만들기 함수가 확인 줄을 잠그고 「쓴 시각」을 채운다)
  위반 시: 한 번 받은 확인으로 계정을 여러 개 만든다.

- INV-U3: 휴대폰 번호 하나에 계정 하나다. 아이디도 계정마다 다르다. 같은 번호나 같은 아이디로 동시에 두 가입이 와도
  하나만 성공한다. (강제 위치: DB — 유일 제약)
  위반 시: 한 사람이 계정을 여럿 만들어 차단을 피하거나, 알림톡이 어느 계정 것인지 섞인다.

- INV-U4: 계정 하나는 한 번에 만들어진다 — 로그인 정보·프로필·연락처 줄(휴대폰, 확인 대기 이메일, 알림 기본값)·약관 동의 기록.
  어느 하나라도 실패하면 아무것도 남지 않고, 본인 확인도 쓰지 않은 상태로 남는다. (강제 위치: DB 함수 한 트랜잭션 +
  서버 — 로그인 정보는 Supabase Auth 에 따로 만들므로, DB 쪽이 실패하면 방금 만든 로그인 정보를 지운다)
  위반 시: 로그인은 되는데 프로필이 없는 계정, 또는 연락처 줄이 없어 알림이 안 가는 계정이 생긴다.

- INV-U5: 역할은 가입 때 팬·크리에이터 둘 중 하나만 고른다. 그 밖의 값(운영자 등)이 오면 거부한다. 크리에이터로 가입해도
  방송 채널 인증 전에는 크리에이터 찾기에 나오지 않고 승인 요청도 받지 않는다. (강제 위치: 서버 입력 검사 + DB 함수)
  위반 시: 가입만으로 운영자가 되거나, 채널 주인이 아닌 사람이 크리에이터로 선물을 받는다.

- INV-U6: 입력 경계 — 아이디는 소문자·숫자·밑줄 4~20자(`withdrawn_` 로 시작하는 아이디는 탈퇴 처리가 쓰므로 받지 않고 이미 쓰는 아이디로 알린다 — DB 도 탈퇴하지 않은 계정에는 막는다), 비밀번호는 8~72자이고 영문·숫자·특수문자(영문·숫자가 아닌 글자) 가운데 3종류 이상을 섞어야 하며 아이디와 같을 수 없다, 이메일은 내 정보와 같은
  꼴(INV-A5), 휴대폰은 `01` 로 시작하는 10~11자리 숫자, 필수 약관 둘(이용약관·개인정보 수집·이용)에 동의해야 한다.
  동의는 약관 이름·판 번호·동의 시각으로 남긴다. (강제 위치: 서버 입력 검사, DB 제약)
  위반 시: 짧은 비밀번호로 계정이 털리거나, 동의하지 않은 사람의 개인정보를 받는다.

- INV-U7: 가입 때 적은 이메일은 확인 대기로만 저장되고 확인 메일이 간다(내 정보 INV-A7·A8 과 같은 방식·같은 한도).
  링크를 누르기 전에는 그 주소로 선물 소식이 가지 않는다. (강제 위치: DB — 계정 만들기 함수, 메일 보내기는 내 정보와 같은 길)
  위반 시: 남의 이메일을 적어 그 사람에게 선물 소식이 간다.

- INV-U8: 운영 계정의 로그인 주소는 `<아이디>@login.fankkuk.invalid` 다 — 실제로 메일이 갈 수 없는 예약 도메인이고,
  사용자가 적은 이메일과 상관없다. 운영에서는 아이디를 이 주소로만 바꿔 로그인한다. 시험 계정 주소(`@fankkuk.test`)는
  로컬에서만 시도한다(INV-L6 은 그대로). (강제 위치: 서버 — 로그인·가입 처리)
  위반 시: 사용자의 실제 이메일이 로그인 주소가 되어, 이메일을 바꿀 때 로그인이 깨지거나 주소로 계정 존재가 드러난다.

- INV-U9: 가짜 본인 확인은 운영에서 켜질 수 없다. 운영 환경에서는 실제 카카오 연결 설정이 없으면 본인 확인 요청과 가입을
  모두 거부한다(조용히 가짜로 넘어가지 않는다). 예외는 시험 사이트 하나뿐이다 — 판정 조건은 test-site INV-TS1 이 정한다.
  (강제 위치: 서버 — 본인 확인 제공자 고르는 곳 하나)
  위반 시: 운영 사이트에서 아무 번호로나 가입된다.

- INV-U10: 본인 확인 요청은 한 번호에 한 시간 다섯 번까지다. 넘으면 카카오를 부르지 않고 거부한다.
  (강제 위치: DB — 요청 기록 개수 확인과 기록을 한 번에, 행 잠금)
  위반 시: 남의 번호로 인증 요청을 계속 보내 괴롭히거나, 건당 비용이 드는 카카오 호출이 쌓인다.

- INV-U11: 가입 응답은 실패 이유를 칸 단위로만 알려 준다 — 「이미 쓰는 아이디」, 「이미 가입된 번호」. 번호 중복은
  본인 확인을 마친 뒤에만 알려 준다. 가입 응답·화면은 캐시되지 않고, 가입은 같은 사이트의 JSON 요청만 받는다.
  (강제 위치: 서버 — 가입 처리)
  위반 시: 본인 확인 없이 번호만 넣어 보며 누가 가입했는지 알아낸다.

- INV-U12: 휴대폰 번호 바꾸기는 로그인한 사람(session-login INV-L2) 자신의 번호만 바꾸고, 새 번호에 대한 카카오 본인 확인을 다시 받아야 한다. 가입과 같은 규칙을 쓴다 —
  서버가 직접 확인한 번호만(INV-U1), 확인 한 건은 한 번·10분 안에만(INV-U2), 번호 하나에 계정 하나(INV-U3), 요청 횟수 한도(INV-U10), 운영에서 카카오 연결 전에는 거부(INV-U9).
  확인 결과의 번호와 바꿀 번호가 다르면 거부한다. 다른 계정이 쓰는 번호면 본인 확인을 마친 뒤에만 「이미 가입된 번호」라고 알려 준다(INV-U11).
  지금 비밀번호도 함께 받아 맞을 때만 바꾼다 — 카카오 확인은 「새 번호가 바꾸는 사람 것」만 증명하므로, 세션만 빼앗은 사람이 자기 번호로 확인받아 바꾸는 것을 막는다.
  바뀌는 것은 연락처 줄의 번호 하나이고, 바꿀 때마다 누가·언제 바꿨는지 한 줄 남기며 그 기록에는 번호 값이 없다(주소 등록 기록 address-protection INV-P13 과 같은 방식).
  (강제 위치: 서버 — 번호 바꾸기 처리, 본인 확인 제공자 고르는 곳 하나 / DB 함수 — 확인 줄 잠금·사용 표시·번호 바꾸기를 한 처리에서, 번호 유일 제약)
  위반 시: 세션만 빼앗은 사람이 번호를 자기 것으로 바꿔 알림톡을 가로챈다. 같은 번호가 두 계정에 붙어 알림이 섞인다.

- INV-U13: 가입 때 닉네임을 받는다 — 앞뒤 공백을 뺀 1~12자(내 정보 INV-A5 와 같은 경계), 태그·팬덤 이름과 같은 금칙어·연락처 필터를 거친다.
  닉네임은 계정마다 다르다 — 앞뒤 공백을 빼고 영문 대소문자를 구분하지 않고 비교한다. 같은 닉네임으로 동시에 두 가입(또는 내 정보에서 바꾸기)이 와도
  하나만 성공하고, 진 쪽은 「이미 쓰는 닉네임」(칸 단위, INV-U11)을 받는다. 내 정보에서 닉네임을 바꿀 때도 같은 규칙이다.
  탈퇴해 가명 처리된 계정(my-account INV-A15)은 모두 「탈퇴한 회원」이라 이 비교에서 빠지고, 그 대신 「탈퇴한 회원」은 회원이 쓸 수 없다.
  (강제 위치: 서버 입력 검사 + DB — 닉네임 비교 값의 유일 제약, 필터는 DB 함수)
  위반 시: 같은 닉네임 두 사람이 승인 요청·답장에서 구분되지 않아 크리에이터가 엉뚱한 팬에게 답하거나 사칭이 된다.

- INV-U14: 가입 화면은 아이디·닉네임을 제출 전에 미리 확인할 수 있다. 답은 셋뿐이다 — 「쓸 수 있어요」·「이미 쓰고 있어요」·「형식이 맞지 않아요」.
  누구의 계정인지·언제 가입했는지 같은 다른 정보는 주지 않는다. 미리 확인은 안내일 뿐이고, 최종 판정은 가입 때 INV-U3·U13 제약이 한다
  (확인과 제출 사이에 남이 먼저 가져가면 가입이 「이미 쓰는」으로 거부된다).
  한 접속 주소(IP)에서 1분에 30번을 넘으면 1분 동안 「잠시 뒤에 다시 확인해 주세요」로만 답하고 DB 를 찾지 않는다(IPv6 는 주소 하나가 아니라 앞 64비트 대역 단위로 센다).
  형식이 틀린 값은 한도와 상관없이 DB 를 찾지 않고 「형식이 맞지 않아요」로 답한다 — DB 를 부르지 않으니 긁는 데 쓸 수 없다. 접속 주소는 원문이 아니라
  비밀 값을 섞은 해시로만 잠깐 센다. 응답은 캐시되지 않고 같은 사이트 요청만 받는다(INV-U11 과 같음).
  (강제 위치: 서버 — 확인 처리와 횟수 한도, DB — 존재 여부만 돌려주는 함수, 로그인 없이 부를 수 있되 개인정보 구역에 닿지 않는다)
  위반 시: 아이디 목록을 대량으로 긁어 로그인 공격 대상을 고르거나, 확인 요청만으로 DB 를 몰아붙인다.

## 시나리오

- S1 (INV-U1): Given 010-1234-5678 로 본인 확인 완료 / When 같은 번호로 가입 / Then 계정이 생기고 연락처 줄의 번호가 그 번호다.
- S1b (INV-U1, 실패경로): Given 010-1234-5678 로 확인 / When 가입 입력 번호를 010-9999-0000 으로 바꿔 보냄 / Then 거부, 계정 없음.
- S1c (INV-U1, 실패경로): Given 본인 확인 안 함 / When 없는 번호표·남이 받은 번호표로 가입 / Then 거부.
- S2 (INV-U2, 실패경로): Given 확인 한 건으로 가입 성공 / When 같은 번호표로 다시 가입 / Then 거부.
- S2b (INV-U2, 실패경로): Given 확인 후 11분 / When 가입 / Then 거부.
- S2c (INV-U2, 동시): Given 확인 한 건 / When 같은 번호표로 가입 둘을 동시에 / Then 하나만 성공.
- S3 (INV-U3, 실패경로): Given 그 번호로 이미 계정이 있음 / When 새로 확인받고 가입 / Then 「이미 가입된 번호」, 계정 하나 그대로.
- S3b (INV-U3, 동시): Given 같은 아이디로 가입 둘을 동시에 / Then 하나만 성공.
- S4 (INV-U4, 실패경로): Given 계정 만들기 중간(연락처 줄)에서 실패하게 만든 상태 / When 가입 / Then 로그인 정보·프로필 모두 없고 확인은 미사용.
- S5 (INV-U5, 실패경로): Given 역할 값 `admin` / When 가입 / Then 거부.
- S5b (INV-U5): Given 크리에이터로 가입 / When 크리에이터 찾기 / Then 나오지 않는다.
- S6 (INV-U6, 실패경로): Given 7자 비밀번호·두 종류만 섞은 8자 이상 비밀번호(`abcdefgh1`)·아이디와 같은 비밀번호·필수 약관 하나 빠짐 / When 가입 / Then 각각 거부.
- S6b (INV-U6): Given 세 종류를 섞은 8자 비밀번호(`abc12!@#`)·72자 비밀번호 / When 가입 / Then 받는다.
- S7 (INV-U7): Given 가입 완료 / When 연락처 줄을 봄 / Then 이메일은 비어 있고 확인 대기 칸에 적은 주소, 확인 메일 한 통.
- S8 (INV-U8): Given 운영 환경 / When `newfan` 으로 로그인 / Then `newfan@login.fankkuk.invalid` 로만 시도한다.
- S9 (INV-U9, 실패경로): Given 운영 환경(시험 사이트 아님), 카카오 설정 없음 / When 본인 확인 요청 / Then 거부, 가짜로 넘어가지 않음.
- S10 (INV-U10, 실패경로): Given 한 번호로 한 시간에 다섯 번 요청 / When 여섯 번째 / Then 거부, 카카오 호출 없음.
- S11 (INV-U11, 실패경로): Given 본인 확인 안 함 / When 가입된 번호로 가입 / Then 응답이 「본인 확인 필요」뿐, 가입 여부를 알 수 없다.
- S12 (INV-U12): Given 별빛이 010-2222-3333 으로 본인 확인, 지금 비밀번호 맞음 / When 그 번호로 바꾸기 / Then 연락처 줄의 번호가 바뀌고 기록 한 줄(번호 값 없음).
- S12b (INV-U12, 실패경로): Given 010-2222-3333 으로 확인 / When 바꿀 번호를 010-9999-0000 으로 보냄 / Then 거부. 이미 쓴 확인·11분 지난 확인·틀린 지금 비밀번호 → 거부. 달토끼 번호로 확인받고 바꾸기 → 「이미 가입된 번호」, 둘 다 그대로. 같은 번호로 두 계정이 동시에 → 하나만.

## 신뢰 경계

- 믿는 값: 서버가 카카오(로컬은 가짜 제공자)에게 직접 받아 DB 에 저장한 확인 결과, DB 의 유일 제약
- 믿지 않는 값: 브라우저가 보낸 인증 완료 표시·번호·이름·역할·약관 판 번호, 가입 화면이 미리 알려 준 「쓸 수 있는 아이디」

## 비범위

- 실제 카카오 인증 연결 — 이용기관 심사 뒤. 연결 전까지 운영 가입은 막혀 있다(INV-U9)
- 크리에이터 방송 채널 인증과 크리에이터 공개 정보(채널·이름) 만들기 — 따로 스펙
- 비밀번호 재설정 — session-login INV-L10·L11. 휴대폰 번호 바꾸기는 이 스펙 INV-U12. 탈퇴 — 따로
- 로그인 시도 횟수 제한 — session-login 비범위 그대로

# 회원가입 스펙

가입은 팬 세 단계, 크리에이터 네 단계다(2026-11-10 — 이전: 크리에이터 다섯 단계). 단계마다 화면이 따로다.
1. 팬·크리에이터 고르기
2. 정보 입력 — 아이디·닉네임·이메일·비밀번호, 「만 14세 이상입니다」, 약관 동의(크리에이터는 공개 정보 칸도)
3. 휴대폰 번호 확인
   - 팬: 문자로 받은 6자리 인증번호를 입력한다. 맞으면 계정이 만들어지고 로그인된다. 팬은 여기서 끝난다.
   - 크리에이터: 이름·생년월일·휴대폰 번호를 적고 그 정보로 대상을 지정한 카카오 인증서 서명을 카카오톡에서 마친다(INV-U19). 서버가 서명 완료를 확인하면
     계정이 만들어지고 로그인되며, 이 서명이 휴대폰 번호 확인과 승인 서명 연결(approval-signature INV-S16)을 함께 끝낸다. 6자리 인증은 하지 않는다.
     서버가 카카오 서명 창구의 장애를 확인했을 때만 6자리 인증으로 가입하는 길이 열리고, 그때 승인 서명 연결은 가입 뒤로 미뤄진다(INV-U20).
4. (크리에이터) 채널 확인 — creator-verification 스펙 그대로. 운영자 확인이 필요한 채널이 있어 「나중에 하기」로 건너뛸 수 있다(확인 전에는 INV-U5 대로 찾기에 나오지 않고 선물도 받지 않는다)
(뺀 단계 — 크리에이터 5단계 「승인 서명 연결하기」는 3단계에 합쳐졌다. 장애 대비 길로 가입한 크리에이터만 가입 뒤 크리에이터 홈·설정에서 연결한다.)
팬에게는 실명·생년월일을 받지 않는다. 크리에이터의 이름·생년월일은 서명 대상 지정에만 쓰고 승인 서명 연결과 같은 봉투 방식으로만 둔다(approval-signature INV-S16) — 계정·프로필에는 들어가지 않는다.

이 스펙이 막는 사고는 **확인하지 않은 번호로 계정이 생기는 것**이다. 휴대폰 번호는 선물 소식 알림톡이 가는 곳이라,
남의 번호로 가입되면 그 사람에게 내 선물 소식이 가고, 진짜 주인은 그 번호로 가입하지 못한다.
번호 확인은 서버가 문자로 보낸 인증번호를 그 사람이 맞혔는지, 또는 (크리에이터) 그 번호로 지정해 보낸 카카오 서명을 서버가 검증했는지로만 판단한다 — 브라우저가 보낸 「확인됨」 표시는 믿지 않는다.

문자 발송 대행사 연결은 아직 없다. 연결 전까지 로컬·시험 사이트는 **가짜 문자 창구**(문자를 실제로 보내지 않고, 인증번호는 언제나 000000)로 대신한다 — 인증번호를 기록에 남기지 않아도 시험할 수 있고, 해시·만료·횟수·한도는 진짜와 같은 길을 지난다. 그리고
운영에서는 가입을 받지 않는다(INV-U9).

## 불변식

- INV-U1: 계정은 서버가 확인한 휴대폰 번호로만 만들어진다. 확인 방법은 둘이다 — ① 서버가 그 번호로 보낸 인증번호를 맞힘(팬, 그리고 INV-U20 의 장애 대비 길로 가는 크리에이터)
  ② 그 번호로 대상을 지정해 보낸 카카오 서명을 서버가 검증함(크리에이터 기본, INV-U19). 아래 번호표 규칙은 둘에 똑같이 적용된다. 인증번호를 맞히면 서버가 DB 의 확인 줄에 「확인됨」을 적고,
  가입 요청에는 번호표(서버가 발급한 ID, 쿠키)만 실어 보낸다. 서버는 그 번호표로 DB 의 확인 결과를 찾아 쓴다. 확인한 번호와 가입 입력의 번호가 다르면 거부한다.
  브라우저가 보낸 「인증 완료」·「서명 완료」 표시·번호·이름은 판단에 쓰지 않는다. 크리에이터는 ①로 가입하려면 그 번호표에 서버가 적은 「창구 장애 확인」(INV-U20)이 있어야 한다 —
  없으면 ①의 확인 결과로는 크리에이터 계정을 만들지 않는다. (강제 위치: 서버 — 인증번호 확인·서명 결과 확인·가입 처리, DB — 확인 함수·계정 만들기 함수)
  위반 시: 브라우저에서 「인증 완료」만 꾸며 보내 남의 번호로 가입한다. 크리에이터가 카카오 서명을 건너뛰고 6자리로 가입해 승인 서명 연결 없는 계정이 늘어난다.

- INV-U2: 본인 확인 한 건(인증번호 확인이든 검증된 카카오 서명이든)은 가입 한 번에만 쓰이고, 확인된 때부터 10분이 지나면 쓸 수 없다. 같은 번호표로 동시에 두 가입이
  와도 계정은 하나만 생긴다. (강제 위치: DB — 계정 만들기 함수가 확인 줄을 잠그고 「쓴 시각」을 채운다)
  위반 시: 한 번 받은 확인으로 계정을 여러 개 만든다.

- INV-U3: 휴대폰 번호 하나에 계정 하나다. 아이디도 계정마다 다르다. 같은 번호나 같은 아이디로 동시에 두 가입이 와도
  하나만 성공한다. 카카오 서명 길(INV-U19)도 같은 유일 제약을 지난다 — 서명에 지정한 번호가 이미 가입된 번호면 서명이 검증돼도 계정·연결 기록이 생기지 않고
  「이미 가입된 번호」(INV-U11)로 답한다. 서명 요청을 보내기 전에는 그 번호가 가입됐는지 알려 주지 않는다. (강제 위치: DB — 유일 제약)
  위반 시: 한 사람이 계정을 여럿 만들어 차단을 피하거나, 알림톡이 어느 계정 것인지 섞인다.

- INV-U4: 계정 하나는 한 번에 만들어진다 — 로그인 정보·프로필·연락처 줄(휴대폰, 확인 대기 이메일, 알림 기본값)·약관 동의 기록(만 14세 확인 포함).
  어느 하나라도 실패하면 아무것도 남지 않고, 본인 확인도 쓰지 않은 상태로 남는다. (강제 위치: DB 함수 한 트랜잭션 +
  서버 — 로그인 정보는 Supabase Auth 에 따로 만들므로, DB 쪽이 실패하면 방금 만든 로그인 정보를 지운다)
  위반 시: 로그인은 되는데 프로필이 없는 계정, 또는 연락처 줄이 없어 알림이 안 가는 계정이 생긴다.

- INV-U5: 역할은 가입 때 팬·크리에이터 둘 중 하나만 고른다. 그 밖의 값(운영자 등)이 오면 거부한다. 크리에이터로 가입해도
  방송 채널 인증 전에는 크리에이터 찾기에 나오지 않고 승인 요청도 받지 않는다. 승인 서명을 연결하기 전에는 선물을 받지 않는다(approval-signature INV-S16) —
  카카오 서명으로 가입한 크리에이터는 가입과 함께 연결돼 있고(INV-U19), 장애 대비 길로 가입한 크리에이터만 연결 전 상태로 시작한다(INV-U20).
  (강제 위치: 서버 입력 검사 + DB 함수)
  위반 시: 가입만으로 운영자가 되거나, 채널 주인이 아닌 사람이 크리에이터로 선물을 받는다.

- INV-U6: 입력 경계 — 아이디는 소문자·숫자·밑줄 4~20자(`withdrawn_` 로 시작하는 아이디는 탈퇴 처리가 쓰므로 받지 않고 이미 쓰는 아이디로 알린다 — DB 도 탈퇴하지 않은 계정에는 막는다), 비밀번호는 8~72자이고 영문·숫자·특수문자(영문·숫자가 아닌 글자) 가운데 3종류 이상을 섞어야 하며 아이디와 같을 수 없다, 이메일은 내 정보와 같은
  꼴(INV-A5), 휴대폰은 `01` 로 시작하는 10~11자리 숫자, 필수 약관 둘(이용약관·개인정보 수집·이용)에 동의해야 한다.

- S12b (INV-U12, 실패경로): Given 010-2222-3333 으로 확인 / When 바꿀 번호를 010-9999-0000 으로 보냄 / Then 거부. 이미 쓴 확인·11분 지난 확인·틀린 지금 비밀번호 → 거부. 달토끼 번호로 확인받고 바꾸기 → 「이미 가입된 번호」, 둘 다 그대로. 같은 번호로 두 계정이 동시에 → 하나만.
- S18 (INV-U18): Given 010-1234-5678 로 가입 / When 연락처 줄을 직접 읽음 / Then 01012345678 이 어느 칸에도 없고, 앞 3자리 010·뒤 4자리 5678 과 암호문·해시만 있다. 서버 모듈로 풀면 01012345678.
- S18b (INV-U18, 실패경로): Given 별빛 줄의 암호문을 달토끼 줄에 옮겨 붙임 / When 달토끼 번호를 풂 / Then 풀리지 않는다(실패, 별빛 번호를 돌려주지 않음). 같은 번호로 두 번째 가입 → 해시 유일 제약으로 「이미 가입된 번호」.
- S18c (INV-U18, 실패경로): Given 암호화 키 없음 / When 가입·번호 바꾸기 / Then 실패, 연락처 줄 안 생김.

- S19 (INV-U19): Given 크리에이터 가입 2단계를 마침 / When 이름·생년월일·010-1234-5678 을 적고 카카오 서명을 마침 → 가입 / Then 계정·연락처 줄(010-1234-5678)·승인 서명 연결 기록이 한 번에 생기고 로그인된다. 6자리 인증번호 요청은 없다. 연결 기록의 세 값은 봉투뿐이다.
- S19b (INV-U19, 실패경로): Given 서명 요청을 보냄 / When 서명 전에 가입 요청, 5분 지나 온 서명, 결과의 이름·생년월일·번호 중 하나가 다름, 브라우저가 「서명 완료」만 꾸며 보냄 / Then 각각 계정·연결 기록 없음.
- S19c (INV-U19, 실패경로): Given 010-1234-5678 로 서명 검증 / When 가입 입력 번호를 010-9999-0000 으로 바꿔 보냄 / Then 거부, 계정 없음.
- S19d (INV-U19·U3, 실패경로): Given 010-1234-5678 로 이미 계정이 있음 / When 그 번호로 서명 요청 / Then 요청은 만들어지고(가입 여부를 알리지 않음), 서명 검증 뒤 가입 → 「이미 가입된 번호」, 계정·연결 기록 그대로 하나.
- S19e (INV-U19, 실패경로): Given 연결 기록 만들기가 실패하게 만든 상태 / When 서명 검증 뒤 가입 / Then 로그인 정보·프로필·연락처 줄 모두 없고 확인은 미사용.
- S19f (INV-U19, 동시): Given 검증된 서명 한 건 / When 같은 번호표로 가입 둘을 동시에 / Then 하나만 성공, 연결 기록 하나.
- S19g (INV-U19, 실패경로): Given 한 번호로 1시간 안에 서명 요청 5번 / When 여섯 번째 / Then 거부, 카카오톡 안 감. 한 IP 하루 20번 뒤 → 거부.
- S20 (INV-U20): Given 게이트웨이가 연결 오류로 두 번 실패 / When 서명 요청 / Then 번호표에 「창구 장애 확인」, 화면은 6자리 인증 길. 인증번호를 맞혀 가입 → 계정은 생기고 연결 기록은 없다, 링크 페이지는 「승인 수단 등록 전」.
- S20b (INV-U20, 실패경로): Given 창구는 정상 / When 크리에이터가 인증번호 요청·확인을 직접 불러 그 번호표로 가입 / Then 거부, 계정 없음.
- S20c (INV-U20, 실패경로): Given 크리에이터가 서명을 거절함 · 5분이 지남 · 운영에 창구 설정 없음 / When 서명 결과 확인 / Then 「창구 장애 확인」 없음 — 앞의 둘은 카카오 서명 다시 요청, 마지막은 크리에이터 가입 거부.

## 신뢰 경계

- 믿는 값: 서버가 보낸 인증번호를 서버가 비교해 DB 에 적은 확인 결과, 서버가 게이트웨이에 직접 조회해 검증한 서명 결과와 「창구 장애 확인」 기록, DB 의 유일 제약
- 믿지 않는 값: 브라우저가 보낸 인증 완료·서명 완료 표시·번호·이름·역할·약관 판 번호, 6자리로 가겠다는 선택, 가입 화면이 미리 알려 준 「쓸 수 있는 아이디」

- 실제 문자 대행사 연결과 발신번호 등록 — 연결 전까지 운영 가입은 막혀 있다(INV-U9, BACKLOG 「출시 전 필수」)
- 승인 서명 연결 자체의 약속(봉투·검증·설정에서 다시 연결) — approval-signature INV-S16. 가입 3단계에서 연결이 함께 끝나는 것은 이 스펙 INV-U19
- 크리에이터 방송 채널 인증과 크리에이터 공개 정보(채널·이름) 만들기 — 따로 스펙
- 비밀번호 재설정 — session-login INV-L10·L11. 휴대폰 번호 바꾸기는 이 스펙 INV-U12. 탈퇴 — 따로
- 로그인 시도 횟수 제한 — session-login 비범위 그대로

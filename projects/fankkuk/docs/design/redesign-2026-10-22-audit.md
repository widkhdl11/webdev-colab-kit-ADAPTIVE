# 화면 진단 — 2026-10-22 (요청: 레이아웃 변주·디테일 마감, 사이트 전체)

> 기준: 요청의 진단 기준 1~13, 설계 원칙 A(레이아웃 변주)·B(디테일 마감). 값의 기준은 `tokens.md` 00절(이번 요청 대조, 승인 전)과 0~5절(승인값).
> 요청이 지정한 ui-ux-pro-max·redesign-existing-projects 스킬은 이 작업 환경에 설치돼 있지 않아, 요청 본문의 기준과 원칙을 그대로 판단 기준으로 썼다.
> **방법이 10-18 진단과 다르다.** 이번에는 실제 화면을 띄워 재지 않았다 — 이 환경에 DB(Supabase 로컬)를 올릴 도구와 디스크가 없다. 대신 화면 44개(운영자 화면 제외)의 page → widget → CSS 를 끝까지 읽어 **구간 순서·열·폭·바탕·누름 반응**을 코드 줄 근거로 뽑았다. 기준 1~11 의 실측 결과는 10-18 진단(`redesign-2026-10-18-audit.md`, 43화면 × 두 폭, 대비 미달·넘침·단계 밖 글자 0)을 출발점으로 쓰고, 그 뒤 바뀐 곳만 다시 봤다.
> 그래서 이 목록의 「지금」 열은 **코드에 적힌 값**이다. 화면에 실제로 그렇게 보이는지는 3단계(수정)에서 화면마다 1440·390 스크린샷으로 다시 확인한다.
> 열: 화면 / 요소 / 기준 / 지금 / 바꿀 값 / 근거. 「표준」 = 업계 기준이 있는 값, 「판단」 = 이 사이트 사정으로 고른 값, 「요청」 = 이번 요청의 원칙 값.

## 먼저 — 한 줄 결론

1. **층 1(기본 규칙)은 10-18 에 대부분 정리됐다.** 남은 것은 폼 오류 표시(기준 8)와 빈 상태 모양(기준 7)이 화면마다 다른 것, 그리고 오류 상자가 정보 상자와 같은 하늘색인 것(아래 A-1).
2. **층 2(레이아웃 단조로움)가 지금 가장 크다.** 로그인 전·후 거의 모든 화면이 「흰 바탕 + 같은 폭 기둥 + 같은 크기 제목」 구간을 간격(48~96)만으로 이어 붙인다. 구간 전환 표시(A-7)가 있는 화면은 랜딩·홈의 첫 화면 띠 하나뿐이다.
3. **층 3(디테일)은 「없다」기보다 「한쪽으로 몰려 있다」.** 카드 그림자를 뺀 것은 10-18 결정(평소 1px 선, 올림 때만 그림자)이라 유지한다. 비어 있는 것은 바탕 그라데이션(B-1)과, `:hover`·`:active` 가 없는 작은 누름 요소 17종(B-4)이다.

## C. 레이아웃 제안 — 기준 12 를 어긴 화면

## D. 판단이 애매했던 것 (승인 때 확인)

1. **크림 바탕을 다시 쓸지** — 2026-10-07 「배경을 하얗게」 이후 넓은 면에 크림이 없다. 요청은 「크림 ↔ 흰색 교대」를 원칙으로 적었다. 시안은 페이지 바탕은 흰색 그대로 두고 구간 띠로만 크림을 썼다(화면 넓이 30% 이하).
2. **좌우 배치** — 이용 방법 4/8, 크리에이터 8+4, 계정 설정 4/8 은 design-rules 0000절 「카드를 왼쪽·오른쪽으로 늘어놓는 구성은 피한다」와 부딪힌다. 요청 A-4(F형)·A-5(비대칭 그리드)는 이것을 권한다. 시안에는 넣었고, 휴대폰(767 이하)에서는 모두 위아래로 쌓인다.
3. **약관 옆 목차** — 880 기둥에서는 PC 에서도 늘 숨는다. 넓히면 공개 폭 880 결정과 부딪히고, 지우면 v26 약관 구성이 바뀐다.
4. **요청의 값 중 결정과 부딪힌 것**(글자 단계·버튼 반경 10·카드 여백 20·섹션 80·최대 1200·카드 모양) — tokens 00-6 대로 결정 쪽 유지.
5. **기준점이 없는 것이 맞는 화면** — 계정 설정·약관 본문처럼 「찾아서 고치는」 화면에 큰 요소를 억지로 넣으면 오히려 방해가 된다. 요청 A-3 의 예외로 둘지.

## 2. 형태 — fanding.kr 의 동글동글함을 따른다 (색·구조는 따르지 않음)

- 카드 반경 12px + 1px 연한 선(`--line`), **그림자 없음**. 그림자는 떠 있는 요소(바텀시트·토스트)에만
- 버튼 반경 = 높이 ÷ 4 (높이 56px → 14px). 알약 버튼 아님
- 배지·칩은 알약형(완전 둥근 끝). 번호·아바타·도장은 정원 — **원을 반복해서 쓰는 것**이 둥근 인상의 핵심
- 아이콘은 통통한 채움형, 옅은 청록 둥근 타일(48px, 반경 12px) 안
- 떠 있는 면(바텀시트 위쪽·모달)은 한 단계 더 둥글게 20px

## 3. 글자

- Pretendard (cdn.jsdelivr.net, 실패 시 시스템 고딕)
- 본문 16px 이상. 16px 미만 글자 없음 (메인 시안 실측)
- 제목은 굵게, 줄 간격 넉넉하게

## 4. 레이아웃

- 모바일 우선 375px 설계, 최대 폭 480px 중앙 정렬. 좌우 여백 16px
- 간격 4px 단위, 짝수 px만
- 여백 위주 — 휴대폰 한 화면에 한 가지. 운영자 작업 화면만 예외로 빽빽하게(그때 별도 기준)

## 5. 무드와 말투

- 플레이풀·귀여움. 단 **두 층**: 일러스트·색·말투는 귀엽게("보내 드려요"), 보안 약속·절차 설명은 또렷하고 차분하게
- 문구 한계: "승인 없이는 저희 시스템이 주소를 열지 않습니다"(참) / "절대 유출되지 않습니다"·"저희도 열 수 없습니다"(쓰지 않음)
- 검수는 "모든 상자의 송장 제거·겉면 검사, 걸린 상자만 개봉" — "모든 상자를 열어"라고 쓰지 않는다
- 경쟁 서비스 이름은 쓰지 않는다

## 6. 아직 정하지 않은 것

- 오류 색 — 지금은 본문색 굵은 글자 + 옅은 살구 원 안의 「!」로 표시한다(색 하나만으로 오류를 알리지 않게). 빨강 계열을 따로 둘지는 오류가 많은 화면(가입·주소 등록)을 만들 때 정한다

- 새 캐릭터(마스코트) — 살구색이 부리 자리로 예약돼 있다. 만들 때 별도 시안
- 로고 확정본 — 지금은 청록 원 안 하트 자리표시

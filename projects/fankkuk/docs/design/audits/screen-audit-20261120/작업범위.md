### 1-1. 운영자 화면 버튼 높이 36(15건)·설명 글자 13px(11건) — 예외로 닫음

승인값을 유지한다. 운영자 화면은 PC에서 마우스로 쓰고, 1023 폭 이하에서는 「PC에서 써 주세요」 안내로 막혀 있다. 26건(S54-4 S55-2 S57-4 S58-3 S59-3 S61-1 S62-1 S63-1 S64-1 S65-1 S66-1 S67-1 S68-1 S69-1 S70-1 S52-2 S53-2 S54-2 S56-2 S59-1 S60-1 S61-2 S62-2 S63-2 S67-2 S70-2)은 이 문서에서 「예외로 닫음」이다.

design-prompt.md 에 넣을 문장 제안(문서는 고치지 않았다):

- **8-12 끝에 덧붙일 문장**: 「예외: 운영자 화면(PC 전용, 1023 이하에서 열리지 않음)은 승인된 관리자 시안 크기(버튼 36 · 작은 버튼 30 · 탭 34 · 입력칸 36)를 쓴다. 마우스로 쓰는 화면이라 높이 44를 덧대지 않는다. [고정] 24×24 는 지킨다.」
- **「충돌 결정」 표에 더할 줄**:

| 무엇 | P1 | P3 | 정한 것 |
|---|---|---|---|
| 운영자 화면의 누르는 칸·설명 글자 | — | — | **승인 관리자 시안 값 유지.** 버튼 36·작은 버튼 30·탭 34·입력칸 36, 설명 글자 13. 누르는 칸 44(8-12)와 「설명 문장 14 이상」은 운영자 화면에 적용하지 않는다. PC 전용이고 휴대폰 폭에서는 화면이 막혀 있기 때문이다(2026-11-20 사용자) |

### 1-2. 추천 크리에이터 큰 카드 — 작은 카드로 변경

- 놓인 곳: 크리에이터 상세(`/creators/[id]`)와 크리에이터 개인 주소 페이지(`/[주소]`, 점검에서는 `/wikdhdl`)의 아래쪽 「추천 크리에이터 둘러보기」. 두 주소가 같은 화면 부품(`src/widgets/creator-profile/ui/creator-profile-page.tsx`)을 연다.
- 판정(8-14): 이 화면의 목적은 그 크리에이터를 보고 선물을 보내는 것이고, 추천은 다른 크리에이터를 보여 주는 보조 영역이다 → **작은 카드로 변경**. 지금은 찾기 화면용 큰 배경 카드(1440에서 배경 349×175)를 쓴다. 11-19에 넣은 8-14 보조 영역 규칙(그림 64 이하 가로형, 높이 88~100)을 따른다.
- design-rules 44절(11-12)의 카드 정의와 부딪히는 부분은 고칠 때 44절에 「보조 영역은 8-14 작은 카드」 한 줄을 더해 맞춘다.
- 아래 2절 「creator-card-recommend」 줄로 넘겼다(딥 QA 전).

### 1-3. 크리에이터 회색 보조 카드의 테두리 — 테두리 제거

- 확인한 세 곳 모두 누를 수 없다(링크·버튼이 아닌 `div`): 승인 내역의 「승인 · 거절 · 기한 만료 · 차단」 숫자 요약 칸, 열람 기록 오른쪽 「주소 열람은 … 최대 3회」 안내 칸, 보낸 역조공 「팬의 주소와 실명은 크리에이터에게 공개되지 않습니다」 안내 칸.
- 판정(4-6): 읽기만 하는 묶음 → **테두리와 그림자 제거, 회색 면만**.
- 같은 테두리 선언이 CSS 파일 9개에 복사돼 있고 크리에이터·팬 화면 13곳이 쓴다. 아래 2절 「gray-sub-card」 줄로 넘겼다(딥 QA 전).

## 작업 중 발견

시안·변경비교를 만드는 중에 새로 보인 문제. 고치지 않고 적기만 한다.

- (creator-card) 찾기 화면이 한 열(휴대폰)일 때 배경 사진이 있는 카드는 배너가 2:1, 없는 카드는 4:1 이라 사진 유무로 카드 높이가 다시 달라진다 — 지금 시험 데이터에는 배경 사진 있는 카드가 없어 드러나지 않았다
- (creator-profile-head) 이름 「하루」가 큰 원형 사진 오른쪽 끝에 거의 붙어 있다(사진 오른쪽 388 · 이름 왼쪽 388, 간격 0) — 사진에 왼쪽 여백 24를 줘서 사진이 칸 사이 간격 24를 다 먹는다. 같은 점검 묶음(S21)에 있던 지적이지만 맡은 변경(요금 줄)이 아니라 고치지 않았다
- (empty-state) /creator/progress 받는 선물 칸 머리의 「받은 선물 전체 ›」와 보내는 선물 칸의 「보낸 내역 전체 ›」 링크가 밑줄 글자인데 홈 요약 칸의 「… 모두 보기 >」와 모양이 다르다
- (empty-state) 보낸 역조공 빈 상태 문구의 「역조공」은 같은 화면 제목·메뉴(「팬에게 보내기」)와 이름이 다르다 — 용어집 대조 필요
- (empty-state) 크리에이터 홈 「진행 중인 선물」 빈 칸에도 다음 행동이 없다(이번 지적 대상 아님)
- (gray-sub-card) 전역 .card--soft·.quote(base.css)도 회색 면에 --hair 1px 선을 붙인다 — 주소 확인 창(return-address-window, 승인 창의 주소 칸)에서 쓰인다. 공용이라 이번에 고치지 않음
- (gray-sub-card) 전역 .okmsg·.sw-row(base.css)도 회색 면 + 1px 선 — 누르지 않는 칸인지 화면별 확인 필요
- (gray-sub-card) design-rules 760행 「회색 보조 칸에도 1px --gray-200」 문장이 이번 판정(테두리 제거)과 반대 — 승인되면 문서도 고쳐야 한다
- (home-intro-banner) 그림 속 문장 「승인한 선물을 검수해 전달해요.」와 대체 글자(alt)·INTRO_BANNER 설명 「승인된 선물을 검수 후 전달합니다.」가 다르다 — 낭독기 사용자와 눈으로 보는 사용자가 다른 문장을 받는다. 그림을 새로 만들 때 문구를 하나로 정해야 한다
- (policy-summary-panel) 요금 안내 「핵심 안내」 판은 줄에 갈 곳(조 링크)이 없어 화살표가 없다 — 점검 shared-files 의 「요금 안내도 같이 걸림」 추정은 실제 화면과 다름(고칠 문제는 아님, 기록만)
- (section-save-bar) 같은 원인 줄의 셋째 지적(바뀐 것이 없을 때 「저장」이 연회색이라 「취소」보다 약해 보임 — .idle)은 이번 「고치면 달라지는 것」에 없어 고치지 않았다
- (section-save-bar) 휴대폰에서 탭 순서는 마크업 순서(취소 → 저장)라 보이는 순서(저장 위, 취소 아래)와 반대다 — PC 「보조 → 주」 순서를 지키려고 마크업은 그대로 뒀다
- (section-save-bar) 프로필 수정 1440 에서 「소개」 판 닉네임 칸 폭(240)과 한 줄 소개 칸(폭 전체)이 다른 것은 8-2 대로라 문제 아님 — 기록만
- (S01-3) 시안 파일은 개발 서버(localhost:3000)가 떠 있어야 일부 이미지가 아닌 링크만 연결됨; 글꼴·이미지는 레포 public 과 CDN 에서 불러 단독으로도 열림(링크 이동만 3000)
- (S02-1) 첫 화면 버튼도 같은 .btn 이라 소개 안에서 모양이 일관됨
- (S05-2) 팬 안내는 조가 길어 끝까지 읽는 사람이 적을 수 있음 — 첫 화면(요약 판 아래)에도 같은 버튼을 둘지는 사용자 판단
- (S06-3) 크리에이터 안내 마지막 조는 「역조공 보내기」라 이미 가입한 사람용 내용 — 끝에 가입 버튼이 어색할 수 있음. 가입 안내 조(첫 부분)가 더 자연스러운지 사용자 판단
- (S10-2) 보내기 버튼이 PC에서 오른쪽 끝에 있어 design-prompt 2-21의 1) 「한 열 폼은 왼쪽 끝」과 다름 — 기존 동작, 이번 범위 밖(제안)
- (S29-3) 시안은 바뀌는 구역만 담았고 크리에이터별 보기 구역은 점선 칸으로 생략했다. 실제 캡처(before)는 main 영역 전체라 그 구역이 보인다.
- (S34-2) 상태 판이 맥락용으로 들어가 있고 바뀌지 않는다. 시안 상자 태그 「입고됨」은 정상 데이터일 때의 모습.
- (S34-2) unchanged 캡처는 별도 비교 쌍이 아니라 입고 전 주문이 그대로임을 보이는 참고 캡처.
- (S36-1) 정책 결정 필요 항목이라 사용자가 A·B·중간안 중 고른 뒤 UX 명세·스펙에 적어야 한다.
- (S36-1) 시안 새 문구는 확인 대기.

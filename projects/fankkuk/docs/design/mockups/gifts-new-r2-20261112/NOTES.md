## 5. 확인 필요 / (가정)
- (가정) `--aside-w: 288px` — 오른쪽 칸 폭 토큰이 없어 지금 구현 값을 변수로. design-rules 「두 단」 칸 280~288. 토큰 추가 제안: `--col-aside: 288px`.
- 컨테이너 쿼리 경계 880·584는 지금 구현과 같은 값. CSS 가 var()를 못 받아 숫자로 적음(폭 토큰이 아니라 전환 경계).
- **구현에 닿는 점**: 단계 판이 지금은 `register-form`(위젯 안 왼쪽 기둥) 안에 있다. 이 시안은 단계 판을 1040 전체 폭으로 올리고 그 아래에 판과 칸을 두므로, 구현 때 단계 판 자리를 위젯(`gift-register-page`)으로 옮기는 구조 변경이 필요하다(화면 동작·입력은 그대로).
- 결제창·상태 카드 화면은 `--col-form`(720) 한 기둥이라 입력 폼 화면(1040)과 제목 왼쪽 시작선이 다르다. 지금 구현도 같다.
- 3단계 설명은 지금 코드 문구 「배송비 포함」 그대로. 명세 「바뀌는 것 4」(배송비→택배비 두 곳)는 코드에 아직 반영되지 않은 것으로 보임 — 문구는 건드리지 않았다.
- 크리에이터 카드 이름·태그·승인 시간, 상자 요금(6,900·8,900·10,900), 결제창 점선 칸(토스 위젯 자리)은 화면 예시 값.
- 명세 상태표에 없는 「미리 고르고 왔는데 아직 팔로우 안 함」(코드의 followFirst 안내 칸)은 그리지 않음.

## 7. 배치 진단 (6-5) — 작업형
① 같은 구조 3번 이상 반복: 1단계 한 줄 한 명 5개 → 2열 카드 격자(1판과 같은 결론). 3단계 상자 칸 3개는 수량 입력이 달린 한 묶음이라 그대로.
② 모든 영역 폭 같음: 해당 없음(단계 판 1040 · 입력 판 720 · 칸 288).
③ 큰 영역 아래 같은 크기만: **해당(2판에서 새로)** — 단계 판을 전체 폭으로 올리자 바로 아래가 입력 판 하나와 칸 하나로 폭이 다름. 문제 없음.
④ 먼저 읽을 영역: 해당 없음(단계 판의 큰 숫자 하나).
⑤ 묶음 안·사이 간격: 해당 없음(카드 안 12·4 / 카드 사이 24, 입력 묶음 안 12 / 사이 32).
⑥ 같은 모양 3곳 이상: 해당 없음(4단계 줄 목록 = 확인 줄·오른쪽 칸 2곳).
이전·다음 위치(점검표 24·25): 이전 왼쪽 끝 · 다음(결제하기) 오른쪽 끝.

## 8. 현재 화면 대비 (14-7)
1) 글자·버튼·사진 지금보다 큼: 없음(휴대폰 단계 판 설명 16 → 14, 제목 24 → 20 으로 오히려 작아짐). 2) 누를 수 없는 묶음의 테두리·그림자: 없음(회색 안내판은 그림자 없이 윤곽선만 — 지금과 같음). 3) 한 줄 칸의 너비·글자·아이콘: 같음. 4) 2열 한쪽만 긺: 오른쪽 칸이 짧지만 따라오는(sticky) 칸이라 빈 면이 아님. 5) 떨어진 정보: 금액은 오른쪽 칸 하나(휴대폰은 결제 칸 안). 6) 모양: 고르는 대상 = 카드, 확인 = 줄 목록, 안내 = 회색 판. 7) 조작 위치: 이전 왼쪽·다음 오른쪽(표준), 합계 줄은 휴대폰 아래 붙음(팬에게 보내기 결제 띠와 같은 방식).

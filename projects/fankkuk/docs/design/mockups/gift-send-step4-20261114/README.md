# 선물 보내기 4단계 · 현재안과 추천안

**[비교 화면 열기](index.html)** — 컴퓨터 1440과 휴대폰 390 캡처를 나란히 비교합니다. 각 그림을 누르면 해당 정적 화면이 열립니다. 현재안은 요청 시점의 구현을 정적 HTML로 옮긴 비교용 재현이며, 운영 화면을 직접 캡처한 것은 아닙니다.

추천안은 기존 작업형 구성을 유지하고, **확인 정보 → 반송 주소 → 반송·환불 안내 → 동의 → 결제** 순서에서 각 묶음이 구분되게 다듬었습니다. 시안 제안만이며 실제 화면이나 승인 기준에 반영하지 않았습니다.

## 바꾼 점과 이유

| 현재 구현과 다른 점 | 이유 | 적용한 디자인 원칙 |
|---|---|---|
| 휴대폰의 확인 정보를 한 열에서 두 열로 배치하고, 수정 버튼은 각 항목에 붙였습니다. | 네 항목을 확인한 뒤 반송 주소로 넘어가는 거리를 줄입니다. 값이 길면 자르지 않고 줄을 바꿉니다. | 1-4, 2-9, 6-5, 14-8 |
| 반송 주소의 칸 폭을 값의 길이에 맞췄습니다: 우편번호 160 · 이름 240 · 휴대폰 번호 200, 주소는 폼 폭 전체. 이름과 휴대폰 번호는 지금처럼 한 줄에 나란히 둡니다(768 이하는 모두 한 줄에 하나, 폭 전체). | 칸 폭으로 입력할 값의 길이를 구분합니다. 2026-11-14 사용자 지적 둘 — 「이름·전화번호 칸은 줄여도」, 「배치는 원래대로, 이름 옆에 전번 칸」. | 2-19, 8-2(칸 폭·짧은 칸 나란히 — 같은 날 추가), design-rules 37·41절 |
| 주소 입력칸 사이 24를 16으로, 주소 묶음과 다른 묶음 사이 24를 32로 바꿨습니다. 입력 완료는 컴퓨터에서 왼쪽, 휴대폰에서 전체 폭입니다. | 같은 작업의 칸들은 가까이 묶고, 입력의 시작과 끝을 구분합니다. | 2-1, 2-2, 2-21 |
| 회색 안내 안의 세 가지 환불 조건을 조건 제목과 결과로 나눴습니다. 검수·개인접수 예외와 승인 정보는 여백으로 분리했습니다. | 조건을 찾아 읽기 쉽게 합니다. 원문의 금액·기한·환불 조건은 모두 유지했습니다. 접거나 숨기는 기능은 없습니다. | 1-8, 3-8, 8-14, 9-1, 13-2 |
| 컴퓨터 요약 칸의 글 정보를 왼쪽 정렬하고 금액은 오른쪽 정렬했습니다. 결제 칸은 하늘 면을 유지하되 효과를 낮추고 동의를 구분선 아래에 묶었습니다. | 이름과 선물 종류는 읽기 쉽게, 금액은 자릿수를 비교하기 쉽게 합니다. 결제 버튼은 기존 위치·크기·문구를 유지합니다. | 1-2, 2-7, 2-18, 4-6, 12-4 |

추천안의 환불 안내는 조건별 여백 때문에 현재안보다 길어질 수 있습니다. 내용을 줄이거나 숨기지 않고 읽는 기준점을 만드는 쪽을 택했습니다. 입력 완료 뒤에는 주소 입력칸이 기존과 같이 완료 문장과 ‘다시 입력’ 버튼으로 바뀝니다.

## 요소와 상태

- 확인 표 네 항목과 수정 버튼, 선택한 경우의 선물 사진·기념일 표시를 유지했습니다.
- 팬의 반송 주소에는 우편번호·주소 검색·기본 주소·상세 주소·받는 사람 이름·휴대폰 번호·입력 완료가 있습니다. 크리에이터 계정 상태에서는 기존 조건대로 이 묶음이 없습니다.
- 주소 입력 전·입력 중·완료·주소 오류·검색 실패·등록 불가·결제 동의 오류·등록 처리 중·등록 실패를 별도 정적 파일로 제공합니다. [비교 화면 아래 상태 목록](index.html)에서 엽니다.
- 주소 검색은 컴퓨터 중앙 창, 휴대폰 하단 창입니다. **기존 주소 검색 서비스를 넣는 자리만 표시**했습니다. 검색 결과나 새 검색 입력을 만들지 않았습니다. 회색 영역의 설명은 시안 검토용 표시이며 제품에 추가할 안내 문구가 아닙니다.
- 휴대폰 번호는 `010-0000-0000` 형태로 표시했습니다. 입력 중 자동 하이픈과 검색·주소 저장·등록·결제는 실행하지 않습니다. 제품 스크립트와 외부 서비스 호출이 없는 정적 시안입니다.
- 반송·환불 조건, 평균 승인 시간, 검수 포함, 배송비 구분, 서비스 제공 기간, 필수 동의 및 규정 링크 셋, 이전·결제 버튼을 유지했습니다.
- 컴퓨터에서는 오른쪽 요약 칸에 금액·합계가 한 번, 좁은 화면에서는 아래 결제 칸에 한 번 나옵니다. 4단계에 휴대폰 고정 합계 줄을 추가하지 않았습니다.
- 로그인 전·팔로우 없음·받기 중지 상태는 4단계 폼에 진입하기 전 상태이므로 이번 4단계 비교 대상 밖입니다. 해당 조건을 바꾸지 않았습니다.

## 명세와 현재 코드의 차이

UX 문서 `gifts-new.md`는 10월 26일 요약 칸 변경을 기록한 문서여서, 오늘 코드의 반송 주소와 최근 문구가 모두 적혀 있지는 않습니다. 이 시안은 명세의 단계·합계 노출 규칙을 유지하면서 사용자가 지정한 최신 코드의 주소 요소와 문구를 함께 담았습니다. 오래된 제목 ‘이럴 때는 돌려보내 드려요’ 대신 현재 구현의 ‘반송·환불 안내’를 사용합니다.

**할증은 4단계 확인 화면에 표시되지 않습니다.** 현재 `register-form.tsx`는 기본 상자 요금 합계를 보이고, 등록 후 `payment-step.tsx`가 서버에서 받은 할증과 결제 금액을 표시합니다. 할증은 크리에이터 주소를 기준으로 결정되므로 팬의 반송 주소에서 할증을 계산하는 화면을 만들지 않았습니다.

- [할증 없는 결제창](checkout-standard.html): 13,800원.
- [할증 있는 결제창](checkout-surcharge.html): 기본 13,800원 + 할증 8,000원 = 21,800원. 할증은 0보다 클 때만 보입니다.
- 외부 결제창의 결제 수단·약관 영역은 회색 대체 영역으로 구분했습니다. 결제사 화면을 임의로 그리거나 서비스 조건을 추가하지 않았습니다.

## 수치와 기준

- 전체 폭 `--col-flow` 1040, 좁은 화면 `--col-form` 720. 오른쪽 요약 폭 288은 design-rules의 두 단 기준과 현재 구현에서 가져왔습니다.
- 요약 노출 경계는 **본문 폭 880**입니다. 이 시안의 사이드바 240과 본문 좌우 여백 32 때문에 화면 폭 1184부터 보입니다. 상단 모바일 막대는 768 이하, 본문 모바일 모양은 767 이하로 현재 구현 경계를 유지합니다.
- 글자·색·간격·반경은 실제 `src/shared/ui/tokens.css`를 복사한 [tokens.css](tokens.css)를 불러옵니다. 새 색·글꼴 체계는 없습니다. 주소 검색 창 뒤 배경도 `--scrim`을 사용합니다.
- 제목 32/24, 단계 제목 24/20, 단계 숫자 48, 본문 16, 안내 14, 합계 32/24. 현재 구현의 같은 역할보다 키우지 않았습니다. 얼굴도 확인 표 32·요약 24 그대로입니다.
- 본문 버튼 48, 수정·단계·정책 링크의 누름 높이 44 이상. 반경은 판 24·안내 16·입력 및 버튼 12입니다.
- 고르기 칩과 플랫폼 뱃지는 4단계에 없으므로 추가하지 않았습니다. 오늘 정한 ‘칩의 보이는 높이 36·누름 높이 44·연회색 테두리’와 ‘플랫폼 뱃지 높이 22·글자 12·회색 한 모양’은 변경하지 않았습니다. ‘검수 포함’은 플랫폼 뱃지가 아니므로 기존 14 크기를 유지합니다.
- 사이드바·상단 메뉴는 맥락을 보여 주기 위한 간소화된 공통 틀입니다. 두 안에 동일하게 사용하며 이번 변경 제안에 포함하지 않습니다.

## 글꼴과 정적 시안의 한계

본문은 저장소의 Pretendard, 페이지 제목과 합계는 Tmoney Round Wind 실제 파일을 로컬에서 불러옵니다. 브라우저가 실제 사용한 글꼴은 [검증 기록](validation.json)의 `renderedFonts`에 있습니다.

저장소에는 Pretendard 500·600·700 파일만 있어 본문 CSS의 400 요청은 브라우저가 가장 가까운 **Pretendard Medium 500**으로 표시합니다. 외부 글꼴 다운로드가 차단되어 400 파일을 추가하지 못했습니다. 현재안·추천안 모두 같은 파일을 사용하므로 배치 비교는 가능하지만, 운영 화면의 본문 400과 완전히 같은 굵기는 아닙니다. 로컬 글꼴을 임의로 다른 굵기로 이름 붙이지 않았습니다.

모든 인물·주소·연락처·요금·승인 시간은 비교용 가상 정보입니다. 실제 회원 정보나 확정 요금 안내가 아닙니다. 상태 전환은 별도 파일 링크로 열며 제품 동작을 구현하지 않았습니다. 따라서 자동 하이픈, 모달 초점 이동, 주소 봉인, 결제 동의 검증이 동작한다고 판정한 자료가 아닙니다.

## 원칙 대조와 배치 진단

화면 종류는 **작업형: 한 열 폼 + 옆 요약 영역**입니다(6-4). 주 작업은 입력·확인·동의 후 결제, 보조 정보는 선택한 선물과 금액입니다.

- 6-5의 같은 구조 반복: 확인 정보는 표, 주소는 폼, 환불 조건은 설명 목록, 결제는 금액·동의 묶음으로 구분했습니다.
- 6-5의 같은 폭: 본문과 보조 열의 폭을 다르게 유지했습니다.
- 6-5의 묶음 간격: 주소 내부 16 / 바깥 32로 구분했습니다. 환불 조건 제목↔내용 8 / 조건 사이 16입니다.
- 14-7의 빈 보조 열: 요약은 기존처럼 스크롤을 따라오므로 긴 폼을 읽는 동안 선택 정보와 금액이 남습니다. 빈 내용을 채우기 위해 새 카드를 추가하지 않았습니다.
- 1-5의 첫 화면 행동은 기존 단계 이동·수정·주소 검색입니다. 결제 버튼을 위로 복제하지 않았습니다(1-3·9-4, 명세의 기존 순서).
- 회색 안내와 하늘 결제 면은 명세 및 design-rules 39절의 구체적 승인 기준이므로 유지했습니다. 비상호작용 묶음에 새 카드나 그림자를 추가하지 않았으며 내부 그림자만 낮췄습니다.
- 외부 스킬 기준과 다름: `ux-designer`의 본문 16 이상 대신 안내 문장은 프로젝트 기준 14, `impeccable`의 보조색 권고 대신 기존 회색 토큰을 사용합니다. 일반 카드 반경 권고 12~16 대신 승인된 큰 판 24를 유지합니다. 우선순위는 design-prompt 적용 규칙 7에 따릅니다.

## 검증과 재생성

실행 명령(저장소 루트 기준):

```text
node projects/fankkuk/docs/design/mockups/gift-send-step4-20261114/build.mjs
node projects/fankkuk/docs/design/mockups/gift-send-step4-20261114/capture.mjs
.agents/skills/impeccable/scripts/impeccable.cmd detect --json --scope layout projects/fankkuk/docs/design/mockups/gift-send-step4-20261114/style.css
```

`build.mjs`는 지정 폴더 안 정적 파일만 생성합니다. `capture.mjs`는 설치된 Playwright와 Chrome으로 캡처하며, 결과를 `validation.json`에 저장합니다. 화면 안에 이 스크립트를 불러오지 않습니다. 자동 배치 검사의 결과는 `[]`였습니다.

현재안·추천안의 전체 화면, 추천안 주소 완료·주소 검색 창, 할증 결제창을 1440·390으로 캡처했습니다. 상태 화면과 전환 경계 320·767·768·769·1183·1184를 검사합니다. 검사가 비어 있지 않은지 확인하기 위해 메모리에서만 가로 넘침과 작은 버튼을 일부러 만들고 감지한 뒤 페이지를 다시 열었습니다. 원본 HTML에는 위반을 남기지 않습니다.

검증 범위는 정적 배치·폰트·누름 높이·콘솔 오류입니다. 제품 테스트·결제 테스트·외부 주소 서비스 테스트를 실행한 것은 아닙니다. Context7 도구는 이번 세션에 제공되지 않았으며, 새 라이브러리나 설정 없이 저장소의 HTML/CSS와 설치된 캡처 도구를 사용했습니다.

`src`·다른 시안 폴더·승인 문서·보호 파일을 수정하지 않았고 커밋하지 않았습니다.

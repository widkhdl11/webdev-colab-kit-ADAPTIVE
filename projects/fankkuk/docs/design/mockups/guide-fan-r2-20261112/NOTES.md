## 1. 결론: 화면 구조와 요소의 역할

화면 종류는 **문서형**(6-4). 글은 `--prose-max` 로 좁게, 그림·카드 묶음은 `--pub-max` 안쪽 글 기둥(880)으로 넓게 둔다(6-4 「글은 좁게, 그림과 카드 묶음은 넓게」). 열 구성은 한 열 하나뿐이다(6-6).

| 구역 | 모양 | 이유 |
|---|---|---|
| 머리 | 탭 다섯 → 제목·설명 → 핵심 안내 → 문서 내 검색 → 목차 줄 | 지금 구성 그대로. 순서만 정리 |
| 핵심 안내(요약 세 줄) | 하늘 판 안의 가로 세 칸 흐름. 칸 사이는 직선 화살표, 칸 전체가 해당 조로 가는 누르는 칸 | 순서가 있는 세 줄 = 흐름(6-1, 5-2). 링크 연결은 원칙 ④. 칸 안에 조 이름 같은 새 글자를 더하지 않고 오른쪽 아래 화살표만 둔다(9-3) |
| 01 선물 등록·발송 순서 | 세로 단계(번호 원 + 직선) | 순서 열 개(5-2) |
| 02 상자별 팬꾹 주소 | 송장 두 장 그림(보내는 분 · 받는 사람 주소 + 끝 6자리 칸) + 점 목록 | 「상자마다 6자리가 다르다」와 「보내는 분 칸에 닉네임」을 글보다 그림이 빨리 전한다(5-1, 1-7). 그림 글자는 01 조의 문장에 나오는 칸 이름만 썼다 |

| 06 선물 거절·반송·환불 | 줄 목록 열네 줄(조용한 번호) | 규칙·안내 = 줄 목록(8-14). 문장은 줄이거나 합치지 않았다. 「출고한 뒤에는 환불 금액이 없습니다.」 한 줄만 빨간 알약(글자 병행, 4-1) |
| 07 송장번호 비공개 | 약속 한 줄 판(잠금 그림 + 첫 문장) + 점 목록 | 첫 문장이 이 조의 약속(1-7) |
| 08 끝 6자리 누락 | 점 목록(두 갈래 시작 문구만 굵게) + 착불 반송 주의 판 | 갈래는 글이 이미 「~를 썼다면 / ~를 적지 않았다면」으로 나눈다. 순서를 바꾸지 않으려고 갈래 칸 두 개로 쪼개지 않았다 |

## 새로 제안한 요소 (design-rules 후보)

1. 핵심 안내(요약 세 줄)를 하늘 판 안 가로 세 칸 흐름으로 — 칸 전체가 링크, 칸 사이 직선 화살표.
2. 문서형 안의 모양 목록: 세로 단계 · 송장 그림 · 크기 카드 · × 줄 + 한도 칸 · 주의 판(`--warn-soft`) · 가로 단계(칸 폭 기준) · 약속 판 · 두 칸 흐름.
3. 조 번호 `01`~`10`(제목 위, `--gray-500`, `aria-hidden`) — 지금 구현에는 없다.
4. 줄 목록의 조용한 번호(`01`~`14`, `--gray-500`).
5. 문서형 화면 배치를 화면 폭이 아니라 칸 폭(컨테이너) 기준으로 바꾼다는 원칙 — 사이드바가 붙는 로그인 후에서 같은 화면 폭이라도 칸이 좁기 때문.

## 색 제안 (시안에는 넣지 않음)

- **제안: tokens.md·design-prompt 의 「조용한 번호 `#7F97AC`」를 `--gray-500`(#6B7280)으로.** 이유: `#7F97AC` 는 흰 바탕 약 3:1 로 14px 보통 글자 기준(4.5:1)에 못 미친다. 이 시안은 이미 `--gray-500` 로 그렸다. 승인되면 tokens.md 부터 고친다.

## 판단이 필요한 것

1. 요약 세 줄을 가로 흐름 판으로 바꾸는 것(지금은 세로 번호 줄).
2. 조 번호 `01`~`10` 을 새로 두는 것(원칙 7 의 번호는 보조 요소지만 지금 화면에는 없다).
3. 04·08 의 주의 판(노란 면)과 06 의 빨간 한 줄 강조 — 환불·반송 결과를 눈에 띄게 하는 정도가 과한지.
4. 오른쪽 따라오는 목차를 넣지 않은 판단(위 표)을 받아들일지.

# 팬에게 보내기 — 크리에이터 설명 페이지 시안

사용자 검토 전 시안입니다. 실제 서비스 화면이나 요금 정책은 변경하지 않았습니다.

본체 1차 피드백: 「PC 히어로가 약620px로 위아래 빈 공간이 너무 큽니다. 내용+그림 높이에 맞춰 약350~400px로 낮춰 주세요.」 → 이미지 원본 높이 속성이 고정 높이로 적용되던 것을 `height: auto`로 바로잡아 원본 비율을 유지하고 캡션을 그림 아래 12px에 붙였습니다.

본체 좁은 PC 폭 피드백: 「769px에서 요금 제목·필수사항 제목이 3줄」 → 사이드바가 남는 769~1023px에서는 요금과 준비사항을 한 열로 바꿨습니다. 휴대폰은 여백 전환이 끝난 뒤 넘침 0으로 확인되어 따로 수정하지 않았습니다.

## 화면의 목적과 구성

- 읽는 사람: 여러 팬에게 선물을 보내려는 크리에이터.
- 목적: 선물함 신청 절차, 묶음 발송 방식, 비용, 준비할 것을 이해하고 선물함 만들기로 이동합니다.
- 상태: 이용 안내 한 상태만 그렸습니다. 신청·생성·마감·결제 화면은 이번 범위에 없습니다.
- 구성: 서비스 한 문장과 대표 그림 → 신청 3단계 → 배송 3장면 → 비용 → 준비사항 2개 → 만들기.
- 선물함은 온라인 신청을 모으는 공간, 묶음 배송 상자는 실물 선물을 함께 보내는 바깥 상자로 구분했습니다.

## 근거와 적용 원칙

- 색·글꼴·반경은 승인된 토큰을 복사해 사용했습니다. 제목은 티머니 둥근바람, 본문은 Pretendard입니다. 본문 폭 880px·사이드바 240px을 유지했습니다.
- 가장 먼저 ‘한 상자에 모아 보내면 팬꾹이 나눠 배송한다’를 설명합니다. 첫 화면과 마지막에 주 행동을 두었습니다. 디자인 프롬프트 1-1·1-2·1-5·1-7·1-8.
- 절차는 순서 목록, 배송은 그림 흐름, 비용은 비교, 준비사항은 간결한 확인 목록으로 구성을 달리했습니다. 5-1·5-2·6-1.
- 배송 그림은 같은 높이 칸을 쓰며 화살표는 그림 칸 중심에 둡니다. 휴대폰은 세로로 바뀌고 각 그림 아래 설명을 붙입니다. 2-10~2-14.
- 여백은 8 단위, 그림과 설명은 12px. 제목은 32·24·20, 본문 16, 설명 14, 그림 속 보조 표시는 12px입니다. 2-1·3-1~3-4.
- 정적 설명에 폼·시간 제한·입력 상태·로딩·실제 신청 수치는 넣지 않았습니다. 후기·홍보 수치·별도 FAQ도 추가하지 않았습니다. 필요한 비용 조건은 요금 구역에, 자주 생길 질문은 준비사항에 담았습니다. 5-5·6-3·9-1·11-1·13-1.
- 자동 등장 모션은 없으며 메뉴와 링크만 작동합니다. 12-1·12-3.
- 다른 마케팅 디자인 지침보다 이 프로젝트의 승인된 카드 경계·제목 글꼴·정적 표현 기준을 우선했습니다.

## 내용 근거와 확인할 부분

- 사용자 최신 요청: 선물함 만들기 → 팬 신청 → 마감, 큰 상자 한 번으로 팬꾹에 전달 → 팬꾹에서 팬별 발송, 선물별 팬 닉네임 필수, 팬꾹으로 보내는 택배는 직접 접수·별도 결제.
- 서비스료 300원·700원은 사용자 요청과 선물함 스펙 INV-GB13~GB15를 대조했습니다. 300원이 배송비 포함 금액으로 보이지 않게 배송비를 분리했습니다.
- 초기 혜택은 선물함 스펙 INV-GB14·GB15의 첫 50명, 확인일부터 3개월, 월 30개 조건을 함께 적었습니다. 기간/개수 초과분은 일반 요금입니다.
- 제주·도서 및 규격 초과는 INV-GB16·GB17에 따라 예외 비용이 있을 수 있음을 적었습니다. ‘추가요금 없음’을 약속하지 않았습니다.
- 최신 요청은 팬꾹행 택배 별도 결제입니다. 과거 명세의 착불 선택은 이번 시안에서 안내하지 않았고 실제 결제 규칙은 수정하지 않았습니다.
- ‘묶음 배송 상자’는 이번 설명용 이름 제안이며 사이트 전체의 확정 용어로 변경하지 않았습니다.

## 시안에서 작동하는 부분

- 본문 바로가기 네 개, 모바일 메뉴, 사이드바 접기/펼치기.
- 이번 시안 범위가 아닌 사이드바 메뉴는 실제 이동을 하지 않는 비활성 표시이며, 화면 위에 시안임을 표시했습니다.
- ‘선물함 만들기’는 기존 만들기 시안의 `#m1` 상태로, ‘내 선물함’은 기존 목록 시안의 `#list2`로 이동합니다. 실제 서비스에 기록을 만들지 않습니다.
- 본체가 Playwright로 1440·1024·769·768·390·360px에서 확인했습니다. 가로 넘침 0, 두 줄을 넘는 제목 0, 본문 대비 최저 7.04:1, 깨진 이미지 0, 본문 링크 높이 44px 미만 0입니다. 폰트 두 종류가 정상 로드됐습니다. 실측 결과는 `browser-check.json`에 있습니다.
- 폭 2000px 요소를 임시 삽입했을 때 넘침 검사에서 감지했고, 제거하면 정상으로 돌아왔습니다. 화면 전환 후 여백 애니메이션이 끝나기를 기다린 뒤 측정했습니다.
- 만들기 버튼을 눌러 기존 시안의 만들기 대화상자가 보이는 것까지 확인했습니다. 모바일 메뉴 열기·Escape 닫기와 이용 요금 바로가기도 확인했습니다.
- 최종 PC·휴대폰 캡처: `desktop.png`, `mobile.png`. 첫 화면만: `desktop-top.png`, `mobile-top.png`.

## 확인할 지점

- 절차와 배송을 나눠 설명한 구성이 이해하기 쉬운지.
- ‘묶음 배송 상자’가 큰 바깥 상자를 가리키는 이름으로 적절한지.
- 비용 조건의 양과 위치, 필수 준비사항의 강조 정도가 적절한지.

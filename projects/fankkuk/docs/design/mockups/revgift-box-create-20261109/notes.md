# 팬에게 보내기 — 선물함 목록·설명·만들기 모달 시안 (2026-11-09)

기준: `docs/design/design-prompt.md`(출력 형식 「설계할 때」 1~5) · UX 명세 `creator-revgifts-new.md` 「2026-11-09 바꿀 것」(승인). 시안: `index.html`(위 막대 버튼으로 상태 11개 전환, `#m3` 처럼 주소 뒤 해시로 바로 열림). 값은 같은 폴더 `tokens.css`(= `src/shared/ui/tokens.css` 복사본)·`shell.css`(사이드바·위 막대 복사본). 미리보기 서버는 mockups 폴더만 서빙해서 src 를 링크할 수 없어 복사했다.

## 1. 결론
- 한 화면 한 메인 행동: 채움 버튼 「선물함 만들기」 하나. 첫 화면 안(제목 줄 오른쪽, 휴대폰은 폭 전체)과 끝에 한 번 더(1-5).
- 선물함 0개: 장점 → 진행 순서 → 비용 → 끝 버튼. 선물함 2개: 「내 선물함」 목록이 먼저, 같은 설명이 아래.
- 장점은 1번(주소)을 넓은 강조 판+큰 그림, 2·3번은 카드 한 장 안 두 칸으로 가르고, 진행 순서는 가로 6단계 장면, 비용은 문장 3줄 + 예시 표로 구성을 다르게 했다(6-1).
- 모달: 같은 자리 3단계(이름 → 받을 인원 → 공개 범위) → 만들었습니다. 닫기·Esc·바깥 누름은 「입력한 내용을 지울까요?」. 휴대폰은 전체 시트.

## 5. 확인 필요 · (가정)
- 확인 필요 — 그림 없음: 「팬 신청」은 휴대폰+체크(promise-message), 「큰 상자로 보내기」는 revgift-pack, 「실측 뒤 명세서·결제」는 검수 그림(icon-inspect)으로 대신했다. 명세서·결제 장면 그림은 세트에 없음. 「선물함 만들기」는 icon-gift. 같은 세트 새 그림이 필요하면 단계 1·2·5.
- revgift-pack 은 장점 2번과 진행 4단계에 두 번 나온다(같은 사실이라 뜻은 맞지만 반복).
- 금액(극소형 3,000 · 소형 3,500 · 중형 4,400 · 대형 5,500, 서비스료 700원)은 「예시」 표시. 앞의 넷은 명세 「정한 것」 ⑤ · /admin/pricing 「팬에게 보내기 택배비」 값. 서비스료 700은 시험 데이터 값(설정값, 확정 아님). 구간 크기·무게는 `TIER_RULE` 값.
- 신청 링크 `https://fankkuk.com/gift-boxes/<id>` 는 예시 주소.
- (가정) 3/3 공개 범위는 「공개」를 미리 골라 둠(9-2). 지금 구현은 미선택+오류 문구라 구현과 다름.
- (가정) h1 은 「팬에게 보내기」 하나(지금 목록은 「선물함」). 목록은 h2 「내 선물함」.
- (가정) 3/3 진행 표시의 「다음: 신청 링크 받기」 · 저장 실패 문구 「선물함을 만들지 못했습니다. 입력한 내용은 그대로 있습니다.」 · 닫기 확인 본문에 입력한 선물함 이름을 보여 줌.
- 명세 「비공개(신청 링크로만 신청)」는 구현·용어집이 쓰는 「초대 링크」와 다르다. 시안은 명세 글자 그대로.
- 푸터는 시안에서 뺐다(이 화면 변경 범위 아님).

## 7. 선물함 목록을 카드로(2026-11-09 사용자 「리스트 형태는 딱딱하고 내용 파악도 어렵다」)
- `#list2` 가 4개 카드: 신청 받는 중 · 팬꾹으로 배송하기 · 결제 요청 · 발송 중(상태 이름은 상태 전이표 화면 표기). 카드 하나 = 선물함 하나, 카드 전체가 신청 관리로 가는 누르는 칸(이름 링크를 카드 전체로 늘림, 키보드 초점 테두리도 카드 전체).
- 담은 것은 이전 줄과 같다: 이름 · 상태 뱃지 · 신청 N명 / 받을 인원 · 공개 여부 · 만든 날. 새 정보 없음(「신청 관리」는 이동할 곳 이름일 뿐).
- 순서(8-8): 그림 → 제목 → 설명(신청 수·공개·날짜) → 행동. 제목 칸은 최소 56(두 줄) 이상이고 같은 줄 카드끼리 높이가 같아 아래 정보 위치가 맞는다(이름 40자도 확인).
- 신청 수는 막대 + 숫자 같이(8-10, `role=progressbar`). 상태는 점+글자+색 뱃지(4-1·4-2): 신청 받는 중=info, 팬꾹으로 배송하기=warn, 결제 요청=brand 면, 발송 중=success.
- 그림 판단(1-6·5-6): 상태마다 다른 그림(신청 휴대폰 · 상자 · 명세서 · 트럭)을 진행 순서 장면과 같은 그림으로 써서 상태가 어느 단계인지 알려 주므로 장식이 아니라 정보로 봤다. 크기는 72×64 칸 안 48로 제한해 제목보다 작게.
- 열 수: 본문 칸 폭 480 이상 2열(PC 1440에서 카드 508), 미만 1열(휴대폰 390). 카드 사이 24(휴대폰도 같은 값 하나, 2-4). 4개라 3열은 쓰지 않음(3+1 로 끝 줄이 비는 것을 피함, (가정)).
- 상태 뱃지 색 매핑은 (가정): 구현의 상태→색 갈래는 아직 없어 이 화면 안에서만 정함.

## 8. 설명 구역 다시 짬(2026-11-09 사용자 「'장점'이라고 노골적으로 쓰는 사이트가 어딨냐」) — §1·§3 의 장점 카드·진행 순서 그림 6개 설명은 이 절이 대신한다
- 구역 이름표(「장점」「진행 순서」「비용」) 제거. 맨 위는 「팬에게 보내기란?」 + 한 문장 정의 + 「선물함 만들기」(선물함 0개는 h1, 2개는 목록 아래 h2). 사용자가 쓴 「팬에게 선물하기」는 메뉴 이름 「팬에게 보내기」로 맞췄다(용어 통일).
- 주인공은 큰 그림 한 장(1-1·5-1·5-2·6-1): 크리에이터+선물이 담긴 큰 상자(「택배 접수 1번」) → 팬꾹이 열어 잼 → 팬 여러 명으로 세 갈래. 갈래는 직선 화살표, 가운데 갈래·화살표는 그림 칸 중심(2-12). 휴대폰은 세로(캡션은 그림 아래 12, 화살표는 그림 가로 중심, 2-14).
- 장점 셋은 세 단계 캡션에 녹임: 주소는 팬꾹에만·닉네임만 → 팬 쪽 캡션 / 포장·접수 한 번 → 큰 상자 캡션 / 도착 뒤 실제 크기로 한 번 결제 → 팬꾹 캡션. 따로 묶은 카드 없음.
- 요금이 덜 든다는 말은 쓰지 않음(화면 문구 규칙 9). 「택배 접수 1번」과 상자 하나에서 갈라지는 그림, 아래 비용 칸의 「팬마다: 상자 크기별 택배비 + 서비스료」 사실로 읽히게 했다.
- 13-1 판단: 여섯 단계를 그림 6개로 다시 그리면 위 큰 그림과 같은 말이 되풀이돼서 그림을 뺐다. 아래 흰 카드 한 장에 번호+주체+제목+설명만 둔 글 목록(14 글자, 한 단계 낮은 비중)과 비용(사실 3줄 + 예시 표)을 같은 카드 안에 두었다. 72시간·168시간 같은 조건은 숨기지 않고 5단계에 그대로 둔다(문구 규칙 10).
- 확인 필요(질문): 일반 택배(팬마다 따로 접수)와 요금을 숫자로 비교하는 칸을 넣을까요? 지금은 확인된 비교 값이 없어 넣지 않았다.
- 확인 필요 — 그림: 팬 쪽 세 갈래 끝의 작은 선물 상자는 gift-box-small, 닉네임 별빛·하늘·보라는 화면 예시. 「팬꾹이 열어 잼」은 검수 그림(icon-inspect). 크리에이터와 큰 상자는 한 칸에 나란히(creator-cat + revgift-pack).
- 카드 신청 수 막대는 사이트 하늘색 `--primary`. 비공개 문구 「신청 링크로만 신청」·3/3 「공개」 미리 선택은 이미 그렇게 되어 있음.
- 상태 이름 변경(사용자): 「상자 보내 주세요」 → 「팬꾹으로 배송하기」(시안 카드 뱃지). 뱃지가 길어져 좁은 카드(폭 229)에서는 그림 아래 줄로 내려가게 했다. 폭 1440·880·769·768·390에서 뱃지 넘침 0·그림과 겹침 0.

- 실측(Playwright, 상태별 새로 불러옴): 칩 줄 수(처음 열었을 때 → 현황을 지나 내린 뒤) 1366×768 2→3(`#mgpick` 4) · 1440×900 3→5 · 1280×720 1→3 · 390×664 0~1→2~3. 마감하기 버튼 아래 여백 56·66·56·72px, 가로 넘침 0.
- 처음 열었을 때의 칩 줄 수는 그대로다 — 현황·검색이 같은 자리를 차지한다. 늘어나는 것은 내린 뒤다.

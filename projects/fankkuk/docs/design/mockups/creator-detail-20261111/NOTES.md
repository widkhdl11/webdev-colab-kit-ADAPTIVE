## 1. 결론 — 구조와 역할 (6-4 프로필 상세형)

위에서 아래로: 상단 바 → **배경 사진 면(유지)** → **머리 줄**(왼쪽: 큰 원형 사진 · 이름 + 팬덤 뱃지 + 채널 아이콘 · 팬 수 · 채널 확인·칩 · 소개 · 감사 문장 / 오른쪽: 버튼 + 요금·승인 시간 + 기념일) → **주 영역 : 보조 열 = 2 : 1**.

| 영역 | 넣은 것 | 이유 |
|---|---|---|
| 머리 왼쪽 | 사진·이름·소개·감사 문장, **이번 달 선물한 팬 N명은 이름 바로 아래** | 팬 수는 이 크리에이터의 인기·활동이라 이름과 함께 읽는다(6-5 3, 14-7 ⑤) |
| 머리 오른쪽 | 버튼 → **요금 · 평균 승인 소요 시간**(같은 종류라 칸 둘, 같은 너비·같은 크기) → **기념일** | 「얼마에, 얼마나 걸려, 언제가 좋은지」는 보내기 직전에 보는 조건이라 버튼 가까이 둔다. 요금은 버튼 바로 아래(6-5 3) |
| 주 영역(2) | 받기 어려운 선물 알림 · 선물함 입구 · 감사 답장 모음(대표 1 + 줄 7) | 보내기 전 확인 → 이동 → 읽을거리 순 |
| 보조 열(1) | 보내기 전 안내(보낼 수 없는 물품 펼침 + 검수·주소 보호) · 다른 크리에이터(한 카드 안 줄 3) | 행동 가까이의 신뢰 정보(11-2)와 나가는 길. 두 열 높이를 맞춤 |
| 한 열 | 휴대폰 390 · 칸 폭 879 이하 | 열 구성은 「한 열」과 「2:1」 두 가지뿐(6-6) |

- **평균 승인 시간은 요금 옆**: 둘 다 보낼 때의 조건이고 「3,000원부터」·「약 2시간」처럼 한 번에 비교하는 값이라 같은 종류. 버튼과 같은 칸에 두면 「보내면 얼마·얼마나」가 한 번에 읽힌다.
- **기념일은 버튼 아래 따로 한 줄**: 보낼 날을 고르는 단서라 버튼 가까이, 단 요금·시간과 종류가 달라(숫자가 아니라 날짜) 같은 줄에 묶지 않았다. 이름 쪽에 두면 머리 왼쪽만 길어져 두 칸 높이가 어긋난다.
- 상태: needs_follow / open / self / hidden / unsigned / verifying / 저장 실패 2종. 이 중 verifying 은 프로필 + 안내 한 줄만(숫자·팬 수 없음). withdrawn·not_found 는 공통 화면이라 안 그림.

- 버튼 순서(위 4).

- hidden(쉬는 중)에서는 알림이 빠져 주 열이 짧아진다(1440: 810 대 919, 1024: 810 대 1009). 실제 답장은 최대 20개라 보통 주 열이 더 길다.

- 실사진이 들어간 모습은 「화면 예시」 그림(`img/cover-sample.svg`)이고, 사진 없을 때는 도구의 「배경 사진 없을 때」 버튼으로 본다.

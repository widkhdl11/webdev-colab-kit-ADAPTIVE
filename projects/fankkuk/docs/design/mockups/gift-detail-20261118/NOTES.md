## 배치 진단 (design-prompt 7항 양식)
- 정한 화면 종류: 상세형(위 판 + 주 칸 + 보조 열).
- 6-5 해당 항목과 고친 내용(고치기 전 → 고친 뒤):
  1) 같은 구조 3번 이상 반복: 지금은 상자 줄 → 결제 카드 → 주문 정보 카드가 같은 흰 카드로 이어짐 → 결제를 낮춘 회색 면(22절 「주문 정보는 #f7f7f8 로 낮춤」과 같은 값)으로 바꿔 흰 카드 연속을 끊음. 상자는 주소가 없을 땐 작은 타일 2개(소형·중형이 한눈에), 있을 땐 상자별 묶음.
  2) 영역 폭이 같음: 해당 없음(주 칸 : 오른쪽 288 로 이미 다름).
  3) 큰 영역 바로 아래 같은 크기만 이어짐: 판 바로 아래가 주 칸·오른쪽 칸 폭이 다른 두 단이라 해당 없음.
  4) 먼저 읽을 영역이 하나로 안 정해짐: 해당 → 판 안에서 「지금 상태 한 줄」(20 굵게)을 가장 크게, 누구에게 보내는지(제목)는 16 굵게로 내림. 지금은 제목 20·상태 줄 16 이라 둘이 경쟁했다. 숫자(n/6·도착 예정일 32)는 그대로.
  5) 묶음 안·사이 간격: 묶음 안 4~12, 카드 사이 16, 두 단 사이 32 로 2배 이상 차이.
  6) 같은 모양을 3개 영역 이상: 구분선 줄 목록을 상자 사이(1곳)·답장 상자 사이(1곳)에만 씀. 상자=타일/묶음, 답장=말풍선, 안내=회색 면, 결제=낮춘 면, 승인 상태=노란 칸으로 영역 성격마다 모양을 달리함(8-14).
- 14-7 자기 검토: ① 글자·버튼·사진 크기는 지금 화면과 같거나 작음(예외 아래 「가정」의 두 곳) ② 눌리지 않는 묶음의 테두리: 결제·안내·상자 타일·말풍선은 면만, 흰 카드(상자·선물 정보·답장 묶음)는 22절 승인대로 테두리 유지 ④ 상태 1·4·7 은 왼쪽이 짧아 오른쪽 카드가 더 길어 보이지 않게 결제를 왼쪽으로 옮겨 맞춤(옮기기 전에는 오른쪽이 왼쪽의 2배였음).

## 제안 (노출·구성 변경이 필요하다고 본 것 — 시안에는 반영하지 않음)
1. 선물 정보 카드의 「받는 크리에이터·선물·상자」가 판의 제목·「선물 · 상자 2개」와 겹친다(9-4). 한 곳(카드)에만 두고 판은 제목만 두는 안.
2. 상자가 둘 이상일 때 크라프트 칸이 상자마다 통째로 반복돼 상태 2·3 이 가장 길다(1440 약 3000, 휴대폰 약 4000). 크리에이터 쪽 팬별 칸처럼 안내(제목·부제·노트 두 줄)는 첫 상자에만 두고 나머지는 종이 판+띠만(`compact`) 두는 안.
3. 배송 중·도착 상태에서 「수령 확인·답장」 줄과 「상자 N · 입고됨」 줄이 같은 상자를 두 번 보여 준다. 한 목록으로 합치는 안(읽기 두 개를 한 화면 줄로 합쳐야 해서 구현 결정이 필요).
4. 「승인됨」 뒤에도 「승인 전에도 팬꾹으로 보낼 수 있지만… 7일 이내 승인이 필요합니다」 줄이 남는다(코드의 `anyAddress` 조건만 봄). 승인 뒤엔 뺄지.
5. 결제 카드의 「구간」(「실측 결과가 선택한 요금 구간을 초과하면…」)은 명세 6번(「상자 크기」로 바꿈)이 아직 코드에 반영되지 않아 코드 그대로 썼다.
6. 도착(6/6)에서 도착 예정일을 큰 숫자로 계속 둘지(코드는 날짜가 있으면 「전후 도착 예정」을 보임).

## 가정 (design-rules·tokens 에 없는 값 — 승인되면 추가 후보)
- 판의 얼굴 48(「모」, 크리에이터 사진이 없으면 첫 글자): 판에 얼굴이 없던 곳이라 새 요소. 목록 얼굴과 같은 48 로 맞춤.
- 상태 한 줄 20 굵게(지금 16): 적용 규칙 8의 「지금 화면보다 크지 않게」를 어기는 한 곳. 이유: 이 화면의 목적이 「지금 어디까지 왔나」라서 1-2 에 따라 가장 크게 둠. 대신 제목을 20→16 으로 줄여 판 안 가장 큰 글자 수는 늘지 않는다.
- 결제 카드를 주 칸으로 옮기고 낮춘 면(`--surface-muted`, 테두리·그림자 없음)으로 둠 — **33절(결제·주문 정보를 선물 정보 카드 하나로 합침)에서 벗어남.** 사용자 지시 ④(「선물에 대한 내용과 정보를 한번에」)는 오른쪽 카드가 선물 정보를 한곳에 모아 그대로 지킨다.
- 도착(6)의 6/6, 거절 상태의 숫자 없음: 코드의 「날짜가 없으면 n/6, 거절이면 숫자 없음」 가정. 날짜·금액·닉네임·송장번호·답장 문구는 전부 더미.
- 상자 타일 아이콘(사이드바 「받은 선물」의 상자 선): 장식이 아니라 상자 표시. 2열 타일은 컨테이너 기준 자동(`minmax(240px,1fr)`).
- 열린 접는 줄(송장번호·찾기)의 양식 내용은 코드 문구 일부만 두고 택배사 칸 등은 그리지 않음(지금 그대로, design-rules 38절).

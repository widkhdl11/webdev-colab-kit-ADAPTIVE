## 스킬별 반영

### ux-designer
- 명세 대조: 구역 순서 1→6, 첫 화면 헤드라인 「팬꾹의 소개」, 버튼 두 자리 「[행동 버튼 미정]」, 「확인 필요」 표시 4곳(구역 2 제목·본문 끝, 3-2 둘째·넷째 문장), 신뢰 요소 4줄, 질문 4개(추천 「넣음」 4개, 「뺌」 요소는 넣지 않음), 구역 3-1 그림. 모두 반영됨. 없는 것(고정 목차·검색·구역 주소 복사·최종 수정일·후기·장식 그림)도 넣지 않음.
- 상태: 로그인 전 default 한 장. 로그인 후(사이드바 + 같은 본문)는 이번 지시 범위 밖이라 안 그림. error 상태는 요금 질문을 뺐으므로 없음.
- 핵심 규칙: 주인공 하나(헤드라인)·주 행동 하나(채움 버튼), 펼침은 `<details>`/`<summary>`, 그림에 대체 글(`role="img"` + `aria-label`), 본문 16, 건너뛰기 링크, 진행 막대 `role="progressbar"`, 초점 표시 유지, 상태 칩은 글자 병기.
- references는 읽지 않았다(SKILL.md 본문의 값으로 충분했음).

### ui-ux-pro-max (`--domain landing` 1회, `--domain ux` 3회. 팔레트·글꼴·`--design-system`·`--persist` 안 씀)
- 검색어: 「service introduction landing page section order trust FAQ」(landing) · 「accordion FAQ keyboard disclosure」 · 「content hierarchy single primary CTA scannable long page」 · 「responsive mobile horizontal scroll touch target spacing」(ux)
- 반영: 구역 순서가 「첫 화면 > 본문 > FAQ > 끝 행동」인 패턴 확인(명세 순서와 같음) · 키보드만으로 모든 동작 · 긴 글이 가로로 넘치지 않게 `overflow-wrap` · 가로 스크롤 없음 · 누르는 칸 사이 8 이상.
- 검색 결과가 나온 것 중 이 페이지에 안 맞아 뺀 것: 가격표·기능 비교표(근거 없음), 상단 고정 버튼, 검색창.

## 본문을 그대로 쓰기 어려웠던 곳

- 문장은 한 글자도 안 고쳤다(맞춤법 포함). 「(그림 포함).」은 지시문이라 뺐다 — 「보낼 수 있어요.」 뒤에 마침표 하나만 남김.
- 구역 2 둘째 문장은 원문에서 쉼표 뒤 줄바꿈 두 줄이다. 한 문단으로 이어 붙였다(글자는 그대로).
- 구역 3 제목의 「->」는 원문 그대로 화면에 나온다. 말로 바꾸자는 제안은 명세의 「제안」 절 그대로(결정은 사람).
- 구역 3-1 제목 끝 마침표는 원문에 있어서 그대로 남겼다(3-2·다른 제목에는 없다 — 표기 통일은 제안으로만).
- 구역 3-2 비교 서술(「높은 이용료」「저렴한 비용」)은 그림으로 그리지 않았다(근거 없는 비교를 그림으로 굳히지 않으려고, 5-5). 그림은 팬꾹 방식만 보여 준다.
- 신뢰 요소 4줄·질문 4개의 답은 `about-page.tsx`·`faq-doc.ts` 원문 그대로. 답의 변수는 실제 값으로 바꿈(승인 기한 `APPROVAL_DEADLINE_DAYS` = 7일, 고객센터 이메일 `support@fankkuk.com`).
- 구역 6은 명세 표 순서(질문 → 신뢰)와 달리 신뢰 요소를 질문 위에 뒀다(design-prompt 6-2·11-2: 신뢰 → 의심 해소 → 행동).
- 그림 속 예시 값(닉네임·선물 이름·인원·시각·팬덤 이름 「솜뭉치」·채널 이름 「나비」)은 지어낸 값이라 「화면 예시」 표시를 붙였다. 선물함 상태 이름(신청 받는 중·마감)·신청 상태(신청·제외·대기)는 revgift-box 스펙의 화면 표기를 썼다.

# 랩업 — 다음 대화가 파일에서 시작하게 남기는 일

**이 스킬은 무엇을 하는지만 적는다. 끝났는지는 `scripts/check-wrapup.mjs` 가 판정한다.**
산문 체크리스트는 빠뜨린다 — 그래서 완료 선언은 검사가 한다. 검사가 안 보는 항목은 아래에서
「권장」으로 내려 두었다. 검사가 안 보는데 필수인 척 남으면 또 빠진다.

**랩업은 세션을 닫지 사이클을 닫지 않는다.** 열린 사이클은 workspace/CYCLE.md 에 그대로 두고
「멈춘 지점」에만 적는다(사이클을 닫는 것은 종료 조건 판정이다 — docs/references/decision-layer.md).

## 두 종류

| 종류 | 언제 | 하는 것 |
|---|---|---|
| **항목 랩업** | 요청 항목 하나가 끝날 때마다. 자율 실행 루프 안에서는 이것만 돈다 | 아래 1 |
| **세션 랩업** | 대화 세션을 끝낼 때 · 대화 길이 경고가 「새 세션 권장」을 냈을 때 | 아래 1 + 2 + 3 |

## 1. 항목 랩업 (이 순서로)

1. **항목 닫기**: `node scripts/report-request.mjs --done <항목 id>`
2. **통과 전환 줄**: `node scripts/report-note.mjs --node <노드> --task <식별자> --now "<한 줄>" --item "<항목 label>" --result 통과`
   (done 과 통과 줄은 쌍이다 — 한쪽만 있으면 검사 B2 가 잡는다)
3. **PROGRESS 「현재 상태」** 를 5개 필드로 갱신한다(10줄 이내). 이 요청의 식별자가 보여야 한다(검사 B4):
   - 오늘의 목표 · 완료 · 멈춘 지점(「T3 폼 검증 로직 작성 중」 수준) · 다음 할 일(그대로 입력창에 칠 수 있는
     한 문장, 화면 국면이 남았으면 그것부터) · 대기 중인 결정(사용자 승인 대기만, 없으면 「없음」)
4. **HANDOFF 갱신**: `node gates/graph-stop.mjs` (검사 B3 — 마지막 전환보다 늦게 쓰여야 한다)
5. **커밋**: docs/references/commit-policy.md 대로. 커밋 뒤 남은 변경이 없어야 한다(검사 B1)
6. **판정**: `node scripts/check-wrapup.mjs --item <항목 id> --since <이 항목 시작 시각>` — 통과해야 끝이다

결정을 기다리며 멈추는 항목이면 1·2 대신 카드를 연다(`report-decision.mjs --ask --item <항목 id>` + 같은 턴에
`report-note.mjs --blocker`). 검사는 그 항목을 막는 카드가 열려 있으면 done 이 아닌 것을 통과로 본다.

## 2. 발견 정리 (세션 랩업)

- **실패·반려·정정이 있었으면 같은 날짜로 한 줄 남긴다.** 제품이면 `projects/<이름>/docs/BACKLOG.md`, 하네스면
  `docs/references/harness-backlog.md`. `docs/LESSONS.md` 는 보호 파일이라 retro 의 승인 절차로만 쓴다
  (검사 B8 — 전환 줄에 `실패`·`반려` 가 있거나 재시도 회차면 오늘 날짜 줄을 요구한다)
- **열린 결정 카드**가 있으면 규약을 지키는지(검사 B5), 답이 왔으면 `--answer` 로 닫았는지 본다
- **요청 밖 작업**을 했으면 전환 줄의 `--item` 에 항목 목록에 없는 이름으로 남았는지 본다(검사 B7)
- **미룬 작업은 BACKLOG 로 뺀다.** PROGRESS 의 「대기 중인 결정」은 사용자 승인 대기 전용이다. 한 항목은 정확히 이 한 줄 꼴
  (브리핑이 `- [ ]` 를 센다 — 들여쓰기 금지):
  ```
  - [ ] **제목 한 줄** (YYYY-MM-DD) — 지금 안 하는 이유 · 되살릴 조건
  ```
  처리한 항목은 `- [x]` 로 바꿔 「닫힘」으로 옮긴다. 같은 것이 이미 있으면 그 줄에 덧붙인다.
  하네스(킷) 개선은 docs/references/harness-backlog.md 이고 retro 가 관리한다. 섞지 않는다.

## 3. 인수인계 리허설과 다음 첫 입력 (세션 랩업)

1. `node scripts/check-wrapup.mjs` — --since 없이 부르면 오늘 0시부터의 기록을 본다. 통과해야 한다
2. `node scripts/loop-rehearsal.mjs` — 새 대화가 HANDOFF·PROGRESS·request.json 만 보고 지금 위치·다음 항목·
   열린 결정을 맞히는지 본다. 어긋나면 HANDOFF·PROGRESS 를 보강하고 다시 돌린다
3. 리허설이 낸 네 줄(지금 위치 / 다음 할 항목 / 열린 결정 / 주의할 것)을 **「다음 세션 첫 입력」** 으로 출력한다.
   사람이 `/clear` 뒤 이것을 그대로 붙여 넣으면 된다

## 권장 (검사가 보지 않는다)

- 「현재 상태」에서 파일을 가리킬 때는 백틱이 아니라 문서 위치 기준 마크다운 링크로 쓴다
  (`[패치 문서](../../../docs/references/pending-patches/....md)`). 브리핑이 링크를 레포 루트 기준으로 바꿔 찍고,
  대상 파일이 없어지면 경고를 띄운다
- 상세 내역은 PROGRESS 하단 로그에 날짜와 함께 덧붙인다
- 대화 중 결정됐는데 문서에 없는 것을 PRODUCT·DECISIONS(projects/<이름>/docs/)에 반영한다
- 끝에 한 문단 요약으로 보고한다

BACKLOG.md 가 없으면 이 머리말로 만든다:

```markdown
# BACKLOG — <이름> (미룬 것)

지금 안 하기로 한 작업. wrap-up 이 쌓고, 세션 시작 브리핑은 미결 건수만 띄운다(0건이면 침묵).
- 미결은 `- [ ]`, 닫히면 `- [x]` 로 바꿔 "닫힘" 으로 옮긴다.
- 형식: `- [ ] **제목** (날짜) — 보류 이유 · 되살릴 조건`
- 하네스 개선은 여기가 아니라 docs/references/harness-backlog.md.
```

# 랩업 — 다음 세션의 브리핑 재료를 만드는 일
projects/<이름>/workspace/PROGRESS.md "현재 상태" 블록을 정확히 이 5개 필드로 갱신한다 (10줄 이내):
- 오늘의 목표: (달성 여부 포함)
- 완료: (오늘 끝난 것)
- 멈춘 지점: (진행 중이던 작업과 정확한 중단 위치 — "T3 폼 검증 로직 작성 중" 수준)
- 다음 할 일: (그대로 입력창에 칠 수 있는 한 문장. **순서 원칙: 화면(디자인) 국면이 남았으면 그걸 1순위로 — DB/데이터 계층을 앞에 두지 말 것.** briefing 가드가 이 순서를 점검한다)
- 대기 중인 결정: (**사용자 승인을 기다리는 것만.** 없으면 "없음". 내가 안 하기로 미룬 작업은 여기가 아니라 BACKLOG.md)

## 미룬 것은 BACKLOG.md 로 뺀다
"지금 안 하기로 한 것"을 "현재 상태"에 쌓으면 그 블록은 세션마다 길어지고, 10줄을 넘는 순간
브리핑이 읽어 주는 다섯 줄이 뭉개진다. 그래서 **미결은 파일을 따로 쓴다.**
projects/<이름>/workspace/BACKLOG.md 에 append 한다 (파일이 없으면 아래 머리말째로 새로 만든다).

한 항목은 **정확히 이 한 줄 꼴**이다 — 브리핑이 `- [ ]` 개수를 세므로 줄 시작이 어긋나면 세지 못한다
(들여쓰기 금지, 굵기 표시를 `-` 앞에 붙이지 말 것):

```
- [ ] **제목 한 줄** (YYYY-MM-DD) — 지금 안 하는 이유 · 되살릴 조건(무엇이 끝나면/무엇이 관찰되면)
```

- 이번 세션에 처리한 항목은 `- [x]` 로 바꾸고 "닫힘" 절로 옮긴다(무엇으로 닫혔는지 한 줄).
- 이미 있는 항목이면 새 줄을 만들지 말고 그 줄에 이번 관찰을 덧붙인다 — 같은 것이 두 줄이면 건수가 거짓이 된다.
- **제품 백로그만 여기.** 하네스(킷) 개선은 docs/references/harness-backlog.md 이고 retro 가 관리한다. 섞지 않는다.
- 미룬 것이 없는 세션이면 파일을 건드리지 않는다. 억지로 채우지 않는다.

새로 만들 때 쓰는 머리말:

```markdown
# BACKLOG — <이름> (미룬 것)

지금 안 하기로 한 작업. wrap-up 이 쌓고, 세션 시작 브리핑은 미결 건수만 띄운다(0건이면 침묵).
- 미결은 `- [ ]`, 닫히면 `- [x]` 로 바꿔 "닫힘" 으로 옮긴다.
- 형식: `- [ ] **제목** (날짜) — 보류 이유 · 되살릴 조건`
- 하네스 개선은 여기가 아니라 docs/references/harness-backlog.md.

## 미결

## 닫힘
```

## 순서
PROGRESS "현재 상태" 갱신 → BACKLOG.md 갱신(미룬 것 append + 닫힌 것 `- [x]`) → 상세 내역을 PROGRESS
하단 로그에 날짜와 함께 append → 대화 중 결정됐는데 문서에 없는 것 점검(PRODUCT/DECISIONS 반영 —
PRODUCT는 projects/<이름>/docs/, DECISIONS는 projects/<이름>/workspace/) → 한 문단 요약 보고 후 종료.
브리핑(SessionStart)이 이 블록을 읽는다 — 여기 안 적힌 것은 다음 세션에 없는 것이다.

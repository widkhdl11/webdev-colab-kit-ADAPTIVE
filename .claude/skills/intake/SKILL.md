# 들여오기 — 밖에서 만들어진 프로젝트를 문서로 추출한다

목표: 외부 프로젝트를 읽어 `projects/<slug>/docs/` 를 문서 계약 형식으로 만들고,
`projects/<slug>/workspace/` 를 세워 하네스가 이어서 개발할 수 있는 상태로 만든다.

내보내기(이전 = `docs/` 복사 + 계약 문서 전달)의 역방향이다. 두 가지를 새로 발명하지 않는다:
**무엇을 만들어야 하는지**는 `docs/references/docs-contract.md` 가 이미 정의하고,
**됐는지의 판정**은 `scripts/check-handover-rehearsal.mjs` 가 이미 한다.

## 추출과 발명의 구분 — 이 절차의 전부

코드는 "무엇이 그런지"만 말한다. "무엇이어야 하는지(스펙)"와 "왜 그런지(결정의 이유)"는
말하지 않는다. 그래서:

1. **모든 스펙은 `status: draft` · `surfaces: []`.** `approved` 는 사람의 승인 기록인데
   들여오는 시점엔 아무도 승인하지 않았다. `surfaces` 도 승인할 때 사람이 판정한다.
   코드가 아무리 완성돼 보여도 예외 없다.
2. **코드에서 역산한 동작을 불변식으로 적을 때는 전부 `[추정 — 확인 필요]`.**
   지금 동작이 버그일 수 있다 — 버그를 불변식으로 승격하는 것이 이 절차의 최대 위험이다.
3. **결정의 이유는 확인된 것만.** 커밋 메시지·기존 문서에 이유가 적혀 있으면 출처와 함께
   적고, 없으면 적지 않는다. 빈 `DECISIONS.md` 가 지어낸 `DECISIONS.md` 보다 낫다.
4. **시각 방향은 발명 금지·보존 허용.** 컨셉·무드·레퍼런스는 코드에서 역산하지 않는다.
   다만 사람이 써 둔 명시적 선언이 기존 문서에 있으면 `[문서에서 확인]` 으로 옮긴다 —
   버리는 것은 신중함이 아니라 있는 지식을 버리는 것이다. `status` 는 `draft` 로 두고
   "이 방향이 지금도 유효한가"를 질문 목록에 올린다.

## 출처 태그 — 항목마다 하나씩

| 태그 | 무엇 |
|---|---|
| `[코드에서 확인]` | 코드·설정·마이그레이션이 직접 말해주는 것 |
| `[문서에서 확인]` | 기존 문서·커밋 메시지에 적혀 있던 것 |
| `[추정 — 확인 필요]` | 정황상 그럴 것 같은 것. 반드시 질문 목록에 오른다 |
| `[사용자 답변]` | 질문에 답을 받은 것 |

답이 오지 않은 `[추정]` 은 그대로 남긴다. **추정을 확인된 사실로 승격하지 않는다.**

## 절차

0. **입력 확인** — 소스 경로가 존재하고 읽히는가, slug 가 소문자·숫자·하이픈인가,
   `projects/<slug>/` 가 아직 없는가. 이미 있으면 들여오기가 아니라 갱신이므로 멈추고 묻는다.
1. **조사** — 읽는 순서는 "기계가 말해주는 것"부터다.
   설정 파일(`package.json` · 프레임워크 설정 · `tsconfig`)에서 스택,
   마이그레이션·스키마에서 데이터 모델과 위험 표면, 기존 문서에서 의도,
   커밋 이력에서 결정의 이유. 읽은 자리는 전부 대응표에 적어 둔다(리포트에 들어간다).
2. **docs 초안** — 계약 형식대로 쓴다. 필수는 `docs/PRODUCT.md` ·
   `docs/design/design-rules.md` · `docs/DECISIONS.md` · `docs/BACKLOG.md` 이고,
   위험 표면과 데이터 모델이 있으면 `docs/specs/<slug>.md` 를 표면마다 하나씩.
   `docs/tech-stack.md` 는 스택이 코드로 확인되면 만든다.
3. **질문 목록 일괄 제시** — 조사가 끝난 뒤 **한 번**에. 실행 중에 반복해서 묻지 않는다.
   코드가 답할 수 없는 것만 올린다(이 동작이 의도인가 버그인가 / 왜 이 스택인가 /
   이 미완성 기능은 계속 갈 것인가 / 이 시각 방향이 지금도 유효한가).
   목록 전체는 리포트에, **사람 결정 없이는 다음 노드로 못 가는 것만** `workspace/PENDING.md` 에
   `blocks:` 와 함께 올린다 — 전부 올리면 열린 보류가 상한에 닿아 사이클이 조기 종료된다.
4. **답 반영** — 답이 온 항목만 `[사용자 답변]` 으로 바꾼다. 나머지는 그대로.
5. **검증** — 이 순서로 돌린다. 하나라도 실패하면 고치고 처음부터 다시 돌린다.
   - `node scripts/check-intake.mjs <slug>` — `[추정]` 집계를 받는다. 리포트가 아직 없으니
     필수 산출물 항목은 이때 실패한다(정상이다)
   - `workspace/reports/INTAKE_REPORT.md` 발행: 무엇을 어디서 추출했는지(대응표) ·
     질문 목록 전체 · 남은 `[추정]` 건수 · 게이트 현황. **건수는 위 출력을 그대로 옮긴다 —
     손으로 세지 않는다**
   - `node scripts/check-intake.mjs <slug>` 다시 — 이번엔 전부 통과해야 한다
   - `node scripts/check-handover-rehearsal.mjs` — 이전 리허설(전 프로젝트 대상)
   - 루트 `ACTIVE` 를 `<slug>` 로 바꾸고 **턴을 끝낸다** → Stop 훅이 `workspace/HANDOFF.md` 를
     만들고 프론티어를 뽑는 것을 확인한다. 확인이 끝나면 `ACTIVE` 를 원래 값으로 되돌리고
     다시 턴을 끝낸다 — 되돌리지 않으면 다음 세션 브리핑이 엉뚱한 프로젝트를 읽는다

## 소스 경로는 docs 에 적지 않는다

출처 파일 경로와 대응표는 `workspace/reports/INTAKE_REPORT.md` 에만 둔다.
`docs/` 에는 내용과 출처 **태그**만 남는다.

이유는 두 겹이다. 소스 트리의 경로는 하네스를 바꾸면 새로 만드는 과정 기록이지 프로젝트
지식이 아니다. 그리고 외부 프로젝트에는 `scripts/` · `gates/` 같은 이름의 폴더가 흔해서,
그 경로를 `docs/` 에 한 줄 적는 것만으로 이전 리허설이 그것을 하네스 참조로 잡는다.
리허설은 한 번에 모든 프로젝트를 판정하므로 다른 프로젝트 검사까지 같이 실패한다.

## v1 의 경계 — 코드는 옮기지 않는다

**`projects/<slug>/src/` 를 만들지 않는다. 스캐폴딩도 돌리지 않는다**(그것이 `src/` 골격을
만든다). 산출물은 `docs/` 와 `workspace/` 뿐이다.

게이트는 방금 편집한 파일이 아니라 `src/` 가 있는 모든 프로젝트의 트리 전체를 매번 본다.
규약을 안 지키는 코드가 들어오면 그 위반이 레포 전체의 턴을 막고, 다른 프로젝트 작업까지
같이 멈춘다. 코드 이관은 별도 사이클이고, 그 사이클의 첫 일은 위험 표면 스펙을 승인하는 것이다.

대가는 숨기지 않는다: `src/` 가 없는 동안 **들여온 코드의 위험 표면은 아무도 안 본다.**
리포트에 그렇게 적는다.

## 금지

- **원본에 쓰지 않는다.** 읽기 전용이다 — 파일을 고치거나 옮기거나 지우지 않는다.
- 코드가 답할 수 없는 것을 지어내지 않는다. 모르는 것은 질문 목록으로 간다.
- 조사 도중에 하나씩 묻지 않는다. 질문은 조사가 끝난 뒤 목록 하나로.
- 스펙을 `approved` 로 만들지 않는다. 승인은 사람이 별도 절차로 한다.

# 같이 바꿔야 하는 범위 (작업 시작 규칙)

> 2026-11-14 사용자 지시로 만들었다. 팬꾹 설정 세 화면 재디자인에서 범위를 시안 두 장으로 잡았고,
> 시안이 사이드바를 「맥락용, 시안 대상 아님」으로 뺀 것을 그대로 따랐다. 같은 화면으로 들어가는 길
> (사이드바·서랍)과 옮겨진 칸의 옛 주소(#fandom·#days·#verify)는 사용자가 물은 뒤에야 확인했다.
> 루트 CLAUDE.md 의 라우팅, spec·page-brief 스킬, design-drafter 에이전트가 이 파일을 가리킨다.

작업 범위는 시안이나 파일 목록이 아니라 사용자가 지시한 변경으로 정한다. 지시한 변경이 사이트 전체에서 참이 되려면 함께 바뀌어야 하는 곳은, 지시에 이름이 나오지 않아도 같은 작업에서 고친다.

## 시작하기 전에
바꿀 대상의 주소, 컴포넌트 이름, 화면에 보이는 이름으로 코드와 문서를 검색해서 아래를 찾는다.
1. 그 화면으로 들어가는 길: 사이드바, 휴대폰 서랍 메뉴, 상단 메뉴, 탭, 홈의 바로가기, 다른 화면의 버튼과 링크
2. 이름을 쓰는 곳: 메뉴 이름, 페이지 제목, 브라우저 탭 제목, 그 화면을 인용한 안내 문구·알림·이메일, 용어집
3. 주소: 옮기거나 합친 화면의 옛 주소와 내부 링크
4. 같은 내용을 보여 주는 다른 화면: 요약 카드, 빈 상태의 안내
5. 역할별 화면: 팬, 크리에이터, 운영자 각각
6. 문서와 시험: UX 명세, design-rules, 화면 구조를 판정하는 시험

## 나누는 기준
찾은 곳을 둘로 나눈다.
- 반드시 같이: 고치지 않으면 사용자가 옛 구조를 보게 되거나, 링크가 끊기거나, 같은 것의 이름이 화면마다 달라지는 곳. 묻지 않고 같은 작업에서 고친다.
- 제안: 고치지 않아도 틀린 곳은 없고 더 좋아질 뿐인 곳(모양 맞추기, 주변 정리). 고치지 않고 목록으로만 적는다.

## 보고
- 작업을 시작할 때 「같이 바꾸는 곳」과 「제안」 목록을 짧게 보여 준다.
- 시안에서 "맥락용"으로 뺀 요소가 이번 변경의 영향을 받으면, 시안 결과물에 「시안에는 없지만 같이 바뀌어야 하는 곳」으로 적는다.
- 서브에이전트에 맡길 때는 「같이 바꾸는 곳」 목록을 지시문에 넣는다.
- 끝나면 목록의 항목마다 고쳤는지 표시한다.

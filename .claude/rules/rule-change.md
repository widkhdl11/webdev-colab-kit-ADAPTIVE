# 규칙 값을 바꿀 때 — 옛 값이 남은 자리를 찾는다 (2026-10-30 retro, fankkuk)

같은 규칙이 SQL·시험 기대값·스펙 문장·화면 문구에 따로 적혀 있다. 한 곳을 고치면 나머지는
아무 신호 없이 옛 규칙으로 남고, 누가 그 자리를 건드릴 때에야 터진다. fankkuk 에서 세 번 났다 —
10-15 가입 닉네임(옛 기대값 3건), 10-21 기한 168→720시간(시험 10여 건·스펙 문장 잔존),
10-30 알림 묶음(옛 동작을 기대한 통합 시험 29건).

**승인된 스펙의 값(기한·한도·금액·횟수·용어)을 바꾸거나, 마이그레이션에서 함수를 다시 만들어 값이 바뀌면**
그 작업을 끝내기 전에(커밋 전) 아래를 한다.

1. `node scripts/find-old-values.mjs` — 이번 변경에서 지운 값(숫자+단위·「」 용어)을 뽑아, 그 값이 아직 남은
   자리를 보여 준다. 다시 만든 함수는 바로 앞 정의와 본문을 비교한다. 커밋한 뒤라면 `--base <커밋>~1 --head <커밋>`.
2. 「먼저 볼 곳」(값을 지운 함수를 같이 쓰는 파일)은 줄마다 본다. 「그 밖의 파일」은 같은 숫자를 쓰는 다른 규칙일 수
   있으니 파일 이름으로 훑고 관련된 것만 연다. **고르는 것은 사람이다** — 168시간은 승인 기한(7일)에도 쓰인다.
3. 찾은 자리는 고치거나, 그대로 두는 이유가 있으면 두거나, 지금 못 고치면 BACKLOG 에 올린다.
   스펙 문장이 옛 값이면 그 스펙도 같이 고친다(대화와 문서가 다르면 문서가 우선이라, 옛 문장이 다음 작업의 근거가 된다).
4. 프로젝트에 관련 시험을 고르는 명령이 있으면 돌린다(fankkuk: `npm run test:related -- --run`).
   옛 값 찾기는 값이 사라진 함수만 보므로, 그 값을 다른 함수로 보는 시험은 여기서 빠진다 — 관련 시험 명령이 그것을 잡는다.

스펙의 INV 를 고치면 그 번호를 인용하는 다른 스펙·화면 명세의 파일:줄이 편집 때 경고로 뜬다
(`node scripts/check-inv-citations.mjs` 로 직접 볼 수도 있다). 경고는 막지 않는다 — 인용이 그대로 맞는지 보고 넘어간다.

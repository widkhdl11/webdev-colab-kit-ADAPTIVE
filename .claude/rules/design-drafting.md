# 디자인 시각 방향 — 시안 먼저, 그다음 구현 (경로 조건 규칙)

이 규칙은 **새 화면/페이지의 시각 작업**에 적용된다. 목적은 하나: 새 시각 방향을
코드로 굳히기 전에 버려도 싼 시안(mockup)으로 먼저 반복하는 것.

## 판단 — 이 화면은 새 방향인가, 반복인가

CLAUDE.md 의 표면별 판단 중 '시각 방향' 표면에 해당한다. 화면 작업 시작 전에 먼저 판단한다.
기준은 하나다: **뒤집었을 때 버릴 것이 얼마나 되는가.**

- **반복**: `projects/<이름>/docs/design/design-rules.md` 로 이미 승인된 레이아웃 언어를 물려받는 화면.
  (예: 홈이 승인됐고 상세·개설 폼이 같은 카드/폼 언어를 씀)
  → **시안 건너뛴다.** design-rules.md 를 근거로 바로 구현. checkpoint 불필요.

- **새 방향**: design-rules.md 로 커버되지 않는 새 레이아웃 언어.
  (예: 목록 그리드와 구조가 전혀 다른 대시보드·지갑, 첫 페이지, 전면 리디자인)
  → **시안 루프를 탄다** (아래).

애매하면 새 방향으로 취급한다 (싸게 확인하는 게 낫다). 단 레퍼런스가 이미 있거나 사용자가
"알아서 무난하게"라고 하면 루프를 압축한다 — 상담을 한 바퀴로 줄이거나 시안을 1장만 뽑는다.
루프 전체를 도느냐가 아니라 몇 바퀴를 도느냐가 판단 대상이다.

## 새 방향일 때의 시안 루프

0. `design-interview` 스킬로 **먼저 상담한다** (깊게, 반복). 무드·색·밀도·레퍼런스를
   양식 반복으로 수렴시킨다. 사용자가 디자인 지식이 없어도 답할 수 있는 선택지 양식으로.
   → 결론이 다음 시안의 근거가 된다.
1. (레퍼런스 URL 이 있고 Playwright 연결됐으면) `style-scout` 파견 — 스타일 프로필 수집.
   미연결이면 사용자에게 스크린샷 요청. (0의 상담 중에 병행 가능)
2. `design-drafter` 위임 → `projects/<이름>/docs/design/mockups/<화면명>.html` 시안 생성 (필요시 -a/-b 비교안).
   비즈니스 로직 없는 정적 HTML. design-rules.md 를 근거로.
3. **제출 전 본체가 직접 열어 검증한다** (drafter 보고를 그대로 넘기지 않는다).
   `node scripts/preview.mjs <프로젝트명>` 으로 띄우고 Playwright 로 연다
   (file: 은 Playwright 가 차단하므로 http 로 서빙해야 한다). 확인할 것:
   - **텍스트 대비 4.5:1 실측** — 눈으로 보지 말고 computed style 로 전 요소를 훑어 미달을 뽑는다.
     레퍼런스에서 가져온 색은 배경이 달라지면 그대로 미달되고(회색 카드 위 메타색 등),
     "흐릿하게" 류 요청은 곧장 하한에 부딪힌다. **안 재면 미달인 채로 승인된다.**
   - 렌더 자체(폰트 로드·콘솔 에러)와 스크린샷 1~2장
   - 실측값은 승인 시 design-rules.md 에 남긴다 — 다음 화면이 그 하한을 물려받는다
4. **[checkpoint]** 시안을 브라우저로 열어보게 안내하고 승인받는다(같은 미리보기 URL 을 그대로 알려준다).
   피드백이 있으면 drafter 에 재위임(원문 전달). 코드가 아니라 시안을 버리며 반복한다.
5. 승인되면:
   - 새로 확정된 시각 기준을 `projects/<이름>/docs/design/design-rules.md` 에 한 블록 추가
     (날짜 · 화면명 · checkpoint 승인 · 톤/색/형태/타이포/레이아웃)
   - 파일 상단에 프론트매터 `status: approved` 를 둔다 — 게이트(design/BEFORE_UI)가 이걸 보고
     pages/widgets 구현을 허용한다. 없으면 화면 작업이 차단된다.
   - `projects/<이름>/src/shared/ui/tokens.css` 에 새 토큰이 필요하면 추가
6. **그다음에야 구현.** 승인된 시안 HTML 을 시각 스펙 삼아 projects/<이름>/src/ 에 실제 컴포넌트를 만든다.
   구현물은 게이트(FSD·접근성)와 ui-reviewer 로 검증된다.

## 왜 이 순서인가
v2 기본은 "코드로 만들어 checkpoint" 인데, 새 방향에서는 구현물을 버리며 반복하게 되어
비싸다. 시안(mockup)은 버려도 싸므로, 새 방향에 한해 checkpoint 를 **코드 앞으로 당긴다.**
반복 화면은 이 비용이 없으므로 시안 없이 바로 구현한다.

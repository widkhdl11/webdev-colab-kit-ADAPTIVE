# 06. qa — 얕고 결정론적인 검증

## Purpose
매 턴 자동으로 도는 값싼 검증층. 테스트가 green 이고 approved 스펙의 INV가 전부 테스트에 참조되는지만 본다. 깊은 판단(리뷰)은 review 노드로 미루고, 여기서는 빠른 루프를 유지한다 [(graph.mjs:67-68)](../../graph.mjs#L67-L68).

## Entry condition
implement 가 clean 이고 qa 가 dirty 일 때 [(graph.mjs:70)](../../graph.mjs#L70). implement 가 dirty 면 전파로 qa 도 dirty 이므로 순서가 뒤집히지 않는다.

## What it does
1. Stop 훅이 `run-gates` 전체(=`--quick` 아님)를 돌린다 [(graph-stop.mjs:210)](../../gates/graph-stop.mjs#L210).
2. 프로젝트마다 `npm test --silent` 실행, 실패하면 `[test/FAIL]` 로 마지막 800자를 붙인다 [(run-gates.mjs:255-270)](../../gates/run-gates.mjs#L255-L270).
3. `spec-coverage.mjs` 가 approved 스펙의 `INV-*` 를 모아 테스트 텍스트에서 참조를 찾는다 [(spec-coverage.mjs:29-60)](../../gates/spec-coverage.mjs#L29-L60).
4. 실패가 있으면 graph-stop 이 "분류기 필요" 신호를 출력한다 [(graph-stop.mjs:252-256)](../../gates/graph-stop.mjs#L252-L256).

## Gate
`clean_when: { gate: ["test", "spec-coverage"] }` [(graph.mjs:72)](../../graph.mjs#L72).
- `[test/FAIL]` 는 프로젝트 단위 에러라 경로 매칭 없이 노드를 통째로 막는다 [(graph-stop.mjs:142-146)](../../gates/graph-stop.mjs#L142-L146).
- `[spec-coverage/MISSING_TEST]` 는 스펙 파일 경로로 보고되므로 spec 노드에도 함께 걸린다.
- 통합 테스트는 기본 `npm test` 에서 분리해야 한다 — 네트워크 장애로 게이트가 비결정적으로 실패하는 것을 막기 위해서다 [(rules/tdd.md:12-15)](../../.claude/rules/tdd.md#L12-L15).

## Failure path
1. graph-stop 이 `↩ qa dirty + 검증 실패 — 분류기(qa-classifier) 필요` 를 출력한다 [(graph-stop.mjs:254-256)](../../gates/graph-stop.mjs#L254-L256).
2. `qa-classifier` 를 파견해 `{level, reason, evidence}` 를 받는다 [(CLAUDE.md:83)](../../CLAUDE.md#L83).
3. 레벨별 행동: impl → 코드 수정 / design → design-rules 를 draft 로 / spec → 해당 스펙을 draft 로 [(CLAUDE.md:84-86)](../../CLAUDE.md#L84-L86).
4. `spec-level` 이거나 위험 표면이면 등급과 무관하게 사용자에게 먼저 보고 [(CLAUDE.md:87-88)](../../CLAUDE.md#L87-L88).

## Exit condition
`npm test` 가 green 이고 spec-coverage 에러가 0건. qa 는 결정론 게이트라 조건을 만족하면 **그 턴에 자동으로** clean 이 된다.

## Unverified
- **produces 글롭이 `.test.tsx` 를 놓친다** — `src/**/*.test.ts` 는 signal 의 테스트 9개 중 `.tsx` 4개를 잡지 못한다. 그 파일만 고치면 qa 해시가 변하지 않는다 (findings F10). [CONFIRMED: graph.mjs:71 + globToRegex 실측]
- **`tests/**` 디렉터리** — 규칙은 통합 테스트를 여기 두라고 하지만 signal 에는 존재하지 않는다. [CONFIRMED: 부재]
- **test-auditor 파견 시점** — "테스트 작성 후"라는 서술뿐, 자동 트리거가 없다. [INFERRED]
- **분류기가 실제로 파견되는지** — 스크립트는 신호만 출력하고 파견은 모델·사용자의 몫이다. [INFERRED]

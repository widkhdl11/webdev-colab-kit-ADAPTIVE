# 서브에이전트 작업 지시 양식 (구현·리뷰 반영)

2026-10-12 사용자 지시로 만들었다. 구현 서브에이전트 한 번(61분)을 실행 기록으로 집계해 보니,
도구 128회 가운데 코드 찾기·파일 보기가 69회였다. 지시에 경로를 미리 넣어 이 탐색을 줄이는 것이 목적이다.
리뷰어 파견(읽기 전용)에는 쓰지 않는다 — 구현·반영처럼 코드를 바꾸는 위임에만 쓴다.

목적:            무엇을 왜 바꾸나 (결정 번호·스펙 INV)
수정 대상 파일:   경로 목록
따라야 할 패턴 파일: 같은 일을 이미 하고 있는 파일 경로 (마이그레이션·화면·시험 각각)
관련 시험 파일:   바꾼 모듈을 import 하는 시험 + 바꾼 DB 테이블을 건드리는 시험 전부
관련 DB 테이블:   읽거나 쓰는 테이블·함수 이름
  ※ 위 네 칸은 시작점이며 범위가 아니다. 바꾼 함수의 호출처 검색은 직접 한다.

미룬 문서:        약관·처리방침·스펙 수정은 이 묶음에서 하지 않고 고칠 곳만 목록으로 보고한다(DECISIONS 는 결정 시점에 바로 적는다).

## 「같이 바꾸는 곳」은 비워 두고 넘기지 않는다

2026-11-14 사용자 지시로 넣었다. 지시문을 쓰는 본체가 `.claude/rules/change-scope.md` 로 찾은 「반드시 같이」 목록을 그대로 옮긴다.
「제안」 목록은 넣지 않는다 — 서브에이전트가 고칠 범위가 아니다.
찾아봤는데 없으면 「없음」이라고 적는다. 빈칸과 「없음」은 다르다: 빈칸은 찾지 않았다는 뜻이고, 「없음」은 찾아본 결과다.
계기: 같은 날 설정 화면 재디자인을 시안 두 장 범위로만 맡겨, 그 화면으로 들어가는 사이드바와 옮겨진 칸의 옛 주소를 아무도 보지 않았다.

## 「관련 시험」을 좁게 고르지 않는다

「관련」은 바꾼 모듈을 import 하는 시험과 바꾼 DB 테이블을 건드리는 시험 **전부**다.
시간을 아끼려고 그중 몇 개만 고르면, 전체 실행을 사인오프까지 미룬 만큼 회귀가 늦게 드러난다.

로그인 키로 부를 수 있는 DB 함수를 새로 만들거나 바꾸면, 그 함수를 import 하지 않아도 **DB 전체를 훑는 검사**(팬꾹: `pii-exposure-check` — 로그인 키 함수가 개인정보 구역에 닿는지)를 관련 시험에 넣는다.
2026-10-12: 크리에이터 확인 답 함수가 공통 정리 함수를 거쳐 개인정보 구역에 닿았는데, 이 검사가 관련 목록에 없어 구현·반영 두 번을 지나 사인오프 전체 실행에서야 잡혔다.

## 칸을 비워 두면 막는 검사는 아직 없다

칸이 채워졌는지 기계로 보는 검사는 일부러 만들지 않았다(「같이 바꾸는 곳」도 마찬가지다 — 비워 두지 않는 것은 위 절의 규칙으로 지킨다). 다음 문제집의 첫 구현 묶음에서
AI 시간·도구 시간·호출 횟수(탐색 호출 따로)를 이번 기준(61분 = AI 43분 + 도구 18분, 128회, 탐색 69회)과
비교한 뒤 사용자가 정한다.

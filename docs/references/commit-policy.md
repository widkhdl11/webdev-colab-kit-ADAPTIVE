# 커밋 규약 — 언제 끊고 무엇을 한 덩어리로 묶나

커밋을 언제 끊을지·어떻게 나눌지·push 할지는 **`auto-decide` 등급**이다(결정층 2절의 살림 판단).
물어서 정하지 않는다. 이 문서는 그 자동 결정이 매번 같은 모양으로 나오게 하는 기준이다.

기준이 없으면 자동 결정이 곧 제멋대로가 된다 — 어떤 턴은 스무 파일이 한 커밋에 들어가고
어떤 턴은 안 들어간다. 그러면 나중에 "무엇을 되돌릴까"를 커밋 단위로 고를 수 없다.

## 언제 끊나 (트리거)

넷이다. 이 중 하나가 성립하면 그 자리에서 커밋한다.

| 트리거 | 무엇이 끝났을 때 |
|---|---|
| 항목 `done` | 요청 항목(`request.json` 의 `items`) 하나가 끝났다 |
| 킷 작업 종료 | 그래프 밖 작업(검사 추가·문서 규약·스킬 수정) 하나가 끝났다 |
| 사인오프 | `review.md` 에 `status: passed` 를 적었다 |
| 사이클 닫힘 | 사이클 리포트를 발행하고 `CYCLE.md` 의 줄을 옮겼다 |

트리거가 없으면 커밋하지 않는다. "턴이 끝났다"는 트리거가 아니다 — 턴은 작업의 단위가 아니라
대화의 단위라서, 그것으로 끊으면 커밋이 작업과 아무 관계가 없어진다.

## 조건 — 통과한 것만 커밋한다

- `node gates/run-gates.mjs` 가 통과한다.
- 이번에 손댄 부품의 계약 테스트가 통과한다(`@check-guards` 가 그 경로를 가리키는 검사).

실패한 상태는 커밋하지 않는다. 실패를 커밋하면 그 커밋으로 되돌아가는 것이 복구가 아니게 된다.

## 한 커밋 = 한 부류

부류는 넷이다.

| 부류 | 무엇 | 예 |
|---|---|---|
| 제품 코드 | `projects/<이름>/src/**`, 마이그레이션, 설정 | `feat(feed): …` |
| 스펙·문서 | `projects/<이름>/docs/**` | `docs(spec): …` |
| 과정 기록 | `projects/<이름>/workspace/**`, `report/**` | `chore(wrap-up): …` |
| 킷 | 루트의 `scripts/`·`docs/`·`.claude/`·`.agents/` | `feat(kit): …` |

- **같은 턴에 여러 부류를 고쳤으면 커밋도 그만큼 나눈다.** 섞으면 "제품을 되돌리려다 킷 수리까지
  되돌아가는" 일이 생기고, 그걸 피하려면 커밋 하나를 손으로 쪼개야 한다.
- **요청 밖 작업은 언제나 별도 커밋이다.** 요청 안의 것과 같은 부류여도 따로 끊는다. 요청 밖이라는
  사실이 커밋 목록에서 보여야, 나중에 "왜 이게 여기 들어왔나"를 물을 자리가 생긴다.

## 메시지

기존 관행 그대로다 — `type(scope): 무엇 — 왜` 한 줄. 본문에는 **항목 id 와 결정 id** 를 적는다.

```
feat(ingest): 수집 목적지 호스트를 소스 목록으로 제한 — 내부 주소를 받아 오는 길을 막는다

- 항목: ingest-auth INV-G1
- 결정: signal-20260920-1-d2 (사용자 답: 착수해)

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: <이 세션 링크>
```

id 를 적는 이유는 커밋에서 "왜"로 거슬러 갈 수 있게 하려는 것이다. 커밋 메시지 한 줄에 이유를
다 적으려 하면 한 줄이 문단이 된다.

## 보호 파일은 커밋에 넣지 않는다

`gates/`·`graph.mjs`·`.claude/hooks/`·`.claude/settings.json`·`docs/LESSONS.md` 는 사용자가 직접
붙이는 파일이다. **붙이는 것이 사용자 몫이면 커밋도 사용자 몫이다** — 에이전트가 커밋해 버리면,
사용자가 아직 읽지 않은 변경이 이력에 사용자 이름으로 들어간다.

`git add` 에서 빼고, **미커밋으로 남아 있다는 것을 보고에 한 줄로 적는다.** 조용히 빼면
"왜 내 작업 트리가 안 깨끗하지"가 남는다.

**예외 하나 — 사용자가 이미 붙인 것은 커밋한다.** 위 규칙이 막으려는 것은 「사용자가 아직
읽지 않은 변경이 이력에 들어가는 것」이다. 사용자가 직접 붙였으면 그 전제가 깨진다.
판정은 말이 아니라 검사로 한다 — 그 패치의 확인 검사가 통과하면 붙은 것이고, 커밋 메시지에
그 결과를 적는다(예: `check-hash-newline 4/4`). 검사가 없는 보호 파일 변경은 이 예외를
쓰지 않는다.

## push 는 사이클이 닫힐 때

항목마다 올리지 않는다. 사이클 리포트를 발행하는 자리에서 한 번 올린다 — 그때가 "이 지시에 대해
한 덩어리가 끝났다"가 성립하는 유일한 지점이다.

**push 자체는 `auto-decide` 다.** 물어서 정하지 않는다.

**`escalate` 인 것은 이미 올라간 것을 바꾸는 일이다** — push 된 커밋의 amend, 이력 재작성,
force push. 남이 이미 받아 갔을 수 있는 것을 바꾸는 일이라 되돌릴 수 없다. 카드로 올린다.

# 2026-09-24 — 자율 실행 루프의 보호 파일 패치 (잠금 훅 · 대화 길이 훅)

보호 파일 **셋**을 고친다. 새 훅 파일 둘(`.claude/hooks/`)과 그 둘을 등록하는 `.claude/settings.json`.
붙일 파일은 이 문서 옆 폴더에 있다: `docs/references/pending-patches/2026-09-24-run-loop/`.
정본: docs/references/run-loop.md (2절 잠금 · 7절 대화 길이).

권한 허용 목록(G)은 이 패치에 없다 — 킷 시험에서 실제로 쓴 도구 목록이 나온 뒤 따로 올린다.

## 무엇이 바뀌나

1. **루프가 도는 동안 대화 세션이 제품 파일을 못 고친다.** 살아 있는 루프 잠금(`projects/<이름>/report/loop.lock`)이
   있으면 그 프로젝트의 제품 파일(`docs/`·`workspace/`·`report/` 를 뺀 곳) 편집과 셸 쓰기, git 의 색인·브랜치를
   바꾸는 명령(add·commit·stash·reset·checkout 등)을 막는다. 킷 파일·프로젝트 docs·카드 답은 된다.
   루프 자신의 회차는 환경 변수 `KIT_RUN_LOOP` 로 구별해 막지 않는다. 잠금이 남았는데 프로세스가 없으면 막지 않는다.
   - git 명령까지 막는 것은 설계 A 에 없던 것을 더한 것이다. 이유: 루프 회차가 커밋하는 사이에 대화 세션이 커밋하면
     어느 커밋이 어느 항목 것인지 섞인다 — 설계가 잠금을 둔 이유 그대로다. 과하면 이 줄만 빼면 된다.
2. **대화가 길어지면 알린다.** 매 턴 끝에 대화 파일의 마지막 응답 사용량(입력 + 캐시 읽기 + 캐시 생성)으로 지금
   컨텍스트 크기를 잰다. 기준(기본 120k, 루프 설정 `session_warn_tokens`)을 넘으면 항목 경계에서는
   「항목 완료 · 새 세션 권장」을 보이고 대시보드 특이사항에 띄운다. 항목 중간이면 알리기만 한다. 턴은 막지 않는다.

## 적용 전 판정 (지금 돌리면 실패한다)

```
node scripts/check-loop-hooks.mjs
```

지금 나오는 것: `실패 22/22` — 설치 2 · 등록 2 · 잠금 동작 10 · 길이 동작 8 이 전부 ✗ (훅 파일이 없어서).
붙이고 나면 **22/22 통과**다.

붙이기 전에 패치 폴더 파일로 동작만 먼저 볼 수 있다: `node scripts/check-loop-hooks.mjs --staged` → 18/18 통과(2026-09-24 확인).

검사는 설치된 훅을 **임시 폴더에 복사해** 가짜 프로젝트·가짜 잠금·가짜 대화 파일로 돌린다. 진짜 레포에 잠금을 심지 않는다.
막혀야 할 것(심은 위반)과 통과해야 할 것을 같이 본다 — 「전부 막는 훅」도 「아무것도 안 막는 훅」도 실패한다.

## 붙이는 순서 (이 순서로)

**1. 훅 파일 둘을 복사한다** (먼저 — 이유는 아래 부분 적용 표)

```
cp docs/references/pending-patches/2026-09-24-run-loop/loop-lock.mjs .claude/hooks/loop-lock.mjs
cp docs/references/pending-patches/2026-09-24-run-loop/session-size.mjs .claude/hooks/session-size.mjs
```

**2. `.claude/settings.json` 에 등록한다**

`hooks.PreToolUse` 배열에 한 덩어리를 더한다:

```json
{
  "matcher": "Edit|Write|MultiEdit|NotebookEdit|Bash|PowerShell",
  "hooks": [
    {
      "type": "command",
      "command": "node \"C:/Users/PC/Desktop/dev/webdeb-colab-kit-ADAPTIVE/.claude/hooks/loop-lock.mjs\""
    }
  ]
}
```

`hooks.Stop` 의 기존 덩어리(`graph-stop.mjs` 가 있는 것)의 `hooks` 배열에 한 줄을 더한다:

```json
{
  "type": "command",
  "command": "node \"C:/Users/PC/Desktop/dev/webdeb-colab-kit-ADAPTIVE/.claude/hooks/session-size.mjs\""
}
```

**3. 판정**: `node scripts/check-loop-hooks.mjs` → 22/22.

**4. (에이전트가 할 일)** 붙인 뒤 `scripts/check-loop-hooks.mjs` 머리의 `@check-guards` 에 훅 파일 둘을 더한다.
지금은 파일이 없어서 설정 파일만 지키고 있다(없는 파일을 지키면 등록부가 막는다).

## 부분 적용 조합 (하나씩 확인)

| 붙은 것 | 무슨 일이 일어나나 | 검사 |
|---|---|---|
| 아무것도 | 지금과 같다 | 22 실패 |
| 훅 파일만(등록 안 함) | 훅이 안 돈다 — 동작은 지금과 같다. **안전** | 설치 2 통과 · 등록 2 실패 |
| 등록만(파일 없음) | 매 도구 호출·매 턴마다 node 가 파일을 못 찾아 오류를 낸다. 종료 코드가 2 가 아니라서 **막지는 않지만** 오류 줄이 계속 뜬다. 시끄럽고 보호도 없다 | 설치 2 실패 · 동작 전부 실패 |
| 잠금 훅만(파일+등록) | 잠금만 돈다. 길이 경고는 없다. 서로 독립이라 **안전** | 길이 항목 실패 |
| 길이 훅만(파일+등록) | 경고만 돈다. 잠금 보호는 없다. **안전** | 잠금 항목 실패 |
| 파일을 일부만 고쳐 붙임 | 동작이 반쪽일 수 있다 | 「설치 … 가 패치 폴더의 파일과 같다」 가 잡는다 |

위험한 조합은 없다. 시끄러운 조합은 「등록만」이라서 파일을 먼저 복사한다.

## 알려진 한계

- 셸 쓰기 판정은 명령 문자열을 본다(리다이렉트·sed -i·tee·rm·mv·cp·touch·PowerShell 쓰기 명령). 스크립트 파일을
  만들어 그 안에서 쓰는 식의 우회는 못 잡는다. 목적은 실수로 섞이는 것을 막는 것이지 적대적 우회를 막는 것이 아니다.
- 길이 경고는 턴마다 뜬다(기준을 넘은 동안 계속). 한 번만 띄우는 것은 넘은 뒤 세션을 이어 가는 것을 막지 않으려는 선택이다.

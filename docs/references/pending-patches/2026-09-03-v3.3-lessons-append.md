# 보류 패치 — LESSONS.md 에 v3.3 항목을 덧붙인다 (v3.3 · C단계)

`docs/LESSONS.md` 는 이 킷의 판정 레이어와 같은 취급이라 사용자가 직접 붙인다(v3.2 때와 같음).
붙는 것은 **맨 아래 덧붙이기뿐**이고 기존 문장은 하나도 안 고친다.

## 붙일 것 — `docs/LESSONS.md` 맨 끝에 추가

```markdown
## 2026-09-03 — v3.3: 게이트가 막으려던 일이 게이트 때문에 일어난다 (4번째)

- 증상: 보류 항목을 게이트 실패로 내게 했더니 **모든 편집이 막혔다.** PostToolUse 훅이 편집마다
  `run-gates --quick` 을 돌리고 exit 2 면 편집을 막는데, 보류는 저절로 사라지는 종류가 아니라서
  한 건만 열려 있어도 편집이 영구히 막힌다. **보류를 닫아서 푸는 것조차 편집이라 같이 막혔다.**
  같은 세션에서 한 번 더 났다 — 패치 셋 중 하나만 빠진 상태에서 Stop 훅이 매 턴 차단했고,
  푸는 유일한 길은 보호 파일 편집이라 모델이 할 수 없었다. 열 턴 넘게 같은 메시지만 오갔다.
- 교훈: **새 신고를 게이트에 넣을 때는 그 게이트가 도는 자리를 전부 세어 본다.** 이 레포의
  게이트는 두 자리에서 돈다 — 편집마다(`--quick`)와 턴 끝(전체). 전자는 "지금 고친 코드가
  규칙을 어겼나"를 보고, 후자는 "지금 상태가 다음으로 갈 수 있나"를 본다. 성격이 다르다.
  **저절로 사라지지 않는 조건은 편집 훅에 넣으면 안 된다** — 그것을 없애는 행동이 편집이면
  빠져나올 길이 없어진다. 2026-08-06·08-10·08-11 에 이어 4번째다.
- 근거: 2026-09-03 세션에 2회. 조합표가 "턴이 막힌다"까지는 예측했지만 그 상태에서
  어떻게 나오는지를 안 적어서, 실제로 막혔을 때 세션이 반복에 갇혔다.
- 반영 위치: gates/run-gates.mjs 의 보류 블록을 `if (!QUICK)` 로 감쌈 ·
  scripts/check-pending-kind.mjs 의 A4(`--quick` 에서 신고가 없는지) ·
  다중 파일 패치 문서에 「막혔을 때 빠져나오는 길」 절 (② 게이트 계열 + ③ 조건부 문서).

## 2026-09-03 — v3.3: 검사는 그 코드가 실제로 도는 자리에서 돌려 본다

- 증상: B단계 dry run 이 `graph-stop` 과 `run-gates` **단독 실행**만 봤다. 편집 훅이 도는
  `--quick` 경로를 안 밟아서, 패치가 모든 편집을 막는다는 것을 붙인 뒤에야 알았다.
  dry run 자체는 결함 셋을 잡아낸 좋은 검사였는데도 그랬다.
- 교훈: **같은 코드라도 도는 자리가 다르면 다르게 실패한다.** 검사를 짤 때 "이 코드가
  어디서 불리는가"를 세는 것이 "이 코드가 무엇을 하는가"를 보는 것보다 먼저다.
  훅 설정(`.claude/settings.json`)이 그 목록이다.
- 근거: 1회(2026-09-03). 구조적 빈칸 — dry run 을 설계하는 국면에 호출 자리를 세는 자리가 없었다.
- 반영 위치: scripts/check-pending-kind.mjs 의 A3·A4 를 같은 코드의 반대 방향으로 둠
  (A3 만 있으면 "신고는 되는데 아무것도 못 고치는" 상태가 통과한다) (② 게이트 계열).

## 2026-09-03 — v3.3 정의

**이 버전부터 auto-decide 등급 결정은 실행을 멈추지 않으며, 사람의 판단은 provisional 규칙으로
축적된다.** 되돌리기 싼 결정은 정책 규칙을 근거로 스스로 내리고 로그에 남기며, 되돌리기 비싼
결정은 보류로 올라가되 실행은 계속된다. 같은 판단이 두 번 반복되면 규칙이 되고, 사용자가
뒤집지 않으면 확정된다. 사이클은 사용자 지시 하나이고 계획 승인에서 열려 종료 조건에서 닫힌다.
```

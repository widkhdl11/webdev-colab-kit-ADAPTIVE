## 무엇을 켜는 건가

`report-dashboard` 스킬이 설치한 대시보드의 **3층(활동 로그)** 이다. 세 층 중 둘은 이미 돈다:

- 1층(워크플로우 지도) · 2층(현재 위치와 전환 피드) — **훅 없이 지금도 돈다**
- 3층(툴 호출 기록) — 이 패치가 켠다. 피드의 각 줄을 펼쳤을 때 그 구간에 무슨 파일을
  건드렸는지가 나온다. 지금은 "이 구간의 활동 기록 없음"이 나온다

훅은 `PostToolUse` 에서 돌면서 시각·툴 이름·대상 경로만 한 줄로 덧붙인다.
**모델 컨텍스트에는 아무것도 넣지 않는다 — 토큰 비용 0이다.**

## 부분 적용 — 조합 넷을 하나씩

이 패치는 파일 둘을 고친다(훅 파일 · 설정). 둘 다 붙은 상태만 검사하면 한쪽만 붙은 상태는
아무도 안 본다. 네 조합을 하나씩 적는다.

| 훅 파일 | 배선 | 무슨 일이 일어나나 | 안전한가 |
|---|---|---|---|
| 없음 | 없음 | 지금 상태. 3층만 꺼져 있고 대시보드는 돈다 | 안전 |
| 있음 | 없음 | 아무 일도 안 일어난다. 아무도 그 파일을 안 부른다 | 안전 |
| 없음 | **있음** | **툴 호출마다 stderr 에 모듈 없음 오류가 찍힌다** | 시끄럽다 |
| 있음 | 있음 | 3층이 켜진다 | 안전 |

**위험한 조합은 셋째 하나뿐이고, 작업을 막지는 않는다.** 훅이 종료 코드 1로 죽는데 그 값은
차단이 아니라 경고다(차단은 2다) — 2026-09-14 에 실제로 돌려 확인했다. 증상은 툴을 쓸 때마다
빨간 글자가 붙는 것이고, 훅 파일을 복사하면 바로 멎는다.

**설계로 없애지 못한 이유를 밝힌다.** 이 조합을 아예 불가능하게 만들려면 훅 스크립트를
`scripts/` 처럼 안 지켜지는 폴더에 두면 된다. 그러면 배선이 가리키는 파일이 항상 존재하므로
셋째 줄이 사라진다. 그렇게 하지 않았다 — 매 툴 호출마다 도는 코드를 모델이 승인 없이 고칠 수
있게 되는데, `.claude/hooks/` 를 지키는 이유가 정확히 그것이기 때문이다. **시끄러운 실패를
받고 조용한 우회로를 막는 쪽을 골랐다.** 대신 적용 순서를 ①②로 고정해 그 조합을 안 지나가게 했다.

## 검사가 보는 것 — 여덟 항목

| 항목 | 무엇 | 붙기 전 |
|---|---|---|
| A 파일 | 훅이 `.claude/hooks/` 에 있다 | 실패 |
| B 내용 | 붙은 훅이 정본과 같다(반쯤 낡은 사본을 잡는다) | 실패 |
| C 배선 | `PostToolUse` 가 그 훅을 부른다 | 실패 |
| D 보존 | 기존 훅 일곱이 전부 남아 있다 | 통과 |
| E 중복 | 배선이 두 벌로 안 들어갔다 | 통과 |
| F 프로브 | 정본 훅에 가짜 입력을 넣으면 활동 한 줄이 생긴다 | 통과 |
| G 프로브 | 배선 없는 설정을 「없다」고 판정한다 | 통과 |
| H 계약 | `scripts/check-report.mjs` 가 여전히 통과한다 | 통과 |

**F·G 는 패치와 무관하게 항상 통과해야 하는 항목이다.** 검사가 아예 안 도는 것과 "위반 0건"은
겉이 같아서, 잡을 줄 아는지를 따로 봐야 한다. F 가 실패하면 훅 자체가 고장난 것이고,
G 가 실패하면 C 의 판정이 무효라 "붙었다"는 보고를 믿을 수 없다.

## 이 훅이 안 하는 것

- 모델 컨텍스트에 아무것도 넣지 않는다
- 설치 안 된 프로젝트(`report/` 폴더가 없는)에는 파일을 만들지 않는다
- 입력이 깨졌거나 무슨 일이 나도 종료 코드 0으로 끝낸다 — 관찰하려고 넣은 것이
  관찰 대상을 망가뜨리면 안 된다
- 로그가 무한히 자라지 않는다. 날이 바뀌면 어제치를 `activity-<날짜>.jsonl` 로 옮긴다

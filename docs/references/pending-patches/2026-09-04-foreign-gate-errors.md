# 다른 프로젝트의 실패가 턴을 막는 것을 푼다 (보호 파일 1개)

## 무슨 일이 났나

`projects/study-mate/` 를 들여온 직후 **모든 턴이 막혔다.** 활성 프로젝트는 `signal2` 였고,
막은 것은 `study-mate` 의 보류 2건이었다. 보류는 원래 턴을 막지 않는 종류다.

원인은 두 코드가 범위를 다르게 본다는 것이다.

- `run-gates` 는 `workspace/PENDING.md` 가 있는 **모든 프로젝트**의 보류를 실패로 신고한다.
- `graph-stop` 의 `parseGateErrors` 는 **활성 프로젝트 경로가 아닌 줄을 건너뛴다.**
  다른 프로젝트의 에러는 이 그래프의 판정과 무관하다는 뜻이고, 그 자체로는 옳다.

그래서 실패는 있는데(`run-gates` exit 2) 파싱 결과가 0건이 되고, 차단 판정의 첫 조건

```js
if (gateErrors.length === 0 || blocking.length > 0) {   // 못 파싱했으면 막는다(모르면 막는 쪽)
```

에 걸린다. 보류를 턴 차단에서 낮춰 주는 규칙(`GATE_KIND` 의 `escalated`)은 **파싱된 카테고리에만**
적용되므로 닿지 못한다.

**빠져나오는 길이 사용자 답변뿐인데 그 답을 받으려면 턴이 끝나야 한다.** 게이트가 막으려던 일이
게이트 때문에 일어나는 계열의 5번째다(2026-08-06 · 08-10 · 08-11 · 09-03).

## 무엇을 고치나

`parseGateErrors` 는 그대로 둔다 — 그 판단은 옳고, 다른 프로젝트의 에러가 이 그래프의
release · n/a 취소 · qa 안내에 섞이면 안 된다. 대신 **차단 판정에만 쓰는 목록을 따로 만든다.**

낮추는 기준은 `GATE_KIND` 에 그 카테고리가 있느냐다.

- **있으면 낮춘다.** `GATE_KIND` 에 있다는 것은 "그래프가 처방한 상태에서 비롯된 실패"라는
  뜻인데, 그 판정은 **그 프로젝트의** 노드 상태로 해야 한다. 이 그래프는 활성 프로젝트 것이라
  판정할 근거가 없다. 그리고 그런 실패는 이 턴 안에서 풀 수 있는 것이 아니다.
- **없으면 지금처럼 막는다.** `fsd` · `security` · `tsc` · `test` · `risk-surface` 는 아무 데서나
  나는 위반이고, `graph.mjs` 가 "어디서 나든 무조건 차단한다"고 적어 둔 그대로다.

## 사용자가 붙일 것 — `gates/graph-stop.mjs` 네 자리

### ① `parseGateErrors` 앞에 함수 하나를 더한다

**찾을 것** (183줄 근처):

```js
// ── 게이트 에러 파싱 → { cat, relPath, whole } ─────────────────
function parseGateErrors(text) {
```

**바꿀 것** — 위 두 줄 **앞에** 아래를 넣는다(기존 두 줄은 그대로 둔다):

```js
// 다른 프로젝트에서 난 에러. 이 그래프의 판정(release · n/a 취소 · qa 안내)에는 쓰지 않는다 —
// 6단계 차단 판정에만 쓴다. 안 쓰면 "실패는 있는데 파싱 0건"이 되어 낮춤 규칙이 닿지 못하고,
// 사람의 결정으로만 풀리는 보류가 턴을 영영 막는다(2026-09-04 study-mate 들여오기에서 실제로 났다).
function parseForeignErrors(text) {
  const out = [];
  for (const line of text.split("\n")) {
    const m = line.match(/^\[([a-z-]+)\/[^\]]+\]\s+(.+)$/);
    if (!m) continue;
    const p = m[2].split(" — ")[0].split(" ")[0].split("\\").join("/");
    const pm = p.match(/^projects\/([^/:]+)/);
    if (pm && pm[1] !== active) out.push({ cat: m[1], project: pm[1] });
  }
  return out;
}
```

## 판정 — 코드를 안 읽고 확인하는 법

```
node scripts/check-foreign-gate-errors.mjs
```

| | 무엇 | 붙기 전 | 붙은 뒤 |
|---|---|---|---|
| A | 다른 프로젝트의 보류만 남으면 턴이 끝난다 | **실패** | 통과 |
| B | 다른 프로젝트의 진짜 위반은 여전히 막는다 | 통과 | 통과 |
| C | 활성 프로젝트의 보류는 지금처럼 낮춰진다 | 통과 | 통과 |
| D | 패치를 적용한 **사본**에서 A 가 통과하고 B 도 유지된다 | 통과 | (생략) |

**붙기 전 3/4 → 붙은 뒤 4/4 · exit 0** 이면 붙은 것이다.

- **D 가 이 검사의 핵심이다.** 보호 파일이라 붙기 전에는 A 를 통과시킬 수 없는데, 그러면
  "이 패치가 실제로 고치는지"를 아무도 확인하지 못한 채 붙이게 된다. D 는 패치를 적용한
  사본을 임시 폴더에 만들어 거기서 A·B 와 같은 판정을 돌린다. 사본은 이 문서의 ①~④ 와 같은
  문자열 치환으로 만든다 — 검사가 들고 있는 패치와 이 문서의 패치가 같은 것이다.
- **B 가 A 와 각도가 다르다.** 이 패치는 차단을 **푸는** 변경이라 실패 방향이 과통과다.
  A 만 보면 "전부 통과시키는" 고장난 패치도 초록불이다. B 는 다른 프로젝트에 `eval(` 을 심어
  그래도 막히는지 본다.
- 검사는 전부 임시 디렉터리에서 돈다. 이 레포의 파일은 하나도 안 건드린다.

**검사하지 않는 것**: "에러를 하나도 못 파싱했으면 막는다"는 분기 자체는 픽스처로 만들 수 없다
(`run-gates` 가 exit 2 를 내면서 대괄호 줄을 하나도 안 내는 상태를 만들 방법이 없다).
그 분기는 이 패치가 건드리지 않는다 — 바뀌는 것은 조건의 왼쪽 절뿐이다.

## 부분 적용 조합

파일 둘을 고친다. `scripts/check-foreign-gate-errors.mjs` 는 보호 파일이 아니라 **커밋으로 먼저**
들어가고, `gates/graph-stop.mjs` 만 사용자가 붙인다. 그래서 실제로 생기는 조합은 ①②④뿐이다.

| 조합 | 상태 | 무슨 일이 일어나나 |
|---|---|---|
| ① 둘 다 없음 | 패치 전 | 지금까지와 같다. 다른 프로젝트에 열린 보류가 있으면 턴이 막힌다 |
| ② `scripts/` 만 | **이 커밋 직후** | 검사가 3/4 로 실패한다(exit 2). 이 검사를 부르는 훅이 없으므로 **턴을 막지 않는다.** 손으로 돌렸을 때만 빨간불이고, 그게 "설정을 붙여라"라는 뜻이다 |
| ③ `gates/` 만 | 이 커밋을 받기 전에 훅만 고쳤을 때 | 동작은 고쳐진다. 검사가 없으니 고쳐졌다는 근거만 없다 |
| ④ 둘 다 | 패치 후 | 검사 4/4 · exit 0 |

**어느 조합에서도 안전하게 실패한다.** ③ 이 위험하지 않은 이유는 이 패치가 **차단을 푸는**
변경이고 푸는 범위가 `GATE_KIND` 에 있는 카테고리로 한정돼 있어서다 — 진짜 위반은 ③ 에서도
그대로 막힌다(B 가 보는 것이 그것이다).

## 막혔을 때 빠져나오는 길

패치를 붙이다 중간에 문법이 깨지면 Stop 훅이 아예 못 돈다. 그러면 `graph-stop` 이 출력을 하나도
안 내는데, 겉으로는 "배선이 안 됐다"와 구별되지 않는다.

```
node --check gates/graph-stop.mjs      # 문법만 본다
git checkout gates/graph-stop.mjs      # 패치 전으로 되돌린다(커밋 전이라면)
```

되돌리면 원래 상태(다른 프로젝트 보류가 턴을 막는 상태)로 간다. 그 상태에서 턴을 끝내려면
그 프로젝트의 `## 열린 항목` 을 비우면 된다 — `projects/study-mate/workspace/PENDING.md` 가
지금 그렇게 되어 있고, 왜 그렇게 뒀는지도 그 파일에 적혀 있다.

## 붙인 뒤 되돌릴 것

`projects/study-mate/workspace/PENDING.md` 의 두 항목을 `## 열린 항목` 으로 되돌린다
(`blocks:` 줄을 다시 붙인다). 지금 그 항목들이 밖에 나가 있는 것은 이 결함 때문이지
그 자리가 맞아서가 아니다 — 되돌려도 턴이 막히지 않는 것이 이 패치가 붙었다는 또 하나의 신호다.

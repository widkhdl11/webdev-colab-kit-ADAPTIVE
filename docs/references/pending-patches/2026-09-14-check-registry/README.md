## 무엇을 고치나

`scripts/check-*.mjs` 스물아홉 개의 호출처를 전부 훑었더니, 게이트가 매번 부르는 것은
다섯이었다 — client-server-import · cycle-policy · exempt-expiry · hooks · mirror-sync.
나머지 스물넷은 사람이 손으로 쳐야만 돈다.

스물넷이 전부 죽은 코드는 아니다. 일부는 패치가 듣는지 증명하려고 쓴 도구고, 일부는 매 턴
지켜야 하는데 아무도 안 부르는 것이다. **문제는 파일만 봐서 둘이 구별되지 않는다는 것이다.**
그래서 "검사를 만들었다"는 기록(LESSONS.md 열다섯 군데)이 "그 검사가 지금도 돈다"처럼 읽힌다.
이 레포가 이미 두 번 겪은 모양이다 — 훅이 죽어 있던 2026-08-16, 하네스가 통째로 꺼져 있던 2026-09-06.

패치가 하는 일은 하나다. 게이트 전체 실행 끝에 `scripts/check-registry.mjs --changed` 를 부른다.

## 등록부가 보는 것

각 검사는 파일 상단에 자기 역할을 한 줄로 선언한다. **스물아홉 개 전부 이미 달아 뒀다.**

```
// @check-role: standing    게이트·훅·스킬이 기계로 부른다. 부르는 곳이 없으면 실패
// @check-role: on-change   지키는 하네스 파일이 바뀐 턴에만 돈다. @check-guards 필수
// @check-role: manual      사람이 필요할 때 부르는 도구. @check-why-manual 필수
// @check-role: pending     상시로 올려야 하는데 아직 배선 안 됨. @check-backlog 필수
```

standing 이 아닌 역할은 전부 **자기를 정당화하는 줄을 하나 더** 요구한다. 안 그러면 역할
이름이 "안 돌아도 되는 이유" 자리를 공짜로 메운다.

지금 분포 — standing 9 · on-change 18 · manual 2 · pending 1.

게이트가 실패로 올리는 것 여덟:

| 코드 | 무엇 |
|---|---|
| `NO-ROLE` | 역할 선언이 아예 없다 (새로 만든 검사가 여기 걸린다) |
| `BAD-ROLE` | 모르는 역할 값 |
| `UNWIRED` | standing 인데 부르는 곳이 없다 — 매번 돈다고 적힌 검사가 안 돈다 |
| `NO-GUARDS` | on-change 인데 무엇이 바뀔 때 도는지 안 적었다 |
| `DEAD-GUARD` | 지킨다고 적힌 파일이 없다 — 대상이 사라졌으면 검사도 낡은 것이다 |
| `NO-WHY` | manual 인데 게이트에 안 올리는 이유가 없다 |
| `NO-BACKLOG` | pending 인데 근거가 될 백로그 항목을 안 가리킨다 |
| `LOST-BACKLOG` | 가리킨 백로그 항목이 harness-backlog.md 에 없다 |

`pending` 건수는 **오류가 아니라 알림**으로 뜬다. 스물넷을 하루에 다 배선할 수 없고, 전부
오류로 띄우면 상수가 된 경고가 되어 아무도 안 본다.

그리고 `--changed` 는 대조만 하지 않는다. 이번에 바뀐 하네스 파일(`git status`)을 지키는
on-change 검사를 **실제로 돌린다**. 보통 0건이고 `gates/` 를 고친 턴에만 한둘이 돈다.

## 붙이는 중에 하나 걸렸다 — 재귀

처음 붙였을 때 게이트가 **6분이 지나도 안 끝났다.** on-change 검사 여럿은 픽스처 레포를
만들어 그 안에서 게이트를 돌리는데, 픽스처가 킷을 통째로 복사하면 그 게이트가 다시 등록부를
부르고 등록부가 또 on-change 검사를 돌린다 — 서로를 부르며 끝나지 않는다.
`check-mirror-sync` 가 `--repo-only` 로 피해 둔 것과 같은 함정이었다.

빗장은 환경 변수 하나다. 등록부가 검사를 띄울 때 `HARNESS_CHECK_NESTED=1` 을 넘기고, 그 값이
있으면 `--changed` 를 **선언 대조까지만**으로 낮춘다. 깊이가 1로 묶인다. `--probe` 에 이 빗장을
확인하는 항목을 넣었다 — **빗장이 풀리면 증상이 "느리다"로만 보여서, 검사가 없으면 아무도
원인을 못 찾는다.**

같이 고친 것 하나 더: 검사 스크립트가 없는 폴더에서는 등록부가 **조용히 통과**한다. 픽스처
레포에서 걸리면 이 등록부가 남의 검사를 깨뜨린다.

## 부분 적용 조합

파일 둘이 바뀐다 — `gates/run-gates.mjs`(사용자가 적용) 와 `scripts/check-registry.mjs`(이미 있음).
**어느 조합에서도 안전하게 실패한다.**

| 조합 | 무슨 일이 일어나나 | 안전한가 |
|---|---|---|
| 스크립트만 (지금 상태) | 게이트 판정은 전과 똑같다. 손으로 `node scripts/check-registry.mjs` 를 쳐야만 돈다 | 안전 — 지금과 같다 |
| run-gates 패치만, 스크립트 삭제됨 | `⚠ [registry/SKIP] scripts/check-registry.mjs 가 없다` 를 찍고 넘어간다. 나머지 게이트는 그대로 판정 | 안전 — mirror·hooks 블록과 같은 방식 |
| 둘 다 | 등록부가 매번 돈다. 지금 레포 상태에서는 통과(배선 대기 1건 알림) | 의도한 상태 |
| 둘 다 + 역할 없는 검사를 새로 만듦 | `[registry/NO-ROLE]` 로 게이트가 막는다 | 의도한 상태 |

**빠져나오는 길**: 등록부가 못 고칠 이유로 막으면 `git checkout gates/run-gates.mjs` 로 블록을
떼면 된다. 다른 판정에 영향이 없으므로 떼도 나머지 게이트는 그대로 돈다.

## 이 패치가 보증하지 않는 것

- **`on-change` 로 분류한 것이 정말 그 파일만 지키는지는 사람의 판정이다.** 등록부는 적힌 파일이
  존재하는지만 본다. 분류가 틀리면 안 돌아야 할 때 돌거나, 돌아야 할 때 안 돈다.
- **`manual` 은 여전히 아무도 안 부른다.** 달라진 건 "안 부르는 이유가 파일에 적혀 있다"는 것뿐이다.
- 등록부는 `scripts/check-*.mjs` 만 본다. 다른 이름의 검사 도구는 이 판정 밖이다.

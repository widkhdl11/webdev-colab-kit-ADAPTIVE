# `check-hooks` 를 `.claude/` 편집에 자동으로 붙인다 (보호 파일 1개)

`check-hooks` 는 **도구는 있고 트리거가 없었다.** 손으로 돌려야 해서, 2026-08-16 에 보호 5개 중
4개가 죽어 있던 것을 한참 뒤에야 발견했다 — 훅은 등록돼 있었고, 실행도 됐고, 그냥 통과시켰다.

자동 실행을 미뤄 둔 이유는 하네스 백로그에 적혀 있다: *"아직 하네스를 엔지니어링하는 중이라*
*`.claude/` 를 자주 만지는데, 편집마다 2초짜리 검사가 붙으면 작업이 느려진다."* 승격 트리거는
*"하네스 변경이 잦아드는 시점이 오면"* 이었고, **2026-09-04 에 사용자가 그 시점을 선언했다**
(v3.3 이 닫히고 제품 작업으로 넘어간다). 보류 이유의 전제가 깨졌으므로 붙인다.

**왜 편집 대상이 `.claude/` 일 때만 도나**: 전체 검사가 2.4초다(실측). 모든 편집에 붙이면
제품 코드를 고칠 때마다 그 값을 낸다. `.claude/` 밖은 86ms 만에 조용히 빠져나온다(실측).

**왜 `check-hooks.mjs` 안이 아니라 새 파일인가**: settings.json 이 부르는 명령은 훅 페이로드를
stdin 으로 받는데, `check-hooks` 는 사람이 손으로도 부르는 검사기다. 한 파일이 두 호출 규약을
들면 어느 쪽으로 불렸는지에 따라 동작이 갈린다.

**실패 방향**: 입력을 못 읽거나 대상이 `.claude/` 밖이면 아무 말 없이 통과한다. 편집 뒤에 도는
훅이라 여기서 막아 봐야 편집은 이미 끝났고, 시끄러우면 사람이 훅을 뗀다. 반대로 검사가 실제로
실패했으면 종료 코드 2 로 올린다 — 그때는 조용하면 안 되는 자리다.

**이 패치는 잡는 범위를 넓히지 않는다.** `check-hooks` 가 보던 것을 그대로 보고, 언제 보는지만
바뀐다. 사용자가 손으로 적용하는 보호 파일 패치(`gates/`·`graph.mjs`)는 도구를 거치지 않으므로
PostToolUse 가 뜨지 않는다 — 그 경로는 여전히 손으로 돌려야 한다.

---

## 붙이기 전에 — 지금 상태

```
node scripts/check-hooks.mjs      → 61/62  (exit 2)
```

실패 한 건이 정확히 이 패치가 고치는 자리다:

```
✗ 자동 실행 배선 — PostToolUse 가 scripts/check-hooks-on-edit.mjs 를 부른다
  — 빠진 도구: Edit, Write, MultiEdit — 그 도구로 .claude/ 를 고치면 검사가 안 돈다
```

**붙인 뒤 62/62 · exit 0 이 되면 붙은 것이다.** 파싱 검사 대상도 13 → 14개로 는다
(settings.json 이 부르는 스크립트 목록에서 뽑기 때문에, 배선이 붙어야 새 파일이 그 목록에 들어온다).

이 판정이 "안 돌아서 초록"인 상태와 구별되는지는 같이 붙는 프로브 셋이 본다:

- **배선 프로브** — 배선을 지운 설정 사본을 같은 판정 함수에 넣어 **실패로 잡히는지** 본다.
- **실행 프로브** — `check-hooks-on-edit` 을 실제로 돌린다. 프로젝트 소스 경로는 출력 0자로
  빠져나가고, `.claude/` 경로는 실제로 검사를 돌린다.
- **실패 전달 프로브** — 임시 디렉터리를 작업 폴더로 둬서 검사가 실패하게 만들고, 그때
  `check-hooks-on-edit` 이 종료 코드 2 로 올리는지 본다(실패를 삼키지 않는지).

프로브는 전부 **임시 폴더**에서 돈다. 이 레포의 파일은 하나도 건드리지 않는다
(2026-09-04: 진짜 파일을 심었다 되돌리는 프로브가 끊기면 손상이 남고, 다음 실행이 그 손상을
원본으로 읽어 "복원 성공"이라고 보고한다).

## 사용자가 붙일 것 — `.claude/settings.json` 한 곳

`PostToolUse` 의 **이미 있는 항목**에 훅 하나를 덧붙인다. 새 항목을 만들지 않는다 — 같은
`matcher` 를 두 번 선언했을 때 훅 엔진이 어떻게 처리하는지는 재 본 적이 없고, 이미 도는
자리에 얹으면 그 미지가 없다.

**넣기 전** (파일 끝쪽, `"Stop"` 바로 위):

```json
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [{ "type": "command", "command": "node gates/run-gates.mjs --quick" }]
      }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "node gates/graph-stop.mjs" }] }
    ]
```

**넣은 뒤** (바뀌는 것은 `hooks` 배열 한 줄이 두 줄이 되는 것뿐):

```json
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          { "type": "command", "command": "node gates/run-gates.mjs --quick" },
          { "type": "command", "command": "node scripts/check-hooks-on-edit.mjs" }
        ]
      }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "node gates/graph-stop.mjs" }] }
    ]
```

`run-gates` 를 앞에 두는 이유는 그것이 편집을 막는 게이트이기 때문이다. 이 검사는 뒤에서
보조로 돈다.

## 부분 적용 조합 — 넷을 하나씩 확인했다

패치가 파일 둘을 고친다. `scripts/` 쪽 둘(`check-hooks-on-edit.mjs` 신규 ·
`check-hooks.mjs` 의 ④군)은 보호 파일이 아니라 **커밋으로 먼저 들어간다**. `settings.json` 만
사용자가 붙인다. 그래서 실제로 일어나는 조합은 ①②④뿐이고, ③은 이 커밋을 받기 전에
설정만 고쳤을 때만 생긴다.

| 조합 | 상태 | 무슨 일이 일어나나 |
|---|---|---|
| ① 둘 다 없음 | 패치 전 | 지금까지와 같다. `check-hooks` 는 손으로 돌린다. 58/58 |
| ② `scripts/` 만 | **이 커밋 직후** | `check-hooks` 가 61/62 로 **실패**한다(exit 2). 그런데 이 검사기를 부르는 훅이 아직 없으므로 **턴을 막지 않는다.** 손으로 돌렸을 때만 빨간불이고, 그 빨간불이 "설정을 붙여라"라는 뜻이다 |
| ③ `settings.json` 만 | 커밋 없이 설정만 | `node scripts/check-hooks-on-edit.mjs` 가 `MODULE_NOT_FOUND` 로 종료 코드 **1** 을 낸다(실측). 편집마다 에러가 한 번씩 뜨고, 메시지가 없는 파일 이름을 그대로 가리킨다. **시끄럽지만 조용히 틀리지는 않는다** |
| ④ 둘 다 | 목표 | 62/62 · exit 0. `.claude/` 편집에 2.4초, 그 밖에는 86ms |

③이 위험하지 않은 이유를 설계로 만들지 않고 **순서로** 만들었다. 없는 파일을 부르는 것은
어차피 시끄러운 실패라 숨지 않고, 커밋이 먼저 들어가면 그 조합이 생길 수 없다.

**막혔을 때 빠져나오는 길**: ③에 갇혔다면 붙인 두 줄을 지우면 즉시 ①로 돌아간다. ②에서
`check-hooks` 빨간불이 거슬리면 그것도 설정을 붙이면 사라진다 — 어느 쪽도 편집이나 턴 종료를
막지 않으므로 갇히는 상태가 없다.

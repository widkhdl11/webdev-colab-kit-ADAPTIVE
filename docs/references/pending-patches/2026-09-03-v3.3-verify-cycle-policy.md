# v3.3 검증 후속 — 사이클 판정을 코드로 (보호 파일 4개)

무엇을 고치는 패치인가. v3.3 을 검증하다 나온 것 중 보호 파일에 닿는 셋이다.

- **승격이 문서에는 자동이라고 적혀 있는데 실행 경로가 없었다.** 후보 대장을 읽는 코드가
  검사 스크립트 하나뿐이었고, 그 검사기는 파서를 자기 안에 따로 들고 있었다. 그래서
  "승격 0건"과 "아무도 안 셌다"가 겉이 같았다.
- **종료 조건의 상한이 코드에 없었다.** 문서에는 `상한(N)` 이라고 적혀 있고 N 에 숫자가
  없었고, 숫자 5 는 `PENDING.md` 산문에만 있었다. 보류가 몇 건 쌓여도 아무 일도 안 났다.
- **`last_applied` 는 "기계가 읽는다"고 등재됐는데 읽는 쪽도 쓰는 쪽도 없었다.**

고치는 방향은 하나다: **판정을 lib 한 자리에 두고, 게이트는 판정을 부르되 쓰지는 않는다.**
승격도 사이클 마감도 무엇을 적을지 판단해야 하는 쓰기라 사람과 에이전트가 한다. 게이트가
하는 일은 "처리 안 된 것이 남아 있다"를 신고하는 데까지다.

---

## 붙이기 전에 — 지금 상태

```
node scripts/check-cycle-policy.mjs     → 10/13  (A·B·K 실패)
node scripts/check-read-policy.mjs      →  8/10  (H·I 실패)
```

- `A lib 적용` — `gates/lib/cycle-policy.mjs` 가 없다
- `B 게이트 배선` — 미처리 후보를 심어도 `run-gates` 가 신고하지 않는다
- `K 훅 배선` — 보류를 상한까지 심어도 Stop 훅이 사이클 종료를 안 알린다
- `I 어휘 대조` — 계약 문서 7절에는 `harness` 가 등재됐는데 lib 은 넷만 안다
- `H 현행` — **규칙 파일 하나가 실제로 안 읽힌다.** 이번에 승격된
  `docs/references/policy/check-where-it-runs.md` 가 `scope: [harness]` 인데 lib 이 그 값을
  몰라서 통째로 버려진다. 지금은 정책 규칙을 읽는 소비자가 없어 기능적 피해는 없지만,
  **② 를 제일 먼저 붙여야 하는 이유가 이것이다.**

붙인 뒤 이 다섯이 통과하면 붙은 것이다. **코드를 읽지 않고 판정할 수 있다.**

```js
// 결정층(사이클)의 판정이 사는 한 자리. 게이트·Stop 훅·검사 스크립트가 전부 여기서 읽는다.
//
// 왜 lib 로 빼나: v3.3 을 만들 때 승격 판정과 종료 판정이 검사 스크립트 안에만 있었다.
// 그러면 검사가 자기 사본을 검사한다 — 실제로 도는 코드는 아무도 안 밟는다.
// (승격 후보 대장의 "검사는 그 코드가 실제로 도는 자리에서 돌려 본다")
//
// **파일을 읽지 않는다. 문자열을 받고 판정을 돌려준다.** 픽스처로 프로브하기 위해서다.
// **쓰지 않는다.** 승격도 사이클 마감도 판단이 필요한 쓰기라 사람과 에이전트가 한다 —
// 여기서 하는 일은 "처리 안 된 것이 남아 있다"를 신고하는 데까지다.

import { POLICY_SCOPES } from "./read-policy.mjs";

// 열린 보류 항목 수의 상한. 닿으면 사이클을 조기 종료한다.
// 숫자가 문서 산문에도 적혀 있으면 두 자리가 조용히 어긋난다 — 값은 여기 하나뿐이다.
export const PENDING_CAP = 5;

// 같은 유형이 몇 번 쌓이면 규칙이 되는가. 1회짜리는 우연일 수 있어 승격하지 않는다.
export const PROMOTE_AT = 2;

/**
 * 사이클을 닫을 때인가.
 *   frontier   지금 작업할 노드 목록
 *   blocked    보류 항목이 막는 노드 (Set 또는 배열)
 *   openCount  열린 보류 항목 수
 * 반환 { close, reason }
 */
export function closeVerdict({ frontier = [], blocked = new Set(), openCount = 0 } = {}) {
  const b = blocked instanceof Set ? blocked : new Set(blocked);
  // 조건 1 — 프론티어의 모든 노드가 보류에 막혔다.
  // 프론티어가 비면 여기서 닫지 않는다: 그건 그래프 종단(조건 2)이고 판정하는 자리가 다르다.
  if (frontier.length > 0 && frontier.every((n) => b.has(n)))
    return { close: true, reason: `조건 1 — 프론티어(${frontier.join(", ")})가 전부 보류에 막혔다` };
  // 조건 1' — 보류가 상한에 닿았다. 그쯤 되면 남은 작업 대부분이 곧 보류에 걸리고,
  // 리포트의 보류 목록이 한 화면을 넘으면 비동기 검토가 다시 병목이 된다.
  if (openCount >= PENDING_CAP)
    return { close: true, reason: `조건 1' — 열린 보류가 상한에 닿았다(${openCount}/${PENDING_CAP})` };
  return { close: false, reason: null };
}

/**
 * 승격 후보 대장 읽기. `## 후보` 아래의 항목만 세고, 줄 맨 앞의 scope/seen/no-auto 만 읽는다.
 * 나머지 본문은 파싱하지 않는다.
 */
export function readCandidatesText(src) {
  const items = [];
  let inSection = false, cur = null;
  const flush = () => { if (cur) items.push(cur); cur = null; };
  for (const raw of String(src).replace(/\r\n/g, "\n").split("\n")) {
    const h = raw.match(/^##\s+(.*)$/);
    if (h) { flush(); inSection = h[1].trim() === "후보"; continue; }
    if (!inSection) continue;
    const t = raw.match(/^-\s+\*\*(.+?)\*\*/);
    if (t) { flush(); cur = { title: t[1].trim(), scope: [], badScope: [], seen: [], noAuto: null }; continue; }
    if (!cur) continue;
    const sc = raw.match(/^[ \t]*scope:[ \t]*(.*)$/);
    if (sc) {
      for (const v of sc[1].replace(/^\[|\]$/g, "").split(",").map((x) => x.trim()).filter(Boolean))
        (POLICY_SCOPES.includes(v) ? cur.scope : cur.badScope).push(v);
      continue;
    }
    const se = raw.match(/^[ \t]*seen:[ \t]*(.*)$/);
    if (se) {
      // 횟수는 세지 않고 사이클 이름을 모은다. 같은 사이클이 두 번 적혀도 1회다.
      for (const v of se[1].split(",").map((x) => x.trim()).filter(Boolean))
        if (!cur.seen.includes(v)) cur.seen.push(v);
      continue;
    }
    const na = raw.match(/^[ \t]*no-auto:[ \t]*(.*)$/);
    if (na) { cur.noAuto = na[1].trim() || "(사유 없음)"; continue; }
  }
  flush();
  return { items };
}

/**
 * 처리되지 않은 채 대장에 남은 항목.
 *   mustHandle  승격 조건을 다 갖췄다 — 규칙으로 올리거나 no-auto 사유를 달아야 한다
 *   unreadable  2회 이상인데 scope 를 못 읽어 승격할 수 없다 — 신고만 하고 실패시키지 않는다
 *
 * 실패 방향은 승격하지 않는 쪽이다(잘못 승격된 규칙은 그 뒤 모든 결정의 근거가 되고,
 * 승격이 한 사이클 늦는 것은 그냥 한 사이클 늦는 것이다). 그래서 이 함수는 승격하지 않는다.
 */
export function promotionPending(items) {
  const mustHandle = [], unreadable = [];
  for (const it of items) {
    if (it.seen.length < PROMOTE_AT) continue;   // 1회짜리 — 대장에 그대로 둔다
    if (it.noAuto) continue;                     // 사유가 달렸다 — 처리된 것이다
    if (it.scope.length === 0) unreadable.push(it);
    else mustHandle.push(it);
  }
  return { mustHandle, unreadable };
}

/**
 * 결정 로그의 `근거` 열에서 규칙 id 를 걷는다(표의 마지막 열).
 * `NEW`(커버 규칙 없음)와 `HUMAN`(사람 개입)은 규칙이 아니다.
 */
export function readLogCitations(src) {
  const ids = new Set();
  for (const raw of String(src).replace(/\r\n/g, "\n").split("\n")) {
    if (!raw.startsWith("|")) continue;
    const cells = raw.split("|").slice(1, -1).map((c) => c.trim());
    if (cells.length < 2) continue;
    const last = cells[cells.length - 1].split("`").join("").trim();
    if (!last || last === "NEW" || last === "HUMAN" || last === "근거") continue;
    for (const v of last.split(",").map((x) => x.trim()).filter(Boolean))
      if (/^[a-z0-9][a-z0-9-]*$/.test(v)) ids.add(v);
  }
  return ids;
}

  console.error(`   이 훅은 알리기만 한다. 리포트(workspace/reports/CYCLE_REPORT.${cid}.md) 발행과 CYCLE.md 의 줄 이동은 사이클 마감 절차가 한다.`);
});
```

## 붙은 뒤 확인

**먼저 문법부터 본다.** 손으로 붙이다 닫는 괄호가 빠지면 그 파일이 통째로 안 돌고,
`graph-stop` 이 안 돌면 매 턴 HANDOFF 갱신과 차단 판정이 통째로 빠진다.

```
node --check gates/graph-stop.mjs       → 아무것도 안 나오면 통과
node --check gates/run-gates.mjs        → 같음
```

```
node scripts/check-cycle-policy.mjs     → 13/13
node scripts/check-read-policy.mjs      → 10/10
node scripts/check-promotion.mjs        →  8/8
node scripts/check-pending-kind.mjs     → 11/11
node gates/run-gates.mjs                → 보류 1건 신고 외에 새 실패 없음
```

`B` 와 `K` 는 **위반을 일부러 심어 잡히는 것을 본다.** 두 항목 다 심는 것과 지우는 것을
둘 다 본다 — "위반 0건"이라는 보고와 검사가 아예 안 돈 것은 겉이 같기 때문이다.

- `B` — `projects/__probe__/` 에 2회짜리 후보를 만들고 게이트를 돌려
  `[promotion/UNPROCESSED]` 가 나오는지 보고, 1회로 줄여 안 나오는지 본 다음 지운다.
- `K` — 활성 프로젝트의 `PENDING.md` 에 상한만큼 항목을 심고 Stop 훅을 돌려
  `[cycle/CLOSE]` 가 나오는지 보고, 되돌린 뒤 안 나오는지 본다. 되돌리기는 `finally` 에서
  하고 바이트 단위로 복원을 확인한다 — 실패하면 파일 경로와 함께 크게 알린다.

## 이 패치 문서의 코드는 실제로 돌려 봤다

붙이기 전에 판정할 수 없는 상태로 넘기지 않으려고, 위 네 조각을 그대로 떼어 `gates/` 사본에
적용하고 이 레포를 상대로 돌렸다(2026-09-03).

| 무엇 | 확인한 것 |
|---|---|
| ③ 승격 미처리 | 2회짜리 후보를 심으니 `[promotion/UNPROCESSED] ... '후보 제목' 이 2개 사이클(c1, c2)에서 나왔는데 처리가 안 됐다` — 1회로 줄이니 안 나온다 |
| ③ last_applied | 다른 사이클 이름으로 규칙을 인용하니 `[cycle/LAST_APPLIED] docs/references/policy/open-for-extension.md — ... last_applied 에 'probe-1' 가 없다(현재: signal2-20260903-1)` |
| ③ 현행 | 손 안 댄 레포에서는 결정층 신고가 0건 |
| ④ 상한 | 보류를 5건으로 늘리니 `[cycle/CLOSE] 사이클 signal2-20260903-1 종료 조건 성립 — 조건 1' — 열린 보류가 상한에 닿았다(5/5)` — 되돌리니 안 나온다 |
| ④ 턴 | 패치된 훅이 `exit 0` 으로 끝난다(보류 1건은 여전히 턴을 안 막는다) |

**사본으로 확인한 것이라 붙이는 자리가 다르면 결과도 다를 수 있다.** 그래서 위의 "붙은 뒤
확인"을 그대로 한 번 더 돌린다 — 사본에서 통과한 것은 배선의 근거지 적용의 근거가 아니다.

## 부분 적용 — 어느 조합에서도 편집과 턴 종료가 막히지 않는다

**설계로 막았다.** 새 코드는 전부 `--quick` 밖에 있고(편집 훅은 건드리지 않는다),
`run-gates` 쪽은 import 실패와 본문 예외를 둘 다 잡아 ⚠ 로 떨어지고, `graph-stop` 쪽은
lib 이 없으면 옛 판정으로 떨어진다. 그래서 16가지 조합 중 세션을 가두는 것이 없다.

| 붙인 것 | 무슨 일이 일어나나 | 위험 |
|---|---|---|
| 없음 | 지금과 같다 | — |
| ① 만 | 아무도 lib 을 안 부른다. `check-cycle-policy` A 만 통과 | 없음 |
| ② 만 | `harness` scope 규칙이 읽힌다. `check-read-policy` 10/10 | 없음 |
| ③ 만 | `⚠ [cycle/SKIP]` 이 매 전체 실행에 뜬다. 판정은 안 돈다 | 없음 |
| ④ 만 | 옛 판정(조건 1만)으로 돈다. 상한을 안 본다 | 없음 |
| ①+③ | 승격·last_applied 검사가 실제로 돈다 | 없음 |
| ①+④ | 상한 조건이 살아난다 | 없음 |
| ①+③, ② 없음 | `harness` 후보가 `unreadable` 로 분류된다 → ⚠ 만 뜨고 실패는 안 난다 | **경고가 뜨는데 원인이 ② 미적용이라는 게 안 보인다.** ②를 먼저 붙이면 이 상태를 안 거친다 |
| ② 없음 (지금) | `scope: [harness]` 규칙 파일이 통째로 버려진다 | 정책 규칙을 읽는 소비자가 아직 없어 기능적 피해는 없다. `check-read-policy` H 가 그 상태를 신고한다 |
| ③+④, ① 없음 | 둘 다 옛 동작 + ⚠ SKIP | 없음 |
| 전부 | 위 "붙은 뒤 확인" 그대로 | — |

**권장 순서는 ② → ① → ③ → ④** 다. **② 를 제일 먼저** 붙이는 이유는 지금 레포에 이미
`scope: [harness]` 규칙 파일이 있어서, ② 전까지 그 파일이 버려진 상태이기 때문이다.
① 이 ③·④ 보다 먼저면 `⚠ SKIP` 을 안 본다. 순서를 지키지 않아도 턴이 막히지는 않는다.

**중간에서 빠져나오는 길**: 어느 단계든 `node gates/run-gates.mjs --quick` 이 통과하면
편집은 계속 된다. 되돌리려면 ① 파일을 지우고 ③·④ 의 추가분을 빼면 원래대로다 —
③·④ 는 각각 독립이라 하나만 되돌려도 다른 쪽이 깨지지 않는다.

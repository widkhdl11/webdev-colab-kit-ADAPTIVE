# 패치 — spec-coverage 가 "정의한 불변식"만 요구하게 (2026-08-31)

> **✅ 2026-08-31 적용 완료**(사용자가 직접). `node scripts/check-inv-anchor.mjs` → **4/4**.
> 적용 후 실측: signal2 스펙 5개의 요구가 **75개 → 60개**(유령 15개 소멸). 게이트 통과.

보호 파일 **하나**(`gates/spec-coverage.mjs`)를 고친다. 한 줄이다.
**붙이기 전에 검사가 실패하고, 붙인 뒤에 통과한다.**


붙이기 전 (지금 이 레포에서 실측):

```

```

붙인 뒤 (후보 판정기를 끼워 미리 실측한 값):

```

```

지금도 통과하는 `C`·`D` 는 **이 패치가 게이트를 무력하게 만들지 않는지** 보는 검사다.
이 패치는 요구를 **줄이는** 방향이라, 느슨한 쪽으로 틀리면 놓친 것이 소리를 내지 않는다.
그래서 "막아야 할 것을 여전히 막는가"를 같이 본다.

검사기는 임시 디렉터리에 킷을 복사해 **실제로 게이트를 돌린다** — 소스 문자열 대조가 아니고,
이 레포의 파일은 하나도 건드리지 않는다.

**파일이 하나라 부분 적용 조합 문제는 없다.** (CLAUDE.md 의 "패치가 파일 둘 이상을 고치면
부분 적용 조합을 확인한다" 규칙은 여기 해당하지 않는다 — 붙었거나 안 붙었거나 둘뿐이다.)

## 무엇이 문제인가

`gates/spec-coverage.mjs` 는 approved 스펙의 불변식마다 테스트를 하나씩 요구한다.
그 "불변식 목록"을 만드는 방법이 **파일 전체에서 `INV-` 로 시작하는 글자를 전부 줍는 것**이다.

그런데 스펙 문서에서 `INV-` 는 두 가지 뜻으로 나온다.

**정의** — 이 스펙이 만든 규칙. 테스트가 있어야 한다:

```
- INV-C1: 항목의 유일성은 정규화된 원문 URL(canonical_url)로 판정한다. (강제 위치: 서버)
```

**인용** — 다른 스펙을 가리키는 문장. 테스트를 요구하면 안 된다:

```
태그 부여 조항(옛 INV-T3)은 2026-08-30 에 폐기됐다. badge-keywords.md 의 INV-B1 이 …
```

지금은 둘을 구분하지 못한다. **다른 파일의 조항을 설명하려고 한 번 언급한 대가로**
그 조항의 테스트를 요구받는다.

부작용이 하나 더 있다. `invToSpec` 은 INV 이름을 키로 쓰는 Map 이라 **나중에 읽은 파일이
앞의 것을 덮어쓴다.** 그래서 실패 메시지가 정의한 파일이 아니라 **인용한 파일**을 가리킬 수 있다 —
어디를 고쳐야 하는지가 틀린 곳을 가리킨다.

## 실측 — 지금 signal2 스펙 5개

```
badge-keywords.md        지금 세는 것  8 · 실제 정의  6 · 인용뿐: INV-X INV-T2
content-safety.md        지금 세는 것  6 · 실제 정의  6 · 인용뿐: -
content-selection.md     지금 세는 것 12 · 실제 정의 11 · 인용뿐: INV-R4
ingestion-ranking.md     지금 세는 것 21 · 실제 정의 19 · 인용뿐: INV-T3 INV-B1
keywords-and-kinds.md    지금 세는 것 28 · 실제 정의 18 · 인용뿐: INV-K1 INV-K4 … (10개)
합계  지금 75 → 정의만 60
```

**15개가 유령이다.** 스펙 5개를 `approved` 로 올리면 있지도 않은 조항 15개의 테스트를
요구받는다. `INV-K1`·`INV-K4` 는 "badge-keywords.md 로 옮겼다"고 **알려 주는 문장**에서 나오고,
`INV-X` 는 형식을 설명하는 예시에서 나온다.

이건 가정이 아니다 — **2026-08-31 세션에 실제로 턴이 막혔다.**
`ingestion-ranking.md` 가 `badge-keywords.md 의 INV-B1` 을 인용한 줄 하나 때문이었다.

## 고칠 것 — `gates/spec-coverage.mjs` 36줄

목록 항목으로 시작하는 것만 정의로 센다. 이 모양은 킷의 스펙 템플릿
(`docs/references/spec-template.md:62`)이 이미 요구하는 형식이다.

**before** (36줄):

```js
  for (const m of src.matchAll(/\bINV-[A-Z0-9]+\b/g)) invToSpec.set(m[0], relative(ROOT, f));
```

**after** (주석 5줄 + 코드 1줄로 교체):

```js
  // 정의 앵커만 센다 — 목록 항목으로 시작하는 `- INV-X:` 가 스펙 템플릿이 요구하는 정의 형식이다.
  // 파일 전체에서 `INV-` 를 찾으면 **다른 스펙을 가리키는 문장 한 줄**도 요구가 된다
  // ("badge-keywords.md 의 INV-B1 이 …"). 실측 2026-08-31: signal2 스펙 5개에서
  // 75개를 세는데 실제 정의는 60개였다 — 15개가 남의 조항이거나 설명용 예시였다.
  // 귀속도 같이 고쳐진다: 옛 방식은 Map 에 나중 파일이 덮어써서, 어느 파일을 고쳐야 하는지가
  // 인용한 쪽을 가리켰다. (검사: scripts/check-inv-anchor.mjs)
  for (const m of src.matchAll(/^[ \t]*-[ \t]+(INV-[A-Z0-9]+)[ \t]*:/gm)) invToSpec.set(m[1], relative(ROOT, f));
```

바뀌는 것 셋:

| | 전 | 후 |
|---|---|---|
| 어디를 보나 | 파일 전체 | 줄 맨 앞(들여쓰기 허용)의 `-` 목록 항목 |
| 무엇을 잡나 | `INV-` 로 시작하는 모든 글자 | `- INV-X:` 처럼 **콜론까지** 붙은 것 |
| 캡처 | `m[0]` (매치 전체) | `m[1]` (괄호 안 INV 이름) — 앞의 `- ` 를 빼려고 |

`m[0]` → `m[1]` 을 빠뜨리면 키가 `- INV-A1:` 이 되어 테스트 대조가 전부 실패한다.
**검사기 D 가 그걸 잡는다.**

## 붙이는 방법 — 둘 중 편한 쪽

**① 한 줄만 고친다**

1. `gates/spec-coverage.mjs` 를 연다
2. 36줄(`for (const m of src.matchAll(/\bINV-...`)을 위 **after** 블록으로 바꾼다

**② 완성본으로 통째로 덮어쓴다** — 붙일 때는 후보 파일을 이 폴더에 같이 뒀다.
적용 후 지웠다(두 벌이 같이 낡는 것을 막는다).

**어느 쪽이든 붙인 뒤:**

3. `node scripts/check-inv-anchor.mjs` → **4/4** 가 나오면 맞게 붙은 것이다
4. `node gates/run-gates.mjs` → 게이트 통과 확인

**주의 — 줄 수를 유지할 것.** 이 파일을 가리키는 문서 참조가 여럿이다(`docs/v2/` 의
`02-spec.md` · `05-qa.md` · `runtime.md`). 실제로 적용 중에 `}` 가 앞줄로 딸려 올라가
66줄 → 65줄이 됐고, 37줄부터 전부 한 칸씩 밀려 `L38`·`L56`·`L60` 참조가 엉뚱한 곳을
가리켰다. `}` 를 제자리에 돌려놓자 저절로 맞았다. 밀렸으면 `scripts/remap-doc-refs.mjs` 로 옮긴다.
같은 이유로 **설명 주석은 이 파일에 안 넣었다** — 왜 이 정규식인지는 이 문서와
`scripts/check-inv-anchor.mjs` 머리 주석, `docs/v2/stages/02-spec.md:85` 에 있다.

## 안 하면 어떻게 되나

지금 당장은 아무 일도 없다 — signal2 스펙 5개가 전부 `status: parked` 라 이 게이트가 안 본다.
**첫 스펙을 `approved` 로 올리는 날 막힌다.** 그날은 구현에 착수하는 날이라, 그때 이걸
만들면 흐름이 끊긴다. 회피하려면 스펙에서 다른 스펙을 가리키는 문장을 지워야 하는데,
그건 문서를 나쁘게 만들어 게이트를 통과시키는 것이다.

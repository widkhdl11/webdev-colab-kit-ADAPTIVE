# 패치 — 클라이언트 컴포넌트가 서버 전용 모듈을 끌고 들어가는 것을 편집 시점에 잡는다

`gates/run-gates.mjs` 는 보호 파일이라 직접 못 고친다. 아래를 직접 적용하고, 검사로 판정하면 된다.

## 무슨 일이 일어나고 있나

`"use client"` 파일이 import 를 따라가다 `next/headers` 를 쓰는 모듈에 닿으면 브라우저 번들이
서버 코드를 끌고 들어가고 빌드가 죽는다. **유닛 검사는 이때 전부 초록불이다** — tsc 도 통과하고
테스트도 통과한다. 매번 잡은 것은 `npm run build` 한 번이었다.

study-mate 에서만 2026-09-05~06 에 네 번 났다.

| 언제 | 어디 |
|---|---|
| 09-05 | 미들웨어가 서버 클라이언트를 상대 경로로 끌어옴 |
| 09-05 | 클라이언트 컴포넌트가 데이터베이스에 직접 접근 |
| 09-06 | 모집글 길이 상수가 서버 액션 파일에 있었음 |
| 09-06 | 프로필 이름 상수가 서버 액션 파일에 있었음 |

넷 다 원인이 같고, 넷 다 import 그래프를 따라가면 정적으로 보인다.

## 무엇이 달라지나

편집할 때마다 도는 게이트에 검사 하나가 붙는다. 위반이 있으면 이런 줄이 나온다.

```
[bundle/CLIENT_IMPORTS_SERVER] projects/study-mate/src/features/create-post/ui/CreatePostForm.tsx:17
  — "use client" 파일이 서버 전용 모듈에 닿는다
  (…/ui/CreatePostForm.tsx → …/api/insert-post.ts → …/supabase/server-client.ts → next/headers).
  브라우저 번들이 서버 코드를 끌고 들어가 빌드가 죽는다 — 공유하는 값은 서버 전용 import 가
  없는 파일로 떼거나, 서버 접근은 "use server" 액션 뒤로 옮긴다
```

위 줄은 지어낸 예가 아니다. **09-06 에 실제로 났던 세 번째 건을 그대로 되돌려 놓고 돌린 결과**다
(`limits.ts` 의 상수를 `insert-post.ts` 로 되돌리고 폼이 거기서 가져가게 한 사본).
위치는 클라이언트 파일의 그 import 줄에 찍고, 괄호 안이 어디를 거쳐 서버에 닿았는지다.

### 판정 규칙 셋

| | 규칙 | 왜 |
|---|---|---|
| ① 씨앗 | `next/headers` · `server-only` 를 import 하는 파일은 서버 전용 | 클라이언트 번들에서 반드시 깨지는 것만 넣었다. 늘리면 과차단이 실패 방향이 된다 |
| ② 벽 | `"use server"` 파일은 지나가지 않는다 | 번들러가 그 자리를 원격 호출로 바꾼다. 막으면 폼이 전부 걸린다 |
| ③ 타입 | `import type` · `export type` 은 따라가지 않는다 | 컴파일에서 지워지므로 번들에 안 들어간다 |

배럴(`export * from "./x"`)도 따라간다. 이게 없으면 `index.ts` 를 거치는 경로가 통째로 안 보인다.

## 고치는 법

`gates/run-gates.mjs` 를 이 폴더의 `run-gates.patched.mjs` 로 바꾼다. **파일 하나만 바뀐다** —
부분 적용 조합이 없다. 붙는 것은 FSD 검사 바로 뒤의 블록 30줄이고, 판정 로직은 거기 없다.
로직은 `scripts/check-client-server-import.mjs` (보호 파일 아님, 이미 레포에 있다) 한 자리에 있고
게이트는 그것을 부르기만 한다 — 두 벌이 되면 씨앗 목록이 늘 때 한쪽만 늘어서 게이트와 검사가
다른 답을 낸다.

검사기가 없거나 못 돌면 게이트는 죽지 않고 `⚠ [bundle/SKIP]` 로 건너뛴다.

## 붙었는지 판정하는 법 — 코드를 안 읽고

```
node scripts/check-client-server-import.mjs
```

| | 항목 | 붙기 전 | 붙은 뒤 |
|---|---|---|---|
| A | 직접 감지 — 클라이언트 → 헬퍼 → `next/headers` **심어 둔 위반** | 통과 | 통과 |
| B | 벽 — 클라이언트 → `"use server"` → `next/headers` 는 안 잡는다 | 통과 | 통과 |
| C | 서버 컴포넌트 — 지시어 없는 파일은 안 잡는다 | 통과 | 통과 |
| D | 배럴 경유 — `index.ts` 재수출로 딸려 들어가는 경로 **심어 둔 위반** | 통과 | 통과 |
| ③ | 타입 import 는 안 잡는다 | 통과 | 통과 |
| **E** | **배선 — `run-gates --quick` 이 위반을 화면에 낸다** | **실패** | **통과** |
| F | 과차단 없음 — 이 레포의 실제 코드는 0건 | 통과 | 통과 |

**붙기 전 6/7, 붙은 뒤 7/7.** E 하나가 가른다.

A·D 는 **위반을 일부러 심어 잡히는 것을 본다** — "위반 0건"이라는 보고와 검사가 아예 안 돈 것은
겉이 같기 때문이다. B·C·③·F 는 반대 방향이다. 이 패치는 조이는 변경이라 과차단이 실패 방향이고,
멀쩡한 폼까지 막으면 매 턴 걸려서 우회가 값싸진다.

붙이기 전에 후보 파일을 미리 확인하려면:

```
node scripts/check-client-server-import.mjs --gate docs/references/pending-patches/2026-09-06-client-server-import/run-gates.patched.mjs
```
→ 7/7 (지금 확인한 결과다)

## 검사하지 않는 것 — 밝혀 둔다

- **동적 경로**(`import(varName)`)는 못 따라간다. 문자열 리터럴만 본다.
- **`node_modules` 안**은 안 들어간다. 서드파티가 `next/headers` 를 끌어오는 경우는 안 잡힌다.
- **씨앗은 둘뿐**이다. `node:fs` 같은 Node 내장 모듈도 클라이언트 번들을 깨지만 넣지 않았다 —
  실제로 난 네 건이 전부 `next/headers` 였고, 씨앗을 늘리면 과차단 위험이 먼저 온다.
  필요해지면 `SERVER_ONLY_SPECIFIERS` 에 한 줄 더한다.
- 이 게이트는 **빌드를 대신하지 않는다.** 빌드가 죽는 이유 중 이 한 가지만 앞당겨 잡는다.

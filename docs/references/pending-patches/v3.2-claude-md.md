## 수정 ② — 「시각 방향 표면 상세」 압축 (−4줄)

**CLAUDE.md 118~123줄 / AGENTS.md 112~117줄.** 찾을 것 (6줄):

```
- **시각 방향 표면 상세**: 디자인 국면(design-interview→시안→checkpoint→design-rules 확정)이 있는 이유는
  시각이 말로는 합의되지 않고 크게 만든 뒤 뒤집으면 비싸기 때문이다. 그래서 붙는 조건도 둘이다 —
  취향이 갈릴 수 있고 + 뒤집는 비용이 클 때. 레퍼런스가 이미 있거나 "알아서 무난하게"면 시안 1장으로
  압축하거나 건너뛰고 바로 구현해도 된다. 다만 UI 구현 전 design-rules `status: approved`라는 하한선은
  게이트 design/BEFORE_UI가 기계로 지키므로, 판단은 "국면을 얼마나 깊게 돌 것인가"에만 쓴다.
  순서 상세는 .claude/rules/design-drafting.md
```

바꿀 것 (2줄):

```
- **시각 방향 표면 상세**: 국면을 얼마나 깊게 돌지의 판단 기준(뒤집는 비용)과 순서는
  .claude/rules/design-drafting.md. UI 구현 전 design-rules `status: approved` 하한선은 게이트가 지킨다
```

**왜 강등해도 되나**: 뺀 내용이 `.claude/rules/design-drafting.md` 에 이미 그대로 있다 —
"기준은 하나다: **뒤집었을 때 버릴 것이 얼마나 되는가**"(9줄), "애매하면 새 방향으로 취급한다
(싸게 확인하는 게 낫다). 단 레퍼런스가 이미 있거나 사용자가 '알아서 무난하게'라고 하면 루프를
압축한다"(21~23줄). 그 파일은 화면 작업 경로에서 자동으로 로드되므로, 필요한 순간에 읽힌다.
CLAUDE.md 는 상시 고정비라 같은 내용을 두 벌 들고 있을 자리가 아니다.

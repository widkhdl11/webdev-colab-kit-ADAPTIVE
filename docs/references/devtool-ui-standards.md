# 개발 도구 UI 기준 — 대시보드·리포트 화면의 판정 기준

제품 화면의 기준은 `projects/<이름>/docs/design/design-rules.md` 다. **이 문서는 그것과 별개다.**
대시보드처럼 사람이 작업을 지켜보려고 켜 두는 개발 도구 화면에 적용한다.

왜 나눠 두나: 제품 화면의 기준은 시각 정체성까지 담고 프로젝트마다 다르다. 개발 도구는
정체성이 필요 없고 **읽히는가**만 필요하다. 두 기준을 한 문서에 두면 개발 도구가 제품의
승인 절차에 얹히고, 반대로 제품이 개발 도구의 헐거운 기준을 물려받는다.

이 문서는 **다음 재판정의 정본이다.** 화면을 고칠 때 여기 있는 항목을 다시 본다.

## 1. 명도 대비

- 모든 텍스트는 배경 대비 **4.5:1 이상**. 노드 상자 안의 글자도 포함한다.
- 색 토큰을 바꿀 때는 대비를 다시 재고, 값을 CSS 주석에 적는다.
  (지금 값: 본문 15.8:1 · 흐린 글자 8.2:1 · 강조 7.4:1 · 진행 6.4:1 · 대기 7.1:1)

## 2. 글자 크기

| 자리 | 최소 |
|---|---|
| 본문 | 14px |
| 노드 라벨 | 13px |
| 그 밖의 모든 글자 | 12px |

**12px 미만은 없다.** 그래서 지도를 화면 폭에 맞춰 축소하지 않는다 — 축소하면 노드 글자가
13px 아래로 떨어진다. 넘치면 그 칸 안에서 가로로 스크롤한다.

## 3. 키보드

- `Tab` 으로 노드 · 단계 띠의 칸 · 서브에이전트 · 요약 박스의 특이사항 줄을 순회한다.
- 노드에서 `Enter`(또는 `Space`)로 스킬 패널을 연다.
- 단계 띠의 칸에서 `Enter` 로 지연 진단 패널을 연다.
- `Esc` 로 패널을 닫는다.
- **우측 열의 패널 자리는 하나다.** 스킬 패널과 지연 진단 패널은 그 한 자리를 나눠 쓰고
  동시에 열리지 않는다. 요약 박스는 그 위에 항상 남아 있다.
- **포커스 링이 보인다.** 3px 실선에 2px 띄움. `outline: none` 금지.

## 4. 스크린리더

- 노드는 `role="button"` 과 `aria-label`(이름 + 상태)을 갖는다.
- 패널은 `role="dialog"` 와 이름을 갖는다.
- 각 구역(`section`)에 `aria-label` 이 있다.

## 5. 상태 표기

**상태를 색으로만 구분하지 않는다.** 색을 쓰면 라벨이나 모양을 함께 준다.

| 상태 | 색 | 함께 주는 것 |
|---|---|---|
| 진행 중 | 강조색 채움 | "진행 중" 라벨 + 굵은 테두리 |
| 사람 입력 대기 | 경고색 채움 | "대기" 라벨 + 점선 테두리 |
| 스킬 실행 중 | 진행색 | "실행 중" 라벨 |
| 대기(서브에이전트) | 저채도 | "대기" 라벨 |
| 항목 완료(단계 띠) | 저채도 채움 | "완료" 라벨 + ✓ |
| 항목 진행 중(단계 띠) | 강조색 채움 | "진행 중" 라벨 + 굵은 테두리 |
| 항목 아직(단계 띠) | 저채도 | "아직" 라벨 + 점선 테두리 |
| 임계 초과 | 경고색 테두리 | "임계 초과" 라벨 |

판정 방법: 화면을 흑백으로 만들어도 상태가 구별되는가.

## 6. 폭

**창 폭 1024px 에서 페이지 본문에 가로 스크롤이 없다.** 그리고 **1400px 이상에서는 칸 안쪽에도
가로 스크롤이 없다** — 지도가 통째로 들어간다.

화면은 두 열이다. 왼쪽이 요청 층·지도·활동이고, 오른쪽은 300px 고정 열(요약 박스 + 패널)이다.
본문 최대 폭은 1400px 이고, 이 숫자는 지도에서 거꾸로 나왔다:
`1400 − 페이지 좌우 44 − gap 16 − 우측 열 300 = 왼쪽 1040px ≥ 지도 962px`.
여기를 줄이면 지도 칸에 가로 스크롤바가 다시 생긴다.

우측 열은 1024px 에서도 그대로 있는다 — 요약 박스는 항상 보여야 하는 칸이라 접히면 안 된다.
860px 미만에서만 아래로 내려간다.

좁은 창(1024px)에서 왼쪽에 남는 폭은 약 680px 이고, 두 가지가 여기서 갈린다.

- **지도**(자연 폭 `18*2 + 층수*116 + (층수-1)*46`, 층 여섯이면 962px)는 **줄이지 않는다.**
  줄이면 노드 글자가 13px 아래로 떨어져 2절을 어긴다. 대신 지도 칸 안에서만 가로로 스크롤한다.
  페이지 본문은 그대로 안 넘친다.
- **단계 띠**가 실제로 쓰는 폭은 **629px** 이다(1024 에서 페이지 패딩 44 · gap 16 · 우측 열 300 ·
  카드 좌우 패딩 36 을 뺀 값). 칸 최소 폭 84px · 칸 사이 gap 4px · 화살표 10px 로
  **항목 여섯까지 스크롤 없이** 들어가고(실측 606 ≤ 629), 그보다 많으면 띠 안에서만
  가로로 스크롤한다. 이 숫자 중 하나라도 키우면 여섯이 안 들어간다.
  칸의 라벨은 두 줄에서 잘리고 전체 문장은 `title` 과 `aria-label` 에 남는다
  (스펙에서 뽑은 항목 label 은 60자까지 온다).

### 스크롤바

**스크롤바는 내용이 아니라 장치다.** 기본 스크롤바는 두껍고 대비가 세서 옆 칸의 글자보다 먼저
눈에 들어온다. 그래서 8px 로 얇게 깔고, 트랙은 투명하게 두고, 손이 올라가면 진해지게 한다
(`--line` → `--dim`).

**폭 0 으로 숨기지는 않는다.** 숨기면 「옆에 더 있다」는 유일한 신호가 사라진다 — 지도가 잘린
것을 모르고 노드 수를 잘못 세는 일이 실제로 있었다.

## 7. 자동으로 못 재는 것 — 사람이 보는 체크리스트

대비·키보드 순회·스크린리더는 이 레포에 자동 검사가 없다. 화면을 고친 뒤 **사람이** 본다.

- [ ] `Tab` 만으로 노드 → 패널 열기 → `Esc` 닫기가 된다
- [ ] 포커스 링이 모든 자리에서 보인다
- [ ] 브라우저 확대 200% 에서 글자가 안 잘린다
- [ ] 흑백으로 봐도 진행 중·대기·실행 중이 구별된다
- [ ] 창 폭 1024px 에서 페이지 본문에 가로 스크롤이 없다 (지도·띠 안쪽 스크롤은 정상)
- [ ] 단계 띠만 보고 "무엇을 어떤 순서로 하고 지금 어디인가"가 읽힌다
- [ ] 임계 초과 항목의 지연 진단 패널만 보고 "시간이 어디에 갔는가"의 근거가 읽힌다
- [ ] 요약 박스만 보고 목표·요청·지금·경과·특이사항이 읽힌다

## 8. 화면에 쓰는 말

**화면은 코드가 아니라 사람이 읽는다.** 기록 파일의 필드 이름과 화면에 찍히는 글자는 다른 것이고,
같을 필요가 없다. 필드 이름은 규약이 정하고(`report-contract.md`), 화면 글자는 이 절이 정한다.

원칙 셋:

1. **일상에서 쓰는 말로 쓴다.** 「체류」·「임계」·「집계」처럼 문서에서나 보는 한자어를 화면에
   그대로 내보내지 않는다. 읽는 사람이 그 말을 한 번 더 번역해야 하면 화면이 늦어진다.
2. **결론이 아니라 무슨 일이 있었는지를 적는다.** 「지연 진단」이 아니라 「왜 오래 걸리나」,
   「임계 초과」가 아니라 「오래 걸리는 중」이다.
3. **기록에 있는 말은 바꾸지 않는다.** `status` 의 `승인 대기`·`중단`, `result` 의 `통과`·`반려`,
   노드 이름(`implement`·`qa`)은 파일에 그 글자로 들어 있어서, 화면에서 바꿔 쓰면 사람이 본 말과
   파일에 적힌 말이 달라진다.

바꿔 쓰는 말(2026-09-15 기준). **왼쪽을 화면에 쓰지 않는다:**

| 쓰지 않는 말 | 화면에 쓰는 말 |
|---|---|
| 체류 (시간) | 걸린 시간 |
| 임계 초과 | 오래 걸리는 중 |
| 임계 T | 기준 30분 |
| 지연 진단 | 왜 오래 걸리나 |
| 특이사항 | 눈여겨볼 것 |
| 경과 | 지금까지 |
| 브리프 | 메모 |
| 미설치 | 아직 없음 |
| 요청 밖 작업 | 시킨 것 밖의 일 |
| 파생 항목 | 중간에 끼어든 일 |
| 블로커 대기 | 답을 기다린 시간 |
| 사람 입력 대기 | 답을 기다리는 중 |
| 활동 공백 | 아무 기록도 없던 시간 |
| 검사 실패 반복 | 검사에서 되돌아온 횟수 |
| 그래프 밖 | 지도 밖 · 지도에 없는 일 |
| 파이프라인 | 작업 흐름 |
| 최근 검사 | 방금 끝난 검사 |
| 상시(스킬) | 항상 쓰는 것 |
| 아직 / 진행 중(항목) | 아직 안 함 / 하는 중 |
| 현재 노드 아님 | 지금 여기 아님 |
| 구간 N개 | N번 |

여기 없는 말을 새로 쓰게 되면 **이 표에 먼저 올린다.** 표에 없으면 화면마다 다른 말을 쓰게 되고,
그러면 같은 것을 가리키는 말이 둘이 된다.

**이 절은 CLAUDE.md 의 「설명은 비유 말고 사실로」와 같은 규칙을 화면에 적용한 것이다.**
문서에 쓰지 않기로 한 말(논리학·전산 용어 직역)은 화면에도 쓰지 않는다.

## 9. 등재 이력

- 2026-09-14 신설. 대시보드 개편(요청 층·서브에이전트 칸·Mermaid 제거)과 함께.
  그전까지 이 기준들은 어디에도 적혀 있지 않아 재판정이 불가능했다.
- 2026-09-15(둘째). 8절 신설(화면에 쓰는 말), 6절에 스크롤바와 1400px 본문 폭. 사용자 지시 셋을
  받은 것이다 — 스크롤바가 투박하다 · 가로 스크롤을 없애 달라 · 어휘가 안 읽힌다.
  **화면 문구를 정한 프롬프트가 있었지만(요약 박스의 고정 문구들) 이 지시가 이긴다** —
  구조(조건 여덟 개·고정 템플릿·문장을 새로 만들지 않는다)는 그대로 두고 말만 바꿨다.
- 2026-09-15. 우측 고정 열(요약 박스 + 패널 한 자리)과 단계 띠가 생기면서 3·5·6·7절을 고쳤다.
  6절의 폭 숫자는 **브라우저에서 잰 값**이다(1024px 에서 여섯 칸 635/635, 일곱 칸 736>635).
  처음 적었던 「680px · 최소 96px」은 카드 패딩과 칸 사이 화살표를 빼먹은 계산이었고,
  그대로 뒀으면 문서와 화면이 다른 숫자를 말했다.
  6절의 「1290px 미만에서 패널이 내려간다」가 사라진 이유: 요약 박스는 항상 보여야 하는 칸이라
  같이 내려보낼 수 없다. 대신 1024px 에서 넘치는 것을 지도·띠 **안쪽** 스크롤로 받는다.

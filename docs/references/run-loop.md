# 자율 실행 루프 (run-loop) — 정본 규약

요청의 항목을 하나씩, **매번 새 대화(`claude -p`)로** 처리한다. 대화가 길어지는 것을 감시해서 비우는 대신
대화를 항목 하나 크기로 잘라, 커질 틈을 주지 않는다. 항목 사이의 상태는 전부 파일에 있다 —
`request.json`·`transitions.jsonl`·`HANDOFF.md`·`PROGRESS.md`·백로그.

설계도 위치: docs/references/harness-design.md 3절 대기열 「자율 실행 루프(run-loop)」 (2026-09-24 사용자 등재).

| 부품 | 파일 |
|---|---|
| 루프 | `scripts/run-loop.mjs` |
| 회차 지시문(고정) | `scripts/loop-item-prompt.md` |
| 항목 끝 검사 | `scripts/check-wrapup.mjs` · 판정 `scripts/lib/wrapup-checks.mjs` |
| 인수인계 리허설 | `scripts/loop-rehearsal.mjs` |
| 판정(다음 항목·상한·자동 시작·화면 한 줄) | `scripts/lib/loop-model.mjs` · 파일 자리 `scripts/lib/loop-files.mjs` |
| 시험 | `scripts/check-run-loop.mjs` (가짜 프로세스로 전 경로) · `check-wrapup.mjs --probe` |

## 1. 회차 하나

1. 열린 요청(`report/request.json`)에서 **진행 가능한 항목**을 고른다 — done 아님 · 의존 항목이 전부 done ·
   열린 결정 카드에 안 걸림. 의존은 항목의 `deps`, 없으면 **바로 앞 항목**이다(report-contract 6절).
   카드는 `item` 칸의 항목 하나를 막고, `item` 이 없으면 전부를 막는다(report-contract 12절).
2. 고른 항목이 없으면 멈춘다 — 남은 항목이 0 이면 「요청 완료」, 아니면 「결정 대기」.
3. `claude -p --output-format stream-json --verbose --permission-mode <설정>` 을 띄우고 지시문(고정 파일에 항목을
   채운 것)을 표준 입력으로 준다. 환경 변수 `KIT_RUN_LOOP=1` · `KIT_LOOP_ROUND` · `KIT_LOOP_ITEM` 이 붙는다.
   출력은 `report/loop/<n>.log`.
4. 끝나면 항목 끝 검사(3절). 항목이 닫혔고 검사를 통과하면 다음 회차로. 카드를 열고 멈춘 항목이면(검사 통과)
   다른 항목으로. 그 밖이면 **같은 항목을 강제로** 한 번 더 돌리고, 또 안 되면 「항목 실패」로 멈춘다.
   (재시도를 다시 고르기에 맡기면 안 된다 — 커밋만 빠뜨린 항목은 이미 done 이라 다음 항목으로 새 버린다.
   2026-09-24 시험에서 잡혔다.)
5. 회차 기록 `report/loop/<n>.json`(프로세스 id·세션 id·권한 거부·끝 검사 결과·실패 요약)과
   `report/loop/state.json`(대시보드가 읽는다)을 갱신한다.
   **실패 요약** `failure_summary` 는 「항목 미완」 회차에만 한 줄 문자열이고, 끝났거나 카드를 열고 넘어간 회차는 `null` 이다.
   원인에 가까운 순서로 적는다 — 프로세스를 못 띄움/종료 코드 → 오류 결과 → 권한 거부 → 항목이 닫히지 않음 → 실패한 끝 검사
   id 와 그 사유(80자에서 자름). 예: `B1 커밋 안 된 변경 2건: … · B8 …`. `state.json` 의 `last_result` 에도 같은 값이 들어간다 —
   `<n>.wrapup.json` 을 열지 않고 왜 멈췄는지 읽게 하려는 칸이다. 판정: `roundFailureSummary`(loop-model).

**멈춤 종류**: 요청 완료 · 결정 대기 · 항목 실패 · 상한 도달 · 리허설 실패 · 정지 요청.

## 2. 설정 · 상한 · 잠금 · 정지

설정 `report/loop/config.json`(커밋한다). 없는 칸은 기본값:

| 칸 | 기본 | 뜻 |
|---|---|---|
| `max_rounds` | 10 | 회차 상한 |
| `max_minutes` | 120 | 실행 시간 상한 |
| `retries_per_item` | 1 | 같은 항목 재시도 |
| `autostart` | false | 결정 답이 루프를 띄우나(5절) |
| `permission_mode` | `auto` | **언제나 명시해서 넘긴다**(4절). `bypassPermissions` 는 거부 |
| `max_turns` | null | 회차 하나의 턴 상한 |
| `rehearsal` | true | 시작 직전 리허설 |
| `rehearsal_token_limit` | 30000 | 리허설 입력 크기 표시 기준 |
| `claude_cmd` · `gates_cmd` | `claude` · 빠른 게이트 | 시험이 가짜로 바꿔 끼우는 자리 |

- **상한은 회차를 열기 전에만 본다.** 항목 중간에 프로세스를 죽이지 않는다 — 기록이 반쪽이 된다.
  그래서 회차 하나가 멈추지 않으면 시간 상한도 그 회차를 끊지 못한다(알려진 한계).
- **잠금** `report/loop.lock` 은 루프가 도는 동안만 있다(회차·프로세스 id·시작 시각). 끝나면 걷힌다.
  비정상 종료로 남으면 새 루프는 시작을 거부하고, `--stop` 이 정리한다.
- **정지** `node scripts/run-loop.mjs --stop` — 지금 항목이 끝나면 멈춘다. 즉시 중단이 아니다.
  대시보드에 「멈춤 요청됨 — 지금 항목이 끝나면 정지」가 뜬다.
- 잠금이 있는 동안 **대화 세션의 제품 파일 수정을 막는 것**은 게이트(보호 파일) 몫이다 — 패치:
  docs/references/pending-patches/2026-09-24-run-loop-lock.md.

## 3. 항목 끝 검사 (check-wrapup) — 여덟 가지

항목 하나가 끝난 상태의 파일만 본다. 전부 참이어야 통과한다. 결과는 `report/loop/<n>.wrapup.json`.

| id | 무엇 | 어떻게 |
|---|---|---|
| B1 | 커밋 안 된 변경이 없다 | `git status --porcelain` 이 빈다 |
| B2 | 항목이 닫혔고 통과 줄과 쌍이다 | 그 항목 done(또는 그 항목을 막는 카드가 열림) + 기존 쌍 규칙(record-rules) |
| B3 | HANDOFF 가 이 회차 마지막 전환 뒤에 갱신됐다 | HANDOFF.md 수정 시각 ≥ 회차 안 마지막 전환 시각. 회차에 전환이 0줄이어도 실패 |
| B4 | PROGRESS 현재 상태에 이 요청이 보인다 | 기존 잔재 검사(progressResidue) — 요청 식별자나 항목 이름 |
| B5 | 열린 카드가 규약을 지킨다 | 결정 카드 스키마 + `item` 이 요청 항목에 있다 |
| B6 | 게이트가 잡은 위반이 없다 | `node gates/run-gates.mjs --quick` 종료 0 (0.4초) |
| B7 | 요청 밖 작업을 숨기지 않았다 | 회차 안 전환 줄 중 단계가 있는데 `item` 이 빈 줄이 없다. 항목 밖 이름은 「밖으로 기록됨」으로 보고 |
| B8 | 실패·반려에 같은 날 발견 기록 | 회차에 `실패`·`반려` 줄이 있거나 재시도 회차면, 회차 시작 커밋 이후 백로그·하네스 백로그·LESSONS 에 **오늘 날짜가 든 줄이 더해졌다** |

- 세션 랩업에서는 `--item` 없이 부른다. 그때 기준 시각은 오늘 0시다.
- LESSONS 는 보호 파일이라 무인 루프는 백로그에 쓴다. 검사는 셋 다 인정한다.
- 프로브: `node scripts/check-wrapup.mjs --probe` — 여덟 항목 각각에 위반을 **하나씩** 심어 **그것만** 잡히는지 본다
  (다른 항목이 대신 잡아 빨간불인 경우를 가려낸다).

## 4. 권한 — 실측 (2026-09-24)

- **비대화 모드는 권한을 묻지 않는다.** 허용 안 된 도구는 거부한 채 계속 진행하고, 종료 코드 0 · 결과 `success` 로
  끝난다. 거부된 것은 결과의 `permission_denials`(도구 이름과 입력)에만 남는다. 그래서 루프는 이 목록을 반드시 읽는다.
  (실측: `--permission-mode default` 로 파일 쓰기와 `node -e` 를 시키자 둘 다 거부됐고 결과는 success 였다.)
- 이 PC 의 사용자 전역 설정은 기본 모드가 `auto` 다. 루프가 모드를 안 넘기면 그 값을 물려받는다 — 레포 밖 설정
  한 줄에 무인 실행의 권한이 달리는 것이라, 루프는 **언제나** `--permission-mode` 를 넘긴다.
- 프로젝트 훅(PreToolUse·Stop 등)은 비대화 모드에서도 돈다. 게이트·보호 파일 훅이 루프 안에서도 그대로 막는다.
- 허용 목록의 재료는 `report/loop/permissions.json` — 회차들이 **쓴 도구**와 **거부된 도구**를 센다.
  목록을 설정으로 올리는 것은 보호 파일 패치다(사용자 적용). 파괴적 git 명령·외부 전송·결제는 넣지 않는다.

## 5. 시작 — 사람 답이 유일한 방아쇠

- 결정 카드를 `--starts-loop` 로 열고, 사람이 **첫 선택지**를 고르면 `report-decision.mjs --answer` 가 루프를
  분리된 프로세스로 띄운다. 「결정 대기」로 멈춘 루프는 카드 답이 기록되면(답이 무엇이든) 같은 경로로 다시 뜬다.
- **설정 `autostart` 가 꺼져 있으면 언제나 띄우지 않는다**(기본 꺼짐). 이미 도는 루프가 있으면 띄우지 않는다.
- 에이전트가 스스로 루프를 띄우는 경로는 없다. 사람이 직접 `node scripts/run-loop.mjs` 로 띄울 수는 있다.

## 6. 인수인계 리허설

새 대화에 HANDOFF·PROGRESS·request.json(+열린 카드, LESSONS 최근 3줄)만 주고 넷을 답하게 한다 —
지금 위치 / 다음 할 항목 / 열린 결정 / 주의할 것. 앞의 셋을 파일에서 기계로 뽑은 값(HANDOFF 프론티어 줄 ·
1절의 고르기 · 열린 카드 id)과 대조한다. 넷째는 기록만 한다.

- 돌리는 때: 루프 시작 직전 한 번 · 세션 랩업. **회차마다 돌리지 않는다**(회차가 곧 새 대화다).
- 불일치면 루프는 「리허설 실패 — HANDOFF 보강 필요」로 멈춘다. 결과는 `report/loop/rehearsal.json`.
- 입력 크기는 바이트/3 으로 추정한다(한국어 한 글자 3바이트 ≈ 1토큰, 영문은 크게 나온다 — 상한 판정엔 안전한 쪽).
  설정 상한(30k)을 넘으면 표시한다. 멈추지는 않는다.

## 7. 대화 세션의 길이 경고 (루프 밖)

- 멈춤 훅(보호 파일 — 패치: docs/references/pending-patches/2026-09-24-session-size.md)이 대화 파일의 **마지막 응답
  기록의 사용량**(입력 + 캐시 읽기 + 캐시 생성)으로 지금 컨텍스트 크기를 잰다. 훅 입력에는 토큰 수 칸이 없고
  대화 파일 경로(`transcript_path`)만 있어서다. 바이트나 턴 수로 짐작하지 않는다.
- 임계(기본 120k)를 넘으면: **항목 경계**(열린 요청이 없거나, 마지막 항목 전환이 `통과`로 끝남)이면
  「항목 완료 · 새 세션 권장」을 사람에게 알리고 `report/session-warning.json` 을 남겨 대시보드 특이사항에 띄운다.
  **항목 중간**이면 알리기만 한다(멈추지 않는다, 대시보드에 안 띄운다).
- 리허설은 훅이 돌리지 않는다(훅 시간 제한 안에 새 대화를 띄우는 것은 무겁다). 경고를 받으면 세션 랩업이 돌린다.

## 8. 완성 판정과 시험의 대응

| 판정 | 시험 |
|---|---|
| 세 항목이 루프로 끝나고 회차마다 새 프로세스 | `check-run-loop` J1(가짜) · 킷 시험 요청(진짜) |
| 끝 검사 여덟 개에 위반을 심으면 잡히고 재시도 1회 후 멈춤 | `check-wrapup --probe` · `check-run-loop` J2 |
| 카드 — 건너뛰기 · 전부 걸리면 멈춤 | J3 |
| 정지 요청 · 회차 상한 · 시간 상한 · 잠금 정리 | J4 |
| 잠금 중 대화 세션의 제품 파일 수정 차단 | 잠금 게이트 패치의 적용 전 실패/적용 후 통과 검사 |
| 리허설 불일치 멈춤 · 일치 통과 · 30k 초과 표시 | J6 |
| 승인 답 → 자동 시작(켜졌을 때만) | J7 |
| 대시보드에 루프 상태 | J8(화면 계산과 스크립트 계산 대조 포함) |
| 경고 훅 — 경계에서 새 세션 권장, 중간엔 경고만 | 경고 훅 패치의 검사 · J8 의 화면 줄 |
| 권한 목록이 패치로 올라옴 | 킷 시험 뒤 `permissions.json` → 패치 문서 |
| wrap-up 스킬 개정 · 계약 테스트 | `.claude/skills/wrap-up/SKILL.md` · 바인딩 contract = `check-run-loop.mjs` |

## 9. 하지 않는 것

컨텍스트 자동 요약에 기대기 · 항목을 루프가 쪼개거나 합치기 · 항목 중간 강제 종료 · 루프 안에서 사람 답을 대신
채우기 · 리허설을 매 회차 돌리기 · 에이전트가 스스로 루프 띄우기. 제품 요청에 쓰는 것은 킷 시험 뒤 결정 카드로 정한다.

노드를 클릭하면 그 단계가 무엇을 하고, 어떤 파일을 읽고 만드는지 옆에 뜬다. 사실(만드는 파일 · clean 조건 · 의존)은 graph.mjs 에서 직접 읽어 생성했다 — node scripts/build-explorer.mjs

노드를 클릭하세요.

게이트가 뭔가

게이트는 턴이 끝날 때마다 자동으로 도는 검사다. 사람이 부르지 않는다 — .claude/settings.json 에 등록돼 있어서 저절로 돈다.

하는 일은 두 가지뿐이다. ① 코드와 문서를 훑어 규칙 위반을 찾는다(레이어를 거꾸로 import 했나, 타입 에러가 있나, 테스트가 깨졌나…). ② 위반이 0건인 단계에 clean 도장을 찍는다. 하나라도 걸리면 안 찍는다.

그래서 "게이트가 막았다"는 말은 정확히는 "clean 도장을 안 찍어 줬다"는 뜻이다. 도장이 없으면 그 단계는 dirty 로 남고, 거기에 기대는 아래 단계는 아예 시작도 못 한다.

언제 도나

파일을 편집한 직후run-gates.mjs --quick빠른 것만 — 레이어·보안·디자인 승인. 타입 검사와 테스트는 비싸서 건너뛴다
턴이 끝날 때graph-stop.mjs → run-gates.mjs전부 다. 그다음 해시를 비교해 상태를 고치고 HANDOFF.md 에 적는다
도구를 쓰기 직전보호 훅 3개게이트는 아니지만 같이 도는 것 — 시크릿 유출·보호 파일 수정·위험 명령을 아예 막는다

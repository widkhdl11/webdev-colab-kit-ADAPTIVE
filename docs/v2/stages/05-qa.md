# 05. qa

**얕은 검증.** 결정론 게이트로만 판정되므로 매 턴 자동으로 clean 이 된다 ([CLAUDE.md:75](../../../CLAUDE.md#L75) "얕은 qa(테스트)는 매 턴 자동 clean").
그래프에서 `on_fail_diagnose` 를 가진 유일한 노드다 ([graph.mjs:76](../../../graph.mjs#L76)).

## Purpose

구현이 스펙을 지켰는지를 **사람 판단 없이** 확인하고, 실패했을 때 **어느 노드의 잘못인지 귀속**한다.
없으면 깨지는 것: 불변식과 코드 사이의 추적이 끊긴다. approved 스펙의 INV 에 테스트가 없으면 그 불변식은 문서에만 존재한다.

`on_fail_diagnose` 는 "어디로 갈지"가 아니라 "무엇을 살펴볼지"다 — [graph.mjs:73-75](../../../graph.mjs#L73-L75) 가 이 둘을 갈라 놓았다. 목적지 필드가 아니다.

## Entry condition

| 조건 | 어디서 막나 |
|---|---|
| `implement` 가 clean | [graph.mjs:70](../../../graph.mjs#L70) `depends_on: ["implement"]` |
| approved 스펙이 있으면 테스트가 **이미** 존재 | [tdd.md:7-9](../../../.claude/rules/tdd.md#L7-L9) — TDD 순서상 implement 보다 먼저 쓰인다 |

**진입 조건이 시간순과 어긋난다.** 테스트는 implement 보다 먼저 쓰이는데(TDD), 그래프에서 qa 는 implement 의 하류다. 그래프가 표현하는 것은 작성 순서가 아니라 **판정 순서**다.

## What it does

1. `npm test --silent` 를 프로젝트 디렉터리에서 실행한다 ([run-gates.mjs:259-263](../../../gates/run-gates.mjs#L259-L263)). `package.json` 에 `scripts.test` 가 없으면 건너뛴다 ([run-gates.mjs:258](../../../gates/run-gates.mjs#L258))
2. `spec-coverage` 를 실행한다 — approved 스펙의 모든 `INV-*` 가 테스트 텍스트에 등장하는지 ([spec-coverage.mjs:56](../../../gates/spec-coverage.mjs#L56))
3. 실패하면 graph-stop 이 **분류기 필요**를 출력한다 ([graph-stop.mjs:254-256](../../../gates/graph-stop.mjs#L254-L256)) — 스크립트는 알려 주기만 하고, 실제로 부르는 건 사람이나 모델이다
4. `qa-classifier` 가 실패를 `spec / design / impl` 중 **하나**로 귀속한다. 여러 칸이 의심돼도 하나만 고른다 ([qa-classifier.md:15](../../../.claude/agents/qa-classifier.md#L15))
5. 판정은 **아래에서 위로 한 칸씩 올라가며 따진다(레포는 이걸 "충실성 사다리"라 부른다)**다 — 코드가 상류를 지켰나 → 설계가 요구를 충족하나 → … 위쪽 말을 안 지킨 첫 칸에서 멈춘다 ([qa-classifier.md:14-20](../../../.claude/agents/qa-classifier.md#L14-L20))
6. 판정 결과는 `node gates/graph-stop.mjs --mark <노드>` 로 찍는다. 재작업 범위는 전파가 파생한다 ([graph-stop.mjs:190-206](../../../gates/graph-stop.mjs#L190-L206))

## Documents written

| document | ownership | consumed by |
|---|---|---|
| `projects/<이름>/src/**/*.test.ts` | qa 의 produces ([graph.mjs:71](../../../graph.mjs#L71)) | [spec-coverage.mjs:51-54](../../../gates/spec-coverage.mjs#L51-L54) · test-auditor |

**qa 는 문서를 쓰지 않는다.** 판정 결과조차 자기 파일이 아니라 다른 노드의 dirty 상태로 남는다.

## Gate

**조건**: `gate: ["test", "spec-coverage"]` ([graph.mjs:72](../../../graph.mjs#L72))

| 카테고리 | 판정 | 근거 |
|---|---|---|
| `test/FAIL` | `npm test` 종료 코드 ≠ 0 | [run-gates.mjs:265-268](../../../gates/run-gates.mjs#L265-L268) |
| `spec-coverage/MISSING_TEST` | approved 스펙의 INV 가 테스트 텍스트에 없음 | [spec-coverage.mjs:57-60](../../../gates/spec-coverage.mjs#L57-L60) |

**둘 다 `--quick` 에서는 실행되지 않는다** ([run-gates.mjs:228](../../../gates/run-gates.mjs#L228)) — 편집마다 돌리기엔 비싸서다. 턴 종료 시에만 판정된다.

**커버리지 검사는 글자가 들어 있나만 본다.** 모든 테스트 파일을 이어붙인 텍스트에 `INV-D2` 라는 문자열이 있으면 통과한다 ([spec-coverage.mjs:54-56](../../../gates/spec-coverage.mjs#L54-L56)) — 그 테스트가 실제로 그 불변식을 검증하는지는 보지 않는다. **그래서 `test-auditor` 가 따로 있다.**

**실패 경로**: approved 스펙이 0개면 spec-coverage 는 즉시 exit 0 한다 ([spec-coverage.mjs:38](../../../gates/spec-coverage.mjs#L38)). `scripts.test` 가 없으면 test 검사도 건너뛴다. 두 경우 모두 qa 는 **아무것도 안 보고 clean** 이 된다.

## Failure path

- 실패 시 graph-stop 은 **막지 않고 알려 주기만** 한다 ([graph-stop.mjs:254-256](../../../gates/graph-stop.mjs#L254-L256)) — 다만 게이트 에러가 남아 있으면 [graph-stop.mjs:266-269](../../../gates/graph-stop.mjs#L266-L269) 에서 exit 2 로 차단된다
- 분류기가 **impl** 로 판정 → 지목된 위치의 코드 수정 (실패한 qa 가 이미 dirty 로 잡고 있음)
- **design** 판정 → `design-rules.md` 를 `status: draft` 로 (거부)
- **spec** 판정 → 해당 스펙을 `status: draft` 로 (거부). 이 경우 **등급 무관 사용자에게 먼저 보고** ([CLAUDE.md:88](../../../CLAUDE.md#L88))
- 네트워크 의존 통합 테스트가 기본 `npm test` 에 있으면 게이트가 **비결정적으로** 실패한다 → `test:integration` 으로 분리해야 한다 ([tdd.md:12-15](../../../.claude/rules/tdd.md#L12-L15))

## Exit condition

`npm test` 가 green 이고 approved 스펙의 모든 INV 가 테스트에서 참조된다 → qa clean.
프론티어가 `review` 로 이동한다. 다만 review 는 게이트가 아니라 마커로만 clean 되므로, 프론티어에 도달해도 저절로 진행되지 않는다.

## Unverified

- **`npm test` 출력 중 마지막 800자만 에러 메시지로 남는다** ([run-gates.mjs:267](../../../gates/run-gates.mjs#L267)). 실패 원인이 그 앞에 있으면 분류기 입력에서 잘린다. 실제로 잘리는 경우가 있는지 확인 안 했다. `[INFERRED]`
- **`test/FAIL` 에러에는 프로젝트 경로만 있고 파일 경로가 없다** → [graph-stop.mjs:143](../../../gates/graph-stop.mjs#L143) 에서 `whole: true`(전역 에러)로 쳐서 produces 글롭과 무관하게 막는 것으로 보인다. 의도로 보이나 그렇게 쓰인 데를 못 찾았다. `[INFERRED]`
- **`test-auditor` 를 언제 파견하는지가 그래프에 없다.** [CLAUDE.md:78](../../../CLAUDE.md#L78) 이 "정식 경로: … 테스트 작성 후 test-auditor" 라고 쓰지만, qa 노드의 `clean_when` 에는 없다. 감사를 건너뛰어도 qa 는 clean 이 된다. `[INFERRED]`
- **분류기 판정이 기록되는 곳을 못 찾았다.** `--mark` 는 HANDOFF 의 status 만 바꾼다 ([graph-stop.mjs:200-202](../../../gates/graph-stop.mjs#L200-L202)) — 왜 그 노드로 판정했는지는 어디에도 남지 않는다. 다음 세션은 dirty 만 보고 이유를 모른다. `[INFERRED]`
- `spec-coverage` 는 테스트 파일을 `/\.(test|spec)\.(ts|tsx|js)$/` 로 찾는다 ([spec-coverage.mjs:53](../../../gates/spec-coverage.mjs#L53)). `.test.mts` 나 `__tests__/` 규약을 쓰면 커버리지 검사가 소리 없이 비는지 확인 안 했다. `[INFERRED]`
